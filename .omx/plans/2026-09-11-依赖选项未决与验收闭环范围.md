# 2026-09-11：依赖、可选配置、版本未决状态与验收闭环

## 状态与目标

**状态：A–G 的设计与代码已完成；迁移后本地回归通过；最终 dev 验收因外部能力不足为 BLOCKED。**

本轮只修复已经由代码和既有单资源设计共同证明的闭环缺口：依赖范围的服务端事实校验、可选配置的类型能力门禁、版本 POST 结果未知的本地状态、最终真网验收入口，以及一处与当前模板查询行为不一致的提示语。目标不是增加产品能力，而是让已承诺的单资源能力在异常路径与验收结论上同样可信。

## 固定前提（不重新讨论）

- 范围仍是普通单文件、主题 RT001、插件 RT002；不引入多文件资源、集合、session 或 studio。
- `N.json` 是长期身份事实，标题只是可同步的显示缓存；本轮不改变选择器、绑定或标题同步。
- 依赖在已有授权或策略签约成功后即可写入工作稿；**CLI 不处理支付**，浏览器支付既不阻断依赖声明，也不阻断版本提交。
- 策略模板暂时请求全量列表；事件 DSL / 模板参数输入等后端契约问题不在本轮猜测或绕过。
- 每个支持的非必填能力也必须有真实平台生命周期证据；后端或测试素材缺失应标为 `BLOCKED`，不能伪装为通过。
