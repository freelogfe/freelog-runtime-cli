# 研发交付门禁落地计划

用户已授权规范设计至发布全流程、必要时重构；不授权本轮实际 npm 发布或 Git 提交推送。

1. 以 `docs/研发交付规范/README.md` 固定阶段契约、结果协议、数据边界和候选发布机制；纠正过时入口。
2. 修复 CI/空测试/命令文档漂移/静态安全等离线门禁；质量工具必须独立自测。
3. 修复旧验收脚本漏记与假绿；聚合器输出结构化结果，不靠输出正则推断业务状态；必需未实现专项保持 NOT_TESTED。
4. 固定候选 tarball，绑定源/锁/测试/设计摘要、包 SHA-512 和隔离 bin；dev 只跑该安装包，标准发布检查拒绝任何缺失/过期/非通过证据。
5. 修复文档、发布入口与交接；运行离线验证、候选实际打包安装、门禁失败分支和独立双路复核。

验收：本地工具测试通过；旧错误 filter 和假绿分支消失；缺候选/用例/新鲜证据不能发布；不触发 npm/Git 外部写入。当前缺失功能覆盖不假装完成，保留为可见发布阻断。

2026-10-16 实施结果：五项均落地，独立代码 APPROVE / 架构 CLEAR；新增跨候选共享发布 claim，未知结果不能靠重建候选重试。58 项质量工具与 402 项 CLI 测试通过，候选真实打包安装和缺证据拒绝已实跑；规范回填后再次准备候选。真实 dev、Console、远端 CI、npm 发布及 Git 写入本轮未做，7 项必需产品验收 gap 仍阻断发布。完整事实、边界与清理残留见质量规范 §7。
