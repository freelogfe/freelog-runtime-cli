## 固定故障/状态类

| 规则 | 注入与操作 | 精确预期 |
|---|---|---|
| C09.F01 | prepared持久后终止进程，再resume/default/apply | 初次零PUT；默认不改字节；未确认apply拒绝；不重发 |
| C09.F02 | sending持久后、HTTP调用前终止 | 同上，保留sending与完整稿 |
| C09.F03 | 接收PUT但服务端未提交即断连 | 一次PUT、unknown、旧完整快照；重复publish拒绝，resume/apply不再PUT |
| C09.F04 | 服务端提交后丢回复 | 一次PUT；默认confirmed不清理；显式apply清同次未变稿/intent |
| C09.F05 | F04后改当前稿或写坏JSON | 两种各测；apply只清intent，新稿字节保留 |
| C09.F06 | 纯目录发布原来无稿，断连后新建稿 | apply保留新建稿，目录/完整表单仍需命中 |
| C09.F07 | 后续读回错误目标/版本、表单、授权映射或merge目录不符 | 每种分别拒绝confirmed/apply；intent与稿保留；不把当前草稿当已发布目录 |
| C09.F08 | 远端确认成功后本地清intent失败 | 仅一次PUT，留记录；重启后只读核验及apply收尾，不再发布 |
| C09.F09 | 明确拒绝、完整旧快照未变，但清记录失败 | rejected不得冒充confirmed；apply仅清记录、稿完整保留；数值ret/errCode按SDK实际行为核对，不能用直接注入API替代 |
| C09.F10 | 旧v1、坏JSON、摘要错误 | 三种分别保留、不可猜成功或apply |
| C09.F11 | intent环境/账号/类型不符 | 拒绝且完整保留，不能从当前稿补造旧请求 |
| C09.F12 | 默认resume遇无关本地txn | 全字节不变、不前滚；apply继续遵守既有项目锁规则 |

表单前置包含系统附加值、属性、文本/下拉配置、依赖、描述、六展示及非空授权映射；merge类至少两单品。读取DTO与写body分开，服务端不引用生产toPayload函数制造正确答案。故障终止不是正常业务失败：需装置真实标记和预期退出码，不将任意signal/timeout当成通过。
