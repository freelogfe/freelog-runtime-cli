# 第三章：索引与性能优化

## 3.1 索引基础

索引是提高查询性能的关键。MongoDB 使用 B-Tree 索引结构。

### 什么是索引？

索引是数据库中用于快速定位数据的数据结构。类似于书籍的目录，索引可以帮助 MongoDB 快速找到满足查询条件的文档，而不需要扫描整个集合。

### B-Tree 索引结构

MongoDB 使用 B-Tree（平衡树）索引结构：

```
        [50]
       /    \
    [25]    [75]
   /  |  \  /  |  \
[10][20][30][60][80][90]
```

**特点**：
- 平衡树结构，保证查询时间复杂度为 O(log n)
- 支持范围查询和排序操作
- 索引键按顺序存储，便于范围扫描

### 为什么需要索引？

**性能提升**：
- ✅ **加快查询速度**：从 O(n) 全表扫描降低到 O(log n) 索引查找
- ✅ **提高排序性能**：索引已排序，直接使用索引排序
- ✅ **支持唯一性约束**：唯一索引确保字段值唯一
- ✅ **减少全表扫描**：避免扫描所有文档

**实际效果对比**：
```javascript
// 无索引：需要扫描 1,000,000 个文档
db.users.find({ email: "user@example.com" })
// 执行时间：~500ms

// 有索引：只需查找索引树
db.users.createIndex({ email: 1 })
db.users.find({ email: "user@example.com" })
// 执行时间：~1ms（提升 500 倍）
```

### 索引的代价

**存储和性能成本**：
- ❌ **占用存储空间**：索引需要额外的磁盘空间（通常为数据的 10-20%）
- ❌ **降低写入性能**：每次插入/更新/删除都需要更新索引
- ❌ **增加内存占用**：索引会被加载到内存中以提高查询速度
- ❌ **维护成本**：索引需要定期维护和优化

**权衡建议**：
- 读多写少的场景：多创建索引
- 写多读少的场景：谨慎创建索引
- 平衡读写：根据查询模式创建必要的索引

## 3.2 创建索引

### 单字段索引

```javascript
// 创建升序索引
db.users.createIndex({ age: 1 })

// 创建降序索引
db.users.createIndex({ age: -1 })

// 查看所有索引
db.users.getIndexes()

// 删除索引
db.users.dropIndex({ age: 1 })
db.users.dropIndex("age_1")  // 使用索引名称
```

### 复合索引

复合索引是在多个字段上创建的索引，字段顺序非常重要！

```javascript
// 创建复合索引
db.users.createIndex({ age: 1, name: 1 })

// 索引顺序很重要！
// { age: 1, name: 1 } 可以支持：
// - { age: ... }                    ✅ 可以使用索引
// - { age: ..., name: ... }         ✅ 可以使用索引
// - { age: ..., name: ..., ... }   ✅ 可以使用索引
// 但不能支持：
// - { name: ... }                   ❌ 不能使用索引（缺少前缀）
// - { name: ..., age: ... }         ❌ 不能使用索引（顺序不对）
```

**复合索引的前缀规则**：
- 复合索引 `{ a: 1, b: 1, c: 1 }` 可以支持：
  - `{ a: ... }` ✅
  - `{ a: ..., b: ... }` ✅
  - `{ a: ..., b: ..., c: ... }` ✅
- 但不能支持：
  - `{ b: ... }` ❌（缺少前缀 a）
  - `{ c: ... }` ❌（缺少前缀 a, b）
  - `{ b: ..., c: ... }` ❌（缺少前缀 a）

**实际示例**：
```javascript
// 创建复合索引
db.users.createIndex({ status: 1, createdAt: -1, age: 1 })

// ✅ 可以使用索引的查询
db.users.find({ status: "active" })
db.users.find({ status: "active" }).sort({ createdAt: -1 })
db.users.find({ status: "active", age: { $gte: 18 } }).sort({ createdAt: -1 })

// ❌ 不能使用索引的查询
db.users.find({ createdAt: { $gte: ISODate("2024-01-01") } })  // 缺少 status
db.users.find({ age: { $gte: 18 } })  // 缺少 status
```

**索引顺序选择原则**：
1. **等值查询字段**放在最前面
2. **排序字段**放在中间
3. **范围查询字段**放在最后

### 多键索引（数组字段）

MongoDB 会自动为数组字段创建多键索引（Multi-key Index），为数组中的每个元素创建索引条目。

```javascript
// 为数组字段创建索引（自动创建多键索引）
db.users.createIndex({ hobbies: 1 })

// 示例数据
db.users.insertMany([
  { name: "张三", hobbies: ["读书", "游泳", "编程"] },
  { name: "李四", hobbies: ["读书", "旅游"] },
  { name: "王五", hobbies: ["游泳", "编程"] }
])

// 查询时会自动使用多键索引
db.users.find({ hobbies: "读书" })
// 返回：张三、李四

// 多键索引会为每个数组元素创建索引条目
// hobbies: ["读书", "游泳", "编程"]
// 索引条目：
//   - hobbies: "读书"
//   - hobbies: "游泳"
//   - hobbies: "编程"
```

**多键索引的限制**：
1. **不能创建复合多键索引**：如果多个字段都是数组，不能创建复合索引
   ```javascript
   // ❌ 错误：两个数组字段不能创建复合索引
   db.users.createIndex({ hobbies: 1, skills: 1 })
   // Error: cannot index parallel arrays
   
   // ✅ 正确：只有一个数组字段
   db.users.createIndex({ name: 1, hobbies: 1 })
   ```

2. **哈希索引不能是多键索引**

   哈希索引使用哈希函数将字段值转换为哈希值，然后对哈希值进行索引。由于哈希索引的特殊性，它不能用于数组字段（多键索引）。

   **原因**：
   - 哈希索引需要对整个字段值进行哈希计算
   - 数组字段包含多个元素，无法对整个数组进行单一的哈希计算
   - 哈希索引主要用于分片键，需要确定性的哈希值

   ```javascript
   // ❌ 错误：不能为数组字段创建哈希索引
   db.users.createIndex({ hobbies: "hashed" })
   // Error: hashed indexes do not support multi-key indexes

   // ✅ 正确：为标量字段创建哈希索引
   db.users.createIndex({ userId: "hashed" })
   // userId 是字符串或数字，不是数组

   // ✅ 正确：为数组字段创建普通索引（自动成为多键索引）
   db.users.createIndex({ hobbies: 1 })
   // 这会创建多键索引，为数组中的每个元素创建索引条目
   ```

   **哈希索引的特点**：
   - ✅ 用于分片键，提供均匀的数据分布
   - ✅ 支持等值查询（精确匹配）
   - ❌ 不支持范围查询（如 `$gt`、`$lt`）
   - ❌ 不支持排序操作
   - ❌ 不能用于数组字段（多键索引）

3. **嵌套数组**：如果数组元素是文档，可以为嵌套字段创建索引
   ```javascript
   // 示例数据
   db.users.insertOne({
     name: "张三",
     contacts: [
       { type: "phone", value: "13800138000" },
       { type: "email", value: "zhangsan@example.com" }
     ]
   })
   
   // 为嵌套字段创建索引
   db.users.createIndex({ "contacts.type": 1 })
   db.users.find({ "contacts.type": "phone" })
   ```

### 文本索引详解

文本索引用于全文搜索，支持在文本内容中搜索关键词，并可以按相关性排序。

**什么是文本索引？**

文本索引会对文档中的文本字段进行分词，然后为每个词创建索引条目。当搜索时，MongoDB 会查找包含搜索词的文档，并计算相关性分数。

```javascript
// 创建文本索引（集合级别只能有一个文本索引）
db.articles.createIndex({ title: "text", content: "text" })
// 这会为 title 和 content 字段创建文本索引
// MongoDB 会自动分词，例如："MongoDB 教程" 会被分成 ["MongoDB", "教程"]
```

**工作原理**：

```javascript
// 示例数据
db.articles.insertMany([
  {
    title: "MongoDB 入门教程",
    content: "这是一个关于 MongoDB 数据库的教程"
  },
  {
    title: "MongoDB 高级特性",
    content: "学习 MongoDB 的高级功能"
  },
  {
    title: "Node.js 开发指南",
    content: "使用 Node.js 和 MongoDB 开发应用"
  }
])

// 创建文本索引后，MongoDB 会分词并创建索引：
// title: "MongoDB" → 文档1, 文档2
// title: "入门" → 文档1
// title: "教程" → 文档1
// content: "MongoDB" → 文档1, 文档2, 文档3
// content: "教程" → 文档1
// ...
```

### 文本搜索基本用法

**1. 基本文本搜索**：

```javascript
// 搜索包含 "MongoDB" 的文档（默认不区分大小写）
db.articles.find({ $text: { $search: "MongoDB" } })
// 返回：文档1、文档2、文档3（都包含 "MongoDB"）

// 搜索多个词（OR 关系）
db.articles.find({ $text: { $search: "MongoDB 教程" } })
// 返回：包含 "MongoDB" 或 "教程" 的文档
// 结果：文档1（包含两者）、文档2（包含 MongoDB）、文档3（包含 MongoDB）
```

**2. 文本搜索排序（按相关性）**：

`textScore` 是 MongoDB 计算的相关性分数，分数越高表示文档与搜索词越相关。

```javascript
// 步骤1：在查询中获取 textScore
db.articles.find(
  { $text: { $search: "MongoDB 教程" } },
  { score: { $meta: "textScore" } }  // 添加 score 字段，值为 textScore
)
// 结果：
// {
//   title: "MongoDB 入门教程",
//   content: "...",
//   score: 2.5  // 相关性分数（包含两个词，分数较高）
// },
// {
//   title: "MongoDB 高级特性",
//   content: "...",
//   score: 1.0  // 只包含一个词，分数较低
// }

// 步骤2：按相关性排序
db.articles.find(
  { $text: { $search: "MongoDB 教程" } },
  { score: { $meta: "textScore" } }
).sort({ score: { $meta: "textScore" } })
// 结果：按相关性从高到低排序
// 最相关的文档（包含更多搜索词）排在前面
```

**$meta 和 textScore 详解**：

```javascript
// $meta: "textScore" 是 MongoDB 的特殊操作符
// 用于获取文本搜索的相关性分数

// 在投影中使用
{ score: { $meta: "textScore" } }
// 这会添加一个 score 字段，值为该文档的相关性分数

// 在排序中使用
.sort({ score: { $meta: "textScore" } })
// 按相关性分数排序（降序，分数高的在前）

// 完整示例
db.articles.find(
  { $text: { $search: "MongoDB" } },
  { 
    title: 1,
    content: 1,
    score: { $meta: "textScore" }  // 添加相关性分数字段
  }
).sort({ score: { $meta: "textScore" } })  // 按相关性排序
```

**3. 排除某些词（使用 `-` 前缀）**：

```javascript
// 搜索包含 "MongoDB" 但不包含 "教程" 的文档
db.articles.find({ $text: { $search: "MongoDB -教程" } })
// "-教程" 表示排除包含"教程"的文档
// 结果：文档2、文档3（包含 MongoDB 但不包含"教程"）

// 多个排除词
db.articles.find({ $text: { $search: "MongoDB -教程 -入门" } })
// 排除包含"教程"或"入门"的文档
```

**4. 短语搜索（使用引号）详解**：

引号的作用是**将多个词作为一个整体短语**进行搜索，要求这些词必须**相邻**且**顺序一致**。

**关键理解**：

```javascript
// 示例数据
db.articles.insertMany([
  {
    title: "MongoDB 教程",
    content: "这是一个 MongoDB 教程"
  },
  {
    title: "MongoDB 入门",
    content: "MongoDB 是一个数据库，这是入门指南"
  },
  {
    title: "数据库教程",
    content: "这是关于数据库的教程，包含 MongoDB 内容"
  },
  {
    title: "教程 MongoDB",
    content: "教程内容：MongoDB 数据库"
  }
])

// ========== 不使用引号（OR 关系）==========
db.articles.find({ $text: { $search: "MongoDB 教程" } })
// MongoDB 会分词：["MongoDB", "教程"]
// 查找条件：包含 "MongoDB" **或** 包含 "教程"（OR 关系）
// 结果：
// ✅ 文档1：包含 "MongoDB" 和 "教程"（都包含）
// ✅ 文档2：包含 "MongoDB"（只包含一个）
// ✅ 文档3：包含 "教程"（只包含一个）
// ✅ 文档4：包含 "MongoDB" 和 "教程"（都包含，但顺序不同）

// ========== 使用引号（短语搜索）==========
db.articles.find({ $text: { $search: "\"MongoDB 教程\"" } })
// 引号表示这是一个短语，要求：
// 1. 必须同时包含 "MongoDB" **和** "教程"（AND 关系）
// 2. 这两个词必须**相邻**（中间可以有空格，但不能有其他词）
// 3. 顺序必须一致（"MongoDB" 在前，"教程" 在后）
// 结果：
// ✅ 文档1：包含 "MongoDB 教程"（相邻且顺序正确）
// ❌ 文档2：包含 "MongoDB" 但不包含相邻的 "教程"
// ❌ 文档3：包含 "教程" 但前面不是 "MongoDB"
// ❌ 文档4：包含 "MongoDB" 和 "教程"，但顺序是 "教程 MongoDB"（顺序不对）
```

**详细对比说明**：

```javascript
// ========== 情况1：不使用引号 ==========
db.articles.find({ $text: { $search: "MongoDB 教程" } })
// 分词结果：["MongoDB", "教程"]
// 查询逻辑：文档包含 "MongoDB" **或** 包含 "教程"（OR 关系）
// 
// 匹配示例：
// ✅ "MongoDB 入门"          → 包含 "MongoDB"
// ✅ "数据库教程"            → 包含 "教程"
// ✅ "MongoDB 教程"          → 包含两者
// ✅ "教程 MongoDB"          → 包含两者（顺序无关）
// ✅ "MongoDB 高级 教程"     → 包含两者（中间有其他词也可以）

// ========== 情况2：使用引号 ==========
db.articles.find({ $text: { $search: "\"MongoDB 教程\"" } })
// 短语搜索：要求 "MongoDB" 和 "教程" 必须相邻且顺序一致
// 查询逻辑：文档包含 "MongoDB" **和** "教程"，且必须相邻（AND 关系 + 相邻）
//
// 匹配示例：
// ✅ "MongoDB 教程"          → 相邻且顺序正确
// ✅ "这是 MongoDB 教程"     → 相邻（中间只有空格）
// ✅ "MongoDB 教程 入门"     → 相邻（后面有其他词可以）
// ❌ "MongoDB 入门 教程"     → 不相邻（中间有"入门"）
// ❌ "教程 MongoDB"          → 顺序不对
// ❌ "MongoDB 高级 教程"     → 不相邻（中间有"高级"）
```

**"AND 关系"的含义**：

```javascript
// 引号内的 "MongoDB 教程" 会被解析为：
// - 必须包含 "MongoDB" **和** 必须包含 "教程"（AND 关系）
// - 这两个词必须相邻（中间可以有空格，但不能有其他词）
// - 顺序必须一致（"MongoDB" 在前，"教程" 在后）

// 具体来说：
// "MongoDB" 和 "教程" 之间的关系是 AND（都必须存在）
// 但不仅仅是 AND，还有额外的约束：
//   1. 相邻约束：两个词必须紧挨着（中间只能有空格）
//   2. 顺序约束："MongoDB" 必须在 "教程" 前面

// 所以更准确的描述是：
// "MongoDB" AND "教程" AND 相邻 AND 顺序一致
```

**实际应用示例**：

```javascript
// 场景1：搜索产品名称
db.products.find({ $text: { $search: "\"iPhone 15\"" } })
// 只返回包含完整短语 "iPhone 15" 的产品
// ✅ "iPhone 15 Pro"        → 匹配（相邻）
// ❌ "iPhone 14 和 15"      → 不匹配（不相邻）
// ❌ "15 iPhone"            → 不匹配（顺序不对）

// 场景2：搜索人名
db.users.find({ $text: { $search: "\"张三 李四\"" } })
// 只返回包含 "张三 李四" 这个完整短语的文档
// ✅ "我的朋友是 张三 李四"  → 匹配（相邻）
// ❌ "张三 和 李四"          → 不匹配（中间有"和"）
// ❌ "李四 张三"             → 不匹配（顺序不对）

// 场景3：搜索代码片段
db.code.find({ $text: { $search: "\"function async\"" } })
// 只返回包含 "function async" 这个短语的代码
// ✅ "function async() {}"   → 匹配
// ❌ "async function() {}"   → 不匹配（顺序不对）
```

**引号内的空格处理**：

```javascript
// 引号内的空格会被保留，表示词之间的分隔
db.articles.find({ $text: { $search: "\"MongoDB 教程\"" } })
// 空格表示 "MongoDB" 和 "教程" 之间可以有空格
// ✅ "MongoDB 教程"         → 匹配（中间有空格）
// ✅ "MongoDB教程"          → 匹配（中间没有空格也可以）
// ❌ "MongoDB 入门 教程"    → 不匹配（中间有其他词）

// 多个空格会被视为一个空格
db.articles.find({ $text: { $search: "\"MongoDB    教程\"" } })
// 多个空格会被视为一个空格
// ✅ "MongoDB 教程"         → 匹配
// ✅ "MongoDB    教程"      → 匹配
```

**总结**：

| 搜索方式 | 分词结果 | 查询逻辑 | 匹配要求 |
|---------|---------|---------|---------|
| `"MongoDB 教程"`（无引号） | `["MongoDB", "教程"]` | OR 关系 | 包含 "MongoDB" **或** 包含 "教程" |
| `"\"MongoDB 教程\""`（有引号） | `["MongoDB 教程"]`（短语） | AND + 相邻 + 顺序 | 必须包含 "MongoDB" **和** "教程"，且相邻，顺序一致 |

**关键点**：
- **不使用引号**：OR 关系，只要包含任意一个词就匹配
- **使用引号**：AND 关系 + 相邻 + 顺序，必须包含所有词且相邻且顺序一致

**如何实现 AND 关系（不要求相邻）？**

引号内的 AND 关系要求词必须相邻。如果需要 AND 关系但不要求相邻，可以使用以下方法：

**方法1：使用聚合管道（推荐）**

```javascript
// 需求：查找同时包含 "MongoDB" 和 "教程" 的文档（不要求相邻）
db.articles.aggregate([
  // 步骤1：使用 $text 搜索（OR 关系，获取候选文档）
  {
    $match: {
      $text: { $search: "MongoDB 教程" }
    }
  },
  // 步骤2：添加 textScore 字段
  {
    $addFields: {
      score: { $meta: "textScore" }
    }
  },
  // 步骤3：过滤出同时包含两个词的文档（AND 关系）
  {
    $match: {
      $expr: {
        $and: [
          // 检查 title 或 content 中包含 "MongoDB"
          {
            $or: [
              { $regexMatch: { input: "$title", regex: "MongoDB", options: "i" } },
              { $regexMatch: { input: "$content", regex: "MongoDB", options: "i" } }
            ]
          },
          // 检查 title 或 content 中包含 "教程"
          {
            $or: [
              { $regexMatch: { input: "$title", regex: "教程", options: "i" } },
              { $regexMatch: { input: "$content", regex: "教程", options: "i" } }
            ]
          }
        ]
      }
    }
  },
  // 步骤4：按相关性排序
  {
    $sort: { score: -1 }
  }
])

// 结果：只返回同时包含 "MongoDB" 和 "教程" 的文档（不要求相邻）
// ✅ "MongoDB 入门 教程"     → 匹配（包含两者，不相邻也可以）
// ✅ "教程：MongoDB 数据库"  → 匹配（包含两者，顺序无关）
// ❌ "MongoDB 入门"          → 不匹配（缺少"教程"）
// ❌ "数据库教程"            → 不匹配（缺少"MongoDB"）
```

**方法2：使用正则表达式（简单但性能较差）**

```javascript
// 需求：查找同时包含 "MongoDB" 和 "教程" 的文档
db.articles.find({
  $and: [
    {
      $or: [
        { title: /MongoDB/i },
        { content: /MongoDB/i }
      ]
    },
    {
      $or: [
        { title: /教程/i },
        { content: /教程/i }
      ]
    }
  ]
})

// ⚠️ 注意：这种方法不使用文本索引，性能较差
// 适用于数据量较小或无法使用文本索引的场景
```

**方法3：使用 textScore 过滤（更高效）**

```javascript
// 需求：查找同时包含 "MongoDB" 和 "教程" 的文档
// 原理：如果文档同时包含多个词，textScore 会更高
db.articles.find(
  {
    $text: { $search: "MongoDB 教程" },
    // 使用 textScore 过滤：只返回包含多个词的文档
    // 注意：这种方法不够精确，可能漏掉一些结果
  },
  {
    score: { $meta: "textScore" }
  }
).sort({ score: { $meta: "textScore" } })
  .limit(100)  // 限制结果数量
  .toArray()
  .filter(doc => {
    // 在应用层进一步过滤：确保同时包含所有词
    const text = `${doc.title} ${doc.content}`.toLowerCase();
    return text.includes('mongodb') && text.includes('教程');
  })
```

**方法4：组合使用（最佳实践）**

```javascript
// 需求：查找同时包含 "MongoDB"、"教程"、"数据库" 的文档（不要求相邻）
db.articles.aggregate([
  // 步骤1：使用 $text 搜索（利用索引，快速筛选候选文档）
  {
    $match: {
      $text: { $search: "MongoDB 教程 数据库" }
    }
  },
  // 步骤2：添加 textScore
  {
    $addFields: {
      score: { $meta: "textScore" },
      // 合并所有文本字段
      fullText: {
        $concat: [
          { $ifNull: ["$title", ""] },
          " ",
          { $ifNull: ["$content", ""] }
        ]
      }
    }
  },
  // 步骤3：使用 $expr 和 $regexMatch 精确过滤（AND 关系）
  {
    $match: {
      $expr: {
        $and: [
          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "mongodb"] }, -1] },
          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "教程"] }, -1] },
          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "数据库"] }, -1] }
        ]
      }
    }
  },
  // 步骤4：按相关性排序
  {
    $sort: { score: -1 }
  }
])
```

**三种 AND 关系对比**：

| 方法 | 查询方式 | 是否相邻 | 是否有序 | 性能 | 适用场景 |
|------|---------|---------|---------|------|---------|
| `"MongoDB 教程"`（无引号） | OR 关系 | - | - | ⭐⭐⭐⭐⭐ | 包含任意一个词 |
| `"\"MongoDB 教程\""`（有引号） | AND + 相邻 + 有序 | ✅ 必须相邻 | ✅ 必须有序 | ⭐⭐⭐⭐⭐ | 精确短语搜索 |
| 聚合管道过滤 | AND 关系 | ❌ 不要求相邻 | ❌ 不要求有序 | ⭐⭐⭐⭐ | 同时包含多个词（不要求相邻） |

**实际应用示例**：

```javascript

db.articles.aggregate([
  {
    $match: { $text: { $search: "MongoDB 索引 性能" } }
  },
  {
    $addFields: {
      score: { $meta: "textScore" },
      fullText: { $concat: ["$title", " ", "$content"] }
    }
  },
  {
    $match: {
      $expr: {
        $and: [
          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "mongodb"] }, -1] },
          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "索引"] }, -1] },
          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "性能"] }, -1] }
        ]
      }
    }
  },
  {
    $sort: { score: -1 }
  }
])

// 场景2：搜索产品（必须包含多个特征词）

db.products.aggregate([
  {
    $match: { $text: { $search: "手机 5G 256GB" } }

    }
  },
  {
    $match: {
      $expr: {

          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "手机"] }, -1] },

          { $gt: [{ $indexOfCP: [{ $toLower: "$fullText" }, "256gb"] }, -1] }
        ]
      }
    }
  },
  {
    $sort: { score: -1 }
  }
])
```

**性能优化建议**：

1. **优先使用文本索引**：先用 `$text` 搜索缩小范围，再用正则过滤
2. **限制结果数量**：使用 `limit()` 限制返回的文档数量
3. **合理使用索引**：确保文本索引包含所有搜索字段
4. **避免过度过滤**：如果数据量很大，考虑在应用层进行二次过滤

**5. 组合搜索**：

```javascript
// 搜索包含 "MongoDB" 或 "Node.js"，但不包含 "入门"
db.articles.find({ $text: { $search: "MongoDB Node.js -入门" } })

// 搜索短语 "MongoDB 教程" 或包含 "数据库"
```


### 地理空间索引详解

地理空间索引用于存储和查询地理位置数据，支持"附近"、"范围内"等地理空间查询。

**什么是地理空间索引？**

地理空间索引专门用于处理地理位置数据，可以快速查找：
- 附近的点（如：查找附近的餐厅）
- 范围内的点（如：查找某个区域内的商店）
- 距离计算（如：计算两点之间的距离）

**地理空间数据类型**：

MongoDB 支持两种地理空间数据格式：

1. **GeoJSON 格式**（推荐）：标准的地理空间数据格式
2. **传统坐标对格式**：简单的 `[x, y]` 数组

### GeoJSON 格式详解

GeoJSON 是标准的地理空间数据格式，支持多种几何类型：

```javascript
// 1. Point（点）- 表示一个地理位置
{
  name: "天安门",
  location: {
    type: "Point",
    coordinates: [116.3974, 39.9093]  // [经度, 纬度]
    // ⚠️ 注意：坐标顺序是 [经度, 纬度]，不是 [纬度, 经度]
  }
}

// 2. LineString（线）- 表示一条路径
{
  name: "路线1",
  route: {
    type: "LineString",
    coordinates: [
      [116.3974, 39.9093],  // 起点
      [116.4074, 39.9193],  // 中间点
      [116.4174, 39.9293]   // 终点
    ]
  }
}

// 3. Polygon（多边形）- 表示一个区域
{
  name: "北京市朝阳区",
  area: {
    type: "Polygon",
    coordinates: [[
      [116.3974, 39.9093],  // 第一个点
      [116.4074, 39.9093],  // 第二个点
      [116.4074, 39.9193],  // 第三个点
      [116.3974, 39.9193],  // 第四个点
      [116.3974, 39.9093]   // 闭合多边形（必须与第一个点相同）
    ]]
  }
}
```

**坐标顺序说明**：

```javascript
// ⚠️ 重要：GeoJSON 使用 [经度, 纬度] 顺序
// 经度（Longitude）：东西方向，范围 -180 到 180
// 纬度（Latitude）：南北方向，范围 -90 到 90

// ✅ 正确
coordinates: [116.3974, 39.9093]  // [经度, 纬度]
// 116.3974 = 东经 116.3974 度（北京）
// 39.9093 = 北纬 39.9093 度（北京）

// ❌ 错误
coordinates: [39.9093, 116.3974]  // [纬度, 经度] - 错误顺序！
```

### 2dsphere 索引（推荐）

`2dsphere` 索引用于球面坐标（地球表面），支持 GeoJSON 格式，**推荐用于真实地理位置**。

```javascript
// 创建 2dsphere 索引
db.places.createIndex({ location: "2dsphere" })

// 示例数据
db.places.insertMany([
  {
    name: "天安门",
    location: {
      type: "Point",
      coordinates: [116.3974, 39.9093]  // 北京天安门
    }
  },
  {
    name: "故宫",
    location: {
      type: "Point",
      coordinates: [116.3972, 39.9163]  // 北京故宫
    }
  },
  {
    name: "颐和园",
    location: {
      type: "Point",
      coordinates: [116.2731, 39.9994]  // 北京颐和园
    }
  }
])
```

**2dsphere 索引的特点**：
- ✅ 支持 GeoJSON 格式（Point、LineString、Polygon 等）
- ✅ 支持球面距离计算（考虑地球曲率）
- ✅ 支持所有地理空间查询操作符
- ✅ 适用于真实地理位置查询

### 2d 索引（平面坐标）

`2d` 索引用于平面坐标（二维平面），支持传统坐标对格式，**适用于平面地图、游戏地图等**。

```javascript
// 创建 2d 索引
db.places.createIndex({ location: "2d" })

// 示例数据（传统坐标对格式）
db.places.insertMany([
  {
    name: "点A",
    location: [100, 200]  // [x, y] 坐标对
  },
  {
    name: "点B",
    location: [150, 250]
  }
])
```

**2d 索引的特点**：
- ✅ 支持传统坐标对格式 `[x, y]`
- ✅ 支持平面距离计算（不考虑地球曲率）
- ✅ 查询速度较快
- ⚠️ 不适用于真实地理位置（不考虑地球曲率）
- ⚠️ 不支持所有 GeoJSON 类型

**2d vs 2dsphere 对比**：

| 特性 | 2d 索引 | 2dsphere 索引 |
|------|---------|--------------|
| 坐标格式 | `[x, y]` 坐标对 | GeoJSON 格式 |
| 适用场景 | 平面地图、游戏地图 | 真实地理位置（地球表面） |
| 距离计算 | 平面距离（直线距离） | 球面距离（考虑地球曲率） |
| GeoJSON 支持 | ⚠️ 有限支持 | ✅ 完全支持 |
| 推荐使用 | 平面场景 | ✅ **真实地理位置（推荐）** |

### 地理空间查询操作符

**1. $near - 查找附近的点（按距离排序）**

`$near` 用于查找指定点附近的文档，结果按距离从近到远排序。

```javascript
// 查找天安门附近 1 公里内的地点
db.places.find({
  location: {
    $near: {
      $geometry: {
        type: "Point",
        coordinates: [116.3974, 39.9093]  // 天安门坐标
      },
      $maxDistance: 1000  // 最大距离：1000 米（1 公里）
    }
  }
})
// 结果：按距离从近到远排序
// 1. 故宫（距离最近）
// 2. 其他附近的地点...

// 指定最小距离
db.places.find({
  location: {
    $near: {
      $geometry: {
        type: "Point",
        coordinates: [116.3974, 39.9093]
      },
      $maxDistance: 1000,  // 最大距离：1 公里
      $minDistance: 100    // 最小距离：100 米（排除太近的点）
    }
  }
})

// 限制返回数量
db.places.find({
  location: {
    $near: {
      $geometry: {
        type: "Point",
        coordinates: [116.3974, 39.9093]
      },
      $maxDistance: 1000
    }
  }
}).limit(10)  // 只返回最近的 10 个地点
```

**2. $geoWithin - 查找范围内的点**

`$geoWithin` 用于查找指定区域内的所有点，不按距离排序。

```javascript
// 查找多边形区域内的点
db.places.find({
  location: {
    $geoWithin: {
      $geometry: {
        type: "Polygon",
        coordinates: [[
          [116.3874, 39.8993],  // 左下角
          [116.4074, 39.8993],  // 右下角
          [116.4074, 39.9193],  // 右上角
          [116.3874, 39.9193],  // 左上角
          [116.3874, 39.8993]   // 闭合（必须与第一个点相同）
        ]]
      }
    }
  }
})

// 使用圆形范围（$centerSphere）
db.places.find({
  location: {
    $geoWithin: {
      $centerSphere: [
        [116.3974, 39.9093],  // 中心点 [经度, 纬度]
        1 / 6378.1             // 半径：1 公里
        // 6378.1 是地球半径（公里）
        // 半径单位：弧度 = 距离（公里）/ 地球半径（公里）
      ]
    }
  }
})

// 使用矩形范围（$box）- 仅 2d 索引
db.places.find({
  location: {
    $geoWithin: {
      $box: [
        [116.3874, 39.8993],  // 左下角 [x, y]
        [116.4074, 39.9193]   // 右上角 [x, y]
      ]
    }
  }
})
```

**3. $geoIntersects - 查找相交的几何图形**

`$geoIntersects` 用于查找与指定几何图形相交的文档。

```javascript
// 查找与指定多边形相交的地点
db.places.find({
  location: {
    $geoIntersects: {
      $geometry: {
        type: "Polygon",
        coordinates: [[
          [116.3874, 39.8993],
          [116.4074, 39.8993],
          [116.4074, 39.9193],
          [116.3874, 39.9193],
          [116.3874, 39.8993]
        ]]
      }
    }
  }
})
```

### 实际应用场景

**场景1：查找附近的餐厅**

```javascript
// 1. 创建索引
```

### 地理空间索引的限制和注意事项

**1. 坐标顺序**：
```javascript
// ✅ 正确：[经度, 纬度]
coordinates: [116.3974, 39.9093]

// ❌ 错误：[纬度, 经度]
coordinates: [39.9093, 116.3974]
```

**2. 多边形必须闭合**：
```javascript
// ✅ 正确：最后一个点与第一个点相同
coordinates: [[
  [116.3974, 39.9093],
  [116.4074, 39.9093],
  [116.4074, 39.9193],
  [116.3974, 39.9193],
  [116.3974, 39.9093]  // 闭合
]]

// ❌ 错误：未闭合
coordinates: [[
  [116.3974, 39.9093],
  [116.4074, 39.9093],
  [116.4074, 39.9193],
  [116.3974, 39.9193]
  // 缺少闭合点
]]
```

**3. 距离单位**：
- `$maxDistance`、`$minDistance`：单位是**米**
- `$centerSphere` 半径：单位是**弧度**（距离/地球半径）

**4. 索引要求**：
- `$near` 查询**必须**有地理空间索引
- `$geoWithin` 查询**建议**有地理空间索引（提高性能）

**5. 复合索引**：
```javascript
// 地理空间 + 其他字段的复合索引
db.places.createIndex({
  location: "2dsphere",
  category: 1,
  rating: -1
})

// 可以同时使用地理空间查询和其他条件
db.places.find({
  location: {
    $near: {
      $geometry: { type: "Point", coordinates: [116.3974, 39.9093] },
      $maxDistance: 1000
    }
  },
  category: "餐厅",
  rating: { $gte: 4 }
})
```

### 哈希索引

哈希索引使用哈希函数将字段值转换为哈希值，然后对哈希值进行索引。主要用于分片键，提供均匀的数据分布。

**哈希索引的特点**：

```javascript
// 创建哈希索引（用于分片）
db.users.createIndex({ userId: "hashed" })
```

**哈希索引的特性**：

1. **均匀分布**：哈希索引可以将数据均匀分布到不同的分片上
2. **等值查询**：支持精确匹配查询
3. **不支持范围查询**：不能用于 `$gt`、`$lt`、`$gte`、`$lte` 等范围查询
4. **不支持排序**：不能用于 `sort()` 操作
5. **不能用于数组字段**：哈希索引不能是多键索引

**使用场景**：

```javascript
// 场景1：分片键（主要用途）
db.users.createIndex({ userId: "hashed" })
sh.shardCollection("mydb.users", { userId: "hashed" })

// 场景2：等值查询
db.users.find({ userId: "user123" })
// ✅ 可以使用哈希索引

// ❌ 不支持范围查询
db.users.find({ userId: { $gt: "user100" } })
// 错误：哈希索引不支持范围查询

// ❌ 不支持排序
db.users.find().sort({ userId: 1 })
// 错误：哈希索引不支持排序
```

**哈希索引 vs 普通索引**：

| 特性 | 哈希索引 | 普通索引（B-Tree） |
|------|---------|------------------|
| 分片键 | ✅ 适合（均匀分布） | ⚠️ 可能不均匀 |
| 等值查询 | ✅ 支持 | ✅ 支持 |
| 范围查询 | ❌ 不支持 | ✅ 支持 |
| 排序 | ❌ 不支持 | ✅ 支持 |
| 数组字段 | ❌ 不支持（不能是多键索引） | ✅ 支持（多键索引） |

**为什么哈希索引不能是多键索引？**

1. **哈希函数的特性**：哈希函数需要一个确定性的输入值来计算哈希值
2. **数组的复杂性**：数组包含多个元素，无法对整个数组进行单一的哈希计算
3. **多键索引的工作方式**：多键索引为数组中的每个元素创建索引条目，这与哈希索引的单一值要求冲突

```javascript
// 示例：理解为什么不能
db.users.insertOne({
  userId: "user123",
  hobbies: ["读书", "游泳", "编程"]
})

// 哈希索引需要：hash("user123") = 某个哈希值
// 但如果字段是数组：hash(["读书", "游泳", "编程"]) = ?
// 数组的哈希值不确定，无法用于分片

// 多键索引会为每个元素创建索引：
// - hobbies: "读书" → 索引条目1
// - hobbies: "游泳" → 索引条目2
// - hobbies: "编程" → 索引条目3
// 这与哈希索引的单一值要求冲突
```

## 3.3 索引选项

### 唯一索引

```javascript
// 创建唯一索引
db.users.createIndex({ email: 1 }, { unique: true })

// 复合唯一索引
db.users.createIndex({ userId: 1, resourceId: 1 }, { unique: true })
```

### 部分索引（Partial Index）

部分索引只为满足特定条件的文档创建索引，可以节省存储空间和提高性能。

```javascript
// 只为满足条件的文档创建索引
db.users.createIndex(
  { email: 1 },
  { partialFilterExpression: { age: { $gte: 18 } } }
)
// 只为 age >= 18 的用户创建 email 索引

// 查询时会自动使用部分索引
db.users.find({ email: "user@example.com", age: { $gte: 18 } })
// ✅ 可以使用索引

db.users.find({ email: "user@example.com", age: 17 })
// ❌ 不能使用索引（不满足过滤条件）
```

**部分索引的优势**：
- ✅ 节省存储空间：只为部分文档创建索引
- ✅ 提高写入性能：减少索引维护开销
- ✅ 提高查询性能：索引更小，查询更快

**适用场景**：
- 只查询活跃用户（status: "active"）
- 只查询已审核的内容（approved: true）
- 只查询特定时间范围的数据

### 稀疏索引（Sparse Index）

稀疏索引只为存在该字段的文档创建索引，字段为 null 或不存在的文档不会被索引。

```javascript
// 只为存在 email 字段的文档创建索引
db.users.createIndex({ email: 1 }, { sparse: true })

// 示例数据
db.users.insertMany([
  { name: "张三", email: "zhangsan@example.com" },  // ✅ 会被索引
  { name: "李四" },                                  // ❌ 不会被索引（没有 email）
  { name: "王五", email: null }                      // ❌ 不会被索引（email 为 null）
])

// 查询存在 email 的文档
db.users.find({ email: "zhangsan@example.com" })
// ✅ 可以使用稀疏索引

// 查询所有文档（包括没有 email 的）
db.users.find({})
// ⚠️ 可能不会使用稀疏索引（取决于查询优化器）
```

**稀疏索引 vs 部分索引**：
- **稀疏索引**：基于字段是否存在（null 或不存在）
- **部分索引**：基于任意查询条件

```javascript
// 稀疏索引：只为存在 email 的文档创建索引
db.users.createIndex({ email: 1 }, { sparse: true })

// 部分索引：只为 email 不为 null 且 age >= 18 的文档创建索引
db.users.createIndex(
  { email: 1 },
  { partialFilterExpression: { email: { $ne: null }, age: { $gte: 18 } } }
)
```

**稀疏索引的限制**：
- 不能用于唯一索引（除非所有文档都有该字段）
- 查询可能不会使用稀疏索引（如果查询条件不匹配）

### TTL 索引（自动过期）

TTL（Time To Live）索引用于自动删除过期文档，常用于会话、日志、临时数据等场景。

```javascript
// 创建 TTL 索引，文档在 3600 秒（1小时）后自动删除
db.sessions.createIndex(
  { createdAt: 1 },
  { expireAfterSeconds: 3600 }
)

// 示例数据
db.sessions.insertOne({
  userId: "user123",
  token: "abc123",
  createdAt: new Date()  // 1小时后自动删除
})

// MongoDB 后台任务每 60 秒运行一次，删除过期文档
```

**TTL 索引的特点**：
- ✅ 自动删除过期文档，无需手动清理
- ✅ 后台任务每 60 秒运行一次
- ✅ 支持副本集和分片集群
- ⚠️ 删除操作有延迟（最多 60 秒）

**使用场景**：
```javascript
// 1. 用户会话
db.sessions.createIndex(
  { expiresAt: 1 },
  { expireAfterSeconds: 0 }  // expiresAt 字段存储过期时间
)

// 2. 临时数据
db.tempData.createIndex(
  { createdAt: 1 },
  { expireAfterSeconds: 86400 }  // 24小时后删除
)

// 3. 日志数据
db.logs.createIndex(
  { timestamp: 1 },
  { expireAfterSeconds: 2592000 }  // 30天后删除
)
```

**TTL 索引的限制**：
- 索引字段必须是 Date 类型或 Date 数组
- 不能用于复合索引
- 删除操作有延迟（最多 60 秒）
- 如果文档在后台任务运行前被手动删除，TTL 索引不会报错

### 索引名称

```javascript
// 自定义索引名称
db.users.createIndex(
  { age: 1, name: 1 },
  { name: "age_name_index" }
)
```

### 执行计划解读

`explain()` 方法返回详细的查询执行计划，帮助我们了解查询如何执行以及性能如何。

```javascript

// 输出示例
{

    "executionSuccess": true,
    "nReturned": 10,              // 返回的文档数
```

| **SORT_MERGE** | 合并排序 | ✅ 良好 |
| **LIMIT** | 限制结果数量 | ✅ 良好 |
| **SKIP** | 跳过文档 | ⚠️ 中等（如果跳过数量大） |

**详细解读示例**：


### 性能指标详解

**关键指标**：

1. **nReturned（返回文档数）**
   - 查询返回的文档数量
   - 理想情况：只返回需要的文档

2. **executionTimeMillis（执行时间）**
   - 查询执行时间（毫秒）
   - 理想情况：< 100ms

3. **totalKeysExamined（检查的索引键数）**
   - 扫描的索引键数量
   - 理想情况：接近 nReturned

4. **totalDocsExamined（检查的文档数）**
   - 扫描的文档数量
   - 理想情况：等于 nReturned（覆盖索引）

5. **效率比 = nReturned / totalDocsExamined**
   - 越接近 1 越好
   - 1.0 = 完美（每个检查的文档都被返回）
   - < 0.1 = 需要优化

**性能优化建议**：

```javascript
// ❌ 差：效率比低
{
  nReturned: 10,
  totalDocsExamined: 10000,
  效率比: 10/10000 = 0.001
}
// 建议：添加索引或优化查询条件

// ✅ 好：效率比高
{
  nReturned: 10,
  totalDocsExamined: 10,
  效率比: 10/10 = 1.0
}
// 完美：每个检查的文档都被返回

// ✅ 优秀：覆盖索引
{
  nReturned: 10,
  totalKeysExamined: 10,
  totalDocsExamined: 0,  // 不需要读取文档
  效率比: 10/0 = 无限（最佳）
}
```

## 3.6 索引设计原则

### 1. ESR 规则（Equality, Sort, Range）

ESR 规则是 MongoDB 索引设计的最佳实践，按照 **等值查询（Equality）→ 排序（Sort）→ 范围查询（Range）** 的顺序创建复合索引。

**ESR 规则详解**：

```javascript
// 查询示例
db.users.find({
  status: "active",           // E: 等值查询
  age: { $gte: 25 }          // R: 范围查询
}).sort({ createdAt: -1 })   // S: 排序

// 最佳索引顺序：E → S → R
db.users.createIndex({ status: 1, createdAt: -1, age: 1 })
// 顺序：等值查询(status) → 排序(createdAt) → 范围查询(age)
```

**为什么是这个顺序？**

1. **等值查询（E）**：精确匹配，可以快速缩小范围
2. **排序（S）**：索引已排序，直接使用索引排序
3. **范围查询（R）**：范围查询会扫描多个值，放在最后

**实际示例对比**：

```javascript
// 查询：{ status: "active", age: { $gte: 25 }, sort: { createdAt: -1 } }

// ❌ 错误顺序：R → S → E
db.users.createIndex({ age: 1, createdAt: -1, status: 1 })
// 问题：范围查询放在前面，无法有效缩小范围

// ❌ 错误顺序：S → E → R
db.users.createIndex({ createdAt: -1, status: 1, age: 1 })
// 问题：排序放在前面，但等值查询可以更快缩小范围

// ✅ 正确顺序：E → S → R
db.users.createIndex({ status: 1, createdAt: -1, age: 1 })
// 优点：
// 1. 先用 status 精确匹配，快速缩小范围
// 2. 然后使用索引排序（createdAt 已在索引中）
// 3. 最后在范围内过滤 age
```

**多个等值查询**：

```javascript
// 查询：{ status: "active", role: "user", age: { $gte: 25 }, sort: { createdAt: -1 } }
// 多个等值查询都放在前面，按选择性排序（高选择性在前）

db.users.createIndex({ role: 1, status: 1, createdAt: -1, age: 1 })
// 顺序：等值查询(role, status) → 排序(createdAt) → 范围查询(age)
```

**等值查询的选择性排序**：

```javascript
// 高选择性字段（唯一值多）放在前面
// 例如：userId（高选择性）> status（低选择性）

// 查询：{ userId: "user123", status: "active", sort: { createdAt: -1 } }
db.users.createIndex({ userId: 1, status: 1, createdAt: -1 })
// userId 选择性高，放在前面
```

### 2. 覆盖索引

```javascript
// 如果查询只需要索引字段，不需要读取文档
db.users.createIndex({ name: 1, email: 1 })

// 这个查询可以使用覆盖索引
db.users.find({ name: "张三" }, { name: 1, email: 1, _id: 0 })
```

### 3. 索引选择性

```javascript
// 高选择性字段优先（唯一值多的字段）
// 例如：userId（高选择性） > status（低选择性）
db.users.createIndex({ userId: 1, status: 1 })
```

## 3.7 性能优化技巧

### 1. 避免全表扫描

```javascript
// ❌ 差：全表扫描
db.users.find({ $or: [{ name: /张/ }, { email: /@gmail/ }] })

// ✅ 好：使用索引
db.users.createIndex({ name: 1 })
db.users.createIndex({ email: 1 })
```

### 2. 限制返回字段

```javascript
// ❌ 差：返回所有字段
db.users.find({ age: 25 })

// ✅ 好：只返回需要的字段
db.users.find({ age: 25 }, { name: 1, email: 1 })
```

### 3. 使用 limit()

```javascript
// ❌ 差：返回所有匹配的文档
db.users.find({ age: 25 })

// ✅ 好：限制返回数量
db.users.find({ age: 25 }).limit(10)
```

### 4. 避免使用 $regex 开头查询

```javascript
// ❌ 差：无法使用索引
db.users.find({ name: /^张/ })

// ✅ 好：如果可能，使用精确匹配或范围查询
db.users.find({ name: { $gte: "张", $lt: "章" } })
```

### 5. 合理使用 skip()

```javascript
// ❌ 差：大数据集时 skip() 很慢
db.users.find().skip(10000).limit(10)

// ✅ 好：使用范围查询代替 skip()
db.users.find({ _id: { $gt: lastId } }).limit(10)
```
