# 第二十四章：MongoDB 性能调优实战

## 24.1 性能分析工具

### explain() 详解

```javascript
// 查看查询计划
db.users.find({ age: 25 }).explain()

// 执行统计
db.users.find({ age: 25 }).explain("executionStats")

// 所有计划
db.users.find({ age: 25 }).explain("allPlansExecution")
```

### 关键指标解读

```javascript
const explain = db.users.find({ age: 25 }).explain("executionStats");

// 执行时间
explain.executionStats.executionTimeMillis  // 越小越好

// 扫描文档数 vs 返回文档数
const examined = explain.executionStats.totalDocsExamined;
const returned = explain.executionStats.nReturned;
const ratio = returned / examined;  // 越接近 1 越好

// 执行阶段
explain.executionStats.executionStages.stage
// "IXSCAN" - 索引扫描（好）
// "COLLSCAN" - 集合扫描（差）
// "FETCH" - 获取文档
// "SORT" - 排序
```

### 慢查询分析

```javascript
// 启用性能分析
db.setProfilingLevel(1, { slowms: 100 })  // 记录超过 100ms 的查询

// 查看慢查询
db.system.profile.find().sort({ ts: -1 }).limit(10).pretty()

// 分析查询模式
db.system.profile.aggregate([
  {
    $group: {
      _id: "$command.find",
      count: { $sum: 1 },
      avgDuration: { $avg: "$duration" },
      maxDuration: { $max: "$duration" }
    }
  },
  { $sort: { avgDuration: -1 } }
])
```

## 24.2 索引优化

### 索引选择策略

```javascript
// ✅ 好：为常用查询创建索引
// 查询：db.users.find({ email: "..." })
db.users.createIndex({ email: 1 })

// ✅ 好：复合索引匹配查询模式
// 查询：db.users.find({ status: "active", age: { $gte: 18 } }).sort({ createdAt: -1 })
db.users.createIndex({ status: 1, age: 1, createdAt: -1 })

// ❌ 差：创建过多索引
// 每个字段都创建索引会降低写入性能
```

### 覆盖索引

```javascript
// 创建覆盖索引
db.users.createIndex({ email: 1, name: 1 })

// 查询只使用索引字段
db.users.find(
  { email: "user@example.com" },
  { email: 1, name: 1, _id: 0 }
)  // 可以使用覆盖索引，不需要读取文档
```

### 部分索引

```javascript
// 只为活跃用户创建索引
db.users.createIndex(
  { email: 1 },
  { partialFilterExpression: { status: "active" } }
)

// 查询活跃用户可以使用索引
db.users.find({ status: "active", email: "..." })

// 查询非活跃用户不会使用索引（但数据量小）
db.users.find({ status: "inactive", email: "..." })
```

## 24.3 查询优化

### 1. 使用索引字段查询

```javascript
// ✅ 好：使用索引字段
db.users.find({ email: "user@example.com" })  // 使用 email 索引

// ❌ 差：不使用索引
db.users.find({ name: /张/ })  // 全表扫描
```

### 2. 限制返回字段

```javascript
// ✅ 好：只返回需要的字段
db.users.find({ age: 25 }, { name: 1, email: 1 })

// ❌ 差：返回所有字段
db.users.find({ age: 25 })
```

### 3. 使用 limit()

```javascript
// ✅ 好：限制返回数量
db.users.find({ age: 25 }).limit(10)

// ❌ 差：返回所有结果
db.users.find({ age: 25 })
```

### 4. 避免 skip() 大偏移

```javascript
// ❌ 差：skip() 大偏移很慢
db.users.find().skip(10000).limit(10)

// ✅ 好：使用范围查询
db.users.find({ _id: { $gt: lastId } }).limit(10)
```

### 5. 合理使用排序

```javascript
// ✅ 好：排序字段有索引
db.users.find().sort({ createdAt: -1 })  // createdAt 有索引

// ❌ 差：排序字段无索引
db.users.find().sort({ name: 1 })  // name 无索引，需要内存排序
```

## 24.4 写入优化

### 1. 批量操作

```javascript
// ❌ 差：循环插入
for (const user of users) {
  await db.users.insertOne(user);
}

// ✅ 好：批量插入
await db.users.insertMany(users, { ordered: false })
```

### 2. 使用有序批量操作

```javascript
// 有序批量操作（遇到错误停止）
const bulkOps = db.users.initializeOrderedBulkOp();
bulkOps.insert({ name: "用户1" });
bulkOps.insert({ name: "用户2" });
await bulkOps.execute();

// 无序批量操作（继续处理错误）
const bulkOps = db.users.initializeUnorderedBulkOp();
bulkOps.insert({ name: "用户1" });
bulkOps.insert({ name: "用户2" });
await bulkOps.execute({ ordered: false });
```

### 3. 减少索引数量

```javascript
// ⚠️ 注意：每个索引都会降低写入性能
// 只创建必要的索引
```

## 24.5 聚合优化

### 1. 尽早使用 $match

```javascript
// ✅ 好：先过滤再处理
db.orders.aggregate([
  { $match: { status: "completed" } },
  { $group: { ... } }
])

// ❌ 差：先处理再过滤
db.orders.aggregate([
  { $group: { ... } },
  { $match: { status: "completed" } }
])
```

### 2. 使用索引

```javascript
// ✅ 好：为 $match 字段创建索引
db.orders.createIndex({ status: 1, createdAt: -1 })

db.orders.aggregate([
  { $match: { status: "completed", createdAt: { $gte: ... } } },
  { $group: { ... } }
])
```

### 3. 限制中间结果

```javascript
// ✅ 好：使用 $limit 减少处理量
db.orders.aggregate([
  { $match: { ... } },
  { $limit: 1000 },
  { $group: { ... } }
])
```

### 4. 使用 $project 减少字段

```javascript
// ✅ 好：只保留需要的字段
db.orders.aggregate([
  { $match: { ... } },
  { $project: { userId: 1, amount: 1 } },
  { $group: { ... } }
])
```

## 24.7 实际优化案例

### 案例 1：分页查询优化

```typescript
// ❌ 差：使用 skip()
async function getUsers(page: number, pageSize: number) {
  return await User.find()
    .skip((page - 1) * pageSize)
    .limit(pageSize);
}

// ✅ 好：使用游标
async function getUsers(lastId: string, pageSize: number) {
  const query = lastId ? { _id: { $gt: lastId } } : {};
  return await User.find(query)
    .limit(pageSize)
    .sort({ _id: 1 });
}
```

### 案例 2：统计查询优化

```typescript
// ❌ 差：应用层统计
async function getStats() {
  const users = await User.find();
  const activeCount = users.filter(u => u.status === 'active').length;
  const inactiveCount = users.filter(u => u.status === 'inactive').length;
  return { activeCount, inactiveCount };
}

// ✅ 好：数据库层统计
async function getStats() {
  const stats = await User.aggregate([
    {
      $group: {
        _id: '$status',
        count: { $sum: 1 }
      }
    }
  ]);
  
  const activeCount = stats.find(s => s._id === 'active')?.count || 0;
  const inactiveCount = stats.find(s => s._id === 'inactive')?.count || 0;
  return { activeCount, inactiveCount };
}
```

### 案例 3：关联查询优化

```typescript
// ❌ 差：应用层 JOIN
async function getOrdersWithUsers() {
  const orders = await Order.find();
  const userIds = orders.map(o => o.userId);
  const users = await User.find({ _id: { $in: userIds } });
  
  return orders.map(order => ({
    ...order,
    user: users.find(u => u._id.equals(order.userId))
  }));
}

// ✅ 好：使用 $lookup
async function getOrdersWithUsers() {
  return await Order.aggregate([
    {
      $lookup: {
        from: 'users',
        localField: 'userId',
        foreignField: '_id',
        as: 'user'
      }
    },
    { $unwind: '$user' }
  ]);
}
```

## 24.8 监控指标

### 关键指标

```javascript
// 服务器状态
const status = db.serverStatus();

// 操作计数器
status.opcounters  // insert, query, update, delete, getmore

// 连接数
status.connections  // current, available, totalCreated

// 网络流量
status.network  // bytesIn, bytesOut

// 内存使用
status.mem  // resident, virtual, mapped

// 索引使用
status.indexCounters
```

### 性能监控

```typescript
// 定期监控性能指标
setInterval(async () => {
  const status = await db.serverStatus();
  
  console.log('操作统计:', {
    queries: status.opcounters.query,
    inserts: status.opcounters.insert,
    updates: status.opcounters.update,
    deletes: status.opcounters.delete
  });
  
  console.log('连接数:', status.connections.current);
  console.log('内存使用:', status.mem.resident, 'MB');
}, 60000);
```
