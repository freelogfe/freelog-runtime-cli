# 第十七章：MongoDB 副本集详解

## 17.1 副本集基础

### 什么是副本集？

副本集（Replica Set）是一组 MongoDB 实例，维护相同的数据集，提供高可用性和数据冗余。

### 副本集成员类型

| 成员类型 | 说明 | 特点 |
|---------|------|------|
| **Primary** | 主节点 | 处理所有写操作，默认处理读操作 |
| **Secondary** | 从节点 | 复制主节点数据，可处理读操作 |
| **Arbiter** | 仲裁节点 | 不存储数据，只参与选举 |

### 副本集架构

```
        ┌─────────┐
        │ Primary │ ← 写操作
        └────┬────┘
             │
    ┌────────┼────────┐
    │        │        │
┌───▼───┐ ┌──▼───┐ ┌──▼───┐
│Secondary│ │Secondary│ │Arbiter│
└────────┘ └────────┘ └───────┘
    │           │
    └─────┬─────┘
          │
      读操作（可选）
```

## 17.2 副本集部署

### 单节点副本集（开发环境）

```bash
# 1. 启动 MongoDB 并启用副本集
mongod --replSet rs0 --dbpath /data/db --port 27017

# 2. 连接到 MongoDB
mongosh

# 3. 初始化副本集
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "localhost:27017" }
  ]
})

# 4. 查看状态
rs.status()
```

### 多节点副本集（生产环境）

```bash
# 启动三个节点
mongod --replSet rs0 --dbpath /data/db1 --port 27017
mongod --replSet rs0 --dbpath /data/db2 --port 27018
mongod --replSet rs0 --dbpath /data/db3 --port 27019

# 初始化副本集
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "localhost:27017" },
    { _id: 1, host: "localhost:27018" },
    { _id: 2, host: "localhost:27019" }
  ]
})
```

### Windows 配置

```powershell
# 1. 编辑 mongod.cfg
replication:
  replSetName: "rs0"

# 2. 重启 MongoDB 服务
Restart-Service MongoDB

# 3. 初始化副本集
mongosh
rs.initiate({
  _id: "rs0",
  members: [{ _id: 0, host: "localhost:27017" }]
})
```

## 17.3 副本集操作

### 查看状态

```javascript
// 查看副本集状态
rs.status()

// 查看配置
rs.conf()

// 查看成员信息
rs.isMaster()
```

### 添加成员

```javascript
// 添加从节点
rs.add("localhost:27018")

// 添加带优先级的成员
rs.add({
  _id: 2,
  host: "localhost:27019",
  priority: 2  // 优先级（影响选举）
})

// 添加仲裁节点
rs.addArb("localhost:27020")
```

### 移除成员

```javascript
// 移除成员
rs.remove("localhost:27018")

// 或使用配置
cfg = rs.conf()
cfg.members = cfg.members.filter(m => m.host !== "localhost:27018")
rs.reconfig(cfg)
```

### 修改成员配置

```javascript
// 修改成员优先级
cfg = rs.conf()
cfg.members[0].priority = 10
rs.reconfig(cfg)

// 设置成员为隐藏节点
cfg = rs.conf()
cfg.members[1].hidden = true
cfg.members[1].priority = 0
rs.reconfig(cfg)

// 设置延迟从节点
cfg = rs.conf()
cfg.members[1].priority = 0
cfg.members[1].slaveDelay = 3600  // 延迟 1 小时
rs.reconfig(cfg)
```

## 17.4 读写操作

### 写操作

```javascript
// 写操作自动路由到主节点
db.users.insertOne({ name: "张三" })

// 写关注（Write Concern）
db.users.insertOne(
  { name: "张三" },
  { writeConcern: { w: "majority", wtimeout: 5000 } }
)

// 写关注选项
// w: 1 - 等待主节点确认
// w: "majority" - 等待大多数节点确认
// w: 2 - 等待 2 个节点确认
```

### 读操作

```javascript
// 默认从主节点读取
db.users.find()

// 从从节点读取（需要设置 readPreference）
db.users.find().readPref("secondary")

// 读偏好选项
// primary - 从主节点读取（默认）
// primaryPreferred - 优先主节点，不可用时从从节点
// secondary - 从从节点读取
// secondaryPreferred - 优先从节点，不可用时从主节点
// nearest - 从延迟最低的节点读取
```

### 应用层配置

```typescript
// Mongoose
mongoose.connect(uri, {
  readPreference: 'secondaryPreferred',
  readPreferenceTags: [{ region: 'us-east' }]
});

// 原生驱动
const client = new MongoClient(uri, {
  readPreference: 'secondaryPreferred'
});
```

## 17.5 故障转移

### 自动故障转移

```javascript
// 当主节点故障时，副本集自动选举新的主节点
// 选举条件：
// 1. 大多数节点可用
// 2. 新主节点数据最新
// 3. 优先级最高（如果相同，则选择 _id 最小的）

// 查看当前主节点
rs.isMaster()

// 强制重新选举（需要大多数节点同意）
rs.stepDown()
```

### 手动故障转移

```javascript
// 1. 在主节点执行
rs.stepDown(60)  // 60 秒内不参与选举

// 2. 或直接关闭主节点
// 副本集会自动选举新的主节点
```

## 17.6 数据同步

### Oplog（操作日志）

```javascript
// 查看 oplog
use local
db.oplog.rs.find().sort({ ts: -1 }).limit(10)

// oplog 大小配置
// 默认大小：可用磁盘空间的 5%
// 最小：990MB
// 最大：50GB

// 查看 oplog 大小
db.oplog.rs.stats()
```

### 同步延迟

```javascript
// 检查从节点延迟
rs.printSlaveReplicationInfo()

// 查看同步状态
rs.status().members.forEach(member => {
  print(`Member: ${member.name}`);
  print(`State: ${member.stateStr}`);
  print(`Lag: ${member.optimeDate - member.lastHeartbeat}`);
});
```

## 17.7 副本集配置

### 优先级配置

```javascript
cfg = rs.conf()
cfg.members[0].priority = 10  // 主节点优先级
cfg.members[1].priority = 5   // 从节点优先级
cfg.members[2].priority = 0   // 不参与选举
rs.reconfig(cfg)
```

### 隐藏节点

```javascript
// 隐藏节点不参与选举，不处理读请求
cfg = rs.conf()
cfg.members[1].hidden = true
cfg.members[1].priority = 0
rs.reconfig(cfg)

// 从隐藏节点读取（需要明确指定）
db.users.find().readPref("secondary", [{ hidden: true }])
```

### 延迟从节点

```javascript
// 延迟从节点用于数据恢复
cfg = rs.conf()
cfg.members[1].priority = 0
cfg.members[1].slaveDelay = 3600  // 延迟 1 小时
rs.reconfig(cfg)
```

### 标签集（Tag Sets）

```javascript
// 为成员添加标签
cfg = rs.conf()
cfg.members[0].tags = { region: "us-east", dc: "nyc" }
cfg.members[1].tags = { region: "us-west", dc: "sf" }
rs.reconfig(cfg)

// 使用标签读取
db.users.find().readPref("secondary", [{ region: "us-west" }])
```

## 17.8 监控和维护

### 健康检查

```javascript
// 检查副本集状态
function checkReplicaSetHealth() {
  const status = rs.status();
  
  const primary = status.members.find(m => m.stateStr === "PRIMARY");
  const secondaries = status.members.filter(m => m.stateStr === "SECONDARY");
  
  console.log("主节点:", primary?.name);
  console.log("从节点数量:", secondaries.length);
  console.log("健康状态:", primary ? "正常" : "异常");
  
  // 检查延迟
  secondaries.forEach(secondary => {
    const lag = primary.optimeDate - secondary.optimeDate;
    console.log(`${secondary.name} 延迟: ${lag}ms`);
  });
}
```

### 性能监控

```javascript
// 监控副本集性能
db.serverStatus().repl

// 查看复制统计
db.serverStatus().opcounters

// 监控 oplog
db.oplog.rs.find().sort({ ts: -1 }).limit(1)
```

## 17.9 常见问题

### 问题 1：无法初始化副本集

```javascript
// 错误：This node was not started with replication enabled
// 解决：在 mongod.cfg 中添加
replication:
  replSetName: "rs0"
```

### 问题 2：选举失败

```javascript
// 原因：节点数量不足（需要大多数节点）
// 解决：确保有奇数个节点，或添加仲裁节点

// 3 个节点：需要 2 个可用
// 4 个节点：需要 3 个可用
// 5 个节点：需要 3 个可用
```

### 问题 3：从节点无法同步

```javascript
// 检查从节点状态
rs.status()

// 检查网络连接
rs.status().members.forEach(m => {
  print(`${m.name}: ${m.lastHeartbeat}`);
});

// 重新同步
// 在从节点执行
rs.syncFrom("primary:27017")
```

## 17.10 最佳实践

### 1. 节点数量

```javascript
// ✅ 好：使用奇数个节点（3、5、7）
// 避免脑裂问题

// ❌ 差：使用偶数个节点（2、4、6）
// 需要添加仲裁节点
```

### 2. 写关注

```typescript
// ✅ 好：使用 majority 写关注
await collection.insertOne(data, {
  writeConcern: { w: "majority" }
});
```

### 3. 读偏好

```typescript
// ✅ 好：读操作使用 secondaryPreferred
mongoose.connect(uri, {
  readPreference: 'secondaryPreferred'
});
```

### 4. 监控

```typescript
// ✅ 好：定期检查副本集状态
setInterval(() => {
  const status = rs.status();
  // 检查主节点、从节点状态
}, 60000);
```
