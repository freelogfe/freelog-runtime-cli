# 使用指南

> 讲解与评审请用 **[脚手架对齐Console完整方案.md](./脚手架对齐Console完整方案.md)**（含完整流程与命令表）。  
> 核心原则：**先 `pull` 同步线上，再执行写命令**；不要手改配置文件。

## 1. 快速开始

### 安装与登录

```bash
npm install -g @freelog-cli/cli
freelog-cli login
freelog-cli --test login    # 测试环境
```

若系统存在旧版 CLI，请用 `freelog-cli2`，详见 [开发维护.md](./开发维护.md)。

### 初始化主题项目

```bash
freelog-cli init my-theme
# 选择：主题 → vite-vue-ts → pnpm
cd my-theme && pnpm install
pnpm run start    # 本地开发
pnpm run build    # 构建 dist
```

生成 `freelog.resource.config` + `freelog.version.config`，主题入口为 `window.mount` / `window.unmount`。

### 首次发布流程

```bash
freelog-cli create
freelog-cli updateVersion --version 1.0.0 --description "初始版本" --filePath ./dist
freelog-cli publish
freelog-cli policy add      # 上架前必须
freelog-cli update --intro "介绍" --tags "Vue,主题"
freelog-cli online
```

### 发新版（线上可能已超前）

```bash
freelog-cli status              # 检查漂移（待实现）
freelog-cli pull                # 同步线上最新（syncr + syncv）
pnpm build
freelog-cli updateVersion --version 1.1.0 --filePath ./dist
freelog-cli publish
```

### 合集与批量

```bash
freelog-cli init my-collection          # 选「合集」
freelog-cli collection create
freelog-cli batch create && batch publish
freelog-cli batch add-to-collection
```

详见 [命令参考/合集资源.md](./命令参考/合集资源.md)、[命令参考/批量资源.md](./命令参考/批量资源.md)。

## 2. 配置文件

CLI 用本地配置文件代替控制台向导状态，类型定义在 `public/` 目录。

| 文件 | 场景 |
|------|------|
| `freelog.resource.config` | 单品：资源元信息、策略、上架状态 |
| `freelog.version.config` | 单品：版本号、构建路径、依赖 |
| `freelog.collection.config` | 合集：元信息 + `items` + `catalogueProperty` |
| `freelog.batch-resources.config` | 批量：`defaults` + `resources[]` |

### resource.config 主要字段

| 字段 | 说明 |
|------|------|
| `resourceId` | `create` 后平台回填 |
| `resourceName` / `resourceTitle` | 授权标识与标题 |
| `resourceType` / `resourceTypeCode` | 类型名称与代码 |
| `intro` / `coverImages` / `tags` | 简介、封面、标签 |
| `policies` | 授权策略，上架前至少一条启用 |
| `status` | `0` 待发行 / `1` 上架 / `4` 下架 |

### version.config 主要字段

| 字段 | 说明 |
|------|------|
| `version` / `description` | 版本号与描述 |
| `filePath` | 构建产物路径，如 `./dist` |
| `dependencies` | 依赖声明 `{ resourceId, versionRange }` |
| `fileSha1` / `versionId` | `publish` 后自动回填 |

主题/插件发布时，`publish` 自动将 `filePath` 目录 ZIP 压缩上传。

### 命令与配置的对应

| 命令 | 写入的配置 |
|------|-----------|
| `create` | resource → `resourceId` |
| `updateVersion` | version → `version` / `filePath` |
| `publish` | version → `versionId` / `fileSha1` |
| `policy add` | resource → `policies` |
| `update` / `online` | resource → `intro` / `tags` / `status` |
| `dep add` | version → `dependencies` |
| `syncr` / `syncv` | 从平台拉取覆盖本地 |

## 3. 与控制台对齐

控制台三条创建流程与 CLI 的对应关系：

| 控制台 | CLI 配置 | CLI 命令 |
|--------|---------|---------|
| `creator` 单品 | resource + version | `create` → `publish` → `policy` → `online` |
| `collectionCreator` 合集 | collection + batch | `collection` + `batch` |
| `creatorBatch` 批量 | batch-resources | `batch init/create/publish` |

### 单品 creator 四步

| 控制台步骤 | CLI |
|-----------|-----|
| Step1 创建授权条目 | `create` |
| Step2 上传资源文件 | `updateVersion` + `publish` |
| Step3 添加授权策略 | `policy add` |
| Step4 完善信息并上架 | `update` + `online` |

### 核心差异

- CLI 拆成**配置文件 + 独立命令**，不强制按步骤顺序执行
- CLI 额外提供**代码脚手架**（vite 模板 + freelog-runtime），控制台不管代码仓库
- 合集 Step2 的 RSS 导入、自动收录等能力，CLI 目前通过 `batch` 配置文件实现，交互不同但 API 对齐

沟通时可说：「对齐 creator Step2」= 关注 `version.config` + `publish`；「对齐 collectionCreator Step2」= 关注 `collection.items` + `batch`。

## 4. 常用命令

| 场景 | 命令 |
|------|------|
| 登录状态 | `freelog-cli status` |
| 同步平台数据 | `freelog-cli syncr` / `syncv` |
| 添加依赖 | `freelog-cli dep add <资源ID>` |
| 下架 | `freelog-cli offline` |
