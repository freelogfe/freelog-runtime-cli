## 公共行为（每条命令默认遵守）

| 项 | 定稿 |
|----|------|
| 交互 | 无 TTY 或 `--yes` 不得 `inquirer`；缺参 exit 4 |
| 输出 | 人读 → stderr 进度 + stdout 结果；`--json` 时 stdout 纯 JSON |
| 写盘 | 原子写 config；不写 token |
| 错误 | `CliError.code` → 进程退出码；带 hint |
| 临时文件 | `finally` 清理 |

## 规格模板（每条命令）

```text
命令:
前置: ensureOwner? ensureSynced? 校验?
步骤: 有序列表
API: Method Path（或内部 service）
写回: 哪些 config 字段
退出码: 0/2/3/4/5/1
选项: 必填 / 可选
非交互: 所需 flags 列表
```

## 1. 全局

### `status`

| 项 | 定稿 |
|----|------|
| 前置 | 可读本地 config；可选打平台 |
| 步骤 | 读 auth → 若有 resourceId 则 info → 比对 owner/同步/平台发版草稿 |
| API | `GET …/resources/{id}`（info）；`GET …/versions/drafts`（草稿有无） |
| 输出 | 人读 + `--json`：owner、sync、`platformVersionDraft`、`localDraftSync` |
| 退出码 | 0；未登录可 2（若约定 status 允许未登录则 0+提示） |

### `pull`

| 项 | 定稿 |
|----|------|
| 前置 | 已登录；有 resourceId（或 `--collection`） |
| 步骤 | info（+ 最新 version / collection draft items）→ **覆盖**本地缓存（含 owner） |
| API | info；`resourceVersionInfo1`；合集 draft items / collectRules |
| 写回 | resource/version/collection config |
| 选项 | `--version` `--collection` `--all` `--cwd` |
| 备注 | **删除**用户向 `syncr`/`syncv`；内部可复用旧实现但不暴露 |

### `init` / `login` / `logout`

保持现有能力；`init` **不写** owner。

## 2. 单品主路径

### `create`

| 项 | 定稿 |
|----|------|
| 前置 | 已登录；目录无 resourceId 或允许覆盖策略（定稿：已有 id 则 exit 4） |
| 校验 | [字段约束](./03-字段约束.md) §1 |
| API | `POST` create（及 `--from-dir` 时 createBatch 或循环 create） |
| 写回 | resourceId、owner、listing 初值 |
| 选项 | `--title` `--type` `--name` 全 flags；`--from-dir`；`--yes` |

### `updateVersion`

| 项 | 定稿 |
|----|------|
| 前置 | ensureOwner + ensureSynced |
| 步骤 | **只写本地** version.config；**不**调草稿 API、不改 draftSync |
| 写回 | version / description / filePath / deps 等意图字段 |
| 备注 | 跨端续编必须用户显式 `draft push` |

### `publish`

| 项 | 定稿 |
|----|------|
| 前置 | Owner + Sync；字段约束 §2；版本号未占用；授权完整 |
| 步骤 | 处理 filePath（压缩/上传）→ `createVersion` → 写回 versionId/sha1 → 清空一次性 publish 字段 |
| API | upload / files；`POST …/versions` |
| 退出码 | 未授权 **5**；校验 **4**；冲突 **3** |
| 选项 | `--bump` `--yes`；**禁止** `--draft`（改走 `draft push`） |

### `draft push` / `pull` / `discard`

完整算法与字段映射 → **[04-草稿转换层.md](./04-草稿转换层.md)**（§7–§8）。摘要：

| 命令 | 要点 |
|------|------|
| push | lookDraft → 冲突判定 →（可选 `--upload`）→ toDraftData → POST drafts → 更新 draftSync |
| pull | lookDraft → applyDraft → 保留 filePath → 更新 draftSync；无草稿 exit 4 |
| discard | DELETE drafts → 清 draftSync |

### `update` / `policy add|list` / `online` / `offline`

| 命令 | API | 要点 |
|------|-----|------|
| `update` | `update` listing | Owner+Sync；字段约束 |
| `policy add` | update addPolicies | **`--from-file` 主路径**；policyText encode；名 2–20 |
| `policy list` | 读缓存/平台 | `--json`；启用/停用走 updatePolicies |
| `online` | **resourceOnline** 语义 | 须 latestVersion + 启用策略；否则 exit 4；不代建策略 |
| `offline` | status=4 | `--yes` |

### `dep add|remove|list|update`

| 项 | 定稿 |
|----|------|
| 写 | 改本地 dependencies（随下版 publish）；Owner+Sync |
| `list` | 可读平台依赖树；`--json` / `--tree` |
| 签约 | 不在 dep add 内嵌微应用；缺口在 publish 时 exit 5 |

### `version edit`

| 项 | 定稿 |
|----|------|
| 前置 | Owner+Sync；目标版本已存在 |
| API | `updateResourceVersionInfo` |
| 范围 | 已发行版本元数据；**不**升版本、不换文件 |

### `dep auth`（后期）

`--policy-map <file>` → batchCreate/SignContracts；非 P0。

## 3. 合集

| 命令 | API 要点 | 备注 |
|------|----------|------|
| `collection create` | create subjectType=4 | 写 owner |
| `item add/remove/update/reorder` | catalogues/drafts/* | item add 允许他人 resourceId；本地路径则校该资源 owner |
| `collection update` | update + catalogueProperty | `--display-*` 枚举见页面覆盖文档 |
| `collection publish` | updateCollection isMergeCatalogueDraft | 授权门禁同单品 |
| `collect-rules *` | setCollectRules | 声明式 |
| `rss bind/sync` | bindRssFeed / syncBinding | bind 必须 `--code` |
| `logs` | getCollectionUpdateLogs | P2 |

---

## 4. 明确删除（实现时不要保留用户入口）

| 旧入口 | 处理 |
|--------|------|
| `batch *` | 删除用户命令面；多资源用 `--from-dir` / 循环 `--cwd` |
| `syncr` / `syncv` | 删除；统一 `pull` |
| `publish --draft` | 删除；用 `draft push` |

---

## 5. 开写顺序（建议）

1. API drafts POST/GET/DELETE + ensureOwner/ensureSynced 底座  
2. `pull` / `status --json`  
3. `create`/`update`/`publish`/`online` 接字段约束  

4. `draft *` + adapter（04）  
5. 合集 item/publish/rss  
6. `dep auth --policy-map`
