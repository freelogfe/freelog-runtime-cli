## 命令概览

| 命令 | 功能 | 参数 | 选项 |
|------|------|------|------|
| `dep add <resourceIdOrName>` | 添加依赖 | 资源ID或名称（可选版本：`resourceId@1.0.0`） | `-sv, --select-version`: 交互式选择版本<br>`-c, --config <path>`: 指定配置文件路径 |
| `dep remove <resourceIdOrName>` | 移除依赖 | 资源ID或名称 | `-c, --config <path>`: 指定配置文件路径 |
| `dep list` | 查看依赖列表 | 无 | `--tree`: 以树形结构显示<br>`-c, --config <path>`: 指定配置文件路径 |
| `dep update <resourceIdOrName>` | 更新依赖版本 | 资源ID或名称 | `-sv, --select-version`: 交互式选择版本<br>`-c, --config <path>`: 指定配置文件路径 |
| `dep change <resource>` | 修改依赖配置 | 资源ID或名称 | `-c, --config <path>`: 指定配置文件路径 |
| `dep sync [version]` | 同步依赖版本 | 可选：`latest` 或不传 | `-c, --config <path>`: 指定配置文件路径 |

## 数据结构

### Dependency（依赖）

```typescript
interface Dependency {
  resourceId: string;        // 资源ID（必填）
  resourceName?: string;      // 资源名称（可选）
  versionRange: string;       // 版本范围，如 "1.0.0", "^1.0.0", "*" 等
}
```

### BaseUpcastResource（上抛资源）

```typescript
interface BaseUpcastResource {
  resourceId: string;        // 资源ID
  resourceName: string;      // 资源名称
}
```

### VersionConfig（版本配置）

依赖信息存储在 `freelog.version.config.js/ts` 文件中：

```typescript
interface VersionConfig {
  resourceId?: string;
  version?: string;
  dependencies?: Dependency[];              // 依赖列表
  baseUpcastResources?: BaseUpcastResource[]; // 上抛资源列表
  // ... 其他字段
}
```

## 命令详细说明

### dep add - 添加依赖

**功能**：向项目中添加一个新的依赖资源，包括签约、支付和配置保存。

**执行流程**：

1. **认证检查**
   - 检查用户是否已登录（`requireAuth()`）
   - 显示当前登录用户信息并确认（`confirmAuth()`）

2. **解析资源标识符**
   - 支持格式：`resourceId` 或 `resourceId@1.0.0`
   - 解析出资源ID和可选版本号

3. **获取资源信息**
   - 调用 `getResourceInfo()` 获取资源详情
   - 显示资源名称、类型、描述等信息

4. **获取当前项目信息**
   - 从 `version.config` 或 `resource.config` 读取当前项目的 `resourceId`
   - 如果存在，获取当前项目的版本列表

5. **处理上抛资源（baseUpcastResources）**
   - 如果当前项目有版本，获取项目资源信息并更新 `baseUpcastResources`
   - 判断要添加的依赖是否在上抛资源列表中
   - 如果在上抛列表中，标记为可上抛；否则不允许上抛

6. **确定依赖版本**
   - 如果命令行指定了版本，使用指定版本
   - 否则询问用户是否使用最新版本（`*`）
   - 如果不使用最新版本，获取版本列表供用户选择
   - 版本格式：`^版本号`（如 `^1.0.0`）

7. **检查依赖是否已存在**
   - 如果已存在，询问是否覆盖
   - 如果用户选择不覆盖，终止操作

8. **确认添加**
   - 询问用户是否继续添加

9. **处理上抛资源的签约和支付**
   - 如果依赖在上抛资源列表中，先处理所有上抛资源的签约和支付
   - 对每个上抛资源：
     - 检查授权状态（`checkResourceAuth()`）
     - 如果已授权，跳过
     - 如果未授权，获取策略列表
     - 用户选择策略
     - 创建合约（`createContract()`）
     - 处理支付（`processPayment()`）
     - 如果主资源有上抛资源，必须完成签约（不允许跳过）

10. **处理主资源的签约和支付**
    - 检查授权状态
    - 如果未授权，执行签约和支付流程
    - 如果主资源没有上抛资源，允许跳过签约

11. **保存依赖到配置文件**
    - 调用 `addDependency()` 保存到 `version.config`
    - 如果依赖已存在，更新版本范围；否则添加新依赖

**关键业务规则**：

- **上抛资源**：如果当前项目的版本列表不为空，且依赖在上抛资源列表中，必须先处理上抛资源的签约和支付
- **版本格式**：支持 `*`（最新版本）、`^1.0.0`（兼容版本）、`1.0.0`（精确版本）
- **重复检查**：添加前检查依赖是否已存在，如果存在可选择覆盖

### dep remove - 移除依赖

**功能**：从配置文件中移除指定的依赖。

**执行流程**：

1. **认证检查**
   - 检查登录状态并确认用户信息

2. **加载依赖列表**
   - 从 `version.config` 加载所有依赖

3. **查找要移除的依赖**
   - 通过 `resourceId` 查找依赖
   - 如果未找到，提示错误并退出

4. **显示依赖信息**
   - 显示资源ID、版本范围等信息

5. **确认移除**
   - 询问用户是否确认移除

6. **移除依赖**
   - 调用 `removeDependency()` 从配置文件中移除
   - 保存配置文件

**关键业务规则**：

- 只能通过 `resourceId` 查找依赖（不支持资源名称）
- 移除操作不可逆，需要用户确认

---

### dep list - 查看依赖列表

**功能**：查看当前项目的所有依赖信息，支持树形结构显示。

**执行流程**：

1. **认证检查**
   - 检查登录状态并确认用户信息

2. **加载配置**
   - 加载 `resource.config` 和 `version.config`
   - 获取依赖列表

3. **获取依赖树**
   - 调用 `getResourceDependencyTree()` 获取完整的依赖树结构
   - 参数包括：资源ID、版本号、最大深度、是否包含根节点

4. **显示依赖信息**
   - 显示直接依赖列表（资源ID、版本范围）
   - 如果指定 `--tree` 选项，显示完整的依赖树结构

5. **统计信息**
   - 显示依赖总数

**关键业务规则**：

- 依赖树通过 API 获取，显示完整的依赖关系（包括间接依赖）
- 树形结构使用 `└──` 和 `├──` 符号表示层级关系

---

### dep update - 更新依赖版本

**功能**：更新指定依赖的版本范围。

**执行流程**：

1. **认证检查**
   - 检查登录状态并确认用户信息

2. **加载并查找依赖**
   - 从配置文件中加载依赖列表
   - 通过 `resourceId` 查找要更新的依赖
   - 如果未找到，提示错误并退出

3. **显示当前依赖信息**
   - 显示资源ID和当前版本范围

4. **获取可用版本列表**
   - 调用 `getResourceVersionInfoList()` 获取资源的版本列表
   - 显示前10个版本（版本号、创建日期）

5. **选择更新方式**
   - 如果指定了 `-sv, --select-version` 选项，进入交互式选择
   - 否则询问用户选择更新方式：
     - **指定具体版本**：从版本列表中选择
     - **使用版本范围**：手动输入版本范围（如 `^1.0.0`, `~2.3.0`）
     - **使用最新版本**：自动使用版本列表的第一个版本

6. **显示更新信息**
   - 显示原版本范围和新版本范围

7. **确认更新**
   - 询问用户是否确认更新

8. **更新配置**
   - 调用 `updateDependencyVersion()` 更新配置文件
   - 保存配置文件

**关键业务规则**：

- 支持三种更新方式：具体版本、版本范围、最新版本
- 版本范围格式：`^1.0.0`（兼容版本）、`~2.3.0`（小版本范围）、`1.0.0`（精确版本）

---

### dep change - 修改依赖配置

**功能**：修改依赖的版本范围（`update` 命令的别名）。

**执行流程**：

- 直接调用 `executeUpdate()` 函数
- 与 `dep update` 命令功能完全相同

**关键业务规则**：

- 这是 `dep update` 的别名，提供更语义化的命令名称

---

### dep sync - 同步依赖版本

**功能**：批量检查并同步所有依赖的版本，支持检查更新、更新到最新版本、交互式选择版本。

**执行流程**：

1. **认证检查**
   - 检查登录状态并确认用户信息

2. **加载依赖列表**
   - 从 `version.config` 加载所有依赖

3. **确定同步模式**
   - 如果参数为 `latest`：直接同步到最新版本
   - 如果参数为具体版本号：提示错误（暂不支持）
   - 如果不传参数：交互式选择模式
     - **检查更新**：仅查看，不修改
     - **同步到最新版本**：批量更新所有依赖到最新版本
     - **交互式选择版本**：逐个选择每个依赖的版本

4. **获取所有依赖的同步信息**
   - 对每个依赖：
     - 获取资源信息（包含最新版本）
     - 检查授权状态
     - 判断是否有更新（当前版本 vs 最新版本）
     - 构建同步信息对象

5. **显示同步信息**
   - 显示每个依赖的当前版本、最新版本、是否有更新、授权状态

6. **根据模式执行操作**
   - **检查更新模式**：仅显示信息，不修改配置
   - **同步到最新版本模式**：
     - 询问用户是否确认批量更新
     - 批量更新所有依赖到最新版本
     - 保存配置文件
   - **交互式选择模式**：
     - 逐个询问每个依赖的更新方式
     - 用户可以选择跳过、更新到最新、指定版本等
     - 批量保存更新

**关键业务规则**：

- **版本比较逻辑**：
  - 如果当前版本为 `*` 或包含最新版本，认为是最新
  - 否则进行版本号比较（简单字符串比较，实际应使用 semver）
- **授权检查**：检查每个依赖的授权状态，但授权状态不影响同步操作
- **批量操作**：支持批量更新所有依赖到最新版本，提高效率

## 关键业务逻辑

### 1. 上抛资源（baseUpcastResources）处理

**概念**：上抛资源是指当前项目依赖的资源，这些资源需要被"上抛"到父级资源中。

**处理逻辑**：
- 在 `dep add` 命令中，如果当前项目有版本，会获取项目的 `baseUpcastResources` 列表
- 如果要添加的依赖在上抛资源列表中，必须先处理上抛资源的签约和支付
- 如果主资源有上抛资源，必须完成签约（不允许跳过）

**潜在问题**：
- 上抛资源的判断逻辑可能不够清晰
- 上抛资源的签约和支付流程可能与主资源混淆

### 2. 版本范围格式

**支持的格式**：
- `*`：最新版本
- `^1.0.0`：兼容版本（1.x.x，但不包括 2.0.0）
- `~2.3.0`：小版本范围（2.3.x，但不包括 2.4.0）
- `1.0.0`：精确版本

**潜在问题**：
- 版本比较使用简单字符串比较，可能不准确
- 应该使用 `semver` 库进行版本比较和范围解析

### 3. 依赖查找逻辑

**当前实现**：
- `dep remove`、`dep update` 等命令通过 `resourceId` 查找依赖
- 不支持通过资源名称查找

**潜在问题**：
- 用户可能需要通过资源名称查找依赖
- 命令参数名为 `resourceIdOrName`，但实际只支持 `resourceId`

### 4. 配置文件路径处理

**当前实现**：
- 所有命令都支持 `-c, --config <path>` 选项
- 如果不指定，使用默认路径查找配置文件

**潜在问题**：
- 配置文件路径解析逻辑可能不一致
- 需要确认在不同命令中路径解析是否一致

### 5. 授权检查

**当前实现**：
- `dep add` 命令会检查资源的授权状态
- `dep sync` 命令会检查授权状态但不影响同步操作

**潜在问题**：
- 授权检查失败时的处理逻辑可能不够完善
- 未授权的依赖是否可以添加到配置中？

## 潜在问题与改进建议

### 1. 版本比较不准确

**问题**：当前使用简单字符串比较版本号，可能不准确。

**建议**：使用 `semver` 库进行版本比较和范围解析。

```typescript
import semver from 'semver';

// 比较版本
semver.gt('1.2.0', '1.1.0'); // true

// 检查版本是否满足范围
semver.satisfies('1.2.0', '^1.0.0'); // true
```

### 2. 依赖查找只支持 resourceId

**问题**：命令参数名为 `resourceIdOrName`，但实际只支持 `resourceId`。

**建议**：
- 如果输入的是资源名称，先通过 API 查询获取 `resourceId`
- 或者明确文档说明只支持 `resourceId`

### 3. 上抛资源逻辑不清晰

**问题**：上抛资源的判断和处理逻辑可能不够清晰。

**建议**：
- 添加更详细的日志说明上抛资源的处理过程
- 明确上抛资源与普通依赖的区别
- 优化上抛资源的签约和支付流程

### 4. 错误处理不完善

**问题**：某些错误情况可能没有完善的错误提示。

**建议**：
- 统一错误处理机制
- 提供更友好的错误提示和解决建议
- 添加错误日志记录

### 5. 批量操作确认

**问题**：`dep sync latest` 批量更新所有依赖，可能影响较大。

**建议**：
- 添加更明确的确认提示
- 显示将要更新的依赖列表
- 支持预览模式（dry-run）

### 6. 依赖树显示优化

**问题**：依赖树显示可能不够清晰。

**建议**：
- 优化树形结构的显示格式
- 添加颜色区分不同类型的依赖
- 支持展开/折叠功能

## 总结

本文档详细描述了所有依赖管理命令的业务逻辑。主要特点：

1. **功能完整**：支持添加、移除、查看、更新、同步依赖
2. **交互友好**：提供交互式选择，用户体验良好
3. **业务复杂**：涉及签约、支付、上抛资源等复杂业务逻辑

**需要改进的地方**：
- 版本比较应使用 `semver` 库
- 依赖查找应支持资源名称
- 上抛资源逻辑需要更清晰的文档和实现
- 错误处理需要更完善

建议根据实际使用情况，逐步优化这些命令的实现。
