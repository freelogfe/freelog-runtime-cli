# Freelog CLI 产品与测试简明说明

本文面向产品经理和测试人员，用于快速理解新 CLI 要解决什么问题、和 Console 有什么差异、测试时重点验证什么。

## 1. 产品目标

Freelog CLI 是面向开发者和运营脚本的资源发行工具。它不替代 Console 页面，而是把 Console 中“创建资源、发布版本、维护策略、上下架、管理合集目录”等能力拆成可重复执行的命令。

核心目标：

1. 支持主题/插件项目打包后发布。
2. 支持单个图片、视频等文件作为独立资源发布。
3. 支持文件夹批量发布为多个独立资源。
4. 支持文件夹作为合集目录发布。
5. 支持资源更新：基础信息更新、版本更新、草稿同步、策略启停、上下架。
6. 和 Console 使用同一套平台接口与业务规则，结果对齐 Console。

## 2. 关键概念

| 概念 | 说明 |
|---|---|
| `freelog.manifest.json` | 本地用户意图：资源名、类型、标题、下一版文件、合集版本等。可以提交 git。 |
| `.freelog/state.json` | 平台事实缓存：resourceId、owner、latestVersion、策略、同步指纹等。不提交 git。 |
| 资源壳 | 已在平台创建资源，但还没有发布版本。 |
| 正式版本 | 通过 `publish` 或 `collection publish` 发布到平台的版本。 |
| 策略 | 资源上架前必须至少有一条启用策略。发布版本本身不要求已有策略。 |
| 上架 | 只能通过 `online`，并严格检查 latestVersion 和启用策略。 |

环境规则：

- manifest 不绑定环境，可以复用到 dev/test/prod。
- state 绑定环境。一个目录写入 dev state 后，用 test/prod 读取会失败，避免串资源。

## 3. 与 Console 的主要差异

| Console | CLI | 差异原因 |
|---|---|---|
| 四步向导串联创建、发版、策略、上架 | 拆成多个命令执行 | CLI 要支持脚本化、重试和 CI |
| 页面打开即加载并编辑远端状态 | `status` 查看，`pull` 显式同步 | 避免命令静默改本地文件 |
| 自动保存发版草稿 | `draft push/pull/discard` 显式操作 | 避免后台隐式写远端草稿 |
| 可能存在软上架入口 | `online` 严格门禁 | 防止缺版本或缺策略的资源被上架 |
| 策略 Builder 页面交互 | `policy apply --from-file` 新增策略，`policy set` 启停策略 | CLI 适合声明式输入，不做复杂 Builder |
| 依赖授权微应用 | CLI 只处理声明式免费策略签约，复杂/付费回 Console | 支付和复杂确认不适合纯 CLI |
| 合集目录和发版表单在同一页面 | `collection item *` 管目录草稿，`draft --collection` 管发版草稿 | 两类草稿不是同一种业务对象 |

这些差异是有意设计，不是功能缺失。

## 4. 典型业务流程

### 4.1 主题或插件项目发布

适用于用户已有 React 主题项目、Vue 插件项目，或通过 CLI 模板创建的新项目。

```bash
freelog-cli init . --scaffold none --resource-type <主题或插件typeCode> --runtime 0.5 --yes --env dev
freelog-cli create --yes --env dev
freelog-cli version set --version 1.0.0 --file dist --runtime 0.5 --env dev
freelog-cli publish --yes --env dev
freelog-cli policy apply --from-file ./policy.json --yes --env dev
freelog-cli online --yes --env dev
```

验收重点：

- `create` 后平台有资源壳。
- `publish` 后平台 latestVersion 更新。
- 没有启用策略时 `online` 必须失败。
- 添加启用策略后 `online` 成功。
- `offline` 能下架。

### 4.2 单个图片或视频发布

```bash
freelog-cli init . --scaffold none --resource-type <图片或视频typeCode> --yes --env dev
freelog-cli create --yes --env dev
freelog-cli version set --version 1.0.0 --file ./photo.png --env dev
freelog-cli publish --yes --env dev
freelog-cli policy apply --from-file ./policy.json --yes --env dev
freelog-cli online --yes --env dev
```

验收重点：

- 文件存在、格式和大小校验正确。
- SHA1 与平台/Console 结果一致。
- 重复发布相同版本号应失败。

### 4.3 文件夹批量发布为多个独立资源

```bash
freelog-cli resource import-dir ./photos --resource-type <图片typeCode> --title-prefix "照片 " --yes --env dev
```

验收重点：

- 每个文件生成一个独立资源。
- 成功和失败要有汇总。
- 单个文件失败不应导致结果不可追踪。

### 4.4 文件夹作为合集发布

```bash
freelog-cli init photo-album --scaffold collection --resource-type <合集typeCode> --yes --env dev
cd photo-album
freelog-cli collection create --yes --env dev
freelog-cli collection item import-dir ../photos --resource-type <图片typeCode> --title-prefix "照片 " --item-policy-file ./item-policy.json --yes --env dev
freelog-cli collection version set --description "首版合集" --env dev
freelog-cli collection publish --yes --env dev
freelog-cli policy apply --from-file ./policy.json --yes --env dev
freelog-cli online --yes --env dev
```

验收重点：

- `collection item *` 修改的是合集目录草稿。
- 平台要求合集条目单品已上架；CLI 通过 `--item-policy-file` 自动给导入的子资源加策略并上架。dev 实测建议子资源策略文件使用 Console 内置“永久免费”模板文本，合集自身策略文件可与其分开。
- `collection publish` 后平台合集版本更新。
- 目录项授权不完整时必须阻断发布，并提示处理方式。

## 5. 更新类流程

| 场景 | 命令 | 通过标准 |
|---|---|---|
| 更新标题/简介/标签/封面 | `update` / `collection update` | 平台 listing 更新，manifest 同步为本地意图 |
| Console 改了 listing，本地采纳 | `pull --apply-listing` | manifest 被平台 listing 覆盖 |
| 本地和平台都改了 listing | `pull --apply-listing` | 默认失败；加 `--force` 才覆盖 |
| 发布新版本 | `version set` -> `publish` | latestVersion 推进 |
| 保存远端发版草稿 | `draft push` | Console 能看到草稿 |
| 拉取远端发版草稿 | `draft pull` | 本地版本意图更新 |
| 修改策略启停 | `policy set <policyId> --status 0/1` | 平台策略状态更新 |
| 上下架 | `online` / `offline` | 状态正确变化，门禁正确执行 |

## 6. 必测负向用例

| 用例 | 预期 |
|---|---|
| 未登录执行 create/publish/online | 失败，提示登录 |
| 使用他人资源目录执行写操作 | 失败，提示 owner 不匹配 |
| 没有版本直接 online | 失败 |
| 没有启用策略直接 online | 失败 |
| 已上架且只有一条启用策略时停用该策略 | 失败 |
| 同一目录 dev state 下用 test/prod 执行命令 | 失败，提示环境不一致 |
| `policy apply` 传 policyId 想更新旧策略 | 失败；CLI 只新增策略，旧策略只支持启停 |
| `status` 命令 | 只读，不应修改本地文件 |

## 7. 验收通过标准

1. CLI 能完成主题/插件、单文件、文件夹独立资源、文件夹合集四类主流程。
2. CLI 创建、发布、策略、上下架结果能在 Console 中看到一致状态。
3. Console 中修改 listing 或草稿后，CLI 能通过 `status` / `pull` 给出正确结果。
4. 所有写平台命令都有 owner、环境、同步或门禁保护。
5. 非交互模式可用 `--yes --json` 稳定执行，失败时有明确 code、message、hint。
6. 测试环境数据留在 devfreelog.com，不误写 test/prod。
