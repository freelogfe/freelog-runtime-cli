## 2. 对齐类型

| 类型 | 含义 |
|---|---|
| **PARITY** | 同一 API、同一门禁，结果等价 Console |
| **EQUIVALENT** | API 相同，CLI 用参数/拆步替代 UI |
| **OUT** | 不做；handoff 或 Console |
| **CLI_ONLY** | 无 Console 等价（如 `--dry-run`、模板） |

## 9. 二期 MVP 验收链（verify:exhibit-smoke · 规划）

**前置：** 获授权 `<env>` 凭据；**节点已在 Console 创建**（CLI 不创建）；`NODE_ID` 来自配置或 `node list`；市场存在可签约测试资源。

| 步骤 | 能力 | 命令 | 断言 |
|:---:|---|---|---|
| S1 | NM-01 | `market search --limit 5 --json` | ok；`data.items[].resourceId` |
| S2 | NM-02 | `market show <rid> --json` | `status=1`；`canSignToNode` 或 policies 非空 |
| S3 | NM-04 | `node show <nodeId> --json` | owner 匹配；`frozen=false` |
| S4 | NM-08 | `node exhibit sign --dry-run ...` | checks pass 或预期 warn |
| S5 | NM-08 | `node exhibit sign --yes ...` | `presentableId`（反查，见 Q1） |
| S6 | NM-11 | `node exhibit online <pid> --yes` | `onlineStatus=1` |
| S7 | NM-09 | `node exhibit list --node ...` | 含 pid、`isOnline` |
| S8 | NM-12 | `node exhibit offline <pid> --yes` | `onlineStatus=0` |

**Console 并排（层 C）：** 每步对照 [05 §C.1](./05-Console源码证据与调用链.md#c1-core-追溯矩阵)；报告用 [10-L4验收模板](./10-L4验收模板.md)「Console 并排」列。

| ID | 能力 | 场景 | 期望 |

| T-NM-N1 | NM-04 | 非 owner 调用 `node show` / sign | code **2**（optional，[16 §4](./16-verify-exhibit-smoke设计.md)） |

**追溯：** 测试 ID ↔ 能力 ↔ Console 步骤见 [05 §C](./05-Console源码证据与调用链.md#c-测试人员-console-对照nm-core)、[12 §4.3](./12-多视角设计说明.md#43-追溯矩阵core--二期)。

## 10. 验证脚本关系

```text
pnpm verify:exhibit-smoke         # 二期 dev E2E（规划，未实现）
pnpm verify:session-smoke         # 一期，不变
pnpm verify                       # 一期全量，默认不含二期
```

二期 **不** 默认并入 `pnpm verify`，直到 [08-DESIGN回写草案](./08-DESIGN回写草案.md) 合并 DESIGN 且 smoke 稳定后再议。

## 13. 风险

| 风险 | 缓解 |
|---|---|
| 付费 policy 比例高 | handoff 标准化（[07-Q4](./07-开放问题与设计裁决.md)）；文档明确免费 policy 自动化 |
| 平台 batchCreate 部分失败 | 解析 per-resource status；JSON `results[]` |
| 节点/资源 owner 不同账号 | 文档 + smoke 用两账号测 sign |
| Agent 误改节点壳 | **不提供** node 写命令；仅 list/show |
| Agent 误用 studio 做节点 | 原则 P7/P11；展品用 `node exhibit` |
| NM 与 N 系列 ID 混淆 | 本文 NM；对齐 §6 保留原生 N-01~N-06 |
