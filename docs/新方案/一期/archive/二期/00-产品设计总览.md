## 1. 产品定位

Freelog Runtime CLI 是以 **本地工程** 为工作面的 Freelog **资源发行与节点运营** 工具：

> 本地文件和 manifest 表达发版意图；CLI 将 Console 隐性约束显式化，经校验、构建、上传和平台写入完成可重复发行；在固定节点上完成市场选品、展品签约与上下线。

**不是**「没有界面的 Console」拷贝，也 **不是** API 薄封装。

| 表面 | 说明 |
|---|---|
| 终端交互 | 向导、confirm、`session` / `studio` |
| 声明式工程 | `freelog.manifest.json` + `.freelog/state.json` |
| CI / Agent | `--json` + `--yes` + preflight + handoff |
| 平台 API | 经 `@freelog/tools-lib` / services 统一门禁 |

## 2. 完整商业闭环

```text
┌──────────────┐  create/publish   ┌──────────────┐  online    ┌──────────────┐
│  资源作者     │ ───────────────→ │  平台资源     │ ─────────→ │  资源市场     │
│  (CLI 一期)   │                  │  Resource     │  status=1  │  discover    │
└──────────────┘                  └──────┬───────┘            └──────┬───────┘
                                         │                            │
                                         │ dep auth（依赖签约）        │ exhibit sign
                                         ▼                            ▼
                                  ┌──────────────┐            ┌──────────────┐
                                  │  可发行版本   │            │  节点 · 展品  │
                                  └──────────────┘            │  (CLI 二期)   │
                                                              └──────┬───────┘
                                                                     ▼
                                                              ┌──────────────┐
                                                              │  C 端访客     │
                                                              │  (CLI OUT)   │
                                                              └──────────────┘
```

**两条签约链（勿混淆）：**

| | `dep auth`（一期） | `node exhibit sign`（二期） |
|---|---|---|
| 谁 | 资源 **作者** | **节点主** |
| 签什么 | **依赖** 资源 | **市场** 资源 |
| 结果 | 版本可 `publish` | 创建 **presentable** |

节点 **壳**（域名、Logo、主题激活）在 **Console** 一次性配置；CLI 对节点 **只读** `list/show`，对展品 **读写**。

## 4. 产品信息架构（完整命令面）

按 **用户任务** 组织，不按 Console 页面组织：

```text
环境与身份
  login / logout / config

工程立项（一期）
  init / bind / template

理解状态（一期）
  status / validate / doctor / diff / pull

准备发行意图（一期）
  version / draft / dep / policy / collection item

执行发行（一期）
  create / publish / release / resource import-dir / collection publish

维护平台资源（一期）
  update / policy apply|set / online / offline / dep auth / version edit

资源市场（二期 · 规划）
  market search / market show

节点与展品（二期 · 规划）
  node list / node show
  node exhibit sign|list|online|offline

会话模式（一期）
  resource * --session / dep * --session / policy|online|offline --session

交互壳（一期 · TTY）
  session（11） / studio（10）— Agent headless 不得依赖
```

### 三种发行模式（一期）

| 模式 | 入口 | 结果 |
|---|---|---|
| 单资源 | `init` → `create` → `publish` | 一个资源 + 版本 |
| 批量独立资源 | `resource import-dir` | N 个独立资源工程 |
| 合集 | `init collection` → `collection *` | 一个合集 + 有序条目 |

## 5. 双模式与 Agent 路径

| 编码 | 名称 | Agent 默认 | 说明 |
|:---:|---|:---:|---|
| 00 | 工程模式 | ✅ | manifest + state；资源与展品运营 |
| 01 | 命令会话 | ✅ | `--session` 单次原子 |
| 10 | studio | ⚠️ | 多账号 **发资源**；非展品主路径 |
| 11 | session | ❌ headless | TTY 交互壳 |

Agent / CI 主路径：**00 或 01** + `--json` + `--yes` + L0 预检 → L3 写入；遇 handoff（code 5）暂停。原则见 [01-面向AI的CLI设计原则](./01-面向AI的CLI设计原则.md)。
