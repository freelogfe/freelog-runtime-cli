# Freelog CLI 一期（资源发行域）

> **文档角色：** 一期已实现能力的 **产品与实现 consolidated 真源**——供产品改体验、研发写代码、测试对门禁时「先读这一包」，再下钻对齐/开发细节。  
> 产品总契约仍为仓库根 [DESIGN.md](../../../DESIGN.md)；二期节点/展品见 [二期/README.md](../二期/README.md)。

最后更新：2026-08-21

---

## 为什么需要本目录

一期能力分散在 `DESIGN.md`、`对齐/`、`开发/`、`packages/cli/src/ARCHITECTURE.md` 等多处。**没有单一文档**时难以：

- 精细思考 **用户体验**（TTY / CI / 错误 / handoff 应在哪一步出现）
- **修改设计** 时知道改哪、同步哪、验收哪

本目录补齐二期 [`15-二期实现规格.md`](../二期/15-二期实现规格.md) 在一期侧的等价物。

## 维护规则

改一期行为时：

1. 先改 **本文 §4–§8**（旅程 / UX / 门禁 / 伪代码）  
2. 同步 [对齐/](../对齐/) 能力矩阵或 [开发/CLI双模式实现设计.md](../开发/CLI双模式实现设计.md) §17–§19（若 API/Console 映射变）  
3. 同步 [使用/](../使用/) 用户可见示例（若命令或 flag 变）  
4. 产品边界变 → [DESIGN.md](../../../DESIGN.md)  
5. 更新 [审计/](../审计/) 仅在专项审计后
