# Freelog CLI 一期（资源发行域）

> **文档角色：** 一期资源发行域的 **consolidated 设计包入口**——供产品先改体验拓扑，研发再写代码，测试按门禁与场景验收。
> 产品总契约仍为仓库根 [DESIGN.md](../../../DESIGN.md)；二期节点/展品见 [二期/README.md](../二期/README.md)。

最后更新：2026-08-28

---

## 为什么需要本目录

一期能力分散在 `DESIGN.md`、`对齐/`、`开发/`、`packages/cli/src/ARCHITECTURE.md` 等多处。**没有单一文档**时难以：

- 精细思考 **用户体验**（TTY / CI / 错误 / handoff 应在哪一步出现）
- **修改设计** 时知道改哪、同步哪、验收哪

本目录补齐二期 [`15-二期实现规格.md`](../二期/15-二期实现规格.md) 在一期侧的等价物。

## 维护规则

改一期行为时：

1. 先改具体 [场景分册](./场景/README.md)（用户目标、输入、资源类型、失败处理）
2. 将两个以上场景重复出现的规则回收到 [02-CLI体验拓扑设计](./02-CLI体验拓扑设计.md)
3. 用 [03-多视角设计审查](./03-多视角设计审查.md) 从 AI、产品、用户、QA、研发和安全视角挑刺
4. 同步 [01-产品与实现规格](./01-产品与实现规格.md) §2–§8（能力、命令、门禁、伪代码）
5. 同步 [对齐/](../对齐/) 能力矩阵或 [开发/CLI双模式实现设计.md](../开发/CLI双模式实现设计.md) §17–§19（若 API/Console 映射变）
6. 同步 [使用/](../使用/) 用户可见示例（若命令、flag 或提示变）
7. 产品边界变 → [DESIGN.md](../../../DESIGN.md)
8. 更新 [审计/](../审计/) 仅在专项审计后
