# Freelog CLI 一期设计入口

> **文档角色：** 一期资源发行脚手架的设计导航。这里不承载细节，只规定阅读顺序、文档分工和维护规则。
> 产品总契约仍为仓库根 [DESIGN.md](../../../DESIGN.md)。

最后更新：2026-08-31

## 1. 主读链路

只想判断产品设计是否合理，按下面 4 个入口读，不要在所有文档里跳来跳去：

| 顺序 | 文档 | 作用 |
|:---:|---|---|
| 1 | [对齐/Console业务流程字段接口总账.md](./对齐/Console业务流程字段接口总账.md) | Console 业务事实：流程、字段约束、API、待实测歧义 |
| 2 | [01-产品设计总纲.md](./01-产品设计总纲.md) | CLI 产品目标、用户、边界、信息架构 |
| 3 | [02-CLI体验拓扑设计.md](./02-CLI体验拓扑设计.md) | CLI 主流程、全局交互契约、命令面 |
| 4 | [场景/README.md](./场景/README.md) | S01–S14 场景校验集，用来反推主设计缺口 |

这条链路的意思是：

```text
先确认 Console 真实业务
  → 再定义 CLI 产品目标和边界
  → 再设计 CLI 主流程
  → 最后用场景逐条挑战设计
```

## 2. 文档分工

| 文档区 | 放什么 | 不放什么 |
|---|---|---|
| `对齐/` | Console 源码事实、字段约束、接口证据 | CLI 交互取舍 |
| `01-产品设计总纲.md` | 产品目标、用户、范围、原则 | 场景细节、API 长表 |
| `02-CLI体验拓扑设计.md` | 主流程拓扑、屏幕契约、命令结构 | 每个场景的完整剧本 |
| `场景/` | 具体用户场景、异常、反推结论 | 全局规则重复堆叠 |
| `开发/` | manifest/state/API/模块结构 | 产品争议 |
| `使用/` | 面向最终用户的当前操作手册 | 设计争论和内部证据 |
| `验证/` | 手测清单、测试报告模板 | 产品真源 |

## 3. 冲突裁决

发生冲突时按这个顺序处理：

```text
DESIGN.md
  → Console业务流程字段接口总账
  → 01 产品设计总纲
  → 02 CLI 体验拓扑
  → 场景分册
  → 开发/使用/验证文档
  → 当前代码实现
```

旧实现和旧文档只能作为“现状证据”，不能反向决定产品。

## 4. 维护规则

1. 新发现 Console 事实，先补 [Console业务流程字段接口总账](./对齐/Console业务流程字段接口总账.md)。
2. 影响产品边界，再改 [01-产品设计总纲.md](./01-产品设计总纲.md)。
3. 影响用户怎么走流程，再改 [02-CLI体验拓扑设计.md](./02-CLI体验拓扑设计.md)。
4. 只影响一个具体使用场景，改对应 Sxx 场景文档。
5. 两个以上场景重复出现的规则，回收到 02，不在场景里复制。
6. 命令、flag 或文案改变后，最后同步 `使用/` 和 `验证/`。
