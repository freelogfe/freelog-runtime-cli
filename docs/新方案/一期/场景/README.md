# 一期 CLI 场景设计目录

> **文档角色：** 一期体验拓扑的逐场景设计分册。总原则见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)；本文档目录只负责把每个真实用户场景拆开，确保重构前能逐条评审、实现和手测。

最后更新：2026-08-28

---

## 1. 为什么拆场景

`02-CLI体验拓扑设计.md` 负责回答“CLI 应该长成什么样”；本目录负责回答“用户实际走到某个场景时，每一步具体发生什么”。

每个场景都必须写清：

1. 用户目标：用户手上有什么、想完成什么。
2. Console 对齐：对齐哪些字段限制、API payload、状态门禁和流程结果。
3. CLI 体验：TTY 如何连续引导；AI/CI 如何显式执行。
4. 资源类型：类型从哪里来，是否逐级选择，最终 leaf code 怎么确认。
5. 写入边界：哪些步骤只写本地，哪些步骤写平台，哪些步骤可能需要恢复。
6. 失败处理：用户输错、网络断、远端已存在、需要浏览器动作时怎么继续。
7. 回归总设计：该场景反向要求总拓扑、命令面、help、文案如何调整。

场景不是测试报告；真实环境是否通过写到 `docs/新方案/一期/验证/reports/`。

## 3. 场景迭代规则

每次改设计按这个顺序来回归：

```text
先改具体场景
  → 看是否影响其它场景
  → 抽象为 02 总拓扑原则
  → 回到场景检查是否能落地
  → 再同步 01 摘要、字段约束、使用文档或验证清单
```

如果某个细节只在一个场景成立，留在场景文档；如果两个以上场景重复出现，必须回收到 `02-CLI体验拓扑设计.md` 的总规则。
