# S08 · 合集从本地目录创建

> **文档角色：** 用本地目录创建子资源并组成合集的完整体验设计。总规则见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)。

最后更新：2026-08-28

---

## 1. 用户目标

用户想做相册、专辑、文章集或资源集合。目录里的文件通常要先成为独立资源，再加入合集目录草稿，最后发布合集版本。

---

## 2. 产品模型

合集不是“把文件夹压缩上传”。它有四层：

| 层 | 用户动作 | 平台含义 |
|---|---|---|
| 合集壳 | `collection create` | subjectType 为合集的 Resource |
| 子资源 | `collection item import-dir` | 文件变成独立资源 |
| 目录草稿 | `collection item add/reorder/update/remove` | 合集条目草稿 |
| 合集版本 | `collection publish` | 正式发布目录/展示设置 |

Console 对齐来自 `collectionCreator` 和 `collectionSidebar`：合集创建字段、目录项增删改排、display、collect-rules/RSS、合集版本发布和上下架门禁都必须保持同一业务结果。CLI 可以把步骤拆开，但不能把目录草稿误写成正式版本。

---

## 3. 资源类型设计

| 对象 | 类型来源 | 规则 |
|---|---|---|
| 合集本身 | subjectType=4 的合集类型树 | 不能混入独立资源类型 |
| 子资源 | subjectType=1 的普通资源类型树 | 可统一 leaf，也可逐项声明 |
| RSS 合集 | 先有合集壳，再绑定 RSS | 绑定后进入 S09 锁定规则 |

用户必须在界面上看到“我现在选的是合集类型”还是“我现在选的是子资源类型”。

## 4. TTY 连续向导

| checkpoint | 用户看到 | 输入 | 副作用 | 失败处理 |
|---|---|---|---|---|
| C1 选择合集 | “创建合集/相册/专辑” | collection | 无 | 返回主菜单 |
| C2 合集类型 | 合集类型树 | leaf | 无 | 父节点继续下钻 |
| C3 合集字段 | title/name/display/description | 文本 | 写 collection manifest | 字段同源校验 |
| C4 创建合集壳 | 将写平台 Resource.create | confirm | 写平台/state | 重名按精确恢复或冲突 |
| C5 添加条目 | 已有资源、本地目录、RSS | 选择 | 看入口 | 模型解释清楚 |
| C6 本地导入 | 扫描文件、创建子资源、加入草稿 | confirm | 写平台/report/draft | 子资源失败不污染目录 |
| C7 管理目录草稿 | list/update/reorder/remove | 选择/文件 | 写目录草稿 | 重复执行幂等 |
| C8 发布合集版本 | merge/display/version preflight | confirm | 写平台/state | 目录冲突先 diff |
| C9 策略/上架 | 策略模板/online | 选择 | 写平台 | 策略进入 [S14](./S14-策略模板选择与应用.md)；同独立资源门禁 |

## 5. AI/CI 目标等价命令

```bash
freelog-cli init collection ./album --resource-type <collection-leaf-code> --env <env>
cd ./album
freelog-cli collection create --yes --env <env>
freelog-cli collection item import-dir ./photos --resource-type <item-leaf-code> --yes --env <env> --json-lines
freelog-cli collection publish --yes --env <env>
freelog-cli collection policy apply --template <templateId-for-永久免费> --name "永久免费" --yes --env <env>
freelog-cli online --yes --env <env>
```

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 用户以为合集就是上传 zip | 在 C5 前解释四层模型，允许切到 S05 |
| 子资源创建部分失败 | report 记录；未成功项不加入目录草稿 |
| 添加已有资源 | 校验 resourceId 存在和授权风险 |
| reorder 后发布 | preflight 展示旧顺序/新顺序摘要 |
| display 改动但目录没变 | `isMergeCatalogueDraft=0`，用户可见 |
| RSS 绑定后手改目录 | 拒绝并提示 S09 |

---

## 7. 回归到总设计

合集场景要求：

- 第一屏有「合集」；
- 必须区分合集类型和子资源类型；
- item 写的是目录草稿，publish 才是合集版本；
- collection publish preflight 必须展示 merge 语义。
