# S13 · 只管理线上策略与上下架

> **文档角色：** 不发布新文件，只维护策略、授权、上架、下架的体验设计。总规则见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)。

最后更新：2026-08-28

---

## 1. 用户目标

用户已有资源或合集，只想管理线上状态：补策略、启停策略、上架、下架、查看依赖签约。CLI 不应强迫用户进入 publish。

---

## 2. Console 对齐点

| Console sidebar | CLI 行为 |
|---|---|
| policy 新增 | `fPolicyBuilder3`：模板列表 → 参数编辑 → 译文/代码预览 → addPolicies |
| policy 启停 | `policy set/list`；不修改已存在正文 |
| 最后一条启用策略保护 | 禁用前 code 4 |
| online 三分支 | CLI 采用严格门禁：latestVersion + 启用策略 + 非 frozen |
| offline 确认 | TTY confirm；非 TTY `--yes` |
| dependency/contract | `dep auth` 或 Console handoff |

---

## 3. TTY 连续向导

```text
选择“管理线上状态”
  → 选择当前工程或搜索线上资源
  → 展示 status/latestVersion/启用策略/冻结/依赖授权
  → 选择 添加策略 / 启停策略 / online / offline / dep auth
  → 添加策略时进入模板列表，不进入文件路径输入
  → preflight
  → confirm
  → 写平台并刷新 state
```

---

## 4. 操作规则

| 动作 | preflight 必须展示 | 失败处理 |
|---|---|---|
| policy template apply | 可用模板、模板标题、参数、策略名、译文、策略代码摘要、是否付费/不可判 | 模板拉取失败不 fallback；付费/不可判 code 5 |
| policy apply --from-file | 文件路径、策略名、策略正文摘要、advanced 警告 | 仅专家/AI/CI；同样校验重复与追加语法 |
| policy enable/disable | 策略 id/name、当前状态、是否最后启用策略 | 最后一条启用策略拒绝 |
| online | latestVersion、启用策略数、frozen、owner/env | 缺版本/策略/冻结在确认前失败 |
| offline | 当前线上状态、下架后影响 | 用户取消不写平台 |
| dep auth | 依赖数、免费可签、付费/需浏览器 | handoff + nextCommand |

---

## 5. AI/CI 目标等价命令

```bash
freelog-cli policy list --json --env <env>
freelog-cli policy template list --json --env <env>
freelog-cli policy apply --template <templateId-for-永久免费> --name "永久免费" --yes --json --env <env>
freelog-cli dep auth --yes --json --env <env>
freelog-cli online --yes --json --env <env>
freelog-cli offline --yes --json --env <env>
```

---

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 没有 latestVersion | online 停止，提示 publish |
| 没有启用策略 | online 停止，提示先进入策略模板选择或启用已有策略 |
| 资源 frozen | 停止，提示 Console/平台处理 |
| 用户误以为 offline 会删除版本 | 明确说明只是下架 status，不删除 |
| 策略涉及支付 | code 5，给 Console 链接 |
| 用户想手写策略 | 提醒这是 advanced；可导出/使用 `--from-file`，但普通路径仍推荐模板 |

---

## 7. 回归到总设计

线上状态场景要求：

- root/start 要能从“我不发文件，只想上下架”进入；
- policy 模板 Builder、online、offline 是一等维护路径；
- CLI 不复制 Console 的弱软上架路径，采用 sidebar 严格门禁。
- 本场景的新增策略细节以 [S14](./S14-策略模板选择与应用.md) 为准。
