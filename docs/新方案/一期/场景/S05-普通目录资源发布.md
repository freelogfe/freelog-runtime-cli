# S05 · 普通目录资源发布

> **文档角色：** 非主题/插件/package 的目录型资源发布体验设计。总规则见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)。

最后更新：2026-08-31

---

## 1. 用户目标

用户有一个本地目录，希望把目录整体作为一个资源发布。它不是合集，也不是批量拆成多个资源；CLI 要把目录处理为一个发行物。

---

## 2. 和合集/批量的区分

| 用户说法 | 应走场景 | 平台结果 |
|---|---|---|
| “这个目录整体就是一个资源” | S05 普通目录资源 | 一个独立资源版本，文件是 zip |
| “目录里每个文件都是一个资源” | S07 批量发布 | N 个独立资源 |
| “这些文件要组成相册/专辑” | S08 合集 | N 个子资源 + 一个合集 |

第一屏必须把这三者讲清，否则用户会把“文件夹”误发成错误模型。

---

## 3. Console 对齐点 / CLI 原生差异

Console 没有“把任意目录自动打包成一个资源”的显式 UI；它的对齐点来自本地上传链路：类型能力、文件大小、SHA1、属性解析和 createVersion payload。目录压缩是 CLI-native，但压缩后的 zip 进入平台时必须像 Console 上传文件一样接受同一套限制。

| 步骤 | 规则 |
|---|---|
| 类型选择 | 仍从平台类型树逐级选到 leaf |
| artifactMode | 必须明确为 `directory-zip`，或由平台 type capability 明确返回 |
| 禁止猜测 | 不得靠中文展示名、英文名或 `RT*` 推断压缩 |
| ignore | 应用 `.freelogignore` 与强制排除项 |
| zip | 稳定顺序、稳定时间戳、无敏感文件、可计算 SHA |

资源类型仍按 02 的全局类型选择器处理：逐级选择优先，搜索只是快捷入口，最终必须确认 leaf。

---

## 4. TTY 连续向导

| checkpoint | 用户看到 | 输入 | 副作用 | 失败处理 |
|---|---|---|---|---|
| D1 选择对象 | “发布一个目录为单个资源” | 目录路径 | 无 | 目录不存在重新选 |
| D2 模型确认 | “不是批量/合集，会打成一个 zip” | confirm | 无 | 可切换到批量/合集场景 |
| D3 选择类型 | 逐级类型树 | leaf | 无 | 父节点继续下钻 |
| D4 artifactMode | file / directory-zip | directory-zip | 写 manifest | 缺能力则要求显式选择 |
| D5 ignore 预览 | 将排除哪些文件 | confirm | 无 | 敏感文件永远排除 |
| D6 发布预检 | zip 名、文件数、大小、SHA | confirm | 临时 zip 仅正式时生成 | 超限停在本地 |
| D7 发版 | 上传 zip/createVersion | 等待 | 写平台/state | unknown 停损 |

---

## 5. AI/CI 等价命令

```bash
freelog-cli init other ./dir-resource --resource-type <leaf-code> --artifact-mode directory-zip --env <env>
cd ./dir-resource
freelog-cli create --yes --env <env>
freelog-cli version set --file ./dist --version 1.0.0 --env <env>
freelog-cli publish --yes --env <env>
```

---

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 用户其实想做合集 | 在模型确认页解释并允许返回选择合集 |
| 目录包含 `.freelog-auth` | 强制排除并警告，不允许反选 |
| 目录包含符号链接 | 默认拒绝或明确规则；不能静默跟随 |
| dry-run | 不生成长期 zip、不上传、不写 state；无法确定字段标 unresolved |
| zip 后超大小 | 显示压缩后大小和限制 |

## 7. 回归到总设计

目录场景要求总设计把“目录整体发布 / 批量拆资源 / 合集策展”作为第一屏分叉，而不是都叫“文件夹上传”。
