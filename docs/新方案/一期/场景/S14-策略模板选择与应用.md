# S14 · 策略模板选择与应用

> **文档角色：** 授权策略新增体验的专项设计。它修正“普通用户手写 policy 文件”的旧思路：Console 的主体验是策略模板 Builder，CLI 的 TTY 主体验也必须先选模板、再填参数、再预览应用。总规则见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md) §2.6。

最后更新：2026-08-28

---

## 1. 用户目标

用户已经有一个资源或合集，想让访客能按某种规则获得授权：永久免费、限时免费、等待免费、永久解锁、订阅、借阅等。用户不应该被迫先理解 Freelog policy DSL，也不应该先手写 `policyText`。

成功体验是：

```text
选择“添加授权策略”
  → 看见当前资源类型可用的策略模板
  → 选择一个模板
  → 填价格/时长/单位/截止时间等参数
  → 编辑策略名称
  → 预览人类译文和策略代码摘要
  → 确认应用
  → 回到策略列表 / 继续 online
```

---

## 2. Console 业务证据

Console 的策略创建不是文件入口：

| Console 证据 | 业务含义 | CLI 设计结论 |
|---|---|---|
| `components/fPolicyBuilder3/FPolicyBuilderDrawer3` | Drawer 状态从 `template` → `editor` → `confirm` | TTY 必须三段式：选模板、填参数、预览确认 |
| `Policy.policyTemplates` | 按 `resourceTypeCode` 或节点 `nodeID` 拉模板 | CLI 模板列表必须跟资源/合集类型相关 |
| `Policy.policyReCompile` | 用模板 id + fillArgs 生成最终策略代码 | CLI 不应让普通用户拼 policyText |
| `Policy.policyTranslation` | 生成可读译文用于确认 | CLI preflight 必须展示译文或摘要 |
| `alreadyUsedTitles / alreadyUsedTexts` | 策略名和策略代码不可重复 | CLI 写前同源校验 |
| `Payment.queryWithdrawStatus` | 交易类模板需要结算能力 | CLI 付费模板无法继续时 code 5 handoff 到 Console |

Console 模板族当前包含：`永久免费`、`限时免费`、`等待免费`、`永久解锁`、`限时特价永久解锁`、`免费试用后订阅`、`借阅解锁`、`付费订阅`。

## 3. 产品裁决

| 裁决 | 说明 |
|---|---|
| 普通 TTY 主路径 | **模板选择优先**，不是 `policy init` / `policy apply --from-file` |
| 文件入口 | 只给专家、迁移、AI/CI、测试 fixture；必须在 help 中标为 advanced |
| 策略正文 | 用户可查看代码，但默认只编辑模板参数和策略名 |
| 付费模板 | 可展示和选择；若 CLI 无法完成结算/验证码/签约，输出 Console actionUrl 与 nextCommand |
| online | 策略新增成功后不自动上架，只建议继续 `online`；避免复制 Console 策略页的软上架 |
| 资源与合集 | 同一个 Builder 模型；合集使用 collection policy 入口和合集类型/owner 上下文 |

## 4. TTY 连续向导

| checkpoint | 用户看到 | 输入 | 副作用 | 失败处理 |
|---|---|---|---|---|
| P1 进入策略 | 当前资源/合集标题、env、owner、已有策略数 | 添加策略 / 启停策略 / 返回 | 无 | 未绑定资源则引导 bind/search |
| P2 拉模板 | 当前类型可用模板列表，按免费/付费/时间/订阅分组 | 选择模板；可搜索 | 只读 API | 拉取失败可重试，不 fallback 旧本地模板 |
| P3 展示模板详情 | 模板标题、授权译文、是否涉及支付、参数列表 | 下一步 / 换模板 | 无 | 付费模板缺结算能力时提前提示 Console |
| P4 填参数 | number/select/datetime 控件及默认值、min/precision | 参数值 | 无 | 参数为空、低于 min、日期格式错则原地提示 |
| P5 策略名 | 默认模板名，可编辑；2–20 字 | policyName | 无 | 空、太短、重复则原地提示 |
| P6 编译预览 | policyTranslation、policyText 摘要、重复检测、支付风险 | 确认 / 返回编辑 | 只读 API | 编译/翻译失败说明阶段 |
| P7 应用策略 | 即将调用 `Resource.update.addPolicies` | confirm | 写平台；刷新 state | 远端成功本地失败按 remote-write recovery |
| P8 下一步 | 策略列表、是否继续 online | online / 结束 | 仅确认后写 | online 仍走 latestVersion + 启用策略 + frozen 门禁 |

## 5. AI/CI 目标等价命令

AI/CI 不进交互，但也不应该盲写手工 policyText。重构后的推荐链路：

```bash
freelog-cli policy template list --json --env <env>
freelog-cli policy template render <templateId> --param price=1 --param unit=day --json --env <env>
freelog-cli policy apply --template <templateId> --param price=1 --param unit=day --name "<策略名>" --yes --json --env <env>
```

专家/迁移 fallback：

```bash
freelog-cli policy apply --from-file ./policy.custom.json --yes --json --env <env>
```

fallback 仍必须执行：策略名长度、策略名重复、策略代码重复、追加策略语法、付费/不可判 handoff、URI 编码。

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 没有模板 | 停止并说明当前类型无可用模板；不要自动生成 `policy.free.json` 当作平台事实 |
| 用户只想永久免费 | 推荐 `永久免费` 模板，可一键接受默认参数和默认策略名 |
| 用户选择付费模板但未设置结算 | code 5，给 Console 结算设置链接；不写策略 |
| 策略名重复 | 保留模板和参数，让用户只改名称 |
| 策略代码重复 | 提示已有相同策略，可改参数或直接启用已有策略 |
| 用户想手写 DSL | 进入 advanced：导出模板文件或 `--from-file`，并提示普通用户不推荐 |
| 已上架且只有一条启用策略 | 新增策略允许；禁用旧策略前必须保证仍有一条启用 |
| 合集策略 | 使用合集 owner/type 上下文拉模板；应用到合集 resourceId，不混到子资源 |

## 7. 回归到总设计

策略模板场景要求：

- `policy` 在 TTY 中必须是 Builder，不是文件命令说明页；
- root/start 成功续接到“配置策略”时要进入本场景；
- S01/S02/S04/S08/S13 中所有“配策略”都引用本场景；
- `--from-file` 只能在 AI/CI/advanced 中出现，不能作为普通用户主路径；
- 对齐文档必须记录 Console 的 `template → editor → confirm` 三段式，而不是只记录最终 `Resource.update.addPolicies`。

## 8. 目标代码结构（避免旧实现继续污染）

实现时不要把模板逻辑继续塞进 `policyService.ts` 或命令文件。建议拆成：

| 模块 | 职责 | 不应做 |
|---|---|---|
| `commands/policy.ts` | 只声明 `policy template list/render`、`policy apply --template/--from-file`、`policy set/list` 的参数和输出模式 | 不拼 policyText，不直接调 Console 模板 API |
| `services/policyTemplate/normalize.ts` | 把 `Policy.policyTemplates` 返回值规范化为 CLI 模板、参数和译文结构 | 不做 TTY prompt |
| `services/policyTemplate/params.ts` | 校验 number/select/datetime 参数、策略名、重复标题 | 不读取命令行 argv |
| `services/policyTemplate/compiler.ts` | 调 `policyTemplates` / `policyReCompile` / `policyTranslation`，做付费 handoff 和重复正文检测 | 不保存 manifest/state |
| `services/policyTemplate/resource.ts` | 在 ProjectStore/session 上下文中 preview/apply/commit，并在写成功后刷新 state | 不处理 TTY prompt |
| `services/interactive/policyTemplateWizard.ts` | TTY 三段式：模板列表 → 参数编辑 → 预览确认 | 不拼平台 payload |
| `services/policyService.ts` | 接收已经生成的 `{ policyName, policyText }`，执行 addPolicies/updatePolicies 和 state 刷新 | 不关心模板 UI |
| `services/policySubjectContext.ts` | 统一解析 resource / collection / session 的 resourceId、resourceTypeCode、owner、nodeID | 不泄露 store 实现细节到命令层 |

这样代码读起来会像 Console 业务链，而不是像旧 CLI 的“读一个 JSON 然后 update”。
