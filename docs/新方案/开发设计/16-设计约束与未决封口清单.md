# 开发设计：设计约束与未决封口清单

> 本文用于防止实现阶段把已定设计重新发散。若代码遇到本文未覆盖的新场景，先补本文再实现。

## 1. 不再讨论的硬约束

| # | 约束 | 原因 |
|---|---|---|
| 1 | 项目主配置只有 `freelog.manifest.json` | 用户意图必须可审阅、可提交、不可执行 |
| 2 | CLI 状态只有 `.freelog/state.json` | 平台事实不能污染用户意图 |
| 3 | 不读旧配置文件 | 新脚手架无旧负担 |
| 4 | 不执行用户 JS/TS 配置 | 安全与可预测性 |
| 5 | CLI 只 import `@freelog/tools-lib2/node` | 浏览器入口留给 Console |
| 6 | 浏览器项目不因 CLI 改造而改依赖方式 | 前端已有 workspace 依赖，不需要迁移 |
| 7 | `publish` 不要求本资源策略 | 创建正式版本与上架是两条边 |
| 8 | `online` 必须要求 latestVersion + 启用策略 | 对齐 Console 侧栏硬门禁 |
| 9 | CLI 不自动创建策略 | 策略是业务授权文本，不能猜 |
| 10 | CLI 不自动执行 build | build 属于用户项目，不属于发布命令 |
| 11 | 文件夹不会被隐式 zip 成合集 | 文件夹语义由命令决定 |
| 12 | 合集目录草稿不是发版草稿 | API、冲突和用户心智不同 |
| 13 | `status` 永远只读 | 状态检查不能产生隐式副作用 |
| 14 | 自动 owner/sync 只能写 state | manifest 是用户意图，不能被平台事实静默覆盖 |
| 15 | `pull --apply-listing` 才允许写 manifest listing | 远端事实应用为本地意图必须显式 |

## 2. 场景封口

| 用户输入 | CLI 解释 | 命令 |
|---|---|---|
| React 主题项目 | 构建目录压缩为运行时类资源版本 | `publish` |
| Vue 插件项目 | 同主题，resourceTypeCode 不同 | `publish` |
| 单张图片 | 一个文件，一个资源，一个版本 | `create` + `version set` + `publish` |
| 单个视频 | 一个文件，一个资源，一个版本 | 同上 |
| 图片文件夹，想每张图都是资源 | 多个独立资源 | `resource import-dir` |
| 视频文件夹，想每个视频都是资源 | 多个独立资源 | `resource import-dir` |
| 图片文件夹，想成为合集 | 多个独立资源 + 一个合集目录 | `collection item import-dir` |
| 视频文件夹，想成为合集 | 多个独立资源 + 一个合集目录 | `collection item import-dir` |
| 已有他人资源加入合集 | 只写合集目录条目，不校验条目 owner | `collection item add <resourceId>` |

未覆盖场景先放 P2：外部存储空间导入、远程 URL 导入、直播流、付费授权自动化、合集发版表单草稿。

## 3. 新建拓扑

| 动作 | 会创建什么 | 不会创建什么 |
|---|---|---|
| `init` | manifest/state 本地文件 | 平台资源 |
| `create` | 平台资源壳 | 版本、策略、上架 |
| `version set` | 本地下一版意图 | 平台草稿、正式版本 |
| `publish` | 正式版本 | 策略、上架 |
| `policy apply` | 策略 | 版本、上架 |
| `online` | status=1 | 策略、版本 |
| `collection item *` | 合集目录草稿 | 合集正式版本 |
| `collection publish` | 合集正式版本/目录合并 | 策略、上架 |

## 4. 更新拓扑

| 要更新 | 命令 | 约束 |
|---|---|---|
| 资源标题/简介/标签/封面 | `update` | 不改 status |
| 下一版版本号/文件/描述/依赖 | `version set` | 只改 manifest |
| 已发布版本说明 | `version edit` | 不改文件/SHA/依赖 |
| 平台发版草稿 | `draft push/pull/discard` | 单品维护 state.version.draftSync；合集发版表单草稿维护 state.collection.draftSync |
| 策略正文或启停 | `policy apply/set` | 上架时不能停掉最后启用策略 |
| 上架状态 | `online/offline` | online 严格门禁 |
| 平台事实缓存 | `pull` | 默认只写 state；`--apply-listing` 才写 manifest.resource |
| 合集目录 | `collection item *` | 写 catalogue draft |
| 合集展示 | `collection update --display-*` | 枚举校验 |
| 合集正式版本 | `collection publish` | 调 updateCollection |

## 5. 非交互封口

| 情况 | 行为 |
|---|---|
| 无 TTY 缺 `resourceTypeCode` | exit 4 |
| 无 TTY 缺策略文件 | exit 4 |
| 无 TTY 需要确认覆盖 | exit 4，提示 `--yes` / `--force --yes` |
| `--yes` 缺业务字段 | exit 4 |
| TTY 下缺字段 | 可以 prompt |
| CI 下 RSS 无验证码 | exit 4 |

## 6. Console 差异封口

| Console 能力 | CLI 约定 |
|---|---|
| Step4 软上架 | 不实现；只能 `online` |
| 自动保存草稿 | 不实现；只能 `draft push` |
| 依赖授权微应用 | 付费/交互回 Console |
| 策略 Builder | Console 导出策略文本，CLI 只 apply |
| 页面打开即加载远端 | CLI 用 `status` / `pull` 明确同步 |

## 7. 生命周期状态矩阵

| 状态域 | 本地/平台状态 | 允许入口 | 禁止入口 |
|---|---|---|---|
| 资源壳 | 未绑定 resourceId | `create` / `pull` 绑定已有资源 | `publish` / `policy` / `online` |
| 资源壳 | 已创建，未发布版本 | `update` / `version set` / `publish` / `draft push` | `online` |
| 正式版本 | 有 latestVersion | `version set` 新下一版 / `version edit` / `online` | 重发同版本 |
| 发版草稿 | 平台无草稿 | `draft push` | `draft pull` |
| 发版草稿 | 平台有草稿且本地未对齐 | `draft pull` / `draft push --force` / `draft discard` | 普通 `draft push` |
| 策略 | 无启用策略 | `policy apply` / `policy set --status 1` | `online` |
| 策略 | 已上架且仅一条启用策略 | `policy apply` / 新增启用策略后再停用 | `policy set <last> --status 0` |
| 上下架 | status=1 | `offline` / `update` / `version set` / `publish` | 关闭最后启用策略 |
| 上下架 | status=4 或未上架 | `online` 严格门禁通过后上架 | 绕过门禁的 status update |
| 合集目录 | catalogue draft 有变更 | `collection publish` | `online` 不能代替 publish |
| 合集正式版 | 已 publish | `collection item *` 开启下一轮目录草稿 / `online` | `collection update` 合并目录 |

## 8. 验证标准

一个改造 PR 只有同时满足以下条件才算合理：

1. 主路径命令没有读旧配置。
2. manifest/state schema 测试覆盖非法边界。
3. `publish` 和 `online` 的策略门禁分别被测试。
4. `resource import-dir` 与 `collection item import-dir` 语义被测试。
5. `status --json` 能解释平台草稿、本地 draftSync、owner、sync。
6. Windows 路径、中文路径、无 TTY、`--json` 都有最小验证。
