# 开发设计：命令规格

> 产品命令面：[../产品设计/02-命令面.md](../产品设计/02-命令面.md) · 写管线：[00](./00-总览与模块.md) · 字段约束：[03](./03-字段约束.md) · Console API：[API/Console资源页API对照表.md](./API/Console资源页API对照表.md)

本文只写最终用户入口。旧入口不保留为正式命令。

## 0. 公共行为

| 项 | 定稿 |
|---|---|
| 配置 | 读 `freelog.manifest.json`；写 `.freelog/state.json` |
| 交互 | 只有 TTY 且参数不足时才 prompt；无 TTY 或 `--yes` 缺关键参数 exit 4 |
| 输出 | 人读进度/警告走 stderr；结果走 stdout；`--json` 时 stdout 只输出 JSON |
| 写盘 | 原子写；manifest 只改用户意图；state 可重建 |
| 环境 | manifest 不绑定环境；state 记录当前 CLI env，跨环境读取非空 `state.env` 时 exit 2 |
| 错误 | service 抛 `CliError`；command 统一映射退出码 |

全局选项：`--cwd`、`--yes`、`--json`、`--no-auto-pull`、`--debug`、`--env <prod|test|dev>`。
`--debug` 只输出脱敏后的错误详情；token、password、cookie、authorization 不得出现在 stdout/stderr。
多级命令的父命令只注册 `subCommands`，不写抛错型 `run`；缺少子命令时交给命令框架输出 help/usage。
普通资源与合集共用 `freelog.manifest.json` 文件名，命令分流必须读取 manifest.subject，禁止只用“文件存在”判断合集。

## 1. 类型发现

### `type list`

| 项 | 定稿 |
|---|---|
| API | `FServiceAPI.Resource.listResourceTypesByGroup` |
| 输出 | 类型树/分组；`--json` 输出稳定数组 |
| 用途 | 让用户取得 `resourceTypeCode` |

### `type search <keyword>`

按 code、名称、分组搜索；没有匹配 exit 4 并提示 `type list`。

### `type info <code>`

| 输出 | 包含 |
|---|---|
| 人读 | 名称、code、文件提交模式、格式、大小、自定义配置支持、运行时要求 |
| JSON | 原始 typeInfo 的稳定投影 |

## 2. 本地初始化

### `init [dir]`

| 项 | 定稿 |
|---|---|
| 前置 | 不要求登录 |
| 步骤 | 选/收集 resource type -> 选 scaffold/template/runtime -> 拷模板或接入已有目录 -> 写 manifest/state/.gitignore |
| 写回 | `freelog.manifest.json`、`.freelog/state.json` 空壳 |
| 不做 | 不创建平台资源，不写 owner，不上传，不发版 |
| 非交互 | `--resource-type` 必填；runtime 模板须 `--template`；覆盖已有 manifest/state 须 `--yes` |

常见形态：

```bash
freelog-cli init my-theme --scaffold runtime --template vite-react-ts --resource-type <themeCode> --runtime 0.5 --yes
freelog-cli init . --scaffold none --resource-type <themeCode> --runtime 0.5 --yes
freelog-cli init my-photo --scaffold none --resource-type <imageCode> --yes
freelog-cli init my-album --scaffold collection --resource-type <collectionCode> --yes
```

`init .` 表示接入当前目录，不得生成 `-` 子目录。`--scaffold none` 只是不复制模板；如果用户传 `--runtime`，说明这是已有主题/插件项目，manifest 必须写入 `version.runtimeVersion`。

## 3. 全局状态

### `status`

| 项 | 定稿 |
|---|---|
| 前置 | 可无登录，但有登录时展示 auth/env |
| 步骤 | 读 manifest/state/auth；有 resourceId 时查 info/latest/draft |
| 写回 | 不写盘；需要刷新平台事实时使用 `pull` |
| 输出 | owner、resource、listing sync、latestVersion、version intent、platform draft |
| 退出码 | 正常 0；登录态失效可 2 |

### `pull`

| 项 | 定稿 |
|---|---|
| 前置 | 已登录；state 中有 resourceId |
| 步骤 | info -> latest version -> policies -> collection cache if needed |
| 写回 | 刷新 state；默认不覆盖 manifest |
| 选项 | `--apply-listing`、`--version <semver>`、`--collection`、`--all`、`--force` |
| 冲突 | `--apply-listing` 采用三方判断：manifest 相对 `state.sync.listingFingerprint` 未改动时可直接采用平台 listing；本地与平台都改过同字段时 exit 3，除非 `--force` |

## 4. 资源壳与 listing

### `create`

| 项 | 定稿 |
|---|---|
| 前置 | 已登录；manifest.subject=`resource`；state 无 resourceId |
| API | `FServiceAPI.Resource.create` |
| 参数 | 短 `name`、`resourceTitle`、`resourceTypeCode` |
| 写回 | state.resource，包括 resourceId、完整 resourceName、owner、status、type |
| 退出码 | 重复创建/缺字段 exit 4；未登录 exit 2 |

### `update`

| 项 | 定稿 |
|---|---|
| 前置 | Owner + Sync |
| API | `FServiceAPI.Resource.update` |
| 范围 | title、intro、coverImages、tags、baseUpcastResources 等 listing 字段 |
| 禁止 | 不接受 `status:1` 作为上架捷径 |
| 写回 | manifest listing 意图；平台成功后刷新 state |

## 5. 版本意图与正式发版

### `version set`

| 项 | 定稿 |
|---|---|
| 前置 | 有 resourceId 时 Owner + Sync；无 resourceId 时只改本地意图 |
| 步骤 | 校验参数 -> 合并到 manifest.version |
| 写回 | manifest |
| 不做 | 不上传、不保存平台草稿、不改 state.version.draftSync |
| 状态 | 当 version 或 filePath 变化时，清理旧 `state.version.fileSha1/filename/versionId`，避免把上一版发布产物显示成当前意图 |

典型：

```bash
freelog-cli version set --version 1.0.0 --file ./dist --description "first release"
freelog-cli dep add <resourceId> --range "^1.0.0"
```

### `publish`

| 项 | 定稿 |
|---|---|
| 前置 | Owner + Sync；typeInfo 校验；版本未占用；依赖授权完整 |
| 步骤 | 运行时类压缩构建目录 -> SHA1 -> fileIsExist/getResourceBySha1 -> upload if needed -> createVersion |
| API | `FServiceAPI.Storage.*` + `FServiceAPI.Resource.createVersion` |
| 写回 | state.version、state.resource.latestVersion；可按策略清理一次性 manifest 字段 |
| 退出码 | 未授权 exit 5；字段 exit 4；冲突 exit 3 |
| 禁止 | 不支持草稿参数；不隐式执行 `pnpm build` |

publish 可在没有本资源策略时创建正式版本；但后续 `online` 必须有 latestVersion + 启用策略。

失败 `--json` 的依赖授权契约：

```json
{
  "ok": false,
  "code": 5,
  "error": "DEPENDENCY_AUTH_INCOMPLETE",
  "message": "依赖授权未完成",
  "hint": "打开 Console 资源发版页或使用 dep auth --policy-map 完成免费策略签约",
  "unresolvedDependencies": [],
  "consoleHint": {
    "resourceId": "本资源 id",
    "suggestedPath": "/resource/detail?resourceId=..."
  }
}
```

### `version edit`

| 项 | 定稿 |
|---|---|
| 前置 | Owner + Sync；目标版本已存在 |
| API | `FServiceAPI.Resource.updateResourceVersionInfo` |
| 范围 | 已发布版本元数据 |
| 禁止 | 不换版本号、不换文件、不改依赖 |

## 6. 平台发版草稿

### `draft push`

| 项 | 定稿 |
|---|---|
| 前置 | Owner；草稿冲突算法 |
| 步骤 | manifest.version -> draftData；可选 `--upload` 写 selectedFileInfo；POST drafts |
| 写回 | state.version.draftSync |
| 选项 | `--force`、`--upload`、`--yes` |

### `draft pull`

拉平台 versions/drafts 到 manifest.version；保留本地 `version.filePath`；写 state.version.draftSync。无远端草稿 exit 4。

### `draft discard`

DELETE 平台草稿；清 state.version.draftSync。无草稿可幂等成功。

完整算法见 [04](./04-草稿转换层.md)。

## 7. 策略与上下架

### `policy apply --from-file <policy.json>`

| 项 | 定稿 |
|---|---|
| 前置 | Owner + Sync |
| API | `Resource.update(addPolicies)` 新增策略；`Resource.update(updatePolicies)` 只用于启停 |
| 输入 | 单策略或数组；只新增策略，schema 见 [03](./03-字段约束.md) |
| 写回 | 平台成功后刷新 state.resource.policies |
| 不做 | 不读取 manifest.policies 自动提交；不修改已有策略正文/名称；策略文本必须由 `--from-file` 明确指定 |

### `policy list`

读平台或 state；`--json` 稳定输出 policyId、policyName、status、updateDate。

### `policy set <policyId> --status <0|1>`

停用最后一条启用策略且资源已上架时 exit 4。

说明：Console/tools-lib 的 `updatePolicies` 契约只用于策略启停（`policyId + status`），不是策略正文编辑接口。CLI 因此不伪造策略正文 update；需要修改策略文本时，在 Console 修改或新增一条策略后切换启用状态。

### `online`

| 项 | 定稿 |
|---|---|
| API | 读取 info/policies 做门禁，再 `Resource.update({ status: 1 })` |
| 门禁 | latestVersion 存在；至少一条启用策略 |
| 不做 | 不自动创建策略；不把 listing update 当上架 |
| 幂等 | 已上架 exit 0 |

### `offline`

`Resource.update({ status: 4 })`；需要 `--yes` 或 TTY 确认。

## 8. 依赖

| 命令 | 定稿 |
|---|---|
| `dep add/remove/update` | 改 manifest.version.dependencies，随下一次 publish 生效 |
| `dep list` | 可展示平台依赖树与本地声明 |
| `dep auth --policy-map <file>` | 仅对已声明直接依赖创建免费策略合约；付费/交互 exit 5 |

`dep auth` 不调用 Payment / Transaction / `/events/payment`。

## 9. 多资源导入

### `resource import-dir <dir>`

目录下每个文件创建一个独立资源并发布首版。适合图片文件夹、视频文件夹变成多个单品资源。

| 项 | 定稿 |
|---|---|
| 前置 | 已登录；`--resource-type` 必填 |
| 步骤 | 扫文件 -> 每项建 manifest/state 子目录或 sidecar -> create -> version set -> publish |
| 失败 | 跑完汇总；任一失败 exit 4 |
| 不做 | 不创建合集；不把目录 zip 成一个资源 |

### `collection item import-dir <dir>`

每个文件先作为独立资源发布，再加入当前合集目录草稿。适合图片合集、视频合集。

## 10. 合集

| 命令 | API | 说明 |
|---|---|---|
| `collection create` | `Resource.create` subjectType=4 | 写 state.resource |
| `collection item add/remove/update/reorder` | `catalogues/drafts/*` | 管理目录草稿 |
| `collection update` | `Resource.update` + catalogueProperty | listing 与展示配置 |
| `collection version set` | 无平台调用 | 更新合集下一次 publish 的描述意图；官方接口说明合集固定版本，不支持传 version |
| `collection publish` | `Resource.updateCollection` | 合并目录草稿生成正式合集版本 |
| `collection collect-rules set` | `setCollectRules` | 声明式规则 |
| `collection rss send-code` | `Rss.sendVerificationCode` | 发邮件验证码 |
| `collection rss bind --code` | `Rss.bindRssFeed` | 无 code exit 4 |
| `collection rss sync` | `Rss.syncBinding` | 可轮询，超时 exit 1 |

合集 publish 不要求合集已有策略；合集 online 仍要求 latestVersion + 启用策略。

## 11. 用户入口收敛

本文列出的命令就是最终命令面。未列出的历史命令、历史参数和过渡别名不进入正式实现；内部可以选择批量 API，但不能暴露第二套用户命令。
顶层 `contract list` 不进入正式命令面；依赖签约统一走 `dep auth`，复杂合约查询回 Console。

## 12. 开写顺序

1. platform/tools-lib2 Node facade + auth/env/bootstrap + SHA1。
2. manifest/state schema 与原子读写。
3. `type *`、`init`、`status`、`pull`。
4. `create`、`version set`、`publish`、`policy`、`online/offline`。
5. `draft *`。
6. `resource import-dir`。
7. `collection *`。
8. `dep auth` 与 P2 能力。
