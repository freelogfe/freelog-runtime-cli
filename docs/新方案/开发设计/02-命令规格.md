# 开发设计：命令规格

> 产品「有哪些命令」→ [命令面](../产品设计/02-命令面.md)。  
> **实现横切**→ [08](./08-CLI工程约定.md)；**业务咬合**→ [09](./09-业务与CLI技术结合.md)。  
> 写管线 → [00-总览](./00-总览与模块.md) · 校验 → [03-字段约束](./03-字段约束.md) · API → [对照表](./API/Console资源页API对照表.md)。

## 公共行为（每条命令默认遵守）

| 项 | 定稿 |
|----|------|
| 交互 | 无 TTY 或 `--yes` 不得 `inquirer`；缺参 exit 4 |
| 输出 | 人读 → stderr 进度 + stdout 结果；`--json` 时 stdout 纯 JSON |
| 写盘 | 原子写 config；不写 token |
| 错误 | `CliError.code` → 进程退出码；带 hint |
| 临时文件 | `finally` 清理 |

## 规格模板（每条命令）

```text
命令:
前置: ensureOwner? ensureSynced? 校验?
步骤: 有序列表
API: Method Path（或内部 service）
写回: 哪些 config 字段
退出码: 0/2/3/4/5/1
选项: 必填 / 可选
非交互: 所需 flags 列表
```

---

## 1. 全局

### `status`

| 项 | 定稿 |
|----|------|
| 前置 | 可读本地 config；可选打平台 |
| 步骤 | 读 auth → 若有 resourceId 则 info → 比对 owner/同步/平台发版草稿 |
| API | `GET …/resources/{id}`（info）；`GET …/versions/drafts`（草稿有无） |
| 输出 | 人读 + `--json`：owner、sync、`platformVersionDraft`、`localDraftSync`（可 `null`）、远端有草稿且无 sync 时含 `draftAdvice`（见 [04 §9.2](./04-草稿转换层.md)） |
| 退出码 | 0；未登录可 2（若约定 status 允许未登录则 0+提示） |

### `pull`

| 项 | 定稿 |
|----|------|
| 前置 | 已登录；有 resourceId（或 `--collection`） |
| 步骤 | info（+ 最新 version / collection draft items）→ **覆盖**本地缓存（含 owner） |
| API | info；`resourceVersionInfo1`；合集 draft items / collectRules |
| 写回 | resource/version/collection config |
| 选项 | `--version` `--collection` `--all` `--cwd` |
| 备注 | **不提供** `syncr`/`syncv`；实现只写 `pull` |

### `init` / `login` / `logout`

`login`/`logout` 保持能力。`init`：**不写** owner、不调 `ServiceAPI.create`；脚手架规格 → [11-脚手架与模板](./11-脚手架与模板.md)（本地 `packages/templates/` + npm 回落；flags 非交互）。

## 2. 单品主路径

### `create`

| 项 | 定稿 |
|----|------|
| 前置 | 已登录；目录无 resourceId 或允许覆盖策略（定稿：已有 id 则 exit 4） |
| 校验 | [字段约束](./03-字段约束.md) §1 |
| API | `POST` create（及 `--from-dir` 时 createBatch 或循环 create） |
| 写回 | resourceId、owner、listing 初值 |
| 选项 | `--title` `--type` `--name` 全 flags；`--from-dir`；`--yes` |

### `updateVersion`

| 项 | 定稿 |
|----|------|
| 前置 | ensureOwner + ensureSynced |
| 步骤 | **只写本地** version.config；**不**调草稿 API、不改 draftSync |
| 写回 | version / description / filePath / deps 等意图字段 |
| 备注 | 跨端续编必须用户显式 `draft push` |

### `publish`

| 项 | 定稿 |
|----|------|
| 前置 | Owner + Sync；字段约束 §2；版本号未占用；授权完整 |
| 步骤 | 检测依赖授权 → 缺口则 **exit 5**（不调 createVersion）→ 处理 filePath（压缩/上传）→ `createVersion` → 写回 versionId/sha1 → 清空一次性 publish 字段 |
| API | upload / files；`POST …/versions` |
| 退出码 | 未授权 **5**；校验 **4**；冲突 **3** |
| 选项 | `--bump` `--yes`；**禁止** `--draft`（改走 `draft push`） |

#### publish exit 5（`--json` 契约）

人读（stderr）：依赖 resourceId 列表 + Console 发版/依赖页 hint。  
`--json` 时 stdout **仅**下列 shape（失败体；exit 5）：

```json
{
  "ok": false,
  "code": 5,
  "error": "DEPENDENCY_AUTH_INCOMPLETE",
  "message": "依赖授权未完成",
  "hint": "打开 Console 资源发版页或依赖 Tab 完成签约；Phase5 可用 dep auth --policy-map",
  "unresolvedDependencies": [
    {
      "resourceId": "…",
      "resourceName": "…",
      "resourceType": "…"
    }
  ],
  "consoleHint": {
    "resourceId": "本资源 id",
    "suggestedPath": "/resource/detail?resourceId=…"
  }
}
```

字段名稳定；禁止 silently rename（见 08）。

### `draft push` / `pull` / `discard`

完整算法与字段映射 → **[04-草稿转换层.md](./04-草稿转换层.md)**（§7–§8）。摘要：

| 命令 | 要点 |
|------|------|
| push | lookDraft → 冲突判定 →（可选 `--upload`）→ toDraftData → POST drafts → 更新 draftSync |
| pull | lookDraft → applyDraft → 保留 filePath → 更新 draftSync；无草稿 exit 4 |
| discard | DELETE drafts → 清 draftSync |

### `update` / `policy add|list` / `online` / `offline`

| 命令 | API | 要点 |
|------|-----|------|
| `update` | `update` listing | Owner+Sync；字段约束；**禁止**把 `status:1` 当作上架捷径 |
| `policy add` | update addPolicies | **`--from-file` 主路径**；校验 §6 schema；policyText **恰好一次** encode；名 2–20 |
| `policy list` | 读缓存/平台 | `--json`；启用/停用走 updatePolicies |
| `online` | **严格 resourceOnline** | 见下节；**禁止**软 `update(status:1)` |
| `offline` | status=4 | `--yes` |

#### `online`（严格门禁）

| 项 | 定稿 |
|----|------|
| API | 与 Console 侧栏硬上架同源：**resourceOnline**（或等价封装）；**不是** Step4 `update(status:1)` |
| 门禁 | 平台 `latestVersion` 存在 **且** ≥1 条 **启用**策略；否则 **exit 4** |
| 不代建 | 不自动 `policy add`；hint 指向 `policy add --from-file` |
| 已上架 | exit 0 + ℹ 已是上架（幂等） |
| 与 Console 分歧 | Step4 软上架资源若缺策略/版本，CLI `online` **仍拒**；见 [05 页面覆盖](./05-Console页面覆盖.md) · [API 对照](./API/Console资源页API对照表.md) |

失败 `--json` 示例：

```json
{
  "ok": false,
  "code": 4,
  "error": "ONLINE_GATE_FAILED",
  "message": "上架门禁未满足：需要 latestVersion 与至少一条启用策略",
  "gates": { "hasLatestVersion": false, "enabledPolicyCount": 0 },
  "hint": "先 publish 再 policy add --from-file，然后 online"
}
```

### `dep add|remove|list|update`

| 项 | 定稿 |
|----|------|
| 写 | 改本地 dependencies（随下版 publish）；Owner+Sync |
| `list` | 可读平台依赖树；`--json` / `--tree` |
| 签约 | Phase1：不在 dep 内嵌微应用；缺口在 publish 时 exit 5 + Console hint |

### `version edit`

| 项 | 定稿 |
|----|------|
| 前置 | Owner+Sync；目标版本已存在 |
| API | `updateResourceVersionInfo` |
| 范围 | 已发行版本元数据；**不**升版本、不换文件 |

### `dep auth`（Phase 5；字段本轮先锁）

| 项 | 定稿 |
|----|------|
| 选项 | `--policy-map <file>`（yaml/json，§6） |
| 步骤 | 解析 map → 校验 resourceId/policyIds → `batchSignContracts`（或平台等价）→ 汇总 |
| 部分失败 | 打印成功/失败明细；有未解决 → **exit 5**；参数非法 → **exit 4**；其它 → 1 |
| 与 publish | 也可在 createVersion 附属字段带已选策略（若 API 支持）；失败策略同 09 |

## 3. 合集

| 命令 | API 要点 | 备注 |
|------|----------|------|
| `collection create` | create subjectType=4 | 写 owner |
| `item add/remove/update/reorder` | catalogues/drafts/* | item add 允许他人 resourceId；本地路径则校该资源 owner |
| `collection update` | update + catalogueProperty | `--display-*` 枚举见页面覆盖文档 |
| `collection publish` | updateCollection isMergeCatalogueDraft | **授权门禁同构单品**：未授权 → **exit 5**，`--json` 同 §2 exit5 契约（`unresolvedDependencies` 可为空数组若仅条目授权缺口则用同字段或扩展 `unresolvedItems`） |
| `online` / `offline` | **严格** resourceOnline / status4 | 合集目录下同单品；**禁止**软 status:1 |
| `collect-rules *` | setCollectRules | 声明式 |
| `rss send-code` | Rss.sendVerificationCode | 发到邮箱；CLI 不收码 |
| `rss bind` / `sync` | bindRssFeed / syncBinding | 见下 |
| `logs` | getCollectionUpdateLogs | P2 |

#### `rss send-code` / `bind` / `sync`

| 步骤 | 定稿 |
|------|------|
| 1 | （可选）bindingsPreview；冲突 alreadyexists_* → exit 4 |
| 2 | `send-code <feedUrl>` → 平台发邮件；CLI 提示「查邮箱」 |
| 3 | `bind <feedUrl> --code <code> --yes`；**无 code → exit 4** |
| 4 | `sync` → syncBinding；可轮询 progress（超时 300s → exit 1 + hint 重试 sync） |
| 错误 | error_invalid / noemail → exit 4 + hint；网络 → 1 |
| CI | **人机混合**：流水线只能人工注入 `--code`，不能纯自动收邮箱 |

## 4. 明确删除（实现时不要保留用户入口）

| 旧入口 | 处理 |
|--------|------|
| `batch *` | 删除用户命令面；多资源用 `--from-dir` / 循环 `--cwd` |
| `syncr` / `syncv` | 删除；统一 `pull` |
| `publish --draft` | 删除；用 `draft push` |

## 5. 开写顺序（建议）

1. `platform/ServiceAPI` + `PlatformTool.getSHA1Hash` + Node Request（见 [10](./10-技术选型.md) / [API迁移](./API/API迁移清单.md)）；drafts POST/GET/DELETE  
2. ensureOwner/ensureSynced；切走主路径，停用旧 `src/api`  
3. `pull` / `status --json`  
4. `create`/`update`/`publish`/`online`（publish 走 Console 同序 sha1 链）  
5. `draft *` + adapter（04）  
6. 合集 item/publish/rss；删脏封装  
7. `dep auth --policy-map`

## 6. 声明式文件最小 schema（实现可直接用）

### policy.json（单策略或数组）

单对象或对象数组均可：

```json
{
  "policyName": "免费",
  "policyText": "<已是最终文本，非 Builder AST>",
  "status": 1
}
```

数组：

```json
[
  { "policyName": "免费", "policyText": "…", "status": 1 },
  { "policyName": "试用", "policyText": "…", "status": 1 }
]
```

| 字段 | 约束 |
|------|------|
| `policyName` | 必填；长度 2–20（与字段约束一致） |
| `policyText` | 必填；非空；CLI **恰好一次** `encodeURIComponent` 后提交 |
| `status` | 可选；默认 `1`（启用）；`0` 停用 |

非法 → **exit 4**（缺字段 / 名过长 / 空文本）。不做 Builder；文本须已是平台可接受的最终策略文。

### auth-map.yaml（Phase5，字段先锁）

文件名用户可用 `--policy-map`；扩展名 yaml/yml/json。最小字段：

```yaml
contracts:
  - resourceId: "依赖资源 id"
    policyIds: ["策略 id1", "策略 id2"]
```

等价 JSON：

```json
{
  "contracts": [
    { "resourceId": "…", "policyIds": ["…"] }
  ]
}
```

| 字段 | 约束 |
|------|------|
| `contracts` | 必填数组；可空则 exit 4 |
| `resourceId` | 必填非空字符串 |
| `policyIds` | 必填非空字符串数组 |

映射：`batchSignContracts` / createVersion 附属签约字段。部分失败：汇总 + exit **4**（参数）/ **5**（仍有未授权）/ **1**（其它），与 [09](./09-业务与CLI技术结合.md) 一致。
