# 开发设计：脚手架与模板（init）

> 仓库：[12](./12-仓库与发布管理.md) · 技术选型：[10](./10-技术选型.md) · 数据字段：[06](./06-Config字段.md)

`init` 只创建本地项目，不创建平台资源，不写 owner，不上传，不发版。

## 1. 核心口径

| 概念 | 定稿 |
|---|---|
| 资源 | 平台一等实体；类型来自 `type list/search/info` |
| 主题 / 插件 | 资源类型中的两类，发布时需要 runtimeVersion |
| 模板 | 可选本地工程骨架，不是资源类型本身 |
| `scaffold` | 只描述是否复制工程骨架，不描述资源是否运行时 |
| 发行管线 | `create -> version set -> publish -> policy apply -> online` |
| 无模板接入 | 图片、视频、已有主题/插件项目均可 `init --scaffold none` |
| 合集 | `init --scaffold collection`，后续 `collection create/item/publish` |

主题和插件共用 runtime 模板池；差异只体现在 `resource.typeCode` 和平台类型配置。

## 2. init 输出

```text
my-project/
├── freelog.manifest.json
├── .freelog/
│   └── state.json
└── ...
```

`.gitignore` 必含：

```gitignore
.freelog/state.json
.freelog/cache/
.freelog/tmp/
```

`freelog.manifest.json` 写用户意图：

1. `subject`
2. `identity.name`
3. `resource.typeCode`
4. `resource.title`
5. `version.filePath`
6. 提供 `--runtime` 时写 `version.runtimeVersion`
7. collection 模式的目录展示默认值

`.freelog/state.json` 初始为空壳，不含 owner。

## 3. 模板目录

```text
packages/templates/<id>/
  package.json
  template/
  template.manifest.json
```

| 模板类型 | 用途 | 说明 |
|---|---|---|
| `runtime` | 主题 / 插件 | Vite/Webpack 等工程模板；内嵌 freelog-runtime |
| `package` | 前端库 | react/vue/js 包工程 |
| `none` | 图片、视频、普通文件 | 不拷工程模板，只写 manifest/state |
| `collection` | 合集 | 不拷工程模板，只写合集 manifest/state |

模板 manifest 示例：

```json
{
  "id": "vite-react-ts",
  "npmName": "@freelog-cli/template-vite-react-ts",
  "title": "Vite React TS",
  "tags": ["runtime", "theme", "widget"],
  "version": "0.5.2",
  "runtimeVersions": ["0.5"],
  "freelogRuntimeRange": "^5.0.0",
  "filePath": "dist",
  "startCommand": "pnpm dev",
  "buildCommand": "pnpm build"
}
```

## 4. 命令面

```bash
freelog-cli type search 主题
freelog-cli init my-theme --scaffold runtime --template vite-react-ts --resource-type <themeCode> --runtime 0.5 --yes
freelog-cli init . --scaffold none --resource-type <themeCode> --runtime 0.5 --yes

freelog-cli type search 插件
freelog-cli init my-widget --scaffold runtime --template vite-vue-ts --resource-type <pluginCode> --runtime 0.5 --yes
freelog-cli init . --scaffold none --resource-type <pluginCode> --runtime 0.5 --yes

freelog-cli init my-photo --scaffold none --resource-type <imageCode> --resource-name cover-001 --yes

freelog-cli init my-album --scaffold collection --resource-type <collectionCode> --resource-name album-001 --yes
```

| 选项 | 说明 |
|---|---|
| `--scaffold` | `runtime` / `package` / `none` / `collection` |
| `--template` | runtime/package 必填；TTY 可选择 |
| `--resource-type` | 平台 resourceTypeCode；非交互必填 |
| `--runtime` | runtime scaffold 必填或默认 CLI 主档；只允许 `0.4` / `0.5` |
| `--resource-name` | 短授权名；默认目录名或当前目录名 |
| `--title` | 资源标题；默认目录名 |
| `--pm` | `pnpm` / `npm` / `yarn` |
| `--skip-install` | 不安装模板依赖 |
| `--templates-dir` | 本地开发模板目录 |

无 TTY 或 `--yes` 不得猜 `resourceTypeCode`。缺失就 exit 4，并提示 `type list/search`。

## 5. 版本纪律

| 对象 | 规则 | 例子 |
|---|---|---|
| 平台 runtimeVersion | `0.4` / `0.5` | manifest `runtimeVersion: "0.5"` |
| CLI 包 | `0.<档>.<patch>` | `0.5.3` |
| 模板包 | 与档位对齐 | `0.5.2` |
| `freelog-runtime` npm 依赖 | 保持库自身 major | runtime 0.5 对应 `^5.x` |
| 资源版本 | 独立 semver | `1.0.0` |

compat 表：

```text
packages/cli/compat/template-compat.json
```

要求：

1. `defaultRuntime` 与 CLI 版本第二位一致。
2. runtime 模板版本必须匹配对应档位。
3. compat 引用的模板必须存在于 npm 或 `--templates-dir`。
4. 不再引用历史 `1.x` / `3.x` 模板版本。
5. Vite ESM 模板使用 `import.meta.dirname` 解析本地路径，不使用 `__dirname`。

## 6. 模板解析顺序

```text
--templates-dir / FREELOG_TEMPLATES_DIR
  -> repo packages/templates/<id>
  -> npm 精确版本缓存 ~/.freelog-cli/templates/<npmName>/<version>
```

开发时优先本地模板；正式用户按 compat 精确版本下载。

## 7. init 后流程

已有主题/插件项目：

```bash
freelog-cli init . --scaffold none --resource-type <themeOrPluginCode> --runtime 0.5 --yes
pnpm build
freelog-cli create
freelog-cli version set --file ./dist --version 1.0.0
freelog-cli publish
freelog-cli policy apply --from-file policy.json
freelog-cli online
```

模板创建主题/插件项目：

```bash
freelog-cli init my-theme --scaffold runtime --template vite-react-ts --resource-type <themeCode> --runtime 0.5 --yes
cd my-theme
pnpm build
freelog-cli create
freelog-cli version set --file ./dist --version 1.0.0
freelog-cli publish
freelog-cli policy apply --from-file policy.json
freelog-cli online
```

单图片/视频：

```bash
freelog-cli create
freelog-cli version set --file ./cover.png --version 1.0.0
freelog-cli publish
```

合集：

```bash
freelog-cli collection create
freelog-cli collection item import-dir ./images --resource-type <imageCode> --item-policy-file ./item-policy.json --yes
freelog-cli collection publish
freelog-cli policy apply --from-file policy.json
freelog-cli online
```

## 8. 验收

| # | 场景 | 期望 |
|---|---|---|
| 1 | runtime init | 写 runtimeVersion、模板元数据、manifest/state |
| 2 | none init | 不要求 template；传 `--runtime` 时写 runtimeVersion，用于已有主题/插件 |
| 3 | collection init | subject=collection |
| 4 | 非交互缺 resource type | exit 4 |
| 5 | theme/plugin 同模板不同 typeCode | 均可创建与发布 |
| 6 | publish 前未 build | CLI 不构建；文件路径不存在 exit 4 |
| 7 | compat 版本不匹配 | 构建或 init 校验失败 |
| 8 | `init .` | 在当前目录写 manifest/state，不创建 `-` 子目录 |
