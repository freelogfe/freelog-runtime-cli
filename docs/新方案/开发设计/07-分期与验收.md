# 开发设计：分期与验收

> 目标态 only。先建稳定边界，再补体验命令。

## 1. 阶段

| 阶段 | 内容 | 验收锚点 |
|---|---|---|
| P0-1 | `@freelog/tools-lib2/node` facade、auth/env、SHA1、错误映射 | CLI 不加载浏览器入口；同文件 SHA1 与浏览器一致 |
| P0-2 | manifest/state schema、原子读写、context、CliError | init 后只有 manifest/state；无可执行用户配置 |
| P0-3 | `type *`、`init`、`status`、`pull` | 非交互可获取类型并初始化 |
| P0-4 | `create`、`update`、`version set`、`publish` | 单品 create -> publish 跑通 |
| P0-5 | `policy apply/list/set`、`online/offline` | 无策略 online 拒绝；有策略可上架 |
| P0-6 | `collection create/item/publish` | 合集目录草稿 -> 正式合集版本 |
| P1 | `draft *`、`resource import-dir`、`collection item import-dir`、RSS、display | 双端草稿冲突可控；文件夹场景跑通 |
| P2 | `dep auth`、collection logs、合集发版表单草稿 | 免费依赖签约自动化 |

## 2. 阻塞前置

1. `package.json` 安装 `@freelog/tools-lib2`。
2. CLI 只能从 `@freelog/tools-lib2/node` 取 `FServiceAPI/FUtil`。
3. 删除或停止使用旧 `src/api` 平行封装。
4. 补齐 drafts POST/GET/DELETE 的 tools-lib2 Node 可用性。
5. schema 先于命令落地，避免命令各自解析文件。

## 4. 质量门槛

| 类型 | 必测 |
|---|---|
| 单测 | schema、owner 比较、payload adapter、draft fingerprint、policy encode |
| 契约测 | FServiceAPI method/body/url 与 Console 对照 |
| E2E | CLI dist 命令、exit code、stdout/stderr、无 TTY |
| 平台联调 | 测试环境单品、合集、上下架、草稿 |
| OS | Windows + Linux |

## 5. 发布前停止条件

1. 还有命令读取旧配置文件。
2. 业务代码绕过 platform facade 直接拼 API。
3. `online` 能绕过 latestVersion 或 policy 门禁。
4. 非交互模式可能卡在 prompt。
5. manifest/state 边界被命令写乱。
