> 文档角色：**完整** Freelog 平台业务摘要：资源域（一期）+ 节点/市场/展品域（二期）。Console 证据：`freelogfe-web-repos/packages/console`；API：`@freelog/tools-lib`。节点域调用链见 [05](./05-Console源码证据与调用链.md)；资源域 Console 路径摘要见 §2.3。

## 1. 商业闭环

```text
┌─────────────┐    上架      ┌──────────────┐    签约      ┌─────────────┐
│  资源作者    │ ──────────→ │  资源市场     │ ──────────→ │  节点主      │
│  publish    │   status=1  │  discover    │  presentable │  nodeDomain │
│  online     │             │  /market     │              │  + 主题runtime│
└─────────────┘             └──────────────┘              └──────┬──────┘
                                                                  │
                                                                  ▼
                                                           ┌─────────────┐
                                                           │  C 端访客    │
                                                           │  浏览·购买   │
                                                           │  (Payment)  │
                                                           └─────────────┘
```

| 角色 | 目标 | CLI 覆盖 |
|---|---|---|
| 资源作者 | 生产并发版、上架 | ✅ 一期：`create` → `publish` → `online` |
| 节点主 | 选资源、签约、展品上下线 | ✅ 二期规划；**节点壳** → Console |
| C 端用户 | 访问、付费 | ❌ OUT |

## 2. 资源域（一期）

### 2.1 核心实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Resource** | `resourceId`, `resourceName`, `status` | `0` 未发行 / `1` 上架 / `2` 冻结 / `4` 下架 |
| **Version** | `version`, `fileSha1`, `versionId` | 发布后 fileSha1 不可变；变更须新版本 |
| **Policy** | `policyId`, `policyText`, `status` | 上架须至少一条启用策略 |
| **Collection** | `subjectType=4`, 目录条目 | 与「批量独立资源」不同 |

**本地对象：** `freelog.manifest.json`（意图）、`.freelog/state.json`（平台事实）。详见 [00 §7](./00-产品设计总览.md)。

```text
login → init → create → validate → publish → dep auth? → policy apply/set → online
  → update / version edit / pull / draft / offline（维护）
```

| 合集 | `collectionSidebar` | `collection *` | C-01~C-10 |

完整能力表见 [04 §2–§5](./04-能力矩阵与验收.md)。

## 3. 核心实体（节点 · 市场 · 展品）

### 3.1 Node（节点）

| 字段 | 说明 |
|---|---|
| `nodeId` | 平台主键 |
| `nodeName` | 唯一标识（≤24，正则约束） |
| `nodeDomain` | 域名前缀（4–24，`a-z0-9-`） |
| `nodeTitle` | 展示标题（≤100） |
| `nodeThemeId` | 当前激活主题展品关联 |
| `ownerUserId` | 节点主 |
| `status` | `1` 公开 / `2` 私密 / `8` 暂停；`&4` 冻结；`-1` 删除 |

**API（tools-lib `Node`）：** `create`、`details`、`nodes`、`setNodeInfo`、`deleteNode`、`searchForClient`

**Console 创建流程**（`/node/creator`）：
1. 校验 `nodeName`、`nodeDomain` 唯一 → `Node.details`
2. `Node.create({ nodeName, nodeDomain, nodeTitle })` → **`nodeId`**
3. UI 提示每用户节点数上限（业务规则以平台为准）

### 3.2 Resource / Market listing（市场条目）

市场 **不是** 独立表；条目 = **已上架资源** 的分页列表。

**Console**：`/market` → `discoverPage` model

**列表 API**：`Resource.list`

| 参数 | 说明 |
|---|---|
| `status` | 固定 `1`（已上架） |
| `operationCategoryCode` | 运营分类 |
| `operationTypes` | `4,5` 首页推荐 / `5` 编辑精选 / `3,4,5` 最新 |
| `resourceType` | 类型筛选，`-1` 表全部 |
| `skip` / `limit` | 分页 |

**列表项关键字段**：`resourceId`、`resourceTitle`、`latestVersion`、`policies[]`、`operationType`、`subjectType`（1 资源 / 4 合集等）

**详情**：`Resource.info` — 签约前必查 `status === 1`

### 3.3 Presentable / Exhibit（展品）

| 字段 | 说明 |
|---|---|
| `presentableId` | 展品 ID |
| `nodeId` | 所属节点 |
| `resourceId` | 源资源 |
| `version` | 挂载版本 |
| `onlineStatus` | `0` 下架 / `1` 上架 |
| `subjectType` | `1` 单品 / `4` 挂载合集 / `5` 自建合集 |

**API（tools-lib `Exhibit`）：** 见 `presentables.ts` — `createPresentable`、`batchCreatePresentable`、`presentables`（列表）、`presentablesOnlineStatus`、`presentablesVersion` 等

### 3.4 Contract（合约）

签约后在节点与资源之间形成 **授权合约**。

- 节点 **授权出去**（licensor = node）：`Contract.contracts({ identityType: 1, licensorId: nodeId })`
- 节点 **被授权**（licensee = node）：`identityType: 2, licenseeId: nodeId`

**批量签约 payload**（主题创建等）：

```typescript
Contract.batchSign({
  subjects: [{ subjectId, policyId }],
  subjectType: 1,
  licenseeId: nodeId,
  licenseeIdentityType: 2  // 节点方
})
```

**节点** ≈ 店铺（`nodeDomain` + 主题 runtime）。**展品** ≈ 店铺 SKU。**市场** ≈ 已上架资源 catalog。

## 4. 关键业务流程

### 4.1 资源进入市场（一期 CLI 已覆盖）

```text
create → publish → policy apply/set → online
→ Resource.status = 1 → 出现在 market list
```

### 4.2 签约至节点（二期核心）

Console 有 **两条路径**：

| 路径 | 入口 | CLI 是否采用 |
|---|---|:---:|
| **A MicroApp** | 资源详情「签约至节点」→ qiankun 子应用 | ❌ |
| **B Drawer/API** | `fSignResourceToNodeDrawer` → `batchCreatePresentable` | ✅ **真源** |

**路径 B 步骤（headless 等价）：**

```text
1. Node.nodes / details     → 确认 node 存在、当前用户 = owner
2. Resource.info            → status === 1
3. Resource.batchInfo       → 资源元数据
4. Resource.batchAuth       → 授权链 warning（authException 可警告）
5. User.batchUserList       → 作者未冻结
6. Exhibit.presentableDetails → 同 node+resource 未重复签约（可选）
7. Exhibit.batchCreatePresentable({ nodeId, resources: [{ resourceId, policyId? }] })
8. 平台返回 per-resource `{ status: 1|2, data?: string }` — **CLI 不得假设 `data` 即 presentableId**；须 `presentableDetails` 反查（[07-Q1](./07-开放问题与设计裁决.md)）
```

**策略选择：**
- 默认永久免费（与 Drawer 一致）
- 或 CLI 传 `--policy <policyId>`（来自 `Resource.info.policies`）
- 新建策略 → `Resource.update({ addPolicies })`（与一期 policy 能力共用）
- **付费策略** → handoff Console 合约/收银（OUT）

### 4.3 展品上下架

**上架**（Console `onlineExhibit` / `nodeTools.tsx`）：

```text
1. 展品须有至少一条 **启用** policy
2. 若无 policy → Console 弹 policy builder（CLI：预检失败 code 4，hint 先 apply policy）
3. Exhibit.presentablesOnlineStatus({ presentableId, onlineStatus: 1 })
```

**下架：**

```text
Exhibit.presentablesOnlineStatus({ presentableId, onlineStatus: 0 })
或 batchUpdatePresentableStatus
```

**批量：** `batchUpdatePresentableStatus({ presentableIds[], onlineStatus })` — 部分失败返回 per-id status

### 4.4 主题激活

**场景：** 节点必须有一个 **上线** 的「主题」类展品，`nodeThemeId` 才生效。

**Console**（Themes tab）：
1. `Exhibit.presentables({ nodeId, resourceType: '主题' })`
2. `Exhibit.batchAuth` 校验
3. 若已有主题 → 确认切换
4. `onlineExhibit(presentableId)` — 与普通展品上架同一套 policy 门禁

**CLI：** **OUT** — 主题切换涉及确认 UI 与 policy 链，留在 Console；Agent 不负责改 `nodeThemeId`。

### 4.5 展品版本

| 操作 | API |
|---|---|
| 切换到资源最新版 | `presentablesVersion({ presentableId, version })` |
| 忽略更新提醒 | `ignorePresentableVersionUpdateTip` |
| 自动更新开关 | `updatePresentable({ autoUpdateStatus })` |

### 4.6 正式节点管理 Tab 映射

| Tab | Console | 二期 CLI |
|---|---|---|
| 展品管理 | exhibitEffects | `node exhibit *` ✅ |
| 主题管理 | themeEffects | **OUT**（Console） |
| 合约管理 | nodeManager_Contract_Page | `node contract list`（只读，可选） |

| 交易记录 | Payment | **OUT** |

## 7. 门禁汇总（CLI 须一致实现）

| 门禁 | 检查点 | 失败 code |
|---|---|:---:|
| 资源 frozen | publish/online preflight | 4 |
| 依赖未授权 | publish preflight | 5 + handoff |
| 未登录 | `requireAuth` | 4 |
| 非节点 owner | `Node.details.ownerUserId` | 2 |
| 节点冻结/删除 | `status & 4` / `-1` | 2 |
| 资源未上架 | `Resource.info.status !== 1` | 4 |
| 资源作者冻结 | `User.batchUserList` | 4 |
| 重复签约 | `presentableDetails` 已有 | 4 |
| 展品上架无启用 policy | preflight | 4 |
| 展品 online 时资源非上架/冻结 | `Resource.info` **当前** status（Q10） | 4 |
| sign 后资源下架但展品仍 online | 文档 + hint；CLI 不 silent 成功 | — |
| 需付费签约 | 策略/合同 | 5 + handoff |

## 9. 两条签约链

| 概念 | 一期 `dep auth` | 二期「签约至节点」 |
|---|---|---|
| 主体 | 发布者签 **依赖** | 节点主签 **市场资源** |
| licensee | 发布者 userId | **nodeId**（identityType=2） |
| 结果 | 版本可发行 | **presentable** 创建 |
| API | `createVersion` 内 batchSignContracts | `batchCreatePresentable` |

**不得混淆** 两条签约链；CLI 文档与错误 hint 须区分 `dep auth` vs `node exhibit sign`。

### 9.1 CLI IN / OUT（完整摘要）

| IN（Agent 可自动化） | OUT（Console / 人工） |
|---|---|
| 资源 create/publish/update/online（一期） | 节点 create/update/delete |
| `market search/show` | 主题 activate、域名/Logo/可见性 |
| `node list/show`（只读 `nodeId`） | 支付、提现、测试节点 |
| `node exhibit sign/list/online/offline` | 可视化策略编辑、封面裁剪 |
