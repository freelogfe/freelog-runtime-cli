# 产品设计：结论与原则

> 定稿基准：开发设计 [14 无旧负担脚手架目标设计](../开发设计/14-无旧负担脚手架目标设计.md) + [15 资源生命周期拓扑设计](../开发设计/15-资源生命周期拓扑设计.md)。

## 1. 总结论

新 CLI 是面向脚手架和本地资源发行的工具，不承担旧 CLI 兼容。设计从一开始采用：

1. `freelog.manifest.json`：用户发布意图，提交 git。
2. `.freelog/state.json`：CLI 平台状态镜像，不提交 git。
3. `@freelog/tools-lib2/node`：CLI 唯一平台接口入口。
4. Console 源码：业务契约依据。
5. CLI 交互：人可选择，CI 必须显式传参。

旧 `freelog.resource.config.*` / `freelog.version.config.*` / `freelog.collection.config.*`、`updateVersion` 作为最终主命令、`batch *`、`syncr`、`syncv`、`publish --draft` 都不进入新命令面。

## 2. 产品原则

| 原则 | 定稿 |
|---|---|
| 平台事实权威 | resourceId、完整 resourceName、owner、status、latestVersion、policyId、draftSync 等状态只写 state。 |
| 用户意图可审阅 | 标题、短授权名、类型 code、发版文件路径、依赖、策略、合集目录意图写 manifest。 |
| 命令按拓扑分层 | `create` 建壳，`update` 改基础信息，`version set` 改下一版意图，`publish` 发正式版本，`online` 上架。 |
| Console 对齐契约 | 对齐 API payload、字段语义、门禁；不复刻 React 向导、弹窗、防抖、微应用。 |
| publish 不绑定策略 | 没有本资源策略也能发正式版本；缺启用策略只阻断 `online`。 |
| 类型来自平台 | 资源类型通过 `type list/search/info` 或交互选择；不能要求用户去 Console 找 code。 |
| 文件处理由类型决定 | 主题/插件/库发布构建目录 zip；图片/视频/普通文件上传原文件；格式和大小按平台类型配置校验。 |
| 合集是资源目录 | 文件夹合集不是上传文件夹 zip，而是每个文件成为单品，再加入合集目录。 |
| 非交互可自动化 | CI/`--yes` 不猜关键字段；缺类型、模板、runtime、filePath 时 exit 4。 |
| 删除旧命令负担 | 新脚手架没有旧命令兼容，不把设计绑在旧实现上。 |

## 3. 关键差异

| Console | CLI |
|---|---|
| 四步向导 | 拆成可组合命令。 |
| 选择资源类型控件 | `type list/search/info` + TTY 选择。 |
| 300ms 自动保存草稿 | `draft push/pull/discard` 显式操作。 |
| Step4 可软 `status:1` | `online` 始终检查 latestVersion + 启用策略。 |
| 策略 Builder | CLI 只接受 `policy apply --from-file` 的最终策略文本，不内置 Builder。 |
| 授权微应用 | CLI 支持声明式免费依赖签约；付费/交互签约引导 Console。 |

## 4. 主路径

单品：

```bash
freelog-cli init . --scaffold none --resource-type <code>
freelog-cli create
freelog-cli version set --version 1.0.0 --file ./dist
freelog-cli publish
freelog-cli policy apply --from-file ./policy.json
freelog-cli online
```

项目型资源：

```bash
pnpm build
freelog-cli init . --scaffold none --resource-type <themeOrWidgetCode> --runtime 0.5
freelog-cli create
freelog-cli publish
```

合集：

```bash
freelog-cli init album --scaffold collection --resource-type <collectionCode>
cd album
freelog-cli collection create
freelog-cli collection item import-dir ../photos --resource-type <imageCode> --item-policy-file ./item-policy.json
freelog-cli collection publish
freelog-cli policy apply --from-file ./policy.json
freelog-cli online
```

## 5. 非目标

| 非目标 | 原因 |
|---|---|
| 复刻 Console 页面向导 | CLI 应可脚本化和组合。 |
| 自动生成策略 | 策略是业务授权文本，必须由用户明确提供。 |
| 自动运行项目 build | 构建命令属于用户项目；P0 不隐式执行。 |
| 把合集文件夹打包成单个资源 | 合集语义是资源目录，不是压缩包。 |
| 支付签约 | 涉及支付密码、订单和用户确认，交给 Console。 |
| 旧 config 迁移 | 新脚手架无旧代码负担。 |

## 6. 成功标准

1. 一个已有 React 主题项目能 `init . -> create -> publish`。
2. 一个已有 Vue 插件项目能发布构建目录 zip。
3. 单个图片/视频能发布原文件。
4. 图片/视频文件夹能批量创建单品并加入合集。
5. 无策略可 publish；无启用策略不可 online。
6. Console 发版草稿能通过 `draft pull` 接回。
7. 所有命令清楚写 manifest 或 state，不出现混写。
