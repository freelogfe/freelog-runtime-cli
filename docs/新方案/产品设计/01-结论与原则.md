# 产品设计：结论与原则

> 命令面 → [02-命令面.md](./02-命令面.md) · 实现 → [开发设计/](../开发设计/) · **无旧命令兼容**

## 1. 产品结论

| 要点 | 定稿 |
|------|------|
| API 同源 | 与 Console 同一接口库契约（`FServiceAPI` 路径 / Method / Body）；CLI 落在 `platform/ServiceAPI`，不整包吃浏览器 tools-lib；Tool（如 sha1）语义对齐 `FUtil.Tool` |
| 资源类型优先 | 主题/插件/前端库等均是平台**资源类型**（create 传 type code）；工程模板可选且主题↔插件**共用**；`create`/`publish` 等发行命令**通用** |
| 运行时 / 脚手架 / 模板版本 | 本仓版本 `0.4.x`/`0.5.x` 对齐运行时档；仅运行时类资源 publish 必带 runtimeVersion；见开发 [11](../开发设计/11-脚手架与模板.md) |
| 语义对齐、形态可异 | 对齐 Save API 与门禁；不对齐页面 / 弹窗 / 微应用 |
| 平台优先 | 平台权威；`freelog.*.config` 仅为 CLI 缓存，**禁止手改** |
| 先同步再改 | 写前与平台一致；落后默认 auto-pull（`--no-auto-pull` 可关） |
| 多资源非第二套命令 | `create --from-dir` 或循环 `--cwd`；**无 `batch *`** |
| Owner 绑定 | resource / collection 必有 `userId`+`username`；写前以平台 info 核对 |
| 字段约束同源 | 见 [开发设计/03-字段约束](../开发设计/03-字段约束.md) |
| 三态发版 | 本地意图 / 平台草稿 / 正式版；草稿显式 `draft push\|pull` |
| 无旧命令兼容 | 删除 `batch` / `syncr` / `syncv` / `publish --draft` |

## 2. Console ↔ CLI

完整映射与人机混合 → **[05-Console与CLI对照](./05-Console与CLI对照.md)**。

```text
Console: 打开页 → Load API → 编辑 → Save API
CLI:     （可 auto）pull → 命令+flags/文件 → Save API → 写回缓存
```

### 向导拆命令（无 `wizard`）

| Console | CLI | 原因 |
|---------|-----|------|
| Step1 创建壳 | `create` | 任务原子 |
| Step2 上传+首版/草稿 | `updateVersion` + `publish`（跨端 WIP 才 `draft push`） | 本地定意图再上传，便于 CI；**不跟 300ms 防抖** |
| Step3 策略 | `policy add --from-file` | 不做 Builder |
| Step4 完善并上架 | `update` + **`online`（严格 resourceOnline）** | listing 与上下架可拆；**不跟软 `update(status:1)`** |
| 打开页自动拉数 | 写命令可 auto-pull | 无「打开页」事件 |

### 原则钉死（防分叉）

| 项 | 定稿 |
|----|------|
| 软上架 | Console Step4 可弱门禁 `status:1`；CLI **禁止**模仿；`online` 始终严格 |
| 防抖草稿 | Console 自动 `saveVersionsDraft`；CLI **永不**自动；靠 `status` 发现远端草稿 |
| 向导命令 | **不提供** `wizard`；流程见 [03-用户流程](./03-用户流程.md) |

## 3. 配置角色

| 文件 | 内容 | 谁写 |
|------|------|------|
| `freelog.resource.config` | owner + listing + 策略 + status | 仅 CLI |
| `freelog.version.config` | userId + 版本意图 / 同步缓存 / draftSync | 仅 CLI |
| `freelog.collection.config` | owner + listing + items 摘要 + catalogueProperty | 仅 CLI |

不引入用户向 `batch-resources.config`。Console 可改字段必须有 flag / 文件入口。

## 4. CLI 层原则

| # | 原则 | 定稿 |
|---|------|------|
| 1 | 不镜像 UI | 按任务拆命令，不按侧栏 Tab |
| 2 | 非交互优先 | 全 flags；TTY 可选；CI 用 `--yes` |
| 3 | 声明式输入 | 策略 `--from-file`；排序 `--order-file`；授权 `--policy-map`（后期） |
| 4 | 同步省事 | 仅落后 → auto-pull；冲突 → 阻断 |
| 5 | 可脚本化 | 统一退出码；关键命令 `--json`；无 TTY 可跑通（见开发设计/08） |
| 6 | 授权不装微应用 | 未授权 → exit 5；后期 policy-map 或引导 Console |
| 7 | RSS | `bind --code` 必填；CLI 不做验证码 UX 主场 |
| 8 | 命令面收敛 | 展示设置并入 `collection update`；logs/contract 为 P2 |
| 9 | 目录即上下文 | 一目录一资源 + `--cwd` |
| 10 | 草稿显式互通 | `updateVersion` 只写本地；跨端用 `draft push/pull`；禁止自动 saveDraft |
| 11 | 无旧命令兼容 | 目标命令面即唯一入口 |

### 退出码

| Code | 含义 |
|------|------|
| 0 | 成功 |
| 2 | 未登录 / Owner 不符 |
| 3 | 同步或草稿冲突 |
| 4 | 字段 / 业务校验失败 |
| 5 | 依赖授权未完成 |
| 1 | 其它错误 |

### 反模式（不做）

| 反模式 | 原因 |
|--------|------|
| 主路径复刻 Step1–4 向导 / `wizard` 命令 | 用文档脚本序列代替 |
| 每 Tab 一个必学命令 | 命令膨胀 |
| 每次 `updateVersion` 自动存平台草稿 / 300ms 防抖 | 防抖会话不属于 CLI |
| CLI 用 `update(status:1)` 当上架 | 与严格 online 分叉 |
| 无 flags、只能问卷 | CI 不可用 |
| 内嵌浏览器微应用授权 | 成本过高 |
| 把 `draftData` 当 CLI 一等模型 | 经防腐层进出 |
| 保留 batch / syncr / syncv / publish --draft | 违背无兼容原则 |
