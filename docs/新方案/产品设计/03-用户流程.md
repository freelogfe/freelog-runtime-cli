# 产品设计：用户流程

> 命令面见 [02](./02-命令面.md)，拓扑见开发设计 [15](../开发设计/15-资源生命周期拓扑设计.md)。

## 1. 单品首次发布

目标：从本地文件或构建产物创建资源、发布首版、可选上架。

```bash
freelog-cli login
freelog-cli init . --scaffold none --resource-type <code>
freelog-cli create
freelog-cli version set --version 1.0.0 --description "初始版本" --file ./dist
freelog-cli publish
freelog-cli policy apply --from-file ./policy.json
freelog-cli online
```

规则：

1. `create` 只创建资源壳。
2. `version set` 只写 manifest。
3. `publish` 创建正式版本，无策略也可执行。
4. `policy apply --from-file` 应用策略。
5. `online` 要求 latestVersion + 至少一条启用策略。

Console 对照：

| Console | CLI |
|---|---|
| Step1 创建资源 | `create` |
| Step2 上传并创建版本 | `version set` + `publish` |
| Step3 策略 | `policy apply --from-file` |
| Step4 基础信息与上架 | `update` + `online` |

## 2. 主题 / 插件项目发布

已有项目：

```bash
cd my-react-theme
pnpm build
freelog-cli init . --scaffold none --resource-type <themeCode> --runtime 0.5
freelog-cli create
freelog-cli publish
```

新建模板项目：

```bash
freelog-cli init my-vue-widget --scaffold runtime --template vite-vue-ts --resource-type <widgetCode> --runtime 0.5
cd my-vue-widget
pnpm build
freelog-cli create
freelog-cli publish
```

规则：

1. 主题/插件共用 runtime 模板池。
2. `publish` 压缩构建产物目录。
3. `publish` 不隐式执行 build。
4. 运行时类资源必须有 `runtimeVersion`。

## 3. 单图片 / 单视频发布

```bash
mkdir cover-resource
cd cover-resource
freelog-cli init . --scaffold none --resource-type <imageCode>
freelog-cli version set --version 1.0.0 --file ../cover.png
freelog-cli create
freelog-cli publish
```

视频同理：

```bash
freelog-cli init . --scaffold none --resource-type <videoCode>
freelog-cli version set --version 1.0.0 --file ../movie.mp4
freelog-cli create
freelog-cli publish
```

规则：

1. 图片/视频上传原文件，不压缩。
2. 格式和大小按 `type info` 返回的平台配置校验。
3. 视频封面 P0 只走 listing cover，不伪造 createVersion 视频封面字段。

## 4. 更新基础信息

```bash
freelog-cli pull
freelog-cli update --title "新标题" --intro "介绍" --tags "a,b" --cover ./cover.png
```

规则：

1. 只调用 listing 更新。
2. 不改版本。
3. 不改策略。
4. 不改上下架状态。

## 5. 发新版

```bash
pnpm build
freelog-cli status
freelog-cli pull
freelog-cli version set --version 1.1.0 --description "新功能" --file ./dist
freelog-cli publish
```

或：

```bash
freelog-cli publish --bump patch
```

规则：

1. 新版本必须大于平台 latestVersion。
2. 依赖授权未完成时 `publish` exit 5。
3. 不因为本资源缺策略而阻断 `publish`。
4. 已上架状态不影响发新版，冻结除外。

## 6. 编辑已发布版本说明

```bash
freelog-cli version edit --version 1.0.0 --description "修正文案"
```

规则：

1. 不上传文件。
2. 不改 SHA1。
3. 不改依赖。
4. 不创建新版本。

## 7. 平台草稿协作

CLI 到 Console：

```bash
freelog-cli version set --version 1.2.0 --file ./dist --description "WIP"
freelog-cli draft push
# Console 续编
freelog-cli draft pull
freelog-cli publish
```

Console 到 CLI：

```bash
freelog-cli status
freelog-cli draft pull
freelog-cli publish
```

规则：

1. `draft push/pull` 是显式操作。
2. CLI 不做 300ms 自动保存。
3. `draft pull` 可以更新 manifest.version，但保留本地 filePath。
4. 冲突 exit 3；`--force` 才覆盖远端。

## 8. 多文件发布为多个单品

```bash
freelog-cli resource import-dir ./photos --resource-type <imageCode> --title-prefix "照片 "
```

规则：

1. 每个文件一个资源。
2. 每个文件发布首版 `1.0.0`。
3. 不创建合集。
4. 部分失败不回滚成功项。

## 9. 图片 / 视频文件夹用于合集

图片合集：

```bash
freelog-cli init photo-album --scaffold collection --resource-type <collectionCode>
cd photo-album
freelog-cli collection create
freelog-cli collection item import-dir ../photos --item-type <imageCode> --title-prefix "照片 "
freelog-cli collection publish
freelog-cli policy apply --from-file ./policy.json
freelog-cli online
```

视频合集：

```bash
freelog-cli init video-album --scaffold collection --resource-type <collectionCode>
cd video-album
freelog-cli collection create
freelog-cli collection item import-dir ../videos --item-type <videoCode> --title-prefix "视频 "
freelog-cli collection publish
freelog-cli policy apply --from-file ./policy.json
freelog-cli online
```

规则：

1. 文件夹不打包为合集文件。
2. 每个文件成为独立单品资源。
3. 成功项加入合集目录草稿。
4. `collection publish` 才合并目录草稿。
5. 合集缺策略不阻断 `collection publish`，只阻断 `online`。

## 10. 合集维护

```bash
freelog-cli pull --collection
freelog-cli collection update --title "新名" --display-sort asc
freelog-cli collection item add <resourceId>
freelog-cli collection item reorder --order-file ./order.json
freelog-cli collection publish
```

规则：

1. `collection update` 改 listing/display。
2. `collection item *` 改目录草稿。
3. `collection publish` 合并目录草稿。
4. `collection item add <resourceId>` 可加入他人已发布资源，因为这是引用，不是修改他人资源。

## 11. 自动收录 / RSS

```bash
freelog-cli collection collect-rules set --from-file ./rules.json
freelog-cli collection rss send-code <feedUrl>
freelog-cli collection rss bind <feedUrl> --code <code>
freelog-cli collection rss sync
```

规则：

1. RSS 邮箱验证码不能纯自动化。
2. CI 只能人工注入 `--code`。
3. RSS 同步后用 `status` / `pull --collection` 查看平台事实。

## 12. CI 示例

```bash
freelog-cli init . --scaffold none --resource-type "$TYPE" --runtime "$RUNTIME" --yes
freelog-cli create --yes
freelog-cli version set --version "$VERSION" --file "$FILE" --description "$DESC"
freelog-cli publish --yes
freelog-cli policy apply --from-file ./policy.json --yes
freelog-cli online --yes
```

规则：

1. CI 必须显式传类型、模板、runtime、filePath 等关键字段。
2. CI 不进入交互选择。
3. 结构化输出用 `--json`。
