# 工程化与预检

[返回使用文档目录](./README.md)

## 项目配置

初始化项目级配置和忽略文件：

```bash
freelog-cli config init --default-env <env>
freelog-cli config show
```

修改默认环境：

```bash
freelog-cli config set --default-env <env>
```

`.freelog/config.json` 的 `defaultEnv` 只能是获授权的 `dev` 或 `test`，可减少重复参数；CI 中仍建议显式传 `--env <env>`，让日志能够直接显示目标环境。

## 忽略批量输入文件

在项目或导入目录创建 `.freelogignore`：

```gitignore
draft.*
*.tmp
```

批量发行和 Studio 选择文件时会遵循这些规则，并始终排除凭据、`.freelog/` 和 Git 元数据。

## 预检

```bash
freelog-cli validate --for project --env <env>
freelog-cli validate --for publish --env <env>
freelog-cli validate --for online --env <env>
freelog-cli doctor --json --env <env>
```

| 深度 | 检查内容 |
|---|---|
| `project` | 登录、manifest 和基本项目结构 |
| `publish` | 版本、发行物、owner、同步和授权 |
| `online` | 正式版本、启用策略和上架状态门禁 |

`doctor` 是 `validate` 的别名。预检失败使用退出码 `4`，不会执行发行或上架。

## 查看本地与平台差异

```bash
freelog-cli diff --env <env>
freelog-cli diff --json --env <env>
```

检测到漂移时退出码为 `3`，可用于 CI 门禁。根据差异选择 `pull`、`pull --apply-listing` 或保留本地意图后执行对应更新命令。

## 自动发版

```bash
freelog-cli release --bump patch --build-cmd "pnpm build" --online --yes --env <env>
```

流水线顺序为：

```text
validate -> 可选 build -> 计算下一版本 -> publish -> 可选 online
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--bump patch\|minor\|major` | 基于最新版本计算下一版本 |
| `--build-cmd <command>` | 发行前执行项目构建命令 |
| `--online` | 发行成功后继续上架 |
| `--dry-run` | 执行 publish 计划，不上传或写平台 |
| `--skip-validate` | 跳过预检，不建议在正式发版使用 |
| `--changelog-from-git` | 使用最近一次 Git 提交正文作为版本说明 |
| `--no-auto-pull` | 平台 listing 漂移时直接失败 |

`release --dry-run` 不会上架。合集工程会执行合集发布计划，但合集不支持 `--bump`。

## CI 建议

```bash
freelog-cli status --json --env <env>
freelog-cli diff --json --env <env>
freelog-cli validate --for publish --json --env <env>
freelog-cli publish --yes --json --env <env>
```

CI 应做到：

1. 固定经过验证的 CLI 版本和 Node.js 主版本。
2. 使用受保护变量提供登录信息和 `FREELOG_CRYPTO_KEY`。
3. 显式传环境、`--yes` 和 `--json`。
4. 根据进程退出码判断成功，不解析人类可读日志。
5. 保存必要的脱敏 JSON 和批量报告，不保存凭据。
6. 发行前构建最终产物，并在构建后重新预检。

## monorepo

```bash
freelog-cli workspace list --cwd . --depth 5
freelog-cli pull --all --cwd . --env <env>
```

根目录工作区凭据可供子项目继承。某个子项目需要其他账号时，在该子目录单独登录。

## 非交互创建主题或插件

```bash
freelog-cli init theme my-theme --template vite-react-ts --runtime 0.5 --yes --env <env>
freelog-cli init widget my-widget --template vite-vue-ts --runtime 0.5 --yes --env <env>
```

模板 ID 先通过 `template list --scaffold runtime` 查询。当前公开文档不包含尚未进入正式验收范围的其他脚手架预设。
