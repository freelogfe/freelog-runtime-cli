# 登录与环境

[返回使用文档目录](./README.md)

## 运行环境

当前 CLI 仅开放以下环境值：

| 值 | 用途 |
|---|---|
| `test` | 获得测试环境权限后用于验收 |
| `dev` | 获得开发环境权限后用于联调 |

环境解析优先级从高到低为：

1. 命令行 `--env` 或 `--test`
2. 环境变量 `FREELOG_ENV`
3. 项目 `.freelog/config.json` 中的 `defaultEnv`
4. production 回退值；当前会明确失败，不会发起平台请求

`production` / `prod` 当前硬禁用。它们即使来自命令行、`FREELOG_ENV` 或项目 `defaultEnv`，也会在
请求 API、生成 Console 链接和平台写入前以退出码 4 停止；不会静默改到 `dev` 或 `test`。可用环境的
Console 地址与账号由环境管理员提供。

平台写操作建议显式传入环境：

```bash
freelog-cli status --env <env>
freelog-cli publish --yes --env <env>
```

在非交互脚本中，写命令必须显式指定环境、设置 `FREELOG_ENV`，或配置项目 `defaultEnv`，否则命令会停止。`defaultEnv` 只能写入 `dev` 或 `test`。

## 登录和登出

工作区登录：

```bash
freelog-cli login --env <env>
freelog-cli status --env <env>
```

默认登录在当前目录写入 `.freelog-auth`。从当前目录向上查找时，距离最近的工作区凭据生效，因此一个 monorepo 可以在根目录登录一次，也可以在子项目中用另一个账号覆盖。

全局登录：

```bash
freelog-cli login --global --env <env>
```

全局凭据写入用户主目录的 `~/.freelog-auth`，仅在目录树中没有工作区凭据时使用。

登出：

```bash
freelog-cli logout --env <env>
freelog-cli logout --global --env <env>
```

默认 `logout` 删除当前目录实际命中的工作区凭据；`logout --global` 只删除全局凭据。登出不会删除 manifest、state 或平台资源。

## 多账号和 owner

`status` 会显示当前账号、凭据来源、资源 owner 以及两者是否一致。平台写命令要求当前账号是资源 owner。

```text
workspace/.freelog-auth               根目录账号
workspace/apps/theme-a/               继承根目录账号
workspace/apps/theme-b/.freelog-auth  子项目账号
workspace/apps/theme-b/               使用子项目账号
```

命中最近的 `.freelog-auth` 后，如果文件损坏或无法解密，CLI 会明确失败，不会静默回退到其他账号。切换账号后应重新执行 `status`。

## 凭据本地加密与安全

`login` 会使用 AES-256-GCM 加密 token、authorization 和 cookie。默认主密钥保存在 `~/.freelog-cli/auth.key`；也可以通过 `FREELOG_CRYPTO_KEY` 为 CI 提供密钥。

- `.freelog-auth` 和 `~/.freelog-cli/auth.key` 都不得提交到代码仓库。
- 不要把密码、token、cookie 或 authorization 写入 manifest、脚本和文档。
- `auth.key` 丢失后，旧凭据无法解密，需要重新登录。
- `--debug` 和 `--json` 会对敏感字段脱敏，但仍应谨慎保存日志。
- 非交互登录的密码参数可能出现在命令历史或进程信息中。应使用 CI 的受保护变量、短生命周期执行器和日志脱敏，不要在命令文件中硬编码密码。

非交互登录示例：

```bash
freelog-cli login --env <env> --login-name "$FREELOG_LOGIN_NAME" --password "$FREELOG_PASSWORD" --yes
```

## 常用全局参数

| 参数 | 作用 |
|---|---|
| `--env dev\|test` | 指定获授权的平台环境；`production` / `prod` 当前会失败 |
| `--test` | `--env test` 的简写 |
| `--cwd <dir>` | 指定项目目录，凭据也从该目录向上解析 |
| `--yes` / `-y` | 非交互确认写操作 |
| `--json` | 输出机器可读 JSON envelope |
| `--debug` | 输出已脱敏的调试信息 |
| `--lang zh_CN\|en_US` | 指定本次命令语言 |
| `--no-auto-pull` | 检测到 listing 漂移时直接失败，不自动刷新 state |
| `--session` | 单命令临时模式，不写 manifest/state |
| `--resource-id <id>` | 临时维护已有资源时指定平台资源 ID |
| `--export-project <dir>` | 将临时操作结果导出为长期工程 |

子命令是否支持某个参数，以 `freelog-cli <命令> --help` 为准。

## 自动同步和冲突

多数写命令会在执行前检查本地 listing 与平台数据。未使用 `--no-auto-pull` 时，CLI 可以先刷新 state 再继续；本地和平台都有改动时仍会停止并要求明确选择。

常用命令：

```bash
freelog-cli status --env <env>
freelog-cli diff --env <env>
freelog-cli pull --env <env>
freelog-cli pull --apply-listing --env <env>
```

`pull` 默认只刷新平台事实缓存。只有 `--apply-listing` 才会把平台标题、简介、封面和标签写回 manifest。

## JSON 和退出码

使用 `--json` 时，成功输出包含 `ok: true`、`command`、`data` 和 `meta`；失败输出包含 `code`、`message`、`hint` 和 `details`。

| 退出码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | API 或其他一般错误 |
| `2` | 未登录、owner 不匹配等身份错误 |
| `3` | 本地与平台同步或绑定冲突 |
| `4` | 参数、预检或业务规则不满足 |
| `5` | 依赖授权未完成 |

批量命令可使用 `--json-lines` 输出 NDJSON 进度事件，适合 CI 持续读取。

## 语言和 Shell 补全

```bash
freelog-cli lang show
freelog-cli lang set zh_CN
freelog-cli --lang en_US status --env <env>
```

语言优先级为 `--lang`、`FREELOG_LANG`、持久化设置，最后默认 `zh_CN`。

Bash 和 Zsh 可以启用补全：

```bash
eval "$(freelog-cli completion bash)"
eval "$(freelog-cli completion zsh)"
```

## 工作方式

| 场景 | 入口 | 凭据 | manifest/state |
|---|---|---|---|
| 长期工程 | `login` 后执行工程命令 | 本地加密保存 | 保存 |
| 单次临时维护 | 命令加 `--session` | 读取已登录凭据 | 不写 |
| 多账号文件工作区 | `freelog-cli studio` | 仅进程内 | 为每个资源保存子工程 |
| 全临时多步维护 | `freelog-cli session` | 仅进程内 | 不写，可选择导出 |

临时模式的详细限制见[特殊流程](./特殊流程.md)和[交互会话与多账号工作区](./交互会话与多账号工作区.md)。
