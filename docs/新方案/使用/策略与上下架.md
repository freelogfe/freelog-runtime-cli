# 策略与上下架

[返回使用文档目录](./README.md)

## 添加策略

生成并编辑策略模板：

```bash
freelog-cli policy init
```

应用到独立资源：

```bash
freelog-cli policy apply --from-file ./policy.free.json --yes --env production
freelog-cli policy list --env production
```

应用到合集：

```bash
freelog-cli policy init --collection
freelog-cli collection policy apply --from-file ./policy.free.json --yes --env production
freelog-cli collection policy list --env production
```

`policy apply` 添加新策略。当前 CLI 不修改已有策略的名称和正文；需要变更时可添加新策略，再切换启用状态。

## 启用和停用策略

独立资源：

```bash
freelog-cli policy set <policyId> --status 1 --yes --env production
freelog-cli policy set <policyId> --status 0 --yes --env production
```

合集：

```bash
freelog-cli collection policy set <policyId> --status 1 --yes --env production
freelog-cli collection policy set <policyId> --status 0 --yes --env production
```

已上架资源不能停用最后一条启用策略。先启用另一条策略，或先下架资源。

## 上架

```bash
freelog-cli validate --for online --env production
freelog-cli online --yes --env production
```

上架必须同时满足：

1. 已有正式版本。
2. 至少有一条启用策略。
3. 资源未被冻结。
4. 当前账号是资源 owner。

`online --json` 失败时可查看 `details.gates`，确认缺少版本还是缺少启用策略。

## 下架

```bash
freelog-cli offline --yes --env production
```

下架只改变上架状态，不删除资源、版本或策略。再次满足上架条件后可重新执行 `online`。

资源被冻结时，发行和上架都会停止，需要在 [Freelog Console](https://console.freelog.cn) 完成解冻。CLI 不绕过平台冻结状态。

## 临时维护已有资源

已登录但不希望写 manifest/state 时：

```bash
freelog-cli policy apply --from-file ./policy.free.json --session --resource-id <resourceId> --yes --env production
freelog-cli policy set <policyId> --status 1 --session --resource-id <resourceId> --yes --env production
freelog-cli online --session --resource-id <resourceId> --yes --env production
freelog-cli offline --session --resource-id <resourceId> --yes --env production
```

临时命令结束后不会保留本地工程状态。长期维护建议使用工程模式。
