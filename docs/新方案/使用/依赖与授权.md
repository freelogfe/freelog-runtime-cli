# 依赖与授权

## 依赖授权

manifest 中与 Console 对齐的授权字段：

| 字段 | 适用 subject | 说明 |
|---|---|---|
| `version.dependencies` / `collection.dependencies` | 资源 / 合集 | 直接依赖；`dep add` 维护 |
| `version.baseUpcastResources` / `collection.baseUpcastResources` | 资源 / 合集 | 基础上抛；须在 manifest 显式声明 |
| `authExcludedItems` | 资源 / 合集 / 目录项 | 授权排除；`--auth-excluded-file` 或 manifest |

声明依赖：

```bash
freelog-cli dep add <dependencyResourceId> --version-range "*" --env dev
freelog-cli dep update <dependencyResourceId> --version-range "^1.0.0" --env dev
freelog-cli dep remove <dependencyResourceId> --env dev
freelog-cli dep list --env dev
freelog-cli dep list --tree --env dev    # 平台 dependencyTree（须已有 resourceId + 版本）
```

`dep add/update/remove/list` 只改**本地 manifest 意图**；同步到平台发版表单草稿须 `draft push`（或直接 `publish` 随版本固化）。`baseUpcastResources` 须在 manifest 手改，无 `dep add` 子命令。

声明式免费策略签约 `auth-map.yaml`：

```yaml
contracts:
  - resourceId: <dependencyResourceId>
    policyIds:
      - <policyId>
  - resourceId: <baseUpcastResourceId>   # 上抛资源同样须列入
    policyIds:
      - <policyId>
```

执行：

```bash
freelog-cli dep auth --policy-map ./auth-map.yaml --yes --env dev
```

`dep auth` 会根据 manifest `subject` 自动选择独立资源或合集：独立资源读取 `version.dependencies` **与** `version.baseUpcastResources`，合集读取 `collection.dependencies` **与** `collection.baseUpcastResources`，并在签约前执行对应的 owner/sync 门禁。policy-map 中的 `resourceId` 须与上述声明字段并集一致。

**自有资源作依赖/上抛也要签约**：即使目标资源与当前工程同属一个登录账号，`dep auth` 仍须走与 Console dependency 页一致的签约流程（`batchCreateContracts` + 可选 `batchSetContracts`）；不能因 owner 相同而跳过。

**各命令授权门禁一览（2026-08-12）：**

| 命令 | Console 对照 | 检查内容 |
|---|---|---|
| `publish` | resourceCreator Step2 / versionCreator | `dependencies` + `baseUpcastResources` → authTree |
| `collection publish` | collectionCreator Step2 | 合集 `dependencies` + `baseUpcastResources` + 目录项 auth |
| `collection item add/import-dir` | FAddResourcesHandleAuth | 子资源 `baseUpcastResources` 在合集下已有生效合同 |
| `dep auth` | sidebar dependency / Authorization 微应用 | 对上述声明字段免费直签；付费返回 Console URL |
| `resource import-dir` | creatorBatch submit | 每项 `batchSignContracts` 覆盖 deps+upcast |

失败时 CLI 返回 `actionUrl`（依赖页）、`contractsUrl`（合约页）与 `nextCommand`（通常为 `freelog-cli dep auth …`）。

**Console 接力 URL（`--env` 决定基址）：**

| subject | 依赖页 `actionUrl` | 合约页 `contractsUrl` |
|---|---|---|
| 独立资源 | `{consoleBase}/resource/sidebar/dependency/{resourceId}` | `{consoleBase}/resource/sidebar/contract/{resourceId}` |
| 合集 | `{consoleBase}/resource/collectionSidebar/dependency/{resourceId}` | `{consoleBase}/resource/collectionSidebar/contract/{resourceId}` |

`consoleBase`：`dev` → `console.devfreelog.com`；`test` → `console.testfreelog.com`；`production` → `console.freelog.cn`。

付费策略、不可验证策略、需要复杂人机确认的授权不在 CLI 内完成。CLI 会按当前 `--env` 和 subject 返回资源 sidebar 或 collectionSidebar 的依赖页、合约页链接，以及操作完成后应重新执行的 `nextCommand`；免费策略仍由 CLI 直接签约。自动化模式只输出 URL，不会自行打开浏览器。
