# 依赖与授权

[返回使用文档目录](./README.md)

资源版本可以声明直接依赖、基础上抛资源和授权排除项。发行前，CLI 会检查所有需要授权的资源；授权不完整时停止发行并返回退出码 `5`。

## 声明直接依赖

在工程目录中执行：

```bash
freelog-cli dep add <dependencyResourceId> --env production
freelog-cli dep add <dependencyResourceId> --version-range "^1.0.0" --env production
freelog-cli dep update <dependencyResourceId> --version-range "^2.0.0" --env production
freelog-cli dep remove <dependencyResourceId> --env production
freelog-cli dep list --env production
```

这些命令只修改 manifest 中的下一版依赖意图，不会立即改变已发行版本。完成依赖调整后需要发行新版本。

未指定版本范围时，CLI 会尝试读取依赖资源的最新版本并写入 `^<latestVersion>`；无法确定最新版本时回退到 `*`。需要可重复构建时应显式指定合法 semver 范围。

已有资源和版本时可查看平台依赖树：

```bash
freelog-cli dep list --tree --env production
```

基础上抛资源和授权排除项没有对应的 `dep add` 简写，需要在 `freelog.manifest.json` 的版本或合集块中显式维护。

## 准备授权映射

生成模板：

```bash
freelog-cli dep init-auth-map
```

`auth-map.yaml` 示例：

```yaml
contracts:
  - resourceId: <dependencyResourceId>
    policyIds:
      - <policyId>
  - resourceId: <baseUpcastResourceId>
    policyIds:
      - <policyId>
```

执行免费策略签约：

```bash
freelog-cli dep auth --policy-map ./auth-map.yaml --yes --env production
```

映射中的资源必须覆盖 manifest 声明的直接依赖和基础上抛资源。即使依赖资源与当前资源属于同一账号，也需要按平台规则完成授权。

## 发行门禁

以下操作会检查授权：

| 操作 | 检查内容 |
|---|---|
| `publish` | 下一版直接依赖和基础上抛资源 |
| `collection publish` | 合集依赖、上抛资源和目录项授权 |
| `collection item add|import-dir` | 子资源及其基础上抛资源 |
| `resource import-dir` | 每个批量条目的依赖和授权映射 |

授权失败时，终端会提示未解决资源；`--json` 输出的 `details` 还会包含 Console 操作链接和建议的下一条命令。

## 需要 Console 的授权

CLI 可以按声明文件完成免费策略签约。以下情况需要进入浏览器：

- 付费策略和支付
- 无法由 CLI 自动确认的复杂策略
- 需要人工查看合约详情或处理异常合同

CLI 会根据 `--env` 和资源类型生成正确的资源或合集页面链接。浏览器操作完成后，回到原工程重新执行 `dep auth`、`publish` 或 `collection publish`。

## 临时授权

单命令会话可以修改下一版依赖，但命令结束后内存意图会消失，因此必须同时导出工程：

```bash
freelog-cli dep add <dependencyResourceId> --session --resource-id <resourceId> --target-version 2.0.0 --export-project ./resource-project --env production
cd resource-project
freelog-cli publish --reuse-version 1.0.0 --version 2.0.0 --yes --env production
```

`dep add|remove|update --session` 都要求 `--resource-id`、目标版本意图和 `--export-project`。需要在内存中连续编辑多条依赖并立即发行时，使用 `freelog-cli session` 的交互菜单。

对已有资源的已发行依赖执行单次授权：

```bash
freelog-cli dep auth --policy-map ./auth-map.yaml --session --resource-id <resourceId> --version <version> --yes --env production
```
