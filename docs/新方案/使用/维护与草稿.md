# 维护与草稿

> 文档角色：当前版本的派生使用说明；不定义产品范围、字段或完成状态。发生冲突时以仓库根目录 [DESIGN.md](../../../DESIGN.md) 和当前 `--help` 为准。

## 更新基础信息

独立资源：

```bash
freelog-cli update --title "新标题" --intro "介绍" --tags "tag1,tag2" --cover ./cover.png --env dev
```

合集：

```bash
freelog-cli collection update --title "新合集标题" --display-sort asc --display-view card --env dev
```

说明：

1. `update` 只改 listing，不改版本、策略、上下架状态。
2. `pull` 默认只刷新 state，不改 manifest。
3. 采用 Console listing 时执行：

```bash
freelog-cli pull --apply-listing --env dev
```

本地和平台相对上次同步都改过 listing 时会冲突；确认采用平台值再加 `--force`。

## 发布新版本和草稿

独立资源新版本（换文件）：

```bash
pnpm build
freelog-cli pull --env dev
freelog-cli version set --version 1.1.0 --description "新功能" --file dist --env dev
freelog-cli version set --clear-file --yes --env dev   # 清除文件意图（交互模式会确认）
freelog-cli publish --yes --env dev
```

**同文件升版（Console「上个版本」，P6-2）：** 仅改 deps/说明、不换 artifact 时：

```bash
freelog-cli publish --reuse-version 1.0.0 --bump --yes --env dev
# 或显式版本号：
freelog-cli publish --reuse-version 1.0.0 --version 1.0.1 --yes --env dev
```

`--reuse-version` 与 `--file` **互斥**；会从平台读取该已发版的 fileSha1/filename，默认继承 deps/attrs（`insertMode`/`supportOptionalConfig` 过滤，见对齐文档 V-06）。不要继承 deps 时加 `--no-inherit-deps`。若平台已有发版表单草稿，`draft pull` 优先于 reuse 意图（§23.11）。

**`publish` 常用 flag：**

| flag | 作用 |
|---|---|
| `--dry-run` | 解析属性并输出 `createVersionParams`，不上传/不写平台；新文件属性可能标 `unresolved` |
| `--bump` | 基于平台 `latestVersion` 自动升 patch 再发行 |
| `--reuse-version <semver>` | 从该已发版继承 fileSha1/filename；与 `--file` 互斥 |
| `--no-inherit-deps` | reuse 路径不继承上一版 dependencies |
| `--version <semver>` | reuse 路径目标版本（与 `--bump` 二选一） |
| `--description <text>` | reuse 路径覆盖版本说明 |
| `--no-auto-pull` | listing 漂移时不自动 pull，直接失败 |

**`release --dry-run`：** 流水线停在 publish dry-run，不实际上线（合集 cwd 时 dry-run `collection publish`）。

**发行前授权（与 Console Step2 / versionCreator 对齐）：** 若 manifest `version.dependencies` 或 `version.baseUpcastResources` 非空，`publish` 会先调用平台 authTree（空树时回退 licensee contracts），全部未解决则失败，文案为 **「依赖中存在未获取授权的资源」**（exit code 5），并返回 Console 依赖页 URL 与 `dep auth` 重试命令。`baseUpcastResources` 须在 manifest 中单独声明，不能混在 `dependencies` 里。

修改已发布版本说明：

```bash
freelog-cli version edit --version 1.1.0 --description "修正文案" --env dev
freelog-cli version edit --version 1.1.0 --sync-properties --env dev   # 从平台拉属性再 merge
freelog-cli version edit --version 1.1.0 --video-cover ./poster.png --env dev
freelog-cli version show --env dev                                     # 查看当前版本意图与平台事实
freelog-cli version bump patch --env dev                               # 仅改 manifest 版本号，不 publish
```

独立资源发版表单草稿：

```bash
freelog-cli draft push --env dev
freelog-cli draft pull --env dev
freelog-cli draft discard --yes --env dev
```

合集发版表单草稿：

```bash
freelog-cli draft push --collection --env dev
freelog-cli draft pull --collection --env dev
freelog-cli draft discard --collection --yes --env dev
```

合集发布说明：

```bash
freelog-cli collection version set --description "新增目录项" --env dev
freelog-cli collection publish --yes --env dev
```

**合集发行前授权：** 除目录项 `getCollectionItemsAuth_Draft` 外，`collection publish` 还会检查 manifest `collection.dependencies` 与 `collection.baseUpcastResources`（与 Console 合集 Step2 发行按钮门禁一致）；未完整授权时报 **「依赖中存在未获取授权的资源」**。

**`collection publish --dry-run`：** 输出 `updateCollectionParams`，不写平台。

草稿规则：

1. CLI 不自动保存远端草稿；只有 `draft push` 才写平台发版表单草稿。
2. `draft pull` 会把远端发版表单草稿合并回 manifest；独立资源场景会保留本地 `filePath`。
3. `draft discard` 只删除平台发版表单草稿，不删除正式版本、策略、资源基础信息。
4. `draft push/pull/discard --collection` 管合集发版表单草稿，不管合集目录。
5. `collection item *` 管合集目录草稿，`collection publish` 才把目录草稿合并成正式合集版本。
6. 本地和远端草稿都有改动时，`draft push` 会失败；先 `draft pull` 合并，或确认后 `draft push --force --yes`。
7. 合集固定版本号，CLI 不允许设置合集版本号，只允许设置发布说明。

典型协作场景：

1. 一个人只用 CLI：`version set -> draft push` 可保存远端草稿，确认后 `publish`。
2. Console 已打开并产生草稿：先 `draft pull`，再本地调整，最后 `draft push` 或 `publish`。
3. 合集只改目录：用 `collection item add/update/reorder/remove`，不需要 `draft push --collection`。
4. 合集只改发布说明或依赖：用 `collection version set` 后 `draft push --collection` 或直接 `collection publish`。
5. **无 manifest 工程**：用 [会话模式](./特殊流程.md#会话模式无-manifest-工程)（`resource publish --session` 等），不走 `draft *`。
