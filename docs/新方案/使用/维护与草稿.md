# 维护资源与草稿

[返回使用文档目录](./README.md)

维护前先进入对应工程，确认当前账号、环境和平台状态：

```bash
freelog-cli status --env production
freelog-cli diff --env production
```

## 更新基础信息

独立资源：

```bash
freelog-cli update --title "新标题" --intro "新简介" --tags "标签一,标签二" --cover ./cover.png --yes --env production
```

合集：

```bash
freelog-cli collection update --title "新合集标题" --intro "新简介" --display-sort asc --display-view card --yes --env production
```

基础信息更新不会创建版本，也不会改变策略或上下架状态。标题不能为空且最多 100 字；简介最多 200 字；标签最多 20 个，每个最多 20 字。

如果 Console 已修改基础信息：

```bash
freelog-cli pull --apply-listing --env production
```

本地和平台相对上次同步都发生变化时，CLI 会停止。确认采用平台值后再使用 `--force`，避免覆盖本地意图。

## 发行换文件的新版本

主题或插件先构建，再设置下一版文件：

```bash
pnpm build
freelog-cli pull --env production
freelog-cli version set --version 1.1.0 --description "新功能" --file dist --artifact-mode directory-zip --env production
freelog-cli validate --for publish --env production
freelog-cli publish --yes --env production
```

图片或视频将 `--file` 指向新的单文件。`version set` 只修改本地下一版意图，不会上传或调用平台草稿 API。

需要撤销本地文件意图时单独执行：

```bash
freelog-cli version set --clear-file --yes --env production
```

## 复用旧文件发行新版本

只修改版本说明、依赖或属性，不更换文件时，可以复用已发行版本的文件身份：

```bash
freelog-cli publish --reuse-version 1.0.0 --bump --description "更新依赖" --yes --env production
```

或指定新版本号：

```bash
freelog-cli publish --reuse-version 1.0.0 --version 1.0.1 --yes --env production
```

- `--reuse-version` 与本地 `--file` 互斥。
- 默认继承旧版依赖和可继承属性；使用 `--no-inherit-deps` 可不继承依赖。
- 复用的是文件 SHA1 和文件名，仍会创建一个新的正式版本。

## 修改已发行版本说明

不换文件、不升版本时：

```bash
freelog-cli version edit --version 1.1.0 --description "修正文案" --yes --env production
freelog-cli version show --env production
```

需要把 manifest 中的属性同步到已发行版本：

```bash
freelog-cli version edit --version 1.1.0 --sync-properties --yes --env production
```

已发行版本的版本号和文件身份不能修改。视频封面只可通过 `version set --video-cover` 声明到下一版，不能用 `version edit` 修改已发行版本。

## 版本号辅助

```bash
freelog-cli version bump patch --env production
freelog-cli publish --bump --yes --env production
```

`version bump` 只修改 manifest，不发行；`publish --bump` 根据平台最新版本自动增加 patch 后发行。

## 独立资源草稿

```bash
freelog-cli draft push --env production
freelog-cli draft pull --env production
freelog-cli draft discard --yes --env production
```

- `draft push` 把本地下一版表单意图保存到平台。
- 本地文件尚未上传且希望草稿包含文件信息时，可使用 `draft push --upload`。
- `draft pull` 把平台草稿合并回 manifest，并保留本地文件路径。
- `draft discard` 只删除平台发版表单草稿，不删除正式版本或资源。

远端草稿和本地草稿都变化时，`draft push` 会停止。先 `draft pull` 合并；确认覆盖远端后才使用：

```bash
freelog-cli draft push --force --yes --env production
```

## 合集草稿和发行

```bash
freelog-cli collection version set --description "新增目录项" --env production
freelog-cli draft push --collection --env production
freelog-cli draft pull --collection --env production
freelog-cli draft discard --collection --yes --env production
freelog-cli collection publish --yes --env production
```

合集发版表单草稿保存说明、依赖等信息，不包含目录项变化。目录项由 `collection item add|update|remove|reorder` 管理，并在 `collection publish` 时合并。合集版本号由平台管理，CLI 不允许手动设置。

## 与 Console 协作

1. Console 打开过发版表单并保存草稿时，先 `draft pull`。
2. CLI 修改后需要让 Console 继续编辑时，执行 `draft push`。
3. 只修改合集目录时，不需要 `draft push --collection`。
4. 临时 `--session` 模式不支持 `draft push|pull|discard`；需要草稿时应使用工程模式。
