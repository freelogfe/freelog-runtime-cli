# 快速上手：dev 环境发一张图并上架

> 文档角色：当前版本的派生使用说明；不定义产品范围、字段或完成状态。发生冲突时以仓库根目录 [DESIGN.md](../../../DESIGN.md) 和当前 `--help` 为准。

最后更新：2026-08-13

[← CLI 使用文档目录](./README.md)

本教程假设你已安装 `freelog-cli`，有一张本地图片（如 `~/Pictures/demo.png`），并在 **dev** 环境有 Freelog 测试账号。全程约 15 分钟。

完成后你将得到：一个 dev 上的独立图片资源，已发行 **1.0.0** 并**上架**。

---

## 0. 准备

```bash
# 确认 CLI 可用
freelog-cli --help

# 准备一张图片（路径按你的机器修改）
# 下文用 ../demo.png 表示与项目目录同级的 demo.png
```

**约定：** 下文所有写命令都带 `--env dev`。测试/联调**不要**省略环境，否则可能误连 production。

---

## 1. 登录

在你要创建项目的**父目录**执行（会在当前目录写入 `.freelog-auth`）：

```bash
mkdir -p ~/freelog-demo
cd ~/freelog-demo
freelog-cli login --env dev
```

按提示输入 dev 账号密码。

**成功时你会看到：** 类似 `已登录 yourname（dev，工作区凭据）`。

验证：

```bash
freelog-cli status --env dev
```

**成功时你会看到：** `已登录: yourname`；若尚未绑定资源，owner 行可能为空，属正常。

---

## 2. 查图片类型 code

Freelog 每种资源有平台 `resourceTypeCode`（如 `RT005001`），须先查到再 `init`。

```bash
freelog-cli type search 图片 --env dev
```

**成功时你会看到：** 若干行，每行含 `typeCode`、类型名、subject 等。

记下你要用的 **typeCode**（下文用 `<imageCode>` 占位）。需要详情时：

```bash
freelog-cli type info <imageCode> --env dev
```

---

## 3. 创建本地工程

```bash
mkdir photo-resource
cd photo-resource

freelog-cli init . --scaffold none --resource-type <imageCode> --artifact-mode file --yes --env dev
```

**成功时你会看到：** `已创建 ...` 或目录内出现 `freelog.manifest.json`。

说明：`--scaffold none` 表示不生成前端模板，只建 manifest；`--artifact-mode file` 表示发行**单个文件**（不压缩成 zip）。

---

## 4. 创建平台资源壳

```bash
freelog-cli create --yes --env dev
```

**成功时你会看到：** `已创建资源 <resourceId>（username/shortname）`。

同时会写入 `.freelog/state.json`（含 `resourceId`、owner），**不要**提交 git。

再确认 owner 一致：

```bash
freelog-cli status --env dev
```

**成功时你会看到：** `所属用户: yourname ... ✅`（登录账号与 owner 一致）。

---

## 5. 指定首版文件并发行

把图片路径换成你的实际文件（相对当前 `photo-resource` 目录）：

```bash
freelog-cli version set --version 1.0.0 --file ../demo.png --env dev
freelog-cli publish --yes --env dev
```

**publish 成功时你会看到：** `已发行 1.0.0（demo.png）` 或类似成功信息；可能附带上传/属性解析阶段日志。

若失败：

| 现象 | 处理 |
|---|---|
| 未登录 / owner 不符 | 回到 §1、`status` 看 ✅/❌ |
| 文件格式/大小不符 | `type info <imageCode>` 看上传限制 |
| 授权 code 5 | 本教程无依赖，一般不会出现；见 [依赖与授权](./依赖与授权.md) |

---

## 6. 添加免费策略

上架前须至少一条**启用**策略。先创建策略文件：

```bash
cat > policy.free.json << 'EOF'
{
  "policyName": "免费",
  "policyText": "for public\r\n\r\ninitial[active]:\r\nterminate\r\n",
  "status": 1
}
EOF

freelog-cli policy apply --from-file ./policy.free.json --yes --env dev
```

**成功时你会看到：** 策略已应用/已添加的提示。

列出策略确认有启用项：

```bash
freelog-cli policy list --env dev
```

---

## 7. 上架

```bash
freelog-cli online --yes --env dev
```

**成功时你会看到：** `已上架` 或 `资源已是上架状态`。

用 status 复核：

```bash
freelog-cli status --env dev
```

**成功时你会看到：** 平台 `latest=1.0.0`，status 为上架态；可在 dev Console 打开资源页验证。

Console 基址（dev）：`https://console.devfreelog.com`

---

## 8. 你学到了什么

整条首版链路：

```text
login → type search → init → create → version set → publish → policy apply → online
```

本地产生：

| 文件 | 提交 git？ |
|---|---|
| `freelog.manifest.json` | 是 |
| `.freelog/state.json` | 否 |
| `.freelog-auth`（父目录或当前树） | 否 |
