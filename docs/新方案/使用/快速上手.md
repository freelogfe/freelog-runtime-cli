# 快速上手：发行一张图片并上架

[返回使用文档目录](./README.md)

本教程使用 Freelog 正式环境。完成后会真实创建、发行并上架一个图片资源。请使用自己的 Freelog 账号和一张可公开发行的本地图片。

## 1. 确认 CLI

```bash
freelog-cli --version
freelog-cli --help
```

版本应为 `0.5.x`。尚未安装时先阅读[安装与升级](./安装与升级.md)。

## 2. 创建工作目录并登录

在准备存放项目的目录中执行：

```bash
mkdir freelog-photo-demo
cd freelog-photo-demo
freelog-cli login --env <env>
```

按提示输入账号和密码。默认登录会把加密凭据写入当前工作区的 `.freelog-auth`，子目录可以继承该账号。

确认登录和环境：

```bash
freelog-cli status --env <env>
```

## 3. 查询图片类型

资源类型由平台动态提供，不要在脚本中猜测类型 code：

```bash
freelog-cli type search 图片 --env <env>
freelog-cli type info <imageTypeCode> --env <env>
```

从结果中选择符合文件格式和用途的叶子类型，并记下 `typeCode`。下文用 `<imageTypeCode>` 表示该值。

## 4. 初始化本地工程

在当前目录创建一个图片资源工程：

```bash
freelog-cli init . --scaffold none --resource-type <imageTypeCode> --artifact-mode file --yes --env <env>
```

命令会生成 `freelog.manifest.json`。检查其中的资源标题和短授权标识，确认无误后继续。

## 5. 创建平台资源

```bash
freelog-cli create --yes --env <env>
freelog-cli status --env <env>
```

`create` 会在平台创建资源，并把 `resourceId`、owner 和环境写入 `.freelog/state.json`。此操作不会创建正式版本。

## 6. 准备并发行首版

将 `<path-to-image>` 替换为本地图片路径：

```bash
freelog-cli version set --version 1.0.0 --file <path-to-image> --env <env>
freelog-cli validate --for publish --env <env>
freelog-cli publish --yes --env <env>
```

`publish` 会计算文件 SHA1、上传文件并创建正式版本。版本创建成功后不会因后续策略或上架失败而自动撤销。

## 7. 添加免费策略

生成免费策略模板并应用：

```bash
freelog-cli policy init
freelog-cli policy apply --from-file ./policy.free.json --yes --env <env>
freelog-cli policy list --env <env>
```

确认列表中至少有一条状态为启用的策略。策略文件可以加入项目版本库，但不要在策略文件中保存账号、token 或其他凭据。

## 8. 上架

```bash
freelog-cli validate --for online --env <env>
freelog-cli online --yes --env <env>
freelog-cli status --env <env>
```

上架成功后，可在当前环境对应的 Freelog Console 查看资源详情。CLI 不在终端内播放视频或渲染资源详情页。

## 本地产生的文件

| 文件 | 用途 | 是否建议提交 |
|---|---|---|
| `freelog.manifest.json` | 资源和下一版发行意图 | 是 |
| `.freelog/state.json` | 当前环境的平台事实缓存 | 否 |
| `.freelog-auth` | 当前工作区的加密登录凭据 | 否 |
| `policy.free.json` | 本教程生成的免费策略 | 按项目需要 |

完整链路如下：

```text
login -> type search -> init -> create -> version set -> validate
      -> publish -> policy apply -> online
```
