# 交互会话与多账号工作区

[返回使用文档目录](./README.md)

`session` 和 `studio` 都要求真实交互终端，登录凭据只保存在当前进程中。它们解决的问题不同。

| 场景 | 入口 | 退出后保留内容 |
|---|---|---|
| 全临时、多步维护一个或多个资源 | `freelog-cli session` | 默认不保留，可选择导出工程 |
| 多个账号从同一文件夹分别发行文件 | `freelog-cli studio` | 每个成功资源的子工程和恢复报告 |
| 长期维护和 CI | 普通工程命令 | manifest、state 和加密凭据 |

## 全临时交互会话

```bash
freelog-cli session --env production
```

会话启动后：

1. 强制重新登录，且不读取或写入磁盘凭据。
2. 通过 resourceId、搜索结果或首发流程选择资源。
3. 在一个进程中完成发版、基础信息、版本说明、依赖、策略和上下架操作。
4. 可切换账号或资源。
5. 退出时清除进程内凭据和临时 Store。

需要长期维护时，可在菜单中导出工程。导出目标必须是可安全写入的目录，成功后会生成 manifest/state，之后改用普通工程命令。

限制：

- 不支持平台发版表单草稿 `draft push|pull|discard`。
- 关闭终端或进程异常退出后，未导出的本地意图不会保留。
- 切换账号后应重新选择该账号拥有的资源，owner 不匹配时写操作会停止。

## 多账号文件工作区

```bash
freelog-cli studio --env production
```

Studio 适合一个操作者管理多个 Freelog 账号，并从同一媒体目录逐个发行文件：

1. 使用账号 A 在进程内登录。
2. 选择工作目录和文件，发行后生成该文件对应的子工程。
3. 切换到账号 B，再选择其他文件发行。
4. 进入已有子工程执行发新版、更新基础信息或上下架。
5. 退出后不留下 `.freelog-auth`，但保留子工程和报告。

同一个账号批量发行一个目录时，应使用 `resource import-dir`，不需要 Studio。

## owner 和子工程

每个 Studio 子工程的 state 记录创建资源时的 owner。后续维护必须使用同一 owner 账号；切换账号不会转移资源所有权。

如果离开 Studio 后改用普通工程模式：

```bash
cd <child-project>
freelog-cli login --env production
freelog-cli status --env production
freelog-cli publish --yes --env production
```

先确认登录账号与 owner 一致，再执行写操作。

## 中断和对账

Studio 首发会写 `.freelog/reports/<runId>.json`，最近一次报告入口为 `.freelog/reports/studio-latest.json`。

- 平台已经成功但本地尚未完成时，再选择同一文件可继续完成本地落盘。
- 报告显示远端结果未知时，不要重复发行。按报告中的账号、资源名和版本到 Console 对账，再使用 Studio 的对账/恢复入口记录结果。
- 不要手工修改恢复报告。
- 同一工作区同时只允许一个 Studio 首发流程，锁冲突不会触发平台创建。

## 文件选择规则

Studio 遵循 `.freelogignore`，并始终排除：

- `.freelog-auth`
- `.freelog/`
- `.git/`
- `freelog.*.config`

资源类型的格式和大小限制仍会在上传前检查。

## 常见问题

| 现象 | 处理 |
|---|---|
| `session` 或 `studio` 拒绝启动 | 使用真实终端；脚本改用工程命令或单命令 `--session` |
| session 切换账号后 owner 不匹配 | 重新搜索并选择当前账号拥有的资源 |
| Studio 子工程维护失败 | 切换到该子工程 owner 账号 |
| 退出后显示未登录 | 临时凭据已经清除；重新进入或使用普通 `login` |
| Studio 看不到可维护子工程 | 先完成至少一个首发，或检查子目录是否有有效 state |
