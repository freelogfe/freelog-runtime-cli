# 交互会话与多账号工作区

> 文档角色：当前版本的派生使用说明。四模式产品定义见 [CLI双维持久化设计](../开发/CLI双维持久化设计.md) 与 [DESIGN.md](../../../DESIGN.md)。

最后更新：2026-08-14

[← CLI 使用文档目录](./README.md)

## 1. 什么时候用哪个

| 你想… | 命令 | 编码 |
|---|---|:---:|
| 长期维护 Git 工程 | `login` + `publish` 等 | 00 |
| 已 login，临时改平台、不写本地 | `xxx --session` | 01 |
| **同一人多个账号**，同文件夹逐条发视频并留子工程 | `freelog-cli studio` | 10 |
| 全临时维护，不留任何本地文件 | `freelog-cli session` | 11 |

**session 一词**在 CLI 里 **只表示不写 manifest/state**。`freelog-cli session` 子命令 = 交互式全临时（11）；`--session` flag = 命令式不写 state（01）。

## 2. `freelog-cli session`（11 · 交互会话）

**适合：** 跳板机、他人电脑、一次性改 listing / 发版 / 上下架。

```bash
freelog-cli session --env dev
```

**流程：**

1. 登录（**不写** `.freelog-auth`）
2. 选 resourceId / 搜索 / 新建首发
3. 菜单：发新版、改 listing、依赖、策略、上下架…
4. 退出 → 凭据与内存 Store 清空
5. 可选「导出工程」→ 指定目录生成 manifest/state（转入工程模式 00）

**限制：** 须 TTY；不支持 `draft push/pull`（须工程目录或导出后操作）。

### 2.1 主菜单

| # | 功能 | 说明 |
|:---:|---|---|
| 1 | 发新版 | 新文件 / reuse-version / bump；无 resourceId 时走新建首发 |
| 2 | 改 listing | 多选字段向导 |
| 3 | 改版本说明 | 已发版 description |
| 4 | 依赖 / 签约 | 子菜单：list / tree / add / remove / update / auth |
| 5 | 策略 | 子菜单：list / apply / set |
| 6 | 上架 / 下架 | 上架含门禁 preflight |
| 7 | 查看当前资源 | 平台摘要 |
| 8 | 导出工程 | 写到空目录 → 00 工程壳（须已有 resource 身份） |
| 9 | 切换 / 选择资源 | 输入 id / 搜索 / 新建首发 / 稍后 |
| 10 | 切换账号 | 重新 no-save 登录；**若已选资源，建议随后菜单 9 重选** |
| 0 | 退出 | 清凭据与内存 Store |

写操作前会提示当前登录账号；须 `--env dev` 等显式环境（与工程写命令一致）。

## 3. `freelog-cli studio`（10 · 多账号工作区）

**适合：** 你注册了多个 Freelog 账号（如个人号 + 品牌号），同一文件夹里多个视频要用**不同账号**各发一条，且：

- 不想在机器上留 `.freelog-auth`
- 但每个视频要有独立子目录（含 `state.owner.userId`），便于以后 `cd` 进子目录维护

```bash
freelog-cli studio --env dev
```

**流程：**

1. 登录账号 A（内存，不落盘）
2. 选工作文件夹（如 `~/exports/`，可以没有 manifest）
3. 选文件发行 → 生成 `~/exports/视频名/` 子工程，`owner` = A
4. 菜单「切换账号」→ 登录账号 B
5. 再选文件发行 → 另一子工程，`owner` = B
6. 退出 → 无 `.freelog-auth`；子目录保留

**之后维护（studio 菜单「进入子工程维护」，或回到 00）：**

```bash
freelog-cli studio --env dev
# 菜单 2 → 选子工程 → 发新版 / 改 listing / 上下架 …
# 须用发行该资源时的账号（owner 门禁）
```

或导出/已知子目录后：

```bash
cd ~/exports/视频名/
freelog-cli login --env dev    # 须用发行该资源时的账号
freelog-cli publish --yes --env dev
```

**注意：**

- 同一人账号 A 不能改账号 B 的子工程（owner 门禁）——须先切换 login。
- **同账号**批量发同一文件夹 → 仍用 [批量发行](./批量发行.md) `import-dir`（00），不用 studio。

### 3.1 工作区根菜单

| # | 功能 |
|:---:|---|
| 1 | 从文件夹选文件发行（新建子工程） |
| 2 | 进入子工程维护 |
| 3 | 切换账号 |
| 4 | 文件夹概况 |
| 0 | 退出 |

### 3.2 子工程维护子菜单

| # | 功能 | 不含 |
|:---:|---|---|
| 1 | 发新版（含 publish preflight） | dep / policy / draft |
| 2 | 改 listing | |
| 3 | 改版本说明 | |
| 4 | 上架 / 下架 | |
| 0 | 返回工作区根 | |

维护列表仅显示含 `resourceId` 的有效 Freelog 子目录。

## 4. 与 `--session` flag（01）对比

| | `xxx --session` | `freelog-cli session` |
|---|---|---|
| 凭据 | 读 `.freelog-auth` | 内存 no-save |
| state | 内存 | 内存 |
| 形态 | 单条命令 + `--yes` | 菜单多步 + confirm |
| 写前账号 | `applyWriteCommandFlags` | 每步写操作 confirm 前提示 |

## 5. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `session`/`studio` 拒绝启动 | 非 TTY | 用 01 `--session` 或 00 工程模式 |
| session 切换账号后写失败 | 仍绑定旧 resourceId | 菜单 9 重选资源 |
| studio 进子目录写失败 | 当前 login ≠ `state.owner` | 菜单 3 切换账号 |
| 退出 studio/session 后「未登录」 | A=1 设计如此 | 重新 `studio`/`session` 或 `login` 落盘 |
| studio 维护列表为空 | 尚无有效子工程 | 先菜单 1 发行 |
