## 1. 验收分层

| 层级 | 命令 | 通过标准 | 频率 |
|---|---|---|:---:|
| **T0 单元** | `cd packages/cli && pnpm test` | 当前测试目录全部通过，失败为零 | 每次改代码 |
| **T1 Parity** | `pnpm verify:parity` | 当前 mandatory parity 域全部执行并通过，失败和未批准 skip 为零 | 发版前 |
| **T2 E2E 场景** | `pnpm verify:scenarios --env dev` | mandatory 全部执行并通过；未批准 skip 为零 | 发版前 |
| **T3 一键** | `node test/run-all-scenarios.mjs --env dev` | T1+T2 全绿 | 发版前 |
| **T4 手工并排** | Console dev + CLI 同资源 | 关键字段一致（见 §4） | 重大变更 |

> **不要**再引用固定「59 项」「83 项」——以脚本实时汇总为准。

## 2. 环境与账号

```bash
freelog-cli login --env dev
freelog-cli status
```

| 账号 | 用途 | 限制 |
|---|---|---|
| `FREELOG_TEST_LOGIN_NAME` / `FREELOG_TEST_PASSWORD` | 主链路：create/publish/policy/online/合集/批量 | 默认全场景；凭据不得入库 |
| `FREELOG_TEST_SECONDARY_LOGIN_NAME` / `FREELOG_TEST_SECONDARY_PASSWORD` | **仅 E3**：非 owner 的 bind/update 须失败 code 2 | **禁止**跑 policy apply、online 主链路；凭据不得入库 |

## 4. 手工 Console 并排（spot check）

发版后在 Console **同一 resourceId** 核对：

| 字段/行为 | Console 位置 | CLI 对照 |
|---|---|---|
| 版本 fileSha1 / filename | 版本详情 | `version show` / `pull` |
| inputAttrs / 自定义属性 | 版本属性 | `version show --json` |
| 策略列表 | 授权页 | `policy list` |
| status 上下架 | Sidebar | `status` |
| 合集目录项数/顺序 | 合集版本 | `collection item list` / draft pull |
| 视频版本封面 | 版本编辑 | `version edit --video-cover`（CLI 创建期也可用 publish） |

**已知 Console 落后：** 创建/发新版 wizard **可能不传 videoCover**——并排时若 Console 无封面而 CLI 有，记为 **Console bug**，非 CLI 缺口。

## 5. 负向用例速查

| 用例 | 预期 |
|---|---|
| 非叶子类型 create | CLI 拒绝 |
| 批量 >20 无 `--strict-batch-limit` | warn；加 strict 则 fail |
| 无策略 publish | 确认流 |
| 非 owner bind/update（E3） | exit code 2 |
| 已绑定再 bind 无 `--force` | 拒绝 |
| semver 非法 dep version-range | 拒绝 |
| 合集壳上 `resource publish` | 拒绝 |

---

## 6. 失败处理

| 现象 | 处理 |
|---|---|
| dev API 超时 | 重跑 `verify:scenarios`；查网络 |
| 动态类型未找到（S16 skip） | dev 环境无小说叶子类型时 **pass(skip)**，非失败 |
| parity 单脚本 fail | 看脚本名跑单项，如 `pnpm verify:console` |
| i18n 回归 | `pnpm i18n:audit` 须 0 命中 |
