# 普通用户简明手册 — 何时用 CLI

> 文档角色：当前版本的派生使用说明；不定义产品范围、字段或完成状态。发生冲突时以仓库根目录 [DESIGN.md](../../../DESIGN.md) 和当前 `--help` 为准。

最后更新：2026-08-10

**命令参数详表：** [CLI使用说明与Console差异](./CLI使用说明与Console差异.md)

---

## 1. 一句话

**你有本地文件（图片、zip、视频、txt…）要发到 Freelog → 用 CLI 最快。**  
**你要在网页里点选、写 Markdown、付费用策略 → CLI 会给出对应环境的 Console 链接，网页完成后回到 CLI 重试。**

---

## 2. 五选一：我要发什么？

```text
① 单个资源（一张图、一个 zip、一个视频…）
   → freelog-cli init <目录>  （按提示选类型）
   → create → version set --file … → publish → policy apply → online

② 很多个独立资源（一批图/一批视频）
   → freelog-cli resource import-dir <文件夹>

③ 合集（多章小说、多集视频放在一个壳里）
   → init 选「合集」→ collection create → collection item import-dir …
   → collection publish → online

④ 文件夹直接变合集
   → freelog-cli collection init-from-folder <文件夹>

⑤ 资源已在平台上，只想本地管理
   → 在资源目录 freelog-cli bind <resourceId>
```

登录一次：`freelog-cli login --env dev`（或 prod）

---

## 3. CLI 和 Console 一样吗？

**发到平台上的结果一样**（同一 API）。  
**操作方式不同：**

| | Console | CLI |
|---|---|---|
| 填表 | 网页向导 | 命令 + 本地 `freelog.manifest.json` |
| 草稿 | 自动保存 | 须自己 `draft push` |
| 策略 | 可视化 Builder | 文本文件 `policy apply --from-file` |
| 封面 | 网页上传+裁剪 | 本地图片路径 `--cover` |
| 上架 | Step4 可「先上架再补」 | 须条件齐全再 `online`（更严格） |

---

## 4. 请用 Console 的情况

- 从**云存储**里选已有文件（CLI 只认本机路径）
- 用 **Markdown / Cartoon 编辑器**写内容
- **付费**策略需要付款；CLI 会给出依赖页、合约页和完成后的重试命令
- 看列表、收藏、收入（CLI 不管这些）

---

## 5. 常用命令（复制即用）

```bash
# 看当前目录绑定的资源
freelog-cli status

# 从平台拉回最新状态
freelog-cli pull

# 改标题、封面、标签
freelog-cli update --title "新标题" --cover ./cover.jpg --tags "tag1,tag2"

# 发新版（先改 manifest 或 version set）
freelog-cli publish --yes

# 下架
freelog-cli offline --yes

# 视频封面（首发或维护）
freelog-cli version set --video-cover ./poster.jpg
freelog-cli version edit --version 1.0.0 --video-cover ./poster.jpg
```

---

## 6. 容易踩的坑

| 情况 | 怎么办 |
|---|---|
| publish 提示无策略 | 先 `policy init` 再 `policy apply --from-file policy.free.json` 再 `online` |
| 批量超过 20 个文件 | 加 `--strict-batch-limit` 或分批 |
| 合集里想单独 publish 某一章 | 不行；用 `collection item *` + `collection publish` |
| 换电脑继续 | 拷贝整个项目目录（含 manifest）；或 `bind` 已有资源 |
| 错误提示是英文 | `freelog-cli lang set zh_CN` 或 `--lang zh_CN` |

## 7. 帮助

```bash
# 发版前预检
freelog-cli validate --env dev
freelog-cli diff --env dev

# 一条命令发版（主题/插件常见）
freelog-cli release --bump patch --build-cmd "npm run build" --yes --env dev

# 只改 manifest 版本号
freelog-cli version bump patch --env dev

# 批量导入（CI 逐行进度）
freelog-cli resource import-dir ./photos --resource-type RT005001 --json-lines --yes --env dev

# 中断后继续；部分失败时只重试失败项
freelog-cli resource import-dir --resume .freelog/reports/<runId>.json --yes --env dev
freelog-cli resource import-dir --retry .freelog/reports/<runId>.json --yes --env dev

# Shell 补全（bash）
eval "$(freelog-cli completion bash)"

# 项目配置与模板
freelog-cli config init --default-env dev
freelog-cli policy init
freelog-cli dep init-auth-map

# monorepo：列出子项目
freelog-cli workspace list

# 发版时用 git commit 作说明
freelog-cli release --changelog-from-git --yes --env dev
```

**封面预处理：** CLI 无裁剪 UI，建议本地用 ImageMagick 等裁好再 `--cover` / `--video-cover`（例：`magick input.jpg -resize 800x800^ -gravity center -extent 800x800 cover.jpg`）。

准备手动验收时使用统一入口：[CLI 手动测试](../验证/手动测试.md)。
