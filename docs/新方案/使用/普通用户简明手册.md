# 普通用户简明手册 — 何时用 CLI

> 文档角色：当前版本的派生使用说明；不定义产品范围、字段或完成状态。发生冲突时以仓库根目录 [DESIGN.md](../../../DESIGN.md) 和当前 `--help` 为准。

**第一次使用？** 先跟 [快速上手](./快速上手.md)（约 15 分钟，dev 发一张图并上架）。

**完整分册说明：** [使用文档目录](./README.md)（适合集成到开发者文档站点）。

## 1. 一句话

**你有本地文件（图片、zip、视频、txt…）要发到 Freelog → 用 CLI 最快。**  
**你要在网页里点选、写 Markdown、付费用策略 → CLI 会给出对应环境的 Console 链接，网页完成后回到 CLI 重试。**

---

## 2. 五选一：我要发什么？

```text
① 单个资源（一张图、一个 zip、一个视频…）
   → freelog-cli init <目录>  （按提示选类型）
   → create → version set --file … → publish → policy apply → online
   → 教程：[快速上手](./快速上手.md) · 详解：[发行单个资源](./发行单个资源.md)

② 很多个独立资源（一批图/一批视频）
   → freelog-cli resource import-dir <文件夹> --resource-type <code> --yes --env dev
   → 详解：[批量发行](./批量发行.md)

③ 合集（多章小说、多集视频放在一个壳里）
   → init 选「合集」→ collection create → collection item import-dir …
   → collection publish → policy apply → online
   → 详解：[合集](./合集.md)

④ 文件夹直接变合集
   → freelog-cli collection init-from-folder --project-dir <项目目录> --media-dir <媒体文件夹> --yes --env dev
   → 详解：[合集](./合集.md)

⑤ 资源已在平台上，只想本地管理
   → freelog-cli resource search "关键词"   # 可选：先搜索
   → init + freelog-cli bind <resourceId>    # 或 bind username/shortname
   → 详解：[特殊流程 — 半路接入](./特殊流程.md)
```

登录（在你要操作的目录下执行）：

```bash
freelog-cli login --env dev          # 当前目录写入 .freelog-auth（工作区）
freelog-cli login --global --env dev # 机器默认账号（~/.freelog-auth）
freelog-cli status --env dev         # 看当前登录 vs 资源 owner 是否一致
```

**脚本/CI 必须传 `--env dev|test|prod` 或配置 `freelog-cli config init --default-env dev`**，否则非交互写操作可能因默认 production 被拒绝。

monorepo 可在根目录 login 一次，子目录自动继承；某子项目要用别的账号时，进入该目录再 login 即可覆盖。

**凭据安全：** `login` 写入的 token/cookie 等 **加密落盘**（默认密钥 `~/.freelog-cli/auth.key`）；详见 [全局参数 — 凭据加密](./全局参数与登录.md#凭据本地加密核心)。

## 3. CLI 和 Console 一样吗？

**发到平台上的结果一样**（同一 API）。  
**操作方式不同：**

| | Console | CLI |
|---|---|---|
| 填表 | 网页向导 | 命令 + 本地 `freelog.manifest.json` |
| 草稿 | 自动保存 | 须自己 `draft push` |
| 策略 | 可视化 Builder | 文本文件 `policy apply --from-file` |
| 封面 | 网页上传+裁剪 | 本地图片路径 `--cover` |
| 上架 | Step4 可「先上架再补」 | 须条件齐全再 `online`（更严格） |
| 依赖/上抛 | Authorization 微应用 | manifest + `dep auth` / `batchSignContracts`；**同账号也要签**；`dep add` 默认 `^latest` |

**授权提示：** 发行（`publish` / `collection publish`）、加合集条目、或批量 import 声明了依赖/上抛时，须先完成签约；失败时 JSON/`details` 含 Console 链接和 `nextCommand`。详见 [依赖与授权](./依赖与授权.md)。

---

## 4. 请用 Console 的情况

- 从**云存储**里选已有文件（CLI 只认本机路径）
- 用 **Markdown / Cartoon 编辑器**写内容
- **付费**策略需要付款；CLI 会给出依赖页、合约页和完成后的重试命令
- 看列表、收藏、收入（CLI 不管这些）

## 5. 常用命令（复制即用）

```bash
freelog-cli status --env dev
freelog-cli pull --env dev
freelog-cli update --title "新标题" --cover ./cover.jpg --tags "tag1,tag2" --env dev
freelog-cli publish --yes --env dev
freelog-cli publish --reuse-version 1.0.0 --bump --yes --env dev   # 同文件升版（仅改 deps/说明）
freelog-cli offline --yes --env dev
freelog-cli version set --video-cover ./poster.jpg --env dev
```

## 6. 容易踩的坑

| 情况 | 怎么办 |
|---|---|
| CI 脚本报「未指定 API 环境」 | 加 `--env dev` 或 `config init --default-env dev` |
| publish 提示无策略 | 可先 publish；**online** 前须 `policy apply` |
| publish 提示依赖未授权 | `dep auth --policy-map auth-map.yaml` 或打开 `details.actionUrl` |
| 批量有 dependencies | freelog.batch.json 每项须配 `batchSignContracts` |
| 批量超过 20 个文件 | 默认自动分批；硬限加 `--strict-batch-limit` |
| 合集里想单独 publish 某一章 | 不行；用 `collection item *` + `collection publish` |
| listing 改了 publish 失败 | `pull` 或去掉 `--no-auto-pull` |
| 同文件已发版想只升版本号 | `publish --reuse-version <旧版> --bump`（与 `--file` 互斥） |
| 资源被冻结 | Console 解冻后再 publish/online |
| 换电脑继续 | 拷贝整个项目目录（含 manifest）；或 `bind` 已有资源 |
| 错误提示是英文 | `freelog-cli lang set zh_CN` 或 `--lang zh_CN` |

更多现象见 [排错与验收](./排错与验收.md)。

## 7. 帮助与进阶

```bash
freelog-cli validate --for publish --env dev   # 发版前预检（doctor 同义）
freelog-cli diff --env dev                   # 本地 vs 平台差异
freelog-cli release --bump patch --build-cmd "npm run build" --online --yes --env dev
freelog-cli publish --dry-run --yes --env dev
freelog-cli version bump patch --env dev
freelog-cli resource import-dir ./photos --resource-type RT005001 --json-lines --yes --env dev
freelog-cli resource import-dir --resume .freelog/reports/<runId>.json --yes --env dev
freelog-cli resource import-dir --retry .freelog/reports/<runId>.json --yes --env dev
eval "$(freelog-cli completion bash)"        # 或 completion zsh
freelog-cli config init --default-env dev
freelog-cli policy init && freelog-cli dep init-auth-map
freelog-cli workspace list
```

**封面预处理：** CLI 无裁剪 UI，建议本地裁好再 `--cover` / `--video-cover`（JPG/PNG/静态 GIF，≤5MB）。

**手动验收入口：** [CLI 手动测试](../验证/手动测试.md)

**查单个命令全部参数：** `freelog-cli <命令> --help` · 全局参数见 [全局参数与登录](./全局参数与登录.md)
