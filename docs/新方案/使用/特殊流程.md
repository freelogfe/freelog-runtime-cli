# 特殊流程

[返回使用文档目录](./README.md)

## 将本地工程绑定到已有资源

如果资源已经在 Console 或其他工程中创建，不要再次执行 `create`。先初始化本地工程，再绑定已有资源：

```bash
freelog-cli init . --scaffold none --resource-type <typeCode> --artifact-mode file --resource-name <shortName> --yes --env production
freelog-cli bind <resourceId> --env production
freelog-cli status --env production
```

也可以使用完整授权名：

```bash
freelog-cli bind username/shortname --env production
```

绑定并采用平台基础信息：

```bash
freelog-cli bind <resourceId> --apply-listing --env production
```

目录已经绑定其他资源时，CLI 会停止。只有确认要替换本地绑定后才使用：

```bash
freelog-cli bind <resourceId> --force --yes --env production
```

`bind` 只允许绑定当前账号拥有、类型与 manifest 一致的资源，并会把平台事实写入 state。

## 搜索当前账号的资源

```bash
freelog-cli resource search "标题或授权名" --env production
freelog-cli resource search <resourceId> --limit 20 --env production
```

搜索结果可用于确定 `bind` 或临时维护所需的 `resourceId`。

## 在多个环境中维护

凭据和 state 都带环境信息。生产、测试和开发环境中的资源 ID 彼此独立，不能把一个环境的 state 直接用于另一个环境。

最佳做法是为不同环境使用独立工作目录。如果必须复用同一份 manifest，应先备份并移除旧环境的 `.freelog/state.json`，再使用目标环境账号登录并绑定目标环境资源。不要把测试资源 ID 写入正式环境 state。

## 批量流程中断

批量发行失败后，使用输出中的 `details.reportFile`：

```bash
freelog-cli resource import-dir --resume <reportFile> --yes --env production
freelog-cli resource import-dir --retry <reportFile> --yes --env production
```

不要直接重新执行整个目录。报告显示远端结果未知时，先在 Console 对账，确认是否已经创建资源。

## RSS 合集

RSS 命令在已有合集工程中执行：

```bash
freelog-cli collection rss inspect <feedUrl> --env production
freelog-cli collection rss send-code <feedUrl> --env production
freelog-cli collection rss bind <feedUrl> --code <verificationCode> --yes --env production
freelog-cli collection rss status --env production
freelog-cli collection rss sync --yes --env production
```

Feed 超过 15 条单集时，绑定时必须同时指定收录日期范围：

```bash
freelog-cli collection rss bind <feedUrl> --code <verificationCode> --pub-start 2026-01-01 --pub-end 2026-12-31 --yes --env production
```

更换 RSS 源且大量 GUID 无法匹配时，绑定会停止。确认新源会被当作新单集处理后，才使用：

```bash
freelog-cli collection rss bind <feedUrl> --code <verificationCode> --force --yes --env production
```

验证码发送到 feed owner 邮箱，不写入本地文件。常见失败处理：

| 现象 | 处理 |
|---|---|
| Feed 无法解析 | 检查公开 URL、网络和 RSS 格式 |
| 缺少 owner 邮箱 | 在 feed 中提供可识别的 owner 邮箱 |
| 已绑定其他合集 | 先处理原绑定，或使用其他 feed |
| 状态为同步中 | 等待当前同步结束后再执行 `sync` |
| GUID 大量不匹配 | 确认换源影响后，在 `bind` 使用 `--force --yes` |

RSS 合集的标题、封面、简介、标签、连载状态、目录、展示设置和版本由 feed 管理。绑定后，CLI 会拒绝对这些字段执行普通人工写操作。

## 自动收录规则

先读取当前规则：

```bash
freelog-cli collection collect-rules get --env production
```

创建 `collect-rules.json`：

```json
{
  "status": 1,
  "serializeStatus": 0,
  "conditionType": 1,
  "filterConditions": [
    {
      "key": "resourceTypeCode",
      "limitOperatorType": "EQUAL",
      "value": "<resourceTypeCode>"
    }
  ]
}
```

应用规则：

```bash
freelog-cli collection collect-rules set --from-file ./collect-rules.json --yes --env production
```

- `status`：`0` 关闭，`1` 开启。
- `serializeStatus`：`0` 连载，`1` 完结。
- `conditionType`：`1` 表示全部条件满足，`2` 表示任一条件满足。
- 条件 key 支持 `resourceTitle`、`resourceTypeCode`、`authIdentity`。
- `resourceTypeCode` 只支持 `EQUAL`；文本字段支持包含、不包含、开头和结尾匹配。
- `filterConditions` 至少包含一条有效条件，因此完整规则应使用 `--from-file`。

RSS 合集不能设置自动收录规则。

## 单命令临时维护

已有登录凭据但不希望写入 manifest/state 时，使用 `--session --resource-id`：

```bash
freelog-cli resource update --session --resource-id <resourceId> --title "新标题" --yes --env production
freelog-cli version edit --session --resource-id <resourceId> --version 1.0.0 --description "修正文案" --yes --env production
freelog-cli resource publish --session --resource-id <resourceId> --file ./v2.zip --version 2.0.0 --artifact-mode file --yes --env production
freelog-cli online --session --resource-id <resourceId> --yes --env production
```

同文件升版：

```bash
freelog-cli resource publish --session --resource-id <resourceId> --reuse-version 1.0.0 --bump --yes --env production
```

首次发行也可以在一条命令中表达：

```bash
freelog-cli resource publish --session --file ./photo.png --type <typeCode> --title "图片标题" --name photo-name --version 1.0.0 --artifact-mode file --yes --env production
```

需要转为长期工程时加 `--export-project <dir>`。单命令临时 Store 不会被下一条进程复用；依赖编辑和远端草稿应使用工程模式，或使用下一页介绍的交互会话。
