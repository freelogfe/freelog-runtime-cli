## 特殊流程（与 Console 写法不同）

### 半路接入

Console 已建资源壳 → CLI **不能** `create` → 用 `bind`：

```bash
freelog-cli init . --scaffold none --resource-type <code> --artifact-mode <file|directory-zip> --resource-name <shortname> --yes --env dev
freelog-cli bind <resourceId> --env dev
freelog-cli bind username/shortname --env dev              # 授权名形式
freelog-cli bind <resourceId> --apply-listing --env dev    # 绑定并写回 listing
freelog-cli bind <resourceId> --force --yes --env dev      # 覆盖已绑定 resourceId
freelog-cli status --env dev
```

**前提：** 目录须已有 manifest（先 `init`）。`bind` 会写 `state.resourceId` 并 pull 平台事实。

### 搜索已有资源

```bash
freelog-cli resource search "关键词" --env dev
```

输出匹配资源；CLI 会提示后续 `bind` 命令。适用于 Console 已创建、本地尚无工程的情况。

### 换环境

```bash
freelog-cli login --env test --yes ...
del .freelog\state.json
freelog-cli bind <test环境 resourceId> --env test
```

### 批量 import 失败

查看错误里的 `details.reportFile`，使用 `resource import-dir --retry <reportFile>` 只重试失败项；进程中断或存在 `remote_succeeded_local_pending` 时使用 `--resume <reportFile>`。**勿整目录重跑。**

### 合集 RSS

```bash
freelog-cli collection rss inspect <feedUrl> --env dev
freelog-cli collection rss send-code <feedUrl> --env dev
freelog-cli collection rss bind <feedUrl> --code <验证码> --yes --env dev
freelog-cli collection rss status --env dev
freelog-cli collection rss sync --yes --env dev
freelog-cli collection rss sync --pub-start 1 --pub-end 15 --yes --env dev   # >15 条须范围
freelog-cli collection rss sync --force --yes --env dev                        # 换源 GUID 大面积不匹配
```

超过 15 条单集必须同时提供 `--pub-start/--pub-end`；换源 GUID 大面积不匹配须显式 `--force --yes`。验证码来自 RSS owner 邮箱，不落盘。

**常见 RSS 失败：**

| 现象 | 处理 |
|---|---|
| feed 无效 / 无法解析 | 检查 URL、网络 |
| 缺少 owner 邮箱 | feed 须含可识别 owner |
| 已绑定其他合集 | Console 解绑或换 feed |
| sync 时状态为 importing | 等待上一轮完成 |
| GUID 不匹配 | 确认换源意图后 `--force --yes` |

RSS 合集的标题、封面、简介、标签、更新状态、目录条目、展示设置、草稿和手工发布均由 feed 管理，CLI 会拒绝对应写操作；仅可通过 RSS 专用命令管理订阅源与同步状态。

### 自动收录规则

```bash
freelog-cli collection collect-rules get --env dev
freelog-cli collection collect-rules set --from-file rules.json --env dev
freelog-cli collection collect-rules set --status 1 --condition-type AND --env dev   # 须配合 filter 或 from-file
```

规则必须包含 `status`、`conditionType` 和至少一条 `filterConditions`，可包含 `serializeStatus`。`resourceTypeCode` 只支持 `EQUAL`；标题/授权标识支持四种文本运算符；匹配值分别最多 100/60 字。

### 会话模式（无 manifest 工程）

无本地 `freelog.manifest.json` 时，用 **`--session --resource-id <id>`** 操作已有资源（对齐 Console 维护页 / versionCreator）。规格见 [CLI双模式设计](../开发/CLI双模式设计.md) §5.2。

**适用命令（须 `--session`；维护类还须 `--resource-id`）：**

| 命令 | Console 对照 |
|---|---|
| `resource publish --session` | versionCreator / creator Step2（含 `--reuse-version` 同文件升版） |
| `resource update --session` | sidebar/info |
| `version edit --session` | sidebar/versionInfo（**不改 deps**） |
| `dep add/remove/update/list/auth --session` | versionCreator deps / Authorization |
| `policy apply/set --session` | sidebar/policy |
| `online --session --resource-id <id>` / `offline --session --resource-id <id>` | 上下架 |

**不适用：** `draft push/pull/discard`（会话模式不调用 draft API；须工程目录或 `--export-project`）。

```bash
# 同文件升版并修改 deps：先导出长期意图，再从工程发布
freelog-cli dep add <depId> --session --resource-id <id> --target-version 2.0.1 \
  --export-project ./resource-project --env dev
cd resource-project
freelog-cli publish --reuse-version 1.0.0 --yes --env dev

# 换文件发新版
freelog-cli resource publish --session --resource-id <id> --file ./v2.zip --version 2.0.0 --yes --env dev

# 只改 listing
freelog-cli resource update --session --resource-id <id> --title "新标题" --yes --env dev

# 只改已发版说明
freelog-cli version edit --session --resource-id <id> --version 1.0.0 --description "修正" --env dev

# 可选：成功后导出工程
freelog-cli resource publish --session --resource-id <id> --file ./a.png --version 1.0.1 \
  --export-project ./exported --yes --env dev
```

说明：

1. 命令会话的内存 Store 只在当前进程有效，不能由下一条命令继续使用；`dep add/remove/update --session` 必须同时传 **`--export-project`**，后续进入导出的工程发布。
2. 需要不落盘的多步依赖编辑与发布时，使用单进程 `freelog-cli session`；单条 `resource publish --session` 只消费本条命令能够完整表达的意图。
3. `dep add/remove/update --session` 在 Store 尚无目标版本时须传 **`--target-version`**。
4. 首发（无 resourceId）可用 `resource publish --session --file … --type … --title …`（见双模式设计 §5.2）。
5. 自动化：`pnpm --filter @freelog-cli/cli verify:session-smoke`；P6 reuse/range 见 `verify:p6-parity`。

### 交互会话（11）与命令会话（01）

| | `xxx --session`（01） | `freelog-cli session`（11） |
|---|---|---|
| 凭据 | 读 `.freelog-auth` | 进程内 no-save |
| Store | EphemeralStore（S=1） | 同左 |
| 形态 | 单条命令 + `--yes` | TTY 菜单 + confirm |
| 适用 | 脚本、CI、已 login 用户 | 跳板机、一次性多步维护 |
| 等价能力 | 见上表命令 | 主菜单覆盖 publish/update/dep/policy/online/export |

TTY 多步维护优先用 **`freelog-cli session --env dev`**，详见 [交互会话与多账号工作区](./交互会话与多账号工作区.md)。
