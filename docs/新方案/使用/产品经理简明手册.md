# 产品经理简明手册 — Freelog Runtime CLI

最后更新：2026-08-10

> 本文是根目录 [DESIGN.md](../../../DESIGN.md) 的派生说明，只帮助快速理解，不反向定义产品。

## 1. CLI 是什么

Freelog Runtime CLI 是以本地工程为工作面的资源发行与生命周期工具。

它把 Console UI 中由下拉框、必填控件、分步向导、按钮禁用和确认弹窗承载的隐性约束，转化为：

- manifest 和本地文件；
- 参数/schema 校验；
- 状态机和写操作门禁；
- 显式确认、冲突处理和失败恢复；
- JSON/NDJSON 与稳定退出码。

CLI 对齐平台业务语义，但不复制 Console 的页面步骤。

## 2. CLI 的独特价值

| 能力 | 产品价值 |
|---|---|
| 工程模板 | 从空目录建立主题、插件、前端库/软件库工程和 manifest |
| 构建产物契约 | 明确源码、构建目录和最终上传物之间的关系 |
| 自动压缩 | 工程型资源发布时将构建目录打成临时 zip |
| 本地意图 | manifest 可审阅、可提交 Git、可复现 |
| 预检与差异 | validate/doctor/diff 在写平台前暴露问题 |
| 批量目录 | 将目录文件批量发行，并提供逐项结果与重试入口 |
| 自动化协议 | 非交互、JSON/NDJSON、exit code、CI 环境保护 |
| release 流水线 | 编排 validate → build → package → publish → online |

模板和压缩是正式产品能力，不是 Console parity 的附属项。

## 3. 三种发行模式

| 目标 | 本地模型 | 主要流程 |
|---|---|---|
| 单资源 | 一个工程、一份 manifest/state | `init` → `create` → `publish` → `policy` → `online` |
| 批量独立资源 | 输入目录生成 N 个可独立维护的子工程 | `resource import-dir` |
| 合集 | 一个合集工程和有序条目 | `init collection` → `collection item *` → `collection publish` |

工程类型和发行模式是两个维度：主题/插件/前端库属于工程立项选择；单资源/批量/合集属于业务发行模式。

## 4. Console 与 CLI 的关系

能力用三个维度描述，避免一个 `✅` 混合多种含义：

| 维度 | 取值 | 示例 |
|---|---|---|
| 范围 | `CORE` / `ADVANCED` / `OUT` / `NATIVE` | RSS 是 ADVANCED，模板是 NATIVE，支付是 OUT |
| 对齐方式 | `PARITY` / `EQUIVALENT` / `CLI_ONLY` | 自动草稿 → `draft push` 是 EQUIVALENT |
| 证据 | `SPEC` / `CODE` / `ENV` / `CONTRACT` | 区分设计、实现、环境可达和契约核验 |

Console 新增页面或 API 不会自动扩大 CLI 范围，必须先做产品判断。

## 5. 关键产品原则

1. manifest 是用户意图，state 是平台事实，凭据不进入项目。
2. CLI 不依赖用户记住 Console 的正确点击顺序；命令验证状态转换。
3. 所有写操作明确环境、owner、目标和副作用。
4. 非交互模式不提问、不猜测；缺少必要信息就明确失败。
5. `dry-run` 的产品定义是零副作用，只输出计划。
6. 本地和远端都变化时默认冲突，不静默覆盖。
7. 批量部分成功必须生成可恢复结果，跳过不能算通过。

## 6. 明确边界

- 云存储中点选文件：回 Console，或先下载到本地。
- Markdown/Cartoon 等浏览器微应用：不在本地文件发行核心范围。
- 付费策略签约：必须通过浏览器支付流程。
- 列表、收藏、收入、节点和详情预览：属于 Console 运营/消费侧。
- 视频转码、图片裁剪：由内容工具处理，CLI 只校验和上传准备好的内容。
- RSS/collect-rules：高级平台维护能力，不进入本地文件发行核心验收，但需完整对齐平台字段和编辑限制。

## 7. 怎样判断“已完成”

不能只看代码存在或某次“全部通过”的汇总数字。能力完成至少需要：

- 产品语义和边界明确；
- 字段、命令、错误和副作用契约明确；
- 静态检查、单元和契约测试通过；
- 真实环境 mandatory 场景通过，失败为零、未批准跳过为零；
- 需要 Console 对齐的能力有源码或 payload 证据；
- 用户说明和失败恢复方式完整；
- 验收报告绑定具体 commit、环境和场景目录。
