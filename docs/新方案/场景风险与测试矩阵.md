# CLI 场景风险与测试矩阵

最后更新：2026-08-05

本文面向开发、产品和测试，用于从真实使用者视角审查 CLI 设计是否覆盖资源发行全链路。CLI 要对齐 Console 的平台业务结果，但不复刻 Console 的页面交互。

## 1. Console 对齐基线

Console 资源页源码基线：

```text
D:\appinside\freelogfe-web-repos\packages\console\src\pages\resource
```

CLI 需要对齐的业务能力：

| 业务 | Console 页面表现 | CLI 设计 |
|---|---|---|
| 基础信息更新 | 页面直接保存 title、intro、coverImages、tags | `update` / `collection update` 显式修改 listing |
| 创建资源 | 创建向导 Step1 | `create` / `collection create` 只创建资源壳 |
| 发布版本 | Step2 或发新版页面 | `version set` 写本地意图，`publish` 创建正式版本 |
| 保存草稿 | 页面防抖保存 | `draft push/pull/discard` 显式处理 |
| 添加策略 | 策略 Builder 生成并提交 | `policy apply --from-file` 新增最终策略文本 |
| 启停策略 | 策略页启用/停用 | `policy set <policyId> --status 0/1` |
| 上下架 | 页面按钮或向导 Step4 | `online` 严格门禁，`offline` 下架 |
| 合集目录 | 合集目录草稿 | `collection item *` |
| 合集发布 | 合集固定版本发布 | `collection version set --description` + `collection publish` |

CLI 有意分叉：

1. 不做页面式一步向导；所有副作用拆成可重试命令。
2. 不做后台防抖草稿保存；避免 CI 或脚本产生隐式远端状态。
3. 不内置策略 Builder；策略正文由用户或上游工具生成。
4. 复杂/付费依赖授权回 Console；CLI 只处理可声明、可自动化的授权。
5. `online` 不走 Console 软 `update(status:1)`，必须检查 latestVersion 和启用策略。

## 2. 真实用户场景

| 用户身份 | 典型输入 | 目标 | 关键风险 |
|---|---|---|---|
| 主题 React 开发者 | 已有主题项目和 `dist` | 压缩产物并发版 | resourceType 选错、dist 不存在、版本号不递增、runtimeVersion 缺失 |
| 插件 Vue 开发者 | 模板创建或已有插件项目 | 构建后发版 | 模板依赖安装失败、runtime 不兼容、压缩逻辑错误 |
| 图片作者 | 单张图片 | 原文件发版 | 格式不支持、文件过大、误把目录当文件 |
| 视频作者 | 单个视频 | 原文件发版 | 大文件上传失败、格式不支持、封面误解 |
| 图片/视频批量作者 | 文件夹 | 每个文件一个资源 | 部分失败、命名冲突、超过批量上限、重试重复创建 |
| 合集维护者 | 图片/视频文件夹或已有资源 | 形成合集正式版本 | 子资源未授权、目录草稿未发布、itemTitle 不可读 |
| Console 协作用户 | Console 和 CLI 都改过 | 同步 listing/草稿 | 冲突被静默覆盖、state 和 env 串用 |
| 高级测试人员 | 异常账号/异常状态 | 验证边界 | owner 不符、未登录、无版本上架、无策略上架、停用最后策略 |

## 3. 必须解决的设计约束

| 优先级 | 约束 | 验收 |
|---|---|---|
| P0 | 发布和批量导入必须读取平台资源类型能力 | 不支持的文件格式、超大小、错误提交模式在上传前失败 |
| P0 | 普通资源和合集的 `status` 都要展示平台门禁 | latestVersion、status、enabledPolicyCount、ownerMatch 对合集同样可见 |
| P0 | `resource import-dir` 批量失败要有明确行为 | batch 不可用时可降级逐个创建；部分失败保留成功项并给失败清单 |
| P0 | 合集版本字段必须按官方固定版本口径封口 | `collection publish` 不传 version；`collection version set --version` 失败 |
| P1 | 已绑定项目不能被普通 `init --yes` 误覆盖 | 已有 resourceId/state 时需额外强制参数或拒绝 |
| P1 | 资源类型列表默认不误导用户选择禁用类型 | `type list/search` 标识状态，后续 create/publish 对禁用类型早失败 |
| P1 | 合集导入目录项标题要可读 | `collection item import-dir --title-prefix` 后 itemTitle 使用资源标题而不是授权名 |
| P1 | 合集导入子资源必须真的有正式首版 | `resource import-dir` / `collection item import-dir` 即使用 `createBatch` 也显式确认或创建 1.0.0 |
| P1 | dev 合集目录添加依赖 Console 免费策略产物 | `--item-policy-file` 使用 Console 内置“永久免费”模板文本；合集自身策略文件可分开 |
| P1 | 文档字段限制和代码一致 | intro、title、tags、cover 等限制以平台/Console 规则为准 |
| P1 | 视频链路和真实素材能力分开验收 | CLI 上传/发布/上下架已验证；真实视频专项只验证原文件上传、平台格式/大小限制、资源详情页链接可访问。CLI 不承担转码，也不在终端内做播放预览 |
| P1 | 草稿协作必须覆盖双写冲突和丢弃清理 | 单品草稿、合集发版表单草稿 live 均已验证 push、aligned、pull、both-dirty、force、discard；合集目录草稿仍按 `collection item *` 专项覆盖 |
| P1 | repo 内模板安装不等同用户环境 | 仓库内 `pnpm --dir` 会受 workspace 影响；模板实际构建发布用隔离安装验证 |
| P1 | 大合集分页不能截断判断 | 超过单页 limit 时继续分页或明确限制 |

## 4. 高级测试清单

基础正向：

1. 主题：`init -> create -> version set --file dist -> publish -> policy apply -> online`。
2. 插件：模板生成、安装依赖、构建、发布、上架。
3. 图片：单文件创建、发布、策略、上架。
4. 视频：单文件创建、发布、策略、上架。
5. 文件夹单品：`resource import-dir` 创建多个单品资源。
6. 文件夹合集：`collection item import-dir -> collection publish -> policy apply -> online`。

更新正向：

1. `update` 修改基础信息后 Console 可见。
2. Console 修改 listing 后，`status` 显示差异，`pull --apply-listing` 可采纳。
3. `version set` 后 `publish` 推进 latestVersion。
4. `version edit` 只修改已发布版本说明/属性，不上传新文件。
5. `policy set` 启停策略后 Console 策略状态一致。
6. `offline` 下架后版本和策略仍保留。

负向和边界：

1. 未登录执行写命令失败。
2. 非 owner 执行写命令失败。
3. 无 latestVersion 执行 `online` 失败。
4. 无启用策略执行 `online` 失败。
5. 已上架且只有一条启用策略时停用该策略失败。
6. 同一版本重复 `publish` 失败。
7. 资源被冻结时 `publish` 失败。
8. state env 与当前 `--env` 不一致时失败。
9. 文件格式不符合资源类型时上传前失败。
10. 文件大小超过资源类型限制时上传前失败。
11. 批量文件超过上限时失败。
12. 批量部分失败时成功项可追踪，失败项可重试。

## 5. 当前已知缺口

1. 文件处理仍存在基于资源类型名称/code 的压缩启发式，需要补平台能力校验。
2. 合集 `status` 的平台状态展示弱于普通资源。
3. `resource import-dir` 的 batch 失败降级逻辑需要修复。
4. `collection item import-dir` 的 itemTitle 需要改为资源标题。
5. 官方 `updateCollection` 文档明确“合集目前固定版本，所以无需传递版本号”；CLI 不支持设置合集版本号。
