# 07 · 用户身份测试手册

最后更新：2026-08-07

**用法：** 选定一种**用户身份**，按「单品 / 合集 / 批量」三条发行形态各跑一遍**首版 + 维护**，并在 Console 并排核对。  
排错 → [04-问题矩阵](./04-问题矩阵.md)；命令复制 → [05-场景实例](./05-场景实例.md)。

**环境：** dev 联调 `--env dev`；账号见 [交接文档 §4.2](../交接/CLI交接文档.md#42-当前联调环境dev)。

---

## 0. 两种维度怎么组合

| 维度 A：我是谁 | 维度 B：发什么 |
|---|---|
| 主题开发者 | **单品**（一个主题 zip） |
| 插件开发者 | **单品** |
| 图片作者 | **单品** / **批量**（文件夹多图） / **合集**（相册） |
| 小说作者 | **单品**（单文件） / **合集**（章节） / **批量**（多部独立） |
| 短视频作者 | **单品** / **合集**（系列） / **批量** |

每条组合 = **阶段 A 首版** + **阶段 B 维护** 至少各 1 次。

```text
阶段 A：login → init/import → create → version set → publish → policy → online
阶段 B：update / version bump / draft / policy set / offline→online /（合集 item *）
```

---

## 1. 主题开发者（P1 · 压缩类 · 单品）

**典型意图：** React/Vue 主题工程，build 出 `dist`，发版为 zip。

### 1.1 首版（必测）

| 步骤 | CLI | Console 核对 |
|---:|---|---|
| 1 | `init` 五选一「主题」→ 选模板 | creator Step1 类型=主题 |
| 2 | `pnpm build` | — |
| 3 | `create` → `version set --file dist --runtime 0.5` | Step2 版本意图 |
| 4 | `publish` | latestVersion、fileSha1 |
| 5 | `policy apply` → `online` | policies、status=1 |

脚本模式：`--resource-type RT001`（dev；以 `type info` 为准）。

### 1.2 维护（必测）

| 步骤 | CLI | Console 核对 |
|---:|---|---|
| 1 | `publish --bump` 或更高 version set + publish | versionInfo 新版本 |
| 2 | `version edit --description` | 已发版说明变更 |
| 3 | `update --title` + `pull --apply-listing` | sidebar **info** 一致 |
| 4 | `draft push` → Console 打开 → `draft pull` | 草稿对象一致 |

### 1.3 易错 / 漏洞关注点（用户视角）

| 现象 | 可能问题 | 见矩阵 |
|---|---|---|
| publish 报路径不存在 | 未 build | [04 §4.4](./04-问题矩阵.md#44-l4-内容与文件) |
| 传了 png 当 filePath | 主题须**目录** | 同上 |
| online 失败 | 无策略或无版本 | [04 §4.5](./04-问题矩阵.md#45-l5l7-发布--策略--上架) |
| Console 改了标题 CLI 不知道 | 未 pull / status | [04 §4.6](./04-问题矩阵.md#46-l8-协作--维护sidebar-info--versioninfo) |

自动化：S4、S7。

## 2. 插件开发者（P1 · 压缩类 · 单品）

与主题相同，init 五选一「**插件**」，dev code 通常 **RT002**。

### 2.1 差异点

| 项 | 说明 |
|---|---|
| `--runtime 0.4\|0.5` | 与主题相同，写入 inputAttrs |
| 已有 Vue/React 仓 | `init .` 选插件或 `init none` + `--resource-type RT002` |
| widget 快捷 | `init widget <dir>`（非交互定稿 RT002） |

### 2.2 维护必测

- 发新版后 **runtime 不变** 或 intentional 变更是否进 createVersion body（Console Network 可选 spot check）。
- `version edit --sync-properties` 后 Console 属性面板一致。

自动化：S8、S9。

## 3. 图片作者

### 3.1 单品 — 一张照片（P2）

```bash
freelog-cli init . --scaffold none --resource-type RT005001 --yes --env dev
freelog-cli create --yes --env dev
freelog-cli version set --version 1.0.0 --file ./photo.png --env dev
freelog-cli publish --yes --env dev
freelog-cli policy apply --from-file policy.free.json --yes --env dev
freelog-cli online --yes --env dev
```

**维护：** `update --cover` `--tags`；`pull --apply-listing --force`（S15a）。

素材：`test/abcdef.png`。

### 3.2 批量 — 文件夹多图各自独立（P3）

**不是合集。** 每张图一个 resourceId。

```bash
freelog-cli resource import-dir ./photos --resource-type RT005001 --yes --json --env dev
```

**必测：**

- 故意让 1 张损坏/超大 → 部分失败 + `retry.batch.json` 只重试失败项。
- 成功项在 Console「我的资源」里各有条目，**没有**合集壳。

### 3.3 合集 — 相册（P4）

```bash
freelog-cli init album --scaffold collection --resource-type RT003006 --yes --env dev
cd album && freelog-cli collection create --yes --env dev
freelog-cli collection item import-dir ../photos --resource-type RT005001 \
  --item-policy-file ./policy.free.json --yes --env dev
freelog-cli collection publish --yes --env dev
freelog-cli collection policy apply --from-file policy.free.json --yes --env dev
freelog-cli online --yes --env dev
```

**维护：** item update/reorder/remove → 再 publish；合集 offline/online（S15e）。

### 3.4 图片作者易错点

| 误区 | 正确理解 |
|---|---|
| import-dir = 发合集 | P3 是多个**独立**资源；P4 才是一个合集 |
| 子目录里的图会被扫到 | 只扫**顶层**文件 |
| 合集 = 上传 zip | 每个文件先变子资源，再进目录草稿 |

自动化：S6、S11、S13。

## 4. 小说作者

**边界（必读）：** Console 的 **Markdown/Cartoon 微应用编辑器** CLI **不做**（[对照 §0.2 #19](../对齐/CLI数据操作与Console对照.md#02-cli-不应做--完全做不到边界真源)）。  
CLI 路径 = **本地文件**（`.txt` / `.md` / 平台允许的文本类叶子类型），不是在线富文本编辑。

### 4.1 查类型（首步必做）

```bash
freelog-cli type search 小说 --env dev --json
freelog-cli type search 文本 --env dev --json
freelog-cli type list --env dev --json
freelog-cli type info <叶子code> --env dev   # 看 fileMaxSize、是否单文件
```

记下叶子 **`<NOVEL_LEAF_CODE>`**（各环境可能不同，禁止硬编码）。

### 4.2 形态 A — 整部小说一个文件（P2 · 单品）

适用：单文件即完整作品。

```bash
freelog-cli init my-novel --scaffold none --resource-type <NOVEL_LEAF_CODE> --yes --env dev
cd my-novel
freelog-cli create --yes --env dev
freelog-cli version set --version 1.0.0 --file ../book.txt --description "首版" --env dev
freelog-cli publish --yes --env dev
freelog-cli policy apply --from-file policy.free.json --yes --env dev
freelog-cli online --yes --env dev
```

**维护：** 修订版 `version set 1.0.1 --file ../book-v2.txt` → publish；改简介 `update --intro`。

### 4.3 形态 B — 分章合集（P4 · 推荐）

适用：每章一个文件，读者按目录阅读（Console collectionSidebar **versionInfo** 目录）。

```bash
freelog-cli init novel-series --scaffold collection --resource-type RT003006 --yes --env dev
cd novel-series
freelog-cli collection create --yes --env dev
freelog-cli collection item import-dir ../chapters \
  --resource-type <NOVEL_LEAF_CODE> \
  --title-prefix "第" \
  --item-policy-file ./policy.free.json \
  --yes --env dev
freelog-cli collection version set --description "连载 v1" --env dev
freelog-cli collection publish --yes --env dev
freelog-cli collection policy apply --from-file policy.free.json --yes --env dev
freelog-cli online --yes --env dev
```

**维护（连载）：**

```bash
# 新章节
freelog-cli collection item add <newChapterResourceId> --env dev
# 或 import-dir 仅新文件到临时目录再 add
freelog-cli collection item reorder <id> --after <id> --env dev
freelog-cli collection publish --yes --env dev
freelog-cli collection update --intro "更新至第 N 章" --env dev
```

### 4.4 形态 C — 多部作品批量独立（P3）

适用：文件夹里每部小说各自一个资源（非系列合集）。

```bash
# freelog.batch.json 可为每部指定 title、intro、tags
freelog-cli resource import-dir ./novels --resource-type <NOVEL_LEAF_CODE> --yes --json --env dev
```

### 4.5 小说作者 × Console 差异（不算 CLI bug）

| Console | CLI |
|---|---|
| Markdown 抽屉编辑 | 本地 `.md` / `.txt` 作 `--file` |
| 防抖自动存草稿 | 显式 `draft push` |
| 章节在 UI 拖拽排序 | `collection item reorder` |

### 4.6 小说作者必测问题

| # | 测什么 | 预期 |
|---|--------|------|
| N1 | 用 Markdown 编辑器路径期望 CLI 等价 | **不支持**；须本地文件 |
| N2 | 章节未 policy/未上架就进合集 | publish/import **阻断** |
| N3 | 改目录后只 draft push --collection | **不应**替代 item * + collection publish |
| N4 | 简介超长 | update/collection update 平台限制 |
| N5 | 分章合集再发「整书新版」 | 合集 publish merge 行为与 Console 一致 |

**自动化缺口：** 小说叶子类型因环境而异，建议手工 + 记入 [08 漏洞台账](./08-测试人员手册.md#5-漏洞与缺口台账)。

## 5. 短视频作者

dev 实测短视频类型：**RT006003**（以 `type info` 为准）。

### 5.1 单品 — 一个视频（P2）

```bash
freelog-cli init . --scaffold none --resource-type RT006003 --yes --env dev
freelog-cli create --yes --env dev
freelog-cli version set --version 1.0.0 --file clip.mp4 --video-cover cover.png --env dev
freelog-cli publish --yes --env dev
freelog-cli policy apply --from-file policy.free.json --yes --env dev
freelog-cli online --yes --env dev
```

### 5.2 合集 — 系列短视频（P4）

与图片合集相同，条目类型改为 **RT006003**，媒体目录放 mp4。

```bash
freelog-cli collection item import-dir ../clips --resource-type RT006003 \
  --item-policy-file ./policy.free.json --yes --env dev
```

### 5.3 批量 — 多个独立视频账号（P3）

```bash
freelog-cli resource import-dir ./clips --resource-type RT006003 --yes --json --env dev
```

### 5.4 短视频作者易错点

| 现象 | 原因 |
|---|---|
| 传目录当视频 | 须单文件 mp4（+ 可选 cover） |
| 期望 CLI 转码 | **不支持**（Console 也不转码） |
| videoCover 维护已发版 | 发**新版**时在 version set 传 `--video-cover` |
| 封面图过大 | `type info` 查限制 |

自动化：S10、S12。

## 6. 身份 × 形态 必测矩阵（用户自检）

完成时在 Console 并排打 ✓。

| 身份 | 单品首版+维护 | 批量(P3) | 合集(P4) | 备注 |
|---|---|:---:|:---:|---|
| 主题开发者 | ✓ | — | — | zip + runtime |
| 插件开发者 | ✓ | — | — | RT002 |
| 图片作者 | ✓ | ✓ | ✓ | RT005001 / RT003006 |
| 小说作者 | ✓ | ✓ | ✓ | 先 type search；无 Markdown UI |
| 短视频作者 | ✓ | ✓ | ✓ | RT006003 + video-cover |

**维护项（每个身份至少抽 2 项）：** update listing · publish bump · draft 协作 · policy set 门禁 · offline/online。

## 7. 用户身份下的「找漏洞」清单

以**真实用户**心态尝试「能不能偷懒、会不会丢数据」：

| # | 恶意/偷懒操作 | 应有结果 |
|---|--------------|----------|
| U1 | 不 login 直接 publish | 失败，提示登录 |
| U2 | 不 policy 直接 online | 失败，门禁 |
| U3 | 不 publish 直接 online | 失败 |
| U4 | 批量失败后整目录重跑 | 应支持 retry，不重复成功项 |
| U5 | Console 改标题后 CLI 直接 publish | status 应提示 listing 差异 |
| U6 | 两终端同时 draft push | 冲突 code 3 或 force |
| U7 | 上架后停用全部策略 | 应拒绝或须先 offline |
| U8 | 把批量当合集（或反过来） | 平台结果完全不同，文档应能区分 |
| U9 | 小说只用 draft 不加章节 | 目录不应变 |
| U10 | 换 --env 不删 state | 写命令失败 |

失败行为不符合上表 → 记 [08 §5 漏洞台账](./08-测试人员手册.md#5-漏洞与缺口台账)。

## 8. 记录模板（用户测试）

```text
身份：图片作者 / 合集
路径：P4 首版 + item reorder 维护
命令：（粘贴 --json 输出）
resourceId / collectionId：
Console 截图/字段：latestVersion / 目录项数 / status
结果：PASS | FAIL（现象 + 期望）
```
