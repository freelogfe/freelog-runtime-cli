# CLI 手动测试

> 文档角色：当前开发版本的唯一手动测试入口；它验证产品契约，不定义产品范围。

最后更新：2026-08-14

## 1. 测试前准备

在仓库根目录执行：

```bash
pnpm install
pnpm verify
pnpm --filter @freelog-cli/cli verify:console-forms
pnpm --filter @freelog-cli/cli exec vitest run tests/fieldConstraints.test.ts tests/preflightSummary.test.ts
pnpm --filter @freelog-cli/cli verify:l3g-automated   # L3-G 自动化层（17 项 + 预检）
pnpm --filter @freelog-cli/cli verify:p6-parity    # P6：dep range / reuse-version / frozen（frozen 可无 fixture 则 skip）
```

然后构建并使用当前 CLI：

```bash
pnpm --filter @freelog-cli/cli build
node packages/cli/dist/bin/index.js --help
```

**dev 自动化全场景（推荐）：**

```bash
node test/run-all-scenarios.mjs --env dev
```

覆盖 `verify:scenarios` 与 L2 健壮性（NEG/BATCH/JSON/CHAOS）及其内置 parity 子脚本。**本入口不执行** `verify:p6-parity`、`verify:session-smoke` 或 `verify:rss`；三者须按本页和[场景目录](./场景目录.md)分别执行并记录。Console 并排见 [探索测试清单](./探索测试清单.md)。**最新自动化快照**见 [2026-08-14-dev.md](./reports/2026-08-14-dev.md)；更早历史见 [2026-08-12-dev.md](./reports/2026-08-12-dev.md)。

测试项目必须放在仓库之外的临时目录。不要在仓库根目录运行 `init/create/bind`。

**凭据（dev 联调）：** 优先 `test/.freelog-test-credentials.local.json`（gitignore，见 [test/README.md](../../../test/README.md)）；或环境变量 `FREELOG_TEST_*` / `FREELOG_TEST_SECONDARY_*`；或工作区 / `login --global` 登录。两个 dev 专用账号仅集中记录在 [CLI交接文档](../CLI交接文档.md#32-dev-两个联调账号)，其他文档和报告不得复制密码。

身份凭据按 [DESIGN.md](../../../DESIGN.md)「身份与凭据 · 本地加密」：在测试目录内 `login` 写工作区 `.freelog-auth`（**敏感字段加密落盘**）；无工作区凭据时回退全局。多账号场景需分别在对应目录 login 并用 `status` 核对 owner。

## 2. 环境规则

```bash
# 在测试工作目录内 login（工作区凭据）
freelog-cli login --env dev
freelog-cli status --env dev   # 确认 loggedIn、auth.scope、owner.matchLogin
```

- 所有写操作显式传 `--env dev`。
- 非交互命令显式传 `--yes`。
- JSON 测试时 stdout 只能是协议数据；诊断信息应在 stderr。
- 每个测试项目检查 `freelog.manifest.json` 与 `.freelog/state.json` 是否职责分离。

## 3. 主路径

### M1：单文件资源

```bash
freelog-cli init image-smoke --scaffold none --artifact-mode file --resource-type <imageLeafCode> --yes --env dev
cd image-smoke
freelog-cli create --yes --env dev
freelog-cli version set --version 1.0.0 --file <imagePath> --yes
freelog-cli validate --for publish --env dev
freelog-cli publish --dry-run --env dev
freelog-cli publish --yes --env dev
freelog-cli policy apply --from-file <policyFile> --yes --env dev
freelog-cli online --yes --env dev
```

核对：文件名、SHA1、版本、策略、status 与 Console 一致；dry-run 不修改 manifest/state、不压缩、不上传、不写平台。

### M2：模板与工程型资源

```bash
freelog-cli init theme-smoke --scaffold runtime --template vite-react-ts --resource-type <themeLeafCode> --runtime 0.5 --yes --env dev
cd theme-smoke
pnpm install
freelog-cli release --bump patch --build-cmd "pnpm build" --dry-run --env dev
freelog-cli create --yes --env dev
freelog-cli release --bump patch --build-cmd "pnpm build" --yes --env dev
```

核对：模板版本和 runtime 匹配；`artifactMode=directory-zip`；build 前不要求 `dist` 已存在；相同输入生成相同 zip SHA；临时 zip 最终被清理。

### M3：已有工程接入

```bash
freelog-cli init . --scaffold none --artifact-mode directory-zip --resource-type <themeLeafCode> --runtime 0.5 --yes --env dev
freelog-cli bind <resourceId> --yes --env dev
freelog-cli status --env dev
freelog-cli diff --env dev
```

核对：已绑定项目不能被 init 覆盖；owner 或环境不一致必须失败。

### M4：批量独立资源

```bash
freelog-cli resource import-dir <filesDir> --resource-type <leafCode> --title-prefix smoke --json-lines --yes --env dev
```

核对：输出 start/item/warning/done 事件；每项生成独立子工程；正式报告位于 `.freelog/reports/<runId>.json`。制造一项失败后：

```bash
freelog-cli resource import-dir --retry <reportPath> --yes --env dev
freelog-cli resource import-dir --resume <reportPath> --yes --env dev
```

`--retry` 只处理明确失败项；`--resume` 从安全阶段恢复；`remote_outcome_unknown` 必须停止并要求 Console 对账。

### M5：合集

```bash
freelog-cli init collection-smoke --scaffold collection --resource-type <collectionLeafCode> --yes --env dev
cd collection-smoke
freelog-cli collection create --yes --env dev
freelog-cli collection item add <resourceId> --yes --env dev
freelog-cli collection version set --description smoke
freelog-cli collection publish --yes --env dev
freelog-cli collection policy apply --from-file <policyFile> --yes --env dev
freelog-cli online --yes --env dev
```

核对：条目顺序、展示属性、目录草稿指纹、merge 语义和 Console 一致。

### M6：依赖与签约

```bash
freelog-cli dep add <dependencyResourceId> --yes --env dev   # 无 range：默认 ^latestVersion
freelog-cli dep add <dependencyResourceId> --version-range "^1.0.0" --yes
freelog-cli dep init-auth-map
freelog-cli dep auth --policy-map auth-map.yaml --yes --env dev
```

免费策略由 CLI 直接签约。付费或复杂授权必须返回当前环境的 `actionUrl`、`contractsUrl` 和 `nextCommand`；在 Console 完成后重跑，CLI 应按每个声明依赖确认至少一份有效合同。

### M8：P6 Console parity（手测对照）

在已有 **1.0.0 已发版** 的资源上（工程模式 cwd 内）：

```bash
# P6-1：dep 默认 range
freelog-cli dep add <dependencyResourceId> --yes --env dev
freelog-cli dep list --env dev   # 核对 versionRange 为 ^<latest> 或 *

# P6-2：同文件升版
freelog-cli publish --reuse-version 1.0.0 --bump --yes --env dev
freelog-cli version show --env dev   # 新版本号 + 同 fileSha1
```

会话模式等价（无 manifest 工程）：

```bash
freelog-cli resource publish --session --resource-id <id> --reuse-version 1.0.0 --bump --yes --env dev
```

**P6-4 冻结（完整签字必填）：**

1. 在 dev Console 打开任一 **自有测试资源** → 冻结（维护页 / 侧栏）。
2. 复制 `test/.freelog-test-fixtures.local.example.json` → `test/.freelog-test-fixtures.local.json`，填入 `frozenResourceId`。
3. 运行 `pnpm --filter @freelog-cli/cli provision:frozen-fixture` 确认可读。
4. 运行 `pnpm --filter @freelog-cli/cli verify:p6-parity` 与 `verify:negative-gates`（NEG-10）；`online` / `publish` 应对该资源 **code 4**。

dev 普通账号 **不能** API 设 `status:2`。未提供 fixture 时自动化记 **skip**，不计入完整产品签字。

### M7：collect-rules 与 RSS

```bash
freelog-cli collection collect-rules get --env dev
freelog-cli collection collect-rules set --from-file <rules.json> --yes --env dev
freelog-cli collection rss inspect <feedUrl> --env dev
freelog-cli collection rss send-code <feedUrl> --env dev
freelog-cli collection rss bind <feedUrl> --code <code> --yes --env dev
freelog-cli collection rss status --env dev
freelog-cli collection rss sync --yes --env dev
```

collect-rules 核对完整字段 round-trip。RSS 必须使用受控 feed 和 owner 邮箱；验证码不得落盘。RSS 是完整产品签字的 mandatory 项：`verify:rss` 与人工 inspect/send-code/bind/status/sync 状态链都必须完成；未执行只能记录为跳过，不能由 `run-all-scenarios` 或其他 CLI 能力替代。

## 4. 必测负向

自动化：`pnpm --filter @freelog-cli/cli verify:negative-gates`（NEG-*，已纳入 `run-all-scenarios`）。下表为人工对照摘要：

| 用例 | 预期 |
|---|---|
| 非叶子资源类型 | 创建前失败 |
| 非 TTY production 写操作未显式 env | 失败 |
| state/auth 环境不一致 | 失败 |
| 非 owner 写资源 | code 2 |
| 版本不大于 latestVersion | 失败；`release --bump` 使用计划版本通过校验 |
| 无正式版本或无启用策略 online | 失败 |
| 上架态停用最后一条策略 | 失败 |
| 目录资源未声明 `artifactMode` | 失败，不猜类型名 |
| 授权树缺少任一声明依赖 | 失败，不因其他有效合同放行 |
| 冻结资源 publish/online | code 4；须 Console 解冻 |
| 批量远端结果未知 | 不自动重试、不报告成功 |

## 5. Console 并排

至少选择一个单文件资源、一个工程型资源、一个合集，逐项核对：

- resourceId/resourceName/type/title/intro/tags/cover；
- version/fileSha1/filename/description/inputAttrs/custom properties；
- policies/status；
- dependencies、合同授权状态；
- 合集条目、顺序、展示字段、collect-rules/RSS 状态。
- **P6：** `dep add` 默认 range；`publish --reuse-version` 同 fileSha1 升版；冻结资源拒绝 online/publish。

字段限制与提示以 [Console表单字段与交互规则](../对齐/Console表单字段与交互规则.md) 为检查表，能力范围以 [CLI数据操作与Console对照](../对齐/CLI数据操作与Console对照.md) 为检查表。

## 6. 签字条件

- `pnpm verify` 全部通过。
- Console 表单源码契约全部通过。
- `node test/run-all-scenarios.mjs --env dev` 通过（含 L2 健壮性）。
- `verify:p6-parity`、`verify:session-smoke` 与 `verify:rss` 分别完成；受控 frozen fixture 和 RSS 邮箱缺失时不得写为通过。
- L3 [探索测试清单](./探索测试清单.md) 每 persona 至少 1 例；**TTY 字段约束**须完成 **L3-G**（G1–G5）。
- 本次 mandatory 手动项失败为零；未执行项单独记录，不计为通过。
- 没有凭据或测试项目残留在仓库。
- 真实环境结果写入新的日期化报告，不覆盖历史报告。
