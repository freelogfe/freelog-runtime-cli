# 00 · 方案总览与验收标准

> **文档角色：** 方案完整性门禁。本文定义“产品方案完整”的标准，后续文档不是材料汇总，而是实现前必须满足的规格。

最后更新：2026-09-02

## 1. 一句话目标

Freelog Runtime CLI 是一个面向本地资源、工程目录、AI/CI 和终端用户的资源发行与维护工具：它必须对齐 Console 的资源业务、字段约束和接口流程，同时把 Console UI 隐含的操作变成 CLI 里清晰、连续、可恢复、可脚本化的体验。

## 2. 完整方案必须包含什么

每个能力必须同时说明以下八件事，少任何一项都不能进入实现：

| 项 | 必须回答的问题 | 放在哪 |
|---|---|---|
| 用户目标 | 用户为什么要做这件事，完成后得到什么 | 01 |
| Console 业务流程 | Console 当前怎么做，步骤顺序是什么 | 02 |
| 字段约束 | 每个字段必填性、长度、枚举、动态来源、禁用条件 | 02 |
| 接口调用 | 何时调用哪个接口，参数从哪里来，成功状态是什么 | 02 |
| CLI 流程 | TTY、非交互、AI/CI 下用户怎么完成同一件事 | 04 |
| CLI 原生准备能力 | 模板、现有工程、构建、独立压缩如何得到发行物 | 03、04 |
| 异常恢复 | 网络失败、平台拒绝、中断、重复、冲突时怎么处理 | 05 |
| 实现契约 | 实现需要哪些层、状态机、校验器、输出协议 | 06 |
| 验收方式 | 如何证明实现没有遗漏流程和字段 | 05、06 |

## 3. 主业务地图

```text
身份与环境
  → 登录 / 会话 / 多账号 / owner 确认
  → 选择工作模式
      ├─ 单资源发布
      ├─ 已有资源更新
      ├─ 合集创建与维护
      ├─ RSS 绑定与同步
      ├─ collect-rules 自动收录
      ├─ 批量本地资源发行
      └─ 主题/插件资源发行与 Console 接力
  → 资源类型选择
      ├─ 逐级浏览
      ├─ 搜索
      └─ 类型能力确认
  → 内容来源与本地准备
      ├─ 从模板创建新工程
      ├─ 使用现有本地工程
      ├─ 使用已有构建产物
      ├─ 使用已有单文件
      └─ 独立压缩/打包得到 artifact
  → 资源壳 / 版本 / 策略 / listing / 上架
  → 报告 / 恢复 / 后续维护入口
```

## 4. 一期覆盖范围

| 能力 | 一期要求 | 是否必须闭环 |
|---|---|---|
| 登录、会话、多账号 | 支持本机持久登录、临时会话、显式账号选择、AI/CI 安全读取 | 必须 |
| 模板/脚手架 | 可独立创建主题/插件/工程模板，也可在发布流程中选择“从模板创建”作为内容来源 | 必须 |
| 独立压缩/打包 | 可单独把目录按 Freelog 规则打成确定 artifact，输出路径、大小、sha1；也可被发布流程调用 | 必须 |
| 单资源首次发布 | 从本地文件/目录/构建产物到资源壳、版本、策略、listing、上架 | 必须 |
| 已有资源更新 | 新版本、版本信息维护、listing、策略、上下架 | 必须 |
| 资源类型选择 | 逐级浏览为主，搜索为辅，动态读取平台类型树 | 必须 |
| 策略 | 先选模板，再填参数，再编译/翻译/保存 | 必须 |
| 依赖与授权 | 依赖选择、版本范围、授权缺口提示、显式排除 | 必须 |
| 合集 | 创建合集、添加条目、排序、条目标题草稿、保存目录草稿 | 必须 |
| RSS | feed 检测、验证码、1000 单集限制、日期筛选、GUID 差异确认、锁定字段 | 必须 |
| collect-rules | 自动收录开关、条件关系、字段/操作符/值联动 | 必须 |
| 批量 | 本地扫描、模板命名、分批、报告、恢复、逐项结果 | 必须 |
| 主题/插件资源 | 按平台类型树发行资源，构建/打包由 CLI 提供 | 必须 |
| 节点主题激活、支付、签约 | CLI 输出 Console 接力链接和携带信息 | Console 接力 |

## 5. 不覆盖范围

- 不在 CLI 内重做支付、收银台、合同风控、节点 UI 激活。
- 不在一期内做 Console 富编辑器的完整替代；CLI 可以上传产物或接力 Console。
- 不把平台动态类型、模板、策略枚举写死到代码。
- 不兼容旧方案里的错误交互；当前没有旧代码和旧数据负担。

## 6. 质量门槛

进入代码实现前必须满足：

1. 所有主流程都有流程图或步骤表。
2. 每个写接口都有调用时机、参数来源、成功状态和失败处理。
3. 每个用户输入字段都有约束、默认值、交互提示和非交互错误。
4. 每个 CLI 特有能力都有 Console 对齐边界和本地体验设计。
5. 每个 Console 无法替代的流程都有接力原因、链接信息和用户下一步。
6. 模板、构建、压缩、上传、平台写入必须是可单独观察的阶段，不能合并成一个黑盒“发布”。
7. 产品方案中不存在未收口的业务占位词。

## 7. 证据与动态边界

方案依据 Console 资源域源码和 `@freelog/tools-lib` 接口定义。源码能确认的规则写为硬约束；需要随平台数据变化的规则写为动态边界；前端没有本地门禁但接口仍可能拒绝的规则写为服务端兜底。动态边界不是未设计，而是实现必须实时读取平台状态。
