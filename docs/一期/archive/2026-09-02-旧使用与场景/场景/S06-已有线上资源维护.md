# S06 · 已有线上资源维护

> **文档角色：** 已在 Console 或其它工具中存在的独立资源接入 CLI 后的维护历史场景材料。当前主线方案见 [../产品方案/README.md](../产品方案/README.md)；交互拓扑补充见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)。

最后更新：2026-08-28

---

## 1. 用户目标

用户已有线上资源，可能只知道标题、授权标识或 resourceId。他希望用 CLI 维护 listing、发布新版本、编辑已发版说明、处理依赖、策略和上下架。

---

## 2. 入口拓扑

```text
搜索 / 输入 resourceId
  → 展示候选资源、owner、类型、状态、latestVersion
  → bind
  → pull 平台事实
  → 选择维护动作
```

绑定不是重新创建资源，也不是把平台内容全部覆盖到本地。

---

## 3. Console 对齐点

| Console sidebar | CLI 动作 |
|---|---|
| info 维护 title/intro/cover/tags | `update` |
| versionInfo 维护已发版 description/属性 | `version edit` |
| dependency/contract | `dep auth` 或 code 5 Console handoff |
| policy | 新增走 [S14 策略模板 Builder](./S14-策略模板选择与应用.md)；启停/列表走 `policy set/list` |
| 上下架 | `online/offline` |

---

## 4. TTY 连续向导

| checkpoint | 用户看到 | 输入 | 副作用 | 失败处理 |
|---|---|---|---|---|
| E1 查找资源 | 输入关键词/resourceId | 文本 | 只读平台 | 无结果给搜索建议 |
| E2 选择资源 | 候选列表：标题/name/type/status/owner | 选择 | 无 | owner 不符停止 |
| E3 绑定确认 | 将写 manifest/state 哪些字段 | confirm | 写本地绑定 | 不覆盖 listing 意图 |
| E4 同步策略 | pull 只刷新 state；apply-listing 会改 manifest | 选择 | 可能写本地 | 冲突需确认 |
| E5 维护动作 | update/publish/version/策略模板/online | 选择 | 看动作 | 每步 preflight |
| E6 成功续接 | 下一步 | 选择 | 确认后写 | 给复制命令 |

---

## 5. AI/CI 等价命令

```bash
freelog-cli search <keyword> --env <env> --json
freelog-cli bind --resource-id <id> --yes --env <env>
freelog-cli pull --env <env>
freelog-cli update --title "新标题" --yes --env <env>
freelog-cli publish --bump patch --yes --env <env>
freelog-cli online --yes --env <env>
```

---

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 同名多个资源 | 列 owner、type、status、latestVersion，让用户选 |
| 本地 manifest 已有其它 resourceId | 拒绝覆盖，除非明确新目录或解绑流程 |
| 平台 listing 与本地 listing 都变了 | 三方冲突，提示 diff/pull/force |
| 用户只改已发版说明 | 引导 `version edit`，不要让他重新发文件 |
| owner 不一致 | 停止并提示当前账号/资源 owner |

---

## 7. 回归到总设计

已有资源场景要求：

- root/start 第一屏有“维护已有线上资源”；
- bind/pull 语义必须在 UI 文案里讲清；
- 不允许为了省事把平台 listing 默认覆盖 manifest。
