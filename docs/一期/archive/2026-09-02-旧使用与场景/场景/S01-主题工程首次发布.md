# S01 · 主题工程首次发布

> **文档角色：** 主题资源从空目录到首次发布的历史场景材料。当前主线方案见 [../产品方案/README.md](../产品方案/README.md)；交互拓扑补充见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)。

最后更新：2026-08-28

---

## 1. 用户目标

用户是主题开发者，手上可能是空目录，也可能已有一个前端工程。他想把本地主题工程发布为 Freelog 平台的“主题”资源，并能继续发版、配置策略和上架。

成功体验不是“搜索到一个类型然后填一堆参数”，而是：

```text
选择「主题」入口
  → 选择技术模板
  → 明确平台资源类型就是「主题」叶子
  → build dist
  → 预检压缩包与版本
  → 发布版本
  → 配策略
  → 上架
```

---

## 2. Console 对齐点

| Console 业务 | CLI 必须对齐的结果 |
|---|---|
| creator Step1 资源类型必选 | 主题入口最终必须落到平台有效 leaf 类型，不能写父类型或旧硬编码 code |
| creator Step1 标题/name | 标题 trim 后非空 ≤100；授权标识 1–60 且规范化后展示 |
| creator Step2 本地上传 | 主题工程不是上传源码目录，而是发布构建产物目录的 zip |
| 版本号/说明 | 版本号必须 semver 且递增；说明进入 createVersion payload |
| 策略与上架 | 策略新增先走 Console 同源模板 Builder；online 前必须有 latestVersion 和启用策略 |

Console 没有“生成本地工程模板”这个能力；模板、构建命令、dist 压缩属于 CLI-native，但不得改变最终平台 payload 语义。

## 3. 资源类型设计

主题不能让用户去普通类型搜索里碰运气。

| 步骤 | 规则 |
|---|---|
| 大类入口 | 第一屏必须有「主题」 |
| 类型来源 | CLI 查询当前环境平台类型树 |
| 定稿规则 | 找到展示名为「主题」的有效 leaf；如果「主题」是父节点，则继续展示它的子级让用户选 leaf |
| 多候选 | 展示完整路径、code、能力摘要，由用户确认 |
| 无候选 | 停止并提示平台类型树无「主题」，不得 fallback 到写死 `RT*` |
| 确认页 | 展示 `资源类型：<完整路径> (<code>)`，但不要求用户手填 code |

类型写入 manifest 时保存 leaf code 和 labels；labels 只服务显示和对账，平台写入以 code 为准。

## 4. TTY 连续向导

| checkpoint | 用户看到 | 输入 | 副作用 | 失败处理 |
|---|---|---|---|---|
| T1 选择任务 | “你要发布什么？” | 主题 | 无 | 返回主菜单 |
| T2 环境/账号 | 当前 env、账号、凭据来源 | 登录或切账号 | 可能写 auth | 登录失败停在本地 |
| T3 工程目录 | 目标目录是否为空/已有工程 | 目录路径 | 无 | 已有 Freelog 工程则引导 status |
| T4 选择模板 | Vue/React/TS 模板 | 模板 id | 未确认前无写入 | 模板不兼容则换模板 |
| T5 资源字段 | 标题、授权标识、版本号 | 文本 | 确认后写 manifest | 即时显示长度/规范化结果 |
| T6 生成工程 | 将写哪些文件 | confirm | 写模板、manifest、gitignore | 写失败不创建平台资源 |
| T7 构建提示 | 需要 `pnpm install && pnpm build` | 继续/退出 | 无 | 退出时给复制命令 |
| T8 发布预检 | dist、zip、SHA、版本、依赖、策略状态 | confirm | 无 | dist 缺失提示先 build |
| T9 发版 | 上传 zip + createVersion | 等待 | 写存储、平台、state | 远端成功本地失败进入 recovery |
| T10 下一步 | 策略模板/上架/结束 | 选择 | 仅确认后继续写 | 策略进入 [S14](./S14-策略模板选择与应用.md)，不让普通用户手写 policyText |

## 5. AI/CI 目标等价命令

```bash
freelog-cli init theme ./my-theme --template vite-vue-ts --runtime 0.5 --env <env>
cd ./my-theme
pnpm install && pnpm build
freelog-cli create --yes --env <env>
freelog-cli publish --bump patch --yes --env <env>
freelog-cli policy apply --template <templateId-for-永久免费> --name "永久免费" --yes --env <env>
freelog-cli online --yes --env <env>
```

非 TTY 缺 `--env`、`--yes`、模板、类型或 runtime 时必须失败并给 hint，不进入 prompt。

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 用户已有工程但无 manifest | 允许 scaffold none 接入，或确认复制模板；默认不覆盖用户文件 |
| dist 不存在 | 停在本地阶段，提示 build 命令 |
| zip 超大小 | 展示 zip 大小、类型限制和 ignore 建议 |
| 平台已有同 name | 如果同 owner/type/title 精确匹配，可恢复绑定；否则提示换 name |
| version 已存在 | 同版本同完整发布意图可恢复；不同意图必须 bump |
| 依赖需付费 | code 5，给 Console 链接和重跑命令 |

## 7. 回归到总设计

主题场景要求总设计具备：

- root/start 第一屏有「主题」入口；
- 类型选择支持“固定大类入口 + 平台类型树 leaf 定稿”；
- publish preflight 能展示 directory zip；
- 成功续接能继续到策略模板/online；
- 文案必须区分“主题资源类型”和“runtime 技术模板”。
