# S04 · 普通单文件资源发布

> **文档角色：** 图片、视频、音频、文档等单文件资源从本地文件到发布上线的历史场景材料。当前主线方案见 [../产品方案/README.md](../产品方案/README.md)；交互拓扑补充见 [../02-CLI体验拓扑设计.md](../02-CLI体验拓扑设计.md)。

最后更新：2026-08-28

---

## 1. 用户目标

用户手上有一个本地文件，想把它发布成 Freelog 独立资源，并完成策略与上架。用户通常不知道平台类型 code，也不知道文件大小、格式、属性解析这些规则。

---

## 2. 资源类型设计

普通文件是最需要“旧式逐级选择”的场景。

```text
选择其余资源
  → 展示一级资源类型
  → 进入子级
  → 直到 leaf
  → 展示完整路径、code、文件限制
  → 确认
```

搜索只作为快捷入口：

- 用户可以在任一级搜索“图片/视频/mp4”等关键词；
- 搜索结果必须只显示 leaf；
- 每条结果展示完整路径，不只显示一个名字；
- 多结果必须确认，不自动选择第一个。

---

## 3. Console 对齐点

| Console 业务 | CLI 必须对齐的结果 |
|---|---|
| creator Step1 类型 | 必选，有效 leaf |
| creator Step1 标题/name | 标题 ≤100；name 1–60、规范化并查重 |
| creator Step2 文件 | 类型决定能否本地上传、格式、MIME、大小 |
| 文件 SHA1 | 已发行重复文件阻止或进入明确恢复 |
| 属性解析 | inputAttrs/customPropertyDescriptors 与 Console createVersion 同构 |
| 策略/上架 | 策略新增先走 Console 同源模板 Builder；online 严格门禁 |

---

## 4. TTY 连续向导

| checkpoint | 用户看到 | 输入 | 副作用 | 失败处理 |
|---|---|---|---|---|
| F1 选择任务 | “发布一个本地文件” | 普通文件 | 无 | 返回主菜单 |
| F2 选择文件 | 当前目录候选或输入路径 | 文件路径 | 无 | 文件不存在则重新选 |
| F3 选择类型 | 一级级类型树 | leaf 类型 | 无 | 父节点继续下钻 |
| F4 能力确认 | 格式/MIME/大小/是否可上传 | 确认 | 无 | 不支持本地上传则提示 Console 路径 |
| F5 填资源字段 | title/name/version/description | 文本 | 写 manifest | 显示规范化 name |
| F6 预检 | 文件、大小、SHA、属性解析计划、依赖状态 | confirm | 无 | 失败停在对应字段 |
| F7 发布 | upload/createVersion | 等待 | 写存储/平台/state | 远端结果未知则停损 |
| F8 续接 | 策略模板/online/加入合集/退出 | 选择 | 确认后写平台 | 策略进入 [S14](./S14-策略模板选择与应用.md)，文件入口仅给专家/CI |

## 5. AI/CI 目标等价命令

```bash
freelog-cli init ./photo-resource --scaffold none --resource-type <leaf-code> --artifact-mode file --env <env>
cd ./photo-resource
freelog-cli create --yes --env <env>
freelog-cli version set --file ./photo.png --version 1.0.0 --env <env>
freelog-cli publish --yes --env <env>
freelog-cli policy apply --template <templateId-for-永久免费> --name "永久免费" --yes --env <env>
freelog-cli online --yes --env <env>
```

## 6. 常见情况处理

| 情况 | 处理 |
|---|---|
| 用户选了父类型 | 不提交；进入子级或说明“该类型下还有子类型” |
| 文件格式不支持 | 展示实际后缀/MIME 与允许列表 |
| 视频超 1GB | 明确提示视频硬上限 |
| 同 SHA 已发版 | 若同版本完整意图一致则恢复；否则提示换文件或 bump |
| 属性解析失败 | 说明是文件属性解析阶段，不把错误伪装成上传失败 |
| 用户取消 publish | 不写平台，输出可复制的下一步命令 |

---

## 7. 回归到总设计

普通文件场景要求：

- 逐级类型选择是默认路径；
- 文件能力摘要必须在用户确认前展示；
- publish preflight 不能只写“将上传文件”，必须展示限制和 SHA；
- 属性解析结果要被用户理解为平台字段，而不是黑盒。
