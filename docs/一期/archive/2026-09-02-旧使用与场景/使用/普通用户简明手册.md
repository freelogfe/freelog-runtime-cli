# 普通用户简明手册：我该用哪个流程？

[返回使用文档目录](./README.md)

如果你不想理解所有命令，先看这一页。CLI 的核心选择只有两个问题：

1. 你的本地内容是“一个资源”、 “很多独立资源”，还是“需要共同展示的一组资源”？
2. 你是要长期维护，还是只想临时完成一次操作？

## 按本地内容选择

| 你的本地内容 | 推荐入口 | 平台结果 |
|---|---|---|
| 第一次不确定怎么走 | `freelog-cli start` | CLI 根据当前目录推荐下一步 |
| 一个主题或插件项目 | `init` 后构建并 `publish` | 一个资源，版本文件为构建目录压缩包 |
| 一张图片、一个视频或一个普通文件 | `init --scaffold none` | 一个独立资源 |
| 一个文件夹，文件之间彼此独立 | `resource import-dir` | 每个文件一个独立资源 |
| 一个文件夹，文件需要按顺序共同展示 | `collection init-from-folder` | 多个子资源和一个合集 |
| 已在 Console 创建的资源 | `init` 后 `bind` | 本地工程绑定已有平台资源 |
| 只想临时维护线上资源 | `session` 或单命令 `--session` | 默认不写本地工程 |
| 一个文件夹里要切换多个账号 | `studio` | 每个成功资源保存独立子工程 |

### 主题或插件项目

CLI 不替代项目自己的构建工具。先运行项目的构建命令，再把构建目录作为 `directory-zip` 发行物。模板创建和已有项目接入都见[发行单个资源](./发行单个资源.md)。

### 单个图片、视频或文件

使用 `artifact-mode file`，CLI 上传原文件，不压缩、不转码。完整示例见[快速上手](./快速上手.md)。

### 多个独立资源

如果每个文件需要独立标题、版本、策略和上下架状态，使用 `resource import-dir`。批量执行不会把文件组织成合集，详见[批量发行](./批量发行.md)。

### 文件夹合集

如果这些文件需要按目录顺序共同展示，使用合集流程。CLI 会先为每个文件创建子资源，再把子资源加入合集目录，详见[合集](./合集.md)。

### 已有平台资源

不要再次执行 `create`。先初始化本地 manifest，再使用 `bind <resourceId>` 或授权名绑定，详见[高级流程](./特殊流程.md)。

## 什么时候需要 Console

CLI 可以完成本地文件型资源的主要生命周期，但以下能力需要浏览器界面：

- 从 Freelog 云存储中选择已有文件
- 使用 Markdown、Cartoon 等网页编辑器制作内容
- 完成付费策略的支付或复杂授权确认
- 解冻资源
- 查看资源详情、收入、收藏和其他运营数据

CLI 遇到需要浏览器处理的授权时，会在输出或 `--json` 的 `details` 中给出当前环境对应的 Console 链接和建议的重试命令。

## 按维护方式选择

| 你想要 | 推荐方式 | 原因 |
|---|---|---|
| 长期维护同一个资源 | 本地工程模式 | `freelog.manifest.json` 保存发行意图，`.freelog/state.json` 记录平台事实 |
| 让 AI 或 CI 执行 | 本地工程模式 + 显式命令 + `--json` | 可复盘、可重试、可审计 |
| 临时改一个线上资源 | 单命令 `--session --resource-id` | 不写 manifest/state |
| 连续临时维护多个步骤 | `freelog-cli session` | 一次会话里完成搜索、策略、版本、上下架 |
| 多账号处理一批本地文件 | `freelog-cli studio` | 凭据只在进程内，成功项落成子工程 |

## 所有发行路径共有的规则

1. 写操作前确认环境和当前登录账号。
2. 创建平台资源后才能发行版本；绑定已有资源时不再创建。
3. 发行版本可以早于添加策略，但上架必须已有正式版本和启用策略。
4. 声明依赖或上抛资源时，发行前必须完成授权。
5. 本地与平台同时修改时先 `pull` 或 `diff`，不要静默覆盖。
6. 平台写入成功后，即使本地落盘失败，也不能直接重复创建；应先根据报告或 Console 对账。
