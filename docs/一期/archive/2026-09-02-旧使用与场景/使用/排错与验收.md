# 故障排查

[返回使用文档目录](./README.md)

排查前先确认版本、环境、登录账号和工程状态：

```bash
freelog-cli --version
freelog-cli status --env <env>
freelog-cli diff --env <env>
freelog-cli validate --for publish --env <env>
```

自动化场景加 `--json`，优先读取 `code`、`message`、`hint` 和 `details`，不要只匹配终端文案。

## 安装和登录

| 现象 | 原因 | 处理 |
|---|---|---|
| 找不到 `freelog-cli` | npm 全局可执行目录不在 `PATH` | 重新打开终端，检查 `npm prefix --global` 和全局安装结果 |
| CLI 版本不是 `0.5.x` | 安装了旧版本或其他发布通道 | 重新安装与本文匹配的版本并确认 `freelog-cli --version` |
| 未登录，退出码 `2` | 当前目录和全局都没有有效凭据 | 在工程目录执行 `login --env <目标环境>` |
| 凭据无法解密 | `auth.key` 丢失或 `FREELOG_CRYPTO_KEY` 变化 | 重新登录；旧密钥无法恢复时旧凭据不能继续使用 |
| 使用了错误账号 | 祖先目录中存在工作区凭据 | 用 `status` 查看来源，在当前子目录重新登录覆盖 |
| owner 不匹配 | 当前账号不是资源 owner | 切换到正确账号，或绑定当前账号拥有的资源 |
| 登录环境不一致 | 凭据环境与命令环境不同 | 在目标环境重新登录，不复用另一环境凭据 |

## 创建、发行和版本

| 现象 | 原因 | 处理 |
|---|---|---|
| `create` 提示已绑定 | 本地工程已有 resourceId | 维护已有资源，不要重复创建；需要替换绑定时核对后用 `bind --force` |
| Console 已有资源但本地没有 | 不能再次创建同一资源 | `init` 后使用 `bind <resourceId>` |
| `publish` 找不到文件 | manifest 文件意图为空或路径失效 | 重新执行 `version set --file <path>` |
| 文件格式或大小不符 | 资源类型限制不接受该文件 | `type info <typeCode>` 查看限制并准备正确文件 |
| 版本冲突 | 版本已存在或不高于最新版本 | 设置更高 semver，或使用 `publish --bump` |
| 同一文件已发行 | 文件 SHA1 与已有版本重复 | 换文件；只升版时使用 `--reuse-version` |
| `--reuse-version` 与本地文件冲突 | 两种文件来源互斥 | 删除本地文件意图，或不使用复用参数 |
| 资源被冻结 | 平台禁止发行和上架 | 到 Console 解冻后重试 |
| listing 漂移，退出码 `3` | Console 和本地都有变化 | `diff` 后选择 `pull`、`pull --apply-listing` 或保留本地并更新 |

## 策略、授权和上下架

| 现象 | 原因 | 处理 |
|---|---|---|
| `online` 失败 | 没有正式版本或启用策略 | 先 `publish`，再 `policy apply` 或启用策略 |
| 授权失败，退出码 `5` | 依赖或上抛资源未签约 | 使用 `dep auth`，或打开 `details` 中的 Console 链接 |
| 不能停用策略 | 当前是已上架资源的最后一条启用策略 | 先启用另一策略或先下架 |
| 想修改已有策略正文 | CLI 只支持添加策略和启停 | 添加新策略并切换状态，或在 Console 处理 |
| 下架后版本消失 | 这是状态判断误解 | `offline` 不删除版本；执行 `status` 或到 Console 核对 |

## 草稿和合集

| 现象 | 原因 | 处理 |
|---|---|---|
| `draft push` 冲突 | Console 或其他人修改了远端草稿 | 先 `draft pull` 合并；确认覆盖时再用 `--force --yes` |
| 合集壳误用 `publish` | 合集使用不同发布命令 | 使用 `collection publish` |
| 合集导入失败 | 子资源无版本、启用策略或上架状态 | 先完成子资源发行和策略，或导入时使用 `--item-policy-file` |
| 加目录项时授权失败 | 子资源的上抛资源未在合集下授权 | 完成合集侧授权后重试 |
| RSS 合集普通更新被拒 | 内容由 feed 托管 | 使用 `collection rss` 专用命令 |
| 自动收录规则为空 | `filterConditions` 缺失 | 使用 `--from-file` 提供至少一条完整条件 |

## 批量和临时模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 批量部分失败 | 成功项不会回滚 | 使用报告执行 `--retry`，不要重跑整个目录 |
| 批量进程中断 | 报告保留了最后安全阶段 | 使用 `--resume <report>` |
| 报告显示远端结果未知 | 无法确定平台是否成功 | 先到 Console 对账，禁止自动继续 |
| `REMOTE_WRITE_PARTIAL` | 一个命令包含的多个幂等平台阶段只有部分确认成功 | 保留原参数直接重试；CLI 会先对账已经完成的阶段，不要手工反向修改已完成字段 |
| `REMOTE_OUTCOME_UNKNOWN` | 平台请求和随后读取均失败，CLI 无法判断是否已应用 | 保留现场和原参数；恢复网络后同参数重试，让 CLI 先读取平台。非幂等创建若仍无法核对，按提示进入 Console 人工确认 |
| `PUBLISHED_VERSION_CONFLICT` | 同一版本号已存在，但文件、说明、封面、依赖、授权或属性等任一不可变发布字段与本地意图不同 | 设置更高版本号；已发布版本不可覆盖。只有完整发布意图一致时才按断线重试补写本地事实 |
| 文件夹中的子目录未处理 | 批量命令只扫描顶层文件 | 调整目录结构或分目录执行 |
| `session` / `studio` 非 TTY | 交互壳要求真实终端 | 脚本使用普通工程命令或单命令 `--session` |
| session 切换账号后失败 | 仍选择了旧账号资源 | 重新选择当前账号拥有的资源 |
| Studio 子工程 owner 不符 | 当前临时账号不是创建者 | 在 Studio 中切换到正确账号 |

## 环境和自动化

| 现象 | 原因 | 处理 |
|---|---|---|
| 非交互写命令要求环境 | 脚本没有明确目标环境 | 传 `--env`、设置 `FREELOG_ENV` 或配置 `defaultEnv` |
| state 环境不一致 | 当前工程绑定了另一个环境 | 使用原环境，或在独立目录重新绑定目标环境资源 |
| `validate` 退出码 `4` | 项目或业务门禁未通过 | 按 `hint` 修复后重跑，不要跳过关键检查 |
| `diff` 退出码 `3` | 本地与平台有差异 | 明确采用本地还是平台值后再继续 |
| JSON 日志无法解析 | 命令没有加 `--json` 或混入人类输出 | 对单命令使用 `--json`；批量进度使用 `--json-lines` |

仍无法定位时，可在不泄露凭据的前提下提供 CLI 版本、操作系统、完整命令、退出码和已脱敏的 `--json --debug` 输出给技术支持。
