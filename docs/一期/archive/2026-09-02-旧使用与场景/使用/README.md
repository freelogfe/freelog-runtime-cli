# Freelog CLI 使用文档

Freelog CLI 的目标，是让你或 AI 在本地电脑上快速管理 Freelog 资源：选择本地文件或构建目录，创建资源，发行版本，选择策略模板，上架，后续再更新版本或维护线上状态。

你可以把它当成两种工具：

- **交互向导：** `freelog-cli start`，适合人第一次操作，一条命令进入连续流程。
- **显式命令：** `init/create/version/publish/policy/online` 等，适合脚本、CI、AI 代执行和可复盘操作。

必须依赖支付、签约、可视化编辑器或云存储选择器的操作，CLI 会给出 Console 接力提示。

本文档适用于 Freelog CLI `0.5.x`。命令参数以当前安装版本的 `freelog-cli <命令> --help` 为准。

当前公司小范围试用统一使用 `@freelog-cli/cli2`。请按本目录的安装命令操作；旧包
`@freelog-cli/cli` 不在本文档的支持范围内。

## 先读哪几篇

如果你是第一次用，不要从全部文档开始读。按这个顺序即可：

1. [安装与升级](./安装与升级.md)：安装 Node.js 和 Freelog CLI，确认版本。
2. [快速上手](./快速上手.md)：用 `start` 或显式命令发行一张图片并上架。
3. [普通用户简明手册](./普通用户简明手册.md)：判断自己该走单资源、批量、合集、session 还是 studio。
4. 需要长期维护或脚本化时，再读 [登录与环境](./全局参数与登录.md)。

## 先选工作方式

| 工作方式 | 入口 | 适合 | 本地会留下什么 |
|---|---|---|---|
| 交互向导 | `freelog-cli start` | 第一次操作、人工手动测试、想一条命令进入连续流程 | 取决于你选择 session 还是工程路径 |
| 本地工程 | `init` → `create` → `version` → `publish` | 长期维护、团队协作、CI、主题/插件/package 项目 | `freelog.manifest.json`、`.freelog/state.json` |
| 临时会话 | `freelog-cli session` 或单命令 `--session` | 不想写 manifest/state，只临时维护线上资源 | 默认不落盘，可选择导出工程 |
| 多账号工作区 | `freelog-cli studio` | 一个文件夹里用多个账号发行多个资源 | 每个成功资源的子工程和恢复报告 |
| 自动化脚本 | 显式命令 + `--json` / `--json-lines` | AI/CI 执行、批量、可审计流水线 | 由脚本控制 |

## 核心流程

```text
选择工作方式
  -> 选择环境并登录
  -> 选择资源类型和本地文件
  -> 创建本地工程或进入临时会话
  -> 创建平台资源或绑定已有资源
  -> 发行正式版本
  -> 从 Console 同源策略模板选择并应用策略
  -> 上架
  -> 后续更新 listing、草稿、版本、策略、依赖或上下架状态
```

## 使用前记住这几条

- `publish`、`online`、`offline`、`update`、策略和合集写命令会修改平台数据。执行前检查命令中的环境与资源。
- `freelog.manifest.json` 保存可提交的发行意图；`.freelog/state.json` 和 `.freelog-auth` 不应提交到版本库。
- 首次发行和新版本发行不会因为后续步骤失败而自动回滚。批量流程会保留成功项和恢复报告。
- 上架前必须已有正式版本，并至少有一条启用策略。
- 付费签约、资源解冻、网页编辑器和云存储选择需要进入当前环境对应的 Freelog Console 完成。
