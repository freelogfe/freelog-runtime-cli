# 01 · 产品设计与实现解决方案

> **文档角色：** 一期资源发行 CLI 的完整解决方案。本文从需求分析、Console 业务流程和 CLI 环境差异推导产品设计，并给出可实现的流程、字段、接口、异常和实现分层。

最后更新：2026-09-02

## 0. 方案结论

Freelog CLI 一期要做的是一个“本地资源发行工作台”，不是一组零散 API 命令。

用户在终端里输入一次主命令后，应该能被连续引导完成资源发行或维护；AI/CI 则用同一套业务规则，通过 manifest、flags、JSON/NDJSON 和 exit code 完成相同流程。

核心结论：

1. **Console 业务必须写进本方案。** 资源创建、版本、策略、listing、上下架、合集、RSS、collect-rules 的字段和接口是 CLI 的产品依据。
2. **CLI 体验不能照搬 Console 页面。** Console 用页面和 disabled 按钮约束用户；CLI 要用逐级选择、字段提示、预检 checkpoint、报告恢复和 Console 接力约束用户。
3. **TTY 主路径是一条连续会话。** 用户不应先记住十几条命令；主命令负责一步步问清楚，显式命令负责熟练用户和 AI/CI。
4. **搜索不是唯一选择方式。** 资源类型、策略模板、依赖授权树都必须先能浏览和逐级选择，搜索只是加速。
5. **归档不是当前依据。** 旧文档只读追溯；当前实现只以本文和 `DESIGN.md` 为产品依据。

## 1. 需求分析

### 1.1 用户目标

| 用户 | 目标 | CLI 价值 |
|---|---|---|
| 主题开发者 | 从模板创建主题，构建并发布到 Freelog | 模板、构建、目录压缩、类型能力和版本发布串成一条路 |
| 插件开发者 | 创建插件工程并发行插件资源 | 同主题，但类型和模板不同，不能被普通目录发布替代 |
| 前端库/软件库开发者 | 发布可被其它资源依赖的包 | 类型必须选到平台叶子类型，依赖/授权要可维护 |
| 普通作者 | 把本地图片、音频、视频、文档、目录发布成资源 | 不需要理解 Console 页面和平台字段，终端一步步引导 |
| 合集维护者 | 创建合集、导入条目、维护排序和目录草稿 | 区分合集和批量独立资源，处理 100 项分批 |
| RSS 维护者 | 绑定 RSS，处理验证码、条目差异和同步限制 | 对齐 Console 的 RSS 限制和错误语义 |
| 运营/维护者 | 管理已有线上资源的 listing、策略、依赖、上下架 | 不一定需要本地工程，可用 session/studio |
| AI/CI | 自动执行发布、更新、批量、预检 | 需要可脚本化、可解析、可恢复的契约 |

### 1.2 非目标

- 不做 Console 的节点运营、结算、收藏、可视化详情预览。
- 不在 CLI 内完成支付、签约、收银台、浏览器验证码和第三方授权；这些通过 Console 接力。
- 不复制 Console 页面数量，也不要求用户按 Console 页面顺序敲多条命令。
- 不为了兼容旧代码保留不合理命令、字段或文档结构。

## 2. Console 资源域业务流程

本节直接写入当前产品方案。读者不需要去 `archive` 拼 Console 业务。

当前 Console 资源域源码入口包括：

- `D:/appinside/freelogfe-web-repos/packages/console/src/pages/resource/creator`
- `D:/appinside/freelogfe-web-repos/packages/console/src/pages/resource/versionCreator`
- `D:/appinside/freelogfe-web-repos/packages/console/src/pages/resource/creatorBatch`
- `D:/appinside/freelogfe-web-repos/packages/console/src/pages/resource/collectionCreator`
- `D:/appinside/freelogfe-web-repos/packages/console/src/pages/resource/collectionSidebar`
- `D:/appinside/freelogfe-web-repos/packages/console/src/pages/resource/sidebar`
- `D:/appinside/freelogfe-web-repos/packages/console/src/components/FPodcastRssSubmit`

### 2.1 Console 总业务链

```text
资源入口
  → 选择资源类型
  → 填资源基础信息
  → 创建资源
  → 上传/选择/编辑版本内容
  → 填版本属性、依赖、授权排除
  → 选择策略模板并编译策略
  → 填 listing：封面、简介、标签
  → 上架或保持草稿
  → 后续在 sidebar/list/detail 中维护
```

Console 的约束来自三个地方：

1. **表单组件：** 输入框、标签组件、封面组件、资源类型选择器、策略模板组件。
2. **页面状态：** step 未完成时按钮 disabled，资源/版本/策略缺失时不能进入下一步。
3. **平台接口：** 创建、更新、绑定 RSS、合集更新、策略编译等接口返回业务错误。

CLI 需要把这些隐性 UI 约束变成显性终端约束。

### 2.2 创建单资源

Console 单资源创建可以抽象成四步：

```text
Step 1：选择资源类型 + 填资源标题/名称
Step 2：选择版本内容 + 填版本号/描述/属性/依赖
Step 3：选择策略模板 + 编译/翻译策略
Step 4：填 listing 封面/简介/标签 + 上架入口
```

CLI 对齐点：

| Console 行为 | CLI 设计 |
|---|---|
| 类型选择器只允许合法类型 | CLI 先展示一级分类，再逐级进入子类，最终只能选择叶子类型 |
| Step 1 缺类型或标题不能下一步 | TTY 输入前展示限制；非交互缺字段 code 4 |
| Step 2 根据类型能力展示 localUpload / storageSpace / editor | CLI 只支持本地文件/目录和构建产物；storage/editor 走 Console 接力 |
| Step 3 展示策略模板组件 | CLI 先 `policy template list`，再选择模板并填参数 |
| Step 4 编辑封面、简介、标签 | CLI 在 listing 阶段统一维护，RSS 锁定字段除外 |

关键接口：

- `Resource.create`
- `Resource.createVersion`
- `Resource.updateResourceVersionInfo`
- `Resource.update`
- `Policy.policyTemplates`
- `Policy.policyReCompile`
- `Policy.policyTranslation`

### 2.3 更新已有资源和版本

Console 的 `versionCreator/$id` 基于已有资源创建新版本，不是任意修改旧版本文件。

CLI 对齐点：

- 已发布版本的文件身份不可原地修改；要发布新文件就创建新版本。
- 新版本可以继承 latestVersion 中可继承字段，但 CLI 必须展示继承来源。
- 资源 owner、env、resourceId 不匹配时必须停止。
- 本地 manifest 与远端同时变化时不能自动覆盖。

关键接口：

- `Resource.info`
- `Resource.createVersion`
- `Resource.updateResourceVersionInfo`
- `Resource.update`

### 2.4 sidebar 维护：基础信息、策略、上下架

Console sidebar/list/detail 负责资源维护：

```text
查看资源
  → 编辑基础展示信息
  → 编辑策略
  → 上架/下架
  → 查看版本、依赖、授权等状态
```

CLI 对齐点：

- listing 维护集中在 `cover / intro / tags`。
- 上架/下架必须在写入前显示目标资源、版本、环境、账号和可能的付费/签约前置条件。
- 支付、签约、收银台等不能在 CLI 内完成时，给 Console 跳转和回到 CLI 的下一步。

### 2.5 合集创建与维护

Console 合集创建与普通资源类似，但增加目录/条目管理：

```text
创建合集资源
  → 添加已有资源或创建子资源
  → 管理条目顺序和展示
  → 保存目录草稿
  → 可选 merge catalogue draft
  → 配置策略和 listing
```

CLI 对齐点：

- 合集不是“把目录压成一个文件”；合集条目是可管理资源引用。
- 本地目录导入合集时，先扫描并确认，再创建子资源/添加条目。
- Console 单次选择/提交上限按 100 项处理；CLI 超过 100 时分批，不预设未知总容量。
- `isMergeCatalogueDraft` 必须让用户明确选择，不能静默合并。

关键接口：

- `Resource.updateCollection`
- 资源创建/版本接口用于本地目录生成子资源时复用。

### 2.6 RSS 绑定与同步

Console RSS 组件处理 feed 检查、验证码、条目差异和大数量限制。

源码中可见的关键行为：

- `FPodcastRssSubmit/bindRssFeedError.ts` 识别 `VerificationCodeInvalid` 和 `wrong_verified_code`。
- `FPodcastRssSubmit/Flow/index.tsx` 使用 `matchedItemCount` 判断数量限制。
- RSS GUID 不匹配数量使用 `max(oldFeedItemCount, newFeedItemCount) - guidMatchedCount`。
- RSS 预览包含 feed title、cover、author、episode count 等信息。

CLI 对齐点：

```text
输入 feedUrl
  → 平台检查 feed
  → 如需验证码，只重试验证码
  → 展示 feed 信息和条目差异
  → matchedItemCount > 1000 时阻止继续
  → 绑定或同步 RSS
  → title/cover/intro 由 feed 锁定
  → tags 仍允许手动维护
```

关键接口：

- `Resource.bindRssFeed`
- `Resource.info`
- `Resource.batchResourceItems`
- `Resource.updateCollection`

### 2.7 collect-rules 自动收录

如果 Console 已支持 collect-rules，CLI 也要作为合集维护能力支持。

CLI 对齐点：

- 先查看当前规则。
- 再选择规则类型或模板。
- 再填写规则参数。
- 保存前说明影响的是“后续自动收录”还是“立即同步”。
- 规则枚举和参数优先来自平台，不在 CLI 内散落硬编码。

关键接口：

- `Resource.setCollectRules`

### 2.8 批量创建

Console 有 `creatorBatch` 批量创建入口。

CLI 对齐点：

- 批量独立资源与合集不同：批量是 N 个独立资源，合集是一个合集资源加 N 个条目。
- CLI 扫描本地目录后必须展示将处理、跳过、失败的项。
- 每一项独立记录结果，支持 resume/retry。
- `Resource.createBatch` 只有在调用前确认不可用时才允许降级逐项创建；调用已发出后的异常必须按未知结果处理。

关键接口：

- `Resource.createBatch`

## 3. CLI 环境差异分析

Console 和 CLI 的核心差异如下：

| 差异 | Console 怎么解决 | CLI 必须怎么设计 |
|---|---|---|
| 字段限制 | 表单组件、disabled、toast | 输入前提示约束；同一校验器用于 prompt、manifest、写入前 |
| 类型选择 | 可视化树/选择器 | 默认逐级选择，搜索只是加速 |
| 策略选择 | 模板卡片/表单 | 先列模板，再选模板，再填参数，再预览 |
| 文件来源 | 上传组件、云存储、编辑器 | 本地文件、目录、构建产物、压缩；其它入口 Console 接力 |
| 长任务 | 页面状态 | 阶段日志、报告文件、resume/retry |
| 多账号 | 浏览器登录态 | 工作区凭据、全局凭据、session/studio、owner 门禁 |
| 自动化 | 不主要面向 CI | JSON/NDJSON、exit code、无交互失败 |
| 失败恢复 | 用户在页面重试 | 明确平台是否可能已写、本地是否待回写 |

## 4. CLI 产品信息架构

```text
身份与环境
  login / logout / status / config / doctor

开始任务
  start       # 新手连续向导
  studio      # 多账号工作区，一次进程内可连续做多件事
  session     # 全临时会话，不留下长期工程状态

本地工程
  init / bind / validate / diff / pull

资源发行
  publish / update / version / draft

策略、依赖、上下架
  policy / dep / online / offline

合集与 RSS
  collection / rss / collect-rules

批量与恢复
  batch / import-dir / report / resume / retry
```

命令名可以演进，但信息架构不能乱：用户任务先于技术模块。

## 5. CLI 主流程设计

### 5.1 TTY 连续会话总流程

```text
freelog-cli start 或 studio
  → 选择任务
  → 确认环境和账号
  → 选择资源类型或已有资源
  → 选择本地文件/目录/模板/线上对象
  → 补全字段
  → 策略模板选择与应用
  → 依赖/授权选择
  → 预检 checkpoint
  → 执行平台写入
  → 写本地 state/report
  → 下一步：上架 / 打开 Console / 继续维护 / 导出工程
```

每一步都必须支持：

- 查看当前步骤说明。
- 返回上一步。
- 取消并说明是否已有副作用。
- 查看字段限制。
- 写平台前最终确认。

### 5.2 非交互 / AI / CI 流程

```text
manifest + flags
  → validate
  → dry-run 可选
  → publish/update/batch --yes --json 或 --json-lines
  → stdout 输出协议
  → stderr 输出日志
  → exit code 表示结果类型
```

非交互模式不提问。缺字段、需确认、需 Console 接力时必须失败并输出结构化错误。

### 5.3 session / studio

| 模式 | 凭据 | 资源状态 | 适用 |
|---|---|---|---|
| 普通工程 | 落盘加密 | manifest/state | Git、CI、长期维护 |
| 命令会话 `--session` | 可读落盘凭据 | 临时 Store | 一次性维护已有资源 |
| `studio` | 进程内凭据 | 多工程 state | 多账号、多资源、人工连续操作 |
| `session` | 进程内凭据 | 全临时 Store | 不想留下本地工程 |

规则：

- session 不降低任何 Console/平台门禁。
- 凭据不得进入 manifest/state/report。
- studio 切换账号时必须显示当前账号和 owner 风险。
- 会话成功后可 `--export-project` 转成长期工程。

## 6. 资源类型选择设计

资源类型选择必须先支持逐级浏览：

```text
选择一级分类
  → 选择二级/三级分类
  → 直到叶子类型
  → 展示类型能力：文件/目录、上传限制、是否支持编辑/下载/可选配置
  → 确认
```

搜索规则：

- 搜索入口在每一级都可用。
- 搜索结果必须展示完整路径，例如 `主题 / Web主题 / ...`。
- 搜索结果只能选择叶子类型。
- 前端库/软件库如果有多个叶子候选，非交互必须显式指定；TTY 让用户选择。
- 主题、插件、前端库/软件库、合集这些关键类型不能藏在搜索里。

接口：

- `Resource.resourceTypes`
- `Resource.ListSimpleByParentCode`
- `Resource.getResourceTypeInfoByCode`

## 7. 单资源发行流程

```text
选择“发布新资源”
  → 选资源类型
  → 选择模板/已有目录/单文件
  → 填资源基础字段
  → 设置版本字段
  → 选择策略模板
  → 可选依赖和授权排除
  → listing
  → checkpoint
  → create resource
  → upload artifact
  → create version
  → update listing
  → optional online
  → write state/report
```

主要字段：

| 字段 | 来源 | CLI 规则 |
|---|---|---|
| `resourceTypeCode` | 平台类型树 | 必须叶子类型 |
| `resourceTitle/title` | Console Step 1 | 必填，长度按 Console 限制 |
| `resourceName/name` | Console Step 1 / 平台授权名 | 必填，校验格式和重复 |
| `version` | Console Step 2 | 必填，不能与已发布版本冲突 |
| `file` / `directory` | CLI 本地能力 | 文件存在；目录按 ignore 压缩 |
| `intro` | Console listing | 长度按 Console 限制 |
| `cover` | Console listing | URL 或本地文件上传结果 |
| `tags` | Console listing | 数量和单标签长度按 Console 限制 |
| `policyTemplateId` | Console Step 3 | 必须来自模板列表 |

## 8. 更新、策略、依赖和上下架流程

### 8.1 更新版本

```text
选择已有资源或读取 state
  → 拉远端事实
  → 校验 env/owner/resourceId
  → 填新版本号和文件
  → 可继承 latestVersion 字段
  → checkpoint
  → upload
  → createVersion
  → updateResourceVersionInfo
  → 写 state
```

### 8.2 策略

策略主路径必须是：

```text
policy template list
  → 用户选择模板
  → 填模板参数
  → reCompile / translation 预览
  → apply
```

不允许把“用户手写策略结构”作为普通主路径。

### 8.3 依赖和授权排除

```text
选择依赖资源
  → 拉授权树
  → 展示可选授权和冲突
  → 用户选择授权或排除项
  → 写入下一个版本意图
```

依赖影响版本，不应偷偷修改已发布版本。

### 8.4 上架/下架

```text
读取资源状态
  → 检查版本、策略、签约/支付等前置条件
  → checkpoint
  → online/offline
```

需要支付或签约时，CLI 输出 Console 跳转链接，不伪装成 CLI 可完成。

## 9. 合集、RSS 和 collect-rules 流程

### 9.1 合集

```text
创建或绑定合集
  → 添加已有资源或从本地目录创建条目资源
  → 条目排序/展示预览
  → 分批保存目录草稿
  → 用户确认是否 merge catalogue draft
  → listing / policy / online
```

约束：

- 100 是 Console 单次选择/提交上限，CLI 超过时分批。
- 合集条目必须可 diff 和预览。
- 批量独立资源和合集导入必须在入口上讲清区别。

### 9.2 RSS

```text
输入 feedUrl
  → compare/check
  → 需要验证码则进入验证码步骤
  → 展示 feed title/cover/author/episode
  → 展示 guid 差异和 matchedItemCount
  → 数量合法后 bind/sync
  → 更新本地同步状态
```

约束：

- `matchedItemCount > 1000` 阻止继续。
- GUID 不匹配数量按 `max(oldFeedItemCount, newFeedItemCount) - guidMatchedCount`。
- 时间范围传 `YYYY-MM-DD HH:mm:ss`；只有日期时补 `00:00:00` / `23:59:59`。
- `VerificationCodeInvalid` / `wrong_verified_code` 只重试验证码。
- RSS 绑定后 title/cover/intro 锁定为 feed 信息，tags 仍可维护。

### 9.3 collect-rules

```text
选择合集
  → 查看当前规则
  → 选择 conditionType 或规则模板
  → 填参数
  → 预览影响
  → setCollectRules
```

必须区分“保存自动收录规则”和“立即同步条目”。

## 10. 批量流程

```text
选择目录
  → 扫描并应用 ignore
  → 选择资源类型和命名规则
  → 展示 plan：create / skip / fail
  → checkpoint
  → 分批创建
  → 每项写 report
  → done / resume / retry
```

批量报告必须记录：

- runId、schemaVersion、env、actor、输入目录 fingerprint。
- 每项相对路径、SHA1、资源类型、幂等键。
- 阶段、结果、resourceId/versionId。
- `remote_outcome_unknown`、`remote_succeeded_local_pending` 等恢复状态。

## 11. 字段约束总表

| 字段 | 约束类型 | 规则 |
|---|---|---|
| `env` | HARD | production/prod 未开放时写入前失败 |
| `resourceTypeCode` | HARD | 平台类型树叶子类型 |
| `artifactMode` | HARD | `file` 或 `directory-zip`，不能按展示名猜 |
| `resourceTitle/title` | HARD | 必填，按 Console 长度限制 |
| `resourceName/name` | HARD | 必填，按平台格式和重复校验 |
| `version` | HARD | 合法版本号，不能重复发布 |
| `file` | HARD | 存在、可读、类型/大小符合能力 |
| `directory` | HARD | 可扫描、可压缩、强制排除凭据/state |
| `intro` | HARD | 按 Console 简介限制 |
| `cover` | HARD/SOFT | 格式、上传、默认图按平台能力 |
| `tags` | HARD | 数量和单标签长度限制；RSS 场景仍可编辑 |
| `policyTemplateId` | HARD | 来自平台模板列表 |
| `policyName` | HARD | 按 Console 策略名限制 |
| `dependencies` | HARD | 来自平台资源和授权树 |
| `feedUrl` | HARD | 可访问 RSS 地址 |
| `verificationCode` | CONDITIONAL | 平台要求时输入 |
| `conditionType` | HARD | collect-rules 支持枚举 |
| `isMergeCatalogueDraft` | HARD | 合集目录草稿合并必须显式确认 |

所有 HARD 约束都要在三个位置复用：TTY 输入、manifest validate、平台写入前 checkpoint。

## 12. 异常恢复

| 情况 | CLI 行为 |
|---|---|
| 缺登录 | TTY 引导登录；非交互 code 2 |
| 账号 owner 不匹配 | 停止，显示当前账号和资源 owner |
| 环境不匹配 | 停止，不自动切换 |
| 资源类型不合法 | 展示合法路径，要求重新选择 |
| 文件不存在 | 本地预检失败，不访问平台 |
| build 失败 | 停止，不上传不写平台 |
| 上传成功但平台写失败 | 记录阶段和可恢复信息 |
| 平台写请求结果未知 | 标记 `remote_outcome_unknown`，必须对账 |
| 平台成功本地失败 | 标记 `remote_succeeded_local_pending`，resume 先补 state |
| RSS 验证码错误 | 只重试验证码 |
| RSS 数量超限 | 阻止继续，给缩小范围或 Console 接力建议 |
| 需要支付/签约 | 输出 Console 跳转和回到 CLI 的命令 |

## 13. 实现解决方案

### 13.1 分层

```text
CLI Entry
  → 命令解析、全局参数、TTY/非 TTY、env

Interaction
  → start/studio/session、逐级选择、prompt、checkpoint、Console 接力

Use Case
  → publish/update/policy/dep/online/collection/rss/batch 编排

Domain
  → 类型树、字段 registry、策略模板、授权树、RSS diff、collect-rules

Artifact
  → 文件扫描、ignore、build、zip、SHA1、上传

State
  → manifest、state、auth、write lock、report、resume/retry

Platform
  → SDK/API 调用、payload normalize、错误映射、env 保护

Output
  → human、JSON envelope、NDJSON、exit code
```

### 13.2 状态机

单资源：

```text
local_validated
  → artifact_ready
  → uploaded
  → resource_created/resource_bound
  → version_created
  → listing_updated
  → online_requested
  → state_written
```

批量：

```text
run_created
  → scanned
  → item_planned
  → item_remote_started
  → item_remote_confirmed / remote_outcome_unknown
  → item_local_written / remote_succeeded_local_pending
  → run_done
```

合集/RSS：

```text
collection_selected
  → items_or_feed_planned
  → user_confirmed
  → platform_updated
  → sync_state_written
```

### 13.3 重构顺序

1. 字段 registry、错误码、JSON/NDJSON envelope、状态机测试。
2. auth / manifest / state / report / write lock 边界。
3. 资源类型逐级选择、策略模板选择、依赖授权树选择。
4. TTY `start`、`studio`、`session` 连续流程。
5. 单资源 publish/update/listing/online。
6. 合集、RSS、collect-rules。
7. 批量、resume/retry 和报告体验。
