# 06 · 维护、策略、依赖与上下架

[返回目录](./README.md)

维护前先确认当前目录、账号、环境和平台状态：

```bash
freelog-cli status --env <env>
freelog-cli diff --env <env>
```

## 更新基础信息

```bash
freelog-cli update --title "新标题" --intro "新简介" --tags "标签一,标签二" --yes --env <env>
```

RSS 相关资源只允许维护标签；标题、封面、简介由 feed 托管。

## 维护草稿

```bash
freelog-cli draft push --yes --env <env>
freelog-cli draft pull --env <env>
```

草稿用于多人或多终端协作。拉取前先看 `diff`，避免把本地意图和平台草稿混在一起。

## 策略模板

普通流程应先看可用模板，再选择模板应用：

```bash
freelog-cli policy template list --env <env>
freelog-cli policy template render <templateId> --env <env>
freelog-cli policy template apply <templateId> --yes --env <env>
freelog-cli policy list --env <env>
```

合集策略使用同样思路：

```bash
freelog-cli collection policy template list --env <env>
freelog-cli collection policy template apply <templateId> --yes --env <env>
```

## 启停策略和上下架

```bash
freelog-cli policy set <policyId> 1 --yes --env <env>
freelog-cli online --yes --env <env>
freelog-cli offline --yes --env <env>
```

上架门禁：

1. 当前账号是资源 owner。
2. 资源没有被冻结。
3. 有最新正式版本。
4. 至少有一条启用策略。

## 依赖与授权

```bash
freelog-cli dep add <resourceId> --env <env>
freelog-cli dep list --env <env>
freelog-cli dep remove <resourceId> --env <env>
```

发行前 CLI 会检查依赖授权。缺少授权、需要付费或需要签约时，CLI 会停止并提示去 Console 完成接力。

## 绑定已有线上资源

```bash
freelog-cli resource search <keyword> --env <env>
freelog-cli bind <resourceId> --apply-listing --yes --env <env>
freelog-cli pull --env <env>
```

已有线上资源不要重新 `create`。先绑定，再维护。
