# 03 · 单资源发行

[返回目录](./README.md)

单资源流程的结果是一个平台资源和一个或多个正式版本。

## 主题、插件、package

```bash
freelog-cli init theme ./my-theme --runtime 0.5 --title "我的主题" --yes --env <env>
freelog-cli init widget ./my-widget --runtime 0.5 --title "我的插件" --yes --env <env>
freelog-cli init package ./my-lib --namespace my-lib --title "我的前端库" --yes --env <env>
```

进入工程后，先按项目自己的方式构建，再写版本产物：

```bash
freelog-cli version set --file ./dist --version 1.0.0 --artifact-mode directory-zip --yes --env <env>
freelog-cli create --yes --env <env>
freelog-cli publish --yes --env <env>
```

## 普通文件

```bash
freelog-cli init ./one-file --scaffold none --resource-type <typeCode> --artifact-mode file --title "资源标题" --yes --env <env>
freelog-cli version set --file ../asset.png --version 1.0.0 --artifact-mode file --yes --env <env>
freelog-cli create --yes --env <env>
freelog-cli publish --yes --env <env>
```

## 普通目录作为一个资源

```bash
freelog-cli init ./one-folder --scaffold none --resource-type <typeCode> --artifact-mode directory-zip --title "目录资源" --yes --env <env>
freelog-cli version set --file ../dist --version 1.0.0 --artifact-mode directory-zip --yes --env <env>
freelog-cli create --yes --env <env>
freelog-cli publish --yes --env <env>
```

如果目录里的每个文件都应该独立上架，不要用这个流程，改看 [05 批量发行](./05-批量发行.md)。

## 发布后继续上架

```bash
freelog-cli policy template list --env <env>
freelog-cli policy template apply <templateId> --yes --env <env>
freelog-cli online --yes --env <env>
```

上架前必须已有最新正式版本，并至少有一条启用策略。

## 更新下一版

```bash
freelog-cli version bump patch --yes --env <env>
freelog-cli version set --file ./dist --artifact-mode directory-zip --yes --env <env>
freelog-cli publish --yes --env <env>
```

如果只改已发行版本说明、不换文件、不升版本：

```bash
freelog-cli version edit --version 1.0.0 --description "新的版本说明" --yes --env <env>
```
