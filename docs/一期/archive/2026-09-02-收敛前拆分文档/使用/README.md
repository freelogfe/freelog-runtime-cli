# Freelog CLI 使用文档

Freelog CLI 用来在本地电脑上创建、发行和维护 Freelog 资源。它适合两类使用方式：

- 人在终端里用 `freelog-cli start` 连续完成一件事。
- AI、脚本或 CI 用显式命令完成同一套平台业务。

本文档适用于 Freelog CLI `0.5.x`。公司小范围试用统一使用 `@freelog-cli/cli2`；旧包 `@freelog-cli/cli` 不在本手册范围内。

## 选择入口

| 你现在的目标 | 推荐入口 |
|---|---|
| 不确定该怎么发行 | `freelog-cli start` |
| 一个主题、插件、package、图片、视频或普通文件 | 单资源发行 |
| 一个文件夹里的文件彼此独立 | 批量发行 |
| 多个资源要作为专辑、相册或连载共同展示 | 合集 |
| RSS feed 自动维护合集内容 | RSS 合集 |
| 只维护线上资源，不想长期保存本地工程 | session |
| 一个文件夹里多个账号分别处理资源 | studio |
| AI 或 CI 代执行 | 显式命令 + `--yes` + `--json` 或 `--json-lines` |

## 通用主流程

```text
安装 CLI
  -> 登录并选择环境
  -> 选择资源类型和本地文件
  -> 创建本地工程或进入临时会话
  -> 创建平台资源或绑定已有资源
  -> 发布版本
  -> 从策略模板选择并应用策略
  -> 上架
  -> 后续维护 listing、版本、策略、依赖、上下架或 RSS
```

## 当前环境口径

production / prod 暂未开放。请从环境管理员取得可用的 `<env>` 值，并在示例中替换它。

如果未传 `--env`，CLI 不会猜测环境；写命令会停止并提示你显式选择环境。

## 安全提示

- `publish`、`online`、`offline`、`update`、策略和合集写命令会修改平台数据。
- `freelog.manifest.json` 可以提交；`.freelog/state.json`、`.freelog-auth` 和密钥文件不要提交。
- 首次发行、新版本发行、批量发行不会自动回滚已经成功的平台写入。
- 支付、签约、资源解冻、网页编辑器和部分可视化管理需要跳转 Console 完成。
