# 00 · 快速上手

[返回目录](./README.md)

这一页用最少概念跑通一次：登录、创建资源、发布版本、应用策略、上架。

## 适合谁

| 适合 | 不适合 |
|---|---|
| 第一次手动测试 CLI | 已经要做批量、RSS 或多账号 |
| 想用一条命令进入连续向导 | 需要完全无交互的 CI |
| 有一份可发行的本地文件 | 还没拿到目标环境权限 |

## 方式一：交互向导

```bash
freelog-cli --version
freelog-cli login --env <env>
freelog-cli start --env <env>
```

在空目录运行 `start` 时，CLI 会按顺序询问：

1. 要发布新资源、维护已有资源，还是处理合集/批量。
2. 资源类型：可以搜索，也可以逐级选择到叶子类型。
3. 本地文件或构建目录。
4. 标题、短授权标识、简介、标签、封面。
5. 发布版本。
6. 是否继续选择策略模板。
7. 是否继续上架。

## 方式二：显式命令

下面示例把一张图片作为单个资源发行。`<typeCode>` 必须来自平台资源类型查询结果。

```bash
freelog-cli login --env <env>
freelog-cli type search 图片 --env <env>
freelog-cli init ./demo-image --scaffold none --resource-type <typeCode> --artifact-mode file --title "示例图片" --yes --env <env>
```

进入工程目录后继续：

```bash
freelog-cli version set --file ../image.png --version 1.0.0 --artifact-mode file --yes --env <env>
freelog-cli create --yes --env <env>
freelog-cli publish --yes --env <env>
freelog-cli policy template list --env <env>
freelog-cli policy template apply <templateId> --yes --env <env>
freelog-cli online --yes --env <env>
```

## 成功后怎么确认

```bash
freelog-cli status --env <env>
freelog-cli policy list --env <env>
```

你应该看到资源已绑定平台 `resourceId`，存在最新版本，至少一条策略处于启用状态，并且资源已上架。

## 失败时先看什么

| 现象 | 先做 |
|---|---|
| 提示未登录 | 重新执行 `login --env <env>` |
| 提示资源类型无效 | 用 `type search` 或 `type pick` 重新选择 |
| 提示非交互需要确认 | 加 `--yes`，或改用 TTY 交互 |
| 提示授权不足或需支付 | 去 Console 完成签约或支付 |
| 发布中断 | 先执行 `status` 和 `diff`，不要手动改 state |
