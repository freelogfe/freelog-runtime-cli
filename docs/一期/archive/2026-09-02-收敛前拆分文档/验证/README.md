# 验证文档入口

> **文档角色：** 测试方法、验收清单和环境报告入口。本文验证产品方案，不定义产品方案。

最后更新：2026-09-02

## 本目录放什么

| 内容 | 应放这里吗 | 说明 |
|---|---|---|
| 手动测试步骤 | 是 | 人工验收和 Console 并排核对 |
| 自动化场景索引 | 是 | 本地门禁、dev/test/prod 环境验收入口 |
| 探索测试清单 | 是 | UI 字段、异常和边界探索 |
| 日期化环境报告 | 是 | 某次环境、账号、版本下的结果 |
| 产品目标或流程裁决 | 否 | 应回到 `产品方案/` |
| Console 源码事实 | 否 | 应回到 `对齐/` |
| 代码结构说明 | 否 | 应回到 `开发/` |

## 阅读顺序

| 顺序 | 文档 | 用途 |
|---:|---|---|
| 1 | [场景目录.md](./场景目录.md) | 用户旅程、测试对抗和自动化脚本的总索引 |
| 2 | [手动测试.md](./手动测试.md) | 当前版本手动验收入口 |
| 3 | [探索测试清单.md](./探索测试清单.md) | Console 并排和边界探索 |
| 4 | [reports/](./reports/) | 日期化环境报告和报告模板 |

## 验证口径

```text
产品方案定义应该是什么
  → 对齐目录证明 Console 事实是什么
  → 开发目录说明实现如何落地
  → 验证目录记录这次是否真的通过
```

本地测试通过不等于目标环境签字；目标环境结果必须进入日期化报告。
