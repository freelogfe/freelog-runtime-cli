# 09 · 实现解决方案

> **文档角色：** 定义一期 CLI 的实现架构、模块职责、数据契约、状态机和扩展规则。本文不绑定具体源码文件名，避免把当前代码结构误当成产品方案。

最后更新：2026-09-01

## 1. 实现目标

实现要支撑一个完整产品，而不是堆命令：

```text
同一套 Freelog 业务规则
  → TTY 向导可用
  → 显式命令可用
  → AI/CI 可用
  → 工程模式可长期维护
  → session/studio 可临时维护
  → 失败可恢复
```

## 2. 架构分层

```text
CLI Entry
  → Interaction Layer
  → Validation & Preflight Layer
  → Use Case Orchestrators
  → Platform Gateway
  → Local State & Report Layer
  → Output Renderer
```

| 层 | 职责 | 禁止 |
|---|---|---|
| CLI Entry | 命令声明、参数解析、模式选择 | 写业务 payload |
| Interaction Layer | TTY prompt、选择器、确认、帮助提示 | 直接调用平台写接口 |
| Validation & Preflight | 字段校验、状态门禁、owner/env/frozen | 做持久化副作用 |
| Use Case Orchestrators | 发行、维护、批量、合集、RSS 等业务流程编排 | 读取 raw CLI argv |
| Platform Gateway | Freelog API 封装、错误规范化、重试边界 | 决定产品流程 |
| Local State & Report | manifest、state、report、session store、事务 | 保存凭据明文 |
| Output Renderer | 文本、JSON、NDJSON、错误和成功摘要 | 改变业务结果 |

## 4. 数据契约

### 4.1 manifest

manifest 保存用户长期意图：

- subject：resource 或 collection；
- identity：name；
- resource：type/title/listing；
- version：file/artifact/version/attrs/deps；
- policies：本地策略意图；
- collection：合集 display/items/deps/attrs；
- preferences：非敏感偏好。

禁止保存：

- token、password、cookie、authorization；
- resourceId、versionId、fileSha1 等平台事实；
- 运行中临时状态。

### 4.2 state

state 保存平台事实：

- env；
- owner；
- resourceId；
- status；
- latestVersion；
- policies；
- published file facts；
- collection draft/version facts；
- sync fingerprint。

state 不作为用户编辑入口。

### 4.3 report

report 保存长任务恢复事实：

- runId；
- command；
- env；
- auth username；
- input/config fingerprint；
- item idempotencyKey；
- stage；
- result；
- remote facts；
- local recovery status；
- nextCommand。

report 是恢复依据，不是普通日志。

### 4.4 session context

session context 保存进程内临时意图：

- current resource；
- selected env/account；
- current version draft；
- selected policy template；
- collected variables；
- pending next actions。

进程结束销毁，除非用户显式 export。

## 5. 统一流程骨架

所有写平台 use case 使用同一骨架：

```text
resolve context
  → load current local/session state
  → fetch platform facts
  → validate fields
  → validate business gates
  → build side-effect summary
  → confirm or require --yes
  → execute platform write
  → verify platform result
  → persist state/report
  → render success/nextCommand
```

如果某个流程跳过 fetch/validate/confirm/verify，需要在设计中明确说明原因。

| 业务 | 接口顺序 |

| 发布版本 | Storage.fileIsExist → Storage.uploadFile → PropertyParser → Resource.createVersion → Resource.resourceVersionInfo1 对账 |
| 修改 listing | Resource.info → Resource.update → Resource.info 对账 |
| 编辑已发布版本 | Resource.resourceVersionInfo1 → Resource.updateResourceVersionInfo → Resource.resourceVersionInfo1 对账 |
| 策略新增 | Policy.policyTemplates → Policy.policyReCompile → Policy.policyTranslation → Resource.update |
| 上下架 | Resource.info → gate checks → Resource.update(status) → Resource.info |
| 批量 | scan/upload/parse/name → Resource.createBatch → per item result → report |
| 合集条目 | Resource.getCollectionItems_Draft → Resource.resourceIsExistInItems_Draft → Resource.getCollectionItemsAuth_Draft → Resource.addResourceItems_Draft / Resource.updateCollectionItemsInfo_Draft / Resource.deleteCollectionItems_Draft / Resource.setCollectionItemsSortID_Draft / Resource.reorderCollectionItems_Draft → Resource.getCollectionItems_Draft |

## 7. 交互实现契约

TTY 组件应是可复用能力，而不是散落在命令里：

| 能力 | 行为 |
|---|---|
| Select Tree | 支持逐级进入、返回、搜索、最近使用 |
| Form Prompt | 输入前显示限制，输入后立即校验 |
| Review Screen | 写平台前统一副作用摘要 |
| Next Action Menu | 成功后给下一步 |
| Handoff Screen | 需要 Console 时给 URL 和恢复命令 |
| Error Renderer | 显示字段、原因、本地/平台副作用和下一步 |
| JSON Renderer | 输出稳定 envelope |
| NDJSON Renderer | 长任务 progress，不混人类文案 |

## 8. 状态和恢复实现

所有外部写入分阶段：

```text
planned
  → local_prepared
  → remote_request_started
  → remote_succeeded
  → local_persisted
  → verified
```

异常状态：

| 状态 | 处理 |
|---|---|
| local_failed_before_remote | 可安全重试 |
| remote_failed_known | 可按错误修正后 retry |
| remote_succeeded_local_pending | 恢复本地，不重复远端 |
| remote_outcome_unknown | 停止并人工对账 |
| handoff_required | 等 Console 完成后继续 |

## 9. 并发与一致性

工程模式必须防止：

- 两个 CLI 同时写同一 manifest/state；
- 本地旧 state 覆盖远端新状态；
- report 恢复跨 env/账号；
- 批量 success 项被重复创建；
- session/studio 凭据串账号。

策略：

- 本地事务锁；
- manifest/state revision；
- 平台写后 GET 对账；
- report fingerprint；
- owner/env 强校验；
- unknown 停止。

## 10. 输出契约

文本输出面向人：

- 当前上下文；
- 正在做什么；
- 为什么失败；
- 下一步。

JSON 输出面向机器：

```json
{
  "schemaVersion": 1,
  "ok": true,
  "command": "publish",
  "data": {},
  "warnings": [],
  "meta": {
    "env": "dev",
    "requestId": "...",
    "nextCommand": "..."
  }
}
```

失败：

```json
{
  "schemaVersion": 1,
  "ok": false,
  "code": 4,
  "message": "字段不合法",
  "details": {},
  "meta": {
    "nextCommand": "..."
  }
}
```

## 11. 国际化和文案

文案应按业务语义组织：

- 字段错误；
- preflight 摘要；
- 成功摘要；
- handoff；
- report/resume；
- 类型选择；
- 策略模板；
- RSS/collect-rules。

禁止把平台 raw error 直接甩给普通用户；raw error 可以放 debug/details。

## 12. 可扩展规则

新增业务能力时：

1. 先确认是否属于资源、版本、策略、合集、RSS、节点或其它域。
2. 写清用户流程和 Console/API 对齐。
3. 加入字段总账。
4. 加入异常恢复。
5. 加入实现组件或扩展已有组件。
6. 加入验收矩阵。

不能先加命令再补产品解释。

## 13. 实现完成标准

- 每条主流程都经过统一流程骨架。
- 字段限制不散落在命令里。
- 策略模板 Builder 是主路径。
- 类型选择器支持逐级和搜索。
- session/studio 不破坏业务门禁。
- report 能恢复长任务。
- JSON/NDJSON 稳定。
- 需要 Console 的动作有 handoff。
- 产品验收、契约测试、环境验证可追踪。
