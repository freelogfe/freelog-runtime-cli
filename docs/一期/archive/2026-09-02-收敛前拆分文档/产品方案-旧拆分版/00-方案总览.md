# 00 · 需求分析、业务推导与方案总览

> **文档角色：** 一期 CLI 产品方案的推导入口。本文从用户需求、Console 业务、CLI 环境差异推导出完整产品方向；后续流程、字段、异常、实现和验收都必须能回到本文解释。

最后更新：2026-09-01

## 1. 一句话目标

Freelog Runtime CLI 一期要让用户或 AI 在本地电脑上，通过一次连续会话或一组可复制命令，完成 Freelog 资源的发行、更新、策略、依赖授权、上下架、批量、合集、RSS 和自动收录维护。

它不是“无界面的 Console”，也不是 API 包壳。它是本地资源工作台。

## 2. 产品定位

| 维度 | 定位 |
|---|---|
| 面向对象 | 本地文件、本地工程、构建产物、素材目录、线上资源、合集、RSS feed |
| 核心价值 | 把 Console UI 中隐性的字段限制和状态门禁，转成终端可探索、可预检、可脚本化、可恢复的流程 |
| 业务边界 | 对齐 Console 资源域：资源类型、资源壳、版本、listing、策略、依赖授权、合集、RSS、collect-rules、上下架 |
| CLI 原生能力 | 模板、构建、目录压缩、批量处理、报告恢复、session、studio、JSON/NDJSON |
| 非目标 | 不完整复制节点运营、收入、消费侧列表、可视化编辑器、支付收银台和浏览器专属页面 |

## 3. 需求分析

### 3.1 用户为什么需要 CLI

Console 适合有 UI 表单约束、可视化编辑和浏览器支付/签约的场景；CLI 要解决的是另一组真实工作：

- 本地文件、工程和构建产物已经在电脑上，用户希望直接发行或更新；
- AI/CI 需要稳定输入输出，不能依赖浏览器页面状态；
- 批量、本地目录、压缩、报告恢复等操作在 Console 中成本高；
- 主题、插件、package 开发者需要从模板到构建产物再到版本发布的一条工作流；
- 线上资源维护者只想临时修改 listing、策略或上下架，不一定想建立长期工程。

### 3.2 产品必须解决的问题

| 问题 | 产品解法 |
|---|---|
| 用户不知道平台资源 type code | 类型树逐级选择为主，搜索为辅，leaf 确认前展示能力 |
| Console 通过 UI 限制字段，CLI 容易绕过 | 所有 prompt、flag、manifest 和 preflight 共用字段校验 |
| 命令行写平台风险高 | 所有平台写入前显示 env/account/target/action/side effects |
| 本地意图和平台事实容易混淆 | manifest 只存意图，state 只存平台事实，pull 默认不覆盖 manifest |
| 长任务中断后难恢复 | 批量、studio、RSS 导入写 report，并区分 success/failed/unknown |
| AI 代执行需要闭环 | 非 TTY 不提问，缺字段结构化失败，成功输出 nextCommand |

### 3.3 成功判定

用户完成主路径时，不应该需要理解平台内部 payload；实现人员完成代码时，不应该需要翻旧文档猜字段；测试人员验收时，不应该只看命令是否返回 0，而要能核对 Console 业务结果。

## 4. Console 业务分析

CLI 要对齐的不是 Console 页面长什么样，而是 Console 在资源域里已经形成的业务秩序。

### 4.1 Console 主业务链

```text
选择资源类型
  → 填资源基础信息
  → 创建资源壳
  → 选择或上传版本文件
  → 填版本信息和属性
  → 创建正式版本
  → 配置策略
  → 检查授权和签约
  → 上架或下架
```

这条链路对应 CLI 的单资源主流程。CLI 可以把页面步骤压缩成连续向导，也可以拆成显式命令，但不能改变业务顺序：没有资源壳不能发版，没有正式版本和启用策略不能上架，需要授权时必须先处理授权。

### 4.2 Console 维护业务

| Console 能力 | 业务含义 | CLI 对齐方式 |
|---|---|---|
| 资源 info / sidebar | 查看并维护标题、封面、简介、标签 | `status`、`update`、`pull/diff` |
| 版本管理 | 创建新版本，维护已发布版本部分元数据 | `version set/bump/edit/show`、`publish` |
| 策略管理 | 从模板或编辑器生成策略，启停策略 | `policy template list/render/apply`、`policy set/list` |
| 依赖和授权 | 检查依赖授权，签约后才能完成发行 | `dep`、发布前 preflight、Console 接力 |
| 上下架 | 在满足版本、策略、状态门禁后切换展示状态 | `online`、`offline` |

Console 的字段限制、禁用状态和提示语是产品事实，不是 UI 细节。CLI 必须在 prompt、flag、manifest 和 preflight 层都执行同一业务约束。

### 4.3 Console 合集 / RSS / 自动收录业务

| 业务 | Console 关键语义 | CLI 产品结论 |
|---|---|---|
| 合集创建 | 合集是资源壳 + 目录草稿 + 合集版本，不是 zip 文件 | CLI 必须解释四层模型 |
| 合集目录 | 条目来源可以是已有资源或本地导入后的子资源 | CLI 提供 item、init-from-folder 和目录草稿恢复 |
| RSS 合集 | feed 托管标题、封面、简介和目录；标签仍可手动维护 | CLI 锁定托管字段，保留 tags 更新 |
| RSS 换源 | preview、send-code、compare、bind，验证码错误是字段错误 | CLI 必须按同一顺序和错误语义实现 |
| 单集范围 | `matchedItemCount > 1000` 时需要发布时间范围 | CLI 让用户传日期并转为平台时间格式 |
| collect-rules | 普通合集可自动收录；RSS 合集不能设置 | CLI 在服务层硬拦 |

### 4.4 Console 无法被 CLI 直接替代的业务

| 业务 | 为什么不能直接替代 | CLI 处理 |
|---|---|---|
| 支付 / 付费签约 | 涉及账户确认、合同确认和浏览器上下文 | 返回 Console 接力提示和下一步命令 |
| 可视化编辑器 | 需要富 UI 操作 | 提示进入 Console |
| 图片裁剪和云存储选择 | 依赖浏览器组件 | CLI 只处理本地路径或 URL |
| 节点和消费侧完整运营 | 超出一期资源发行域 | 一期只提示边界，不假装完成 |

## 5. CLI 环境差异分析

CLI 的约束和机会与 Console 不同，设计必须先承认这些差异：

| CLI 环境事实 | 产品处理 |
|---|---|
| 终端没有页面路由和 disabled 按钮 | 用菜单、即时校验、preflight、exit code 表达同等业务门禁 |
| 当前目录可能是空目录、工程目录、普通素材目录或 report 恢复点 | `start` 第一屏识别目录状态，并让用户确认目录含义 |
| 非 TTY 不能问问题 | 所有必填字段必须来自 flag/config/manifest，缺失返回 code 4 |
| 同一台电脑可能多账号、多环境、多工程 | auth 与 state 分离；workspace/global/ephemeral 凭据边界清楚 |
| 本地文件可能很大、很多或含敏感文件 | 扫描、ignore、大小/格式/sha1 和压缩规则先于平台写入 |
| 网络和平台写入不是本地事务 | 写后 GET 对账；unknown 停止；report 恢复，禁止盲目重试 |
| 用户可能是人，也可能是 AI/CI | 同一业务有 TTY 与 JSON/NDJSON 两套表达，但门禁一致 |

## 6. 从分析推导出的产品原则

| 推导来源 | 结论 |
|---|---|
| Console 用页面控件限制字段 | CLI 必须把限制前移到参数、prompt、manifest 校验和 preflight |
| Console 有连续页面状态 | CLI 必须提供 `start` 连续会话和每步可复制命令 |
| Console 适合单次人工操作 | CLI 必须强化批量、压缩、report、resume 和 JSON/NDJSON |
| Console 有浏览器支付/签约 | CLI 必须承认边界并给 handoff，而不是伪造完成 |
| CLI 会被 AI/CI 使用 | 所有主流程必须有非交互等价路径 |
| 本地和平台不是一个事务 | 所有远端写入必须有 state/report 对账和未知结果处理 |

产品方案后续所有流程都从这些原则派生：先保证 Console 业务结果一致，再把终端环境特有的问题设计清楚。

## 7. 用户任务

| 用户 | 典型目标 | 必须顺畅完成的任务 |
|---|---|---|
| 普通作者 / 普通内容作者 | 发布图片、视频、音频、文档 | 不知道资源 type code 也能逐级选择类型，完成发行和上架 |
| 主题开发者 | 发布主题资源 | 从主题入口初始化、构建、压缩、发版、策略、上线 |
| 插件开发者 | 发布插件资源 | 从插件入口初始化和发行，不被主题/package 文案误导 |
| 前端库开发者 / package 开发者 | 发布 JS / React / Vue 软件库 | 选择 package 模板、namespace、leaf 类型和构建产物 |
| 策展人 | 维护合集、专辑、相册 | 创建合集、导入子资源、排序、展示设置、发布合集版本 |
| RSS 维护者 | 绑定和同步 RSS 合集 | preview、邮箱验证、日期范围、同步、失败项处理 |
| 批量运营 | 批量发布本地素材目录 | 扫描、预览、分批、失败项、resume、report |
| 线上维护者 | 不改本地文件，只改线上状态 | bind/session 后改 listing、策略、依赖、上下架 |
| AI / CI | 代用户自动执行 | 全参数、无 prompt、稳定 JSON/NDJSON、退出码、恢复报告 |

## 8. 范围划分

| 范围 | 一期结论 | 示例 |
|---|---|---|
| CORE | 一期主流程必须完成 | 单资源创建、发版、策略模板、上下架、本地工程 |
| ADVANCED | 一期必须设计并实现主要能力，但可单独验收 | RSS、collect-rules、session、studio、批量恢复 |
| CLI_ONLY | Console 无直接对应，但 CLI 必须具备 | 模板、构建、压缩、JSON/NDJSON、report/resume |
| OUT | 一期不在 CLI 内完成，只提供接力 | 支付收银台、浏览器签约、图片裁剪 UI、节点全域管理 |

OUT 不是忽略。OUT 场景必须告诉用户为什么停、去哪里做、回来执行什么命令。

## 9. 总业务拓扑

```text
身份与环境
  → 选择工作方式：工程 / session / studio / AI-CI
  → 选择任务
      ├─ 发布新资源
      │   ├─ 主题
      │   ├─ 插件
      │   ├─ package / 软件库
      │   ├─ 普通单文件
      │   └─ 普通目录 zip
      ├─ 更新已有资源
      ├─ 维护线上资源
      ├─ 批量发布本地目录
      ├─ 创建或维护合集
      │   ├─ 添加已有资源
      │   ├─ 从本地目录导入子资源
      │   ├─ RSS 绑定 / 更新 / 同步
      │   └─ collect-rules 自动收录
      └─ 只管理策略 / 依赖 / 上下架
```

## 10. 标准资源发行链

单资源和工程类资源最终都落到这条链路：

```text
选择平台叶子资源类型
  → 准备本地工程或文件
  → 填资源标题和授权标识
  → 创建资源壳
  → 选择文件或构建产物
  → 校验文件格式、大小、sha1、属性
  → 创建版本
  → 选择策略模板
  → 填策略变量并预览
  → 应用策略
  → 填 listing：封面、简介、标签
  → 上架
```

CLI 可以把这条链拆成显式命令，也可以在 `start` 中连续引导；业务顺序不能乱。

## 11. 三种“目录”必须分清

| 用户手上的目录 | 用户心智 | CLI 流程 | 平台结果 |
|---|---|---|---|
| 一个构建产物目录 | 这个目录整体就是作品 | 目录 zip 资源 | 一个资源版本文件 |
| 一个素材目录 | 目录里每个文件都是作品 | 批量发行 | 多个独立资源 |
| 一个相册/专辑目录 | 目录内容组成合集 | 合集导入 | 子资源 + 合集条目 + 合集版本 |

这是第一屏必须问清的问题。后面再纠正，会造成错误资源模型。

## 12. Console 对齐原则

CLI 对齐的是 Console 的业务结果，不照搬页面形式。

| Console 保障 | CLI 方案 |
|---|---|
| 下拉树 | 平台类型树逐级选择，搜索只是快捷 |
| 表单限制 | prompt 校验、flag 校验、preflight |
| disabled 按钮 | 写平台前门禁失败 |
| 弹窗确认 | 副作用摘要 + confirm / `--yes` |
| 自动保存草稿 | 工程 manifest/state 或显式 draft 命令 |
| 文件选择器 | 本地扫描、ignore、格式/大小、sha1 |
| 支付/签约页面 | Console handoff URL + nextCommand |
| 成功页 | 成功摘要、下一步菜单、report |

## 13. CLI 原生体验原则

1. **一个入口能开始：** 新用户只需记住 `freelog-cli start`。
2. **每一步知道副作用：** 清楚区分“只写本地”和“将写平台”。
3. **可探索：** 资源类型、策略模板、合集条目来源都能列出和逐级选择。
4. **可撤回：** 未确认前不写平台；本地工程写入可明确展示。
5. **可复制：** 每个 checkpoint 输出等价命令。
6. **可脚本化：** AI/CI 可用 flags、manifest、JSON、NDJSON、exit code 完成同一业务。
7. **可恢复：** 批量、studio、未知远端结果都有 report 和恢复策略。
8. **不猜平台：** 类型 code、能力、字段配置来自平台；无法确认就停。

## 14. 设计完成判定

这套方案只有满足下面条件才算完成：

- 每条流程有 TTY 和 AI/CI 两种路径。
- 每个写平台动作有接口顺序、字段门禁、失败恢复。
- 主题、插件、package 是一等入口。
- 策略主路径是模板 Builder。
- RSS / collect-rules 作为可实现能力设计完整。
- session / studio / 多账号不是附属说明，而是运行表面设计。
- 实现方案不依赖具体源码文件名，能指导重构架构。
- 验收方案覆盖产品、测试、开发、AI/CI 和真实环境差异。
