# 02 · 命令与交互设计

> **文档角色：** 定义一期 CLI 的入口、命令信息架构、TTY 交互、非交互模式、AI/CI、session 和 studio 体验。本文只讲用户如何操作，不展开每个业务字段。

最后更新：2026-09-01

## 1. 总体原则

CLI 的主体验不是“让用户背命令链”，而是：

```text
一个入口进入
  → 每一步清楚知道当前账号、环境、资源、是否写平台
  → 完成后给下一步命令
  → 失败后给恢复路径
```

熟练用户、AI 和 CI 可以跳过 TTY，用显式命令完成同一业务。

## 2. 第一入口

默认入口：

```bash
freelog-cli start
```

`start` 第一屏：

```text
当前环境：<env>
当前账号：<username>
当前目录：<cwd>
目录状态：空目录 / 资源工程 / 合集工程 / 未完成报告 / 普通目录

你要做什么？
  1. 发布一个新资源
  2. 更新当前本地工程
  3. 维护一个已有线上资源
  4. 批量发布一个本地文件夹
  5. 创建或维护合集
  6. 管理策略 / 依赖 / 上下架
  7. 进入 session / studio 临时工作
```

### 2.1 目录状态推荐

| 当前目录 | 默认推荐 | 可切换 |
|---|---|---|
| 空目录 | 发布新资源、创建合集 | 登录、维护线上资源 |
| 有普通文件但无工程 | 发布单文件或目录 zip | 批量、合集 |
| 有资源工程 | 更新当前工程 | 策略、上线、下线、diff |
| 有合集工程 | 维护合集 | RSS、collect-rules、publish |
| 有未完成 report | 恢复上次任务 | 查看报告、放弃、重新开始 |
| 非 TTY | 不提问，只输出建议命令 | `--json` 输出结构化建议 |

## 3. 发布新资源的交互

发布新资源先问“你手里是什么”，不要先问 type code。

```text
你要发布什么？
  1. 主题工程
  2. 插件工程
  3. 前端库 / 软件库 package
  4. 单个文件
  5. 一个目录整体作为 zip 资源
  6. 一个目录里的每个文件作为独立资源
  7. 一个目录内容组成合集
  8. RSS feed 组成合集
```

选择后进入对应流程：

| 选择 | 进入 |
|---|---|
| 主题工程 | 主题模板 + 主题 leaf 类型 + 构建目录 zip |
| 插件工程 | 插件模板 + 插件 leaf 类型 + 构建目录 zip |
| package | package 模板 + namespace + package leaf 类型 |
| 单个文件 | 平台类型树 leaf + file artifact |
| 目录 zip | 平台类型树 leaf + directory-zip artifact |
| 批量 | 批量扫描、预览、createBatch |
| 合集 | 合集壳、子资源、目录草稿、合集发布 |
| RSS | 合集壳 + RSS preview/bind/sync |

## 4. 资源类型选择体验

默认是逐级浏览，搜索只是快捷入口。

```text
选择资源类型
  最近使用
    - 图片 / 摄影作品
  分类
    1. 阅读
    2. 音频
    3. 图片
    4. 视频
    5. 主题
    6. 插件
    7. 软件库

操作：
  ↑↓ 选择
  /  搜索
  ←  返回上一级
  enter 进入或确认 leaf
```

选中一项时显示：

```text
名称：图片 / 摄影作品
code：RTxxxx
状态：可发布 leaf
上传：支持本地文件
格式：jpg, png, gif
大小：最大 <来自平台配置>
属性：需要解析宽高 / 时长 / ...
```

规则：

- 父节点只能继续进入，不能确认发布。
- 类型配置来自平台，不从 CLI 硬编码。
- 主题和插件必须在分类里可见。
- 搜索结果也要显示完整路径。
- 非 TTY 必须显式传 `--resource-type`，不能弹 prompt。

## 5. 策略模板选择体验

新增策略的普通路径：

```text
选择授权策略模板
  1. 免费阅读 / 永久免费
  2. 限时免费
  3. 付费授权
  4. 组合授权

选中模板
  → 显示模板说明、适用资源、需要填写的参数
  → 填策略名称
  → 填模板变量
  → 编译
  → 翻译预览
  → 确认应用
```

策略确认页必须显示：

```text
将写入资源：<title> (<resourceId>)
策略名称：<policyName>
策略模板：<templateName>
授权说明：<translation>
是否需要结算信息：是/否
是否会立即上架：否，需执行 online
```

手写策略文件：

- 只放在高级入口；
- 不作为 `start` 普通默认路径；
- 使用前提示风险；
- 同样要检查策略名、重复策略、语法和结算边界。

## 6. 写平台前 preflight

所有写平台动作确认前都显示同一种摘要：

```text
即将写入 Freelog
  环境：<env>
  账号：<username>
  目标：<resource title / resourceId>
  动作：创建资源 / 发布版本 / 添加策略 / 上架 / ...
  本地：将写 manifest/state/report 或无本地写入
  平台：将调用哪些业务动作
  风险：不可自动回滚 / 需要后续策略 / 可能跳 Console

确认继续？ yes/no
```

非交互模式：

- 缺 `--yes` 的写操作失败；
- `--json` 输出结构化错误；
- stderr 可有人类提示，stdout 只能 JSON。

## 7. 成功后的下一步

每个 checkpoint 成功后都要给明确下一步。

| 当前完成 | 推荐下一步 |
|---|---|
| init | `create` |
| create | `version set` 或 `publish` |
| publish | `policy template apply` |
| policy apply | `online` |
| online | 查看 Console 链接、继续维护 |
| batch 完成 | 查看 report、进入某个子工程、失败项 retry |
| collection item 导入 | `collection publish` |
| collection publish | `policy template apply` / `online` |
| RSS bind | `collection rss status` / `collection publish` |

## 8. session 模式

`--session` 用于“我只维护一次线上资源，不想创建工程”。

示例心智：

```text
freelog-cli update --session --resource-id <id> --title "新标题"
freelog-cli policy template apply --session --resource-id <id>
freelog-cli online --session --resource-id <id>
```

规则：

- 命令结束后不保存 manifest/state。
- 不允许设计“上一个命令改内存，下一个命令消费”的跨进程流程。
- 需要多步纯内存流程时使用 `freelog-cli session`。
- 业务门禁与工程模式一致。

## 9. session 交互壳

`freelog-cli session` 是一个临时工作台：

```text
登录（不保存）
  → 选择资源或创建资源
  → 连续执行 update / publish / policy / online
  → 可导出工程
  → 退出时清除凭据
```

适合：

- 用户临时帮别人维护一次；
- AI 在一个终端里连续完成多个动作；
- 不希望在当前目录留下 manifest/state。

退出前提示：

```text
本次会话没有保存到本地工程。
是否导出工程以便后续维护？
```

## 10. studio 多账号工作台

`freelog-cli studio` 用于多账号或多文件批量处理：

```text
选择/登录账号 A（不保存凭据）
  → 导入文件或目录
  → 发行资源
切换账号 B（不保存凭据）
  → 发行另一组资源
  → 每个成功资源可导出独立子工程
```

规则：

- 凭据只存在内存。
- 子工程保存平台事实，但不保存凭据。
- 每个资源的 owner 必须写入 state，用于后续维护校验。
- 批量和 studio 都需要 report/resume。

## 11. AI/CI 模式

AI/CI 不应该读 TTY 文案。它需要稳定契约：

```bash
freelog-cli <command> --env <env> --yes --json
```

约定：

- stdout 只有 JSON envelope。
- 长任务可输出 NDJSON progress。
- 缺参数返回 code 4。
- 未登录/环境不一致返回 code 2。
- 本地/远端冲突返回 code 3。
- 需要 Console 支付/签约/浏览器动作返回 code 5。
- 可能重复创建远端的未知结果，必须停下并要求对账。

## 12. 命令信息架构

| 命令域 | 用户语言 | 示例 |
|---|---|---|
| 身份环境 | 我是谁、写哪里 | login、logout、config |
| 发现 | 看类型和模板 | type、template |
| 工程 | 创建或接入本地工作台 | init、bind、workspace |
| 状态 | 看本地和平台差异 | status、diff、pull、validate |
| 资源 | 创建、发版、维护 | create、version、publish、release、update |
| 策略 | 授权模板和启停 | policy template、policy set |
| 依赖授权 | 声明依赖、处理签约 | dep add、dep auth |
| 上下架 | 改平台可见状态 | online、offline |
| 批量 | 目录变多个独立资源 | resource import-dir |
| 合集 | 合集壳、条目、RSS、收集规则 | collection * |
| 会话 | 临时工作 | session、studio、--session |

命令名要服务用户心智，不要直接暴露平台 API 名。
