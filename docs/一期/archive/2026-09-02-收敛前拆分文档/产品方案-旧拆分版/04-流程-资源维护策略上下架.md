# 04 · 流程：资源维护、策略、依赖与上下架

> **文档角色：** 定义已有资源或已有本地工程的维护流程，包括 bind、pull、listing、版本更新、策略模板、依赖授权、上线和下线。

最后更新：2026-09-01

## 0. 流程卡片

| 项 | 内容 |
|---|---|
| 用户目标 | 对已有 Freelog 资源继续维护：接入本地、同步差异、更新 listing、发布新版本、编辑版本信息、管理策略/依赖、上架或下架。 |
| TTY 路径 | `freelog-cli start` 识别当前目录或让用户输入 resourceId/authId，再进入维护动作菜单。 |
| AI/CI 路径 | 直接使用显式命令和目标资源：`--resource-id` 或工程 state + `--env` + 写操作 `--yes` + 可选 `--json`。 |
| Console 对齐点 | 维护前读取资源详情；owner、frozen、最新版本、策略状态、RSS 锁字段、版本可编辑字段与 Console 保持同一业务边界。 |
| 平台写入 | `Resource.update` 更新 listing/策略/status；`Resource.createVersion` 发布新版本；`Resource.updateResourceVersionInfo` 编辑已发布版本可编辑信息。 |
| 本地写入 | pull 默认只刷新 state；manifest 只保存用户意图，除非用户显式接受平台 listing；session 不落盘。 |
| Console 接力 | 付费依赖授权、结算、复杂合约、封面裁剪、非 owner 或 frozen 的平台处理交给 Console。 |

## 1. 入口

维护不是重新创建资源。入口分三类：

| 用户手里有什么 | 推荐入口 | 本地结果 |
|---|---|---|
| 已有本地工程 | `start` 自动识别 | 使用现有 manifest/state |
| 只有 resourceId 或 username/name | session 维护或 bind | 临时维护，或创建本地绑定 |
| Console 改过资源 | pull/diff | 刷新 state，按需合并 listing |

## 2. 维护总流程

```text
读取本地/会话上下文
  → 确认 env 和账号
  → 读取 Resource.info
  → 校验 owner / frozen / sync
  → 用户选择维护动作
      ├─ 修改 listing
      ├─ 发布新版本
      ├─ 编辑已发布版本可编辑字段
      ├─ 管理策略
      ├─ 管理依赖授权
      ├─ 上架
      └─ 下架
  → 写前 preflight
  → 写平台
  → 保存平台事实或输出 session 结果
```

### 2.1 AI/CI 等价流程

```text
解析工程 state 或 --resource-id/--auth-id
  → 读取 Resource.info
  → 校验 env/account/owner/frozen/RSS 锁
  → 校验本次动作字段
  → --yes 确认副作用
  → 写平台并对账
  → 输出 JSON envelope 和 nextCommand
```

非交互维护必须避免隐式目标：

- 当前目录没有唯一 state 时，必须传 `--resource-id` 或 `--auth-id`；
- 环境不一致返回 code 2；
- 字段、状态门禁不满足返回 code 4；
- 需要 Console 签约/支付/结算返回 code 5；
- 远端结果未知时停止并要求对账。

## 3. bind：接入已有线上资源

```text
输入 resourceId 或 username/name
  → Resource.info
  → 校验 owner
  → 读取资源类型和最新版本
  → 生成本地工程绑定
```

字段：

| 字段 | 规则 |
|---|---|
| resourceId / authId | 必填，必须存在 |
| env | 必须和资源所在环境一致 |
| owner | 当前登录账号必须是 owner |
| local directory | 不得覆盖未确认的本地工程 |

失败：

| 情况 | 处理 |
|---|---|
| 资源不存在 | 停止，提示检查 env 和标识 |
| owner 不符 | 停止，显示当前账号和资源 owner |
| 当前目录已有不同资源 | 停止，要求换目录或确认覆盖 |
| state 丢失但 manifest 存在 | 不猜远端，要求显式 bind |

## 4. pull / diff：同步和冲突

```text
读取本地 manifest/state
  → 读取 Resource.info
  → 比较平台事实和本地意图
  → diff 展示差异
  → pull 默认只刷新 state
  → 只有显式 apply-listing 才写 manifest listing
```

规则：

- state 是平台事实，不是用户编辑入口。
- manifest 是用户意图，不被 pull 默认覆盖。
- 同字段本地和平台都变更时，写操作必须失败。
- `force` 只能在用户明确知道覆盖方向时使用。

## 5. 修改 listing

接口：

```text
Resource.info
  → 字段校验
  → Resource.update
  → Resource.info 对账
```

字段：

| 字段 | 规则 | CLI 体验 |
|---|---|---|
| title | 非空，最多 100 字 | 输入时显示长度 |
| intro | 最多 200 字 | 超限时不提交 |
| cover | 图片格式，最大 5MB | CLI 不裁剪，提示可去 Console 裁剪 |
| tags | 最多 20 个，单项最多 20，去 `#`，不重复 | 展示规范化结果 |

RSS 相关资源的 listing 锁定必须遵守 RSS 锁字段规则。

## 6. 发布新版本

```text
读取 Resource.info 和版本列表
  → 推荐 patch +1 版本
  → 用户选择新文件或 reuse 旧版本
  → 校验 semver > latestVersion
  → 文件处理 / sha1 / 属性解析
  → 依赖授权 preflight
  → Resource.createVersion
```

规则：

- 改依赖列表必须走新版本。
- 改文件必须走新版本。
- 后续版本不固定 `1.0.0`，默认 patch +1。
- reuse-version 表示复用旧 sha1 创建新版本。

失败：

| 情况 | 处理 |
|---|---|
| 版本号不合法 | 提示 semver 和推荐版本 |
| 版本号不大于最新版本 | 停止 |
| 依赖授权不完整 | code 5，进入 dep auth 或 Console 接力 |
| 资源 frozen | 停止 |

## 7. 编辑已发布版本信息

这是维护已发布版本可编辑字段，不是创建新版本。

允许：

- description；
- inputAttrs 中可编辑项；
- customPropertyDescriptors 中可编辑项；
- 依赖解析项等 Console 允许维护的版本元信息。

禁止：

- 改版本号；
- 换文件；
- 改 dependencies 列表本身；
- 改 fileSha1。

用户如果试图做禁止项，CLI 应引导到“发布新版本”。

## 8. 依赖和授权

依赖流程：

```text
dep add / update / remove
  → 修改本地下版意图
  → publish preflight 读取依赖授权树
  → 免费可自动签约
  → 付费/复杂签约跳 Console
```

字段：

| 字段 | 规则 |
|---|---|
| resourceId / authId | 必须能解析为依赖资源 |
| versionRange | 显式优先；未传时可按 latestVersion 推荐 |
| dependencies | 直接依赖 |
| baseUpcastResources | 上抛依赖 |
| authExcludedItems | 授权排除项，必须可由授权树解释 |

接力：

| 情况 | CLI 处理 |
|---|---|
| 免费策略可签 | 自动创建合同并对账 |
| 付费策略 | 返回 Console 合约/支付链接 |
| 结算信息缺失 | 返回 Console 结算链接 |
| 授权树不可达 | 不继续 publish |

## 9. 策略新增

策略新增流程见 [03-流程-单资源发行.md](./03-流程-单资源发行.md) Step F。维护期策略新增仍然使用同一模板 Builder。

维护期额外规则：

- 同一资源内 policyName 不可重复。
- 编译后的 policyText 不可重复。
- 已上架资源不能停用最后一条启用策略。
- 策略新增后 CLI 不自动上架；用户明确执行 online。

## 10. 策略启停

```text
读取 Resource.info
  → 展示策略列表
  → 用户选择策略
  → 校验是否可启停
  → Resource.update.updatePolicies
```

门禁：

| 情况 | 处理 |
|---|---|
| 资源已上架且只剩一条启用策略 | 禁止停用 |
| 策略不存在 | 停止并刷新策略列表 |
| resource frozen | 禁止 |

## 11. 上架

```text
online
  → Resource.info
  → latestVersion 必须存在
  → 至少一条启用策略
  → owner 是当前账号
  → 非 frozen
  → 确认副作用
  → Resource.update status=1
```

失败指引：

| 失败原因 | next step |
|---|---|
| 无版本 | publish |
| 无策略 | policy template apply |
| 策略全禁用 | policy set |
| owner 不符 | 切换账号或停止 |
| frozen | 只读查看或 Console 联系处理 |

## 12. 下架

```text
offline
  → Resource.info
  → 显示当前资源、状态和影响
  → 用户确认
  → Resource.update status=4
```

下架是外部可见状态变化，TTY 必须二次确认，非 TTY 必须 `--yes`。

## 13. session 维护

用户只有线上资源标识时：

```text
freelog-cli session
  → 临时登录
  → 输入 resourceId
  → 选择维护动作
  → 连续完成 update / policy / online / offline
  → 可导出工程
```

规则：

- 不保存凭据。
- 不默认创建工程。
- 不降低 owner、frozen、策略、版本门禁。

## 14. 验收标准

- bind 不会绑定非 owner 资源。
- pull 不会默认覆盖 manifest。
- listing 字段约束与 Console 一致。
- 新版本和版本编辑的边界清楚。
- 策略模板是新增策略主路径。
- 上架门禁覆盖 latestVersion、启用策略、owner、frozen。
- 下架必须确认。
