# 03 · 流程：单资源发行

> **文档角色：** 定义主题、插件、package、普通单文件、普通目录 zip 的首次发行完整流程。本文包含 TTY 路径、AI/CI 路径、字段、接口顺序、异常处理和验收点。

最后更新：2026-09-01

## 0. 流程卡片

| 项 | 内容 |
|---|---|
| 用户目标 | 把手里的一个主题、插件、package、单文件或目录整体 zip 发布为一个可上架的 Freelog 独立资源。 |
| TTY 路径 | `freelog-cli start` 逐步询问资源形态、资源类型、标题/name、文件/构建产物、策略模板、listing 和上架。 |
| AI/CI 路径 | 显式 manifest/config + `--env` + `--yes` + `--json`，缺字段直接失败，不进入 prompt。 |
| Console 对齐点 | 资源创建、类型 leaf、版本创建、策略模板、listing 字段、上架门禁与 Console 业务结果一致。 |
| 平台写入 | `Resource.create`、上传/复用文件、`Resource.createVersion`、`Resource.update` 添加策略和上架。 |
| 本地写入 | manifest 保存用户意图；state 保存 resourceId/version/file/policy/status 等平台事实；失败时 report/nextCommand 可恢复。 |
| Console 接力 | 付费签约、结算、封面裁剪或平台能力无法在 CLI 表达时给 Console 链接和恢复命令。 |

## 1. 适用范围

本流程覆盖一个 Freelog 独立资源的首次发行：

| 资源形态 | 本地输入 | 平台结果 |
|---|---|---|
| 主题 | 主题工程或空目录模板 | 一个主题资源 + 版本 |
| 插件 | 插件工程或空目录模板 | 一个插件资源 + 版本 |
| package / 软件库 | JS/React/Vue package 工程 | 一个软件库资源 + 版本 |
| 普通单文件 | 图片、音频、视频、文档等 | 一个普通资源 + 版本 |
| 普通目录 zip | dist、静态站点、资料目录 | 一个资源，版本文件是 zip |

不覆盖：

- 一个目录里每个文件生成多个资源：见 [05-流程-批量发行.md](./05-流程-批量发行.md)。
- 一个目录组成相册/专辑合集：见 [06-流程-合集RSS自动收录.md](./06-流程-合集RSS自动收录.md)。

## 2. 标准 TTY 总流程

```text
freelog-cli start
  → 选择“发布一个新资源”
  → 选择手里是什么：主题 / 插件 / package / 单文件 / 目录 zip
  → 登录或确认当前账号和环境
  → 选择平台 leaf 资源类型
  → 选择本地模板或 artifact mode
  → 填 title
  → 生成或确认 name
  → 确认创建资源壳
  → 创建资源壳
  → 选择文件或构建产物
  → 校验文件和资源类型能力
  → 上传或复用文件
  → 解析系统属性
  → 补齐属性、依赖、资源选项
  → 创建 1.0.0 版本
  → 选择策略模板
  → 填参数、编译、翻译预览
  → 应用策略
  → 填封面、简介、标签
  → 上架
  → 输出资源链接和下一步
```

## 3. AI/CI 等价流程

AI/CI 不走 prompt。必须准备完整参数或 manifest：

```text
init 或 manifest 准备
  → create --yes --json
  → version set 或直接 publish 所需字段
  → publish --yes --json
  → policy template apply --yes --json
  → online --yes --json
```

要求：

- 每个写命令显式 env。
- 每个写命令显式 yes。
- 缺字段返回 code 4，不进入交互。
- 输出可机器解析的 JSON envelope。

## 4. Step A：选择资源形态

第一问不是资源 type code，而是用户手里是什么。

| 用户选择 | 后续问题 | 默认 artifact |
|---|---|---|
| 主题 | runtime 版本、主题模板、主题 leaf 类型 | directory-zip |
| 插件 | runtime 版本、插件模板、插件 leaf 类型 | directory-zip |
| package | package 模板、namespace、package leaf 类型 | directory-zip |
| 单文件 | 本地文件、平台 leaf 类型 | file |
| 目录 zip | 本地目录、平台 leaf 类型 | directory-zip |

错误处理：

- 用户选“目录”后必须继续问目录含义：整体 zip、批量、合集。
- 如果用户在普通资源流程里选择合集类型，停止并引导到合集流程。
- 如果用户在主题/插件入口选不到对应 leaf，显示类型树证据并停止。

## 5. Step B：选择平台资源类型

```text
拉取资源类型树
  → 展示分类
  → 用户逐级选择
  → 选中 leaf 后显示详情
  → 确认
```

必须展示：

- 类型路径；
- code；
- 是否 leaf；
- 支持本地上传；
- 允许文件格式；
- 文件大小限制；
- 是否支持资源选项/自定义属性；
- 是否与当前资源形态匹配。

异常：

| 情况 | 处理 |
|---|---|
| 类型接口失败 | 不创建工程，不写平台，提示重试 |
| 用户选父类型 | 提示“父类型不可发行”，继续下钻 |
| 搜索无结果 | 回到逐级浏览 |
| package 模板无法唯一映射 leaf | 要求用户显式选择 |
| 类型不支持本地上传 | 阻止 publish，提示该类型不适合本地文件发行 |

## 6. Step C：初始化本地工程

本地工程初始化只写本地，不写平台。

### 6.1 主题

```text
选择主题 runtime
  → 选择主题模板
  → 选择主题 leaf 类型
  → 填 title/name
  → 生成工程
  → 输出 build/create/publish/policy/online 链路
```

### 6.2 插件

```text
选择插件 runtime
  → 选择插件模板
  → 选择插件 leaf 类型
  → 填 title/name
  → 生成工程
```

插件文案不能复用主题文案。插件和主题都可能用 runtime 模板，但平台资源类型不同。

### 6.3 package

```text
选择 package-js / package-react / package-vue
  → 填 namespace
  → 解析或选择软件库 leaf 类型
  → 填 title/name
  → 生成工程
```

package 的 namespace 是工程语义字段，不是平台资源类型字段；但必须写入本地工程供构建和后续提示使用。

### 6.4 单文件 / 目录 zip

```text
选择本地路径
  → 选择资源类型
  → 填 title/name
  → 写 manifest
  → 输出下一步
```

目录 zip 必须写入 ignore 规则说明，并提示哪些文件永远不会打包：VCS、CLI 状态、凭据、密钥类文件。

## 7. Step D：创建资源壳

接口顺序：

```text
检查 name 是否占用
  → Resource.create
  → 读取资源详情
  → 保存平台事实
```

字段：

| 字段 | 约束 |
|---|---|
| title | 必填，最多 100 字 |
| name | 1–60 字，规范化后查重 |
| resourceTypeCode | 必填，leaf |
| resourceTypeName | 仅自定义类型需要 |

确认页：

```text
将创建资源：
  环境：<env>
  账号：<username>
  标题：<title>
  授权标识：<username>/<name>
  类型：<type path> (<code>)
```

失败：

| 情况 | 处理 |
|---|---|
| name 已占用 | 给建议 name，允许返回编辑 |
| create 成功但本地保存失败 | 显示 resourceId，要求 bind/pull 对账 |
| 网络未知 | 记录 unknown，不自动重试 |

## 8. Step E：发布首版

接口顺序：

```text
读取资源类型配置
  → 校验文件路径和 artifact mode
  → 目录 zip 时确定性压缩
  → 计算 sha1
  → Storage.fileIsExist
  → Resource.getResourceBySha1
  → Storage.uploadFile 或复用
  → PropertyParser 解析属性
  → 组装 createVersion payload
  → Resource.createVersion
  → 保存版本事实
```

字段：

| 字段 | 规则 |
|---|---|
| version | 首版固定 1.0.0 |
| filePath | 必须存在；file 模式是文件，directory-zip 模式是目录 |
| artifactMode | file 或 directory-zip |
| filename | 上传文件名或 zip 文件名 |
| fileSha1 | 由本地计算和平台复用决定 |
| description | 可空 |
| runtimeVersion | 主题/插件等需要 runtime 的类型必须填写 |
| inputAttrs | 来自文件解析和用户补充 |
| customPropertyDescriptors | 仅类型支持时允许 |
| dependencies | 发布前授权必须完整 |
| baseUpcastResources | 发布前授权必须完整 |
| authExcludedItems | 按授权树结果处理 |

失败：

| 情况 | 处理 |
|---|---|
| build 失败 | 停在本地，不上传 |
| 文件不存在 | code 4，提示路径 |
| 类型不接受该格式 | code 4，显示类型允许格式 |
| 文件超大小 | code 4，显示当前大小和上限 |
| sha1 他人已发行 | 阻断 |
| sha1 自己已发行 | 单资源可确认继续，批量不适用 |
| 上传失败 | 不创建版本 |
| createVersion 未知 | report unknown，禁止盲重试 |

## 9. Step F：策略模板

接口顺序：

```text
Policy.policyTemplates
  → 选择模板
  → 填 policyName 和模板变量
  → Policy.policyReCompile
  → Policy.policyTranslation
  → 检查策略名和 policyText 重复
  → Resource.update.addPolicies
```

交互必须先展示可用模板，不允许普通用户默认手写 DSL。

异常：

| 情况 | 处理 |
|---|---|
| 无模板 | 说明资源类型无可用模板，给 Console 链接 |
| 变量不合法 | 停在变量编辑 |
| 编译失败 | 展示错误，不写平台 |
| 交易事件需要结算 | handoff 到 Console 结算页 |
| 重复策略名或文本 | 阻止应用 |

## 10. Step G：Listing 和上架

Listing 字段：

| 字段 | 约束 |
|---|---|
| cover | jpg/jpeg/jpe/png/gif，最大 5MB；CLI 不提供裁剪 |
| intro | 最多 200 字 |
| tags | 最多 20 个；单项最多 20 字；去掉 `#`；不重复 |

上线门禁：

```text
读取资源详情
  → 有 latestVersion
  → 有至少一条启用策略
  → 非 frozen
  → owner 是当前账号
  → Resource.update status=1
```

成功输出：

```text
发行完成：
  资源：<title>
  授权标识：<username>/<name>
  版本：1.0.0
  状态：已上架
  Console：<url>
  后续：更新版本 / 下架 / 添加到合集 / 添加到节点
```

## 11. 验收标准

- TTY 从 `start` 能完整完成普通单文件首发。
- 主题、插件、package 都能从一等入口进入，不依赖搜索猜测。
- 目录 zip、批量、合集不会混淆。
- 策略新增默认走模板列表。
- 每一步写平台前都有 env、账号、目标和副作用摘要。
- 非 TTY 缺字段不 prompt，返回结构化错误。
