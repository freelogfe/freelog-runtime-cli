# 05 · 流程：批量发行

> **文档角色：** 定义把一个本地目录中的多个文件批量创建为多个独立 Freelog 资源的完整流程，包括预览、分批、createBatch、报告和恢复。

最后更新：2026-09-01

## 0. 流程卡片

| 项 | 内容 |
|---|---|
| 用户目标 | 把一个本地目录里的多个文件批量创建为多个独立资源，而不是创建合集或目录 zip。 |
| TTY 路径 | `freelog-cli start` 选择批量发行，扫描目录，预览候选/跳过/拒绝项，统一或逐项确认字段和策略，再分批写平台。 |
| AI/CI 路径 | batch config + `resource import-dir <dir> --env <env> --yes --json/--json-lines`，通过 report 判断后续恢复。 |
| Console 对齐点 | 批量创建、文件限制、sha1 占用、资源类型 leaf、策略和上架门禁与 Console 结果一致。 |
| 平台写入 | 上传/复用文件、属性解析、按 20 项拆分 `Resource.createBatch`；不适合批量接口的项降级逐项创建并在预览中说明。 |
| 本地写入 | 每个成功资源可生成独立维护工程或绑定信息；长任务必须写 report；unknown 不自动重试。 |
| Console 接力 | 付费策略/授权、结算、封面裁剪、批量接口不支持的复杂字段给出 Console 或逐项处理路径。 |

## 1. 产品定义

批量发行的模型是：

```text
一个本地目录
  → N 个文件
  → N 个独立资源
  → 每个资源都有自己的版本、策略、状态和后续维护工程
```

批量发行不是合集，也不是目录 zip。

| 容易混淆 | 正确解释 |
|---|---|
| 批量发行 | 多个独立资源 |
| 目录 zip | 一个资源，版本文件是 zip |
| 合集 | 一个合集资源 + 多个条目 |

## 2. TTY 总流程

```text
选择“批量发布一个本地文件夹”
  → 选择目录
  → 选择批量资源类型
  → 扫描文件
  → 应用 ignore
  → 展示候选/跳过/拒绝
  → 为每项生成 title/name
  → 用户编辑或确认批量字段
  → 选择策略模板或确认稍后处理
  → 分批上传和 createBatch
  → 输出 report
  → 失败项可 retry，未知项需对账
```

## 3. AI/CI 总流程

```text
准备 batch config
  → resource import-dir <dir> --config <file> --env <env> --yes --json
  → 读取 JSON/NDJSON 和 report
  → 如失败，retry/resume
```

AI/CI 必须显式提供：

- env；
- resourceTypeCode 或每项 resourceTypeCode；
- yes；
- policy 或明确允许无策略；
- 输出 report 路径。

## 4. 扫描阶段

扫描规则：

| 项 | 规则 |
|---|---|
| 目录 | 必须存在，必须可读 |
| 文件 | 默认只处理普通文件 |
| 子目录 | 默认可递归，但应展示数量 |
| ignore | 读取 `.freelogignore` |
| 强制排除 | `.git`、`.freelog`、`.freelog-auth`、密钥、系统临时文件 |
| 空目录 | 停止，不写平台 |
| 超大目录 | 展示数量和预计批次数，确认后继续 |

预览必须显示：

```text
扫描结果：
  候选文件：N
  跳过文件：M
  拒绝文件：K
  预计平台批次：B
  report：<path>
```

## 5. 类型和文件限制

批量类型必须支持批量创建。

字段：

| 字段 | 规则 |
|---|---|
| resourceTypeCode | 必填；支持批量创建的 leaf |
| resourceTypeName | 批量不允许新增自定义类型 |
| file size | 视频一级类型最大 1GB；非视频最大 200MB；再叠加平台类型限制 |
| file format | 来自类型配置 |
| sha1 占用 | 同用户或他人已用都作为错误项 |
| batch size | 每次 createBatch 最多 20 个 |

CLI 可以接受超过 20 个文件，但必须拆成多个 createBatch 请求。

## 6. 每项字段生成

每个文件生成一项资源候选：

| 字段 | 默认 | 可编辑 | 约束 |
|---|---|---:|---|
| resourceTitle | 文件名去扩展名 | 是 | 最多 100 |
| name | 标题规范化 + 服务端去重 | 是 | 1–60，批内不重复，平台不冲突 |
| version | 1.0.0 | 可选 | semver |
| description | 空 | 是 | 可空 |
| intro | 空 | 是 | 最多 200 |
| tags | 空 | 是 | 最多 20 个，单项 20 |
| cover | 默认无 | 是 | 图片，最大 5MB |
| policy | 模板或配置 | 是 | 策略名/文本不重复 |
| inputAttrs | 解析后生成 | 是 | 按属性类型 |
| customPropertyDescriptors | 类型支持时允许 | 是 | 按字段总账 |

## 7. 策略处理

批量 TTY 可提供两种体验：

1. 为全部资源选择同一个策略模板；
2. 先发行为未上架/待策略状态，完成后进入策略批处理或逐个处理。

AI/CI 必须显式说明策略来源：

- 模板 ID + 参数；
- policy 文件；
- 或明确允许无策略并不上架。

不能在非交互模式里默认“无策略也继续并上架”。

## 8. 平台写入顺序

```text
为每项计算 sha1
  → 检查文件占用
  → 上传或复用存储文件
  → 解析属性
  → 生成可用 name
  → 按类型/自定义类型分组
  → 每组每 20 个一批调用 createBatch
  → 记录逐项结果
  → 成功项生成可维护子工程或绑定信息
```

如果某项带有 createBatch 不支持的字段，应自动降级为逐项 create + createVersion，但必须在预览中说明。

## 9. 结果状态

每项结果必须区分：

| 状态 | 含义 | 可自动 retry |
|---|---|---:|
| success | 远端创建和本地记录都成功 | 否 |
| failed | 已知失败，未创建远端或远端明确失败 | 是 |
| skipped | 用户或规则跳过 | 否 |
| rejected | 字段/类型/文件不合规，未发请求 | 修正后可 |
| remote_succeeded_local_pending | 平台成功，本地回写未完成 | 先本地恢复，不重复远端 |
| remote_outcome_unknown | 请求可能已发出但结果未知 | 否，必须人工对账 |

## 10. report 设计

批量报告是恢复依据，不是日志。

必须包含：

- runId；
- command；
- env；
- auth username；
- 输入目录 fingerprint；
- 配置 fingerprint；
- startedAt / finishedAt；
- 每项 idempotencyKey；
- 每项 stage；
- 每项 result；
- resourceId/versionId/fileSha1；
- 错误 code/message；
- nextCommand。

报告必须可被 `resume` 和 `retry` 消费。

## 11. resume / retry

```text
resume <report>
  → 校验 env/auth/input/config
  → 继续安全阶段
```

```text
retry <report>
  → 只处理 failed/rejected 修复后的项
  → 不处理 success/unknown
```

安全规则：

- report env 与当前 env 不一致，停止。
- 当前账号与 report owner 不一致，停止。
- 输入目录 fingerprint 变化，停止或要求重新扫描。
- unknown 项必须对账，不自动重复创建。
- success 项永不重复提交。

## 12. 用户实际会遇到的情况

| 情况 | 产品处理 |
|---|---|
| 目录里混入无关文件 | 预览列为 skipped/rejected，给原因 |
| 文件很多 | 显示批次数和预计时间 |
| 中途断网 | 已知失败可 retry，未知项对账 |
| 部分文件名生成重复 name | 批内去重，再调用服务端生成 |
| 某个文件超大小 | 单项 rejected，不影响其它项 |
| 用户想把结果做成合集 | 不在批量流程偷偷创建合集；完成后提示可导入合集 |
| 用户想一键上架 | 只有策略和门禁满足时才允许 |

## 13. 验收标准

- 大目录不会一次提交超过 20 个 createBatch 项。
- 预览能区分候选、跳过、拒绝。
- 每项结果状态可恢复。
- unknown 不自动重试。
- 批量和合集不会混淆。
- AI/CI 可只靠 JSON/NDJSON/report 判断下一步。
