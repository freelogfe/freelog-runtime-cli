# 01 · 业务对象与状态模型

> **文档角色：** 定义一期 CLI 必须理解和维护的业务对象、状态、身份模式和本地/平台边界。流程文档中的所有动作都以本文对象模型为基础。

最后更新：2026-09-01

## 1. 核心对象

| 对象 | 用户理解 | 平台事实 | CLI 表达 |
|---|---|---|---|
| 用户身份 | 当前是谁在操作 | userId、username、登录凭据 | auth scope、当前 env |
| 环境 | 写哪个平台环境 | dev/test/prod API | `--env`、项目默认环境、auth 环境 |
| 资源类型 | 资源属于哪一类 | 类型树 leaf、能力配置 | 逐级选择 / 搜索 / manifest type |
| 资源壳 | 一个可被授权和上架的资源主体 | resourceId、name、title、type | create 后绑定 |
| 版本 | 某次发布的文件和属性 | version、fileSha1、filename、attrs | version intent + publish result |
| Listing | 资源展示信息 | title、intro、coverImages、tags | update intent |
| 策略 | 授权规则 | policyName、policyText、status | 模板选择、变量、编译结果 |
| 依赖 | 当前版本依赖其它资源 | dependencies、baseUpcastResources | dep intent + auth preflight |
| 合集 | subjectType=4 的资源 | resourceId + collection version | collection project/session |
| 合集条目 | 合集目录中的资源引用 | draft item、sort、itemTitle | collection item intent |
| RSS 绑定 | feed 与合集关系 | feedUrl、ownerEmail、sync status | rss preview/bind/sync |
| collect-rules | 自动收录规则 | status、conditionType、filterConditions | 用户友好规则编辑 |
| 报告 | 长任务恢复依据 | 无统一 Console UI 对象 | batch/studio report |

## 2. 资源类型模型

资源类型不是静态配置。CLI 每次需要发行或校验时，应从平台获取：

```text
资源类型树
  → 父子关系
  → 是否 leaf
  → 是否支持本地上传
  → 文件格式和大小限制
  → 系统属性配置
  → 自定义属性/资源选项能力
  → 合集条目来源能力
```

### 2.1 类型选择规则

| 场景 | 规则 |
|---|---|
| 普通资源 | 必须选择 leaf 类型；可从任意一级逐级进入 |
| 主题 | 从主题大类进入，只能选择主题 leaf |
| 插件 | 从插件大类进入，只能选择插件 leaf |
| package | 先选 package 模板，再映射或选择平台 leaf |
| 批量 | 只能选择支持批量创建的类型；不支持自定义类型 |
| 合集 | 只能选择合集类型 leaf；不支持自定义类型 |
| collect-rules 资源类型条件 | 只能选择 leaf，最终值是 `resourceTypeCode` |

父类型不能发行；选到父类型时只能继续下钻或返回。

### 2.2 自定义类型规则

独立资源允许在特定终止选择场景添加自定义子类型名。合集和批量不允许。

自定义类型名规则：

- 必填；
- 1–40 字；
- 支持中文、英文、数字、`-`、`&`、`.`、`,`；
- 区分大小写；
- 不能用来绕过 leaf 选择。

## 3. 独立资源状态机

```text
未初始化
  → 本地工程已初始化
  → 资源壳已创建
  → 版本意图已准备
  → 版本已发布
  → 策略已添加
  → 已上架

任意已创建状态
  → listing 可维护
  → 策略可新增/启停
  → 可下架
  → 可创建新版本
```

| 状态 | 允许动作 | 禁止动作 |
|---|---|---|
| 未初始化 | start、init、session 首发 | publish、online |
| 本地工程已初始化 | create、validate、diff | online |
| 资源壳已创建 | version set、publish、update listing | online（无版本/策略时） |
| 版本已发布 | policy template apply、update listing | 上架无策略 |
| 策略已添加 | online、policy set | 停用最后一条已启用策略后仍上架 |
| 已上架 | update listing、new version、offline | 关闭最后一条启用策略 |
| frozen | 只读查看、handoff | createVersion、policy、online/offline |

## 4. 版本状态机

```text
未设置版本意图
  → 选择文件或 reuse 版本
  → 计算 sha1 / 上传 / 属性解析
  → 生成 createVersion payload
  → 平台创建版本
  → 保存发布事实
```

版本规则：

- 首版默认且固定为 `1.0.0`。
- 后续版本必须是有效 semver，且大于 latestVersion。
- 改文件、改依赖列表、改版本号，只能创建新版本。
- 已发布版本编辑只能改说明、输入属性、自定义属性、依赖解析项等可编辑字段。
- `reuse-version` 表示复用旧版本文件 sha1 创建新版本，不重新解析本地文件。

## 5. 策略状态机

```text
无策略
  → 拉取模板列表
  → 选择模板
  → 填变量
  → 编译策略文本
  → 翻译预览
  → 检查重复
  → 应用策略
  → 可上线
```

策略主路径是模板 Builder。手写 policy 文件只属于高级、迁移、AI/CI fallback，不能作为普通 TTY 默认路径。

## 6. 合集状态机

```text
未创建
  → 创建合集壳
  → 添加条目或绑定 RSS
  → 编辑目录草稿
  → 发布合集版本
  → 添加策略
  → 设置 collect-rules
  → 上架
```

合集有四层，不得混淆：

| 层 | 含义 | 典型动作 |
|---|---|---|
| 合集壳 | subjectType=4 的资源主体 | create/update/online/offline |
| 子资源 | 被合集引用的普通资源 | create/publish/online |
| 目录草稿 | 合集条目列表和排序 | add/update/remove/reorder |
| 合集版本 | 发布后的合集目录与属性快照 | collection publish |

“把本地目录做成合集”不是上传 zip，而是创建子资源、加入目录草稿、发布合集版本。

## 7. RSS 状态机

```text
未绑定 RSS
  → 输入 feed URL
  → preview
  → ownerEmail 校验
  → send code
  → verify code / bind
  → syncing
  → synced 或 failed-items

已绑定 RSS
  → status
  → sync
  → compare 新 URL
  → 高风险确认
  → 重新 bind
```

RSS 相关资源需要锁定 Console 锁定的 feed 托管能力。当前 Console 允许用户继续维护 tags，但禁用标题、封面、简介、普通版本更新、目录展示/条目等与 feed 同步冲突的动作。CLI 没有 UI，不代表可以绕过锁定；也不能把 Console 仍允许的 tags 错误锁死。

## 8. collect-rules 状态机

```text
读取当前规则
  → 选择是否启用
  → 选择持续收录或收录到此为止
  → 选择 all/any
  → 编辑条件列表
  → 预览语义
  → 保存
```

内部字段要翻译为用户语言：

| 平台字段 | 用户语言 |
|---|---|
| `status=1` | 启用自动收录 |
| `status=0` | 关闭自动收录 |
| `serializeStatus=0` | 持续收录后续符合条件资源 |
| `serializeStatus=1` | 当前收录完成后停止继续收录 |
| `conditionType=1` | 全部条件都满足 |
| `conditionType=2` | 任一条件满足 |

## 9. 本地 Store 模型

CLI 有两类业务 Store：

| Store | 用途 | 保存什么 | 不保存什么 |
|---|---|---|---|
| 工程 Store | 长期维护一个资源或合集 | manifest、state、report | token 明文、密码 |
| 会话 Store | 临时一次或一个进程内完成事项 | 内存中的资源/版本/策略意图 | manifest/state |

工程 Store 中：

- manifest 保存用户意图；
- state 保存平台事实；
- report 保存长任务恢复事实。

会话 Store 中：

- 单命令 `--session` 结束即销毁；
- `freelog-cli session` 在一个进程里连续维护临时上下文；
- `freelog-cli studio` 用临时凭据处理多账号/多文件，但可导出子工程。

## 10. Auth 模型

登录信息和资源状态是两个正交维度。

| 模式 | Auth 是否落盘 | Store 是否落盘 | 入口 | 适合 |
|---|---:|---:|---|---|
| 工程模式 | 是 | 是 | login + 工程命令 | 长期维护、Git、CI |
| 单命令会话 | 是 | 否 | `--session --resource-id` | 维护线上资源一次动作 |
| studio | 否 | 是 | `studio` | 多账号、多文件临时工作台 |
| 交互 session | 否 | 否 | `session` | 一个终端内连续做完 |

安全规则：

- token、authorization、cookie 落盘必须加密。
- auth 环境与命令 env 不一致时写操作失败。
- 工作区凭据损坏时不回退全局账号。
- session/studio 不读取磁盘 auth。
- 密码不写入任何本地文件或文档。
