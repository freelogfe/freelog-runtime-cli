# 01 · 完整产品与实现方案

> **文档角色：** 从需求分析、Console 业务分析、CLI 环境差异分析推导出一期完整产品解决方案。

最后更新：2026-09-02

## 1. 一句话目标

Freelog CLI 的一期目标不是复制 Console 页面，而是让用户、AI 或 CI 在本地电脑上用一次连续会话完成资源发行与维护：选择资源类型、准备本地文件、填写 Console 同等字段、预检、上传、创建或更新版本、维护策略依赖、上下架、创建合集/RSS，并在失败时知道平台和本地分别发生了什么。

## 2. 用户需求分析

| 用户 | 真实目标 | CLI 必须解决的问题 |
|---|---|---|
| 主题开发者 | 从模板创建主题工程，构建后发布为主题资源 | 类型逐级选择、模板生成、构建产物压缩、版本发布、上架提示 |
| 插件开发者 | 从插件模板发布插件资源 | 与主题类似，但资源类型、模板和平台能力不同 |
| 前端库/软件库开发者 | 发布可被其它资源依赖的库 | 类型必须选到 Console 叶子类型，不能把父类直接写入 manifest |
| 普通作者 | 把本地文件或目录发布成资源 | 不要求理解工程概念；向导必须解释文件、目录压缩、版本号和 listing |
| 合集维护者 / RSS 维护者 | 把多个资源组织成合集，或用 RSS/collect-rules 自动维护条目 | 区分“批量独立资源”和“合集条目”；处理 100/1000 等 Console 规则 |
| 运营/维护者 | 管理已有线上资源策略、依赖、上下架、listing | 不一定有本地工程；需要 session/studio 或 bind 后维护 |
| AI/CI | 代替人完成稳定发布流程 | 需要 manifest、非交互参数、JSON/NDJSON、exit code、幂等报告 |

## 3. Console 业务分析

Console 在资源域的本质业务链路如下：

```text
资源类型选择
  → 资源基础信息
  → 创建资源或选择已有资源
  → 版本文件/目录/属性/依赖
  → 策略模板选择与策略编译
  → listing 信息
  → 上架/下架
  → 后续维护
```

Console 的优势是 UI 可以天然约束输入：下拉选择只给合法资源类型，表单组件显示字数限制，按钮 disabled 阻止未满足前置条件，列表页和侧边栏提供上下文。

CLI 必须对齐的是业务结果和硬约束：

- 资源类型必须来自平台类型树，只能提交可发行叶子类型。
- 标题、名称、简介、标签、封面、版本号、依赖、授权、策略等字段要采用 Console 同等限制。
- 创建、更新、上架、下架、合集、RSS 和 collect-rules 要调用与 Console 语义一致的平台接口。
- RSS 新绑定后，title/cover/intro 由 feed 锁定，tags 仍可维护。
- RSS 对比差异必须按 feed item 的 guid/数量计算，`matchedItemCount > 1000` 时阻止继续并提示原因。
- RSS 时间范围按平台约定传 `YYYY-MM-DD HH:mm:ss`，起止时间补 `00:00:00` / `23:59:59`。
- RSS 验证码错误要识别 `VerificationCodeInvalid` / `wrong_verified_code`，不能泛化成普通失败。

Console 无法直接替代或 CLI 不应复制的部分：

- 支付、签约、收银台、验证码、浏览器登录态等需要跳转 Console。
- 可视化编辑、节点运营、结算、收藏、详情预览不进入一期 CLI。
- Console 的多页面流程不能机械映射为多条必须手敲的命令；TTY 主路径应是一条命令进入连续向导。

## 4. CLI 环境差异分析

CLI 与 Console 的差异决定了产品不能只是 API 包装：

| 差异 | 风险 | 产品处理 |
|---|---|---|
| 无 UI 表单组件 | 用户看不到限制，容易提交错误字段 | 每次输入前展示约束，输入时同一校验器即时反馈，写入前再预检 |
| 有本地文件和目录 | 文件不存在、目录过大、压缩不确定、ignore 不一致 | 文件扫描、构建、压缩、SHA1、报告恢复是一等流程 |
| 可被 AI/CI 调用 | 不能依赖交互确认和自然语言输出 | 所有核心流程支持非交互、JSON/NDJSON、稳定 exit code |
| 有本地状态 | manifest 与平台可能漂移 | manifest 表达意图，state 表达平台事实，冲突默认停止 |
| 有多账号工作区 | 容易用错账号更新资源 | 凭据与资源状态分离，owner/userId/env 门禁必须在服务层执行 |
| 终端长任务可中断 | 平台写入和本地回写可能只完成一半 | 写入报告记录阶段，支持 resume/retry/对账 |
| 用户可能只维护线上资源 | 不一定想创建长期工程 | 提供 session/studio 和 bind/export-project，不强迫 manifest |

## 5. 产品原则

1. **一条主命令能完成主任务。** TTY 下 `freelog-cli studio` / `freelog-cli start` 应让用户一路完成发行或维护，不要求记忆命令链。
2. **业务对齐 Console，体验按 CLI 重做。** 对齐字段、接口、流程结果；不照搬页面跳转。
3. **资源类型先可浏览、再可搜索。** 默认支持像旧版一样逐级选择；搜索是加速能力，不是唯一入口。主题、插件、前端库/软件库、合集等类型必须在一级/二级选择中可见。
4. **策略先看模板再应用。** 用户应先浏览可选策略模板，理解模板说明和字段，再选择应用；不能让用户凭空输入策略结构。
5. **写入前必须有 checkpoint。** 平台环境、账号、owner、资源 ID、版本、文件 SHA1、副作用必须展示。
6. **失败必须可恢复。** 成功到哪一步、平台是否可能已写入、本地是否待回写，都要明确。
7. **AI/CI 与人类共用业务规则。** 差异只在输入/输出形式，不在门禁宽松度。

## 6. 总流程拓扑

```text
入口
  ├─ start/studio：人类连续向导
  ├─ 显式命令：publish/update/collection/rss/maintain/batch
  └─ AI/CI：manifest + flags + --json/--json-lines

身份与环境
  → 选择/校验 env
  → 登录或读取凭据
  → owner 与资源状态门禁

任务选择
  ├─ 首次发行单资源
  ├─ 更新已有资源版本
  ├─ 只维护线上资源
  ├─ 批量发行多个独立资源
  └─ 创建/维护合集、RSS、collect-rules

执行
  → 类型/字段/文件/策略/依赖预检
  → 构建或压缩
  → 上传
  → 平台写入
  → 本地状态回写
  → 后续动作：上架、打开 Console、导出工程、继续维护
```

## 7. 主命令设计

| 命令 | 定位 | 人类体验 | AI/CI 体验 |
|---|---|---|---|
| `freelog-cli start` | 新手任务入口 | 选择“发布/更新/维护/合集/RSS/批量” | 可用 `--task` 固定任务 |
| `freelog-cli studio` | 多账号工作区 | 登录一次，在同一进程连续管理多个资源 | 不推荐 CI |
| `freelog-cli session` | 纯临时会话 | 不留下长期工程状态 | 适合一次性维护 |
| `freelog-cli init` | 建立本地工程 | 逐级选择类型和模板 | flags + manifest |
| `freelog-cli publish` | 首次发行或发布版本 | 缺字段进入补全向导 | 缺字段 code 4 |
| `freelog-cli update` | 更新已有资源版本/listing | 选择已有资源或读取 state | 需要 resourceId/version |
| `freelog-cli policy` | 策略模板浏览与应用 | 先 list，再 apply | 模板 ID + 参数 |
| `freelog-cli collection` | 合集创建与维护 | 添加条目、排序、merge draft | 批量输入文件 |
| `freelog-cli rss` | RSS 绑定与同步 | 预览差异、验证码、同步 | JSON 差异和结果 |
| `freelog-cli batch` | 批量独立资源 | 扫描、确认、报告恢复 | NDJSON + report |
| `freelog-cli doctor` | 环境和项目诊断 | 给出修复建议 | 只读检查 |

## 8. 状态与安全模型

| 对象 | 保存什么 | 不保存什么 |
|---|---|---|
| `freelog.manifest.json` | 用户长期意图：类型、标题、版本、文件、策略、依赖 | token、authorization、平台临时响应 |
| `.freelog/state.json` | 平台事实：resourceId、owner、版本、同步指纹、env | 用户凭据、未确认的平台写入 |
| `.freelog/reports/*.json` | 长任务阶段、每项结果、恢复信息 | 明文密码、cookie、authorization |
| `.freelog-auth` / 全局 auth | 加密后的登录凭据 | 可提交内容 |
| `auth.key` | 本机 AES-256-GCM 主密钥 | 不进入仓库 |

凭据和资源状态是两个正交维度：

| 模式 | Auth | Store | 入口 |
|---|---|---|---|
| 工程模式 | 落盘加密 | manifest/state | 普通命令 |
| 命令会话 | 可读落盘凭据 | 临时 Store | `xxx --session` |
| studio | 进程内凭据 | 多工程 Store | `studio` |
| session | 进程内凭据 | 临时 Store | `session` |

## 9. Console 接力

CLI 不能完成但应主动提示跳转的事项：

- 需要支付、签约、收银台或用户授权确认。
- 需要浏览器验证码或第三方授权。
- 需要可视化编辑器、节点运营、结算等 Console 专属能力。
- 平台返回需要人工确认的业务状态。

提示必须包含：为什么不能在 CLI 完成、建议打开的 Console 地址、回到 CLI 后如何继续，例如 `pull`、`status`、`resume`。
