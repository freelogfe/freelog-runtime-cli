# 02 · 流程字段接口总账

> **文档角色：** 把 Console 业务流程、字段约束、平台接口和 CLI 处理方式汇总成实现可用的总账。

最后更新：2026-09-02

## 1. 资源类型选择

### 流程

```text
读取平台资源类型树
  → 展示一级分类
  → 逐级选择到叶子类型
  → 可选搜索加速
  → 校验类型能力
  → 写入 manifest 或会话意图
```

### 字段和约束

| 字段 | 约束 | CLI 处理 |
|---|---|---|
| `resourceTypeCode` | 必须来自平台类型树；必须是可发行叶子类型 | 默认逐级选择；搜索结果按路径展示；非交互必须显式传入 |
| `resourceTypeName` | 只用于展示，不作为持久真源 | 从平台响应回填 |
| `artifactMode` | `file` 或 `directory-zip` | 来自类型能力、模板能力或显式参数；冲突时报错 |

### 接口

- `Resource.resourceTypes`
- `Resource.ListSimpleByParentCode`
- `Resource.getResourceTypeInfoByCode`

## 2. 单资源首次发行

### TTY 流程

```text
start/studio
  → 选择“发布新资源”
  → 选择资源类型：逐级浏览或搜索
  → 选择本地文件/目录/模板
  → 填基础信息：title/name/intro/cover/tags
  → 选择策略模板并应用
  → 可选依赖和授权排除
  → 预检 checkpoint
  → 创建资源
  → 上传文件或压缩目录
  → 创建首个版本
  → 可选 listing 和上架
  → 写入 state/report
```

### AI/CI 流程

```text
manifest + flags
  → validate
  → publish --yes --json
  → JSON envelope 输出 resourceId/versionId/status
```

### 字段和约束

| 字段 | 约束 | 提示时机 |
|---|---|---|
| `title / resourceTitle` | 必填；长度按 Console 表单限制；不能只输入空白 | 输入前展示限制，写入前再次校验 |
| `name` | 必填；作为授权名/资源标识时必须符合平台规则 | 同步检查重复和非法字符 |
| `intro` | 按 Console 简介长度限制 | 超长立即提示，不截断 |
| `cover` | URL 或本地文件；类型和大小按平台能力 | 本地文件先上传或转平台路径 |
| `tags` | 数量、单标签长度按 Console 限制 | 去重、去空白、保留用户顺序 |
| `version` | 版本号必须合法，已发布版本不可重复 | 更新时建议 bump |
| `file` / `directory` | 文件存在；目录可压缩；ignore 生效 | 展示大小、SHA1、压缩计划 |
| `policyTemplateId` | 必须来自模板列表 | 先 `policy template list` 再 `apply` |
| `policyName` | 必填；按 Console 限制 | 应用模板时生成，可编辑 |

### 接口

- `Resource.create`
- `Resource.createVersion`
- `Resource.updateResourceVersionInfo`
- `Policy.policyTemplates`
- `Policy.policyReCompile`
- `Policy.policyTranslation`

## 3. 已有资源更新版本

### 流程

```text
读取 state 或选择线上资源
  → 拉取远端事实
  → 校验 owner/env/resourceId
  → 选择更新内容：文件、版本号、描述、属性、依赖、授权排除
  → 预检差异
  → 上传新文件或压缩目录
  → 创建新版本
  → 可选更新 listing
  → 写入 state/report
```

### 关键处理

- 已发布版本不可原地改文件身份，必须创建新版本。
- 可以从 latestVersion 继承可继承字段，但执行计划要展示继承来源。
- 本地和远端同字段都变化时停止，不默认覆盖。
- 远端写成功但本地回写失败时进入 `remote_succeeded_local_pending`，恢复时先对账。

### 接口

- `Resource.getResourceInfo`
- `Resource.createVersion`
- `Resource.updateResourceVersionInfo`
- `Resource.update`

## 4. Listing 与上下架

### 流程

```text
读取资源和最新版本
  → 编辑 listing：cover/intro/tags
  → 校验字段
  → 保存 listing
  → 用户选择上架或保持草稿
```

### 字段

| 字段 | 约束 | CLI 处理 |
|---|---|---|
| `cover` | Console 可维护时才允许编辑 | RSS 锁定场景不允许改 |
| `intro` | Console 可维护时才允许编辑 | RSS 锁定场景不允许改 |
| `tags` | 数量和长度限制 | RSS 场景仍允许维护 |
| `onlineStatus` | 上架前必须满足平台门禁 | 失败给出 Console 接力或修复命令 |

### 接口

- `Resource.update`
- 平台上架/下架接口按现有 SDK 映射调用。

## 5. 策略模板与策略应用

### 正确体验

```text
读取策略模板列表
  → 展示模板名称、说明、适用场景和需要填写的参数
  → 用户选择模板
  → CLI 展开参数表单
  → 编译/翻译/预览
  → 应用到资源
```

不能让用户先手写策略 JSON，也不能把旧实现中的“直接输入策略字段”作为主路径。高级用户可导入策略文件，但仍要经过编译和平台校验。

### 接口

- `Policy.policyTemplates`
- `Policy.policyReCompile`
- `Policy.policyTranslation`

## 6. 依赖与授权排除

### 流程

```text
选择依赖资源
  → 拉取授权树
  → 展示可选授权和冲突
  → 用户确认授权选择或排除项
  → 写入版本意图
  → 发布版本时随 payload 提交
```

### 处理原则

- CLI 可以提供搜索，但必须支持从资源/授权树逐级选择。
- 依赖变更影响版本，不应偷偷修改已发布版本。
- 授权树必须来自平台，不能依赖本地缓存硬猜。

## 7. 批量独立资源

### 流程

```text
选择输入目录
  → 扫描文件并应用 ignore
  → 选择资源类型和命名规则
  → 展示将创建/跳过/失败的项
  → 分批创建资源和版本
  → 每项写入 report
  → 支持 resume/retry
```

### 约束

- 批量独立资源不是合集；每个文件对应一个独立资源。
- 平台批次限制由 CLI 自动分批，但报告必须按单项记录。
- 写请求已发出但响应未知时记录 `remote_outcome_unknown`，不得自动重试创建。

### 接口

- `Resource.createBatch`
- 缺少批量能力时，只有在调用前可证明不支持，才允许逐项创建。

## 8. 合集

### 流程

```text
创建或绑定合集资源
  → 添加已有资源或从本地目录创建子资源
  → 管理条目顺序和展示
  → 保存目录草稿
  → 可选 merge catalogue draft
  → 更新合集 listing / 上架
```

### 字段

| 字段 | 约束 | CLI 处理 |
|---|---|---|
| `items` | 单次选择/提交最多 100 项 | 超过时分批，不预设合集总容量 |
| `isMergeCatalogueDraft` | 用户必须明确选择是否合并草稿 | 不能静默 merge |
| `display` / `sort` | 顺序要可预览 | 提供列表预览和 diff |

### 接口

- `Resource.updateCollection`

## 9. RSS 绑定与同步

### 新绑定流程

```text
输入 feedUrl
  → 平台 compare
  → 如需验证码，提示用户完成验证码
  → 识别 feed title/cover/intro
  → 创建或更新 RSS 合集
  → title/cover/intro 锁定为 feed 信息
  → tags 仍允许手动维护
```

### 差异同步流程

```text
读取 oldFeedItemCount/newFeedItemCount/guidMatchedCount/matchedItemCount
  → 计算新增、删除和匹配
  → matchedItemCount > 1000 时阻止继续
  → 展示差异
  → 用户确认同步
  → 保存同步状态，防止重复同步
```

新增数量口径：`max(oldFeedItemCount, newFeedItemCount) - guidMatchedCount`，最终以平台响应为准。

### 字段和错误

| 字段/错误 | 规则 |
|---|---|
| `feedUrl` | 必填，必须是可访问 RSS 地址 |
| `verificationCode` | 平台要求时才输入 |
| `conditionType` | collect-rules 使用，必须来自平台支持枚举 |
| `dateRange` | 传 `YYYY-MM-DD HH:mm:ss`，日期补全天边界 |
| `VerificationCodeInvalid` / `wrong_verified_code` | 显示为验证码错误，可重试验证码，不重启整个流程 |

### 接口

- `Resource.bindRssFeed`
- `Resource.updateCollection`

## 10. collect-rules 自动收录

### 流程

```text
选择合集
  → 查看当前规则
  → 选择规则类型 conditionType
  → 填写规则参数
  → 预览影响范围
  → 保存规则
```

### 原则

- 如果 Console 支持 collect-rules，CLI 必须按同一接口和字段语义支持。
- 规则模板/枚举优先来自平台，不在 CLI 中散落硬编码。
- 保存前要说明是影响后续自动收录，还是立即触发同步；二者不能混淆。

### 接口

- `Resource.setCollectRules`
