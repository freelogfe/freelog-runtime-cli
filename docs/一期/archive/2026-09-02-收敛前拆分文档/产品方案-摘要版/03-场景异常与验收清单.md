# 03 · 场景异常与验收清单

> **文档角色：** 用真实使用场景反查产品方案是否闭环，并定义手测/自动化验收边界。

最后更新：2026-09-02

## 1. 主场景清单

| 场景 | 用户目标 | 主路径 | 必须覆盖的分支 |
|---|---|---|---|
| S1 主题工程首次发布 | 从模板创建主题并发布 | `start/studio` → 选主题 → 模板 → build → 压缩 → publish | 类型逐级选择、模板版本、构建失败、压缩预览 |
| S2 插件工程首次发布 | 从插件模板发布插件 | 同 S1，资源类型为插件 | 插件类型、插件模板、运行时依赖 |
| S3 前端库/软件库发布 | 发布可依赖的库 | 选择 package 叶子类型 → 文件/目录 → publish | 不能选择父类型，需处理多个叶子候选 |
| S4 普通单文件资源 | 发布图片/音视频/文档等 | 选类型 → 选文件 → 填表单 → 策略 → publish | 文件不存在、类型不匹配、超限 |
| S5 普通目录资源 | 发布目录为压缩资源 | 选类型 → 选目录 → ignore → zip → publish | deterministic zip、强制排除凭据/state |
| S6 更新已有资源 | 维护线上资源或发新版本 | 读取 state/选择资源 → diff → 新版本 → listing | owner 不符、env 不符、远端变化 |
| S7 只管理策略/上下架 | 不改本地文件，只维护线上状态 | session/studio → 选资源 → 策略/listing/online | 支付/签约 Console 接力 |
| S8 批量独立资源 | 一个目录发布成多个资源 | scan → 规则 → 分批写入 → report | 中断、部分失败、resume/retry |
| S9 合集从本地目录创建 | 创建合集并添加条目 | 创建合集 → 子资源/已有资源 → 分批目录草稿 | 100 项分批、merge draft |
| S10 RSS 合集维护 | 绑定 feed 并同步条目 | feedUrl → compare → 验证码 → bind/sync | tags 可维护、1000 匹配限制、重复同步 |
| S11 collect-rules | 配置自动收录 | 选合集 → 选规则模板/枚举 → 预览 → 保存 | 区分保存规则和立即同步 |
| S12 AI/CI 代执行 | 非交互发行 | manifest + flags + `--json` | 缺字段 code 4、stdout 可解析 |
| S13 session/studio | 无长期工程或多账号工作 | 单进程菜单连续执行 | 凭据不落盘、owner 门禁、导出工程 |

## 2. 每个场景的统一检查项

每个场景都必须回答：

1. 用户从哪里进入？一条命令能不能完成主任务？
2. 哪些字段来自 Console 表单？限制是否在输入前展示？
3. 哪些接口会写平台？写之前有没有 checkpoint？
4. 本地会写哪些文件？能否用 Git 审查？
5. 失败时平台是否可能已经写入？如何恢复？
6. 是否需要 Console 接力？接力后如何回到 CLI？
7. 是否支持 AI/CI？输出是否稳定？

## 3. 关键异常处理

| 异常 | 正确行为 |
|---|---|
| 未登录 | 引导 login；非交互 code 2；不得打开隐藏浏览器流程 |
| 环境未指定 | TTY 提示选择；非交互要求显式 env 或项目默认 env |
| production 未开放 | 在任何网络写入前失败 |
| 资源类型不是叶子 | 展示可选叶子路径，要求重新选择 |
| 本地文件不存在 | 停在本地预检，不访问平台 |
| 目录压缩包含凭据/state | 强制排除；不可通过 `!` 反选 |
| build 失败 | 停止，不上传，不改 manifest/state |
| 上传成功但创建版本失败 | report 记录上传结果和后续处理建议 |
| 平台写入响应未知 | `remote_outcome_unknown`，要求对账后恢复 |
| 平台成功但本地回写失败 | `remote_succeeded_local_pending`，resume 先补本地 state |
| owner/env 不匹配 | 停止，显示当前账号、目标 owner、目标 env |
| RSS 验证码错误 | 只重试验证码，不重走 feed 输入 |
| RSS `matchedItemCount > 1000` | 阻止同步，说明需要缩小范围或 Console/平台处理 |
| 策略模板不可用 | 刷新模板列表；不允许手写旧模板 ID 强行通过 |
| 支付/签约需求 | 输出 Console 跳转链接和回到 CLI 的下一步 |

## 4. 验收分层

| 层级 | 证明什么 | 不证明什么 |
|---|---|---|
| L0 静态治理 | 文档结构、敏感信息、链接、公开命令不漂移 | 平台真实可达 |
| L1 单元测试 | 字段校验、状态机、压缩、报告恢复等纯逻辑 | Console 当前 UI |
| L2 契约测试 | CLI payload 与已确认接口语义一致 | dev/test 账号权限 |
| L3 dev/test 真实链路 | 指定账号、环境、资源类型能跑通 | production 可发布 |
| L4 人工跨端验收 | Console 与 CLI 结果一致，体验可接受 | 自动持续回归 |

## 5. 手测前最小验收

手测前必须至少满足：

- 文档活跃区只有 `README.md`、`产品方案/` 和 `archive/`。
- 产品方案能从需求分析推导到流程、字段、接口、异常和实现边界。
- 所有 Markdown 相对链接可解析。
- active 文档不包含测试账号、密码、token、cookie、authorization。
- CLI typecheck 通过。
- 与本次改动相关的文档治理测试通过。

## 6. 测试账号和安全

dev/test 账号可用于本地真实链路验证，但账号密码不得写入仓库、文档、测试快照、报告模板或 JSON fixture。测试报告只能记录账号角色、环境、时间、commit、CLI 版本、场景 ID 和结果。
