# 11 · session 与 studio

## 用户目标

用户不想马上创建长期工程，或需要在同一个本地目录里用多个账号处理不同资源。

## 前置条件

- 用户明确选择临时模式。
- 终端支持交互。
- 需要长期维护时，用户愿意导出工程。

## 主流程

| 模式 | 主流程 |
|---|---|
| session | 临时登录 → 选择/搜索资源 → 维护 listing/版本/策略/上下架 → 可导出工程 |
| studio | 选择工作目录 → 添加账号会话 → 逐项发行或维护 → 生成子工程和报告 |
| 单命令 session | 显式 `--session --resource-id` 执行一次维护 |

## 分支与异常

| 情况 | 处理 |
|---|---|
| 用户需要 CI | 建议显式命令，不用交互 shell |
| session 中途失败 | 保留脱敏结果，可选择导出 |
| 多账号混淆 | 每个账号会话隔离凭据和状态 |
| 需要长期维护 | 导出工程，后续走普通工程命令 |

## 验收点

- 临时凭据不落入工程文件。
- 多账号不会互相覆盖 state。
- 导出的工程能继续 status/publish/update。
