# 02 · 插件工程首次发布

## 用户目标

开发者想创建插件工程，构建后发行为插件资源。插件流程必须是一等入口，不能借用主题文案让用户猜。

## 前置条件

- 已登录目标环境。
- 已确认插件叶子类型可用。
- 本地工程目录为空或用户明确覆盖。

## 主流程

| 阶段 | TTY | AI/CI |
|---|---|---|
| 建工程 | `start` 选择“插件” | `init widget <dir>` |
| 选模板 | 展示 runtime 插件模板 | 显式传模板、runtime |
| 构建 | 提醒运行插件构建命令 | 脚本先构建 |
| 发行 | create 后 publish | create / publish |
| 策略上架 | 策略模板后 online | policy template apply / online |

## 分支与异常

| 情况 | 处理 |
|---|---|
| 用户把插件当主题 | 通过入口文案和资源类型路径纠正 |
| 模板安装失败 | 保留目录，提示重试或跳过安装 |
| 构建产物缺失 | 不调用平台写入 |
| 已有线上插件 | 转入绑定维护场景 |

## 验收点

- 交互中始终称为“插件”，不混用“主题”。
- 模板、类型、runtime 三者一致。
- 策略新增走模板选择。
