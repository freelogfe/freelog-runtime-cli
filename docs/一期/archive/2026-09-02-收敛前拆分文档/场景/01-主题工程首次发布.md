# 01 · 主题工程首次发布

## 用户目标

开发者想从模板创建一个主题工程，构建后发行为 Freelog 主题资源，并完成策略模板和上架。

## 前置条件

- 已登录目标环境。
- 已确认目标环境存在主题资源类型。
- 本地目录可以创建新工程。

## 主流程

| 阶段 | TTY | AI/CI |
|---|---|---|
| 建工程 | `start` 选择“主题” | `init theme <dir>` |
| 选模板 | 列出 runtime 模板后选择 | `template list --scaffold runtime --runtime 0.5` 后传模板 |
| 构建 | 提示运行项目构建命令 | 脚本先执行项目构建 |
| 写版本 | 选择构建目录和版本号 | `version set --file <dist> --artifact-mode directory-zip` |
| 平台写入 | 确认后 create / publish | `create --yes`、`publish --yes` |
| 策略上架 | 列模板、预览、应用、上架 | `policy template list/apply`、`online --yes` |

## 分支与异常

| 情况 | 处理 |
|---|---|
| 用户误选普通资源 | 允许返回资源类型选择，不创建半成品 |
| 没有构建目录 | 停在版本文件选择，不调用平台 |
| 主题类型不匹配 runtime | 提示换类型或换模板 |
| 策略模板需要参数 | 先预览编译结果，再应用 |
| 签约或付费缺失 | 停止并提示 Console 接力 |

## 验收点

- 本地生成主题工程和 manifest/state。
- 平台有主题资源和正式版本。
- 上架前能看到策略模板选择，而不是要求用户直接写策略文本。
- 失败不会留下无法判断归属的本地状态。
