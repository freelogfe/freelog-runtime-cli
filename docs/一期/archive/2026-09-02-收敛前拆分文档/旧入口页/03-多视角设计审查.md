# 多视角设计审查

> **文档角色：** 审查入口。本文只列审查方法，不承载产品规则。产品规则以 [产品方案/](./产品方案/README.md) 为准。

最后更新：2026-09-02

## 审查顺序

```text
先读产品方案
  → 再查 Console 事实证据
  → 再看场景卡是否覆盖真实使用
  → 最后检查实现规格和验证方案
```

## 各视角应该看什么

| 视角 | 重点 | 文档 |
|---|---|---|
| 产品 | 目标、用户、范围、主流程、CLI 原生体验 | [产品方案/00-方案总览.md](./产品方案/00-方案总览.md) |
| Console 对齐 | 字段约束、接口调用、状态门禁 | [对齐/README.md](./对齐/README.md) |
| 普通用户 | 是否能按任务看懂和操作 | [使用/README.md](./使用/README.md) |
| AI/CI | 是否无交互、可解析、可恢复 | [产品方案/02-命令与交互设计.md](./产品方案/02-命令与交互设计.md) |
| 测试 | 是否有验收入口和报告标准 | [验证/README.md](./验证/README.md) |
| 开发 | 是否能落到清晰模块和状态机 | [开发/README.md](./开发/README.md) |

## 审查输出规则

| 发现的问题 | 应改哪里 |
|---|---|
| 产品目标、流程或边界不清 | `产品方案/` |
| Console 事实不清 | `对齐/` |
| 用户手册读不懂 | `使用/` |
| 场景覆盖不足 | `场景/` |
| 实现结构不清 | `开发/` |
| 验收无法执行 | `验证/` |

不要把新规则写进本文；本文只负责告诉你应该回到哪个目录修正。
