## 2. 为什么迁移

原 `01/02/03/场景/开发/对齐` 同时承担了产品目标、业务事实、交互设计、代码实现、测试材料等多种职责，读者容易在材料之间来回跳，最后仍不知道应该怎样实现。

新的处理方式是：

```text
产品方案/        # 主线解决方案，可直接指导实现
对齐/            # Console 事实证据
开发/            # 实现细节和历史拆分材料
场景/            # 编号场景校验卡
使用/            # 编号最终用户操作手册
验证/            # 测试入口和报告
```

以后修改产品设计，先改 `产品方案/`；只有需要追溯证据或补充实现细节时才读其它目录。

## 3. 裁决规则

发生冲突时：

```text
DESIGN.md
  → 产品方案/
  → 对齐证据
  → 开发 / 场景 / 使用 / 验证材料
  → 当前代码
```

旧设计和旧实现不能反向决定产品。
