# 节点与资源市场（使用草案 · 完整产品增补）

> 文档角色：完整用户使用说明的 **增补草案**（一期命令见仓库 `docs/新方案/一期/使用/`；本文为 **市场 + 展品** 规划章节）。评审后可并入使用目录。术语见 [13-术语与对象速查](./13-术语与对象速查.md)。

Freelog CLI 二期将支持：在 **已创建节点** 上，把 **已上架** 的资源签约为 **展品**，并控制展品上下线。资源本身的创建、发版与上架仍使用一期命令（见 [发行单个资源](../使用/发行单个资源.md)、[策略与上下架](../使用/策略与上下架.md)）。

## 前置条件

1. 你已在 Console 创建并配置好节点（域名、可见性等）。
2. 你持有该节点的管理权限（节点主账号）。
3. 目标资源已 **上架**（出现在资源市场），或为你自己发行并已 `online` 的资源。
4. 已登录获授权环境：`freelog-cli login --env <env>`（见 [登录与环境](../使用/全局参数与登录.md)）。

建议将常用 `nodeId` 写入 CI 环境变量（例如 `FREELOG_NODE_ID`），避免每次手动选择。

## 两条不同的「签约」

| 场景 | 命令 | 谁操作 | 目的 |
|---|---|---|---|
| 发版前签 **依赖** | `dep auth` | 资源 **作者** | 让版本可以发行 |
| 把资源挂到 **节点** | `node exhibit sign` | **节点主** | 在店铺里展示该资源 |

不要混淆：依赖签约解决「能不能发版」；展品签约解决「能不能在节点上展示」。技术对照见 [01 §2.1](./01-面向AI的CLI设计原则.md#21-两条签约链勿混淆)。

## 典型流程

### 节点主：从市场选品并上架展品

```text
freelog-cli node show <nodeId> --env <env> --json
freelog-cli market search --limit 20 --env <env>
freelog-cli market show <resourceId> --env <env> --json
freelog-cli node exhibit sign --node <nodeId> --resource <resourceId> --dry-run --env <env> --json
freelog-cli node exhibit sign --node <nodeId> --resource <resourceId> --yes --env <env> --json
freelog-cli node exhibit online <presentableId> --yes --env <env> --json
freelog-cli node exhibit list --node <nodeId> --env <env> --json
```

### 资源作者：先发资源，再挂到自己的节点

```text
freelog-cli publish --yes --env <env>
freelog-cli online --yes --env <env>
freelog-cli node exhibit sign --node <nodeId> --resource <resourceId> --yes --env <env>
freelog-cli node exhibit online <presentableId> --yes --env <env>
```

## 命令摘要（规划）

| 命令 | 作用 |
|---|---|
| `market search` | 分页浏览已上架资源 |
| `market show <resourceId>` | 资源详情与是否适合签约 |
| `node list` | 列出你的节点（获取 nodeId） |
| `node show <nodeId>` | 节点详情；检查冻结与权限 |
| `node exhibit sign` | 将资源签约为展品 |
| `node exhibit list` | 列出节点下展品 |
| `node exhibit online` / `offline` | 上架 / 下架展品 |

写操作需 `--yes`；自动化建议加 `--json`。命令细节见 [03-CLI命令与架构设计](./03-CLI命令与架构设计.md)。

## 完整示例（CI / 脚本）

将下列占位符替换为实际值：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `<env>` | 获授权环境 | `dev` |
| `<NODE_ID>` | 节点 ID | `1001` 或 `$FREELOG_NODE_ID` |
| `<RESOURCE_ID>` | 已上架资源 | `$FREELOG_TEST_RESOURCE_ID` |
| `<PRESENTABLE_ID>` | sign 返回的展品 ID | 从 `--json` 的 `data.presentableId` 读取 |

```bash
# 登录（一次性）
freelog-cli login --env <env>

# 节点主：市场选品 → 挂店 → 上线
freelog-cli node show <NODE_ID> --env <env> --json
freelog-cli market show <RESOURCE_ID> --env <env> --json
freelog-cli node exhibit sign \
  --node <NODE_ID> --resource <RESOURCE_ID> \
  --dry-run --env <env> --json
freelog-cli node exhibit sign \
  --node <NODE_ID> --resource <RESOURCE_ID> \
  --yes --env <env> --json
# 从上一步 JSON 取出 presentableId
freelog-cli node exhibit online <PRESENTABLE_ID> --yes --env <env> --json
```

## 不要这样做

| 做法 | 原因 |
|---|---|
| 用 `session` / `studio` 做展品 sign/online | Agent/CI 主路径是 `--json` + `node exhibit`（P7/P11） |
| `freelog-cli node create …` | **不存在**；节点在 Console 创建 |
| 把 `dep auth` 当挂店 | 那是作者签依赖，不是展品签约 |
| sign 后直接以为访客可见 | 还须 `node exhibit online` |
| 忽略 code 5 继续脚本 | 须人工完成 Console 后重跑 `nextCommand` |

## 常见问题（FAQ）

**Q：自己的资源刚 publish，为什么 market 搜不到？**  
A：还须 `policy apply` + `online --yes` 使 `status=1`。可用 `market show <你的 resourceId>` 确认。

**Q：sign 成功但 online 失败 code 4？**  
A：展品侧须至少一条 **启用** 策略。可先对资源 `policy apply`，或在 sign 时选 `--policy`，或在 Console 为 presentable 启用 policy。

**Q：重复 sign 同一资源到同一节点？**  
A：会 code 4（`duplicate`）。用 `node exhibit list` 查已有 presentableId。

**Q：第三方资源需要作者同意吗？**  
A：Console Drawer 可能对授权链显示 warning；CLI 默认允许 sign，`--strict` 时 warn 升为 code 4（见 [07-Q2](./07-开放问题与设计裁决.md)）。

**Q：code 5 是什么？**  
A：需 Console 完成付费/合约。打开 JSON 里的 URL，完成后执行 `error.nextCommand`。

**Q：能否换节点域名或主题？**  
A：在 Console；CLI 仅 `node list/show` 只读。

**Q：和纯 API 调用有什么区别？**  
A：见 [12 §2.5](./12-多视角设计说明.md#25-竞品与替代方案)。

## 策略与上架

展品上架前须至少一条 **已启用** 策略。若 CLI 提示缺少策略，先用一期 `policy apply` / `policy set`，或在 Console 配置后再 `node exhibit online`。

## Console 接力

付费策略、可视化策略编辑等 → CLI 返回 Console URL 与 `nextCommand`（code 5）。见 [06-JSON协议与Schema草案](./06-JSON协议与Schema草案.md)。

## CLI 不提供的节点能力

请在 Console 操作：节点 create/update/delete、主题切换、收入提现、测试节点。

## 故障排查

| 现象 | 建议 |
|---|---|
| 资源未上架 | 先 `online` 或选市场资源 |
| 已签约 | `exhibit list` 查看 |
| 无策略无法上架 | 配置 policy 后再 online |
| 不确定用 CLI 还是 Console | [12 §3.2 决策树](./12-多视角设计说明.md#32-cli-vs-console-决策树) |
| 自动化遇 code 5 | 打开 handoff URL；完成后重跑 `nextCommand` |
| 权限错误 | `node show` 检查 owner |
| 节点冻结 | Console 检查节点状态 |

更多用户视角说明：[11 §12–13](./11-完整用户旅程.md#12-cli-vs-console-决策树用户视角)。
