## 2. 产品视角

### 2.1 价值主张

| 用户群 | 痛点（无 CLI） | CLI 提供 | 阶段 |
|---|---|---|---|
| 资源作者 | Console 点选发版、难进 Git/CI | manifest + validate + 可重复 publish | 一期 ✅ |
| 节点主 | 批量挂展品、Agent 运营 | market + exhibit sign/online headless | 二期 规划 |
| 平台/研发 | Agent 集成无稳定契约 | JSON envelope + exit code + handoff | 一期 ✅ + 二期扩展 |

**刻意不做：** 复制 Console 列表运营、支付 UI、节点壳配置、C 端购买——避免「半吊子 UI」。

### 2.2 产品成功信号

| 信号 | 度量 | 阶段 |
|---|---|---|
| 作者首次发行无需打开 Console | J-01 人工/ENV 通过 | 一期 |
| CI 同输入同输出 | validate + publish JSON 确定性 | 一期 |
| 节点主 headless 挂展品 | J-06 smoke S1–S8 | 二期 |
| Agent 遇支付诚实 handoff | code 5 + nextCommand 可重跑 | 一期 D-05 + 二期 NM-08 |
| 不误开放节点写命令 | 无 `node create` 注册 | 二期设计 |

### 2.3 分期与范围决策

| 决策 | 理由 | 评审点 |
|---|---|---|
| 节点 **只读** | 域名/删除误操作代价高；Console 一次配置 | P11 |
| 主题 activate **OUT** | 整站级切换影响全部访客；Console 强确认 UI 不可替代 headless 误触风险 | NM-15 |
| 合集展品 sign **OUT（2.0）** | 市场列表可展示合集条目，但 sign/API 链与单资源展品不同；需独立 CRUD 与验收，放 3.0 | NM-19、[07-Q9](./07-开放问题与设计裁决.md#29-q9--市场合集subjecttype4与-sign) |
| `batchCreatePresentable` 为签约真源 | Drawer 路径；非 MicroApp | NM-23 OUT |
| 2.0 不做 bulk exhibit online | Console 批量也不跑 policy 链；headless 不确定 | [07-Q3](./07-开放问题与设计裁决.md) |
| 一期不并入 exhibit smoke | 隔离风险；二期稳定后再议 | [04 §10](./04-能力矩阵与验收.md) |

### 2.4 产品边界一句话

```text
CLI = 资源生产流水线（一期） + 节点货品运营（二期）
Console = 店铺装修、收银台、主题与账户
```

### 2.5 竞品与替代方案

| 方案 | 适合 | 不适合 |
|---|---|---|
| **Console UI** | 节点壳、主题、支付、可视化 policy、探索 | Git/CI 可复现、批量 headless |
| **纯 REST / tools-lib** | 简单 CRUD、已有 HTTP 集成 | 本地文件上传、manifest、preflight 链、恢复报告 |
| **Freelog CLI** | 发资源 + 挂展品全链路；Agent 子进程 + JSON | 复制 Console 全部 UI；节点 create |

对外一句话：**CLI 是「可脚本化的 Console Drawer + 发行流水线」，不是浏览器替代品。**

## 3. 用户视角

### 3.1 Persona 与典型任务

| Persona | 第一诉求 | 推荐路径 | 勿用 |
|---|---|---|---|
| 内容作者 | 发一张图并上架 | J-01 工程模式 | studio 做长期工程 |
| 节点主 | 把市场资源挂到店铺 | J-06；节点事先 Console 建好 | CLI 创建节点 |
| 同账号作者+节点主 | 自发资源并挂店 | J-05 | 混淆 dep auth 与 exhibit sign |
| 运维/Agent | 脚本化 | J-07；`--json` | session 交互菜单 |

### 3.2 CLI vs Console 决策树

```text
需要改本地文件 / 进 Git / CI？
  是 → CLI（一期 publish…）
  否 → 继续

需要创建/改节点域名、Logo、主题？
  是 → Console
  否 → 继续

需要把已上架资源挂到节点、上下线展品？
  是 → CLI market + node exhibit（二期）
  否 → 继续

需要支付、合约收银、可视化改 policy 正文？
  是 → Console（CLI 给链接 + nextCommand）
  否 → CLI 或 Console 均可
```

### 3.3 用户可感知差异（相对 Console）

| 场景 | Console 体验 | CLI 体验 | 设计意图 |
|---|---|---|---|
| 签约至节点 | Drawer 选节点、warning 黄标 | `--dry-run` JSON checks；`--strict` 可更严 | 可脚本化 |
| 展品上架 | 无 policy 弹窗创建 | 预检 code 4，hint 先 policy apply | 非 TTY 完整 |
| 资源上架 | Sidebar 严格门禁 | 同门禁；拆步 policy → online | PARITY |
| 付费签约 | 浏览器收银 | code 5 handoff | 诚实 OUT |

### 3.4 用户常见误解

| 误解 | 正确理解 |
|---|---|
| 「online 资源就能 sign」 | 还须 node owner、未重复签约、资源 status=1 |
| 「sign 等于上架展品」 | sign 创建 presentable；**online** 才访客可见 |
| 「CLI 可以创建节点」 | **OUT**；仅 list/show |
| 「dep auth 和 exhibit sign 一样」 | 作者签依赖 vs 节点主签市场资源 |

### 3.5 失败时用户该做什么

| exit code | 用户动作 |
|:---:|---|
| 0 | 继续下一步；保存 JSON 里的 ID |
| 2 | 检查登录账号、节点 owner、是否冻结 |
| 4 | 读 `error.hint`；补参数或先 policy/online |
| 5 | 打开 Console URL；完成后重跑 `nextCommand` |

## 4. 测试视角

### 4.1 验收三层（与 Console 对齐）

| 层 | 含义 | 谁做 | 二期 CORE 要求 |
|:---:|---|---|---|
| **A** | CLI 代码路径 + API 参数同构 | 研发 | 实现前设计评审 |
| **B** | dev 环境命令跑通 | 自动化/QA | `verify:exhibit-smoke` |
| **C** | 同输入 Console UI 与 CLI 结果一致 | QA 并排 | CORE NM 必须做 C |

**规则：** 仅 A 或 B **不能** 宣称与 Console PARITY 完成。

### 4.2 测试资产要求

| 资产 | 用途 | 说明 |
|---|---|---|
| 节点 A（owner=主测账号） | J-06 smoke | Console 预先创建 |
| 资源 R（status=1） | sign 目标 | 自发行或市场第三方 |
| 账号 B（非 owner） | N1 负向 | 测 code 2 |
| 冻结节点 fixture | N2 | Console 手动冻结（dev 难 API 写） |
| 无 policy 的 presentable | N4 | sign 后不上架前测 online |

Fixture 详细步骤见 [16 §6](./16-verify-exhibit-smoke设计.md#6-fixture-准备手册附录)。

### 4.3 追溯矩阵（CORE · 二期）

| 测试 ID | 能力 | 用户旅程 | CLI | Console 对照 |
|---|---|---|---|---|
| T-NM-S1~S8 | NM-01~12 | J-06 | [10](./10-L4验收模板.md) | [05 §C](./05-Console源码证据与调用链.md) |
| T-NM-N1~N4 | NM-04/08/11 | J-06 负向 | [04 §9](./04-能力矩阵与验收.md) | 05 §C |
| T-J05 | NM-08 + R/P | J-05 | 10 + 一期 verify | 05 §C + 资源 sidebar |
| T-H5 | NM-08 | handoff | 人工 code 5 | Console 合约页 |

一期 CORE：**T-R/V/P** 见仓库 `pnpm verify`、`verify-scenarios`（本目录不展开）。

### 4.4 QA 并排验证流程（二期 CORE）

```text
1. Console 走一遍（记录 UI 状态、Network 关键 API）
2. CLI 同业务输入（--json 存证）
3. 对比：平台侧 presentable 是否存在、onlineStatus、owner
4. 负向：CLI code 与 Console 拦截是否同类（不必 UI 相同）
5. 写入日期化报告（10 模板）；附 Console commit / CLI 版本
```

### 4.5 刻意不测 / 不测等价

| 项 | 原因 |
|---|---|
| MicroApp 签约路径 | OUT；非 CLI 真源 |
| Console 批量 exhibit online 无 policy | CLI 2.0 不做 bulk |
| 节点 create E2E | OUT |
| production | 当前硬禁用 |

## 5. PARITY 债务登记册

> 集中维护「CLI 与 Console **不等价但可接受**」项；实现与 QA 不重复争论。Console 侧「刻意不对齐」索引见 [05 §B.6](./05-Console源码证据与调用链.md#b6-刻意不对齐)。

| 主题 | Console 行为 | CLI 行为 | 对齐类型 | 可接受性 |
|---|---|---|---|:---:|
| Policy 弹窗（展品上架） | `onlineExhibit` 无 policy 时弹 `fPolicyBuilder` | preflight **code 4** + hint 先 `policy apply` | EQUIVALENT | ✅ headless 完整链 |
| authException / ownerFreeze | Drawer 黄标 warning，仍可 sign | 默认 **warn**；`--strict` → code 4 | PARITY + CLI_ONLY | ✅ Q2 |
| 批量 exhibit online | `batchUpdatePresentableStatus`，不逐条 policy | 2.0 **不注册** bulk online | OUT / 分期 | ✅ Q3 |
| MicroApp 签约 | qiankun 嵌入页 | **不对齐**；Drawer API 为真源 | OUT | ✅ NM-23 |
| 市场 keywords / type 筛选 | UI 未暴露 | CLI `--keywords` / `--type` | EQUIVALENT（CLI 更宽） | ✅ Q6 |
| 合集条目 sign | 市场可见 subjectType=4 | sign preflight code 4 | OUT 2.0 | ✅ Q9 → 3.0 |
| sign 后资源下架 | Console 侧可能仍显示展品 | `online` 查当前 status；不 silent 成功 | EQUIVALENT | ✅ Q10 |
| Console 批量 sign 多选 UI | Drawer 多选 | 2.1 `sign --resource` ×N | 分期 | ⏭ NM-18 |
| 主题 activate | 整站确认流 | OUT | OUT | ✅ NM-15 |
| 节点 create / 收入 / 支付 | Console 专属 | handoff 或 OUT | OUT | ✅ P11 |

**评审规则：** 新增债务须在本表登记 + 链 ADR（[07](./07-开放问题与设计裁决.md)）；宣称 PARITY 须含 **层 C** 证据（§4.1）。
