## 📋 **一、设计目标与定位**

### **1.1 核心职责**

CLI 脚手架提供 **通用的模板创建能力**，而非定义资源类型：

```
┌──────────────────────────────────────┐
│   Platform (后端)                     │
│   ─────────────────                   │
│   · Theme, Plugin, Library,           │
│     Software, Collection              │
│   · 定义资源类型及其能力               │
└──────────────────────────────────────┘
           ↓ CLI 适配而非定义
┌──────────────────────────────────────┐
│   CLI 脚手架                            │
│   ──────────                          │
│   · freelog create template          │
│   · 为所有类型生成标准工程结构         │
│   · 自动生成 manifest.yaml            │
└──────────────────────────────────────┘
```

### **1.2 边界条件**

| 事项 | CLI 职责 | 非职责 |
|------|---------|--------|
| **资源类型定义** | 适配 Platform 已有类型 | 不决定支持哪些类型 |
| **模板创建** | `init`命令生成工程骨架 | 不自动构建项目 |
| **manifest 生成** | 写入用户意图字段 | 不缓存平台 ID/owner |
| **依赖管理** | 最小化安装运行时库 | 不引入服务端框架 |


### **2.2 Non-interactive Mode (--flag syntax)**

```bash
# 声明式初始化（CI/自动化场景）
freelog init \
  --type theme \
  --template vite-react \
  --name my-theme \
  --artifact-mode directory-zip \
  --yes

# 包工程初始化
freelog init package \
  --template package-react \
  --resource-type components-library \
  --yes

# 合集初始化
freelog init collection \
  --name my-collection \
  --yes
```

**重要规则**:
- 非交互初始化必须显式给出 `--artifact-mode file|directory-zip`
- 不能根据类型展示名猜测压缩模式
- `init`只创建本地工程，不创建平台资源

## 📁 **三、模板能力矩阵**

### **3.1 当前支持的模板列表**

根据 `template-compat.json` 定义的兼容矩阵：

| 模板 ID | 适用资源类型 | 技术栈 | artifactMode | npm Package | 状态 |
|--------|------------|--------|--------------|-----------|------|
| `theme-vite-react` | Theme | Vite + React | directory-zip | @freelog-cli/theme-react | ✅ Active |
| `theme-vite-vue` | Theme | Vite + Vue | directory-zip | @freelog-cli/theme-vue | ✅ Active |
| `plugin-vite-react` | Plugin | Vite + React | directory-zip | @freelog-cli/plugin-react | ✅ Active |
| `plugin-vite-vue` | Plugin | Vite + Vue | directory-zip | @freelog-cli/plugin-vue | ✅ Active |
| `package-js` | JS 工具包 | Node.js | file | @freelog-cli/package-js | ⏸ Suspended |
| `package-react` | 组件库 | React | file | @freelog-cli/package-react | ⏸ Suspended |
| `package-vue` | 组件库 | Vue | file | @freelog-cli/package-vue | ⏸ Suspended |
| `collection` | Collection | N/A | N/A | Internal | ✅ Active |

**说明**:
- runtime 工程（主题/插件）默认 `artifactMode: directory-zip`
- package 工程（前端库）默认 `artifactMode: file`
- 合集模板只创建 manifest，不强加前端工程

### **3.2 模板发布顺序约束**

根据 DESIGN.md §Template Behavior Constraints #11:

```
正确的发布顺序：
1. 先将四个 runtime 模板发布为新的 `4.x` latest
   - 验证 tarball 包含必需的 template.manifest.json
2. 再发布 `@freelog-cli/cli2`
   - 确保能正确解析和使用最新模板

禁止的发布顺序：
❌ 先发布 CLI → ❌ 依赖的模板缺少 template.manifest.json
```

## 📄 **四、manifest.yaml 生成规则**

### **4.1 基础字段填充**

| 字段 | 值来源 | 格式要求 | 备注 |
|------|--------|---------|------|
| `schemaVersion` | 固定值 | `1` | 仅接受 v1 |
| `resource.title` | 用户输入或命令行 | ≤100 chars | Platform 约束 |
| `resource.typeCode` | 从环境查询叶子类型 | `^[a-z][a-z0-9_\-]*$` | 必须是 isTerminate=true 的类型 |
| `resource.name` | 可选，文件名提取 | ≤60 chars | 自动截断超限 |
| `version` | 默认为 `1.0.0` | SemVer | 维护期可 bump |
| `author` | 读取 package.json | 字符串 | 工程模式必写 |
| `artifactMode` | 模板定义 | `file`\|`directory-zip` | 由 Platform capability 决定 |

### **4.2 特殊处理规则**

#### **规则 1: 类型代码解析**

```
伪代码：
IF 用户输入 typeCode THEN
  response = queryPlatformTypes(env)
  selectedType = findLeafNode(response.tree, user_input)
  
  IF selectedType IS NULL OR NOT selectedType.isTerminate THEN
    showWarning("请选择最终的叶子类型（不可再细分）")
    promptUserForManualSelection()
  ELSE
    write manifest.typeCode = selectedType.code
  END IF
ELSE IF CLI provides --resource-type flag THEN
  validateExplicitTypeFlag(flag_value)
  write manifest.typeCode = validated_code
END IF
```

**对齐 Console**: Console 类型输入只提交 `isTerminate=true` 的候选，CLI 必须遵循同样的规则。

#### **规则 2: 名称展示名处理**

```
伪代码：
IF manifest.typeCode IS standard_RT_type THEN
  # Theme/Plugin/Library 等标准类型
  resourceTypeName = lookupPlatformTypeName(typeCode, env)
  # 不要使用 customInput
ELSE IF explicit --type-name provided THEN
  resourceTypeName = typed_name
  # 真正的自定义类型才允许 customInput
END IF
```

**说明**: manifest 的展示事实不应提升为创建参数，Resource.create 时必须省略展示名。

#### **规则 3: 依赖分类**

```
伪代码：
FOR EACH dependency IN package.dependencies DO
  IF dependency IS browser-runtime-library THEN
    keep in dependencies
  ELSE IF dependency IS type-package OR build-tool THEN
    move to devDependencies
  ELSE IF dependency IS server-framework THEN
    throwError(ERR_INVALID_TEMPLATE, "主题/插件工程不应包含服务端框架依赖")
  END IF
END FOR
```

**模板不得携带未被源码或构建配置使用的包**。

## 🗂️ **五、目录结构设计**

### **5.1 生成的标准目录树**

```
my-theme/
├── .freelogignore              ← CLI 生成默认 ignore 规则
├── .gitignore                  ← 保证.fredelog-auth 被忽略
├── freelog.manifest.json       ← CLI 生成主配置文件
├── package.json                ← 用户填写（模板提供示例）
├── vite.config.ts              ← 构建配置（模板提供）
├── src/
│   ├── index.js                ← 入口文件（模板提供）
│   └── styles/                 ← 样式目录
├── public/
│   └── favicon.ico             ← 静态资源
└── README.md                   ← 使用说明（模板提供）

# 关键文件说明：
# · .freelogignore: CLI 强制排除.fredelog/, auth.key 等敏感文件
# · .gitignore: 追加覆盖规则确保.fredelog-auth 不被提交
# · freelog.manifest.json: CLI 生成的用户长期意图
```

### **5.2 .freelogignore 默认规则**

```
# CLI 强制排除项（不可反选）
.fredelog/
.fredelog-auth
.auth.key
node_modules/
dist/

# 用户可自定义的规则将追加在这些之后
# （例如：*.log, test/）
```

**重要**: 
- 忽略规则采用项目根相对路径的 POSIX 格式
- 暂不支持 `!` 反选，出现时明确报错
- 系统临时文件和敏感文件强制排除

## 🔄 **六、模板版本管理**

### **6.1 模板来源解析顺序**

```
伪代码：
IF FREELOG_TEMPLATE_PATH environment variable set THEN
  use_local_path(FREELOG_TEMPLATE_PATH)
ELSE IF cwd contains node_modules/@freelog-cli/templates THEN
  use_local_templates(cwd/node_modules/@freelog-cli/templates)
ELSE
  # 从 npm 下载 latest dist-tag
  latest_version = npm_getDistTag('@freelog-cli/cli', 'latest')
  
  # 检查版本是否包含必需的 template.manifest.json
  IF latest_version < 4.0.0 OR missing_template_manifest THEN
    showWarning(`最新版本 ${latest_version} 缺少必需的模板契约`)
    fallback_to_specific_version('4.0.0')
  ELSE
    download_and_cache(latest_version)
  END IF
  
  write log(`实际使用的模板版本：${resolved_semver}`)
END IF
```

**关键约束**:
- `latest`只用于选择初始化时的版本
- 进入下载、缓存和结果记录后必须转换为具体 SemVer
- CLI 不提供原地升级用户代码的能力
- 模板新版本只影响之后新建的工程

### **6.2 无效模板检测**

```
IF template.package.manifest IS missing THEN
  throwError(ERR_INVALID_TEMPLATE, "模板包缺少自身 manifest，视为无效")
ELSE IF template.compatibility_matrix DOES NOT include current_env THEN
  showWarning(`当前环境 ${env} 不在模板兼容矩阵中`)
  confirmContinue()
END IF
```

**规则**: 仓库中已移除的模板必须同时退出兼容矩阵、CLI 可选列表和兼容检查，不得保留一个必然无法初始化的入口。

## ⚠️ **七、异常处理矩阵**

| 错误场景 | HTTP Code | Error Code | 用户友好消息 | Recovery Action |
|---------|-----------|------------|-------------|-----------------|
| Invalid Resource Type | 400 | ERR_INVALID_TYPE | "无效的资源类型，请选择有效的叶子类型" | Stay in step reselect type |
| Template Not Found | - | ERR_TEMPLATE_NOT_FOUND | "找不到指定的模板，可选模板：theme-vite-react, theme-vite-vue..." | Rerun with valid --template flag |
| Disk Space Full | ENOSPC | ERR_DISK_FULL | "磁盘空间不足，请释放空间后重试" | Abort workflow |
| Git Ignore Conflict | - | ERR_GITIGNORE_CONFLICT | ".gitignore 中存在反选规则，可能导致.sensitive 文件被提交" | Fix .gitignore before continue |
| Template Version Incompatible | - | ERR_TEMPLATE_VERSION_MISMATCH | "当前模板版本 X.Y.Z 与 CLI 版本 A.B.C 不兼容" | 升级 CLI 或指定兼容的模板版本 |
| Auth Key Missing | - | ERR_AUTH_KEY_MISSING | "加密密钥丢失，请重新登录" | Run freelog login again |
