## 🔗 **二、错误码分层模型**

```
┌─────────────────────────────────────┐
│ Layer 4: UI/UX                      │
│   - 显示友好的错误消息              │
│   - 提供修复建议                     │
├─────────────────────────────────────┤
│ Layer 3: Step Orchestrator          │
│   - Catch APIError                  │
│   - 包装成 CLIError                 │
│   - Checkpoint 回滚逻辑              │
├─────────────────────────────────────┤
│ Layer 2: Business Logic (PHASE)     │
│   - 捕获 CLIError                   │
│   - 根据错误码决定重试/跳过/中断     │
│   - 记录日志                        │
├─────────────────────────────────────┤
│ Layer 1: tools-lib API Client       │
│   - 返回 APIError                   │
│   - 包含服务器返回的错误码           │
└─────────────────────────────────────┘
```

## 💡 **三、使用示例**

### **正确用法:**

```typescript
// Step: F1.1 Step1 创建资源壳
async function step1CreateShell(params: Step1Params) {
  try {
    // 调用 API
    const response = await api.resource.createAuthShell(params);
    
    return response;
    
  } catch (error: any) {
    // ✅ 根据错误码处理
    if (error.code === 'AUTH_ID_EXISTS') {
      console.log(ui.warning('⚠️ 授权标识已被使用，请修改'));
      return PromptForNewTitle();
    } else if (error.code === 'API_RATE_LIMIT') {
      console.log(ui.info('🕒 操作过于频繁，等待 30s 后重试...'));
      await sleep(30000);
      return retryStep1(params);
    } else {
      throw new CLIError(CLI_ERROR_CODES.API_UNKNOWN_ERROR, error);
    }
  }
}
```

## 🎯 **四、扩展规则**

### **新增错误码条件:**
- [ ] 业务梳理中的异常分支未覆盖
- [ ] Console 源码中已有错误码未实现
- [ ] tools-lib 新增错误码需同步到 CLI

### **命名规范:**
- 前缀：ERR_
- 类别：认证 (LOGIN)、资源 (RESOURCE)、合集 (COLLECTION)
- 具体错误：EXISTS, NOT_FOUND, INVALID, TIMEOUT
- 全部大写，下划线分隔
