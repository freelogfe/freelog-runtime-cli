# Freelog CLI 一期文档入口

> **文档角色：** 一期资源发行域的最小活跃入口。这里不承载细节，只说明当前主方案和归档边界。

最后更新：2026-09-02

## 1. 当前只读哪里

当前一期活跃文档只保留一条主线：

| 目的 | 入口 |
|---|---|
| 产品、流程、字段、接口、异常、实现和验收的完整方案 | [产品方案/README.md](./产品方案/README.md) |
| 仓库级产品契约 | [../../DESIGN.md](../../DESIGN.md) |

这意味着：`对齐`、`开发`、`验证`、`使用`、`场景` 和旧 `01/02/03` 不再作为活跃入口。它们已经进入 [archive/2026-09-02-收敛前拆分文档](./archive/2026-09-02-收敛前拆分文档/)，只用于追溯旧分析、旧验证或旧实现讨论。

## 2. 为什么这样收敛

一期业务流程并不复杂，真正复杂的是终端使用场景和失败恢复。文档应该先讲清楚：

```text
需求是什么
  → Console 业务和字段怎么工作
  → CLI 环境有什么差异
  → CLI 应该如何设计流程
  → 每个流程有哪些字段、接口、异常和验收
  → 实现上如何分层
```

这些内容现在统一放在 `产品方案/`，避免读者在多个目录之间拼材料。

## 3. 维护规则

1. 新产品判断先改 `产品方案/`。
2. 需要保留证据、旧测试报告、旧实现草案时放入 `archive/`。
3. 不再新增同级 `对齐/开发/验证/使用/场景` 活跃目录。
4. 如果未来要拆用户手册或测试报告，必须先在 `产品方案/README.md` 说明它不是新的产品真源。
