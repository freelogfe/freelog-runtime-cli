# 04 · CLI 流程与命令设计

> **文档角色：** CLI 流程和命令体验设计。本文是用户实际操作设计，必须能回答：用户输入一条命令后，如何一步步完成资源发行或维护。

最后更新：2026-09-02

## 1. 命令入口原则

CLI 不是让用户记一堆低级接口命令，而是提供业务入口：

```text
freelog create         # 从模板创建本地主题/插件/工程；默认不写平台
freelog pack           # 独立压缩/打包目录，生成可检查、可复用 artifact；默认不上传
freelog publish        # 发布本地资源/工程/目录，进入连续向导
freelog update         # 更新已有资源：新版本、listing、策略、上下架
freelog collection     # 创建或维护合集
freelog rss            # 绑定、更新、同步 RSS
freelog rules          # 维护 collect-rules 自动收录
freelog batch          # 批量扫描和发布
freelog session        # 单进程会话，适合多步操作、AI 协作、多账号切换
freelog doctor         # 检查登录、环境、本地配置、平台连通性
```

低级命令可以存在，但不能成为默认路径。默认路径必须是一个连续会话，把资源发行/更新所需事项一次走完。

## 2. 通用会话拓扑

```text
启动命令
  → 解析环境和账号
  → 识别输入：文件 / 目录 / 工程 / manifest / 远端资源
  → 选择业务意图
  → 拉取 Console 对齐的动态数据
  → 选择或确认内容来源
  → 如需要，执行模板创建 / 构建 / 压缩
  → 补齐字段
  → dry-run 预览
  → 写入前确认
  → 执行远端写入
  → 输出结果和后续动作
```

每一步都必须显示：

- 当前步骤名。
- 已确认字段。
- 缺失字段。
- 下一步是否会写远端，还是只写本地模板/压缩产物。
- 可用操作：继续、返回、跳过、保存草稿、退出、打开 Console。

## 3. 本地准备能力流程

模板、构建和压缩是 CLI 自己的产品能力。它们既可以独立使用，也可以在发布流程中被调用，但不能绕过 Console 对齐的资源业务。

### 3.1 独立模板创建流程

```text
create theme/plugin
  → 选择模板分类：theme / plugin
  → 选择技术模板：React / Vue / JavaScript / TypeScript 等
  → 选择目标目录
  → 检查目录是否为空或可安全合并
  → 写入本地工程文件
  → 写入模板来源、模板版本和默认构建/产物约定
  → 输出下一步：开发、构建、压缩、发布
```

规则：

- 独立模板创建默认只写本地，不创建平台资源。
- 已有文件冲突时必须展示冲突清单；默认不覆盖。
- 模板生成的工程可以立即进入发布流程，但发布仍要选择平台资源类型、创建资源壳、版本、策略、listing 和上架。

### 3.2 独立压缩/打包流程

```text
pack <目录>
  → 扫描目录
  → 应用 ignore 规则和强制排除规则
  → 展示将包含/忽略/拒绝的文件摘要
  → 用户确认输出路径
  → 生成确定性压缩包
  → 输出 artifact 路径、大小、sha1、文件清单和报告
```

规则：

- 独立压缩只写本地 artifact 和报告，不上传、不创建资源、不创建版本。
- 压缩结果可作为后续 `publish` 的已有 artifact 输入。
- 如果目录为空、全部被忽略、存在不可读文件或输出路径冲突，必须停在压缩阶段，不进入发布。

### 3.3 发布流程内内容来源选择

当用户进入 `publish` 并选定资源类型后，CLI 必须询问内容来源，而不是直接假设用户已有产物：

```text
选定资源类型
  → 展示类型能力：文件入口、大小限制、artifactMode、是否支持编辑/可选配置
  → 选择内容来源
      ├─ 使用已有单文件
      ├─ 使用现有本地工程
      ├─ 从模板创建新工程
      ├─ 使用已有构建目录
      └─ 使用已有压缩包/artifact
  → 如需要，构建或压缩
  → 得到待上传 artifact
  → 回到标准资源发行流程
```

不同类型的默认选项：

| 已选资源类型 | 默认内容来源 | 必须提供的替代选项 |
|---|---|---|
| 普通文件型资源 | 使用已有单文件 | 已有 artifact、平台存储对象 |
| 目录/工程型资源 | 使用现有工程或构建目录 | 已有压缩包、只打包不发布 |
| 主题资源类型 | 从主题模板创建或使用现有主题工程 | 已有构建目录、已有压缩包 |
| 插件资源类型 | 从插件模板创建或使用现有插件工程 | 已有构建目录、已有压缩包 |

### 3.4 React 主题的两条正确入口

直接创建本地工程：

```text
create theme
  → 选择 React 主题模板
  → 创建本地工程
  → 用户开发/构建
  → 可选继续 publish
```

标准发行流程中创建：

```text
publish
  → 选择资源类型：主题
  → 选择内容来源：从模板创建
  → 选择 React 主题模板
  → 创建本地工程
  → 构建和压缩
  → 标准资源发行流程
```

两条路径只能在“本地工程准备”阶段不同；一旦进入平台发行，必须使用同一套资源类型、资源壳、版本、策略、listing、上架流程。

## 4. 登录和账号流程

### 4.1 启动时必须展示的信息清单

无论什么命令，在首次接触远端数据前必须展示以下信息：

```
🔍 环境检测
  当前环境：dev/test/production
  登录账号：username (ID: xxx)
  
┌─ Owner 确认 ───────────────────┐
│                                 │
│ 即将在 [环境] 执行写操作       │
│ 当前账号：username (ID: xxx)   │
│ 资源 owner: owner_username      │
│                                  │
│ owner 是否一致：✓ 一致 / ✗ 不一致│
│                                  │
│ ⚠️ 警告：如果不一致将无法写入   │
└─────────────────────────────────┘
```

**说明**:

- **只有写操作**（publish/update/collection update）才需要 owner 校验
- **只读操作**（info/list/dry-run）不需要 owner 校验，但可显示 owner 作为参考
- **批量操作**逐个检查每个资源的 owner，不匹配的跳过或报错

### 4.2 Owner 不一致的处理策略

| 命令类型 | 写操作时的行为 | 允许强制绕过的方式 |
|---------|--------------|------------------|
| publish/create | ❌ 拒绝执行，提示切换到 owner 账号 | `--force-admin`（需管理员权限） |
| update/edit | ❌ 拒绝执行，显示差异和 owner 信息 | `--force-admin`（需管理员权限） |
| collection create/update | ❌ 对不匹配的条目单独跳过 | `--ignore-owner`（谨慎使用） |
| batch publish | 逐个扫描，冻结状态的跳过 | `--force-batch`（全部执行） |
| info/read | ✓ 正常显示 owner 信息 | 无 |
| list/query | ✓ 正常查询，owner 作为过滤条件 | --show-others 查看所有 owner |

### 4.3 TTY vs 非交互模式的行为对比

| 场景 | TTY 交互模式 | 非交互/AI 模式 |
|-----|------------|-------------|
| 未指定 owner | 展示当前账号和目标资源 owner，询问用户 | 直接返回 `OWNER_MISMATCH` 错误 |
| owner 不一致 | 显示告警，提供切换账号选项 | 返回结构化错误码 |
| 显式指定 --owner | 校验指定的 owner 是否存在 | 同样校验并拒绝非法 owner |
| CI 环境 | - | 必须显式配置 owner 或使用默认值 |

### 4.4 非交互模式下的 OWNER_MISMATCH 错误

```json
{
  "event": "error",
  "code": "OWNER_MISMATCH",
  "message": "无法写入非自有资源",
  "details": {
    "resourceId": "res_company_theme_123",
    "currentAccount": "developer (1111111)",
    "resourceOwner": "company-owner (8888888)"
  },
  "recommendation": "Use --switch to change account or contact resource owner",
  "timestamp": "2026-09-02T10:30:00Z"
}
```

### 4.5 Checkpoint 中的 accountId 校验

Checkpoint 保存时必须记录 `accountId`，恢复时进行校验：

```json
// ~/.freelog/checkpoints/publish-abc.json
{
  "accountId": "8847953",        // ← 记录原始账号 ID
  "runId": "publish-20260902-abc",
  "completedSteps": [...],
  ...
}
```

恢复时的校验逻辑：

```bash
$ freelog publish ./file.zip
⚠️ 检测到未完成的发布任务

Checkpoint 账号：liu-kai-github (ID: 8847953)
当前账号：other-user (ID: 9999999)

❌ 拒绝恢复 Checkpoint

原因：Checkpoint 是为其他账号创建的，强行恢复可能导致权限冲突。

选项:
  A) 继续使用当前账号创建新发布
  B) 切换回原账号恢复
  C) 删除旧 Checkpoint
```

### 4.6 跨环境发布的 owner 豁免机制

某些特殊场景下，不同环境的 owner 可能不同：

- **开发环境**: 可以发布测试账号的资源
- **生产环境**: 通常要求 owner 一致性
- **部署脚本**: CI/CD 可以使用专用部署账号，拥有全环境写入权限

验证规则：

```text
if (environment == "production" && command.isWrite()) {
  if (currentAccount != resourceOwner && !hasDeployPermission(currentAccount)) {
    return ERROR_PERMISSION_DENIED;
  }
}
```

权限分级：

| 账号类型 | dev 环境 | test 环境 | production 环境 |
|---------|--------|---------|---------------|
| 普通开发者 | ✓ 读写 | ✓ 读写 | ✗ 只读 |
| 团队管理员 | ✓ 读写 | ✓ 读写 | ⚠️ 需二次确认 |
| 部署账号 | ✓ 读写 | ✓ 读写 | ✓ 完全权限 |
| 超级管理员 | ✓ 读写 | ✓ 读写 | ✓ 完全权限 |

### 4.7 登录和账号流程表

| 场景 | TTY 流程 | 非交互/AI 流程 | 异常处理 |
|---|---|---|---|
| 未登录 | 提示登录方式：账号密码、已有 token、浏览器/Console 接力 | 缺凭据直接返回 `AUTH_REQUIRED` | 不创建本地业务草稿 |
| 多账号 | 列出 profile、环境、用户名、上次使用时间 | 必须通过参数/环境变量指定 profile | 未指定且多账号时返回 `ACCOUNT_AMBIGUOUS` |
| 临时会话 | 本次命令内保存，不写默认 profile | 使用 session 文件或环境 secret | 命令结束清理临时凭据 |
| owner 不一致 | 展示当前账号和目标资源 owner | 返回 `OWNER_MISMATCH`，除非显式 allow | 不继续写入 |

## 5. 资源类型选择流程

```text
选择主体：普通资源 / 合集 / 主题/插件 / 批量
  → 拉取顶层类型
  → 展示一级分类编号
  → 进入子级分类
  → 到叶子类型后展示能力
  → 用户确认类型
```

必须支持：

- 编号选择。
- 返回上一级。
- 搜索关键词。
- 显示类型路径，例如“媒体 / 音频 / 播客”。
- 显示能力：是否支持批量、文件入口、大小限制、可选配置。
- 主题/插件快捷筛选，但最终仍来自平台类型树。

搜索结果不是最终答案，用户仍要确认完整类型路径。

## 6. 单资源发布流程（首次发布）

```text
publish <本地输入>
  → 确认账号和环境
  → 选择资源类型
  → 选择内容来源：已有文件 / 现有工程 / 模板创建 / 构建目录 / 已有压缩包
  → 填资源标题
  → 生成并确认授权标识
  → 检查远端是否已存在
  → 准备版本内容
      ├─ 文件：上传
      ├─ 目录：构建/打包后上传
      ├─ 工程：识别模板或 manifest，构建、压缩、产物确认、上传
      ├─ 新模板工程：创建、构建、压缩、产物确认、上传
      └─ 已有 artifact：校验、上传
  → 维护版本信息：版本号、描述、属性、依赖、授权排除
  → 策略：先选模板，再填参数，再编译和翻译
  → listing：封面、简介、标签
  → 是否上架
  → 输出报告
```

### 5.1 关键体验

| 阶段 | 默认行为 | 用户可改 | 写入点 |
|---|---|---|---|
| 标题 | 从文件名/工程名推断 | 可编辑，100 字以内 | 创建资源壳 |
| 授权标识 | 从标题规范化，60 字以内 | 可编辑，展示规范化结果 | 创建资源壳 |
| 内容来源 | 根据资源类型和本地输入推荐 | 可改为模板、现有工程、构建目录、压缩包 | 本地准备阶段 |
| 压缩 artifact | 目录/工程型资源按规则生成 | 可只打包不发布，或复用已有 artifact | 上传前 |
| 版本号 | 首版固定 `1.0.0` | 首版不可改 | 创建版本 |
| 版本描述 | 默认空，可从 changelog/commit 生成 | 可编辑 | 创建版本 |
| 策略 | 展示模板列表 | 可选模板和参数 | 保存资源策略 |
| listing | 可从资源推断封面/简介/标签 | 可编辑 | `Resource.update` |
| 上架 | 默认询问，不自动上架 | 可选择稍后 | `Resource.update({status:1})` |

## 7. 已有资源更新流程

```text
update <resourceIdOrName>
  → 加载远端资源
  → 确认 owner、类型、最新版本、线上状态
  → 选择更新内容
      ├─ 发新版本
      ├─ 改版本信息
      ├─ 改 listing
      ├─ 改策略
      ├─ 上架
      └─ 下架
  → 展示 diff
  → 写入
  → 输出恢复报告
```

规则：

- 发新版本会继承上一版本可继承信息，但必须展示来源。
- 改版本信息不能替换 `fileSha1`/`filename`。
- 改 listing 只提交用户改过的字段。
- 上下架属于线上影响，必须二次确认或非交互显式声明。

## 8. 策略流程

```text
进入策略阶段
  → 按资源类型拉取模板
  → 展示模板名称、说明、适用对象
  → 选择模板
  → 填参数
  → 编译策略
  → 翻译预览
  → 检查与已有策略是否重复
  → 保存
```

异常：

- 没有模板：提示平台模板为空，可跳过策略或 Console 接力。
- 编译失败：回到具体参数字段。
- 翻译失败：不保存，允许重试。
- 重复策略：展示重复项，允许选择已有策略或修改参数。

## 9. 依赖与授权流程

```text
解析/选择依赖
  → 展示依赖资源
  → 选择 versionRange
  → 校验 semver range
  → 校验至少命中一个版本
  → 查询授权状态
  → 对未授权项处理
      ├─ 去 Console 签约/支付
      ├─ 选择其他版本范围
      └─ 显式排除授权项
```

未授权依赖不能静默跳过。授权排除必须用户显式确认，并写入报告。

## 10. 合集创建与维护流程

```text
collection create
  → 选择合集类型
  → 创建合集资源壳
  → 添加条目：选择已有资源 / 从本地创建后加入 / RSS 导入
  → 排序
  → 条目标题草稿
  → 策略
  → listing
  → 上架或保存草稿
```

维护已有合集：

```text
collection update <collection>
  → 加载合集和条目
  → 选择维护项
      ├─ 添加/移除条目
      ├─ 排序
      ├─ 改条目标题草稿
      ├─ RSS 绑定/更新
      ├─ collect-rules
      ├─ listing
      └─ 上下架
  → 展示目录 diff
  → 保存草稿或发布
```

条目标题必须明确说明“只影响合集内展示，不修改资源全局标题”。

## 11. RSS 流程

```text
rss bind <collection>
  → 输入 feedUrl
  → 预览 feed：标题、封面、作者、邮箱、单集数
  → 发送验证码
  → 输入验证码
  → 如果 matchedItemCount > 1000，进入日期范围筛选
  → 如果是更新 RSS 地址，比较 GUID 差异
  → 写入绑定
  → 锁定 RSS 管理字段
```

规则：

- feed 未预览成功不能发送绑定。
- 验证码错误只清验证码，不清 feed 和预览。
- 日期范围不能选未来。
- 大面积 GUID 不匹配必须明确确认。
- RSS 绑定后，标题、封面、简介由 feed 维护；tags 仍可维护。

## 12. collect-rules 流程

```text
rules edit <collection>
  → 显示当前规则和启用状态
  → 选择启用/停用
  → 选择全部满足/任一满足
  → 添加条件
      ├─ 资源标题
      ├─ 授权标识
      └─ 资源类型
  → 选择操作符
  → 填值
  → 展示自然语言摘要
  → 保存
```

资源类型条件必须进入类型树选择；授权标识前缀必须由当前账号推导，不让用户随便手写别人的 owner。

## 13. 批量流程

```text
batch publish <目录>
  → 扫描目录
  → 应用排除规则
  → 推断资源类型或让用户选择批量类型
  → 生成每项标题和授权标识
  → 检查远端已存在
  → 预览 create/update/skip/fail
  → 用户选择冲突策略
  → 分批写入
  → 输出逐项报告
  → 支持 resume
```

批量不是一次黑盒调用。每个资源都有独立状态：

- `planned`
- `uploaded`
- `resource_created`
- `version_created`
- `listing_updated`
- `online_updated`
- `succeeded`
- `failed`
- `remote_outcome_unknown`

## 14. 主题/插件流程

```text
publish --kind theme/plugin <可选输入>
  → 从平台类型树选择主题或插件类型
  → 选择内容来源
      ├─ 从模板创建新工程
      ├─ 使用现有主题/插件工程
      ├─ 使用已有构建目录
      └─ 使用已有压缩包/artifact
  → 如需要，创建模板工程
  → 如需要，构建和压缩
  → 按普通资源流程发行
  → 检查主题依赖插件
  → 输出 Console 接力信息
      ├─ resourceId
      ├─ latestVersion
      ├─ policyIds
      ├─ node/theme activation link
      └─ 签约/支付提醒
```

CLI 不能因为节点主题激活需要 Console，就漏掉主题/插件资源发行本身。

主题/插件流程必须遵守两个边界：

- 模板创建、构建、压缩只解决本地 artifact；不能替代资源类型、版本、策略和 listing。
- 节点主题激活、签约、支付属于 Console 接力；CLI 只输出所需资源、版本、策略和链接信息。

## 15. 非交互与 AI/CI 流程

非交互不问问题，只做三件事：

1. 从参数、manifest、stdin、环境读取输入。
2. 缺字段直接输出结构化错误。
3. 有写入风险时要求显式 flag，例如 `confirmWrite=true`、`allowOnline=true`。

输出必须稳定：

```text
plan → dry_run → checkpoint → write_event* → result
```

AI 使用时推荐先跑 plan/dry-run，再根据错误补 manifest，而不是让 AI 猜字段。
