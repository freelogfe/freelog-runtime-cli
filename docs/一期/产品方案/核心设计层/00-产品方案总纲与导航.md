## 🚨 **四、错误码速查表**

### **字段验证错误 (FIELD_*)**

```typescript
FIELD_REQUIRED        → 必填字段缺失 (FORM-RES-TITLE 为空时)
TITLE_EXCEEDS_LIMIT   → 标题长度超限 (max=100)
AUTH_ID_EXISTS        → 授权标识已存在
SEMVER_INVALID        → 版本号格式非法
VERSION_NOT_INCREMENTAL → 版本号未递增
TAGS_EXCEED_LIMIT     → 标签数量超限 (max=20 个)
INVALID_TAG_FORMAT    → 标签格式非法 (超过 20 字符或含特殊字符)
```

### **API 调用错误 (API_*)**

```typescript
NETWORK_ERROR         → 网络连接失败
API_TIMEOUT           → API 响应超时 (>30s)
RESOURCE_FROZEN       → 资源处于冻结状态
RATE_LIMIT_EXCEEDED   → 频率超限 (HTTP 429)
BUILD_ENTRY_NOT_FOUND → 构建入口不存在 (main.js 不在 dist/)
```

### **Checkpoint 机制错误 (CHECKPOINT_*)**

```typescript
ACCOUNT_MISMATCH      → 账号不一致 (checkpoint accountId != 当前账号)
CHECKPOINT_EXPIRED    → checkpoint 过期 (>7 天 TTL)
CHECKPOINT_CORRUPTED  → checkpoint 文件格式损坏
```

### **RSS 专属错误 (RSS_*)**

```typescript
FEED_INVALID          → Feed 源无效 (XML 解析失败)
GUID_CONFLICT         → GUID 重复 (已在远端存在)
CAPTCHA_EXHAUSTED     → 验证码次数耗尽 (max=3 次)
COLLECTION_LIMIT_EXCEEDED → RSS 数量超限 (每账号 max=10 个)
```

### **策略模板错误 (POLICY_*)**

```typescript
POLICY_COMPILE_FAILED → 策略编译失败 (JSON Schema 校验不通过)
MISSING_REQUIRED_PARAM → 缺少必填参数 (模板定义的 dynamicParams 未填写)
PARAM_TYPE_MISMATCH   → 参数类型不符 (期望 string,实际为 number)
```

### **批量操作错误 (BATCH_*)**

```typescript
BATCH_SCAN_FAILED     → 目录扫描失败
BATCH_PARTIAL_SUCCESS → 批次中部分成功部分失败
FROZEN_RESOURCE_SKIPPED → 跳过冻结资源而非报错
```

## 💾 **五、Checkpoint 机制速查**

### **数据结构定义**

```typescript
interface Checkpoint {
  version: string;                // 固定为"1.0"
  runId: string;                  // UUID, 唯一标识一次运行
  accountId: string;              // 当前账号 ID(严格匹配)
  completedSteps: string[];       // 已完成的步骤列表
  collectedData: {                // 已收集的业务数据
    resourceShell?: ResourceShell;
    versionInfo?: VersionInfo;
    customProperties?: Record<string, any>;
    policy?: CompiledPolicy;
    coverUrl?: string;
    tags?: string[];
    // ...其他中间状态数据
  };
  remoteResources?: {             // 已写入远端的资源 ID
    resourceId: string;
    versions?: string[];
  };
  timestamp: string;              // 创建时间
  ttlDays: number;                // TTL=7 天
}
```

### **保存时机**

| 场景 | 触发条件 | 代码实现 |
|-----|---------|---------|
| BEFORE_REMOTE_WRITE | 每次写平台 API 前 | `saveCheckpoint({ step: 'before_remote_write', collectedData: {...}})` |
| SIGNAL_HANDLER | Ctrl+C/Ctrl+Z 信号 | `process.on('SIGINT', () => saveCheckpoint({ step: 'signal_handler' }))` |
| EXPLICIT_USER_SAVE | 显式 save 命令 | `freelog checkpoint save --runId <uuid>` |

### **恢复逻辑**

```typescript
async function resumeFromCheckpoint(runId: string): Promise<boolean> {
  const checkpoint = await loadCheckpoint(runId);
  
  // 1. 账号严格匹配
  if (checkpoint.accountId !== currentAccount.id) {
    throw new UserFacingError('ACCOUNT_MISMATCH', {
      hint: `Checkpoint accountId (${checkpoint.accountId}) does not match current credential`
    });
  }
  
  // 2. TTL 检查 (>7 天删除)
  const daysOld = (Date.now() - new Date(checkpoint.timestamp).getTime()) / (1000 * 60 * 60 * 24);
  if (daysOld > checkpoint.ttlDays) {
    deleteCheckpoint(runId);
    throw new UserFacingError('CHECKPOINT_EXPIRED');
  }
  
  // 3. 恢复数据
  skippedSteps.forEach(step => logSkip(step));
  appliedSteps.forEach(step => logContinue(step));
  
  return true;
}
```

### **TTL 过期清理算法**

```typescript
// 每日定时任务
setInterval(async () => {
  const checkpoints = fs.readdirSync(CHECKPOINT_DIR);
  
  for (const file of checkpoints) {
    const checkpoint = JSON.parse(fs.readFileSync(file));
    const age = Date.now() - new Date(checkpoint.timestamp).getTime();
    
    if (age > 7 * 24 * 60 * 60 * 1000) {
      fs.unlinkSync(path.join(CHECKPOINT_DIR, file));
      logger.debug(`Checkpoint expired and deleted: ${file}`);
    }
  }
}, 24 * 60 * 60 * 1000); // 每日执行
```

### **Q2: 为什么有三层架构？**

**A**: 
- **第 1 层（核心设计）**：定规范，PM 和开发必读，确保业务规则一致
- **第 2 层（场景演练）**：看流程，全角色都可查阅，用于理解真实用户旅程
- **第 3 层（实现规范）**：写代码，开发专用，提供具体实现步骤和验收标准

这种分层的好处：
- ✅ 不同角色能快速找到所需信息
- ✅ 新增功能时不会遗漏业务流程

### **Q5: Checkpoint 丢失了怎么恢复？**

**A**: 
```bash
# 查看可用的 checkpoints
$ freelog checkpoint list

# 尝试恢复指定 runId 的 checkpoint
$ freelog checkpoint resume --runId publish-20260902-abc123

# 如果账号不匹配，可以强制丢弃（仅限测试环境）
$ freelog checkpoint force-delete --runId publish-20260902-abc123
```

注意：**生产环境禁止强制丢弃**,因为可能导致业务状态不一致。
