# 06 · 实现解决方案

> **文档角色：** 实现解决方案。本文定义实现架构和交付契约，但不绑定旧代码文件。代码结构可以调整，业务边界不能偏离本方案。

最后更新：2026-09-02

## 1. 实现目标

实现不是把 Console 接口包一层命令，而是把产品方案落成六个稳定能力：

1. 身份与环境解析。
2. 平台动态数据读取。
3. 字段校验和表单状态。
4. 业务流程状态机。
5. 本地模板创建、现有工程识别、构建、独立压缩、发布内打包、上传。
6. 远端写入、报告、恢复和 Console 接力。

## 2. 分层架构

```text
Command Layer
  只解析命令意图、输入来源、输出格式

Interaction Layer
  TTY 向导、非交互字段收集、AI/CI JSON 协议

Workflow Layer
  单资源、更新、合集、RSS、rules、批量、主题/插件状态机

Domain Layer
  字段账本、校验器、默认值、diff、风险等级、错误映射

Platform Adapter Layer
  Console 对齐接口：Resource、Policy、Storage、Rss、Exhibit

Local Resource Layer
  文件扫描、工程模板、构建、独立压缩、发布内打包、manifest、checkpoint、report

Auth/Session Layer
  环境、账号、profile、临时会话、多账号、凭据读取
```

依赖方向只能从上往下。平台 adapter 不能反向调用交互层；workflow 不能直接拼 Console URL；字段校验不能读写本地报告。

### 6.1 Checkpoint Interface Definition

```typescript
/**
 * Checkpoint 数据结构定义 - P0 级重要设计
 */
interface Checkpoint {
  // ===== 基础元数据 =====
  version: "1.0";                              // Checkpoint 格式版本
  runId: string;                               // 唯一运行 ID（UUID）
  accountId: string;                           // 账号 ID（用于校验恢复权限）
  environment: "dev" | "test" | "production"; // 环境标识
  
  // ===== 流程进度 =====
  completedSteps: string[];                    // 已完成步骤列表
  currentStep: string;                         // 当前卡住的步骤
  status: "active" | "abandoned" | "completed";
  
  // ===== 已收集的字段数据（关键！防止数据丢失） =====
  collectedData: {
    resourceTitle?: string;
    resourceName?: string;
    resourceType?: string;
    version?: string;
    description?: string;
    customProperties?: Record<string, any>;
    coverImage?: string;
    tags?: string[];
    intro?: string;
    policyTemplate?: string;
    fileSha1?: string;
    fileName?: string;
    dependencies?: Array<{resourceId: string; versionRange: string}>;
    // ... 其他所有用户输入过的字段
  };
  
  // ===== 远端已创建的资源 ID（关键！避免重复创建） =====
  remoteResources?: {
    resourceId?: string;                       // Resource.create() 返回的 ID
    versionId?: string;                        // Resource.createVersion() 返回的 ID
    policyId?: string;                         // Policy.save() 返回的 ID
  };
  
  // ===== 中断信息 =====
  metadata: {
    createdAt: string;                         // ISO 8601 时间戳
    updatedAt: string;                         // 最后更新时间
    lastAction: string;                        // 最后执行的动作
    interruptedBy?: "SIGINT" | "SIGTERM" | "NETWORK_ERROR" | "API_ERROR" | null;
    cliVersion: string;                        // CLI 版本号
    cwd: string;                               // 工作目录
    command?: string;                          // 原始命令（脱敏）
  };
  
  // ===== 批量任务特有字段 =====
  batchInfo?: {
    totalItems: number;
    processedItems: number;
    succeededItems: string[];                  // 已成功处理的 item
    failedItems: Array<{item: string; reason: string}>;
    pendingItems: string[];
  };
}
```

**AccountId 校验逻辑**：

```typescript
function validateCheckpointRestore(checkpoint: Checkpoint, currentCredential: Credential): boolean {
  if (checkpoint.accountId !== currentCredential.accountId) {
    return {
      valid: false,
      reason: "ACCOUNT_ID_MISMATCH",
      checkpointAccount: checkpoint.accountId,
      currentAccount: currentCredential.accountId,
      message: "Checkpoint 是为其他账号创建的，拒绝恢复以防止权限冲突",
      options: ["switch_account", "force_resume_with_warning", "delete_stale_checkpoint"]
    };
  }
  return { valid: true };
}
```

**TTY 交互模式**：

### 6.5 验收标准

**TYY 模式验证**：

1. ✅ 任意步骤 Ctrl+C → checkpoint 自动保存
2. ✅ 下次启动提示恢复选项
3. ✅ 恢复后已填数据不丢失
4. ✅ 已在平台的资源 ID 不重复创建

**非交互模式验证**：

1. ✅ checkpoint 存在时输出结构化 JSON
2. ✅ accountId 不匹配时返回明确错误码
3. ✅ missing_fields 从 checkpoint 读取
4. ✅ resume 路径可在建议中引用

### 7.1 Checkpoint JSON 错误码定义（P1 级修订）

**背景**（来自完整场景演练发现）：

之前设计中提到非交互模式会输出 checkpoint 信息，但**没有定义具体的 JSON 错误码结构**。这会导致 AI-CI 自动化脚本无法准确解析错误并作出相应处理。

**新规则：为所有 checkpoint 相关事件定义标准化的 JSON 输出格式**

#### 事件类型清单

| 事件 | 触发时机 | 数据结构 |
|-----|---------|---------|
| `checkpoint_detected` | 检测到未完成的 checkpoint | 包含 runId、accountIdMatch、currentStep |
| `checkpoint_resume_success` | 成功恢复 checkpoint | 包含 completedSteps、collectedData |
| `checkpoint_account_id_mismatch` | accountId 不匹配拒绝恢复 | 包含 checkpointAccountId、currentAccountId |
| `checkpoint_deleted_manually` | 用户显式删除 checkpoint | 包含 deletedAt、reason |
| `checkpoint_expired` | 超过 7 天自动清理 | 包含 createdAt、expiredAfter |

#### 具体示例

#### TTY vs 非交互模式的差异

| 场景 | TTY 模式 | 非交互/AI 模式 |
|-----|--------|-------------|
| checkpoint 存在 | ⌨️ 提示：是否恢复？[Y/n] | 📄 JSON: `checkpoint_detected` |
| accountId 不匹配 | ❌ 拒绝恢复 + 选项 A/B/C | ❌ 返回 `CHECKPOINT_ACCOUNT_ID_MISMATCH` 错误码 |
| 成功恢复 | ⌨️ 显示跳过的步骤 | 📄 JSON: `checkpoint_resume_success` |
| 用户取消 | ⌨️ 保留 checkpoint | 📄 JSON: `checkpoint_abandoned` |
| 正常完成 | 🗑️ 自动删除 checkpoint | 📄 JSON: `checkpoint_completed` |
| 超过 7 天 | ℹ️ 提示：是否清理旧 checkpoint | 📄 JSON: `checkpoint_cleanup` |

#### 验收标准

**TTY 模式**：
- ✅ checkpoint 存在时显示清晰的恢复提示
- ✅ accountId 不匹配时给出 3 个可选操作
- ✅ 成功恢复后展示跳过的步骤和继承的字段

**AI/CI 模式**：
- ✅ 所有 checkpoint 相关事件都有明确的 event 名称
- ✅ error 事件包含 errorCode、details、recommendation 三要素
- ✅ options 数组提供可执行的操作命令
- ✅ 结构化数据可被脚本解析（JSON Schema 验证通过）

**边界条件验证**：

1. ✅ 超过 7 天的 checkpoint 自动清理
2. ✅ 跨账号恢复被拒绝并给出选项
3. ✅ 正常完成后 checkpoint 被删除
4. ✅ 显式 cancel 时保留 checkpoint
| RunReport | 执行报告 | plan、events、result、errors、resume |

## 4. 状态机契约

### 4.1 本地准备能力

独立模板创建：

```text
template_select
  → target_dir_validated
  → conflict_checked
  → files_written
  → template_report_written
  → next_steps_printed
```

独立压缩：

```text
pack_scan
  → ignore_applied
  → file_summary_ready
  → output_path_validated
  → archive_written
  → checksum_ready
  → pack_report_written
```

发布流程内准备：

```text
source_selected
  → template_created_optional
  → build_completed_optional
  → pack_completed_optional
  → artifact_ready
```

独立模板创建和独立压缩默认不进入平台写入。只有用户继续 `publish`，或非交互输入明确要求发布，才进入后续资源状态机。

### 4.2 单资源发布

```text
init
  → session_ready
  → type_selected
  → source_selected
  → resource_validated
  → resource_created
  → artifact_prepared
  → artifact_ready
  → artifact_uploaded
  → version_validated
  → version_created
  → policy_saved
  → listing_saved
  → online_decided
  → completed
```

任何远端写入前必须生成 checkpoint。`resource_created` 之后失败，resume 时不能重新创建资源壳，必须先查远端。

### 4.3 已有资源更新

```text
load_remote
  → choose_update_kind
  → prepare_diff
  → confirm_write
  → write
  → verify_remote
  → completed
```

更新流程以 diff 为核心。没有 diff 不调用写接口。

### 4.4 合集

```text
collection_loaded
  → items_loaded
  → catalogue_diff_ready
  → item_title_diff_ready
  → policy_listing_ready
  → save_draft_or_publish
  → completed
```

条目维护和资源本体维护必须是两个不同状态，不能共用字段名导致误写。

### 4.5 RSS

```text
feed_input
  → feed_previewed
  → verification_sent
  → verification_passed
  → limit_checked
  → guid_checked
  → bind_written
  → locked_fields_applied
```

没有 `feed_previewed` 不能进入验证码；没有 `verification_passed` 不能绑定。

### 4.6 批量

```text
scan
  → classify
  → generate_names
  → remote_probe
  → plan
  → dry_run
  → chunk_write
  → reconcile_unknown
  → report
```

批量状态必须逐项记录，不能只有整批成功/失败。

## 5. 字段 registry 契约

每个字段都必须注册：

| 属性 | 说明 |
|---|---|
| fieldId | 与 02 字段账本一致 |
| label | 给用户看的字段名 |
| source | 用户输入、默认值、平台动态数据、继承、解析 |
| required | 必填规则 |
| validate | 本地校验 |
| normalize | 规范化规则 |
| defaultValue | 默认值和来源 |
| prompt | TTY 提示 |
| nonInteractiveError | 非交互缺失/错误 code |
| apiMapping | 写入哪个接口参数 |
| lockedWhen | RSS、owner、状态等禁用条件 |
| recovery | 出错后回到哪里 |

没有 field registry 的字段不能进入远端写入。

## 6. 平台 adapter 契约

平台 adapter 必须做四件事：

1. 把产品语义参数转成平台接口参数。
2. 把平台错误转成字段错误或流程错误。
3. 保留原始平台错误供调试，但默认输出不泄漏敏感信息。
4. 不把交互逻辑写进 adapter。

核心 adapter：

| Adapter | 负责 |
|---|---|
| Resource | 类型树、资源创建、版本创建、资源更新、合集、批量 |
| Policy | 模板、编译、翻译 |
| Storage | 文件和封面上传 |
| Rss | feed 预览、验证码、绑定、比较 |
| Exhibit | 主题激活接力信息构造；一期不默认闭环写入 |

## 7. 输出协议

人类输出和机器输出来自同一份 workflow event。

事件类型：

- `step_started`
- `field_required`
- `field_invalid`
- `remote_call_started`
- `remote_call_succeeded`
- `remote_call_failed`
- `checkpoint_written`
- `template_created`
- `pack_archive_written`
- `artifact_ready`
- `handoff_required`
- `item_succeeded`
- `item_failed`
- `run_completed`

机器输出必须包含：

- `runId`
- `env`
- `account`
- `workflow`
- `step`
- `status`
- `resourceId/resourceName`，如已知
- `fieldId`，如是字段错误
- `errorCode`
- `resumePath`

## 8. 本地文件与状态

| 文件 | 用途 | 规则 |
|---|---|---|
| manifest | 用户可编辑的目标声明 | 可以提交到仓库，但不能包含凭据 |
| checkpoint | 当前 run 的恢复点 | 默认本地生成，不建议提交 |
| report | 执行结果和审计 | 可脱敏后提交 |
| session | 当前身份和临时流程状态 | 不提交，不打印凭据 |
| template report | 模板创建结果 | 记录模板 ID、版本、目标目录、写入文件和冲突 |
| pack report | 独立压缩结果 | 记录输入目录、包含/忽略/拒绝文件、输出路径、大小、sha1 |
| build artifact | 构建/压缩产物 | 写入前显示路径、大小、hash |

所有本地写入必须原子写；覆盖用户可编辑文件前必须保留可恢复副本或明确 diff。

## 9. 测试与验证

实现完成至少需要：

| 类型 | 覆盖 |
|---|---|
| 字段单测 | 资源标题、授权标识、版本号、版本范围、封面、简介、标签、RSS 日期、rules 条件 |
| 状态机单测 | 模板创建、独立压缩、单资源、更新、合集、RSS、批量 |
| adapter 单测 | 参数映射、错误映射、敏感信息脱敏 |
| 文档治理测试 | 文档没有敏感信息、没有不可执行命令、没有悬空占位 |
| 集成 smoke | dev 环境账号登录、类型树读取、dry-run、至少一个真实写入链路 |
| 恢复测试 | 上传成功发布失败、写入未知、批量部分失败 |

真实 dev 写入测试必须记录脱敏报告，不能把账号密码、token、cookie 写进仓库。

## 10. 实现顺序

1. 先落字段 registry 和状态机骨架。
2. 再接平台动态读取和 adapter。
3. 再接 TTY/非交互/AI 三种交互。
4. 再实现独立模板创建和独立压缩，使本地准备能力可单独验收。
5. 再把模板/构建/压缩接入单资源完整闭环。
6. 再实现更新、合集、RSS、rules、批量。
7. 最后做真实 dev smoke 和手测文档。

不能先写零散命令再回头拼流程。

## 11. 完成定义

代码实现只有同时满足以下条件，才算完成：

- 产品方案里的主流程都有对应状态机。
- 模板创建和独立压缩可以脱离发布单独运行，也可以作为发布流程内的内容来源准备阶段。
- 02 字段账本里的字段都有 registry 和测试。
- 04 的每个 CLI 流程都能跑 plan/dry-run。
- 05 的异常至少有单测或 smoke 覆盖。
- 输出协议稳定，AI/CI 不依赖自然语言猜测。
- dev 真实账号测试完成并生成脱敏报告。
