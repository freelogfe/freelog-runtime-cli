## 已确认产品边界

| 主题 | 当前规则 |
|---|---|
| 资源模型 | 单资源为 `subjectType=1`；合集为 `subjectType=4` 的独立线上目录主体。批量单资源发行、RSS 管理、支付、session、studio 当前均不做；普通命令必须保护 RSS 目标，避免误写。 |
| 身份主本 | `.freelog/N.json` 是永久的本地身份主本，不是版本历史。单资源额外含产物锚点；合集不含 `filePath`。已绑定后的 `resourceId`、完整 `resourceName`、类型、环境是身份事实；`title` 只是可过期、可重复的展示缓存。 |
| 工作稿 | `.freelog/N.version.json` 仅为同号资源当前未提交工作稿。确认版本 POST 成功时删工作稿；平台保存历史。 |
| 资源选择 | `--resource` 只选择身份：`id:`、完整 `name:`、`artifact:`、`file:N.json`。不支持 `title:`；标题同步只能显式 `resource sync`。 |
| 产物参数 | 公开命令只使用 `--artifact <path>`；它只表示文件或构建目录，不选择身份。没有公开 `--file`。 |
| 产物形态 | 普通资源必须锚定/提交普通文件。主题、插件可锚定文件或构建目录；仅目录在提交时临时压缩，显式文件（含 zip）直接上传。 |
| 模板 | 模板在线安装并原样复制；当前不渲染 `package.json`。没有 `N.template.json`。主题/插件的类型固定，无需用户选择。 |
| 合集选择 | 合集命令使用 `--resource id:<id>`、`name:<username/name>` 或 `file:N.json`；合集没有 artifact 选择器。无参数时仅在本地恰有一份合集身份时自动选择。 |
| 环境 | 显式 `--env dev` / `test`；省略为 `prod`，当前 prod 平台调用被拦截。身份环境必须与当前环境一致。 |
| 远端写入 | 已绑定资源的写入前必须以 `resourceId` 重查详情，严格确认响应 ID、当前 owner（`userId` / `ownerId` / `creatorId`）和未冻结。 |
| 策略与依赖 | 策略模板分页展示所有适用模板；依赖未授权时展示对方所有启用策略，由人或脚本显式选择 `--policy-id`，绝不取“第一条”。 |

## 2026-09-11 本轮已实现的健壮性闭环

- `version dep add` 与 `version dep range` 已共用目标事实校验：普通资源、可信 `latestVersion`、可用状态、无基础上抛、可解析且包含 latest 的版本列表、范围命中，任一事实异常都不会签约或写工作稿。这个修复不改变已确认的“签约成功即可写稿、支付留浏览器”的规则。
- 可选配置现在有三道类型门：`option add`、`option set` 和版本提交。类型不支持时 add/set/submit 都拒绝；`option rm` 刻意仍可用，以清理历史工作稿中的遗留项。
- `.pending-operation.json` 已升级为 schema v2：`prepared` 表示尚未允许 POST，`sending` 表示请求可能已离开本机；旧 schema v1 一律保守视为 `sending`。`resource recover --apply --yes` 对 prepared 只清 marker、留工作稿；对 sending 仍只有远端目标版本与 SHA 完全一致才同时清稿和 marker。绝不重发。
- 新增 `test/verify-optional-config.mjs`（属性 add/set、依赖签约、文本/下拉 add/set/rm、首版/更新版读回）和 `test/run-final-acceptance.mjs`。字段真网脚本只读取用户维护的 `test/.freelog-test-resource-pool.local.json`，不再引用过时的固定依赖 fixture。最终入口把缺 fixture、TTY 工具、后端事件模板契约或未实际执行的付费签约分支标成 `BLOCKED`（非零），只有全部真实通过才会 `PASS`。
- **可选配置能力已经按 Console 契约闭环。** `type info`、候选扫描、`version option add/set` 和首版/更新版提交均共用 `resourceConfig.supportOptionalConfig === 2` 的归一化结果；旧接口响应才兼容顶层字段。候选扫描是只读诊断，真实验收仍由被忽略的 fixture 显式配对类型与产物，CLI 不猜测跨类型产物。TTY 验收已统一为根开发依赖 `node-pty@1.1.0`：Windows 的 ConPTY 与 macOS/Linux 的系统 PTY 都隐藏在同一个测试 API 后，不安装 `expect`、不保留 PowerShell/C# 驱动分支，也不进入 CLI 发布包。探针同时验证 TTY 标志和 Inquirer 的真实下移选择。
- `node-pty` 迁移后已重新通过完整 CLI test（30 文件 / 168 项）、typecheck、build、发布包 smoke 与 `git diff --check`；Windows 本机的真实 Inquirer 下移选择也已通过。随后 primary dev 已通过 S63/S65/S66（多资源选择、标题同步、连续 create/bind）及 S67（默认取消、reset/discard 工作稿安全），并通过可选配置同稿的完整首版/更新版读取链。2026-09-11 最终入口已实际跑完：场景、字段、资源池依赖、可选配置、TTY 与工作稿安全均 PASS；`verify-commands` 的 46 项均通过但事件模板 DSL 仍 BLOCKED；付费依赖的“未授权→签约”分支因资源池当前所有付费候选均已对 primary 授权而 BLOCKED。临时工程已清理，资源壳按脚本规则保留为未发布审计记录。

## 已知未完成或需继续复核的事项

1. **远端未知结果不是全覆盖。** 已可靠闭环的是版本 POST。create、listing、策略、上下架和依赖签约尚未全部建立同等的可证明 recovery；其中没有平台幂等键或不可歧义查询条件的操作，不能伪造“已经可恢复”。新扩展必须先说明平台可证明事实、用户确认点和无法证明时的保留策略。
2. **未知提交不能稳定地在 dev 人为制造。** 版本 POST 的未知结果由 pending/recover 单测覆盖；若以后有可控网络中断环境，需用真实 POST 中断后按 `resource recover` 再补一次端到端证据。
3. 已完成本轮最终静态精校：非归档文档不再把 `index.json`、`--file`、`artifactMode`、标题选择器或“仅免费模板”描述成现行规则；主题/插件的预制 zip 换锚点也已补入用户手册。
4. [当前设计健壮性问题与目标模型](./当前设计健壮性问题与目标模型-2026-09-10.md) 和 [治理计划](../../../.omx/plans/2026-09-10-单资源CLI健壮性治理计划.md) 仍须在每次新增设计决定后同步状态；不要让早期“全部未实现”表述继续误导后续工作。
5. **策略与依赖的当前范围已确认。** 模板全量请求、事件编译和参数填写等待后端；依赖签约成功即写稿，支付留在浏览器端。依赖的支付业务代码不再因这些平台问题改动；但 `dep add/range` 的目标事实校验已按上节补齐。远端写入未知结果恢复仍按第 1 项的可证明边界另行评估。
6. **付费依赖的真网签约覆盖缺口。** `verify-paid-dep` 不再固定历史资源名，而是从资源池动态选取 primary 当前未授权且策略仍启用的付费目标；目前没有这样的目标，所以明确 `BLOCKED`。若要让最终入口全绿，资源池须提供一个该账号尚未授权的启用付费策略；CLI 不撤销既有合约来制造测试条件。

## 不要违反

- 不实现或注册顶层 `publish`、顶层 `release`、顶层 `dep`、session、studio 命令；合集只实现已写入正式合集设计并经过复核的 `collection` 子命令。
- 不把 `create-version` 与 `update-version` 合并；没有 `update-version --prepare`。
- 不把 `--artifact` 当身份选择器，不按多份状态或策略列表的“第一条”自动操作。
- 不在 `N.json` 放版本号、策略、listing、SHA-1、模板元数据或秘密；标题只作展示缓存。
- 不用不存在本地产物的旧 SHA 发版；不要求主题/插件用户预先手工压 zip。
- 不把历史评审中的“建议”“待实现”“未确认草案”当作可用功能。
- 不将密码、token、cookie 写进仓库、文档、测试输出或终端记录。
