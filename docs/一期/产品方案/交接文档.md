## 当前事实

| 项 | 当前口径 |
|---|---|
| 范围 | 仅普通单资源、主题、插件；合集、批量发行、RSS、支付、上抛、session、studio 不做。 |
| 环境 | 显式使用 `--env dev` 或 `--env test`；省略是 prod，而 prod 平台调用当前被拦截。 |
| 发行 | 无线上版本只能 `create-version` 发布 `1.0.0`；有线上版本只能 `update-version` 发布新号；两条命令不可合并。 |
| 工程边界 | 一个工程可管理多个独立单资源：`.freelog/N.json` 与 `N.version.json` 成对保存，`index.json` 是派生索引。每次资源命令用 `--resource` 选择；未指定时单份自动选择，多份交互选择。 |
| 产物路径 | 公开命令只使用 `--artifact <path>` 表示产物路径；它绝不选择资源。身份通过 `--resource <selector>` 或交互列表选择。 |
| 本地状态 | `N.json` 是身份、标题与默认产物路径；同号 `N.version.json` 是未提交下一版，POST 成功即删除。`update --title` 成功后回写标题，`resource sync` 可按资源 ID 批量同步当前环境的标题。没有 `N.template.json`。重复身份、路径冲突或孤儿工作稿一律保留并报错，给出备份、删除完整状态单元或重新 bind 的选项。 |
| 模板 | `init theme` / `init widget` 仅安装受控、固定版本的线上模板；不渲染、不安装依赖、不写模板元数据。 |
| 主题/插件产物 | `RT001` / `RT002` 的目录产物由 CLI 在发版时打临时 zip；其它类型传目录失败。 |
| 可选配置 | 只能在类型详情 `supportOptionalConfig === 2` 时添加。当前 dev 的 `RT001` 不满足此条件，主题不能假定支持可选配置。 |
| 依赖 | 只看 `Resource.batchAuth` 的 `isAuth`；未授权时列出全部启用策略，用户选一条签约，签后直接写稿；不区分免费/付费，不查合约，不处理上抛。 |
| 本地可靠性 | 状态写入使用锁、原子文件替换；跨身份/工作稿改动写 `.txn.json`，下一次持锁操作前滚恢复。 |

推荐主路径：

```text
普通文件：login → init . → create --artifact video.mp4 → create-version --prepare → create-version --yes
主题/插件：login → init theme|widget . --template <id> → create → 自己构建 dist → create-version --artifact dist --yes
已有资源：login → bind <id|username/name> --artifact <文件或目录> → version draft pull → update-version --yes --bump patch
```

`login` 后再 `init .` 是允许的：init 会保留唯一既有的 `.freelog/auth` 认证选择器；任何其它业务文件或既有身份状态仍拒绝覆盖。

## 不要违反

- 不注册或实现 `publish`、顶层 `release`、顶层 `dep`、合集/F1/RSS/session/studio 命令。
- 不把 `create-version` 与 `update-version` 合成一条；没有 `update-version --prepare`。
- 不把 `--artifact` 当身份选择器；不得按多份状态的“第一条”自动操作。多资源工程必须用 `--resource` 或 TTY 选择，`index.json` 只能作派生索引。
- 不在 `N.json` 放版本号、策略、listing、文件 SHA 或模板信息；仅允许标题作为选择与展示元数据。
- 不复用本地不存在的文件的旧 SHA；每次真实版本提交都要从当前产物重新确认和分析。
- 不把主题/插件工程手工打 zip 当作用户前置步骤；CLI 只压目录内容。
- 不按策略列表“第一条”自动签约；非交互未授权依赖必须给当前列表中的 `--policy-id`。
- 不把历史的“RT001 支持可选配置”当事实；类型能力必须每次由详情接口判定。
- 不把密码、token、cookie 写入仓库、文档或测试输出。
