## 🎨 五、文档格式规范

### 标准模板结构

```markdown
# P0-X-XXXXX

## 📋 概述
Console XX 流程的完整业务流程，基于 `xxx` 源码分析。

### 主流程 (ASCII)
```
开始 → ... → 结束
```

---

## 一、[功能模块 1]

### 操作流程
1. ...
2. ...

### API 调用

| 操作 | tools-lib 函数 | HTTP 接口 | i18n key (zh_CN) |
|------|---------------|----------|------------------|
| ... | ... | ... | key: "中文翻译" |

### 字段约束

| 字段名 | maxLength | 必填 | 默认值 | i18n key (zh_CN) |
|--------|-----------|------|--------|------------------|
| `field1` | 100 | ✅ | null | rqr_field_1: "请..." |

### Console 源码位置
- Lxx-yy: 组件/逻辑描述
```

### 必须包含的内容

✅ **每个文档必须有**:
1. ASCII 流程图
2. 操作流程列表
3. API 调用表 (工具库 + HTTP + i18n 翻译)
4. 字段约束表 (带来源标注)
5. Console 源码引用位置 (文件名 + 行号)
6. i18n keys 中文翻译
7. CLI Flag 设计建议

❌ **禁止出现**:
- TypeScript/JavaScript 真实代码
- 无源码依据的猜测内容
- 跨文档重复定义
