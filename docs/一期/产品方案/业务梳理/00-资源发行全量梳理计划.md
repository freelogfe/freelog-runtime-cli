## 4. 建议执行顺序

先写完「从无到有」，再写「已有资源怎么改」，最后写列表/详情（多半是读状态 + 跳进上述写路径）。

### Wave 1 — 其余创建流（对 CLI 首发命令）

1. **F1 批量**：`showPage` = `resourceType` → `uploadFile` → `finish`。对照 `resource import-dir` / `Resource.createBatch`。
2. **C0 合集**：四步是「创建合集 → 添加单品 → 添加授权策略 → 完善合集信息」，**不是**扫本地五步。单品来自「我的资源」勾选（每批 100）或 RSS。对照 `collection create` / `item` / `publish`。Step2 单独成篇。
3. **M0 新版本**：与 F0 Step2 交叉引用，只写差异：路由 `:id`、`FVersionInput`、可继承上一版、草稿优先于 inherit、`createVersion.version` 用输入值。对照已绑定后的 `version set` + `publish`。

### Wave 2 — 单资源维护（对 CLI 日常命令）

按侧栏从上到下：

| 编号 | 侧栏 i18n | 页面 | CLI |
|------|-----------|------|-----|
| M1 | `edit_resource_tab_versions` | `sidebar/versionInfo` | `version` / 进 M0 |
| M2 | `edit_resource_tab_articleinfo` | `sidebar/info` | `update` `pull` |
| M3 | `edit_resource_tab_authplans` | `sidebar/policy` | `policy` |
| M4 | `edit_resource_tab_relynauth` | `sidebar/dependency` | `dep`（仅免费签约） |
| M5 | `edit_resource_tab_licenceecontracts` | `sidebar/contract` | 只读/提示走 Console |
| M6 | 侧栏开关 | `Sider` `resourceOnline` / `update status:4` | `online` `offline` |

M6 门禁（须有版本、须有启用策略）写进同一篇，供 `validate --for online` 对齐。

### Wave 3 — 合集维护

- **C1** 版本页：单品增删改、排序、授权，比 M1 重。
- **C2** 信息页：listing + 自动收录规则 + RSS 只读字段。
- **C3** 策略/依赖/签约/上下架：与 M3–M6 同构处交叉引用，只记合集差异。

### Wave 4 — 列表与详情

- **L1** 列表筛选项、状态徽章、跳创建/编辑。
- **L2** 详情只读字段 + 跳侧栏/新版本；不把详情当第二套编辑器。
