# P0-F0: 单资源发布流程

## 概述

Console「发行单个资源」四步向导。入口：`creatorEntry` → `FUtil.LinkTo.resourceCreator()` → `pages/resource/creator`。

页面总标题：`rqr_title` → 「发行资源」。

证据与格式见 [业务梳理 README](../README.md)。Step 细节以分册为准，本文只记主流程和跨步状态。

### 主流程 (ASCII)

```
creatorEntry「发行单个资源」
  → Step1 创建授权条目     得到 resourceId + 类型配置
  → Step2 提交资源文件     上传/属性/依赖 → createVersion
  → Step3 添加授权策略     可选；可跳过
  → Step4 完善资源详情     封面/简介/标签 → 可上架
```

### 分册

| 步 | i18n | 文案 | 文档 |
|----|------|------|------|
| 1 | `rqr_step1` | 创建授权条目 | [P0-F0-Step1-创建授权条目.md](./P0-F0-Step1-创建授权条目.md) |
| 2 | `rqr_step2` | 提交资源文件 | [P0-F0-Step2-提交资源文件.md](./P0-F0-Step2-提交资源文件.md) |
| 3 | `rqr_step3` | 添加授权策略 | [P0-F0-Step3-添加授权策略.md](./P0-F0-Step3-添加授权策略.md) |
| 4 | `rqr_step4` | 完善资源详情 | [P0-F0-Step4-完善资源详情.md](./P0-F0-Step4-完善资源详情.md) |

侧栏说明：Step3 显示 `rqr_authplan_info`；Step4 显示 `rqr_listing_info`。

## 跨步状态

创建成功后 `resourceCreatorPage` 里后续步骤依赖这些字段（见 `step1Effects.ts` 创建成功分支、`types.ts`）：

| 字段 | 来源 | 后续用途 |
|------|------|----------|
| `step1_createdResourceInfo.resourceID` | `Resource.create` 的 `resourceId` | Step2 建版本、Step3 策略、Step4 listing |
| `step1_createdResourceInfo.resourceName` | 创建响应 | 展示 / 后续查询 |
| `step1_createdResourceInfo.resourceTypeCode` | 创建响应 | Step2 属性、依赖 |
| `step2_resourceTypeConfig.uploadEntry` | `getResourceTypeInfoByCode.fileCommitMode` 位标志 | 打开哪些上传入口 |
| `step2_resourceTypeConfig.limitFileSize` | `fileMaxSize * 1024 * (1024 ** fileMaxSizeUnit)` | 本地上传上限 |
| `step2_resourceTypeConfig.isSupportDownload` | `supportDownload === 2` | 是否显示下载 |
| `step2_resourceTypeConfig.isSupportEdit` | `supportEdit === 2` | 是否显示编辑 |
| `step2_resourceTypeConfig.isSupportOptionalConfig` | `supportOptionalConfig === 2` | 是否显示可选配置 |

离开确认：`creator/index.tsx` 在 `step1/2/4_dataIsDirty_count !== 0` 时弹出 `FPrompt`（Step3 策略 dirty 不参与该 watch）。

## CLI 串联（已有命令，不新造）

```
login --env <env>
  → type search / type info
  → init . --scaffold none --resource-type <code> --artifact-mode file --yes
  → create --title --type --name [--type-name] --yes
  → version set --version --file
  → validate --for publish
  → publish --yes
  → policy template apply <templateId> --yes
  → online --yes
```

对应关系：`create` = Step1；`version set` + `publish` = Step2；`policy` = Step3；`update` / `online` = Step4。
