# P0-F0: 单资源发布流程

## 📋 概述

Console 单资源发布的完整业务流程，基于 `packages/console/src/pages/resource/creator` 源码分析。

### 主流程 (ASCII)

```
开始 → 选择资源类型 → 输入标题 (自动同步名称) → 唯一性检查 (防抖 300ms) 
     ↓
创建资源壳 (得到 resourceId) → 跳转 Step2
```

---

## 一、选择资源类型

### 操作流程
1. 浏览类型树（一级→二级→...→叶子）
2. 或搜索加速
3. 选择到最后一级叶子类型
4. 支持新建类型

### API 调用

| 操作 | tools-lib 函数 | HTTP 接口 | i18n key (zh_CN) |
|------|---------------|----------|------------------|
| 获取类型树 | `typeService.getResourceTypeTree()` | `GET /resource/type/tree` | rqr_input_resourcetype: "请选择资源类型" |
| 搜索类型 | `typeService.searchResourceTypes(q)` | `GET /resource/type/search?q={q}` | - |
| 选择类型 | - | - | naming_convention_resource_type_required: "请选择资源类型" |
| 新建类型 | `typeService.createResourceType(data)` | `POST /resource/type/create` | cqr_add_new_type_hint: "添加新类型" |

### 字段约束
- **必填**: 必须选择叶子类型
- **组件**: `FResourceTypeInput4`
- **maxLength**: ∞
- **CLI Flag**: `--type-code <typeCode>`

### Console 源码位置
- L91-102: FResourceTypeInput4 组件调用

## 二、输入资源标题与自动同步名称

### 操作流程
1. 输入资源标题
2. 如果当前名称 == 标题 → 自动同步前 60 字符到 name
3. maxLength=100

### API 调用

| 操作 | tools-lib 函数 | HTTP 接口 | i18n key (zh_CN) |
|------|---------------|----------|----------------|
| 输入标题 | - | - | rqr_input_resouce_title: "请输入资源标题" |
| 提示文本 | - | - | rqr_input_resouce_title_help: "帮助文本..." |
| 自动同步逻辑 | - | - | input_resourceauthid_automodified_msg: "您的资源授权标识将自动转换为 {authid}" |

### 字段约束

| 字段名 | maxLength | 默认值 | 变化规则 | i18n key (zh_CN) |
|--------|-----------|--------|---------|----------------|
| `resourceTitle` | 100 | - | 用户直接输入 | rqr_input_resouce_title: "请输入资源标题" |
| `resourceName` | 60 | title.substring(0,60) | 自动同步 OR 手动修改 | rqr_input_resourceauthid: "资源授权标识" |

### 特殊逻辑

**Title → Name 自动同步** (L139-152):
``typescript
if (resourceTitle === resourceName) {
  // 当标题和名称一致时，输入标题会同时更新名称
  const name = resourceTitle.substring(0, 60);
  dispatch(onChange_step1_resourceName, { value: name });
}
```

**规范化规则**: `\ / : * ? " < > | @ # $` → `_` (下划线)

### CLI Flag
- `--title "<title>"` (必填)
- `--name "<name>"` (可选，不填则自动生成)

## 三、校验资源授权标识唯一性

### 操作流程
1. 输入/修改 resource name (authId)
2. 等待 300ms 防抖
3. 调用验证 API
4. 根据响应更新 UI 状态

### API 调用

| 操作 | tools-lib 函数 | HTTP 接口 | i18n key (zh_CN) |
|------|---------------|----------|------------------|
| 唯一性检查 | `resourceService.checkResourceName(name)` | `GET /resource/info?resourceName={name}` | naming_convention_resource_authid_required: "请填写资源授权标识" |
| 验证中 | - | - | - |
| 重复错误 | - | - | resource_name_exist: "资源标识已存在" |
| 自动转换提示 | - | - | input_resourceauthid_automodified_msg: "您的资源授权标识将自动转换为 {authid}" |

### 请求参数
```
Query Parameters:
  resourceName: string
```

### 响应处理

| 响应 | UI 显示 | i18n key (zh_CN) |
|------|---------|------------------|
| isVerify=true | loading 图标 ⏳ | - |
| errorText='已被使用' | 红色文字 ❌ | resource_name_exist: "资源标识已存在" |
| errorText='' + name!=optimized | 黄色提示 ✨ | input_resourceauthid_automodified_msg: "您的资源授权标识将自动转换为 {authid}" |
| errorText='' + name==optimized | 绿色✓ ✔ | - |

### Next Button 禁用条件

以下任一满足则禁用：
- `resourceType === null` → i18n: naming_convention_resource_type_required ("请选择资源类型")
- `resourceName === ''` → i18n: naming_convention_resource_authid_required ("请填写资源授权标识")
- `resourceName_errorText !== ''`
- `resourceName_isVerify === true` (加载中)
- `resourceTitle === ''` → i18n: naming_convention_resource_title_required ("请填写资源标题")
- `resourceTitle_errorText !== ''`

### CLI Flag
- `--auth-id <name>` (可选，不填则用 title 前 60 字符)

## 四、创建资源壳

### 操作流程
1. 点击"创建现在"按钮
2. 调用创建 API
3. 返回 resourceId 和 resourceName
4. 跳转 Step2

### API 调用

| 操作 | tools-lib 函数 | HTTP 接口 | 请求体字段 |
|------|---------------|----------|-----------|
| 创建资源 | `resourceService.createResource(data)` | `POST /resource/create` | 见下方 |

### 请求体结构

```typescript
{
  resourceTypeCode: string,      // 必填
  resourceTypeName?: string,     // 可选
  resourceTitle: string,         // 必填 ≤100
  resourceName: string           // 必填 ≤60，已通过唯一性检查
}
```

### 响应数据

```typescript
{
  resourceId: string,            // 平台生成的资源 ID
  resourceName: string,          // 使用的名称（可能经过规范化）
  step2_resourceTypeConfig: {    // Step2 配置
    uploadEntry: number,         // 位标志
    limitFileSize: number,       // 文件大小限制
    ...
  }
}
```

## 五、总结：CLI 实现要点

### 推荐 CLI 设计

#### 交互式模式
```
freelog-cli create
  → prompts for type (--type-code or select from tree)
  → prompt for title (--title or input)
  → auto-generate name from title (first 60 chars)
  → check uniqueness automatically
  → create resource shell via resourceService.createResource()
  → continue to version upload phase...
```

#### 非交互模式
```
freelog-cli create \
  --type-code audio.music \
  --title "My Album" \
  --auth-id "my-album-2026"
```
