# P0-C3: 合集策略 / 依赖 / 签约 / 上下架

与 [M3](../维护%20-%20单资源/P0-M3-授权策略.md)–[M6](../维护%20-%20单资源/P0-M6-上下架.md) **同构**，只记差异。共用 `resourceAuthPage` / `resourceDependencyPage` / `resourceOnline`。

### 主流程 (ASCII)

```
各子页 sider_onMount_Page + 对应 onMount
  → 策略 / 依赖 / 合约 / 开关 行为同 M3–M6
  → addPolicy / 标题封面 trigger:'collection' → 刷新合集 sider
  → 壳 60s RSS 横幅（与页无关）
```

## 差异表

| 项 | 单资源 | 合集 |
|----|--------|------|
| Tab i18n | `edit_resource_tab_*` | `edit_collection_tab_authplan`「授权策略」；`edit_collection_tab_contracts`「授权合约」；`edit_collection_tab_upstreamauthmgnt`「依赖及其授权」 |
| `onAdd_Policy.trigger` | `'resource'` | **`'collection'`** |
| 策略模板 | 传 `resourceTypeCode` | 合集页 `PolicyTemplates` **未传** `resourceTypeCode`（源码现状） |
| 签约区标题 | `edit_resource_tab_licenceecontracts` | 合集 contract 页**仍用**该单资源 key（源码现状，照记） |
| 依赖微前端 | `resourceDepAuth` | 同组件、同 model |
| 上架函数 | `sidebar/Sider` `resourceOnline` | `collectionSidebar/Sider` 再导出一份，逻辑相同：无版本 / 无策略 / 全下线 / `status:1`；下架 `status:4` |
| 新版本 | M1 有入口 | **无** |

空策略说明两行硬编码与 M3 相同（「资源需添加…」）。「添加策略」硬编码。

## CLI

```text
freelog-cli collection policy template apply <templateId> --yes --env <env>
freelog-cli collection policy set --id <policyId> --on|--off --env <env>
freelog-cli online --yes --env <env>
freelog-cli offline --yes --env <env>
```
