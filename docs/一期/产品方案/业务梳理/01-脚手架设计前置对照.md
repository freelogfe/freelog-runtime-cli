# 脚手架设计前置对照

脚手架（`init` / `template` / 本地工程）是 **CLI 自己的层**，Console `creatorEntry` **没有**对等页。设计前只认下面这张表，不要把 `init` 五选一画成 Console 五张卡。

规格：[脚手架设计/README.md](../脚手架设计/README.md)；`init` 正文见 [03-init.md](../脚手架设计/ARCHITECTURE/03-init.md)。脚手架本期不设计 F1 / 扫盘 / RSS。

源码：`packages/cli/src/commands/init.ts`；分类元数据 `services/init/catalog.ts` `INIT_CATEGORY_META`；交互选项 `services/init/picker.ts` `INIT_CATEGORY_OPTIONS`（注释写明：**不含批量 / 文件夹合集**）。

### 主流程 (ASCII)

```
Console creatorEntry 三张卡
  ├─ 发行单个资源     → F0 四步（主题/插件/前端库/图片…同一向导）
  ├─ 批量发行资源     → F1（不是 init）
  └─ 发行合集         → C0 四步（勾选我的资源 / RSS，不扫盘）

CLI init 五选一（只写本地工程，不调 create）
  ├─ 主题 theme      → scaffold=runtime + 模板 + runtime 0.4|0.5
  ├─ 插件 widget     → 同上
  ├─ 前端库 package  → scaffold=package + 模板 + namespace
  ├─ 其余资源 other  → scaffold=none + --artifact-mode file|directory-zip
  └─ 合集 collection → scaffold=collection（空合集工程）

之后才打平台：
  单资源：create → version set → publish → policy → online
  合集：  collection create → item * → publish → collection policy → online
已有资源：bind <id|name> （不是 init）
```

---

## 1. 入口怎么对

| CLI `init` 大类 | `--scaffold` | 对照 Console | 说明 |
|-----------------|--------------|--------------|------|
| 主题 / 插件 / 前端库 / 其余资源 | `runtime` / `package` / `none` | **都是 F0** | Console 不按这四类拆向导，只是 `resourceTypeCode` 不同 |
| 合集 | `collection` | **C0 Step1 之前** | 只落合集 manifest；下一步才 `collection create` |
| — | — | **F1 批量** | **不进 init**。走 `resource import-dir` |
| — | — | C0 Step2 勾选已有资源 | `collection item add <resourceId>` |
| `collection init-from-folder` | — | **Console 没有** | 扫本地媒体 → 先发子资源再写入目录草稿 |

`catalog.ts` 里「与 Console 创建向导保持五类业务入口」**不能当 Console 事实**。Console 入口是三张卡。

快捷子命令：`init theme|widget|package <dir>` 只是五选一里的三类预设，仍落 F0。

---

## 2. `init` 做什么 / 不做什么

| 做 | 不做 |
|----|------|
| 建目录、写 `freelog.manifest.json` / 合集工程 | **不** `POST /v2/resources`（那是 `create` / `collection create`） |
| runtime/package 拉工程模板（`template list`） | 不上传文件、不加策略、不上架 |
| none 要显式 `--artifact-mode` | 不模仿 Console 四入口（存储/MD/漫画） |
| collection 只建空合集工程 | 不扫盘；扫盘是 `init-from-folder` / `item import-dir` |

`init` 打出的下一步（`initNextSteps`）已按 F0/C0 命令串，合集默认是 `collection item add <resourceId>`（对照 Console 勾选我的资源）。扫盘（`init-from-folder`）只作 CLI 额外标注，不要写成 Console 主路径。

已有 Console 资源：`bind <resourceId|username/name>`，可 `--apply-listing`。不要再 `init` 一套。

## 3. 设计时必须守的发行差异

完整表见 [CLI 功能取舍决策规范.md](./CLI%20功能取舍决策规范.md)。脚手架相关再钉四条：

1. **上架**只生成 `online`，禁止教 `update --status`。
2. **首版** `version set --version 1.0.0 --file …` + `publish`；新版本 inherit 用 `publish --reuse-version`。
3. **合集策略**用 `collection policy template apply`。
4. **批量** flag 是 `--resource-type`；默认拆 20 一批。

## 4. 建议脚手架产物形状（对照已有命令，不新造）

| 产物 | 对应命令 | 对照业务 |
|------|----------|----------|
| 单资源工程（runtime/package/none） | `init` → `create` → `publish` → `policy` → `online` | F0 |
| 合集空工程 | `init --scaffold collection` → `collection create` → `item add` | C0 主路径 |
| 文件夹合集 | `collection init-from-folder` | CLI 额外，标清楚 |
| 批量文件 | `resource import-dir` | F1 |
| 已有资源维护 | `bind` → `update` / `version` / `policy` / `online` | M0–M6 |
