# 00 - 文件分类

目标：打开一个文件只做一件规格里的事。写代码时问「这段进哪个文件」，不要问「产品该怎么做」。

实现包仍是 `packages/cli`。二进制仍是 `freelog-cli`。一期业务源码按下面这棵树放。旧目录先冻结，见 §4。

---

## 1. 依赖方向（只许从上往下）

```
bin/            启动、注册命令
  → commands/   参数、TTY、输出
    → domain/   用例编排（门禁、写盘、调平台）
      → local/  .freelog/ 读写（N.json / N.version.json / index / auth）
      → platform/  tools-lib 安装与解包
      → core/   env、错误、TTY 原语、原子写
      → i18n/   文案 key
```

禁止：

| 从 | 到 | 为什么 |
|----|----|--------|
| `commands/` | `platform/` 里的 `FServiceAPI` | 命令不拼 payload |
| `commands/` | `local/` 直接改文件 | 选哪一份、写哪一字段是 domain 的事 |
| `local/` | `domain/` / `platform/` | 磁盘层不发起业务 |
| `domain/version/createVersion.ts` | `domain/version/updateVersion.ts` | 禁止互相改口；共用只抽 `form/`、`file.ts`、`gates.ts` |
| `domain/` | 旧 `config/project`、`services/store`、`adapters/versionDraftAdapter` | 那是旧 manifest / 平台草稿 |

`bin/` 只依赖 `commands/` 和 `platform/bootstrap`。

---

## 2. 目录树

一期业务只认这些路径。名字跟规格走，不要再造 `publish` / `release` / `manifest` / `draftService`（平台草稿）。

```
packages/cli/src/
  bin/
    index.ts                    # 装 tools-lib、交给 citty 跑主命令
    subCommands.ts              # 只注册 COMMANDS.md 允许的命令
  commands/                     # 根下不放命令文件；只解析参数 / TTY / 打印，调一个 domain
    account/                    # COMMANDS §1 账号
      login.ts                  # login：工作区或 --global 凭据
      logout.ts                 # logout：只删凭据，不调平台
    project/                    # COMMANDS §1 工程
      init.ts                   # init：只建本地工程，不 POST 资源
      bind.ts                   # bind：线上身份接到 N.json，不是 pull
      status.ts                 # status：只打印线上+本地现状，不接续
      type.ts                   # type list/search/pick/info：查叶子类型
      template.ts               # template list：列 scaffold 模板
    create/                     # COMMANDS §2 建壳
      create.ts                 # create：只建新壳，不上传
    version/                    # COMMANDS §3。文件在这 ≠ argv 变成 version xxx
      create-version.ts         # 顶层 create-version：无上一版，提交 1.0.0
      update-version.ts         # 顶层 update-version：定新号 + 提交
      show.ts                   # version show / --local：只读，不写盘
      set.ts                    # version set --file：只改 N.json.filePath
      description.ts            # version description：线上已发号只改描述
      draft.ts                  # version draft pull / discard：拉或丢掉工作稿
      description-draft.ts      # version draft description：只改稿上的描述
      attr.ts                   # version attr *：改稿上的属性
      option.ts                 # version option *：改稿上的可选配置
      dep.ts                    # version dep *：改稿上的依赖（签约在 domain）
    listing/                    # COMMANDS §4 listing
      update.ts                 # 顶层 update：标题/简介/封面/标签，不上架
    policy/                     # COMMANDS §4 策略
      list.ts                   # policy list：看已有策略
      template.ts               # policy template list：列免费模板
      apply.ts                  # policy template apply / apply --from-file
      set.ts                    # policy set --on/--off
    shelf/                      # COMMANDS §4 上下架
      online.ts                 # online：上架
      offline.ts                # offline：下架
      validate.ts               # validate --for online：只预检
  local/                        # 只读写 .freelog/，不调平台
    types.ts                    # N.json / N.version.json / index.json 字段（对照 02）
    identity.ts                 # 读写真源 N.json
    indexFile.ts                # index.json；和 N.json 打架听 N.json 并修好
    resolve.ts                  # --file / 仅一份 / 多份必须指定 → 落到哪份
    draft.ts                    # N.version.json 读写删；盖之前打将丢掉的摘要
    auth.ts                     # .freelog/auth 往上找；坏文件不准回退全局
    lock.ts                     # 同一工程写盘加锁
  domain/                       # 门禁、写盘、调平台；命令层只调这里
    account/
      login.ts                  # 调 User.login，写入 auth
      logout.ts                 # 删哪一层凭据
    init/
      scaffold.ts               # 拷模板、建 .freelog/；合集 scaffold 失败
    bind/
      bind.ts                   # 校验本人/合集失败/--force 换绑删稿
    create/
      create.ts                 # Step1：查重、建壳、写入 resourceId
      typePick.ts               # 类型树 / 建议 / 搜索；create 与 type 命令共用
    status.ts                   # status 汇总：info + 本地身份，不写 gates
    version/
      gates.ts                  # 02 总表：有没有 latest × 有没有稿 → 哪条命令能走
      file.ts                   # 续用 sha1 / 上传 / 等平台解析属性（见树下说明）
      submit.ts                 # 组 POST 版本体、点名校验、成功删稿、失败留稿
      createVersion.ts          # 发行版本编排：准备、会话、提交 1.0.0
      updateVersion.ts          # 更新版本编排：定新号 + 提交；无稿才拉
      show.ts                   # 看线上某一号或看本地稿
      description.ts            # PUT 已发号 description
      draftPull.ts              # 拉某一已发号写入稿；盖之前先摘要
      draftDiscard.ts           # 删工作稿
      form/                     # 每一问只在这里；会话和独立命令共用
        parseLine.ts            # 一行式「名称=… 键=…」
        preview.ts              # 落盘前格式化预览
        attr.ts                 # 自定义 / 系统附加 value
        option.ts               # 可选配置；类型不允许则失败
        dep.ts                  # 先 batchAuth 看 isAuth，没有再免费签
    listing/
      update.ts                 # Step4 与管理/02 同一入口；不带 status
    policy/
      list.ts                   # 拉已有策略
      apply.ts                  # 追加一条免费策略
      set.ts                    # 启用 / 停用
    online/
      online.ts                 # 上架 status:1
      offline.ts                # 下架 status:4
      validate.ts               # 有版本 + 至少一条启用策略
  core/                         # 瘦身沿用，无资源业务
    env.ts                      # --env / 省略=prod
    tty.ts                      # 是否 TTY、确认问句
    errors.ts                   # CliError
    passwordInput.ts            # 密码不回显 / stdin
    atomicWrite.ts              # 原子写文件
    cliArgs.ts                  # 共用 flag：--yes --cwd --json --file
  platform/                     # tools-lib 安装与解包，不写产品状态机
    bootstrap.ts                # Node adapter
    index.ts                    # envelope / 再导出
  i18n/                         # 稳定文案 key；不要沿用旧 publish 文案
```

**等平台解析属性**：上传（或续用 sha1）之后，平台要分析文件才能给出系统附加属性。CLI 调 `Storage.filesListInfo` 轮询，直到 `metaAnalyzeStatus` 为 2（完成）或 3（失败）。0/1 表示还在分析，继续等。**从第一次请求起最长 120 秒**；超时仍是 0/1 → 失败，打「属性解析超时」，不进会话。不要用会空转的 `getFilesSha1Info` / `fileProperty`。这条只写在 `domain/version/file.ts`，发行版本和更新版本都调用它，不要写第二份计时。

|------|----------------|--------|

| `policy/` | §4 策略 | `policy *` |
| `shelf/` | §4 上下架 | `online` `offline` `validate` |

文件在 `commands/version/create-version.ts`，注册仍是顶层 `create-version`，不要改成 `version create-version`。`update` 同理。

## 3. 每个目录只做什么

| 目录 | 只做 | 规格 | 不要做 |
|------|------|------|--------|
| `bin/` | 装 tools-lib、注册命令 | COMMANDS | 门禁、写盘 |
| `commands/` | 参数、是否 TTY、`--yes`、打印、调 **一个** domain 函数 | 各命令正文的「怎么敲」 | `Resource.*`、拼版本 POST 体、猜下一号 |
| `local/` | `.freelog/` 形状与原子读写 | [02](../脚手架设计/ARCHITECTURE/02-本地状态.md)、[01](../脚手架设计/ARCHITECTURE/01-账号.md) | 调平台、决定能不能 create-version |
| `domain/version/gates.ts` | 02 那张「线上 latest × 本地稿 × 三条命令」 | 02 §2.2、[05](../脚手架设计/ARCHITECTURE/05-版本工作稿与独立命令.md) | 上传、会话菜单 |
| `domain/version/file.ts` | 续用 sha1 / 上传 / 等平台解析属性（最长 120 秒，见 §2 树下说明） | 发行版本 §1–3、更新版本对应节、[属性 §2](../脚手架设计/PHASE/单资源/版本表单/01-属性.md) | 改属性问法 |
| `domain/version/form/` | 每一问、一行式、预览、依赖签约 | [版本表单](../脚手架设计/PHASE/单资源/版本表单/README.md) | POST 版本、定新号 |
| `domain/version/createVersion.ts` | 无上一版：准备、会话、提交 1.0.0 | [发行版本](../脚手架设计/PHASE/单资源/创建/02-Step2-发行版本.md) | inherit、`--bump` |
| `domain/version/updateVersion.ts` | 有上一版：定新号 + 提交；无稿才拉 | [更新版本](../脚手架设计/PHASE/单资源/更新版本/01-更新版本.md) | 改口 create-version |
| `domain/version/submit.ts` | 组 `createVersion` 体；成功删稿 | 两篇的提交节 + 点名字段 | 会话 |
| `domain/create/` | 建壳、查重、类型 | [Step1](../脚手架设计/PHASE/单资源/创建/01-Step1-创建授权条目.md) | 上传 |
| `domain/listing/` | 标题/简介/封面/标签 | Step4、[管理/02](../脚手架设计/PHASE/单资源/管理/02-资源信息.md) | `status` |
| `domain/policy/` | 模板、追加、开关 | Step3、[管理/03](../脚手架设计/PHASE/单资源/管理/03-授权策略.md) | 上架 |
| `domain/online/` | 预检、上架、下架 | [管理/05](../脚手架设计/PHASE/单资源/管理/05-上下架.md) | 加策略 |
| `core/` | `env`、`CliError`、密码、原子写、共用 flag | — | 资源业务 |
| `platform/` | Node adapter、envelope | — | 产品状态机 |

`N.json` 字段只在 `local/types.ts` 写一遍，对照 02 §2.2。`N.version.json` 同样。命令和 domain 不要私自加 `title` / `latestVersion` 进身份文件。

## 4. 旧代码：冻结，不要当地基

现有树还能跑，但语义和规格相反。一期 **不要**在这些文件上加新行为：

| 旧路径 | 旧职责 | 一期对应 | 处理 |
|--------|--------|----------|------|
| `config/project/` | `FreelogManifest` + `FreelogState` | `local/` | 不扩字段。新代码不 import |
| `services/store/` | ProjectStore / session / 合集 | 无。身份和稿分开、无 session | 不 import |
| `adapters/versionDraftAdapter.ts` | 平台草稿 DTO | 无平台草稿 | 不 import |
| `services/resource/publishVersion.ts`、`commands/publish.ts`、`release.ts` | 一条龙发版 | `create-version` / `update-version` | 不再注册 |
| `commands/dep.ts`、`services/depAuthService.ts` | 顶层 dep | `domain/version/form/dep.ts` | 不再注册 |
| `commands/draft.ts`、`services/draftService.ts` | 平台草稿 / 旧 draft | `version draft pull\|discard` | 不再注册 |
| `commands/pull.ts`、`services/sync/` | pull 当接入 | `bind` | 不再注册 |
| `commands/session*`、`studio*`、`start.ts` | 不是账号 | — | 不再注册 |
| `commands/collection/`、`services/collection/` | 合集 | 本期不做 | 不再注册 |
| `services/batch/`、`import-dir` | F1 | 本期不做 | 不再注册 |
| `packages/cli/src/ARCHITECTURE.md` | 旧分层 | 本文 | 一期以本文为准 |

允许沿用（只当工具，不带旧产品语义）：

| 沿用 | 注意 |
|------|------|
| `platform/bootstrap.ts` | 继续装 tools-lib |
| `core/passwordInput.ts`、`core/atomicWrite.ts`、`core/tty.ts`、`core/env.ts` | 可搬进仍叫 `core/` |
| `i18n/` 机制 | 文案按规格重写 key，不要沿用 `publish` 文案 |
| `services/init/` 里纯 scaffold 拷文件 | 接到 `domain/init/scaffold.ts`；合集 scaffold 失败 |
| `services/policyTemplate/` 里模板列表 / 编译 | 接到 `domain/policy/`；禁止付费、禁止上架 |
| `services/resourceTypeTree.ts` | 接到 `domain/create/typePick.ts` |

拿不准就 **新写**。复制旧函数进来之前先对规格：旧逻辑里有 `publish`、平台草稿、`baseUpcast` 写入、`authExcludedItems` 非空、`batchSignContracts` 进 POST，一律丢掉。

## 6. 共用，不要复制

这些规则只写一次：

| 规则 | 唯一实现 |
|------|----------|
| `--file` 落到哪一份 `N.json` | `local/resolve.ts` |
| 02 总表（能不能走 create-version / update-version / draft pull） | `domain/version/gates.ts` |
| 续用 sha1 / 上传 / 等平台解析属性（最长 120 秒） | `domain/version/file.ts` |
| 一行式 + 预览 + 键不能改 | `form/parseLine.ts` `preview.ts`；attr/option 只填字段表 |
| `batchAuth` / 免费签 | `form/dep.ts` |
| POST 版本体：`baseUpcastResources: []`、`authExcludedItems: []`、不带 `batchSignContracts` | `domain/version/submit.ts` |
| 成功删稿、失败留稿 | `submit.ts` |
| 提交校验失败点名字段 | `submit.ts`（文案对照发行版本 §5、更新版本 §6） |
| 盖稿前摘要 | `local/draft.ts`（`draftPull` 和 update-version「覆盖重拉」都调它） |

会话菜单不是第三套表单：`createVersion.ts` / `updateVersion.ts` 只负责循环「选 1–6」，每一问进 `form/`。

## 7. 架构测试必须挡住的

`tests/architecture/layout.test.ts` 第一片就写上，后面少返工：

1. `commands/**` 不得出现 `FServiceAPI` / `Resource.` / `Storage.` / `Contract.` / `Policy.`。
2. `local/**` 不得 import `domain/`、`commands/`。
3. `domain/version/createVersion.ts` 与 `updateVersion.ts` 不得互相 import。
4. 新业务文件不得 import `config/project`、`services/store`、`adapters/versionDraftAdapter`、`services/draftService`、`services/resource/publishVersion`。
5. `createSubCommands()` 的 key 必须是 COMMANDS 允许集的子集；`publish` / `release` / `dep` / `pull` / `session` / `studio` / `collection` 不得出现。
6. `commands/` 根下不得出现命令实现 `.ts`（只许分组目录；可选一个 `index.ts` 给 `bin` 做再导出）。

产品文案、字段对错仍以脚手架设计为准。本文件只锁「放哪」。
