# 01 - 实现顺序

一次只做**一个任务编号**。验证栏全过，才能勾完成、才能开下一号。不要并行开两个会写平台的任务。

打开该任务「规格」，对着 [00](./00-文件分类.md) 的文件写。栈听 [02](./02-技术选型.md)。不要改命令名、加旗、合并两条发行命令。

tools-lib：直接用现有函数。不要先补 P0-D §7 待加接口。旧 CLI 只供参考：[archive/cli](../../archive/cli/00-备份说明.md)。

切完一个任务：改 [交接文档](../交接文档.md) §0「下一刀」和本文进度表。

---

## 怎么验证

| 栏 | 过线 |
|----|------|
| 单测 | `pnpm --filter @freelog-cli/cli2 test` 该任务文件绿；从 T0.2 起每次带上 `tests/architecture/layout.test.ts` |
| 命令 | 文档里写的那条 `freelog-cli …` 实际跑出预期（失败也要是预期失败） |
| 手工 | 仅标了「手工」的任务：`--env test` 或 `dev`，**禁止 prod** |
| 回归 | 本阶段前面已勾任务的单测不能红 |

验证失败：先修本任务，不要开始下一号。  
平台任务：先单测（mock `FServiceAPI`），再手工。单测不过不要上真网。

文案：中文写在源码，上一行 `// i18n: key`。
