# 01 - 实现顺序

每一片结束时：该片的架构测试 + 该片场景（或单元）必须绿。下一片才能开始。  
打开规格，对着 [00](./00-文件分类.md) 的文件写。不要在切片里改命令名、加旗、合并两条发行命令。

tools-lib：直接用现有函数。不要先补 P0-D §7 待加接口。

---

## 总序

```
0 空树 + 注册表 + 架构测试
1 本地身份 / 凭据 / 选份
2 账号
3 init / type / template
4 create / bind / status
5 工作稿文件 + 看本地
6 文件 sha1 / 上传 / 解析
7 表单：属性、可选配置（不打平台签约）
8 表单：依赖（batchAuth + 免费签）
9 create-version（--prepare → 会话 → --yes）
10 version draft pull / discard + version show 线上
11 update-version
12 policy / listing / online
13 场景 S1–S35 收口
```

先本地、后平台；先稿、后提交；先首版、后发新号。不要先写 `update-version` 再倒逼稿格式。

## 每片写代码时的检查表

1. 打开本片「规格」那一份，不要凭记忆改门禁。
2. 文件是否在 00 §5 那一行？不在就停，不要新开「方便」目录。
3. POST 版本只许出现在切片 9 和 11 的 `submit.ts`。
4. `baseUpcastResources` / `authExcludedItems` 提交恒 `[]`。
5. 成功 POST 必须删 `N.version.json`。
6. 提交失败点名字段。
7. 跑本片测试 + `layout.test.ts`。
