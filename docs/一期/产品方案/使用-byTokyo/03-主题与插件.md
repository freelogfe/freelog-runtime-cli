# 主题与插件

本页只解释主题/插件相对普通文件的差异：模板初始化、固定类型、构建目录与临时压缩。它们仍是“一条资源一次一条命令”，并与普通文件共用登录、建壳、版本工作稿、属性、依赖、策略、管理和上下架流程；可选配置是否可编辑始终由当前类型详情决定。完整生命周期见[资源生命周期](./02-日常路径.md)，准确命令与参数见[完整命令参考](./10-命令参考.md)。

> 本页沿用[快速上手](./01-快速上手.md)的 `@freelog-cli/cli2@0.5.3` 协议：工程身份保存在 `.freelog/1.json`，首版使用 `create-version`。先执行 `freelog-cli --cli-version` 并确认输出为 `0.5.3`；不要把读取 `freelog.manifest.json` 的新版 CLI 用在本页工程上。

## 第一次发布，只记住五步

`选模板 → 初始化工程 → 安装依赖并构建 → 创建资源壳 → 提交首版`。

下面按这个顺序说明。先让 `npm run build` 成功并生成实际的 `dist/`，再进行创建和发版；不要把空目录发布到平台。

| 项目 | 主题 | 插件 | 普通文件资源 |
|---|---|---|---|
| 从官方模板初始化 | `init theme` | `init widget` | 不适用 |
| 接入已有本地产物 | `init --type RT001 --artifact <文件或目录>` | `init --type RT002 --artifact <文件或目录>` | `init --type <最终叶子> --artifact <文件>` |
| 固定类型 | `RT001` | `RT002` | 由类型树选择并在线复验 |
| 初始 `filePath` | `dist` 目录 | `dist` 目录 | 可无；建壳或发版时记录一个文件 |
| 模板元数据 | 本期不保存；模板只决定初始化时复制什么工程 | 本期不保存；模板只决定初始化时复制什么工程 | 没有 |
| 发版输入 | 构建目录或单个文件 | 构建目录或单个文件 | 一个普通文件 |
| 上传前处理 | 目录由 CLI 临时打 zip；文件直接上传 | 目录由 CLI 临时打 zip；文件直接上传 | 直接上传原文件 |

## 从线上模板创建工程

先查看 CLI 固定的线上模板清单：

```powershell
freelog-cli template list
```

推荐先登录，再创建主题或插件工程：

```powershell
freelog-cli login --env dev
freelog-cli init theme my-theme --template vite-react-ts --yes --env dev
freelog-cli init widget my-widget --template vite-vue-ts --yes --env dev
```

`init theme` / `init widget` 本身不需要登录，因为类型固定；但先登录能使随后 `create --cwd <工程>` 直接复用同一账号。它们从固定版本的线上 npm 模板包下载并只复制包内 `template/` 内容。CLI 不从 `packages/templates/` 复制，也不会执行模板脚本、渲染项目名/版本、安装依赖或执行构建。

成功后会生成：

```text
my-theme/
  .freelog/1.json             # typeCode=RT001，filePath=dist
  ...模板文件
```

本期不保存模板元数据，也不渲染占位符。构建目录始终记录在 `N.json.filePath`。

## 已有主题或插件项目，如何接入

已有项目不运行模板子命令；可以先在项目根只建立本地状态，再创建线上资源壳：

```powershell
freelog-cli login --env dev
freelog-cli init . --type RT001 --artifact dist --yes --env dev
freelog-cli create --title "已有主题" --name existing-theme --yes --env dev
freelog-cli create-version --prepare --env dev
freelog-cli create-version --yes --env dev
```

若线上资源已经存在，先 `bind`。它是否已有发行版本决定后续路径：

```powershell
# 线上还没有 latestVersion：接入后发行首版
freelog-cli login --env dev
freelog-cli bind <resourceId或username/name> --artifact dist --env dev
freelog-cli create-version --prepare --env dev
freelog-cli create-version --yes --env dev
```

```powershell
# 线上已有 latestVersion：接入、拉稿并提交新版本
freelog-cli login --env dev
freelog-cli bind <resourceId或username/name> --artifact dist --env dev
freelog-cli version draft pull --env dev
freelog-cli update-version --bump patch --yes --env dev
```

不要在已发行资源上再运行 `create-version`，也不要在没有发行版本的资源上运行 `draft pull` / `update-version`。

也可以跳过 `init`，以 `create --type RT001 --artifact dist` 一步建壳；但无论哪条路径，状态写入前产物都必须已经存在。主题/插件既有项目可把 `dist` / `build` 记录为目录，也可记录已生成的单个文件；只有目录会在发版时临时压缩。不会补造元数据，也不会覆盖你的源码。

## 创建主题或插件资源壳

初始化只建立本地工程，仍要登录并创建线上资源：

```powershell
freelog-cli login --env dev
freelog-cli create --cwd my-theme --title "我的主题" --name my-theme --yes --env dev
```

不要再传 `--type RT001` / `RT002`：CLI 会使用工程已记录的固定类型并在线复验。若显式传入不同的 `--type`，命令会失败，不能把模板工程改造成普通资源。

## 先生成构建产物

CLI 不运行包管理器或构建命令。你需要在工程自己的开发流程中产生 `dist/`（或其他构建目录）。当前 Vite 模板要求 Node.js `20.19+` 或 `22.12+`；先确认版本，再安装依赖并构建：

```powershell
node --version
cd my-theme
npm install
npm run build
```

如果 `npm run build` 报 `tsc` 不存在、Rolldown 原生绑定缺失或 Node API 不兼容，停止发布：这是模板依赖或 Node 版本问题，不能用空的 `dist` 继续发版。模板应提供可复现的 lockfile，并锁定已验证的 TypeScript/Vite 版本。

如果产物目录不是 `dist`，只更新记录：

```powershell
freelog-cli version set --cwd my-theme --artifact build --env dev
```

这条命令不上传、不压缩、不创建版本。目录可以暂时还不存在；真正发版时必须存在且非空。

## 发布版本：目录会自动压缩

```powershell
freelog-cli create-version --cwd my-theme --prepare --env dev
freelog-cli version show --cwd my-theme --local --env dev
freelog-cli create-version --cwd my-theme --yes --env dev
```

对于 `RT001` / `RT002`，若路径是 `dist` 这类目录，CLI 会把目录的**内容**打入临时 zip（不会再包一层 `dist/`），然后计算 SHA1、上传、等待解析并提交。若路径是单个文件（包括用户已准备的 zip），CLI 直接计算该文件的 SHA1、上传和提交，不会再次压缩。临时 zip 无论成功或失败都会删除，不写入工程，也不写入工作稿。

以下输入会停止：

| 输入 | 结果 |
|---|---|
| `dist` 不存在 | 要求先生成构建产物。 |
| 空目录 | 要求先生成实际文件。 |
| 工程根目录（其中含 `.freelog/`） | 拒绝将工程根作为产物目录。 |
| 一个 `.zip` 或普通文件 | 合法，直接上传；不会再次压缩。 |

后续版本与普通资源完全相同：`version draft pull` → 编辑工作稿 → `update-version --version ...` 或 `--bump ...`；目录会重新生成临时 zip，文件则直接上传。当前 dev 的主题类型 `RT001` 不支持可选配置；不要把 `version option` 当作主题的固定能力。

## 这不是两套版本系统

主题/插件和普通资源都使用同一份 `N.version.json` 工作稿，版本号规则、依赖签约规则、属性校验、成功清稿和失败保留规则完全一致；可选配置仅在类型详情允许时可用。唯一的文件层差异是：

- 普通资源的 `filePath` 指向文件，文件 SHA1 即上传文件的 SHA1；
- 主题/插件的 `filePath` 可指向目录或文件：目录时 SHA1 与 `filename` 指向 CLI 临时 zip，文件时二者指向原文件。

因此可以把已有 zip 记进 `filePath`，但不要因为主题/插件的产物形态而另建一套版本缓存。
