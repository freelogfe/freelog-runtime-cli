# 快速开始：发行一个普通文件

本页是第一次使用的可执行教程：把 `video.mp4` 作为普通资源发成首版 `1.0.0`。以下示例以 dev 环境为例；不要把真实密码写进命令行参数或脚本文件。已有工程、已有线上资源或主题/插件不要套用本页，先到[按场景操作](./09-按场景操作.md)选入口。

> **CLI 协议说明：** 本文只适用于 `@freelog-cli/cli2@0.5.3`，其工程文件为 `.freelog/1.json`，并使用 `create-version` / `update-version`。如果命令提示缺少 `freelog.manifest.json`，或帮助中出现 `publish`、`version set`，说明当前终端命中了另一套新版 CLI；请停止并安装本文指定版本，不能混用两种工程格式。

## 1. 安装、确认与登录

CLI 本身可运行在 Node.js 20+；若后续要构建主题或插件模板，则需要 Node.js `20.19+` 或 `22.12+`。先确认当前 Node 和本文所需的 CLI 协议版本：

```powershell
node --version
npm install --global @freelog-cli/cli2@0.5.3
freelog-cli --cli-version
```

最后一条必须输出 `0.5.3`。如果切换过 Node.js，npm 的全局工具目录也可能随之改变；在**切换后的 Node 环境**重新执行安装和版本检查。若 `freelog-cli` 找不到，重新打开终端；仍无法使用时，检查 npm 全局可执行目录是否已加入 `PATH`。以下统一写作 `freelog-cli`。

先创建并进入工程目录，再登录。默认登录是工作区级的，只有当前目录及其子目录会继承该登录态：

```powershell
mkdir freelog-video-demo
cd freelog-video-demo
```

首次使用推荐在交互终端直接登录；CLI 会安全地隐藏密码输入：

```powershell
freelog-cli login --env dev
```

```powershell
# 登录成功后，可查看安装包内自带的完整手册路径
freelog-cli --help
```

自动化或非交互终端需要同时传 `--login-name`、`--password-stdin`、`--yes`；由 CI 的保密输入把密码写入标准输入，绝不把密码写进命令行、脚本或环境变量。登录成功后，工程只保存账号选择器；token、Cookie 等秘密由系统凭据库保存。

## 2. 建立工程身份

普通资源要先登录，因为资源类型来自平台的当前类型树。第一次跟着本页操作时，直接使用示例中的 `RT006003` 即可；想发布其他类型时，再用 `type search` 和 `type info` 查找最终叶子 code。已知最终叶子 code 时可直接初始化：

```powershell
freelog-cli init . --type RT006003 --artifact video.mp4 --yes --env dev
```

不知道 code 时先查询，或不传 `--type` 进入交互式层级选择：

```powershell
freelog-cli type search 视频 --env dev
freelog-cli type list --env dev
freelog-cli type info RT006003 --env dev
freelog-cli init . --artifact video.mp4 --env dev
```

通用 `init` 必须用 `--artifact` 指向已经存在的本地文件；交互模式只会帮你选类型，不会扫描或猜测文件。它只写 `.freelog/1.json`，不会创建线上资源、上传文件或创建版本。

上一步已在当前目录写入 `.freelog/auth` 也可以再执行 `init .`：CLI 会保留这一个账号选择器，并拒绝覆盖任何其它已有工程内容或资源身份。

## 3. 创建线上资源壳

```powershell
freelog-cli create `
  --title "我的视频" `
  --name <你的唯一资源标识> `
  --artifact video.mp4 `
  --yes --env dev
```

因为工程已经通过 `init` 记录了类型，这里不必重复传 `--type`；CLI 会在提交前重新验证该类型。没有先 `init` 时也可以直接创建，但必须额外传入 `--type <最终叶子 code>`。`--name` 是平台资源标识，应替换为自己的唯一值，例如 `my-video-20260910`；不要直接复用示例值。

此步只创建资源壳并回写 `resourceId`、`name`、环境和文件路径，**不会上传视频**。

## 4. 上传、检查并提交首版

最稳妥的做法是先准备工作稿：

```powershell
freelog-cli create-version --prepare --artifact video.mp4 --env dev
freelog-cli version show --local --env dev
freelog-cli create-version --yes --artifact video.mp4 --env dev
```

第一条会校验文件、计算 SHA1、上传并等待平台解析，但不提交版本。确认本地工作稿后，最后一条会再次从当前文件校验、上传和解析，再提交固定首版号 `1.0.0`。提交成功会删除工作稿；失败或中断会保留工作稿以便继续处理。

如果需要放弃失败稿并更换文件后重新准备，显式重置：

```powershell
freelog-cli create-version --prepare --reset --yes --artifact <新文件路径> --env dev
```

若平台在提交时提示“不能创建重复的资源”，通常表示该文件内容已被当作重复内容处理；请换用一份内容不同的文件重新备稿，而不是重复提交同一份文件。
