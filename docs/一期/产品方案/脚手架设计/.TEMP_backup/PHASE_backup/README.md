## ⚙️ **四、关键设计原则**

### **4.1 通用模块必须实现为独立的 CLI 命令**

```bash
# POLICY 模块 → 独立的命令行工具
freelog-cli policy template-list    # 列出所有可用策略模板
freolog-cli policy select --template commercial-use    # 选择模板
freelog-cli policy params  --form schema.json           # 填写参数
freelog-cli policy compile                                  # Bytecode 编译

# UPLOAD 模块 → 支持多种上传模式
freelog-cli upload chunk --path file.zip --chunk-size 5MB  # 分片上传
freelog-cli upload sha1 --file sample.bin                   # SHA1 校验
freelog-cli upload progress --watch true                    # 实时进度条

# CHECKPOINT 模块 → 内置在 CLI 框架中
freelog-cli checkpoint save --key step2-upload-complete       # 手动保存
freelog-cli checkpoint restore                                # 自动恢复
freelog-cli checkpoint cleanup --older-than 24h               # 清理过期
```

### **4.2 每个业务流程文档必须是完整的产品设计规格**

包含以下内容，无需参考其他文档:

1. **ASCII Diagram 流程图**: 清楚表达步骤流转
2. **字段约束表**: 约束规则 + 提示文案 + 错误码 + 处理方式
3. **数据结构 Interface**: TypeScript 类型定义 (Request/Response)
4. **算法逻辑步骤**: if-then-else 样式的伪代码描述 (不是真代码!)
5. **异常分支矩阵**: 所有可能的错误及处理策略

### **4.3 禁止出现伪代码黑盒调用**

❌ **错误的写法** (伪代码堆砌):
```typescript
executeStep('uploadFiles');
importBusinessStep();
callPolicyModule();
// 开发者不知道这些函数的具体实现！
```

✅ **正确的写法** (纯产品设计):
```typescript
uploadWithChunkStrategy(file):
  IF file.size <= 10MB THEN
    response = POST /v2/storages/uploadSingle({ filePath })
  ELSE IF file.size > 10MB THEN
    chunks = splitFileIntoChunks(file, chunkSize=5*1024*1024)
    FOR EACH chunk in chunks DO
      uploadResponse = POST /v2/storages/uploadChunk({ chunkData })
    END FOR
    mergeResponse = POST /v2/storages/mergeChunks({ chunkIds[] })
  END IF
  RETURN response.fileId
```
