# 多资源选择与标题同步

## S61：工程里还没有资源状态

**现状**：用户在一个素材目录里还没有任何本地资源状态。  
**人要**：查看版本、上架或管理资源。  
**成功**：CLI 清楚说明当前没有可操作资源；新资源可先初始化后创建，已有线上资源可接入。  
**失败**：展示空列表、猜测素材文件对应哪个资源，或为只读命令创建空状态。

## S62：工程里只有一个资源状态

**现状**：工程中只有一份资源状态。  
**人要**：继续查看、发版本、改属性、管理策略或上下架。  
**成功**：直接作用于该资源，不出现多余选择提示。  
**失败**：要求人重复输入文件名、资源 ID 或编号，或把产物路径误认为资源选择。

## S63：工程里有多个资源状态

**现状**：同一素材工程同时管理多个独立资源。  
**人要**：操作其中一份资源。  
**成功**：交互环境展示文件名、标题、标识符、资源 ID、类型、产物路径和工作稿状态，用户可选择一份或退出；脚本环境要求以 `id:`、`name:`、唯一 `title:`、`artifact:` 或 `file:N.json` 明确指定。`file:` 保留给 AI/脚本，不要求人记编号。
**失败**：默认取第一份、只按标题猜测，或把同一工程误报为不支持。

## S64：标题相同或状态冲突

**现状**：两份资源标题相同，或用户手工复制状态造成 ID、标识符、路径、工作稿归属冲突。  
**人要**：安全继续工作或恢复状态。  
**成功**：同标题可由资源 ID、标识符或状态文件精确区分；如果人已经按标题指定却命中多份，CLI 列出候选并要求改用唯一选择器，不再二次猜测；真正冲突时 CLI 保留所有文件、指出冲突组，并提示备份后删除完整状态单元或重新接入。
**失败**：按标题任意选一份，自动删工作稿，或把稿接到另一资源。

## S65：标题在别处被修改

**现状**：用户在平台、另一台机器或其他工具中改过资源标题，本地选择列表已过期。  
**人要**：让当前工程的选择信息反映平台。  
**成功**：用户可同步当前环境的全部资源标题，或只同步一份；成功项更新，失败项保留旧值且可重试。
**失败**：同步标题时改动版本工作稿、产物路径或线上资源，跨环境读取资源，或将部分失败报成全部成功。

## S66：多资源工程继续新增或接入资源

**现状**：工程已有多份已绑定资源；用户要再新建一个壳，或再接入另一条已有线上资源。也可能留有一份或多份未绑定的初始化状态。
**人要**：新增资源不能被已有资源的选择菜单卡住；若明确要接续某份未绑定状态，则能精确指定它。
**成功**：一个素材目录中的 `video.mp4`、`cover.jpg` 等文件可以各自连续创建并发行资源，不必拆成多个工程；没有未绑定状态时，创建或接入会新增一组 `N.json`；唯一未绑定状态时可直接接续；多份未绑定状态时明确要求选择；接入同一资源 ID 时幂等，不会创建重复状态。
**失败**：在多状态工程里默认改写第一份已绑定资源、强制用户从已绑定资源里选一份才能新增、或以为“多资源”而拒绝 create/bind。

## S67：丢弃、覆盖或重置工作稿

**现状**：用户在工程中有一份未提交版本工作稿，想明确丢弃、用线上版本覆盖，或以 `--reset` 重来；工程也可能有多份资源状态。
**人要**：先看清会丢掉什么，再只影响选中的一份；错误命令、错误版本号、缺产物或取消不能造成丢稿。
**成功**：TTY 先显示旧稿摘要、默认不执行，用户确认后才删除/覆盖；非交互必须 `--yes`。`--reset` 先通过路由、版本号和产物路径校验，再确认并删稿；确认后的网络或提交失败不恢复旧稿。
**失败**：不传 `--yes` 的脚本直接删稿、取消后仍写盘、未通过首版/更新版门禁或本地路径校验就删稿、或多资源时影响未选中的工作稿。
