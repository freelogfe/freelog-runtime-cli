# 多资源选择与标题同步：命令路径

本页实现 [真实场景 08](../真实场景/08-多资源选择与标题同步.md)。身份只用 `--resource` 选择，产物只用 `--artifact` 指定。

## S61：零状态

```text
freelog-cli status --env dev
→ 当前目录没有资源状态。新资源请先 init 后 create；已有资源请 bind <资源 ID|标识符> --artifact <路径>。
→ exit 1；不调平台、不创建 .freelog
```

## S62：单状态

```text
freelog-cli version show --env dev
→ 静默使用 .freelog/1.json；不显示选择菜单
```

## S63：多状态

```text
freelog-cli update-version --env dev
→ 请选择资源：
  1) 1.json  标题=标题 A  标识=a  ID=...  类型=RT006003  产物=a.mp4  有工作稿
  2) 2.json  标题=标题 B  标识=b  ID=...  类型=RT006003  产物=b.mp4  无工作稿
  0) 退出

freelog-cli update-version --resource file:2.json --bump patch --yes --env dev
→ 只操作 2.json / 2.version.json

freelog-cli update-version --bump patch --yes --env dev
→ exit 1；多份状态的非交互调用必须传 --resource
→ 例如：file:1.json（标题 A；a；...）、file:2.json（标题 B；b；...）
```

`--resource` 还可为 `id:<resourceId>`、`name:<username/name>` 或 `title:<title>`；标题命中多份时始终失败并列出候选，要求改用 `file:`、`id:` 或 `name:`，不再二次选择。

## S64：冲突

```text
freelog-cli status --env dev
→ 发现 1.json 与 2.json 使用同一 resourceId；保留所有本地文件，未调用平台。
→ 请先备份 .freelog；删除一组完整的 N.json + N.version.json，或在空状态重新 bind。
```

孤儿 `N.version.json`、资源 ID / 类型不匹配工作稿、重复标识符或重复产物路径同样停止，不自动修复。

## S65：标题同步

```text
freelog-cli resource sync --env dev
→ 读取所有 env=dev 的已绑定资源并在一个本地事务中更新 title

freelog-cli resource sync --resource id:<resourceId> --env dev
→ 只同步这一份
```

请求失败的状态保留旧标题；命令打印成功/失败摘要并退出非零。`update --title <title>` 成功后应直接回写选中 `N.json.title`，不需要再调用同步命令。

## S66：多资源中新增或接入

```text
# 1.json、2.json 已绑定，没有未绑定状态
freelog-cli create --title C --name c --type RT006003 --artifact c.mp4 --yes --env dev
→ 成功后新建 3.json；不要求先选择 1.json 或 2.json

# 有且仅有一份未绑定 3.json
freelog-cli bind alice/c --artifact c.mp4 --env dev
→ 接续 3.json

# 有多份未绑定状态
freelog-cli create --title C --name c --type RT006003 --artifact c.mp4 --yes --env dev
→ exit 1；请传 --resource file:N.json，不能按编号或菜单猜测

freelog-cli bind alice/c --resource file:3.json --artifact c.mp4 --env dev
→ 只写 3.json；若 alice/c 已在别的 N.json，失败并保留所有状态
```

`create --resource` 只能接续未绑定状态；对已绑定状态必须失败。`bind --force --yes --resource file:N.json` 才能替换已绑定目标，并在同一事务删除该编号的工作稿。
