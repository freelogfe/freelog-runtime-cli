# 01 - 壳与首版（实现）

真实场景：[01](../真实场景/01-壳与首版.md)

---

## S1 全新：立项 → 建壳 → 发首版

**判定**：能走通

```
freelog-cli login
freelog-cli init . --scaffold none --artifact-mode file   # 可省；主题/插件用 init theme 等
freelog-cli create --title ... --type ... --name ... --file <path>
freelog-cli create-version
```

之后可跳过：`policy template apply` → `update` → `online`。  
真源：[Step1](../../PHASE/单资源/创建/01-Step1-创建授权条目.md) · [发行版本](../../PHASE/单资源/创建/02-Step2-发行版本.md)

---

## S2 首版分几天做完

**判定**：能走通

```
# 今天：只建稿，不 POST
freelog-cli create-version --prepare

# 明天：改缓存
freelog-cli version attr add "名称=作者 键=author 值=张三"
freelog-cli version dep add someone/lib --range ^1.0.0
freelog-cli version show --local

# 交 1.0.0
freelog-cli create-version --yes
```

会话里取消也会留稿。成功 POST 后稿删除。不要跑 `version draft pull`（没有上一号）。

---

## S3 壳已有、还没发行，人又去「建壳」

**判定**：能走通

```
freelog-cli create    # 失败：已有自己的壳，去 create-version
freelog-cli create-version
```

---

## S4 壳已有、还没发行，本地没有这份身份

**判定**：能走通

```
freelog-cli bind <id|username/name> --file <path>
freelog-cli create-version          # 之后可按 S2 分多次
```

不要再 `create`。

---

## S5 人以为在发首版，线上其实已经有版本

**判定**：能走通

```
freelog-cli create-version
# 进入：已有 latestVersion → 失败，「已有发行版本，请使用 update-version」
# 提交前再 info 一次：中间网页刚发出第一版 → 同样失败，稿留下
```

不要改口成 `update-version`。不要用首版稿去发新号。

---

## S6 本地留着「发新号」的稿，人却来发首版

**判定**：能走通

```
freelog-cli create-version
# 发现有 fromVersion：不读这份发 1.0.0
# 打印「这是更新版本的稿，发行版本不用」
# 本命令一旦写盘：整份按首版重写，不要留 fromVersion
```

---

## S7 视频：可以几乎不填表就交首版

**判定**：能走通

```
freelog-cli create-version
# 传文件、解析；菜单可以一次不选，直接提交
# 描述固定空串；不问版本封面；不传 videoCover
```

没有可用 sha1：不进会话、不发行。

---

## S8 一夹多个资源，发首版没指是哪一份

**判定**：能走通

```
freelog-cli create-version                 # 失败：列出各份 filePath，要求 --file
freelog-cli create-version --file a.mp4
```
