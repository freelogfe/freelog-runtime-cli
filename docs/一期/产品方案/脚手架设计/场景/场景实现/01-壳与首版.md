# 01 - 壳与首版（实现）

真实场景：[01](../真实场景/01-壳与首版.md)

---

## S1 全新：立项 → 建壳 → 发首版

**判定**：能走通

```
freelog-cli login
freelog-cli init . --type <leaf-code> --artifact <file> --yes  # 视频等单文件；TTY 可层级/搜索/直接输入 code 选择
# 主题/插件：init theme / init widget，见场景实现/05；目录由 CLI 压缩，已有文件可直传
freelog-cli create --title ... --name ... --artifact <path>   # 复验 init 已选类型
freelog-cli create-version --yes
```

之后可跳过：`policy template apply` → `update` → `online`。  
真源：[Step1](../../PHASE/单资源/创建/01-Step1-创建授权条目.md) · [发行版本](../../PHASE/单资源/创建/02-Step2-发行版本.md)

---

## S2 首版分几天做完

**判定**：能走通

```
# 今天：只建稿，不 POST
freelog-cli create-version --prepare

# 明天：改缓存
freelog-cli version attr add "名称=作者 键=author 值=张三"
freelog-cli version dep add someone/lib --range ^1.0.0
freelog-cli version show --local

# 交 1.0.0
freelog-cli create-version --yes
```

准备成功后工作稿会留在本地；成功 POST 后稿删除。不要跑 `version draft pull`（没有上一号）。

---

## S3 壳已有、还没发行，人又去「建壳」

**判定**：能走通

```
freelog-cli create    # 失败：已有自己的壳，去 create-version
freelog-cli create-version --prepare
```

---

## S4 壳已有、还没发行，本地没有这份身份

**判定**：能走通

```
freelog-cli bind <id|username/name> --artifact <path>
freelog-cli create-version --prepare          # 之后可按 S2 分多次
```

不要再 `create`。

---

## S5 人以为在发首版，线上其实已经有版本

**判定**：能走通

```
freelog-cli create-version --yes
# 进入：已有 latestVersion → 失败，「已有发行版本，请使用 update-version」
# 提交前再 info 一次：中间网页刚发出第一版 → 同样失败，稿留下
```

不要改口成 `update-version`。不要用首版稿去发新号。

---

## S6 本地留着「发新号」的稿，人却来发首版

**判定**：能走通

```
freelog-cli create-version --yes
# 发现有 fromVersion：失败并打印「这是更新版本的稿，发行版本不用」
# 不覆盖、不重写这份稿；人须明确丢稿后再按首版准备
```

---

## S7 视频：可以几乎不填表就交首版

**判定**：能走通

```
freelog-cli create-version --yes
# 传文件、解析后直接提交
# 描述固定空串；不传版本封面或 videoCover
```

没有可用 sha1：不发行。

---

## S8 一夹多个资源，发首版没指是哪一份

**判定**：能走通

```
freelog-cli create-version                 # TTY 选择一份；非交互失败并要求 --resource
freelog-cli create-version --resource file:1.json --yes
```

---

## S59 已有普通文件工程，没有线上资源

**判定**：能走通

```
# 在既有非空工程根；init 只写 .freelog，不覆盖任何源码
freelog-cli login --env dev
freelog-cli init . --type <最终叶子code> --artifact video.mp4 --yes --env dev
freelog-cli create --title ... --name ... --yes --env dev
freelog-cli create-version --prepare --env dev
freelog-cli create-version --yes --env dev
```

也可省略 init，直接以 `create --type <最终叶子code> --artifact video.mp4` 一步建壳；两条路径都必须在写身份前确认文件存在。不要传类型名称或父类型。可上传与可解析仍在 `create-version` 检查。

---

## S60 线上已有自己的普通资源壳但未发行，本地有文件

**判定**：能走通

```
freelog-cli login --env dev
freelog-cli bind <id|username/name> --artifact video.mp4 --env dev
freelog-cli create-version --prepare --env dev
freelog-cli create-version --yes --env dev
```

不要再 `create`。`bind` 不上传或修改文件，只把平台身份和本地文件路径关联起来。
