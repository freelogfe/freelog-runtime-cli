# 03 - 工作稿覆盖与提交冲突（实现）

真实场景：[03](../真实场景/03-工作稿覆盖与提交冲突.md)

现行比场景原文更严的一处：提交命令本身**不对不上就重拉**。要盖走 `version draft pull`；要续用走 `--reuse-version`。

---

## S18 提交前线上已经有更高号

**判定**：能走通

提交前再 `Resource.info`。新号须 > **当时** latest。不够大：失败，稿留下。

```
# 文案要写死：
# 线上已经是 {latest}，不能发 {新号}
```

不要默默 bump 再交。

---

## S19 脚本提交：底对不上

**判定**：能走通

```
# 稿来自 1.0.0，脚本按 latest 交、没带 --reuse-version
freelog-cli update-version --yes --bump patch
# 失败。稿不动。打印：本地稿来自 1.0.0，本次底是 1.2.0
# 去下面两条之一：

freelog-cli version draft pull --yes
freelog-cli update-version --yes --bump patch

# 或明确续用这份底：
freelog-cli update-version --yes --reuse-version 1.0.0 --bump patch
```

不要在 `update-version --yes` 里默默重拉再交。

---

## S20 脚本提交：新号 ≤ 当时 latest

**判定**：能走通

```
freelog-cli update-version --yes --version 1.2.0
# latest 已是 1.2.0 → 失败，「线上已经是 1.2.0，不能发 1.2.0」。稿留下
```

不要默默改成 1.2.1。

---

## S21 进入「发新号」时发现本地是首版残留稿

**判定**：能走通

```
# update-version --yes：失败，「请先 version draft pull --yes」。不要在提交里默默盖
freelog-cli version draft pull --yes
# TTY 跑 update-version：问是否用回显盖，默认否
```

覆盖 = 整份按回显重写，不和首版残留混字段。

---

## S22 看线上不要冲掉本地未交稿

**判定**：能走通

```
freelog-cli version show
# 只读线上。有稿再打一行：本地有未提交的版本工作稿，查看请 version show --local
```

---

## S23 看本地未交稿不要去拉线上、不要写盘

**判定**：能走通

```
freelog-cli version show --local
```

不与 `--version` 一起用。没有稿：失败，「没有本地版本工作稿」。

---

## S24 交成功后本地未交稿必须消失

**判定**：能走通

`create-version` / `update-version` 成功 POST 后删 `N.version.json`。失败留下。

---

## S25 换绑到另一个资源

**判定**：能走通

```
freelog-cli bind <另一个id> --file <path> --force --yes
# 换 resourceId：删该份 N.version.json
# 同一 id 再 bind：稿保留
```
