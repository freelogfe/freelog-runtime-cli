# 02 - 发新号与回显（实现）

真实场景：[02](../真实场景/02-发新号与回显.md)

---

## S9 从最新版改一改再发新号（一次做完）

**判定**：能走通

```
freelog-cli update-version
# 无稿：按 latest 拉进工作稿 → 会话改 → POST 新号
```

一次会话仍允许。底必须来自回显，不要空表。

---

## S10 发新号之前，先把线上最新版拉到本地

**判定**：能走通

```
freelog-cli version draft pull
# 未传 --version = latest。只写 N.version.json，不 POST
freelog-cli version show --local
```

不要用 `update-version --prepare`（不存在）。

---

## S11 发新号之前，先把某一个旧号拉到本地

**判定**：能走通

```
freelog-cli version draft pull --version 1.0.0
# 号须在版本列表里。没有：「没有这个版本」，不写盘
# 不要默默改拉 latest
```

`--reuse-version` 只出现在 `update-version`（这次提交认的底），不要当「只拉」。

---

## S12 本地已有未交稿，人只想用线上某一号整份盖掉再改

**判定**：能走通

```
freelog-cli version draft pull --yes                 # 盖成 latest
freelog-cli version draft pull --version 1.1.0 --yes # 盖成 1.1.0
```

TTY 无 `--yes`：默认不盖。稿已是这一号还要再拉一次：同样加 `--yes`。覆盖 = 整份重写，不冲 `N.json` / 策略。

---

## S13 本地已有未交稿，人想接着改，不要被线上新号冲掉

**判定**：能走通

```
# 稿 fromVersion = 1.0.0，继续改
freelog-cli version attr add ...

# 交的时候明确底仍是 1.0.0；新号须 > 当时 latest（1.1.0）
freelog-cli update-version --reuse-version 1.0.0 --version 1.2.0
# 或脚本：
freelog-cli update-version --yes --reuse-version 1.0.0 --bump patch
```

`--yes` 未带 `--reuse-version`：回显源是 latest，对不上 **失败**，稿不动。脚本续用旧底必须带 `--reuse-version`。

---

## S14 分多次改缓存再交新号

**判定**：能走通

```
freelog-cli version draft pull
freelog-cli version attr add "名称=作者 键=author 值=张三"
freelog-cli version dep add someone/lib --range ^1.0.0
freelog-cli version show --local
freelog-cli update-version --yes --bump patch
```

无稿且已有 latest 时 `version attr` / `dep` 失败，「请先 version draft pull」。

---

## S15 还没有发行版本，人却按「发新号」来

**判定**：能走通

```
freelog-cli update-version          # 失败，「还没有发行版本，请先 create-version」
freelog-cli version draft pull      # 同样失败
```

不要改口发 1.0.0。

---

## S16 只改某一个已发号的描述，不发新号

**判定**：能走通

```
freelog-cli version description --version 1.0.0 --description "..."
```

不写工作稿、不 POST 新号。

---

## S17 新号怎么定

**判定**：能走通

```
freelog-cli update-version --version 1.3.0
freelog-cli update-version --bump patch     # 必须带方向：patch|minor|major
freelog-cli update-version --yes --bump patch
```

`--version` 与 `--bump` 一起：失败。`--yes` 既没有 `--version` 也没有带方向的 `--bump`：失败，不猜测。
