## S36 用模板立项一个主题（或插件）

**判定**：能走通

```
freelog-cli init . --scaffold runtime --template <id> --resource-type <叶子>
# 或
freelog-cli init theme --template <id>
freelog-cli init widget --template <id>
```

`init` **不** `POST /v2/resources`。落盘：`typeCode=RT001`（theme）或 `RT002`（widget），`filePath=dist`，默认 `pnpm install`。  
下一步仍是 `login` → `create` → `create-version`。不要 `init package` 冒充本条（前端库本期不做场景）。

## S37 已经构建过，只要指 dist，不要自己打 zip

**判定**：能走通

```
# 人自己：pnpm build   （CLI 不跑）
freelog-cli create --title ... --type <主题或插件叶子> --name ...
freelog-cli create-version
# 未传 --file：dist 在则问「使用已记录的 dist？」默认是；--yes 采用
# RT001/RT002 + 目录：打临时 zip（内容，不套一层 dist/），再 sha1 / 上传
```

不要让人 `--file xxx.zip`。其余类型若给目录：失败「不支持文件夹」。

---

## S38 还没构建，dist 没有或是空的

**判定**：能走通

```
freelog-cli create-version
# 或 create-version --prepare
# 按磁盘：目录不在或没有可打的文件 → 失败，「没有构建产物 / 构建产物是空的，请先构建」
```

不要打工程根。不要 POST。

---

## S39 产物在 build，不在 dist

**判定**：能走通

```
freelog-cli version set --file build
# 只改 N.json.filePath + index；不打 zip
# 之后 create-version / update-version 按磁盘时打 build
```

没有 `version set --artifact-mode`。打不打 zip 只看 `RT001`/`RT002`。

---

## S40 人把自己打的 zip 当成主题产物

**判定**：能走通

```
freelog-cli create-version --file ./me.zip
# RT001/RT002 且路径是文件 → 失败
# 「主题/插件请指定构建产物目录，不要自己打 zip。」
```

`filePath` 不要写成这个 zip。

## S41 先看有哪些模板，再立项

**判定**：能走通

```
freelog-cli template list --scaffold runtime
freelog-cli init theme --template <列出的 id>
```

`0.4` 未列则拒绝。`collection` 失败。`--scaffold package` 可以列，但不是本条场景。

## S42 主题发新号：又构建了一次

**判定**：能走通

```
# 人自己再 pnpm build
freelog-cli version draft pull
freelog-cli update-version --file dist
# 或未传 --file、dist 在：问是否采用（--yes 采用），再打 zip
freelog-cli update-version --yes --bump patch
```

`--file dist` 已是该份路径且目录在：换的是 zip 内容，不是改成单文件。
