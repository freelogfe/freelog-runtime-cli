## S36 用模板立项一个主题（或插件）

**判定**：能走通

```
freelog-cli init theme . --template <id>
# 或
freelog-cli init widget . --template <id>
```

`init` **不** `POST /v2/resources`。它从固定版本的线上 npm 模板包下载并复制 `template/`；落盘：`typeCode=RT001`（theme）或 `RT002`（widget），`filePath=dist`。不渲染、不跑 `pnpm install`，也不写模板元数据。
下一步仍是 `login` → `create` → `create-version`。不要 `init package` 冒充本条（前端库本期不做场景）。

---

## S37 已经构建过，只要指 dist，不要自己打 zip

**判定**：能走通

```
# 人自己：pnpm build   （CLI 不跑）
freelog-cli login --env dev
freelog-cli create --title ... --name ... --artifact dist --yes --env dev
freelog-cli create-version --yes --env dev
# init theme/widget 已写固定 RT001/RT002，create 不传 --type
# RT001/RT002 + 目录：打临时 zip（内容，不套一层 dist/），再 sha1 / 上传
```

不要让人 `--artifact xxx.zip`。其余类型若给目录：失败「不支持文件夹」。

---

## S38 还没构建，dist 没有或是空的

**判定**：能走通

```
freelog-cli create-version
# 或 create-version --prepare
# 按磁盘：目录不在或没有可打的文件 → 失败，「没有构建产物 / 构建产物是空的，请先构建」
```

不要打工程根。不要 POST。

---

## S39 产物在 build，不在 dist

**判定**：能走通

```
freelog-cli version set --artifact build
# 只改 N.json.filePath + index；不打 zip
# 之后 create-version / update-version 按磁盘时打 build
```

没有 `version set --artifact-mode`。打不打 zip 只看 `RT001`/`RT002`。

---

## S40 人把自己打的 zip 当成主题产物

**判定**：能走通

```
freelog-cli create-version --artifact ./me.zip
# RT001/RT002 且路径是文件 → 失败
# 「主题/插件请指定构建产物目录，不要自己打 zip。」
```

`filePath` 不要写成这个 zip。

## S41 先看有哪些模板，再立项

**判定**：能走通

```
freelog-cli template list
freelog-cli init theme --template <列出的 id>
```

不在输出清单的 id 一律拒绝；模板版本固定在 CLI 清单中。`collection` 与 package 模板不在本期命令面。

---

## S42 主题发新号：又构建了一次

**判定**：能走通

```
# 人自己再 pnpm build
freelog-cli version draft pull --env dev
freelog-cli update-version --yes --bump patch --env dev
```

已记录 `dist` 且目录存在：换的是 zip 内容，不是改成单文件。

---

## S56 已有本地主题/插件工程，还没有线上资源

**判定**：能走通

```
# 在已有工程根；不运行 init，保留现有源码
freelog-cli login --env dev
freelog-cli create --title ... --name ... --type RT001 --artifact dist --yes --env dev
# 插件把 RT001 换成 RT002
freelog-cli create-version --prepare --env dev
freelog-cli create-version --yes --env dev
```

既有主题/插件工程不需要任何模板元数据。`--artifact` 建立目录记录；发版时同样临时压缩目录内容。

---

## S57 线上已有自己的主题/插件壳，但从未发行

**判定**：能走通

```
freelog-cli login --env dev
freelog-cli bind <id|username/name> --artifact dist --env dev
freelog-cli create-version --prepare --env dev
freelog-cli create-version --yes --env dev
```

`bind` 从平台详情取得固定类型；没有目录记录时须传 `--artifact`。不要再 `create`，也不要造模板元数据。

---

## S58 线上已有已发行主题/插件，要在本地发新版本

**判定**：能走通

```
freelog-cli login --env dev
freelog-cli bind <id|username/name> --artifact dist --env dev
freelog-cli version draft pull --env dev
# 编辑工作稿；人自己完成构建
freelog-cli update-version --yes --bump patch --env dev
```

工作稿来自线上版本；更新时按当前目录重新打临时 zip，不能复用旧 SHA1。
