# 合集场景实现

本页用当前命令面走完 [真实场景](./真实场景.md) 的同一编号。示例默认使用 dev 环境，涉及写操作时尽量显式指定目标合集：

```text
--env dev --resource id:<collection-id>
```

`--resource` 在合集命令里只选择目标合集，支持 `id:`、`name:` 或 `file:N.json`。添加单品、依赖等位置参数是另一种资源身份，不能混用。

## C-S1 全新创建一个合集壳

```text
freelog-cli collection create --env dev --type <collection-leaf-code> --title "合集标题" --name <short-name> --yes
```

交互模式可以逐层选择合集最终叶子类型；非交互或 `--yes` 必须同时给 `--type`、`--title`、`--name`。创建成功只输出 `resourceId` 并写入一份 `subject:"collection"` 的 `N.json`，不会添加单品、表单、策略、发布或上架。

## C-S2 直接管理线上已有合集，或把它接入本地

不想绑定也能直接操作：

```text
freelog-cli collection item list --env dev --resource id:<collection-id>
freelog-cli collection form show --env dev --resource name:<loginName/collectionName>
```

想在当前工程保存身份：

```text
freelog-cli collection bind id:<collection-id> --env dev
freelog-cli collection item list --env dev --resource file:<N>.json
```

`collection bind` 的参数是目标合集，绑定后本地身份没有 `filePath`。多份合集身份同时存在时，后续写命令必须带 `--resource`。

## C-S3 本地内容先发行成单资源，再加入合集

合集命令不接收本地文件夹作为单品来源。先走单资源：

```text
freelog-cli create --env dev --type <single-resource-leaf-code> --title "视频 01" --name video-01 --artifact ./videos/01.mp4 --yes
freelog-cli create-version --env dev --resource file:<resource-N>.json --yes
freelog-cli policy template list --env dev --resource file:<resource-N>.json
freelog-cli online --env dev --resource file:<resource-N>.json
```

在交互模板列表中完成填写、预览与确认，取得至少一条启用的单资源策略后再上架；脚本改用带指纹和全部参数的 `policy template apply`。资源上架后再加入合集目录草稿：

```text
freelog-cli collection item add id:<resource-id> --env dev --resource id:<collection-id> --yes
```

这里没有“批量本地目录发行并自动加入合集”的正式命令；批量单资源发行仍是另一个设计项，不能写成合集已实现能力。

## C-S4 添加线上本人已上架单资源

```text
freelog-cli collection item add id:<resource-a> id:<resource-b> --env dev --resource id:<collection-id> --yes
freelog-cli collection item list --env dev --resource id:<collection-id>
```

来源必须是当前账号、线上、已上架、`subjectType=1`、有最新版本的单资源。重复来源会被报告为未变更；写入后命令会读回目录草稿确认。

## C-S5 单品带有上游授权缺口

显式给上游资源选择策略：

```text
freelog-cli collection item add id:<single-resource-id> --policy <upstream-resource-id>=<policy-id> --env dev --resource id:<collection-id> --yes
```

交互终端缺少 `--policy` 时会展示可签策略让用户选择；非交互模式必须显式传。签约成功后继续写目录草稿；需要支付时提示到浏览器完成，不在 CLI 内做支付。

## C-S6 管理目录里的单品

先拿稳定 `itemId`：

```text
freelog-cli collection item list --env dev --resource id:<collection-id>
```

再按 itemId 操作：

```text
freelog-cli collection item rename <item-id> --title "合集内标题" --env dev --resource id:<collection-id> --yes
freelog-cli collection item move <item-id> --before <anchor-item-id> --env dev --resource id:<collection-id> --yes
freelog-cli collection item sort --by title --asc --env dev --resource id:<collection-id> --yes
freelog-cli collection item remove <item-id> --env dev --resource id:<collection-id> --yes
```

这些命令都只写服务端目录草稿。自动收录、RSS、冻结或目标不是本人合集时会在写前失败。

## C-S7 自动收录和手工目录切换

查看规则：

```text
freelog-cli collection collect-rules get --env dev --resource id:<collection-id>
```

开启自动收录前，若服务端目录草稿与已发布目录有差异，先发布手工目录：

```text
freelog-cli collection publish --include-items yes --env dev --resource id:<collection-id> --yes
```

再设置规则：

```text
freelog-cli collection collect-rules set --auto all --rules ./collection-rules.json --env dev --resource id:<collection-id> --yes
```

关闭自动：

```text
freelog-cli collection collect-rules set --auto off --env dev --resource id:<collection-id> --yes
```

自动开启时，`item add/remove/rename/move/sort` 和 `publish --include-items yes` 会拒绝。`publish --include-items no` 只用于发表单差异。

## C-S8 维护合集资料和更新状态

更新标题、简介、封面和标签：

```text
freelog-cli collection update --title "新标题" --intro "简介" --cover ./cover.png --tag "标签A" --tag "标签B" --env dev --resource id:<collection-id> --yes
```

清空标签：

```text
freelog-cli collection update --clear-tags --env dev --resource id:<collection-id> --yes
```

维护完结/连载：

```text
freelog-cli collection collect-rules set --serialize completed --env dev --resource id:<collection-id> --yes
freelog-cli collection collect-rules set --serialize serial --env dev --resource id:<collection-id> --yes
```

封面上传没有裁剪能力；需要裁剪时用户应先在本地准备好图片。

## C-S9 编辑属性、可选配置、描述和目录展示

拉取完整表单协议：

```text
freelog-cli collection form pull --out collection.form.json --env dev --resource id:<collection-id> --yes
```

编辑 `collection.form.json` 后写回本地操作稿：

```text
freelog-cli collection form edit --from collection.form.json --env dev --resource id:<collection-id>
freelog-cli collection form show --env dev --resource id:<collection-id>
```

展示设置可用便捷入口：

```text
freelog-cli collection display set --sort ascending --title resource-title --number true --image true --description true --view list --env dev --resource id:<collection-id>
```

这些命令只维护本地表单操作稿，不发布、不读取 Console 草稿。

## C-S10 维护合集直接依赖

先有本地表单稿：

```text
freelog-cli collection form pull --out collection.form.json --env dev --resource id:<collection-id> --yes
```

添加或修改版本范围：

```text
freelog-cli collection dep add id:<dependency-resource-id> --range "^1.0.0" --policy <policy-id> --env dev --resource id:<collection-id> --yes
freelog-cli collection dep range id:<dependency-resource-id> --range "^2.0.0" --env dev --resource id:<collection-id> --yes
freelog-cli collection dep list --env dev --resource id:<collection-id>
freelog-cli collection dep rm <dependency-resource-id> --env dev --resource id:<collection-id>
```

`--policy` 只在未授权时需要；交互终端可选择策略。依赖写入的是本地表单草稿，发布前不会改变线上合集。

## C-S11 发布合集变更

只发表单，不合并目录：

```text
freelog-cli collection publish --include-items no --env dev --resource id:<collection-id> --yes
```

明确合并当前服务端目录草稿：

```text
freelog-cli collection publish --include-items yes --env dev --resource id:<collection-id> --yes
```

自动判断是否合并目录：

```text
freelog-cli collection publish --include-items auto --env dev --resource id:<collection-id> --yes
```

发布成功不会上架。没有本地表单稿但目录草稿有变化时，`auto` 可以只发布目录；已有发布快照时平台必须明确返回授权排除映射，否则会拒绝。没有本地稿且不需要合并目录时会提示无需发布；已 pull 的本地表单稿不保证有实际修改，不能承诺自动去除无变化稿。

## C-S12 发布中断、冲突或结果未知

发布请求未知或读回不一致后，只读诊断：

```text
freelog-cli collection publish resume --env dev --resource id:<collection-id>
```

`resume` 只读，不自动重发或清理 intent。先保存本地未发布修改并核实前次请求结果；若线上表单基线已变，再重新：

```text
freelog-cli collection form pull --out collection.form.json --env dev --resource id:<collection-id> --yes
```

再人工合并后决定下一次发布，不能把重拉当作未知发布已经解决的证据。`--yes` 会确认覆盖已有本地表单操作稿；不确定时去掉该参数阅读确认。

## C-S13 管理合集自身授权策略

查看当前策略：

```text
freelog-cli collection policy list --env dev --resource id:<collection-id>
```

交互选择模板、填写参数并提交：

```text
freelog-cli collection policy template list --env dev --resource id:<collection-id>
```

查看模板详情和脚本骨架：

```text
freelog-cli collection policy template info <template-id> --env dev --resource id:<collection-id>
```

脚本或 AI 精确提交：

```text
freelog-cli collection policy template apply <template-id> --template-fingerprint <fingerprint> --name "策略名" --param "1=<value>" --param "2=<value>" --env dev --resource id:<collection-id> --yes
```

启停策略：

```text
freelog-cli collection policy set --id <policy-id> --on --env dev --resource id:<collection-id> --yes
freelog-cli collection policy set --id <policy-id> --off --env dev --resource id:<collection-id> --yes
```

模板列表当前由后端一次返回，CLI 按响应里的 `compileType=collection` 过滤；交互列表内部分页选择，不需要用户传分页参数。

## C-S14 上架和下架合集

上架：

```text
freelog-cli collection online --env dev --resource id:<collection-id> --yes
```

下架：

```text
freelog-cli collection offline --env dev --resource id:<collection-id> --yes
```

`online` 要求已有已发布合集快照，并且至少有一条启用的合集自身策略。`offline` 不删除目录、表单、策略或合同。

## C-S15 查看更新日志和授权方合约

更新日志：

```text
freelog-cli collection log list --limit 50 --order desc --env dev --resource id:<collection-id>
freelog-cli collection log list --all --json --env dev --resource id:<collection-id>
```

本合集作为授权方的合约：

```text
freelog-cli collection contract list --status active --limit 50 --env dev --resource id:<collection-id>
freelog-cli collection contract show <contract-id> --json --env dev --resource id:<collection-id>
```

这些都是只读命令，不会修改合集。

## C-S16 RSS、冻结、无权等写保护

RSS 合集暂不注册 `collection rss` 命令。普通写命令检测到 RSS、冻结或非本人目标时失败，例如：

```text
freelog-cli collection item add id:<resource-id> --env dev --resource id:<rss-or-frozen-collection-id>
freelog-cli collection publish --env dev --resource id:<rss-or-frozen-collection-id>
```

只读命令仍按平台权限工作：

```text
freelog-cli collection log list --env dev --resource id:<collection-id>
freelog-cli collection contract list --env dev --resource id:<collection-id>
```

## C-S17 环境、权限、并发和混合身份

同一工程存在多份合集或同时有单资源、合集时，写命令都带显式目标：

```text
freelog-cli collection item list --env dev --resource file:<collection-N>.json
freelog-cli collection publish --env dev --resource id:<collection-id> --yes
```

如果只存在一份合集身份，可省略 `--resource`；存在多份时必须指定。单资源命令会拒绝合集目标，合集命令也不会把普通资源 `N.json` 当合集身份。

并发写同一工程时，本地表单和发布 intent 使用工程锁；远端写入后读回确认。未知发布使用 `publish resume` 诊断；目录、资料和策略写入分别查询各自事实，不能把发布恢复命令当成所有写入的通用恢复入口，也不能自动重发。

## C-S18 已有单品授权修复的功能边界

当前已实现的是只读状态：

```text
freelog-cli collection item auth status <item-id> --env dev --resource id:<collection-id>
```

`collection item auth resolve` 尚未实现，原因是已有单品重新选择上游授权的请求体、真实 `contractId` 映射和读回契约还未完成 dev 验证。文档、测试和使用说明都不能把它写成可用功能。
