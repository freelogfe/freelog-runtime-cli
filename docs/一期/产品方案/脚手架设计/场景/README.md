# 场景

本夹两套文档，编号对齐（S1…）。不要写进一套里。用户实际要敲的完整路径另见 [使用/按场景操作](../../使用/09-按场景操作.md)。

| 子夹 | 写什么 | 不写什么 |
|------|--------|----------|
| [真实场景/](./真实场景/README.md) | 人要用 CLI 干什么：现状 / 人要 / 成功 / 失败 | 命令名、旗标、实现细节 |
| [场景实现/](./场景实现/README.md) | 用**现行**设计命令把同一条场景走完 | 不要改真实场景来迁就命令 |

改 `ARCHITECTURE` / `PHASE` / `COMMANDS` 之前：先看真实场景还成不成立，再看场景实现还能不能走通。覆盖不了 = 设计缺口，改命令，不改真实场景。

当前单资源场景必须至少覆盖以下分流，缺任一项都不是完整体验：

| 资源形态 | 尚未上线 | 线上有壳、未发行 | 已发行后继续维护 |
|---|---|---|---|
| 普通单文件 | 空目录立项或已有工程直接建壳 | bind 文件后发首版 | bind / 拉稿 / 发新号 |
| 主题 / 插件模板工程 | `init theme/widget` 后建壳 | bind 构建目录后发首版 | bind / 拉稿 / 重新构建目录 / 发新号 |
| 已有主题 / 插件工程 | 显式固定类型 + 构建目录建壳 | bind 构建目录后发首版 | bind / 拉稿 / 重新构建目录 / 发新号 |

主题/插件与普通文件共享版本表单、依赖、属性、策略和管理场景；差异仅是固定类型、模板来源（如有）、目录记录和提交前临时压缩。本期不保存模板缓存。
