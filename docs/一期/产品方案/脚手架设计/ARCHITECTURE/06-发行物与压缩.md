# 06 - 发行物与压缩

`create-version` 与 `update-version` 以下统称**发版**。

主题 / 插件在平台上要 zip。人在本地是前端工程，构建后只有 `dist` 或 `build`。**不要让人自己打 zip。**  
打不打 zip **只看类型 + 这次确认的路径是不是目录**，不看 `artifactMode`，也不默默信 `N.json.filePath`。

---

## 1. 写死的类型

CLI **写死**这两个资源类型 code（不要猜名称、不要靠 `artifactMode`）：

| | `typeCode` | 快捷立项 |
|--|------------|----------|
| 主题 | `RT001` | `init theme` |
| 插件 | `RT002` | `init widget` |

树上的子类型：能上溯到 `RT001` / `RT002` 的，按主题 / 插件对待。其余类型一律当普通文件。

`init theme` 写下 `typeCode=RT001`、`filePath=dist`。  
`init widget` 写下 `typeCode=RT002`、`filePath=dist`。  
立项时就要指定打包目录，默认 `dist`；要改成 `build` 用 `version set --file build`（当时目录可以还不在）。

---

## 2. 什么时候打 zip

发版已经确认了本地路径之后：

| 类型 | 路径是目录 | 路径是文件 |
|------|------------|------------|
| 主题 / 插件（§1） | **打 zip**：把目录**里面的文件和子目录**打进去，zip 根不再套一层 `dist/` | 失败。「主题/插件请指定构建产物目录，不要自己打 zip。」 |
| 其余 | 失败。「不支持文件夹，请指定一个文件。」 | 按这个文件上传 |

压缩的是目录**内容**，不是把文件夹本身再包一层。  
人先自己构建。CLI 不跑 `pnpm build`。zip 只在临时目录，传完就删，不写进工程、不写进 `N.json`。

验目录（主题/插件 + 路径是目录时）：

| 情况 | |
|------|--|
| 目录不存在 | 失败。「没有构建产物 {path}，请先构建。」 |
| 没有可打的文件 | 失败。「构建产物是空的，请先构建。」 |
| 目录就是工程根（这一层有 `.freelog/`） | 失败。「不要把工程根当产物目录，请指定 dist 或 build。」 |
| 合法 | 打 zip；大小看 **zip 之后** 的 `fileMaxSize` |

---

## 3. `N.json.filePath` 只是记录，发版不能采信完

`N.json` **会**记本地路径（`init` / `create --file` / `bind --file` / `version set --file` / 发版确认后回写）。  
其余资源文件可能改名、换位置；主题的 `dist` 也可能还没构建。**发版不要只凭记录就上传，更不要只凭工作稿 sha1 在本地文件不在时默默续用。**

改记录、不发版：`version set --file <path>`。名称变了就改这一下，合理，保留这条命令。

### 3.1 发版怎么定「这次用哪条路径」（两条命令共用）

先按 [02](./02-本地状态.md) 落到哪一份（多份必须 `--file`）。再定路径：

| 进入 | TTY | `--yes` |
|------|-----|---------|
| 已传 `--file` | 用这个。若和记录不同，回写 `N.json.filePath` + index | 同上 |
| 未传，记录的路径**本地存在** | 问：使用已记录的 `{path}`？**默认是**。否：再问一次路径 | **采用记录**，不问 |
| 未传，没有记录，或记录的路径**本地不在** | 问一次路径。空则失败 | 失败，「请 --file 指定本地文件或目录」 |

确认后的路径必须在本地。然后按 §2：主题/插件目录 → 打 zip；其余必须是文件。  
再对得到的文件（zip 或原文件）算 SHA1 → `fileIsExist` → 上传。工作稿 `fileSha1` 是这次算出来的。

`--file` 只用来选份、换路径、确认，**不**再表示「本地不在就续用旧 sha1」。

## 4. 插在发版的哪一步

不增加命令，不增加菜单。插在「路径已确认」和「算 SHA1」之间。

### `create-version`（含 `--prepare`）

见 [发行版本](../PHASE/单资源/创建/02-Step2-发行版本.md) §1–2。

```
0 门禁 → 0.1 稿提醒
  → 1 定份 + 按 §3.1 确认本地路径（记录在且存在则问是否采用）
  → 2 按 §2：主题/插件目录则打临时 zip；其余目录失败
        → 对 zip 或文件算 SHA1 → 上传 → 删临时 zip
  → 3 解析 → `--prepare` 结束 / 会话 / POST 1.0.0
```

### `update-version`

见 [更新版本](../PHASE/单资源/更新版本/01-更新版本.md) §3–4。定新号在确认路径之前，和打不打 zip 无关。

```
0 门禁 → 稿 / 回显 → 定新号
  → 3 定份 + 按 §3.1 确认本地路径
  → 4 按 §2 打 zip（若需要）→ SHA1 / 上传 / 解析
  → 会话 / POST 新号
```

`init`、`create`、`bind`、`version set`、`version show` **不**打 zip。  
打 zip 没有 tools-lib。

---

## 5. 禁止

- 用 `artifactMode` 或类型中文名决定打不打 zip
- 其余类型传目录还当成功
- 主题/插件传一个 `.zip` 文件还当成功
- 发版未确认路径就按记录或旧 sha1 上传
- 本地文件不在还续用稿里的 sha1
- 要求人先打 zip；发行时替人跑构建
- 把工程根打进去
