## 📋 **一、CLI 框架能力定位**

### **1.1 重要概念区分**

根据《Freelog 资源发行模块需求分析报告》：

| 概念归属 | 定义方 | 包含内容 | 是否可变 |
|---------|--------|---------|---------|
| **资源类型定义** | **Freelog 平台 (后端)** | Theme, Plugin, Library, Software, Collection | 由平台决定 |
| **模板创建工具** | **CLI 脚手架** | `freelog create template` - 生成标准目录结构 | CLI 实现 |
| **压缩打包工具** | **CLI 脚手架** | `freelog build` - 生成 artifact.zip | CLI 实现 |
| **发布流程编排** | **CLI 脚手架** | `freelog publish` - 调用 API 完成发布 | CLI 实现 |

**关键理解：**
- ✅ **CLI 不是资源类型的定义者** - 只是适配 Platform 已有的资源类型
- ✅ **CLI 是通用工具集** - 为所有资源类型提供相同的模板创建 + 压缩打包能力
- ❌ **不要混淆** - 不能说 "CLI 支持主题插件等模板" → 应该说 "CLI 为 Platform 的主题插件等资源提供模板工具"

### **1.2 关键说明**

**Freelog 平台资源类型 vs CLI 脚手架能力：**

| 概念 | 归属方 | 说明 |
|------|--------|------|
| Theme, Plugin, Library, Software, Collection | **Freelog 平台** | 平台支持的资源分类，由后端定义 (来源：需求分析报告) |
| `freelog create template` | **CLI 脚手架** | 提供通用模板创建能力，支持上述所有类型 |
| `freelog build/package` | **CLI 脚手架** | 提供通用的压缩打包能力，不区分资源类型 |

**CLI 脚手架的定位总结：**
- ✅ **通用工具集**：为 Platform 的所有资源类型（Theme/Plugin/Library/Software/Collection）提供相同的工具
- ✅ **适配而非定义**：不决定平台支持哪些资源类型，只是适配 Platform 已有的类型
- ❌ **错误理解**：不能说 "CLI 支持主题插件模板" → 应该说 "CLI 为 Platform 的主题插件等资源提供通用工具"

## 🔄 **二、完整四层架构**

```
┌─────────────────────────────────────┐
│   Layer 4: UI/UX (TTY Interface)    │
│   └── TTY 交互组件 + 进度渲染器      │
├─────────────────────────────────────┤
│   Layer 3: Step Orchestrator        │
│   └── PHASE 专项设计 (F0/M0/C0/etc) │
├─────────────────────────────────────┤
│   Layer 2: Business Logic           │
│   └── 业务梳理中的 Step 实现          │
├─────────────────────────────────────┤
│   Layer 1: API Client               │
│   └── tools-lib 复用                 │
└─────────────────────────────────────┘
```

### **Layer 1-4 的职责划分：**

| Layer | 职责 | 位置 | 是否经常变化 |
|-------|------|------|------------|
| **UI/UX** | TTY 界面展示、进度条、错误提示 | Layer 4 | 否 |
| **Step Orchestrator** | 编排 Step 流程、Checkpoint 管理 | PHASE/ | 是（随需求变化） |
| **Business Logic** | 业务规则实现、字段验证 | PHASE/ | 部分 |
| **API Client** | HTTP 请求封装、认证处理 | tools-lib | 否 |
| **CLI Framework** | 模板创建、压缩打包、账号管理 | packages/cli/src | 否 |

## 💡 **四、使用说明**

1. 先看 **ARCHITECTURE/01-整体架构.md** 了解 CLI 框架能力
2. 查看 **PHASE/** 学习现有功能的编排方式

1. 打开对应 PHASE 文档（如 F0）
2. 阅读 Step 编排流程图
3. 对照 CLI Framework 的压缩/模板工具调用点

---

**📌 总结**：CLI 脚手架是**通用工具集**，不定义资源类型，只为 Platform 提供的资源类型（Theme/Plugin/Library/Software/Collection）提供创建和发布的基础能力。

关键区别：
- **Platform 的职责**：定义资源类型、业务流程、字段约束
- **CLI 的职责**：提供通用工具适配这些类型，编排发布流程
