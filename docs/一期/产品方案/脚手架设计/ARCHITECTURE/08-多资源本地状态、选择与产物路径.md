# 08 - 多资源本地状态、选择与产物路径

本文件自 2026-09-08 起覆盖先前“一个工程只能管理一个资源”“固定 `1.json`”“发现多份身份即要求拆工程”的决定。一个工程可以管理多份**独立的单资源**；这不引入合集、批量发行或一个版本包含多个资源。

它还覆盖旧文档中把 `--file` 同时用作“选择身份”和“产物路径”的写法。公开命令只用 `--artifact` 表示产物路径；资源选择统一使用 `--resource` 或交互选择。

## 1. 状态模型

```text
<project>/
  .freelog/
    auth                 # 非秘密账号选择器
    1.json               # 资源 A 身份
    1.version.json       # 资源 A 的未提交下一版（存在时）
    2.json               # 资源 B 身份
    2.version.json       # 资源 B 的未提交下一版（存在时）
    index.json           # 派生索引，不是主本
    .lock / .txn.json    # 瞬态可靠性文件
```

`N.json` 与同编号的 `N.version.json` 是一个资源的状态单元，编号只作文件名，不是业务排序，也不复用。`index.json` 可由所有 `N.json` 重建，不能作为恢复唯一依据。

每份身份（包括未绑定立项）都必须记录：`typeCode` 与 `filePath`。已绑定身份再记录 `resourceId`、`name`（资源标识符）、`title`（资源标题）与非 prod 的 `env`；未绑定身份没有后四项。`filePath` 是现存工程内产物的唯一锚点：普通资源为文件；主题/插件可为文件或构建目录。每一条都进入 `index.json`，不得存在或忽略无路径状态。`title` 仅用于本地选择列表与标题匹配：它不是线上标题的缓存真源，命令不得仅凭这个字段向平台作写入判断。

`update --title <title>` 在平台成功后，必须在同一资源的 `N.json` 回写该标题。用户也可显式运行 `resource sync`：它按每份身份的 `resourceId` 从平台读取详情，批量更新本工程中对应的 `title`，以处理 Console、其他 CLI 或其他机器造成的标题变化。

旧版 `N.json` 可以没有 `title`：读取时显示为“未同步标题”，不参与标题选择；不会因补字段而改写本地文件。新建或 bind 的身份必须写入标题。用户在确认当前环境正确后运行 `resource sync`，成功才补齐旧身份的标题；同步失败仍保留旧状态，不得填入猜测值。

## 2. 两个互不混淆的参数

| 参数 | 含义 | 适用命令 |
|---|---|---|
| `--resource <selector>` | 本次操作哪一份 `N.json` | 所有需要本地资源身份的命令 |
| `--artifact <path>` | 当前资源的文件或构建目录；绝不选择身份 | `init`、`create`、`bind`、`create-version`、`update-version`、`version set` |

`--resource` 可精确指定 `N.json` 文件名、资源 ID、短标识（也接受当前账号的 `username/name` 写法）或资源标题。短标识的重复约束以平台的 `username/name` 命名空间为准：创建前查重，创建后不可改；同工程不得保存重复短标识。为消除同值歧义，CLI 同时支持显式形式：`file:2.json`、`id:<resourceId>`、`name:<username/name>`、`title:<title>`。不带前缀时按上述四类精确匹配；得到零条或多条都不猜测，提示用户使用显式形式。

`--artifact` 是写入身份时的必填产物锚点：`init` / 新增 `create` / 新增 `bind` / `version set` 都先验证它存在于工程内；普通资源必须是单个文件；`RT001` 主题和 `RT002` 插件可为单个文件或构建目录。发版时它是实际上传路径且成功后回写；主题/插件目录还须非空，CLI 才临时压缩目录内容，主题/插件文件（包括 zip）直接上传。已有合格状态由 create/bind 复用既有锚点时可省略 `--artifact`，但也必须在写入前重新验证该锚点仍存在且形态匹配；它已被删除时不得建壳或 bind。

## 3. 命令路由与选择规则

每个命令必须先归入下表的一种路由，不能只因“看起来会调用 `resolveIdentity`”而省略该设计。任何身份相关路径都按同一顺序执行：持锁并恢复 `.txn.json` → **全量**校验所有状态单元 → 解析目标 → 再调平台或写入。全量校验包括：所有 `N.json` 可解析；`resourceId`、标识符与规范化 `filePath` 没有重复；每个 `N.version.json` 都有同号身份且资源 ID / 类型匹配。任一项失败，保留文件、退出且零平台调用。

### 3.1 命令路由矩阵

| 路由 | 命令 | 未传 `--resource` | 传 `--resource` |
|---|---|---|---|
| 无资源 | `login`、`logout`、`template`、`type` | 不读取身份 | 不接受或忽略为未知选项；不得暗中绑定身份 |
| 本地产物接入 | `init` | 新建一份带 `typeCode` + `filePath` 的未绑定身份；模板子命令创建 `dist/` | 不接受；`init` 不向已有状态追加 |
| 单资源操作 | `status`、`version show/set/draft/description/attr/option/dep`、`create-version`、`update-version`、`update`、`policy list/template/apply/set`、`validate`、`online`、`offline` | 零份：给 create/bind 指引并失败；一份：静默选中；多份：TTY 选择或退出，非 TTY / `--yes` 失败 | 只接受恰好一份精确匹配；零条/多条均失败 |
| 创建资源壳 | `create` | 仅一份未绑定状态时接续该份；没有未绑定状态时新建未绑定状态并在成功后写入；多份未绑定状态时报错，要求显式选择 | 只能选择未绑定状态；已绑定状态失败，绝不覆盖或重建线上壳 |
| 接入线上资源 | `bind <id\|name>` | 同一资源 ID 已存在时幂等使用那份；否则仅一份未绑定状态时接续它；没有未绑定状态时新增 `N.json`；多份未绑定状态时报错 | 选择目标状态；若该资源 ID 已在另一份，失败；替换已绑定目标必须 `--force --yes` 并同事务删除该份工作稿 |
| 工作区标题同步 | `resource sync` | 同步当前 `--env` 下**全部**已绑定身份；这是唯一批量例外，不弹选择菜单 | 只同步精确命中的一份，且其 `env` 必须等于当前 `--env` |

`init` 的模板子命令保持“不覆盖非空工程”的边界；通用 `init --artifact` 可以在没有资源状态的已有项目中接入**第一份**产物，但不得向已有状态追加身份。`create` 与 `bind` 是新增或接续状态单元的专属生命周期入口，不能套用“多份就先选一份”的通用钩子；这确保已经有多个已绑定资源时，用户仍能新增资源。

对“单资源操作”路由：

1. `--resource` 已给：按 §2 精确解析，得到一条才继续。
2. 未给且工程只有一份可用 `N.json`：静默自动选择该份，不提示选择，保持单资源工程的便捷性。
3. 未给且没有 `N.json`：不弹出空选择列表，不调平台。提示按意图直接执行 `create --type <叶子类型> --artifact <路径>`（新资源；也可先 `init` 再 create），或 `bind <资源 ID|标识符> --artifact <路径>`（接入已有资源）；以 `IDENTITY_NOT_FOUND` 失败。
4. 未给且有多份：TTY 列出 `N.json`、标题、短标识、资源 ID、类型、产物路径和是否有工作稿；用户选择一项或明确退出。退出不写本地、不调平台。
5. 未给且多份但非 TTY 或给了 `--yes`：失败并逐份列出可复制的 `file:N.json` 示例（同时带标题、短标识、资源 ID），绝不按“第一条”执行。

标题不是唯一键；资源 ID、标识符、`N.json` 文件名和规范化产物路径必须在一个工程内唯一。即使在 TTY 中，**已显式给出的歧义选择器也不再弹第二次猜测菜单**：CLI 报出候选并要求改用 `file:`、`id:` 或 `name:`。只有完全未传 `--resource` 时才进入选择列表。

## 4. 已有本地状态冲突与恢复

CLI 先持有 `.lock` 并恢复可验证的 `.txn.json`，再检查所有状态单元。除可无损重建的 `index.json` 外，遇到下列冲突均停止，不访问平台、不删除或覆盖任何身份/工作稿：

| 冲突 | 处理与用户选项 |
|---|---|
| 手工复制造成两份 `N.json` 的同一 `resourceId`、`name` 或 `filePath` | 报出冲突文件。用户可备份后删除整组重复的 `N.json` + `N.version.json`，或保留一组、删除另一组后重新 `bind`。CLI 不选“较新”者。 |
| `N.json` 缺少 `filePath`，或新路径不在工程内 / 不存在 / 形态不匹配 | 视为不完整状态，停止且不访问平台。CLI 不扫描或猜测文件；用户备份后删除同编号状态单元，再用现存产物重新 `init --artifact`、`create --artifact` 或 `bind --artifact`。 |
| `N.version.json` 没有同号身份，或身份与工作稿的资源 ID / 类型不一致 | 报出两份文件并保留。用户可备份后丢弃孤儿工作稿，再 `version draft pull`；不得把稿自动接到另一资源。 |
| `bind` 的资源 ID 已存在 | 选择已存在的那份；同 ID 且类型一致时幂等。若用户要替换该份绑定，须显式 `--force --yes`，并在同一事务内删除其工作稿。 |
| `bind` / `create` 指向已被另一资源占用的规范化 `filePath` | 拒绝并显示占用的 `N.json`；用户可选择那份资源、为新资源传新的 `--artifact`，或先有意识地更改旧资源的 `version set --artifact`。 |
| 标题相同 | 不是状态冲突；交互列表展示 ID / 标识符供选择，非交互必须给唯一 `--resource`。 |
| `index.json` 缺失、损坏或与 `N.json` 不一致 | 从无冲突的 `N.json` 重建；不把索引当主本。 |

### 4.1 标题同步的边界与失败

`resource sync --env dev|test|prod` 只请求同一环境的已绑定状态：`env=dev` 只在 dev 同步，`env=test` 只在 test 同步，未写 `env` 的身份只在 prod 同步。它必须先检查本地身份/工作稿冲突；存在重复 ID、损坏身份或孤儿工作稿时，整体停止，以免把远端标题写到不可信的本地状态。

请求成功的标题先留在内存；所有请求完成后，把成功项的 `N.json` 放进同一 `.txn.json` 原子提交。任一资源的请求失败、不可见或环境不匹配时，该份标题保持原值；命令打印成功数、失败的 `N.json` 与原因，并以非零退出。这样允许网络部分失败而不留下半写 JSON，也不会把失败误报成已同步。`--json` 输出每一份的结果，便于重试。

同步是显式命令，普通资源操作不会因标题可能过期而额外批量访问平台；需要选择资源的命令仍可用 ID、标识符、文件名或交互列表可靠定位。标题精确匹配仅是便利入口，发生歧义仍须交互选择或改用唯一选择器。

用户可以随时备份或删除某个资源完整的本地状态单元（`N.json` 与同号 `N.version.json`），之后在空位重新 `bind <id> --artifact <path>`。删除未提交工作稿会丢失本地未 POST 的属性、配置、依赖和描述；CLI 在任何提供删除动作前必须提示这一点。当前没有自动清理或自动拆分命令。

## 5. 实现与验证边界

所有本地状态写入继续采用锁、原子替换和跨文件 `.txn.json`。资源选择发生在任何平台调用之前；写入目标始终是已解析 `N` 的那一组文件。

最少测试覆盖：零身份时的无平台提示；单份静默自动选择；多份 TTY 选择与退出；多份非交互拒绝；按文件名、ID、标识符和标题选择；同标题歧义；重复 ID/标识符/路径拒绝；孤儿或不匹配工作稿拒绝；`bind --force` 工作稿清理的事务恢复；`update --title` 回写；`resource sync` 的按环境过滤、全量/单资源范围、部分远端失败与事务恢复；以及普通文件、主题、插件的 `--artifact` 形态差异。
