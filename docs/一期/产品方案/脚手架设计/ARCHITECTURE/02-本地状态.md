# 02 - 本地状态与续作

本期只谈**普通单资源**。合集暂缓，见 [archive](../../archive/2026-09-04-脚手架设计-合集备份/README.md)，本文不再展开合集字段和接续。

本地 **身份** 只记不可变字段和对应文件，进 `N.json`。listing / 策略 / 上下架 / 已发版事实不缓存。  
属性和可选配置往往很多，一次会话加不完（人 / AI 想到一个加一个）。所以另有 **版本工作稿** `.freelog/N.version.json`：加一项就写盘，下次接着加。  
不做平台版本草稿（不对 `lookDraft` / `saveVersionsDraft`）。  
接续只发生在「有壳、还没有版本」。`bind` 细则见 [04](./04-bind.md)。创建步骤见 [PHASE/单资源](../PHASE/单资源/README.md)。

没有 `pull` 回写身份。继续前 **GET 平台**，对比身份，TTY 确认再写。

---

## 1. 原则

| 线上 | 本地 |
|------|------|
| 进度、listing、策略、版本 | 不管；每次现问 |
| 已提交的步骤 | 用详情判断 |

本地产品目录只有 **`.freelog/`**：凭据 + 编号 manifest + 对照表。

`status` **只打印现状**，不改文件、不自动打下一步。

```
已 create、还没有版本 → 必须走 create-version（唯一接续）
已经有版本           → 创建结束；策略 / listing / 上架见 [单资源/管理](../PHASE/单资源/管理/00-总览.md)
```

---

## 2. `.freelog/`

根上不再放 `freelog.manifest.json` / `.freelog-auth`。没有 `state.json`。

| 路径 | 角色 | Git |
|------|------|-----|
| `.freelog/auth` | 工作区凭据（[01](./01-账号.md)） | 否 |
| `.freelog/1.json`、`2.json`、… | 每份**身份**和对应本地文件 | 宜提交 |
| `.freelog/1.version.json`、… | **版本工作稿**（属性 / 可选配置 / 依赖 / 描述） | 宜提交 |
| `.freelog/index.json` | 路径 → 编号的查询索引，不是主本 | 宜提交 |

编号只当文件名，**不是排序**。新资源 `max+1`，用过的号不复用。  
`filePath` / `artifactMode` 写在 `N.json`。和 index 打架时听 manifest，并修好 index。

```
.freelog/1.json     filePath: 09-01.mp4
.freelog/2.json     filePath: 09-02.mp4
.freelog/index.json
  09-01.mp4 → 1
  09-02.mp4 → 2
  dist      → 1     # 仅单工程主题/插件
```

命令用 `--file` 落到 `N.json`。只有一条时可省；多条必须指定。

### 2.1 该记

| 字段 | 谁写入 |
|------|--------|
| `subject` / `name` / `typeCode` | `init` / `create` |
| `resourceId` | **仅** `create` 成功或 `bind` |
| `env` | **仅**非 prod 的 `create` / `bind` |
| `filePath` / `artifactMode` | `init` / `create --file` / `bind --file` / `version set --file` |

`init` 不写 `resourceId` / `env` / `title`。未写 `env` = prod。

### 2.2 数据在哪

| 种类 | 放哪 | 例子 |
|------|------|------|
| 不可变身份 + 对应文件 | `N.json` | `resourceId` / `name` / `typeCode` / `filePath` |
| 版本工作稿 | `N.version.json` | 自定义属性、可选配置、依赖、描述 |
| 这条命令的参数 | 只在当次进程 | `create --title`、`update-version --version` |
| 已经提交的 | 平台 | 标题、策略、已发版、上架 |

`N.json` 只有：

```
subject, resourceId, name, typeCode, filePath, artifactMode
env   # 仅非 prod
```

`N.version.json` 只装将要提交的版本表单（形状见 [版本表单](../PHASE/单资源/版本表单/README.md)）：

```
fromVersion                 # 仅更新版本：从哪一号拉下来的。发行版本不要写
description
inputAttrs
customPropertyDescriptors
dependencies
baseUpcastResources
authExcludedItems
```

不准写身份、listing、策略、资源的 `latestVersion`、`fileSha1`。系统 `raw` 不进这份（每次上传现解析）。

**发行版本**：可以空表起步；视频一次都不改表单，盘上可以不建。`--yes` 没有这份就只交系统解析。

**更新版本**：必须先 `GET` 回显源，**立刻写成这份文件**，再改。属性 / 可选配置 / 依赖往往很多，不落盘就没法续改、人也很难直接改文件。  
`fromVersion` 等于本次回显源：听本地（续改）。  
`fromVersion` **低于**本次回显源（没写 `--reuse-version` 时就是低于 latest）：稿落后，**默认放弃**，按回显源重拉。TTY 仍提醒，默认选项是放弃；`--yes` 也放弃并重拉。人指定了 `--reuse-version` 且稿正好来自那一号：不算落后。  
没有这份、没有 `fromVersion`（发行版本留下的空稿也算）：用刚拉的覆盖写入。  
`--yes` 禁止「只交系统解析、丢掉上一版」；落后稿除外，按上面放弃重拉。

每加 / 改一项立刻写盘。退出、杀进程、这一轮只加了一条，已写的都还在。下次开会话先读这份，展示已有的，继续加。不必一次加齐再提交。  
人 / AI 也可以直接改这个文件（和会话写的是同一份），不新造 `property add`。本地预览若要读未提交的配置，也读这份。

### 2.3 不记（身份里）

标题、简介、封面、策略、`latestVersion`、上下架。这些不进 `N.json`。  
不把版本工作稿写进 `N.json`。不对接平台版本草稿。

### 2.4 一夹多个单资源

每天一条仍是多条 F0：`create --file` → `create-version --file`。  
线上已有：`bind <id> --file`，不要 `create` / `pull`。

---

## 3. 接续

策略 / listing / 上架不接续。`init`、再发、登录不接续。

`create` 成功但 `N.json` 还没有 `resourceId`：`bind` 同一 id。禁止再 `create`。

| 线上 | 行为 |
|------|------|
| 没有 | 可以 `create`。同名已存在 → 改 `name` |
| 有壳、无 `latestVersion` | 接续 `create-version`（上传 `filePath`） |
| 已有 `latestVersion` | 创建结束。再发一版：`update-version`，见 [更新版本](../PHASE/单资源/更新版本/01-更新版本.md) |

---

## 4. 上传

没有版本：`create-version`，走 [发行版本](../PHASE/单资源/创建/02-Step2-发行版本.md)（空表）。  
已有版本：`update-version`，走 [更新版本](../PHASE/单资源/更新版本/01-更新版本.md)：先拉回显源写入 `N.version.json`，再改这份文件。两条命令不要互相改口。  
会话每改一项写盘。中途断了整文件再传。`--reuse-version` 只出现在 `update-version`。

---

## 5. 禁止

- 按策略 / listing / 上架接续；用 `pull` 写回 manifest 或代替 `bind`
- 同名已存在当成功；已有自己的壳再 `create`
- 根上再放 `freelog.manifest.json`
- 用编号当排序；prod 还写 `env`
- 把属性 / 可选配置 / 依赖写进 `N.json`
- 按 scaffold 决定有没有工作稿
- 对接平台版本草稿；一次会话必须把属性加完才能退出
- 本期按合集写 `N.json` / 工作稿 / 接续
