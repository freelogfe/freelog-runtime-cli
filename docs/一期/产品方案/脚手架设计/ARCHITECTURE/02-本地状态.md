# 02 - 本地状态与续作

本地 manifest **只记不可变身份和对应文件**。属性、可选配置、依赖、listing、策略都不进 `N.json`。  
接续只发生在「有壳、还没有版本」。`bind` 细则见 [04](./04-bind.md)。

没有本地草稿，没有 `pull` 回写。继续前 **GET 平台**，对比身份，TTY 确认再写。

---

## 1. 原则

| 线上 | 本地 |
|------|------|
| 进度、listing、策略、版本、目录草稿 | 不管；每次现问 |
| 已提交的步骤 | 用详情判断 |

本地产品目录只有 **`.freelog/`**：凭据 + 编号 manifest + 对照表。

`status` **只打印现状**，不改文件、不自动打下一步。

```
已 create、还没有版本 → 必须走 publish / collection publish（唯一接续）
已经有版本           → 创建结束；策略 / listing / 上架见 [共用管理](./05-共用管理.md)
```

---

## 2. `.freelog/`

根上不再放 `freelog.manifest.json` / `.freelog-auth`。没有 `state.json`。

| 路径 | 角色 | Git |
|------|------|-----|
| `.freelog/auth` | 工作区凭据（[01](./01-账号.md)） | 否 |
| `.freelog/1.json`、`2.json`、… | 每份身份和对应本地文件 | 宜提交 |
| `.freelog/index.json` | 路径 → 编号的查询索引，不是主本 | 宜提交 |

编号只当文件名，**不是排序**。新资源 `max+1`，用过的号不复用。  
`filePath` / `artifactMode` 写在 `N.json`。和 index 打架时听 manifest，并修好 index。

```
.freelog/1.json     filePath: 09-01.mp4
.freelog/2.json     filePath: 09-02.mp4
.freelog/index.json
  09-01.mp4 → 1
  09-02.mp4 → 2
  dist      → 1     # 仅单工程主题/插件
```

合集不写 `filePath`；index 用 `.` 指到该合集。一夹只能一份合集。

命令用 `--file` 落到 `N.json`。只有一条时可省；多条必须指定。

### 2.1 该记

| 字段 | 谁写入 |
|------|--------|
| `subject` / `name` / `typeCode` | `init` / `create` |
| `resourceId` | **仅** `create` 成功或 `bind` |
| `env` | **仅**非 prod 的 `create` / `bind` |
| `filePath` / `artifactMode` | `init` / `create --file` / `bind --file` / `version set --file`。合集不写 |

`init` 不写 `resourceId` / `env` / `title`。未写 `env` = prod。

### 2.2 数据在哪

| 种类 | 放哪 | 例子 |
|------|------|------|
| 不可变身份 + 对应文件 | `N.json` | `resourceId` / `name` / `typeCode` / `filePath` |
| 这条命令的参数 | 只在当次进程 | `create --title`、`publish --version` |
| 属性 / 可选配置 / 依赖 / 描述 | 只在当次 `publish` 会话 → 提交才 `createVersion` | 见 [06](../PHASE/06-属性配置与依赖.md) |
| 已经提交的 | 平台 | 标题、策略、版本、上架 |

`N.json` 只有：

```
subject, resourceId, name, typeCode, filePath, artifactMode
env   # 仅非 prod
```

会话 **不写** `N.json`。取消或退出，下次重新开会话（M0 inherit 从平台上一版带）。`--yes` 不进会话，只交系统解析（M0 inherit 再带上一版）。

### 2.3 不记

标题、简介、封面、策略、`latestVersion`、上下架、发版说明、合集目录、collectRules、系统属性、自定义属性、可选配置、依赖。这些不进 manifest。

### 2.4 一夹多个单资源

每天一条仍是多条 F0：`create --file` → `publish --file`。  
线上已有：`bind <id> --file`，不要 `create` / `pull`。  
加合集：`item add <resourceId|username/name>`，不要传 mp4 路径。

---

## 3. 接续

策略 / listing / 上架不接续。`init`、M0、登录不接续。

`create` 成功但 `N.json` 还没有 `resourceId`：`bind` 同一 id。禁止再 `create`。

### 3.1 单资源

| 线上 | 行为 |
|------|------|
| 没有 | 可以 `create`。同名已存在 → 改 `name` |
| 有壳、无 `latestVersion` | 接续 `publish`（上传 `filePath`） |
| 已有 `latestVersion` | 结束。再发一版走 [M0](../PHASE/02-M0-发行新版本.md) |

### 3.2 合集

「版本」= 至少成功过一次 `collection publish`。细则 [C0](../PHASE/03-C0-合集创建.md)。

| 线上 | 行为 |
|------|------|
| 没有 | 可以 `collection create` |
| 有壳、目录从未提交 | 接续 `item add` → `collection publish` |
| 已提交过目录 | 结束。再改目录见 [合集维护](../PHASE/05-合集维护.md) |

---

## 4. 上传

`publish`：先查 §3.1 → 读 `filePath` → SHA1 → 没有才传 → 解析系统属性 → **保持会话**（不写 `N.json`）→ 提交才 `createVersion`。  
中途断了整文件再传。inherit：`publish --reuse-version`（不改 `filePath`），仍进同一套菜单。细则 [06](../PHASE/06-属性配置与依赖.md)。

---

## 5. 禁止

- 按策略 / listing / 上架接续；用 `pull` 写回 manifest 或代替 `bind`
- 同名已存在当成功；已有自己的壳再 `create`
- 根上再放 `freelog.manifest.json`
- 用编号当排序；prod 还写 `env`
- 把属性 / 可选配置 / 依赖写进 `N.json`
