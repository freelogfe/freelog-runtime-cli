## 📋 **一、设计目标与定位**

### **1.1 核心职责**

CLI 脚手架提供 **通用的压缩打包能力**，将本地工程转换为临时上传产物：

```
┌──────────────────────────────────────┐
│   Platform (后端)                     │
│   ─────────────────                   │
│   · 定义资源类型及其发布方式           │
│   · 支持单文件上传 / 文件夹压缩上传     │
└──────────────────────────────────────┘
           ↓ CLI 适配
┌──────────────────────────────────────┐
│   CLI 压缩打包工具                      │
│   ──────────────────                  │
│   · freelog build/package             │
│   · 扫描指定文件夹                    │
│   · 读取 manifest.yaml + .freelogignore |
│   · 生成 artifact.zip（临时上传产物）  │
│   · 计算 SHA1 用于文件身份校验          │
└──────────────────────────────────────┘
```

### **1.2 边界条件**

| 事项 | CLI 职责 | 非职责 |
|------|---------|--------|
| **压缩判断** | 根据 Platform capability 决定 | 不靠展示名或硬编码猜测 |
| **压缩包格式** | ZIP（字节级确定性） | 不支持其他归档格式 |
| **生命周期** | 临时上传产物，成功/失败后可清理 | 不回写为用户长期意图 |
| **构建执行** | `publish`消费已准备好的目录 | `release --build-cmd` 显式编排构建 |

### **2.2 Non-interactive Mode (--flag syntax)**

```bash
# 声明式压缩（CI/自动化场景）
freelog build \
  --dir ./my-theme \
  --output artifact.zip \
  --json-lines

# 批量压缩多个目录
for dir in ./theme-*; do
  freelog build --dir "$dir" --quiet
done
```

**重要规则**:
- dry-run 不执行 build，只显示命令、cwd、预期产物路径和未决字段
- 非交互模式必须输出结构化结果（JSON/NDJSON）
- 压缩产物默认在当前目录生成 artifact.zip，可自定义输出路径

## 📊 **三、压缩模式决策逻辑**

### **3.1 artifactMode 判断流程**

```
伪代码：
IF CLI framework has explicit capability field THEN
  # 从 Platform API 查询该类型的发布能力
  capability = queryPlatformResourceCapability(typeCode, env)
  
  IF capability.requiresCompression === true THEN
    artifactMode = 'directory-zip'
  ELSE IF capability.supportsSingleFileUpload === true THEN
    artifactMode = 'file'
  ELSE
    throwError(ERR_UNKNOWN_CAPABILITY, "无法确定资源的发布方式")
  END IF
  
ELSE IF manifest specifies artifactMode THEN
  # 模板生成的 manifest 中已有明确值
  stored_mode = readManifest().artifactMode
  
  IF stored_mode IS valid THEN
    validateAgainstTemplate(stored_mode)
    artifactMode = stored_mode
  ELSE
    throwError(ERR_INVALID_ARTIFACT_MODE, "manifest 中 artifactMode 字段无效")
  END IF
  
ELSE
  # 缺少必要信息，明确拒绝而非猜测
  showWarning("无法自动判断压缩模式")
  listOptions(["directory-zip", "file"])
  promptUserForManualSelection()
END IF
```

**关键约束** (来自 DESIGN.md):
1. 是否压缩由资源类型能力决定，不能只靠展示名或散落的硬编码
2. 内部统一能力字段为 `artifactMode: file \| directory-zip`
3. 平台适配层只读取显式能力字段并规范化，两者均缺失时必须拒绝而非猜测

### **3.2 能力字段映射表**

| 来源字段 | 内部标准化字段 | 说明 |
|---------|--------------|------|
| Platform.capability.compress | artifactMode = 'directory-zip' | 平台要求压缩 |
| Platform.capability.packageMode | artifactMode = 'directory-zip' | 包模式即压缩 |
| template.manifest.artifactMode | artifactMode = stored value | 模板明确指定 |
| manifest.artifactMode | artifactMode = stored value | 用户意图已写入 |

**冲突处理**:
```
IF platform_capability != template_specified THEN
  showWarning("平台能力与模板指定不一致")
  prefer_platform_capability()  # 以平台为准
END IF

IF platform_capability != user_manifest THEN
  throwError(ERR_CONFLICTING_CONFIG, "平台要求与本地意图冲突")
  require_user_override()
END IF
```

## 📁 **四、压缩规则与 ignore 机制**

### **4.1 忽略规则语法**

**文件格式**: `.freelogignore`（项目根相对路径的 POSIX 格式）

**支持的通配符**:
- `*` - 匹配任意字符（除路径分隔符）
- `?` - 匹配单个字符
- `**` - 匹配任意层级目录
- `/` 后缀 - 只匹配目录（如 `node_modules/`）

**不支持的功能**:
- `!` 反选规则 → 明确报错："暂不支持反选规则，请移除 ! 开头的行"

**强制排除项（不可反选）**:
```
.fredelog/                  # CLI 状态缓存
.fredelog-auth             # 身份凭据
.auth.key                  # 加密密钥
node_modules/              # npm 依赖
.git/                      # Git 仓库
*.log                      # 日志文件
.tmp/*                     # 临时文件
```

### **4.2 压缩过程 If-then-else 伪代码**

```
# Step 1: 读取配置
ignore_rules = loadIgnoreRules('./.freelogignore')

# Merge 强制排除项（优先级最高）
FOR EACH forced_pattern IN FORCED_EXCLUSIONS DO
  prepend(ignore_rules, forced_pattern)
END FOR

# Step 2: 扫描目录
files = []
FOR EACH path IN scanDirectory(source_dir) DO
  IF matchesAny(path, ignore_rules) THEN
    skip_file(path)
    log(`忽略：${path}`)
  ELSE
    files.push(path)
  END IF
END FOR

# Step 3: 验证文件大小限制
total_size = SUM(file.size FOR file IN files)
MAX_COMPRESSION_SIZE = 100 * 1024 * 1024  # 100MB

IF total_size > MAX_COMPRESSION_SIZE THEN
  showWarning(`压缩内容总大小 ${formatBytes(total_size)} 超过 100MB`)
  confirmContinue()
END IF

# Step 4: 创建确定性 ZIP
zip_writer = createZipWriter(output_path)

# 排序以确保字节级确定性
sorted_files = SORT(files BY relative_path)

FOR EACH file IN sorted_files DO
  zip_entry = {
    path: file.relative_path,
    mode: 0o644,  # 统一权限
    mtime: normalizeTimestamp(file.mtime),  # 统一时间戳
    content: readFileSync(file.absolute_path)
  }
  
  zip_writer.addEntry(zip_entry)
END FOR

zip_writer.close()

# Step 5: 计算 SHA1
file_sha1 = calculateSHA1(output_path)

# Step 6: 验证完整性
IF file_sha1 DOES NOT match expected_format THEN
  throwError(ERR_SHA1_FORMAT_ERROR, "SHA1 计算异常")
END IF

log(`压缩完成：${output_path} (SHA1: ${file_sha1.substring(0, 16)}...)`)
```

### **4.3 字节级确定性要求**

DESIGN.md §Build Contract #6 明确规定：
> 相同输入、配置和 CLI 版本必须产生字节级相同的 zip

**实现要点**:
1. **条目排序**: 按相对路径字典序排序
2. **时间戳**: 统一规范化为 Unix timestamp（弃用文件系统原始时间）
3. **权限**: 统一设置为 0644（文件）或 0755（目录）
4. **路径分隔符**: 统一使用 forward slash `/`（即使 Windows）

**验证测试**:
```
# 在相同环境下多次运行
freelog build --dir ./test-theme --out test1.zip
freelog build --dir ./test-theme --out test2.zip

# 比较 SHA1
sha1sum test1.zip test2.zip
# 必须输出完全相同的结果
```

## 🔗 **五、与 G2-UPLOAD 集成**

### **5.1 接口契约**

```
压缩模块 → 上传模块调用链：

compressDirectory(dirPath, ignoreRules) 
  ↓ returns
{
  path: string,        # artifact.zip 的路径
  sha1: string,        # 文件 SHA1
  size: number         # 字节大小
}
  ↓ passes to
detectUploadMode(fileSize) 
  ↓ returns
'single' | 'multi'
  ↓ passes to
G2.upload({
  token: string,
  filePath: string,
  headers: {
    'file-sha1': string,
    'file-size': number,
    'content-type': 'application/zip'
  },
  mode: 'single' | 'multi',
  onProgress: function
})
  ↓ returns
{
  fileId: string,
  url: string
}
```

### **5.2 断点续传机制**

```
伪代码：
# 上传前保存 checkpoint
checkpoint_data = {
  step: 'upload',
  phase: 'init',
  metadata: {
    filePath: artifact_path,
    fileSize: file_size,
    sha1: file_sha1,
    uploadMode: detected_mode
  }
}
saveCheckpoint('F0-Step2', checkpoint_data)

# 上传过程中每完成一个分片更新进度
chunkIndex = 0
WHILE chunkIndex < totalChunks DO
  chunk = readChunk(filePath, chunkIndex)
  
  progress = (chunkIndex + 1) / totalChunks * 100
  
  result = uploadChunk(chunk, chunkIndex)
  
  IF success THEN
    updateCheckpoint({
      phase: 'uploading',
      currentChunk: chunkIndex,
      percentage: progress
    })
    
    chunkIndex++
  ELSE IF network_error THEN
    resumeFromCheckpoint()
  ELSE IF permanent_error THEN
    clearCheckpoint()
    throwError(ERR_UPLOAD_FAILED)
  END IF
END WHILE

# 上传完成后清理 checkpoint
clearCheckpoint('F0-Step2')
```

## ⚠️ **六、异常处理矩阵**

| 错误场景 | HTTP Code | Error Code | 用户友好消息 | Recovery Action | Auto Retry? |
|---------|-----------|------------|-------------|-----------------|-------------|
| Directory Not Found | - | ERR_DIR_NOT_FOUND | "指定的目录不存在或无法访问" | Browse again or change --dir path | ❌ No |
| Disk Space Full | ENOSPC | ERR_DISK_FULL | "磁盘空间不足，请释放空间后重试" | Abort workflow | ❌ No |
| File Permission Denied | EACCES | ERR_PERMISSION_DENIED | "没有权限读取某些文件，请检查文件权限" | Fix permissions and retry | ✅ Yes (1x) |
| Invalid Ignore Rule | - | ERR_IGNORE_SYNTAX | ".freelogignore 中包含不支持的反选规则 (!)" | Edit .freelogignore and retry | ❌ No |
| ZIP Write Error | - | ERR_ZIP_WRITE_FAILED | "压缩过程中遇到写入错误" | Check disk health and retry | ✅ Yes (3x) |
| Upload Timeout | 408 | ERR_UPLOAD_TIMEOUT | "上传超时，网络可能不稳定" | Retry with exponential backoff | ✅ Yes (3x) |
| Checksum Mismatch | 400 | ERR_CHECKSUM_MISMATCH | "文件校验失败，服务端收到内容与本地计算不符" | Recalculate and re-upload | ✅ Yes |
| Too Many Custom Properties | 400 | ERR_TOO_MANY_CUSTOM_PROPS | "最多支持 30 个补充属性，当前 X 个" | Reduce count or remove some | ❌ No |
