# 策略语言接入（未来设计）

状态：**未实现，未注册命令，不进入当前发布包。**

本文只定义未来“用户手写策略 DSL”如何安全接入 CLI。它与已上线的[参数化策略模板](./09-参数化策略模板.md)并列，不替换模板策略，也不重新引入已删除的 `policy apply --from-file`。

## 1. 依据与边界

函数事件及其环境变量的权威教程是：[《📌函数事件环境变量_说明文档（2026.8.3）》](https://freelog.yuque.com/fsl0oy/gkva0w/nttygn2gzpwnoe4s?singleDoc)。已于 2026-09-21 按原文阅读并提炼本节的 CLI 约束；以后策略语言升级仍必须回到该文档复核，不能凭旧示例、旧注释或字符串猜测补写变量名、函数签名或事件语义。

已能从当前 Console 实码及 tools-lib 确认的契约如下：

- Console 的手写正文在确认前会将 `\t`、`\r` 规整为空格，按 UTF-8 Base64 传给 `POST /v2/translate/cg/translate`（`Policy.policyTranslation`），携带 `compileType`；调用成功并得到译文后才进入确认页。
- 写入单资源或合集均为 `Resource.update({ resourceId, addPolicies })`；正文使用 `encodeURIComponent(已验证正文)`，新策略启用。
- 单资源与合集都是 Resource。手写策略的 `compileType` 不从模板获得，而由已核验的目标决定：单资源为 `normal`，合集为 `collection`。
- 服务端可能规范化 DSL 或在读取详情时返回译文。因此成功写入后的核验是“同名策略存在且为启用状态”，不是正文的字节级相等。

这意味着本地解析器、正则或 AI 生成结果只能提供编辑便利，**绝不能作为可提交的编译证明**。每一次提交都必须让服务端校验本次实际正文。

### 教程中已确认、且影响 CLI 的语言事实

- 顶层结构由 `FOR`、签约声明、全局定义/变量、自定义表达式及状态机组成；除签约声明必须在顶层且连续出现外，多数区段可选。状态中的事件形态是 `事件 -> 目标状态[参数传递区]{动作区}`。
- `policy.*` 是发布时环境变量，例如 `policy.subject`、`policy.policyId`、`policy.licensor`；`contract.*` 是运行时环境变量，例如 `contract.contractId`、`contract.licensee`、`contract.currentFsmStateName`、`contract.licenseeSelectedElems`。它们生命周期不同，CLI 不能互换或提前求值。
- `$event.args.*` 读取事件显式/隐式参数，`$event.ctx.*` 读取事件结果；两者**只允许**在 `event -> state { Action }` 的动作区使用。将它们放到全局、状态声明或事件条件中必须依赖服务端拒绝，CLI 不尝试改写。
- 函数是动作（`Query.Service.Function`、`fun.*`、`api.*`、`Kit.*`、`Time.*`），事件是数据（`Event.分类.名称`）且没有返回值。事件的 `=` 是可选参数赋值，不等同于布尔比较 `==`。
- 当前教程列出的主要事件包括：`Event.Void`、`Event.Custom.WatchAD/ShareResource/AcceptEvent`、`Event.Echo.Labels`、`Event.Transaction.Pay/PayForRank`、`Event.Time.Relative/Schedule`。其中 `Pay(amount, elemsNum)` 在单资源中也必须给 `elemsNum=1`；集合的 `elemsNum` 表示用户可选择单品数量。时间事件分别要求时长/单位或 `yyyy-MM-dd hh:mm` 时间。
- 教程同时包含仍标记为 pending / 待讨论的类型、事件或变量。CLI 不能因文档出现名称就宣称支持；只能以本次服务端校验成功和真实 dev 样本为准。

## 2. 用户模型：显式源文件，不制造策略缓存

手写策略是用户管理的源代码，不是资源身份、版本工作稿或策略草稿：

- 推荐扩展名为 `.policy`；文件内容是纯 UTF-8 DSL，不使用 JSON 包装，也不把策略名混入正文。
- CLI 只读取用户明确给出的 `--source <path>`。`--source` 表示策略源码，和资源产物 `--artifact` 完全不同；不使用 `--file`。
- 不将正文、参数、译文、模板 ID、校验结果或未提交意图写进 `.freelog/N.json`、`N.version.json` 或新建的自动本地 JSON。
- 交互模式可以让用户输入源文件路径；非交互模式必须显式给 `--source`。CLI 不隐式创建文件，不从 stdin 静默读取，也不把编辑器临时内容保存为项目状态。
- 源文件由用户自行版本管理。CLI 在一次执行内把读取的字节保存在内存，计算摘要，并且只提交这份已被服务端验证的内存副本；验证后不会重新读文件，避免“验证 A、提交 B”。

策略名仍是单独的线上字段，遵循既有 2–20 字与当前主体内不重名的规则。它不可从文件名、标题或 DSL 自动推断。

## 3. 未来命令面

命令名称在实现前可细化，但功能面固定为以下两组对称入口：

```text
policy source validate --source <path> [--resource <selector>] [--env <env>]
policy source apply --source <path> --name <name> [--resource <selector>] [--yes] [--env <env>]

collection policy source validate --source <path> [--resource <selector>] [--env <env>]
collection policy source apply --source <path> --name <name> [--resource <selector>] [--yes] [--env <env>]
```

`validate` 是零写入命令：输出正文摘要、服务端译文和校验结论。`apply` 必定重复完整校验；`--yes` 只跳过**校验成功之后**的人工确认，不能跳过目标校验、编译/翻译校验、重复检查或写后读回。

人工路径是：指定源文件 → 查看译文与摘要 → 确认创建。AI/脚本路径是：先 `validate` 获取服务端结果 → 使用同一源文件运行带 `--name --yes` 的 `apply`。两条路径的领域流程完全相同。

## 4. 必须共享的领域流程

```text
解析并实时核验目标
  → 读取一次显式 DSL 源文件，固定内存正文与 digest
  → 按目标 compileType 调用服务端校验/翻译
  → 展示译文、正文摘要和源文件 digest
  → 重读可写目标与现有策略，检查名称冲突
  → 用户确认（或 --yes）
  → Resource.update(addPolicies)
  → 读回：同名且启用
```

1. 先复用 `PolicySubject` 适配器解析目标，并实时核验环境、精确 `resourceId`、本人 owner、未冻结及主体类型。单资源不得误写合集，合集不得误写单资源。
2. 对源文件只做安全的本地前置检查：存在、普通文件、可读、非空、UTF-8。不要试图在本地解释函数事件或环境变量。
3. 调用 `Policy.policyTranslation({ policyText: base64(normalizeTabsAndCR(source)), compileType })`。该服务端请求失败、无译文或响应不满足正式契约时，显示原始可读错误并**零写入**。成功结果是当前正文可进入提交确认的唯一编译/翻译凭据。
4. 预览必须同时显示策略名、源文件绝对路径、正文 SHA-256 摘要、目标类型、服务端译文，以及“正文来自本地文件、语义由服务端验证”的说明。默认不在普通成功输出中回显完整 DSL；显式诊断模式才允许回显，且不得混入 `--json` 的稳定机器输出。
5. 写入前重新读取目标和策略列表。已存在同名策略时直接失败；不得按标题、译文或本地摘要匹配线上策略。服务端若拒绝等价正文，保留服务端错误，不进行字符串改写或自动重试。
6. 发送 `addPolicies` 后重读，确认同名策略为启用。读取正文的格式或文本差异不判失败；请求结果未知时不自动重发，也不能仅凭可能早已存在的同名策略宣称本次创建成功。

模板策略与手写策略都复用目标核验、译文预览、`addPolicies`、写后读回和策略启停；两者唯一不可强行合并的部分是前置校验：模板使用 `reCompile(templateId, fillArgs)`，手写 DSL 使用服务端翻译/编译校验。

## 5. 函数事件与环境变量的特别门禁

函数事件的变量、可用事件、实参类型和结算前置条件以教程为准，不以客户端猜测为准。实施时必须满足：

- 将上述教程摘要与原文链接作为**帮助与文档**提供；不要硬编码为本地放行规则。平台升级后，本地白名单会比服务端更早过期。
- 不用 `includes('Transaction')`、正则或旧 `~freelog.*` 名称判断收费事件。当前 Console 的这种模板 UI 辅助逻辑不适合手写 DSL 的提交门禁。
- 若收费/结算事件需要账户前置条件，必须由正式的服务端预检接口或编译响应中的结构化事件元数据判断。该契约尚未确认时，手写策略接入不得把此类检查伪造成已完成；应在实现前补齐接口契约和 dev 样本。
- 服务端校验错误要尽量保留行、列、事件和变量信息；CLI 只补充源文件路径与执行阶段，不重写错误含义。

## 6. 输出、异常与测试

`validate --json` 的未来机器信封至少包含 `schemaVersion`、目标身份摘要、源文件路径、源文件 digest、`compileType`、`valid` 与译文；不输出可执行 DSL 正文。`apply --json` 还包含策略名称、写入结果与读回的策略 ID/status。标准输出只能是一个 JSON 对象，诊断走 stderr。

最低验收必须覆盖单资源和合集两端：

| 节点 | 自动化 | dev 真网 |
|---|---|---|
| 源文件边界 | 空文件、非 UTF-8、目录、读取失败、验证后文件变化 | 一份真实 `.policy` |
| 服务端校验 | `normal` / `collection`、Base64 规整、失败零写入、译文缺失 | 各主体至少一条成功与一条语法/事件错误 |
| 写入安全 | 非本人、冻结、名称冲突、重复正文服务端拒绝、确认取消、`--yes` 不跳过校验 | 两主体各创建、读回、on/off |
| 事件环境变量 | 教程中每类已支持事件的最小样例、错误定位保留 | 有结算前置的样例仅在正式预检契约已具备时执行 |
| 隔离 | 不写 `.freelog` 策略状态、不引入 `--file`、模板路径回归不受影响 | 命令 help 与发布包一致 |

## 7. 实施前置条件

开始编码前必须同时具备：本教程的最新正文复核、`policyTranslation` 对手写 DSL 的正式成功/失败响应契约、函数事件收费前置条件的正式判定来源，以及 normal/collection 的真实 dev 样本。缺任何一项时，保留本文为设计，不注册半成品命令。
