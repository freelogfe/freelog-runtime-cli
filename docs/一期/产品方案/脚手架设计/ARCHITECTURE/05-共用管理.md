# 05 - 共用管理

> listing / 策略 / 上下架。单资源和合集同一套规则，命令前缀不同。  
> F0、C0、维护都指向本文，不各自再写一遍。

创建向导的 Step3 / Step4 从一开始就是管理，**不接续**。有版本后随时单独做。

---

## 1. 谁用哪条命令

| 能力 | 单资源 | 合集 |
|------|--------|------|
| listing | `update` | `collection update` |
| 加策略 | `policy template apply` | `collection policy template apply` |
| 策略开关 | `policy list` / `set --on\|--off` | `collection policy list` / `set --on\|--off` |
| 上架 / 下架 | `online` / `offline` | **同一对**（顶层，不按合集换命令） |

合集禁止用资源 `policy`。禁止 `update --status`。

门禁两边相同：必须是本人；冻结不写。`subjectType===4` 只用 `collection *`（上架除外）。

---

## 2. listing

标题 ≤100、简介 ≤200、标签 ≤20 个 × 每项 ≤20 字、封面 JPG/PNG/静态 GIF ≤5MB。  
维护时标识只读，不再 `create --name`。不传 `status`。

```
freelog-cli update --title --intro --cover --tags --yes
freelog-cli collection update --title --intro --cover --tags --yes
```

---

## 3. 策略

推荐：`policy template list` → `template apply <id>`（合集加 `collection` 前缀）。  
可跳过。无付费 / TransactionEvent。高级路径：`policy apply --from-file`。

Console 加完可能追问上架；CLI **不加完就 online**。

---

## 4. 上架 / 下架

`online` 预检：已有 `latestVersion`，且至少一条启用策略。缺了就失败，不打开 builder。  
下架对齐平台 `status:4`。先 `validate --for online`。

```
freelog-cli validate --for online
freelog-cli online --yes
freelog-cli offline --yes
```
