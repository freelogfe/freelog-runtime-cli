# 08 - 单工程、单资源与产物路径

本文件自 2026-09-08 起覆盖所有旧文档中“一个 `.freelog` 可保存多份 `N.json`”“用 `--file` 选择身份”“`index.json` 路径索引”的描述。

## 决定

一个工程目录只能管理一个单资源：

```text
<project>/
  .freelog/
    auth                 # 非秘密账号选择器
    1.json               # 唯一资源身份
    1.version.json       # 唯一未提交版本工作稿（存在时）
    .lock / .txn.json    # 瞬态可靠性文件
```

不再创建 `2.json`、`index.json`，也没有“在同一工程选择另一份资源”的能力。需要管理另一个资源时，创建另一个工程目录并使用该目录的 `--cwd`。

## 唯一路径参数：`--artifact`

`--artifact <path>` 是唯一的本地产物路径参数；所有命令中都表示当前资源的文件或构建目录，绝不表示身份选择器。

| 命令 | `--artifact` 行为 |
|---|---|
| `create` | 可选地记录默认产物路径，不上传；普通资源应给文件路径，主题/插件应给构建目录。 |
| `bind` | 可选地记录已有工程的默认产物路径；没有已记录路径的主题/插件必须给构建目录。 |
| `create-version` / `update-version` | 指定本次真实上传的产物；每次提交均从磁盘重新校验、上传、分析。成功后回写 `1.json.filePath`。未传时使用已记录路径，路径不存在则失败。 |
| `version set --artifact` | 只修改默认产物路径，不上传、不发版。 |

普通资源的产物必须是单个文件；`RT001` 主题和 `RT002` 插件的产物必须是非空构建目录。CLI 只在发版时将主题/插件目录内容临时压缩为 zip；用户不传 zip。

`--file` 从公开命令面删除；不保留兼容写法，避免脚本把“选择资源”和“发布文件”混为一谈。

## 状态与迁移

`1.json.filePath` 只是默认路径记录，不能当作文件仍存在或 SHA1 仍有效的证据。发版必须重新读取当前产物；缺失时要求 `--artifact`。

旧工程若发现 `2.json` 或 `index.json`，CLI 停止并提示迁移：每份旧身份分别放进独立工程目录后，再在对应目录执行 `bind <resourceId> --artifact <path>`。不自动猜测或删除旧状态。
