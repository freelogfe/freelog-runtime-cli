# 05 - 版本工作稿与独立命令

对照场景：[真实场景](../场景/真实场景/README.md) S2、S10–S14、S19–S20。实现：[场景实现](../场景/场景实现/README.md)。  
工作稿是 `.freelog/N.version.json`（形状见 [02](./02-本地状态.md)）。每一问只写在 [版本表单](../PHASE/单资源/版本表单/README.md)。

先前把「拉线上某一号进缓存」绑在 `update-version` 里，缓存没有自己的入口，不合理。本文把**工作稿管理**和**提交发版**拆开。

两条发行命令仍不合并。依赖只在工作稿里管（`version dep`）。没有顶层 `dep`。不解决上抛、不支付。

---

## 1. 四层，不要搅

```
看              线上 / 本地稿，不写盘
工作稿管理      拉某一号覆盖、丢掉稿          ← 不 POST
改缓存          属性 / 可选配置 / 依赖 / 描述  ← 不 POST
提交            create-version / update-version ← 才 POST
```

| 层 | 命令 | POST 版本？ |
|----|------|-------------|
| 看 | `version show` / `version show --local` | 否 |
| 工作稿管理 | `version draft pull` / `version draft discard` | 否 |
| 改缓存 | `version attr` / `option` / `dep` / `draft description`；或发行会话菜单 | 否（签约当场打平台，树只进稿） |
| 提交 | `create-version` / `update-version` | 是 |

首版没有上一号可拉：用 `create-version --prepare` 建空首版稿（上传/解析），**不要**跑 `version draft pull`。

---

## 2. 工作稿管理（先把缓存管好）

只写 / 删 `N.version.json`。不要新号、不要 `--bump`、不要 POST。

### 2.1 拉线上某一号盖进缓存

```
freelog-cli version draft pull
freelog-cli version draft pull --version 1.0.0
freelog-cli version draft pull --yes
freelog-cli version draft pull --version 1.0.0 --yes
```

| | |
|--|--|
| 未传 `--version` | 拉 **latest** |
| `--version <已发号>` | 必须在版本列表里。没有：「没有这个版本」，失败，不写盘 |
| 线上没有 `latestVersion` | 失败，「还没有发行版本，请先 create-version」 |

写入字段与 [更新版本 §1.2](../PHASE/单资源/更新版本/01-更新版本.md) 相同（`fromVersion` = 本次拉的那一号；`baseUpcastResources` 恒 `[]`）。怎么 GET 见更新版本 §1（列表拉全、`resourceVersionInfo1`）。

盖不盖：

| 盘上 | TTY | `--yes` |
|------|-----|---------|
| 没有稿 | 写入 | 写入 |
| 有稿，来源已是这一号 | 问：稿已来自 {号}，仍用线上覆盖并丢掉改动？**默认否** | **覆盖**（人明确要再拉一次） |
| 有稿，来源是另一号 / 没有 `fromVersion` | 问：用线上 {号} 覆盖本地工作稿？**默认否** | **覆盖** |

覆盖 = 整份按回显重写，不和旧稿混字段。取消则稿不动、退出 0。  
**盖之前必须先打将丢掉的摘要**（TTY 问之前打；`--yes` 也打，再盖）。不要逐项 diff：

```
将覆盖本地工作稿：
  来源：{fromVersion 或 首版}
  文件：{filename}  sha1={前8位}…
  自定义 n / 可选配置 n / 依赖 n / 描述：有|无
```

`--file`：一夹多条必须指定（只选份）。本命令不换文件、不上传。

这就是 S10 / S11 / S12：先拉 latest 或某号，可以盖掉本地稿，先不发行。

### 2.2 丢掉缓存

```
freelog-cli version draft discard
freelog-cli version draft discard --yes
```

TTY 确认后删 `N.version.json`。没有稿：打一句「没有工作稿」，退出 0。`--yes` 不确认。  
不拉线上。要丢掉再拉：`discard` 然后 `pull`，或 `update-version --reset`（见 §4，一次会话用）。

### 2.3 看缓存

`version show --local`：只读，不拉、不盖。  
`version show`：只读线上，不盖本地稿。

## 3. 改缓存

属性 / 可选配置 / 依赖都是下一版表单，挂 `version` 下。问法见版本表单。

| 命令 | 写工作稿 | |
|------|----------|--|
| `version attr add\|set\|rm\|list` | 自定义 / 系统附加 value | 附加须已有 `fileSha1`。自定义可一行式，见版本表单 |
| `version option add\|set\|rm\|list` | 可选配置 | 类型不允许则失败。可一行式 |
| `version dep add\|rm\|range\|list` | 先查已有授权，有则直接加；没有再当场免费签 | 只写稿 |
| `version draft description` | 工作稿描述 | 仅有 `fromVersion` 的更新稿。首版稿失败 |

门禁：须 login、有 `resourceId`、本人、未冻结。合集失败。

| 盘上 / 线上 | |
|-------------|--|
| 无稿，无 `latestVersion` | 可建空首版稿再改自定义/依赖。改附加：没有 `fileSha1` → 失败，先 `create-version --prepare` |
| 无稿，已有 `latestVersion` | **失败**，「请先 version draft pull」。不要空表改下一版 |
| 有首版稿，线上已有版本 | 残留。失败，去 `version draft pull`（会盖掉首版稿） |
| 有更新稿，线上没有版本 | 失败，去 `create-version` |
| 有对应工作稿 | 改这份，立刻写盘 |

`--file`：一夹多条必须指定。`--yes`：能自动的才自动（一条免费策略），不提交版本。

## 4. 提交（只有这两条 POST）

| 命令 | |
|------|--|
| `create-version` | 必须无 `latestVersion`。默认 = 准备 + 会话。`--prepare` 只建首版稿。`--yes` 提交。有 latest → **失败**，去 `update-version` |
| `update-version` | 必须有 `latestVersion`。**定新号 + 提交**。拉缓存优先用 §2.1。无稿时为了一次会话仍会按回显源拉一次（规则同 `draft pull` 写入）。`--yes` 只提交，必须带 `--version` 或带方向的 `--bump` |

一次会话（人懒得先 pull）：

```
update-version                          # 无稿则拉 latest，再菜单，再交
update-version --reuse-version 1.0.0    # 无稿则拉 1.0.0
```

分多次（缓存先管好）：

```
version draft pull
# 或 version draft pull --version 1.0.0
# 本地有稿要盖：再加 --yes
version attr add
version dep add someone/lib --range ^1.0.0
version show --local
update-version --yes --bump patch
```

`--reuse-version` **只出现在 `update-version`**：表示「这次提交认的底」。稿的 `fromVersion` 必须等于它（未传 = latest）。  
`--reset` **只出现在两条发行命令**：丢掉稿再走准备（首版空表 / 更新再拉）。等价于 `draft discard` + 准备。不要用 `version set --reuse-version`。

### `update-version --yes` 和稿

| 稿 | 行为 |
|----|------|
| 没有 | 按回显源拉一份再交（回显源 = `--reuse-version` 或 latest） |
| `fromVersion` **等于**回显源 | 用这份交 |
| `fromVersion` **不等于**回显源，或没有 `fromVersion` | **失败**，不重拉、不交。打印：本地稿来自 {x}，本次底是 {y}。请 `version draft pull [--version y] --yes` 覆盖后再交，或 `--reuse-version {x}` 按这份底交 |
| 人定的新号 ≤ **当时** latest | **失败**，提醒「线上已经是 {latest}，不能发 {新号}」。稿留下。不要默默 bump |

TTY 无 `--yes`：稿对不上时仍问「覆盖重拉 / 仍用这份」，**不要默默盖**。默认：**仍用这份**（人正在改的别丢）。要盖用 `version draft pull`。

这改掉旧规则：「`--yes` 对不上就放弃重拉再交」。那会在脚本里默默丢掉改动。

---

## 5. 和会话怎么共用

版本表单是每一问的真源。会话菜单和 `version attr` / `option` / `dep` 走同一套步骤。

提交前再核（文件、依赖、条数、新号 > latest）只写在发行版本 / 更新版本。失败必须**点名字段**（见那两篇），不要只回「校验失败」或只回平台 `msg`。

---

## 6. 不要再造

| 不要 | |
|------|--|
| `publish` / 顶层 `release` | 已禁止 |
| 顶层 `attr` / `option` / `dep` | 一律 `version *` |
| `version set --reuse-version` | 回显源只在 `update-version`；拉缓存是 `version draft pull --version` |
| 用 `version draft pull` 发首版 | 没有 latest，失败 |
| 用 `version dep` 改已发版树 | 无更新稿则失败 |
| 独立命令里 `--bump` / `--version`（除 `draft pull --version`） | 新号只在 `update-version` |
| 平台草稿 | 不对 `lookDraft` / `saveVersionsDraft` |
