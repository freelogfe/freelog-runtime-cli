# 参数化策略模板与策略追加

状态：**已实现；2026-09-20 dev 已验收单资源与合集的非交互主链**。本文件是单资源和合集添加授权策略的唯一真源；各主体页面只保留目标选择、策略列表和上下架门禁，不能复制参数化流程。真实 TTY 翻页/取消及 datetime 样本仍须在平台提供样本后补证，不能以本次非交互通过替代。

## 1. 结论

策略属于线上资源本体，不属于版本，也不属于本地工程状态：

- `.freelog/N.json` 不记录策略、模板、参数或未提交的策略草稿；`N.version.json` 也不记录它们。
- 模板结构、参数、默认值、下拉选项和编译类型均以**本次服务端响应**为准。模板变化后，旧本地缓存会造成错配，因此不缓存。
- 模板策略不读本地 JSON。以后若正式支持手写策略语言，才单独设计并读取用户明确给出的 DSL 文本文件；它不是模板参数文件，也不属于本期命令面。

```text
模板目录（服务端） → 选模板 → 整体说明标记参数 → 编辑参数
  → reCompile → 翻译预览 → 用户确认 → addPolicies → 读回核验
```

`policy template apply` 绝不再把所有默认参数静默提交。

---

## 2. 一个公共能力，两个主体适配器

单资源（`subjectType=1`）和合集（`subjectType=4`）都是 Resource；策略的读取、模板参数、编译、追加与启停都共用一套领域能力。唯一主体差异是**怎样解析和校验目标**：

| 事项 | 单资源适配器 | 合集适配器 | 公共能力 |
|---|---|---|---|
| 命令入口 | `policy …` | `collection policy …` | `PolicySubject` 后的全部流程 |
| 目标来源 | 已绑定的单资源 `N.json` / `--resource` | 已绑定或显式选择的合集 | 必须实时 `Resource.info` 校验本人、未冻结、主体类型、`resourceId`、`resourceTypeCode` |
| 模板筛选参数 | 当前固定 `{}`；本地仅保留 `compileType=normal` 的全部可用模板；未来按后端正式契约实现 | 当前固定 `{}`；本地仅保留 `compileType=collection` 的全部可用模板；未来按后端正式契约实现 | `Policy.policyTemplates` |
| 编译类型 | 模板返回的 `compileType` | 模板返回的 `compileType` | `Policy.policyReCompile` |
| 创建 / 启停 | `Resource.update` | **同样** `Resource.update` | `addPolicies` / `updatePolicies` |

`resourceTypeCodes4Presentable` 是节点/展品（presentable）分支，不是合集参数。当前 Console 合集侧栏在模板列表组件中遗漏了自身 `resourceTypeCode`；它传入空值后得到的列表不能作为 CLI 的目标契约。模板列表的当前请求体固定为 `{}`；服务端在**响应模板项**中以 `compileType` 标记单资源（`normal`）或合集（`collection`），CLI 必须在响应后去掉**不能在该主体编译**的另一类模板。这不是按免费/付费等运营标签筛选，适用主体的模板必须全部展示。未来若支持以 `resourceTypeCodes4Resource` 缩小范围，须在正式请求字段、组合规则和筛选语义确认后单独实现；当前 CLI **不得**预埋或透传任何筛选参数。

创建策略的 HTTP payload 也没有 subjectType 分支：

```ts
Resource.update({
  resourceId,
  addPolicies: [{
    policyName,
    policyText: encodeURIComponent(compiledPolicyText),
    status: 1,
  }],
});
```

`compileType` 必须原样采用所选模板返回的值；不得因目标是合集就擅自写死 `collection`，也不得因目标是单资源就写死 `normal`。

写入后必须重新读取策略，确认同名策略已存在且为启用状态。服务端可以规范化 DSL，`Resource.info` 也可能返回译文；因此读回正文不能与提交前的编译文本做字节级比较。编译、翻译和写接口共同承担正文语义校验。

## 3. 模板描述符：服务端的动态表单

`Policy.policyTemplates` 返回的每一项至少归一化为：模板 ID、标题、`policyReport`、`policyReportText`、`policyText`、`compileType`、`policyReportUiTemplate`。后者的每个字段含真实 `id`、`uiSectionType`、默认值和（对 select）`selectOptions`。当前 `POST /v2/translate/cg/translate-config/list4Client` 只接受 `resourceTypeCodes4Resource` / `resourceTypeCodes4Presentable`，没有 `page`、`pageSize`、`skip` 或 cursor；平台一次返回完整模板集，CLI 的分页只能在该次内存快照中完成。

CLI 将 `policyReport` 中同一 `${fieldId}` 的所有出现位置标为同一个参数编号；编号从 1 开始，按本次模板字段描述的顺序分配。例如：

```text
任何用户支付 [1: 9.90 元] 后，可获得 [2: 30] [3: 天] 的使用授权。

[1] 数字；默认 9.90
[2] 数字；默认 30
[3] 选项；年(year)、月(month)、天(day)；默认 day
```

编号只供人和命令行使用，实际请求仍发送服务端字段 `id`。字段重复出现只允许填写一次。未知 `uiSectionType` 是平台契约错误，必须失败；不能像旧 Console 一样把任何未知类型猜成日期时间。

每个 UI 字段必须在 `policyReport` 中可定位；同一字段描述冲突或字段顺序不确定时，报告平台契约错误，不创建“看不见、不能编辑”的用户参数。反向不强求：平台真实模板会包含没有 UI 字段的保留变量，它们由编译器自行处理，CLI 在人类说明中显示为“平台内置参数”，不编号、不要求 `--param`，也不输出原始变量名。

已知交互类型为：

| 类型 | TTY 输入 | 非交互值 | 本地校验 |
|---|---|---|---|
| `number` | 数字输入 | 十进制数字 | 有限数；当前 Console 已明确的相对时间 / 交易金额规则复用到公共校验器；其余业务范围由 `reCompile` 判定 |
| `select` | 显示标签，选择一项 | 服务端 option 的 `value`，不是展示 label | 必须属于本次 `selectOptions` |
| `datetime` | `YYYY-MM-DD HH:mm` | 同格式字符串 | 严格格式；时区语义以平台编译结果为准 |

字段 ID、类型和 select 选项（适用时）必须存在；`defaultValue` 不是必填契约。后台可能给出空值、`0`、失效 option 或已不符合当前数值约束的默认值，Console 会继续展示模板、但不允许直接进入下一步。CLI 同样保留模板：该参数在 JSON 中省略 `defaultValue` 并标为 `required: true`，TTY 显示“未填写”，只能在用户给出有效值后预览/创建。CLI 不从字段名或 DSL 猜测可选性。

## 4. 模板目录与分页选择

```text
policy template list
collection policy template list
```

一次命令先完成目标校验，再以 `{}` 拉取一次当前平台完整模板快照。CLI 必须保留服务端的快照顺序：该顺序可能承载平台的运营推荐，不能按标题、ID 或本地 locale 重排。分页、交互选择与 JSON 目录使用同一顺序；参数编号仍只按单个模板的字段描述顺序分配，二者互不影响。CLI 在**内存中的同一快照**固定每页 20 条：模板 ID、标题、简短译文/摘要、动态参数数量都要显示。

| 场景 | 行为 |
|---|---|
| TTY `template list` | 显示第 `n/N` 页；每条模板可直接选择，另有“上一页 / 下一页 / 退出”。选中即进入完整说明、参数编辑、预览、确认、创建和读回；切页、选择或取消都不重拉模板。 |
| 非 TTY `template list` | 只输出首页、总数和剩余数量，并提示在交互终端翻页；没有 `--page`、`--page-size` 或“默认下一条”。 |
| `template list --json` | 为脚本 / AI 输出一次请求得到的**完整可读**模板目录：每项有 ID、标题、说明、参数编号/类型/安全默认值/select 的 value 与 label、指纹；无安全默认值的参数显式 `required: true`。刻意不输出可编辑 DSL。机器模式不分页、不隐式续页，也不增加页码参数。 |
| `template apply <templateId>` | 精确 ID 的直达入口；主要供 AI / 脚本使用，也允许人在 `template list` 浏览后复制 ID 使用。非交互必须给精确 ID；不根据列表顺序替代。 |

`--json` 不是“把终端表格改成 JSON”，而是稳定的机器协议。成功时 stdout 必须只输出一个对象，首版结构固定如下；以后只能新增字段，不能改名、删字段或改变数组顺序：

```json
{
  "schemaVersion": 1,
  "subject": { "kind": "resource", "resourceId": "...", "typeCode": "..." },
  "templates": [
    {
      "id": "...",
      "title": "...",
      "report": "带 [1]、[2] 标记的完整可读说明",
      "summary": "...",
      "fingerprint": "...",
      "parameters": [
        {
          "slot": 1,
          "type": "number",
          "defaultValue": 30,
          "numberRule": { "min": 0.01, "precision": 2 },
          "options": [{ "value": "day", "label": "天" }]
        }
      ]
    }
  ]
}
```

`subject.kind` 为 `resource` 或 `collection`。`parameters` 中非 select 类型的 `options` 是空数组；select 的 `value` 才是 `--param` 可提交值；number 的 `numberRule` 给出 Console 同源的最小值与小数精度。JSON 不给出内部字段 ID、`compileType`、模板 DSL 或任何“可绕过 compile”的原文；编号、指纹与重新读取的模板共同构成唯一可提交边界。`template info <id> --json` 复用同一信封，但 `templates` 恰有一个元素。失败仍走 CLI 的统一结构化错误输出，且 stdout 不得混入提示文字。

空模板快照、未知 ID、无法归一化的模板或描述符不自洽时均失败且零写入。模板为空时只能提示稍后重试或使用 Console；不能回退到未定稿的本地文本策略。

`template list` 在 TTY 是“浏览并选择”的完整人工入口，不是只读表格：在任一页选择模板后，立即展示完整说明并进入编辑。人工完整路径是：`template list` → 分页选择 → 参数编辑 → 预览 → 创建。只想查看而不创建时，可在分页器选择“退出”，或使用 `template info <id>`。

脚本/AI 的完整路径是：`template list --json` 一次取得所有模板的可读说明和参数描述符 → 选择 ID 并填入该项的指纹 / 参数 → `template apply <templateId>`。需要人工复核单个模板、或以最新响应刷新一个已保存请求时，才运行 `template info <id>` / `template info <id> --json`。因此机器流程不用为每个模板逐条 `info`；普通非 TTY 列表也不承担批量枚举职责，只有明确的 `--json` 机器模式输出完整快照，既不引入分页参数，也不静默续页。

## 5. 人工交互：先看整体，再选要改的参数

```text
policy template apply <templateId>
collection policy template apply <templateId>
```

1. `template list` 在 TTY 的分页器中选中模板，或 `template apply <templateId>` 直接定位模板。后者未给 ID 立即失败并提示使用 `template list`；不存在第二个隐藏选择器。
2. 读取所选模板的完整可读说明，标出 `[1]`、`[2]` 等参数，展示默认值与字段表。
3. 模板标题只有在满足 2–20 字且不与当前主体已有名称重复时才可作为默认策略名；否则策略名为空并要求输入。用户可编辑，规则为 2–20 字且不得与当前主体已有名称重复。
4. 进入“编辑参数”菜单：可选择任意编号反复修改、恢复该项安全默认值、查看当前完整说明、继续预览或取消。没有安全默认值的参数恢复后仍是“未填写”，预览会提示先填写。参数只在进程内保存，取消或进程退出即丢弃。
5. 所有必填项有效后，重新读取当前模板快照并计算所选模板指纹。若与选择时的指纹不同，说明模板在编辑期间变化：不编译、不写入，展示变化并要求重新选择；相同才调用 `policyReCompile({_id, compileType, fillArgs})`。`fillArgs` 由编号映射成服务端字段 ID。
6. 用返回的正文调用 `policyTranslation`：与 Console 一致，先将正文中的 `\t`、`\r` 规整为空格，再以 UTF-8 Base64 作为翻译请求的 `policyText`；真正 `addPolicies` 的正文仍使用未编码的编译结果。展示最终可读译文、参数摘要和编译正文摘要，默认不展示完整 DSL；仅明确的诊断选项可展示。
7. TTY 在**编译与翻译之后**确认“创建并启用”。取消不写平台。创建成功后重读策略列表，并确认读回存在同名且为启用状态的策略；服务端可规范化 DSL，不能以正文逐字一致作为成功判据。

交易类模板在进入参数编辑前复用当前 Console 的结算账户检查。该检查只决定“能否创建收费策略”，不处理使用者支付；支付仍不属于 CLI。

## 6. 脚本与 AI：一条命令填齐所有参数

先运行只读命令取得当次模板说明和可复制的命令骨架：

```text
policy template info <templateId> [--json]
collection policy template info <templateId> [--json]
```

`info` 必须输出：完整标记说明、参数编号表、真实 option value、默认值、模板指纹，以及以下形式的骨架：

```powershell
freelog-cli policy template apply <templateId> `
  --template-fingerprint <fingerprint> `
  --name "策略名称" `
  --param "1=<value>" --param "2=<value>" --yes
```

`info --json` 输出一项与 `template list --json` 中相同的规范化描述符（包括有序字段 ID、编号、类型、默认值与 option value），供程序刷新或复核已选模板；格式化输出仍以人工阅读为主。机器目录与 `info` 都不得输出模板 DSL。无论哪种输出，后续 `apply` 都重新读取服务端模板，指纹负责阻止两次读取间的错配。

`--param <number>=<value>` 可重复。非交互模式必须：

- 给模板 ID、`--template-fingerprint`、`--name`、`--yes`；
- 为本次描述符的**每一个**参数恰好给一项 `--param`，即使值等于默认值；
- 不得给重复编号、未知编号或将 select label 当成 value。

模板编号不是稳定 API 名称：后台可以增删或重排字段。因此 `apply` 每次重新读取模板，并将最新规范化描述符计算为指纹；指纹至少覆盖模板 ID、`compileType`、完整 `policyReport` 和有序字段描述（字段 ID、类型、默认值、option value）。与 `--template-fingerprint` 不同立即失败，要求重新 `info`，绝不按新顺序套用旧编号。编号永远不会直接发给平台。

无动态参数的模板仍要求指纹和名称，但不要求 `--param`。

## 7. 追加、读回与异常边界

编译后的正文先和当前策略正文去重，再发送 `addPolicies`。若 TTY 在编译后发现名称或正文已重复，应回到策略名 / 参数编辑菜单，而不是仅报错结束；非交互立即以对应错误码失败。写入成功后必须读回，不能只以 HTTP 成功作为完成证据。

请求结果未知时，不自动重发。由于服务端可规范化正文、且同名策略可能在请求前已存在，单靠一次读回通常不能证明本次写入已完成；保留原始失败并明确“无法证明是否已创建”。本流程不为此写入策略缓存或额外本地 JSON。

策略开关仍共享 `updatePolicies:[{policyId,status}]`；已上架主体最后一条启用策略不可关闭。`online` 是另一条显式命令，添加策略后只提示下一步，绝不自动上架。

## 8. 实现边界与验收

领域层只实现一次：模板归一化、说明标记、编号映射、指纹、参数校验、编译/翻译预览、追加/读回核验和策略开关。命令层只注入 `PolicySubject` 适配器及命令前缀；不得复制单资源实现为 `collection/policy.ts` 的另一套业务。

最小验收矩阵：

| 项目 | 单资源 | 合集 |
|---|---|---|
| 无参数模板：预览、确认、读回 | 必测 | 必测 |
| number / select / datetime：修改、默认恢复、无效输入 | 必测 | 必测 |
| `template list`：首页 / 后续页选中模板后完成创建；退出、取消均零写入 | 必测 | 必测 |
| `template apply`：精确 ID 直达；缺少 ID 明确失败且只引导到 `template list` | 必测 | 必测 |
| `info` → 带指纹的重复 `--param` 非交互创建 | 必测 | 必测 |
| TTY 目录翻页、保留服务端快照顺序，以及 `template list --json` 全量可读目录 / `info --json` 单项描述符与稳定 JSON 信封 | 必测 | 必测 |
| 编辑期间模板变更、指纹变化、缺参、重复参、未知参、错误 option value | 必测 | 必测 |
| 编译失败、翻译失败、重复名称/正文、未知写入结果 | 必测 | 必测 |
| 模板请求 | 当前断言请求 `{}` | 同一规则，断言不使用 presentable 参数；后端未来正式发布主体/类型筛选契约后再新增测试 |

真实 dev 验收还须覆盖至少一个含金额/时长/选项的模板和一个含 datetime 的模板；没有样本时标 `BLOCKED`，不能用默认值或模拟结果宣布通过。

## 9. 实现复查与测试拓扑

测试不按“命令各跑一次”组织，而按一条策略从目标到读回的有向图组织；单资源和合集分别覆盖两端适配器，中间节点必须共用同一断言集：

```text
目标解析 / 登录 / 环境
  → 全量模板快照（服务端一次返回）
  → 描述符归一化 / 指纹 / 可读报告
  → 人工分页选择 或 JSON 发现 + 精确 ID
  → 参数输入与本地规则
  → 重读模板并验证指纹
  → reCompile → translation
  → 重读可写目标 / 去重
  → Resource.update(addPolicies)
  → 读回同名且启用
  → 策略启停 / 上下架门禁
```

| 测试节点 | 自动化必须覆盖 | dev 必须覆盖 |
|---|---|---|
| P1 目标 | 单资源绑定/选择器、合集 `subjectType=4`、未登录、跨环境、非本人、冻结读/写差异 | 两种本人目标各一次真实 `Resource.info` |
| P2 模板快照 | 请求严格为 `{}`、完整返回超过 20 条的本地分页、保持服务端顺序、空列表 | 记录总数和实际响应形状；不传未来筛选参数 |
| P3 描述符 | 无参数、number/select/datetime、字段/报告缺失、重复字段、未知 UI 类型、指纹变化 | 至少金额/时长/选项模板与 datetime 模板各一条；无样本标 `BLOCKED` |
| P4 人工入口 | 首/中/末页选择、上/下页、退出/取消零写入、名称默认/非法/重复、修改/恢复默认 | 用 node-pty 覆盖至少一次跨页选择和一次取消 |
| P5 脚本入口 | `list --json` 全量稳定信封、`info --json` 单项、缺 ID/指纹/名称/参数、重复/未知 slot、select label 拒绝 | 以真实 JSON 选择模板后精确 `apply <id>`；不泄露 DSL/内部 field id |
| P6 编译预览 | `compileType` 原样透传、数值精度/下限、datetime 格式、reCompile/translation 失败零写入、编辑期间模板变化 | 记录编译正文与译文摘要；事件 DSL 被后端拒绝则 `BLOCKED` |
| P7 创建恢复 | 重名/同正文、成功读回、写后同名或启用状态缺失、请求异常后保留原错 | 单资源与合集各创建一条可证明读回的策略；测试资源按计划保留或下架 |
| P8 启停边界 | 无效 ID、on/off 冲突、上架主体最后一条启用策略不能关闭、写后读回 | 两类主体各验证 on/off；上架正向仅在 P7 成功后执行 |
| P9 隔离/回归 | 不写 `N.json` / 工作稿、无 `policy apply --from-file` 命令、单资源/合集共享 template 核心 | 命令 `--help` 与发布包一致 |

执行顺序固定为：P1→P2→P3→P4/P5→P6→P7→P8→P9。任何前置节点失败，后继远端写入一律标 `BLOCKED`，不能绕过前置条件测试后续“成功”。
