# 07 - 环境（dev / test / prod）

CLI 打哪一套平台，由**这一次命令的环境**决定。tools-lib 用这个值拼 API 域名，不自己猜。

账号怎么登见 [01](./01-账号.md)。本文只锁：三个环境叫什么、域名、`--env` 怎么落到 tools-lib。

---

## 1. 三个环境

和 tools-lib 的 `EnvType` 对齐，只认这三个字：

| CLI `--env` | 也接受 | tools-lib `getEnv()` | API | Console |
|-------------|---------|----------------------|-----|---------|
| `prod` | `production` | `prod` | `https://api.freelog.cn` | `https://console.freelog.cn` |
| `test` | — | `test` | `https://api.testfreelog.com` | `https://console.testfreelog.com` |
| `dev` | `development` | `dev` | `https://api.devfreelog.com` | `https://console.devfreelog.com` |

域名后缀写死在 tools-lib `packages/tools-lib/src/utils/domain.ts`：

| `getEnv()` | 公网后缀 | `completeUrlByDomain('api')` |
|------------|----------|------------------------------|
| `prod` | `.freelog.cn` | `https://api.freelog.cn` |
| `test` | `.testfreelog.com` | `https://api.testfreelog.com` |
| `dev` | `.devfreelog.com` | `https://api.devfreelog.com` |

`static` / `image` 固定 `https://static.freelog.cn`、`https://image.freelog.cn`，不跟环境变。

其它字（`staging`、`local`）：失败，「环境只能是 prod、test 或 dev」。不要默默落到 test。

---

## 2. 这一次命令用哪个

优先级，从上到下只取**第一次**命中：

1. `--env <值>`（写操作共用旗；见 [COMMANDS](../COMMANDS.md)）
2. 环境变量 `FREELOG_ENV`（CI）
3. **默认 `prod`**

实现上**发布前先拦 prod**（算定是 prod 就失败，不要改成 test）。这是开发门禁，不是改默认。见 [开发 README](../../开发/README.md)。正式发布前再撤。

不要再发明 `--test` 当第三套入口（旧 CLI 有过；本期只认 `--env test`）。  
不要读旧工程里的「项目默认环境」来改本次命令。

`--env` 与凭据：命中的 `.freelog/auth` / `~/.freelog-auth` **里面的环境必须等于本次环境**。对不上：失败，「当前凭据是 {authEnv}，本次是 {env}。请 logout 再 login --env {env}」。坏文件不准回退另一份。见 [01 §2](./01-账号.md)。

换环境：`logout` 再 `login --env <新环境>`。一份凭据只绑一个环境。

`N.json.env`：**仅非 prod** 的 `create` / `bind` 才写。未写 = prod。prod 不要写出 `env` 字段。发版前若 `N.json.env` 有值，必须等于本次环境，否则失败（避免 dev 壳交到 prod）。

---

## 3. 怎么交给 tools-lib

CLI 只用 **Node 入口**：`@freelog/tools-lib/node`（或仓库里的 workspace 包名）。不要用 browser 入口。

进程启动时先装 Node 默认 adapter，再 `configurePlatform` **覆盖**环境和凭据。只做一次。

```
import { FUtil } from '@freelog/tools-lib/node';

FUtil.configurePlatform({
  getEnv: () => 本次环境,          // 必须是 'prod' | 'test' | 'dev'
  getAuthorization: () => token,   // 来自 .freelog/auth，不要密码
  getUserId: () => userId,
});
```

对照 tools-lib README 的 Node 示例：它用 `FREELOG_ENV` / `FREELOG_TOKEN`。CLI **不要**只靠这两份环境变量过日子——人走 `login`，token 在 auth 文件里。`getEnv` 必须返回 §2 算定的值，不要再读一遍 `process.env.FREELOG_ENV` 盖掉 `--env`。

| 适配器 | 谁给 | 说明 |
|--------|------|------|
| `getEnv` | CLI §2 | 三个字之一。CLI 内部若曾用 `production`，交给 tools-lib 前改成 `prod` |
| `getAuthorization` | 当前 auth | header；`withCredentials: false`（Node 默认） |
| `getUserId` | 当前 auth | 没有登录可以是 `-1`（只读、未 login 的命令） |
| `onAuthError` / `onApiError` | CLI | 收成 CliError，不要浏览器跳转 |

tools-lib 默认 Node adapter（未 configure 时）会读 `FREELOG_ENV`，且**空值会落到 `test`**。所以 CLI 必须覆盖 `getEnv`，否则省略 `--env` 会对到 test，和「默认 prod」相反。

拼 URL：业务代码走 `FServiceAPI.*`，不要自己写 `api.freelog.cn`。需要完整前缀时用 `FUtil.Format.completeUrlByDomain('api')`。

---

## 4. 浏览器入口（对照，CLI 不用）

`@freelog/tools-lib/browser` 从 `window.location.hostname` 推环境（`*.freelog.cn` → prod，`*.devfreelog.com` → dev，其余 → test）。Cookie 会话。CLI 没有 hostname，不能走这条。

---

## 5. 禁止

- 省略 `--env` 却打到 test / dev
- 凭据是 dev、`--env` 省略当 prod 还继续写（应对不上就失败）
- `getEnv` 返回 `production` / `development`（tools-lib 不认，会落到 test）
- 不 `configurePlatform` 就调 `FServiceAPI`（空 `FREELOG_ENV` → test）
- 自己维护一份和 `domain.ts` 不一致的域名表
- 一份 token 跨环境用
- prod 的 `N.json` 还写 `env: prod`
