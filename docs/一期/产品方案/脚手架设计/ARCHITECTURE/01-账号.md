# 01 - 账号与凭据

账号设计只解决三件事：**以谁的身份调用平台、秘密放在哪里、如何明确切换**。`session` / `studio` / `--session` 不是账号能力，本期主路径不使用它们。

`init` 不会代替用户登录；普通资源的类型解析需要登录态时，`init` 会说明原因并退出，绝不在命令中混入登录问答。

---

## 1. 用户可见命令

```text
freelog-cli login [--global] [--env prod|test|dev]
freelog-cli login --login-name <name> --password-stdin --yes [--global] [--env ...]
freelog-cli logout [--global] [--yes]
```

| 情景 | 行为 |
|------|------|
| TTY 执行 `login` | 依次询问登录名和隐藏密码；不回显、不把密码写入 shell 历史或日志 |
| CI / 非 TTY | 必须同时给 `--login-name`、`--password-stdin`、`--yes`；密码只从 stdin 读取一次 |
| `login`（默认） | 为当前工作区写入“使用哪个凭据”的选择器 |
| `login --global` | 修改机器默认凭据选择器，不碰工作区 |
| `logout` | 删除最近工作区选择器；没有工作区选择器时删除全局选择器 |
| `logout --global` | 只删除全局选择器 |

登录请求使用明确的连接/响应超时（默认 15 秒）和取消信号；超时、网络失败、认证失败都不得创建选择器。认证请求不自动重试，避免重复错误密码触发锁定；用户可以修正后显式重试。

切换账号或环境必须先 `logout` 再 `login`。目标选择器已经存在时 `login` 失败，提示精确的 `logout` 命令；不得静默覆盖、合并或把新账号套到旧环境。以后若需要“一条命令换号”，应另设显式的 `login --replace`，并要求 TTY 确认 / `--replace --yes`，不能复用普通 `login` 的语义。

---

## 2. 凭据与选择器分离

密码永不落盘。登录成功后只保存短期/可刷新的平台凭据；密码在请求完成后立即从内存清除。

### 2.1 秘密：只进操作系统凭据库

token、refresh token、到期时间等秘密只保存在操作系统凭据库（Windows Credential Manager、macOS Keychain、Linux Secret Service 的等价实现）中。CLI 使用稳定服务名和环境、用户 id 组成的凭据键；凭据库内容不可被工程文件或 Git 带走。

- 不得用写死在源码中的 AES key、自制加密文件、环境变量或可提交 JSON 作为秘密存储。
- 系统凭据库不可用、被拒绝或写入失败时，`login` 失败；不降级到明文或“可由源码推导的加密”。
- 读取到失效、损坏或被删除的凭据时，失败并提示重新 `login`；不得悄悄回退到另一账号或另一环境。
- 日志、`--json`、错误栈、遥测和测试夹具必须统一脱敏 `password`、`token`、`authorization`、cookie 和凭据库值。

本期不承担旧文件加密格式的兼容或迁移：含 token/cookie/`iv` 等旧字段的 `.freelog/auth` 或 `~/.freelog-auth` 一律不能被读取、解密或转换。用户须先显式执行 `logout` 清理目标选择器，再 `login`；CLI 只会在显式 logout 时删除该目标文件，绝不读取或打印其中的秘密。这避免在新产物中继续保留可推导密钥、旧密文格式或双状态逻辑。

### 2.2 非秘密选择器：决定本次用谁

选择器只保存 `schemaVersion`、`credentialKey`、`env`、`userId`、`username` 和创建时间；它不含 token、密码或可刷新秘密。路径如下：

| 层 | 路径 | 角色 | Git |
|------|------|------|------|
| 工作区 | 最近一份 `.freelog/auth` | 当前工程优先使用的凭据引用 | 忽略 |
| 全局 | 用户配置目录中的 `auth-default.json` | 没有工作区选择器时的机器默认引用 | 不提交 |

从 `--cwd`（否则当前目录）向上找最近的工作区选择器；命中后绝不再回退全局。选择器环境必须等于本次 `--env`，省略 `--env` = `prod`。环境不符、格式不合法、凭据库没有对应项都失败，并显示选择器路径及修复命令。

`logout` 只删除选择器，不调平台注销，不删 `.freelog/N*.json`。凭据库中不再被任何选择器引用的条目可在 logout 后删除；删除前只按 `credentialKey` 操作，不能按模糊用户名批量删除。`logout --all` 不在本期命令面。

## 3. 权限门禁与体验

| 命令 | 是否需要登录 | 原因 |
|------|--------------|------|
| `init theme` / `init widget`、`template list` | 否 | 类型与模板清单均为 CLI 固定契约 |
| 普通 `init` / `type search` / `type info` | 是 | 必须读取平台当前可用的资源类型并验证叶子有效性 |
| `create`、`create-version`、`update-version`、`online`、`update`、`bind` | 是 | 读取或写入当前账号资源 |
| 本地 `version set`、本地工作稿编辑 | 否（若不读平台） | 只改本地状态 |

业务命令在真正请求前解析一次凭据。凭据失效（401/403）时，停止当前动作、保留未提交工作稿、指向 `login`；不要自动弹密码框、不要换用全局账号、不要重试写操作。

资源类型查询是只读 GET，不创建资源；因此普通 `init` 可以读取类型服务，但仍不调用 `POST /v2/resources`。这消除了“init 不打平台”与“init 要选择最新类型”之间的歧义。

---

## 4. 与发行衔接

```text
login → init（可选）→ create → create-version → ...
logout → 只移除本机/工作区账号选择，不影响工程身份
```

写平台前必须验证当前登录账号是资源 owner。`init` 只建立本地工程；它选择的普通资源类型在 `create` 时仍需重新验证，防止类型在两步之间被停用或改成非叶子。

---

## 5. 禁止

- 浏览器 OAuth、在 `init` 内登录、把 `session` / `studio` 当作登录模式
- 密码进入参数、JSON、日志、调试输出、Git 或普通文件
- 固定加密 key、明文回退、坏工作区选择器回退到全局
- 一份选择器跨环境使用；认证失败后自动换号或自动重试写操作
- `logout` 删除工程身份、版本工作稿或未明确属于本次选择器的系统凭据
