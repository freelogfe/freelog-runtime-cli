# 06 - 属性、可选配置、依赖

对照 Console Step2 / M0：「先有文件，再准备属性 / 可选配置 / 依赖，齐了才能发行」。  
跟文件一起进 `createVersion`，不是 listing，也不是策略。

F0 首版、M0 下一版用**同一套菜单**，都在 `publish` 里，上传（或 inherit）**之后**才出现。已发版只改 value 见 [04](./04-单资源维护.md)。合集见 [05](./05-合集维护.md)。

不新造独立的 `property add`。上传之后 **`publish` 保持会话**：用户或 AI 可反复改属性 / 可选配置 / 依赖 / 描述，**只有选「提交」才 `createVersion`**。全程在本进程，**不写** `N.json`（见 [02](../ARCHITECTURE/02-本地状态.md)）。  
系统 `raw` 当次解析、展示、不可改。取消或中途退出即丢，下次重新解析、会话从头来。

---

## 1. 会话（F0 / M0 同一条）

```
读 N.json.filePath（或 --reuse-version）
  → SHA1；没有才上传
  → 按 sha1 + typeCode 解析系统属性
  → 进入会话（展示当前：系统属性 / 自定义 / 可选配置 / 依赖 / 描述）
       循环：选 1–7 改本进程数据，改完回到本列表
       「提交」：文件已有 + 依赖已授权（没有依赖则跳过）→ createVersion
       「取消」：丢弃本会话，不发行
```

没有文件（也没有 inherit）→ 不进会话、不发行。  
inherit：从**平台上一版**带上可复用的属性、依赖、描述，再进同一会话。  
`--yes`：不进会话，只交系统解析（M0 inherit 再带上一版）。要改属性 / 配置 / 依赖 / 描述必须进会话。

| 时机 | 做什么 | 不要 |
|------|--------|------|
| F0 / M0 的 `publish` | 上传后开会话，反复 1–7，提交才 `createVersion` | 没上传就开会话；没提交就当已发行 |
| 已发版 | `version show` / `version edit` 改 **value** | 在已发版上增删 key / 改依赖树 |
| 已发版补签 | `dep auth --policy-map`（仅免费） | 当成本流程的「添加依赖」 |
| 合集 | `collection publish` 可带同构字段 | 单资源 `publish`；合集不走本菜单 |

## 2. 会话里循环选

每次回到列表都展示当前快照（`raw` 空值不展示）。选完一项立刻回到列表，**不提交**。用户或 AI 同一套选项。

| # | 选项 | 谁可以动 |
|---|------|----------|
| 1 | 添加属性 | 只加**自定义**（最多 30；value 可空，≤100 字） |
| 2 | 删除或修改属性 | 自定义：可删可改。系统 `additional` 且有 `valueConfig`：只改 value，不能删 key。系统 `raw`：**不出现在可改列表** |
| 3 | 添加可选配置 | 仅类型 `isSupportOptionalConfig`；最多 30；`input`→`editableText`，`select`→`select`（默认第一项） |
| 4 | 删除或修改可选配置 | 同上；类型不允许则本项不出现 |
| 5 | 添加依赖 | 输入 `resourceId` 或 `username/name` → 查资源 → 选版本范围 → 签约。见 §4 |
| 6 | 管理依赖 | 删掉，或改版本范围。不改文件 |
| 7 | 编辑描述 | 本进程 `description`；可空。M0 inherit 可带上一版再改 |
| 提交 | 发行 | 文件已有 + 依赖已授权。首版 `1.0.0`，M0 用 `--version` |
| 取消 | 退出 | 不 `createVersion` |

类型不允许可选配置：3 / 4 不出现。会话里若仍带了可选配置描述符，提交失败。  
主路径视频可一次都不选 1–7，直接提交。

取消或杀进程不落盘。再跑 `publish`：SHA1 已在平台则跳过上传，重新开会话（M0 inherit 从平台上一版带）。

一夹多资源必须 `--file`。

## 3. 属性规则

| 种 | 从哪来 | 菜单 |
|----|--------|------|
| 系统 `raw` | 上传后解析 | 只读展示；不可改、不可删、不写 manifest |
| 系统附加 | 解析后 `additional` + `valueConfig` | 选项 2 只改本进程里的 value |
| 自定义 | 发行者加 | 选项 1 / 2，本进程；`readonlyText`；最多 30 |

不要把标题 / 简介 / 封面写进这里（那是 [共用管理](../ARCHITECTURE/05-共用管理.md)）。  
视频封面：当次 `publish` 可问；Console `createVersion` **当前不传**，CLI 以实现为准。不写 `N.json`。

## 4. 添加依赖（选项 5）

没有独立的 `dep add`。选 5 之后在本进程里走完：

```
输入 resourceId 或 username/name
  → GET 查资源（必须能定位到一条）
  → 选 versionRange（semver 可解析：*、^1.0.0、>=1.0.0）
  → 签约（自己的资源也要签）
  → 写入本进程依赖表
```

查不到、不是一条、付费 / 微前端 → 失败并提示，这条不加进去。CLI 只做免费签。上抛进 `baseUpcastResources`。`authExcludedItems` 有则不再带 `batchSignContracts`。

选项 6：对本进程已加入的依赖删除或改范围；改完若需重签，当场签。

没有 `dep add` / `dep remove` / `dep update`。已发版只看树、补签：`dep list --tree`、`dep auth`。合集加单品不走本节（`item add`，不签约）。

---

## 5. `createVersion` 带什么

齐了才调用。字段不另造：

- `fileSha1` / `filename` / `version` / `description`
- `inputAttrs`（系统附加 + runtime 等）
- `customPropertyDescriptors`（自定义 + 可选配置）
- `dependencies` / `baseUpcastResources` / `authExcludedItems`

合集是 `PUT catalogue`，不是 `createVersion`，属性 / 依赖字段同构，走 `collection publish`。
