# 02 - M0 发行新版本

已有普通资源再发一版。合集 `subjectType===4` **禁止**走本流程（合集改目录用 `collection publish`）。

不是 F0 接续：线上已有 `latestVersion` 才进这里。无版本仍走 [F0](./01-F0-单资源发行.md) 的 `publish`。  
不是维护：`version edit` 改已发版说明/属性、不换文件，见 [04-单资源维护](./04-单资源维护.md)。

须先有本地身份：本夹 `N.json` 已有 `resourceId`，或先 [bind](../ARCHITECTURE/04-bind.md)。

---

## 1. 两条发法

```
# 换文件
freelog-cli version set --file <path>
freelog-cli publish --version <semver> --yes

# 继承上一版文件（与 --file 互斥）
freelog-cli publish --reuse-version <已发版号> [--version <新semver>] [--bump] --yes
```

`version set --file` 只改这份 `N.json.filePath` 和 index。版本号跟 `publish --version`；说明在会话选项 7，不要写在 `version set` 上。  
`version bump` 现码会写盘；主路径用 `publish --version` / `--bump`。

与 F0 **同一条会话**，见 [06](./06-属性配置与依赖.md)：先有文件（新上传或 inherit），再循环改属性 / 配置 / 依赖 / 描述，提交才发行。  
inherit 从**平台上一版**带可复用字段。都不写 `N.json`。`--yes` 不进会话。

一夹多资源必须 `--file` 指到要发的那条，不猜测。

| Console | CLI |
|---------|-----|
| 路由 `:id` | 当前 `N.json.resourceId` |
| 版本 `semver.valid` 且 `> latest` | `publish --version` / `--bump` |
| 无草稿时 inherit 上一版文件 | `publish --reuse-version` |
| `createVersion.version = versionInput` | `publish` |
| 成功页，不进策略 | 策略走 [共用管理](../ARCHITECTURE/05-共用管理.md)，本流程不加 |

---

## 2. 规则

- 先 GET：不是本人、冻结、或 `subjectType===4` → 失败。
- 新版本号必须合法 semver，且严格大于 `latestVersion`。
- `--file` 与 `--reuse-version` 互斥。inherit **不**写在 `version set`。
- 上传同 [02-本地状态](../ARCHITECTURE/02-本地状态.md) §4：读 `filePath` → SHA1 → 没有才传 → **开会话** → 提交才 `createVersion`。
- 改依赖走会话 5 / 6。已发版补签是维护里的 `dep auth`，不是本流程。
- 成功后不接续、不加策略。

---

## 3. 禁止

- 合集走单资源 `publish` 当新版本
- `version set --reuse-version`
- 把 inherit 当成换文件的默认
- 无 `latestVersion` 还走 M0（那是 F0 接续）
