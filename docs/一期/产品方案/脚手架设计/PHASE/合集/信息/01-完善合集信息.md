# 完善合集信息：listing 与更新状态

状态：已实现，边界补强进行中；省略选择器规则已于2026-10-19经用户确认。本页规格不代表全部分支已验收。

本页只定义合集的全局展示信息与更新状态。它们是已有合集可独立、可重复执行的维护能力，也是首次发行教程中的建议步骤；不属于目录草稿，不创建合集版本，不提交 `updateCollection`，也不自动上架。

## 审阅重点

这一页处理“用户看到的合集资料”和“是否继续自动收录”，不处理表单、目录发布或上架。请先确认：改标题/封面/简介/标签不会发布；改收录规则不会上架；RSS 合集当前一律不在 CLI 中维护。

```text
collection update                # 标题 / 封面 / 简介 / 标签
collection collect-rules set     # 完结/连载与自动收录规则
collection publish               # 合并目录与合集表单
collection online                # 独立上架
```

## 1. 两种独立维护动作，绝不互相夹带

| 能力 | 接口 | 写入内容 | 是否发布/上架 |
|---|---|---|---|
| listing | `Resource.update`，`PUT /v2/resources/{id}` | `resourceTitle`、`coverImages`、`intro`、`tags` | 否；请求中不得携带 `status` |
| 更新状态与自动收录 | `Resource.setCollectRules`，`POST /v2/resources/catalogue/{id}/items/collectRules` | `serializeStatus`、`status`、`conditionType`、`filterConditions` | 否 |
| 目录/表单发布 | `Resource.updateCollection` | 目录 merge、属性、可选配置、直接依赖等 | [发布设计](../发布/01-发布合集变更与恢复.md) |
| 上架/下架 | `Resource.update` | `status:1` / `status:4` | [策略与上下架设计](../策略与上架/01-策略与上下架.md) |

Console 创建向导的最后一步顺序是 listing → 收录规则 → `status:1`。这是页面为“现在上架”按钮组织的流程，不是 listing 或收录规则本身的语义。CLI 不得因为用户改简介、标签或规则而顺带上架，也不能将 `status` 混入 `collection update`。

## 2. Listing：标题、封面、简介、标签

建议命令：

```text
freelog-cli collection update --resource <collection-id|loginName/name> \
  [--title <title>] [--cover <local-image>] [--intro <text>] [--tag <text> ... | --clear-tags | --edit-tags] [--yes] [--env <env>]
```

`--resource` 按[共同定位规则](../README.md#所有已有合集命令的共同定位规则)：恰一份本地合集时自动使用，其余情况TTY选择本人线上合集，非TTY要求显式指定；包括未bind合集，选择不自动bind。每次写入前重新读取并精确核验目标、当前账号、`subjectType=4`、环境和可写状态；本次后续步骤固定该ID。标题从不用于识别目标。

一次调用可合并提交多个 listing 字段，减少 Console 逐字段点击保存造成的中间状态；只发送用户显式给出的字段。没有修改项时拒绝执行。写成功后回读并按字段核对；如果本地存在同一合集的身份缓存，标题缓存仅在远端已确认后刷新，缓存写入失败不能重发远端 PUT。

“写成功”先要求 `Resource.update` 返回对象且数值 `ret===0`、`errCode===0`，再固定目标读回；读回相等不能替代本次写入的成功确认，即使用户要求的值原本就相同。请求异常、失败/缺失/字符串状态码或非对象信封均以固定受控 `COLLECTION_LISTING_WRITE_UNCONFIRMED` 停止，不进入成功读回、不刷新标题缓存、不透传原始 HTTP 诊断、不自动重发。提示先到 Console 核对线上资料；上传过的封面不承诺回滚。

### 2.1 标题

- `trim()` 后不能为空，最多 100 个字符；超长或空白在远端写入前失败。
- 标题是可变展示值且可以重复，不能作为 `--resource`、单品或规则的身份键。
- 提示沿用创建时的产品文案：标题会影响搜索曝光，建议包含品牌或内容主旨。

### 2.2 封面

封面可选；未传 `--cover` 不改变现有封面。当前产品不提供“清空封面”参数，`--cover ""` 必须失败而不是提交空数组。

上传前校验与现有单资源 CLI 保持一致：只接受 JPG/JPEG、PNG 或**静态** GIF，文件不超过 5 MiB，检验文件签名，上传到 `Storage.uploadImage` 后只将平台返回 URL 写入 `coverImages:[url]`。CLI 不接受任意远程 URL 作为绕过上传的封面来源。

上传结果只接受数值`ret:0/errCode:0`且`data.url`为非空字符串的正式响应（Console的FUploadCover实际契约），缺失/失败/别名字段不得继续PUT。GIF必须能解析出恰好一帧，零帧或不完整结构不当作静态图片。

Console 的 `FUploadCover` 会先打开裁剪窗口，支持自由尺寸、原图及 2:3、3:2、3:4、4:3、5:7、7:5、9:16、16:9 比例，并将裁剪结果编码为 JPEG 再上传。**CLI 当前没有裁剪或格式转换功能，只上传用户给出的原图。**

因此交互式上传在确认前必须固定提示：

> CLI 不提供封面裁剪，将上传原图。请先在本地确认构图、尺寸和展示效果；如需与 Console 裁剪结果一致，请先自行裁剪后再上传。

非交互或 `--yes` 仍输出该警告；`--yes` 只跳过确认，不能隐藏能力差异。后续若实现跨平台裁剪，必须作为独立设计，不能暗中改变现有 `--cover` 的上传结果。

执行顺序固定为：全部本地字段与封面文件校验 → 原图警告及包含目标的预览 → 确认 → 上传已校验的文件内容 → PUT → 固定目标读回。任何字段无效、取消或非TTY缺少`--yes`均不得上传。上传后PUT或读回失败不代表上传回滚，不自动重发。

### 2.3 简介

- `--intro` 使用 `trim()` 后的文本，最大 200 个字符；超长不发送请求。
- `--intro ""` 表示显式清空简介；未传参数表示保留原值。
- 简介是 listing，不是合集发布说明、目录单品说明或版本字段。

### 2.4 标签

- 可选，最多 20 个；单项最多 20 个字符；不得为空或重复。
- CLI 采用可重复 `--tag <text>`，而非逗号分隔字符串，避免把合法标签文本中的逗号误切开；展示时可去掉用户习惯输入的 `#` 前缀，最终写入原始标签文字。
- `--tag` 是完整新列表，直接校验和提交，不弹出标签编辑器；未提供标签参数时保留原标签。
- `--clear-tags` 用于显式清空；它与 `--tag`、`--edit-tags` 两两互斥，冲突在读取目标或远端写入前拒绝。
- `--edit-tags` 是用户2026-10-22确认的独立交互入口，要求真实TTY且未使用`--json`；`--yes`只跳过最终写确认，不能代替标签编辑。非TTY/JSON在读取目标或推荐列表前报`COLLECTION_TAGS_TTY_REQUIRED`，提示改用可重复`--tag`或`--clear-tags`。不改变无修改参数时报错的规则。

编辑流程：验证同一目标及全部显式字段/封面文件 → 以当前完整标签数组初始化 → `Resource.availableTags({resourceTypeCode:目标类型})`只读一次 → 显示当前选择，允许添加推荐/活动标签、逐个输入自定义标签、移除已选、完成或取消 → 最终完整预览/确认 → 至多一次PUT和固定ID读回。提示中的平台文字转义控制/格式字符；不改实际业务文字。所有编辑仅在内存，取消（包括Ctrl+C）、列表失败、输入校验失败或最终不确认均不上传封面、不PUT、不改本地身份/表单/intent。

本次编辑与前一命令的事务恢复须区分：合法普通命令仍先遵循[本地状态§2.1](../../../ARCHITECTURE/02-本地状态.md#21-一致性与恢复)，在锁内前滚已有可验证事务，然后才进入上述编辑；取消不回滚前一事务，也不在恢复后的身份/稿/intent上另做本次修改。坏JSON、校验和错误或当前字节冲突的旧事务在问句和平台请求前阻断并保留。能在根入口立即判定的标签参数冲突、非TTY或JSON误用则先拒绝，不能借错误调用触发恢复。此处“不改”不等于把以前已确认的事务恢复也撤销。

推荐接口核对Console的`FResourceLabelEditor`实际调用及Node tools-lib：成功响应须为数值`ret:0/errCode:0`、`data`数组，记录含非空`tagId`、`tagName`及`tagType:1|2`（推荐/活动），可选`tagNote`为字符串；失败/缺失/未知结构固定报`COLLECTION_TAGS_RESPONSE_INVALID`，不透传响应或异常、不自动重试。提交仍为字符串数组，不提交tagId或活动对象。已有标签必须是完整字符串数组，未知不能当空列表覆盖。

本页既有约束及Console标签组件实际代码要求最多20项/每项20字符；字段表当前没有标签条目，不冒称其已逐项覆盖。已选标签不重复提供；满20项时仍可移除/完成/取消，不再提供添加。平台推荐中不符合现行单项约束的条目不可选，固定提示存在不可用项，不截断或悄悄放宽；自定义输入每次只表示一个标签，逗号是合法文字，沿用去`#`及trim校验，错误可修正后继续。已有不合法标签必须先移除才能完成。未改变任何标签且没有其它字段时只读结束，不发空PUT；同时修改其它字段时不夹带未变标签。此交互不发布、不上架、不访问Console草稿API，也不写本地表单。

## 3. 更新状态与自动收录规则

“更新状态”不是资源上下架状态。它包含合集是否完结和是否自动收录满足条件的未来单资源，保存接口是 `setCollectRules`，与目录草稿和 `Resource.update({status})` 完全独立。

建议命令：

```text
freelog-cli collection collect-rules get --resource <collection-id|loginName/name> --env <env>
freelog-cli collection collect-rules set --resource <collection-id|loginName/name> \
  [--serialize completed|serial] [--auto off|all|any] [--rules <rules.json>] [--yes] [--env <env>]
```

`get` 直接读取当前远端规则。`set` 先读当前规则，并只改变显式传入的部分：

- `--serialize completed` 写 `serializeStatus:1`；`serial` 写 `0`。
- `--auto off` 写 `status:0`，保留远端已有条件作为停用规则，符合 Console 关闭自动收录时不清空条件的行为。
- `--auto all|any` 分别写 `conditionType:1|2` 且 `status:1`；必须同时给出非空 `--rules`，防止误把“自动收录全部资源”当作默认行为。
- `--rules` 是完整替换的 JSON 数组；未传时不得覆盖既有 `filterConditions`。

规则文件的稳定外部格式为：

```json
[
  { "field": "title", "operator": "INCLUDES", "value": "旅行" },
  { "field": "type", "operator": "EQUAL", "value": "RT003011" }
]
```

映射及写前校验如下：

| `field` | 平台 `key` | 可用操作 | 值校验 |
|---|---|---|---|
| `title` | `resourceTitle` | `INCLUDES`、`NOT_INCLUDES`、`STARTS_WITH`、`ENDS_WITH` | 非空，最多 100 字符 |
| `authIdentity` | `authIdentity` | `INCLUDES`、`NOT_INCLUDES`、`STARTS_WITH`、`ENDS_WITH` | 非空，最多 60 字符；不以标题代替授权标识 |
| `type` | `resourceTypeCode` | 仅 `EQUAL` | 必须是启用的最终叶子资源类型 code |

Console 实际保存时会将 `authIdentity` 的 `STARTS_WITH` 输入改写为 `<当前用户名>/<输入值>` 再交给接口；其他操作符直接提交输入值。CLI 必须与这一行为一致，并在写前从当前登录身份取得用户名；不能把标题代替授权标识，也不能为其他操作符擅自补前缀。该映射已由 Console 可执行代码确认，仍需 dev 实测确认服务端匹配结果。

规则写入成功后重新 `get` 并做结构化比较；未知结果时不重发 POST，而是提示用户重新读取核验。自动收录可能与手动单品目录修改并发，竞争、模式切换和发布边界见[自动收录与手动目录](../单品/02-自动收录与手动目录.md)；CLI 不假设自动收录立即进入已发布目录。

## 4. RSS 边界

RSS 当前暂时忽略，边界见 [RSS 来源接入与同步](../RSS/01-RSS来源接入与同步边界.md)。为避免误写，命令读取到已绑定 RSS 的合集时，所有本页写操作（包括标签）均失败；CLI 不显示 RSS 状态、不跳转浏览器，也不依据 Console 允许标签的行为推断自己可以写入。

## 5. 验收

1. 每个 listing 更新只调用一次 `Resource.update`，且 payload 不带 `status`、策略、目录或表单字段；成功后读回确认。
2. 标题 100、简介 200、标签 20 项/单项 20、封面格式和 5 MiB 边界均在上传或远端写入前校验。
3. 封面每次上传都可见“无裁剪、原图上传”的提示；CLI 不声称与 Console 裁剪输出一致。
4. `collect-rules set` 不会因只改完结状态而清空自动收录条件，也不会因开启自动收录且没有规则而扩大收录范围。
5. 信息维护不调用 `updateCollection`、不合并目录草稿、不创建策略、不发布、不上架。
6. 读取到 RSS 合集时，本页所有写入均被保护性拒绝。
7. 标签三入口互斥；仅`--edit-tags`会询问和读取推荐。覆盖推荐/活动/自定义与移除、满额、非法推荐、取消及无变化；坏信封/坏当前标签、非TTY/JSON在任何写入前拒绝；`--yes`不能替代选择，所有最终提交与读回均核完整数组。
