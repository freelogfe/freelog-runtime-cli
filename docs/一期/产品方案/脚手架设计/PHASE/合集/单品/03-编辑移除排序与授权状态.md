# 编辑、移除、排序与授权状态

状态：`rename`、`remove`、`move`、`sort` 与只读 `auth status` 已实现并有单元测试；`auth resolve` 仍等待 dev 请求契约验证。

本页补齐已有合集的手动目录管理。所有写入只作用于**服务端目录草稿**；只有 `collection publish` 才把它合并进已发布合集。命令使用 itemId 作为稳定对象，不允许用可变单品标题、来源标题或列表页序号代替。

## 审阅重点

这些命令都只改服务端目录草稿，并由后续 `collection publish` 决定是否发布。编辑前先确认合集处于手工目录模式；自动收录、RSS 或冻结状态下拒绝写入。授权状态目前只读展示，重新选择已有单品的授权需先完成 dev 请求契约验证。

```text
collection item list [--resource <collection>] [--search <text>]
collection item rename <item-id> --title <text> [--resource <collection>] [--yes]
collection item remove <item-id>... [--resource <collection>] [--yes]
collection item move <item-id> --before|--after <item-id> [--resource <collection>] [--yes]
collection item sort --by added|title|resource-updated --asc|--desc [--resource <collection>] [--yes]
collection item auth status <item-id>... [--resource <collection>]
```

不存在 `collection item discard-draft`。已确认的 Node 接口只支持针对指定 itemId 的删除，未提供“恢复整份草稿”为已发布目录的事务；逐项删除不能替代恢复，也不能作为自动收录切换的隐式副作用。

## 1. 所有目录写操作共享的门禁

每个写命令都重新读取目标合集、自动收录规则和目录草稿：目标必须由当前账号维护、为 `subjectType=4`、非冻结、非 RSS，且自动收录 `status=0`。自动收录开启时，所有本页写命令在发送目录请求前失败；关闭后再次读取确认才能继续。`list` 和 `auth status` 只读，不受该限制。

所有写成功后必须回读相应草稿页/全量摘要确认；网络不确定时不得自动重发。目录项并发变化时，目标 itemId 不再存在、顺序基线不同或读回不一致，均报告未知/冲突而非按标题寻找替代项。

四类写命令先以固定ID读取完整手工目录作为确认基线；确认后再次按该ID核验owner/主体/冻结/RSS/自动规则和完整目录。itemId、来源resourceId、单品标题或相对顺序有变化即报`COLLECTION_ITEM_CATALOGUE_CHANGED`并零写；不要求来源可变展示名/展示标题不变，不声称两次读取及后继写入为服务器原子事务。非法itemId（空、空白、逗号或控制/格式字符）在请求前拒绝，不以trim修正身份。

只接受四个写接口数值ret/errCode均0的成功信封，不从HTTP成功、空对象或已有目标值推出写入成功；data可为平台合法空值。写调用异常、失败/缺失信封、读回失败或结果不一致都受控报告`COLLECTION_ITEM_RESULT_UNKNOWN`，保持至多一次写，不输出原始异常/服务端msg。先重新list核对，不能自动重发。取消/缺yes或写前发现变化时没有目录写入。

`reorder` 写接口可以按新增时间、单品标题或来源资源更新时间重排；但当前目录草稿**列表**接口只接受 `createDate` 和 `sortId`，不能把前述两个写排序字段作为列表请求参数。CLI 在重排后统一按 `sortId` 升序分页读回，验证服务端已经把目标顺序固化为手工顺序；这是跨当前后端契约的唯一可靠读回方式。

## 2. 改标题与移除

`rename` 使用 `Resource.updateCollectionItemsInfo_Draft({resourceId,data:[{itemId,itemTitle}]})`。标题是合集内的展示字段：`trim()` 后不能为空；不作为资源身份，也不改变来源单资源标题。CLI 在实现时按 Console 当前控件和 dev 响应锁定精确长度限制；在该验证完成前不擅自从“合集标题 100”或“属性值 140”借用限制。成功后回读该 itemId 和 `itemTitle`。

`remove` 接受一个或多个明确 itemId，经 TTY 摘要/`--yes` 确认后调用 `Resource.deleteCollectionItems_Draft({resourceId,removeCollectionItemIds})`。它只从目录草稿移除单品，不删除来源资源、合同、策略或已发布目录；回读必须确认这些 itemId 不再位于草稿。多项部分失败必须逐项报告，不能把 HTTP 成功表述成全部移除。

rename读回除指定itemId标题外，其它目录身份、标题和完整顺序必须保持；remove去重按首次输入顺序，只允许请求项消失，其余itemId/来源/标题及相对顺序保持。若只移除部分请求项，以unknown退出并分别列出本轮观察已移除/仍存在的itemId；这些是读回事实，不保证无并发，不重试。其余目录额外丢失/增加同样unknown。sortId可由平台重新编号，不将这种编号变化误报为标题/来源变化。

## 3. 排序

`move` 先按 `sortId` 升序全量读取草稿的稳定手工顺序，移除待移动项后，将 before/after 语义换算为目标的一基位置 `targetSortId`，调用 `Resource.setCollectionItemsSortID_Draft({resourceId,data:{itemIds:[id],targetSortId}})`。目标和参照项相同、任一不存在、分页视图不足以建立全量顺序时失败；写后再次按 `sortId` 升序全量回读，必须确认两者的相对位置满足用户选择。

`sort` 是明确的“重新编号”操作，调用 `Resource.reorderCollectionItems_Draft`，只允许 Console 已使用的字段：`createDate`、`itemTitle`、`resourceUpdateDate`；排序方向直映射为 `1|-1`。它不是拖拽位置移动的别名。两个命令完成后均全量回读并显示当前顺序，以便 `collection publish` 的目录 diff 可复现。

move的预期为从完整基线移除待移动项，再紧邻插入参照项之前/之后所得的**完整itemId序列**；只在同侧但未紧邻、其它项相互重排、增加/丢项或标题/来源变化都不能算成功。sort回读完整集合必须与基线一一对应、标题/来源不变，sortId严格递增；实际字段排序由平台定义，CLI不假设中文collation或时间字段别名。安装包受控验收以独立固定样本证明六种请求映射及预期次序，不能把“列出了任意目录”当六排序已验证。

list/move/sort的终端结果为稳定四列itemId、来源resourceId、单品标题、来源授权标识；每个字段的控制/格式字符及行分隔符转义为Unicode文本，不允许平台展示字段伪造新行/列或终端指令。该转义只用于输出，不改变线上值或写payload。

## 4. 单品授权状态

`auth status` 用 `Resource.getCollectionItemsAuth_Draft({resourceId,itemIds})` 显示目录草稿的 `isAuth`，并同时显示该 item 的来源资源 ID 与稳定 itemId。`isAuth:false` 是状态，不允许 CLI 擅自删除单品或改写排除项。

来源与响应按如下规则核验（2026-10-20补强）：

1. itemId必须为非空字符串且不含空白、逗号或控制字符（含不可见格式控制符），不通过trim/数字转换寻找替代项；重复输入按首次出现顺序去重。空批次或无效输入在请求前拒绝。
2. 固定解析一次合集目标后，按[完整目录读取契约](./01-添加单品.md)读取该ID的目录草稿；每个请求itemId都必须存在，来源仅取同一条目的`mountResourceInfo.resourceId`。将输出的来源ID同样须非空且不含空白、逗号或控制字符，不能让异常ID伪造文本列或终端结构。任一项不存在或目录读取不完整时整批失败，不查询其它身份、不按标题匹配。
3. 与Console实际代码一致，以合集resourceId和逗号拼接的itemIds调用上述专用草稿授权接口；不是个人`Resource.batchAuth`，也不是合约查询/签约接口。真实dev成功信封为数值ret/errCode均0、data数组，条目为字符串itemId及布尔isAuth；接口不返回来源资源ID。
4. 只接受完整成功信封。返回itemId集合必须恰等于本次去重请求，拒绝缺项、重复、多余ID、非字符串ID及非布尔状态；false是合法结果，不能补true、补false或省略该行。响应可以乱序，输出按请求首次出现顺序排列。
5. 文本输出固定三列，以tab分隔：`itemId`、来源`resourceId`、`已授权|未授权`。全部核验后一次输出，不输出部分成功。只展示本轮两个读取接口的观察，不承诺它们为原子快照或授权永久有效。

命令不创建本地身份/表单/intent，不修改目录、策略、授权排除项或合同。冻结、RSS或自动收录只限制写入，不禁止本人只读查询；不因false而调用任何写接口。未知响应只报固定受控错误，不输出原始响应或服务端msg。

新增单品时的授权处理已在[添加单品](./01-添加单品.md)定义：合集是 licensee，CLI 仅核验已有有效上游合同并写真实 contractId 映射；缺合同提示到网页按当前合集身份处理后重试，不自动签约或支付。已有有效合同的待支付状态不阻断添加。对**已有**单品重新选择上游授权/排除项，平台当前通过 Console 的 `CollectionSignItems` 授权处理器完成；同级 tools-lib 暴露了 `updateCollectionItemAuthorization_Draft` 路由，但其写入 body 与已有排除映射的完整读回尚未由 dev 契约验证。

因此当前正式边界是：实现 `auth status`；只有在 dev 验证 `updateCollectionItemAuthorization_Draft` 的精确 body、contractId 映射及读回方式后，才设计并实现 `collection item auth resolve`。在此之前不得把 policyId 当 contractId、不得以空数组覆盖现有排除项、不得将浏览器微前端嵌入 CLI。未来 resolve 也不能默认恢复签约；应先核验已有合同事实，把实际 contractId 写入授权操作稿，缺合同继续引导网页处理。

## 5. 验收

1. rename/remove/move/sort 只改服务端目录草稿，随后 `collection publish` 才可见于已发布目录。
2. 所有定位都使用 itemId；标题、资源标题、当前页位置均不作写键。
3. 自动收录、RSS、冻结、无权和不确定网络结果都不会造成目录误写。
4. 没有未验证的“丢弃草稿”或单品授权 payload；支付边界与直接依赖、添加单品一致。
5. C03.A01：完整true/false结果按请求顺序带真实来源ID；重复输入仅查一次；C03.A02：失败/缺失信封、错类型、缺/重/多余ID整批拒绝；C03.A03：空/非法ID或目录中不存在的ID不会发送授权查询。
6. C03.A04：第二页来源ID也能正确关联，分页不完整则零授权查询；C03.A05：冻结/RSS/自动收录只读无写；C03.A06：实际命令输出三列，无失败残缺输出，本地身份/稿/intent及远端写调用不变。这些回归不替代固定候选或完整单品资格/上游合约矩阵。
