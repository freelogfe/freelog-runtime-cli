# 添加合集单品

状态：目录读取、添加与已有上游合同核验已实现并有单元测试；CLI 不签约或支付。

本功能把**当前环境、当前登录账号、已上架的线上单资源**加入某个合集的服务端目录草稿。它是独立的单品管理能力，不是创建合集的第二个强制步骤，也不从本地文件、`.freelog/N.json` 或快速发行清单推断单品。

## 审阅重点

先确认边界：用户选的是线上“我的已上架单资源”，不是本地文件；添加后只改变服务端目录草稿，不发布合集；单品的上游合同缺失时到网页处理，CLI 不代为签约或支付。后文所有校验和接口细节都服务于这三条。

```text
collection item add
  → 从线上本人资源库选择单资源
  → 重新校验候选资源与远端目录草稿
  → 如有上游，核验已有合集合同；缺失则停止并提示网页处理
  → 写入合集目录草稿
  → 回读并报告逐项结果
```

## 1. 用户得到什么，命令不做什么

### 1.1 输入与结果

- 单品最终以线上资源 ID 定位；可由完整授权标识实时解析取得，标题仅用于显示和初始单品标题，不能用于身份匹配。
- 来源必须属于当前登录账号、`subjectType=1`、处于上架状态，且有可用的最新版本。它可以不在当前工作区，也不要求曾被 CLI 绑定或发布。
- 每次添加直接写入目标合集的**服务端目录草稿**。它不是本地暂存，也不要求用户之后再运行一次“保存单品”。
- 同一个资源 ID 在同一合集目录草稿中只能出现一次；重复选择、其他命令已添加或服务端并发变更均不得产生重复项。
- 不允许通过本命令顺带创建、上传、发布或上架来源单资源。批量快速发行若存在，只是用户准备线上单品的独立前置能力，和本命令没有耦合。

### 1.2 本命令明确不做什么

`collection item add` 只管理目录草稿。它不得：

- 设置合集属性、可选配置、描述、封面、listing 或标题；
- 写入合集的直接依赖声明；
- 创建、选择或更新合集授权策略；
- 发布目录草稿、提交合集表单变更、上架或下架合集；
- 修改来源单资源的版本、属性、可选配置、文件或标题；
- 把远端目录完整复制进 `.freelog/` 作为第二份事实来源。

这些都是独立能力。首次发行教程可以提示它们尚未完成，但任何一个命令都可从已有合集单独运行并重复执行。

## 2. 命令与选择体验

建议命令域为：

```text
freelog-cli collection item add [id:<resource-id>|name:<loginName/name>]... [--resource <collection-id|loginName/name>] [--env <env>]
freelog-cli collection item list [--resource <collection-id|loginName/name>] [--env <env>]
```

`--resource` 只用于确定目标合集；省略时恰一份本地身份自动使用，否则TTY选择本人线上合集（包括未bind），非TTY要求明确选择。选择本身不bind。位置参数只描述**来源单资源**，避免把目标合集和来源资源混在同一个参数中。非交互或JSON调用必须明确至少一个来源单资源；缺少时`COLLECTION_ITEM_SOURCE_REQUIRED`且不发请求，`--yes`不代替选择。不接受标题作为来源参数。

无位置参数时进入资源库选择器：

1. 用 tools-lib 的 `Resource.list` 查询当前账号资源，固定 `isSelf:1`、`subjectType:1`，支持关键字及资源类型筛选；不读取本地文件列表。
2. 每页显示 50 项，支持上一页、下一页、搜索、筛选和多选；已选项跨页保留。分页是交互导航，不暴露必须记忆的 `--page` 参数。
3. 显示线上资源标题、完整授权标识、类型路径、最新版本和状态；不可选项必须说明原因（非上架、没有最新版本、已在目录草稿、或不属于当前账号）。
4. 一次提交最多选择 100 个候选项，与 Console 当前选择器的批量上限一致。超出时要求拆分为多次提交。

显式 `id:` 或 `name:` 适合脚本和 AI 操作，但只是定位线索；在写入前仍须执行第 3 节的实时校验。`name:` 必须是完整授权标识，不能使用可变且可重复的标题。

选择器每行以安全引用展示标题、完整标识、类型路径、最新版本与状态，控制符不成为终端指令。非本人、主体不符、未上架、无最新版本及完整目录草稿中已存在项不可选并说明原因；列表信封/分页/身份字段无效则整次选择安全失败，不把缺字段当可选。分页按50条和平台总数，当前筛选内短页、总数漂移或跨页重复ID均拒绝。上一页可使用本轮已读页；修改搜索/类型从第1页重新查询，保留已选ID，不能清空隐藏页选择。可单独查看/移除全部已选项，满100项后禁止新增但仍可取消、移除或完成。

缺来源的非TTY/JSON拒绝必须在完整CLI入口的通用锁/事务恢复之前发生：不能只在领域动作报错，却让全局preAction先创建状态目录、前滚事务或改变序号。显式来源的未决操作/事务门禁保持原样，不因新增选择器而放宽。

资源类型筛选沿Console实际调用：类型树取category1/status1/subjectType1；可按任意层级“全部本分类”或具体最终类型筛选。父分类传resourceType名称；叶子传resourceTypeCode及resourceTypeCategory2；清除则不传类型字段。不以类型筛选代替写前资格核验。只在进入类型筛选时读取树，不查询个人batchAuth，不在本地保存目录或选择结果。

显式“完成选择”至少有一项才进入添加；空选完成、取消、Ctrl+C或失败均零目录写。取消返回`COLLECTION_ITEM_SELECTION_CANCELLED`。选择阶段只读，返回精确目标ID和来源ID后，添加流程从头重新核验目标归属/状态/规则、完整目录、来源详情/上游与判重；不复用列表资格或旧目录绕过实时校验，也不会再次询问/绑定另一个目标合集。

## 3. 写入前的实时校验

资源库列表只是帮助选择，不能当作写入授权。提交时按下列顺序重新检查：

1. 解析目标合集：它必须存在、属于当前账号、主体为 `subjectType=4`，且可在当前环境被当前账号维护。
2. 对所选 ID 去重，并用线上详情/批量详情重新读取来源资源；任何查不到、非当前账号、非 `subjectType=1`、非上架或没有最新版本的项均不写入。
3. 通过 `Resource.resourceIsExistInItems_Draft({ resourceId: collectionId, resourceIds })` 重新检查远端目录草稿。已存在项从待写集合移除，并清楚报告“未变更（已在草稿）”。
4. 对剩余来源资源重新读取其 `baseUpcastResources`，检查该合集作为被授权方是否已经具有这些上游资源所需授权。不能以来源资源“属于我”或某次旧列表结果替代这一检查。
5. 缺少有效上游合同时停止并列出当前合集 ID 与缺失上游 ID，提示到网页处理后重试。已有有效合同不以支付完成或 `authStatus` 已变为正式授权作为目录写入门禁。部分候选失败不能掩盖其他候选的结果。

来源详情不是SDK“没抛错就成功”：只接受数值ret/errCode均0与对象data。显式ID须等于返回resourceId；完整name须等于返回resourceName，标题不能参与匹配。resourceId、完整resourceName及resourceTitle必须为字符串；userId必须为有效数值账号ID，不回退ownerId/creatorId；资源详情的subjectType是数值标量1，不把类型配置的subjectType数组当成详情DTO。status必须是数值，latestVersion必须为字符串；本人、status1且非空最新版本才可添加。坏信封/身份不匹配/字段类型异常为`COLLECTION_ITEM_SOURCE_RESPONSE_INVALID`，合法详情但归属/主体/上架/最新版本不合格维持`COLLECTION_ITEM_SOURCE_INVALID`。

每个来源的baseUpcastResources必须显式为数组，空数组才表示无上游；缺失、null、坏行或缺失/非法resourceId均不能被默认空数组或String转换吞掉。重复有效上游ID稳定去重。来源selector只接受合法ID或完整授权标识（可带id:/name:），空串、空前缀、控制符等在读取详情前拒绝；整批任一来源详情无效都在确认、合同查询和目录POST之前停止，不写本地身份或表单稿。服务端逐项失败的结果处理仍按§5，与这些写前拒绝分开。

实时判重具体为：全部来源详情有效后，对稳定去重的实际resourceId调用一次上述草稿checkExists（`resourceIds`逗号拼接）。只认数值ret/errCode均0、data数组及每行字符串resourceId/布尔isExists；必须精确覆盖请求集合，不接受额外、缺失、重复或强转布尔。坏响应/请求异常为`COLLECTION_ITEM_EXISTENCE_RESPONSE_INVALID`。全量目录仍按§5读取；checkExists和该次目录判重任一方向不一致即`COLLECTION_ITEM_CATALOGUE_CHANGED`，停止且不自动重读、重发或猜测归属，提示先重新查询。即使全已存在也须核验，之后才返回未变更。

一次显式添加最多100个去重后的实际来源ID（包括最后判定已存在的项），ID/name别名不重复计数。解析第101个实际来源即`COLLECTION_ITEM_LIMIT`，不再判重、查合同、确认或POST；不是分成多批自动写入。来源标题在确认中用引用和控制符转义展示，避免换行/ESC/C1/方向控制伪造结构；提交的itemTitle保持原始字符串，不为终端展示改线上标题。

## 4. 单品上游授权与合集直接依赖是两件事

单资源版本表单中的“依赖声明”与这里涉及的“单品上游授权”不可混用：

| 概念 | 作用对象 | 产生位置 | 关键身份 |
|---|---|---|---|
| 单品上游授权 | 被加入的线上单资源的 `baseUpcastResources` | 添加单品前 | 合集 `resourceId` 是被授权方（licensee） |
| 合集直接依赖声明 | 合集自身声明的依赖资源及版本范围 | 合集表单独立功能 | 合集自身提交/发布模型 |
| 单资源版本依赖声明 | 某个单资源版本声明的依赖 | 单资源创建或新版本表单 | 单资源版本创建模型 |

Console 实际流程会在添加单品前读取来源资源的 `baseUpcastResources`，再以合集 ID 调用 `Contract.batchContracts` 查询授权状态。乙方身份必须为合集 4，目标主体为单资源 1；仅有真实合同 ID、正确双方/类型且 `status===0` 的合同算已签，`authStatus=128` 不阻断。CLI 只复用其中已有合同的查询与映射，不复用签约交互，不改变单品目录字段。但**不能直接复用单资源 `dep add` 的提交接口或把其结果写进合集直接依赖**。

合同查询先核验完整成功信封：仅接受数值`ret===0`、`errCode===0`及`data`数组，再筛选上述精确双方/类型/有效状态并使用真实contractId。成功空数组表示没有已有合同；失败、缺失/字符串状态码、裸数组、`dataList/list`别名或非数组data属于不可读响应，返回受控`COLLECTION_CONTRACT_RESPONSE_INVALID`（调用方已有专用码时保留），不能当无合同或有效合同继续。SDK未抛异常不代表成功，尤其`ret!=0、errCode=0`仍须拒绝；拒绝发生在确认和目录写入之前，不签约、不支付、不改稿或排除项。直接依赖链继续不查询合同。

精确身份不做 `trim()`、大小写折叠或其它修复：`subjectId`、`licenseeId` 必须原样等于请求目标，`contractId` 只能原样用于映射。三个字段均须为非空字符串且不含空白、逗号或控制/格式控制字符；无效行不构成已有合同，不能修剪出一个“有效”ID。没有其它有效合同覆盖所需上游时，按缺合同分支停止，确认、目录POST及本地表单均不得变化；不恢复签约或支付。

2026-10-14 起本期 CLI 暂停签约与支付。单品上游仅查询已有有效合集合同，读回真实 contractId 后保持原映射规则；缺上游合同时列出当前合集 ID 与缺失目标，提示先到网页以该合集身份处理，再执行添加。缺失或响应异常时不写目录，不调用签约 API，不填造 contractId。删除 `collection item add --policy` 及其隐藏签约分支。直接依赖已通过独立无合约写入实验，不再要求合同；此单品映射链路未经同样的无映射实验，不能把两者混同。

`authExcludedItems` 不是可猜测字段：Console 授权处理器返回同时含 `policyID` 与 `contractID` 的对象，而平台字段标明 `excludedType:'contractId'` 时必须写入真实 `contractID`。CLI 只能使用授权流程已返回/已读回的 exact contractId；无法取得时停止该单品授权分支，不能用 policyId 冒充 contractId。详见[直接依赖与签约](../表单/02-直接依赖与签约.md)。

合集的**直接依赖声明**见[合集直接依赖与签约](../表单/02-直接依赖与签约.md)：它在发布时写 `updateCollection.dependencies`，不创建或检查直接依赖合同，不能塞进 `collection item add`。

## 5. 目录草稿写入与回读

当前 Console 的实际单品写入接口为 tools-lib 的 `Resource.addResourceItems_Draft`：

```text
POST /v2/resources/catalogues/drafts/{collectionId}/items
{
  addCollectionItems: [{ resourceId, itemTitle }],
  isPublish: 0
}
```

调用tools-lib时另传`resourceId:collectionId`作为路径参数，SDK会从请求体中取出它；不能把SDK入参对象误画成线上JSON body。

CLI 初版使用来源资源实时读取到的 `resourceTitle` 作为 `itemTitle`；这是单品在合集内的初始展示标题，而非来源资源的身份键。后续“修改单品标题”应是单品管理的单独命令，不能通过重新添加覆盖已有项。

服务端响应可同时包含 `addSuccessfulItems`、`addFailedItems` 与 `ignoreItems`。因此 HTTP 成功不等于全部添加成功：CLI 必须逐组展示成功、失败和未变更的资源 ID/完整授权标识及失败原因；`ignoreItems` 只报告未变更，不得表述为新增成功。写入后还要用 `Resource.getCollectionItems_Draft` 回读目录草稿，确认成功项实际存在；无法证明的项列为未知结果，并给出安全重试建议。

结果只接受数值`ret===0`、`errCode===0`与对象data中的三个数组；资源ID在组内/组间不得重复、无额外或遗漏，精确覆盖本次POST的来源ID。成功行含字符串itemTitle；失败行含字符串reason（空串标明未提供原因）；忽略行另含非空itemId及字符串itemTitle。不能用回读存在填补残缺分组。

完整回读中，成功/忽略来源必须各有且仅有一条，忽略itemId须精确对应；失败来源若存在则事实矛盾，不能改称成功。各组按请求顺序展示，写前已存在项合入未变更。有失败时命令退出1，`COLLECTION_ITEM_ADD_PARTIAL`的message包含各组及失败原因；`--json`仍只有单行`{code,message}`，不先输出成功文本。全成功/忽略退出0，保留既有成功摘要格式。

POST异常、无效分组或不完整/矛盾回读均为`COLLECTION_ITEM_RESULT_UNKNOWN`，不假定全部拒绝、不自动重发。固定安全提示引导先用`collection item list`及网页核实，再决定是否显式重试；不输出原始网络异常或整个响应。失败原因按数据转义终端控制符。本地身份及表单工作稿不因目录添加而修改。

目录草稿的服务端状态是事实来源。本地身份缓存只帮助定位目标合集，不保存一份可被误用为发布依据的单品快照；离线、认证或网络错误时不伪造本地成功结果。

目录列表、添加前判重与各写操作读回使用同一完整性规则：只认数值ret/errCode均0及`data:{skip,limit,totalItem,dataList}`，100条分页按总数读完；短的非末页、元数据漂移、重复itemId、缺失nested `mountResourceInfo.resourceId`、非字符串itemTitle或非数值sortId均安全失败。不能用顶层别名或强制String补身份，也不能把不足100条当作独立的完整证明。搜索/排序参数仍按用户意图传递，返回顺序不重排；resourceName/resourceTitle仅作可选展示，不参与身份和发布指纹。

## 6. 验收

1. 从无本地来源资源的工作区，也能从当前账号线上已上架单资源库添加单品。
2. 任何非本人、非单资源、未上架、无最新版本或已在目录草稿的来源都不会进入写请求，并有逐项结果。
3. 添加单品不调用合集表单、直接依赖、策略、发布或上架接口；目录变更可在之后独立发布。
4. 有上游授权缺口时，CLI 不猜测合同字段或静默绕过；仅核验已有有效合同 ID；缺失时提示网页处理，待支付状态不阻断。
5. 批量请求出现成功、失败、忽略混合结果时，输出和回读结果准确，重复运行安全。
6. 所有资源、合同与目录请求均由同级 `packages/tools-lib` 的 Node 兼容接口发起，不复制 Console 请求实现，也不直接调用 Axios。
