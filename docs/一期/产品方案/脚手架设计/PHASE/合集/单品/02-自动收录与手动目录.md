# 自动收录与手动目录：并发规则

状态：本轮定稿设计，尚未实现。

自动收录规则和手动目录都作用于同一个合集，但不是可以随意并发写的两种“方便入口”。目录草稿由服务端维护，自动规则可能在用户未运行 CLI 时改变候选/目录；因此 CLI 采用显式模式切换，而不尝试按标题或时间戳合并。

## 审阅重点

这不是两个可叠加的开关：自动收录开启时，CLI 不写手工目录草稿；要开启自动收录，先把已有手工目录草稿发布掉；关闭自动后才恢复手工操作。没有经过验证的“丢弃目录草稿”接口，因此不承诺一键回退。

## 1. 两种模式如何安全切换

| 模式 | 可执行的目录写操作 | 发布目录 | 规则写操作 |
|---|---|---|---|
| 手动（`status:0`） | add、remove、rename、reorder | 允许，需全量比较 | 可改为自动，但要先消除手动目录差异 |
| 自动（`status:1`） | 禁止 add/remove/rename/reorder | 不允许手工 merge | 可查看、修改/关闭规则 |

`serializeStatus`（完结/连载）与自动开关无关：完结不代表停止自动，连载也不代表自动收录。关闭自动时保留条件，符合 Console 的规则保存行为。

## 2. 模式切换

`collection collect-rules set --auto all|any --rules …` 在写前读取已发布目录和目录草稿。只要两者有任何差异，拒绝开启自动，要求用户先手工 `collection publish --include-items yes`。当前 tools-lib 没有已验证的“整体恢复目录草稿为已发布目录”接口，因此**不设计也不宣传** `collection item discard-draft`；不能为了切换自动模式而用逐项删除伪造恢复。这样自动规则不会吞掉一份用户尚未发布的手工目录。

`--auto off` 写后必须重新读取规则，确认 `status:0` 才解除手动命令门禁。它不自动把自动期间的目录变更“转化”为手工草稿；用户随后通过 `collection item list` 看服务端当前目录，再按需操作。

模式判断永远在每个目录写命令和 publish 前实时读取 `getCollectionCollectRules`；本地缓存、上一次命令输出和“我刚刚关闭了”都不能替代它。

## 3. 自动状态下的发布与管理

自动状态下允许只读 `collection item list`、listing 更新、策略管理和下架；但：

- `collection item add/remove/rename/reorder` 在发送任何目录请求前失败；
- `collection publish --include-items yes` 失败，防止把自动生成的目录草稿误当手工意图；
- `collection publish --include-items no` 仅可发布表单差异，且预览必须显示“目录未合并，自动收录开启”；
- `collection publish --include-items auto` 若检测到目录差异，安全失败并提示显式选择 `no`（只发表单）或先关闭自动；若无目录差异，可发表单。

这比 Console 仅靠页面状态更严格，是 CLI 的并发安全约束。待 dev 验证自动收录究竟在何时、以何种草稿/发布语义落库后，才能讨论更细的自动目录发布策略；在此之前不能做看似方便的盲合并。

## 4. RSS

RSS 合集不是自动收录合集的变体。本期不管理 RSS；检测到 RSS 时，规则与手动目录的所有写操作都拒绝，仅保留在合集信息设计中允许的标签维护。

## 5. 验收

1. 开启自动不会丢弃或暗中发布手工目录草稿。
2. 自动期间没有任何 CLI 目录写入或手工 merge 路径。
3. 关闭自动必须读回确认，之后才允许手动改目录。
4. 不把完结/连载、RSS、策略或上下架错误地当作自动收录开关。
