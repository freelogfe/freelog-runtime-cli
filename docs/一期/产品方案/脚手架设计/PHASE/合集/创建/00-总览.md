# 合集首次发行

状态：设计中，尚未实现。本文只固定流程边界；字段和交互细节写在各步骤正文。

合集是独立主体，不存在“首个版本号”。首次发行不是单资源的 `create → create-version` 变体：创建壳后，用户逐步整理线上单品和合集自身内容，最后发布目录变更并另行上架。

## 审阅重点

这里的 Step1～Step4 只是用户的学习路径，不是 CLI 必须一次跑完的事务。审阅时重点确认：创建壳以后，单品、资料、表单、策略、发布和上架都能独立重试；任何一步失败都不会替用户自动执行下一步。

Console 页面呈现的 Step1～Step4 是帮助用户理解首次发行次序的教程，**不是 CLI 的原子工作流**。CLI 的每一项能力都必须能从已有合集独立进入、失败后重试、完成后再次修改；命令只在成功后提示尚未完成的建议步骤，绝不自动串联。

```text
登录
  → Step1 collection create：选择合集类型、填写标题和授权标识，创建合集壳
      ├─ 单品管理：添加、查看、移除、排序线上本人已上架单资源
      ├─ 合集表单：属性、可选配置、描述、listing 与直接依赖
      ├─ 授权策略：单独管理
      ├─ 发布：单独提交目录与表单变更
      └─ 上架：单独操作
```

`collection create` 只能做 Step1。失败或用户取消时不进入下一步；成功后也不自动增加空单品、默认策略、表单、发布或上架。

当前可确定的首次发行闭环是：先创建壳；按需添加线上单品和维护 listing/收录规则；再完成合集表单、直接依赖和策略；随后显式发布目录与表单变更，最后再上架。上述是推荐检查顺序，不是命令强制顺序。合集身份、本地状态区分、`collection create`、`collection bind` 和手工目录的读取/添加/编辑/移除/移动/排序/授权状态已实现并有单元测试；listing、收录规则、表单、发布、策略和 dev 联调仍待实施，策略调用还受后端恢复约束。
