# 合集策略与上下架门禁

状态：设计定稿；实现与 dev 联调必须等待策略后端恢复后完成。等待不影响其余合集功能的设计和实现。

合集是 `subjectType=4` 的独立授权方。它的策略不是单品策略的集合，不能从单品复制，也不能用单资源 `compileType:normal` 编译后直接套用。

## 审阅重点

策略是合集自身的授权规则，单品策略不会自动继承。上架只检查“已有已发布快照 + 至少一条启用策略”，不会偷偷发布、创建策略或处理支付。策略服务未恢复时，这组命令保持不可用，不能伪造成功。

## 1. 用户能做什么

```text
collection policy list [--resource <collection>]
collection policy template list
collection policy apply --from <policy.txt>|--template <id> [--name <name>]
collection policy set <policy-id> --on|--off
collection online [--resource <collection>] [--yes]
collection offline [--resource <collection>] [--yes]
```

每个命令先实时确认目标由当前账号维护、主体为 `subjectType=4`；目标可以是线上已有合集，不要求当前目录存在或已 bind。本地标题绝不用于选择。`policy list` 返回该合集的全部策略（合集数量通常可控，不暴露分页参数）；`policy template list` 请求**全部**模板后在 CLI 内存中以既有每页 20 条交互式上一页/下一页展示，不强迫用户记页码，也不向当前后端传资源类型过滤条件。

## 2. 策略创建与启停

模板或文本在提交前用策略编译/翻译能力校验。模板必须使用平台模板返回的 `compileType`（可能为 `normal` 或 `collection`），CLI 不得擅自覆盖；用户提供原始文本时默认 `collection`，如平台翻译拒绝则原样报告而不降级为 normal。当前后端已确认模板列表必须请求全部，不能按合集叶子类型过滤。随后通过 `Resource.update({resourceId,addPolicies:[{policyName,policyText}]})` 创建；`policyText` 使用平台要求的 URI 编码形式，成功后重读策略列表，以返回的 policyId 作为后续稳定身份。

`collection policy set` 只发送 `updatePolicies:[{policyId,status:0|1}]`，成功后重读并确认。策略名称和文本去重检测只作本地提醒，最终以平台结果为准；非交互创建必须提供完整来源与名称，不能擅选“第一条模板”或“第一条可用策略”。

实际 Console 合集策略页把 `compileType='collection'` 传给**既有策略列表的展示/翻译组件**，并以 `trigger:'collection'` 创建策略；模板编辑器则使用模板自身的 `compileType`。两者不能混为“所有模板固定 collection”。当前策略 API 后端仍在修复，实施时不得伪造模板、编译或读回成功。

## 3. 上架、下架与门禁

`collection online` 是独立状态写入，严格按以下步骤：

1. 重读 `Resource.info(isLoadPolicyInfo:1,isLoadLatestVersionInfo:1)`；若已经上架则幂等成功。
2. 若没有已发布合集快照（Console 字段 `latestVersion` 为空），拒绝并指向 `collection publish`；不自动发布。
3. 若没有策略，拒绝并指向 `collection policy apply`；若策略均停用，拒绝并列出 policyId，指向 `collection policy set --on`。
4. 至少存在一条启用策略后，提示目标环境、完整授权标识和将开放的合集授权；确认后仅发送 `Resource.update({resourceId,status:1})`，再读回确认状态。

不会额外臆造“必须有单品”“必须免费”“必须无支付合同”等平台门禁；Console 实际上架逻辑只检查已发布合集和至少一条可用策略。已知直接依赖/单品授权问题会在各自的发布门禁中阻止不安全发布，但 online 不偷偷改合同、目录或策略。

`collection offline` 先重读目标，已下架幂等成功；否则确认后仅发送 `Resource.update({resourceId,status:4})` 并读回。它不删除策略、目录、表单、合同或本地身份。冻结/无权目标在任何状态写之前失败。

## 4. 验收

1. 合集模板列表请求全部模板；模板编译严格透传模板返回的 `compileType`，原始合集文本默认 collection；两种路径都保留真实平台读回。
2. 上架不会自动新增、启用策略或发布目录；用户必须明确完成每项。
3. 下架不破坏任何可恢复的合集数据。
4. 所有策略、状态请求只使用同级 `packages/tools-lib`，并以读回而不是 HTTP 成功码作为完成证据。
