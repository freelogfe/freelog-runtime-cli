# 合集表单：属性、可选配置、描述与目录展示

状态：本轮定稿设计，尚未实现。

合集没有文件和版本号，但有一份会随“发布合集变更”提交的**合集表单快照**。它包含系统属性、自定义属性、可选配置、描述、目录展示设置和直接依赖；listing（标题、封面、简介、标签）与收录规则仍按[合集信息](../信息/01-完善合集信息.md)独立维护，不能混入本表单。

## 审阅重点

本页的核心不是“把字段列全”，而是确认表单的生命周期：先从已发布快照或首次空基线建立本地操作草稿；编辑不写平台；只有发布时提交完整快照。类型能力决定能填写什么，listing 和目录单品永远不混进这份表单。

## 1. 表单从哪里来，何时真正发布

```text
collection form pull                         # 读取线上已发布快照
collection form edit --from collection.json  # 校验后写“待发布操作草稿”
collection form show                         # 只显示待发布结果，不写平台
collection display set …                     # 是 form edit 的便捷入口
collection publish                            # 唯一调用 updateCollection 的命令
```

`collection form edit` 不调用 `Resource.updateCollection`，不改变已发布合集，也不隐式合并单品目录草稿。它只在 `.freelog/` 的**短期操作草稿**中保存“本次待发布的完整表单快照、读取时的远端指纹、创建时间和请求摘要”；该草稿用于中断恢复，不是版本管理，不取代线上状态，更不写入不可变的 `N.json`。

读取基线必须来自同级 `packages/tools-lib`：`Resource.info`、当前类型详情、以及有已发布快照时的 `Resource.resourceVersionInfo1`。**`Resource.info` 本身不包含表单快照**，不能用它代替 `resourceVersionInfo1`。

CLI 与 Console 的版本草稿必须彻底隔离：CLI **绝不调用** `Resource.lookDraft`、`saveVersionsDraft` 或 `deleteResourceDraft`，不会读、导入、覆盖、比较或恢复浏览器端草稿；Console 同样不是 CLI 操作草稿的事实来源。两端唯一共同的可比较事实是已发布合集快照。CLI 保存的是该快照的 `publishedBaselineFingerprint`：发布前重新读取已发布快照，指纹已变化即安全失败，要求用户重新 `form pull` 后人工确认本次本地修改。这不是草稿兼容或字段合并，也不会触碰浏览器草稿。

- 已有已发布快照时，以该快照为基线；
- 新建且 `latestVersion` 为空时，建立**首次发布空基线**：当前类型可写系统属性的默认/空值、空属性/配置/依赖、空描述和六项 Console 默认展示设置。它不请求不存在的 `resourceVersionInfo1`，也不把“没有上一版”误判为错误；
- 本地编辑造成的“本地内容不同于已发布基线”是预期状态，**不是冲突**；只有发布/再次 pull 时已发布快照的指纹相对保存值改变，才停止。禁止字段级猜测合并；
- 无法识别的远端描述符、缺少类型配置或读取不完整时，拒绝写操作，宁可不发布也不能把未知字段删掉。

首次发布空基线也写入同一种短期操作草稿，因此 `collection dep add`、`display set` 和 `form edit` 都可在“刚建壳、未发布”状态完成，不需要先用 Console 发行一次。该草稿按 `subjectType=4 + resourceId + env` 定位；`N.json` 仍只保存不可变身份和可刷新的标题副本，绝不按标题或本地目录定位。

## 2. 稳定 JSON 协议

复杂表单必须用文件而不是堆叠几十个 CLI 参数。`collection form pull --out collection.form.json` 输出以下版本化协议；`form edit --from` 只接受完整对象，未知顶层字段报错而不是忽略。

```json
{
  "$schema": "freelog-cli.collection-form.v1",
  "inputs": [{ "key": "author", "value": "Freelog" }],
  "properties": [{ "key": "copyright", "name": "版权", "value": "CC BY", "description": "" }],
  "options": [
    { "key": "language", "name": "语言", "kind": "select", "values": ["zh", "en"], "description": "" },
    { "key": "theme", "name": "主题", "kind": "input", "value": "light", "description": "" }
  ],
  "description": "合集说明",
  "display": {
    "sort": "ascending",
    "title": "resource-title",
    "number": true,
    "image": true,
    "description": true,
    "view": "list"
  },
  "dependencies": [{ "resourceId": "…", "versionRange": "^1.0.0" }]
}
```

外部协议不暴露 Console 的枚举字符串；发布器唯一映射为：

| 协议 | `catalogueProperty` |
|---|---|
| `sort: ascending / descending` | `collection_sort_ascending / collection_sort_descending` |
| `title: resource-title / serial-number / custom / hidden` | `collection_item_title_rtitle / _sn / _custom / _empty` |
| `number/image/description: boolean` | 对应 `collection_item_*_display_show / _hide` |
| `view: list / card` | `collection_view_list / collection_view_card` |

`title:custom` 只选择平台现有“自定义标题”展示模式；单品的逐项标题由 `collection item rename` 管理，不能在 form JSON 中伪造一份单品清单。所有 display 字段在协议中必填，防止 JSON 局部更新意外重置其余展示设置。

现有 Node tools-lib 的 `UpdateCollectionParamsType.catalogueProperty` 只声明了其中四个展示字段，漏掉 `collection_sort_list` 与 `collection_item_title`。实现本设计前必须先把该本地类型同步为上述完整枚举并补请求断言；不能为了通过 TypeScript 而删掉这两个已被 Console 实际使用的设置。

## 3. 属性与可选配置

系统属性 `inputs` 的可写集合完全由当前**合集叶子类型**返回的类型配置决定；CLI 不把单资源或其他类型的字段搬进来。平台实际提交使用 `inputAttrs:[{key,value}]`。

自定义属性映射为 `readonlyText` 描述符；可选配置映射为 `editableText`（`kind:input`）或 `select`（`kind:select`）。可选配置只有类型的 `resourceConfig.supportOptionalConfig === 2` 时才可出现；不支持的类型携带非空 `options` 必须在本地拒绝，不能静默丢弃。

字段校验沿用可信的[字段级校验对照表](../../../../业务梳理/字段级校验对照表.md)，并同样适用于合集：属性/配置各最多 30 条；名称必填、最多 50 且在两类和系统字段之间全局不重复；key 满足 `^[a-zA-Z]([a-zA-Z0-9_]{1,29})?$`、最多 30 且全局不重复；说明最多 50；属性/文本配置值最多 140；下拉最多 30 个、每项最多 140、不得重复，首项就是默认值。不能修改已发布 key；改 key 表示显式删除旧字段并新增字段，预览必须显示此破坏性语义。

发布器必须构造完整 `customPropertyDescriptors`：

- 属性：`readonlyText + defaultValue:value`；
- 文本配置：`editableText + defaultValue:value`；
- 下拉配置：`select + candidateItems:values + defaultValue:values[0]`。

解析到 `radio`、`checkbox` 或未来未知 descriptor 类型时，当前协议不支持编辑；若它存在于远端基线，拒绝发布并报告原始类型，直到协议扩展且有回归测试。这样不会因 CLI “只认识三类”而删除线上配置。

## 4. 与其它命令的关系

- `collection update` 只写 listing，`collection collect-rules` 只写收录规则；二者都不读取或覆盖本地表单草稿。
- `collection item add/remove/rename/reorder` 只改服务端目录草稿；`form edit` 不读取、更不复制单品。
- `collection dep …` 只改本表单中的 `dependencies`，详见[直接依赖与签约](./02-直接依赖与签约.md)。
- `collection publish` 是唯一把本页内容、直接依赖和（可选）当前目录草稿合并为线上合集快照的命令，详见[发布合集变更](../发布/01-发布合集变更与恢复.md)。

RSS 合集当前暂时忽略。检测到 RSS 后，表单所有写操作拒绝；CLI 也不通过其它命令维护其标签或同步状态。

## 5. 验收

1. 修改表单不会调用平台发布接口，也不会影响目录、策略、listing、上下架。
2. CLI 不调用任何服务端版本草稿接口；任一并发的 Console 服务端草稿都不会被 CLI 读取、覆盖或删除。已发布快照变化或未知 descriptor 都会安全失败。
3. 可选配置的开关由合集类型的实时配置决定，而非“主题插件”或硬编码类型。
4. 发布 payload 的属性、配置、描述、展示设置和依赖均可从 JSON 完整复现；空数组与未传字段的含义明确。
5. 本地草稿只用于未完成操作恢复；`N.json` 仍只保留不可变身份和允许同步的标题。
