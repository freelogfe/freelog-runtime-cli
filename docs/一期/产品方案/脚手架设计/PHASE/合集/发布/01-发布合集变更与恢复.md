# 发布合集变更：完整快照、目录合并与恢复

状态：实现与验收补强中；2026-10-13取消直接依赖合约前置，2026-10-19恢复v2及显式收尾已补本地回归，尚未完成新候选真实中断验收。

合集发布不创建 `1.0.0` 或任何新版本。唯一发布动作是 `Resource.updateCollection`：提交合集表单完整快照，并按需把服务端目录草稿合并到已发布目录。

## 审阅重点

发布前确认完整表单基线、目录合并意图、精确授权排除映射与完整依赖声明。直接依赖无合约也可发布；其余必须掌握的事实读不全就不发请求。请求结果不确定时只读回，不重发。

```text
collection publish [--resource <collection>] [--include-items auto|yes|no] [--yes] [--env <env>]
```

`--include-items` 默认 `auto`：基于发布目录与目录草稿的完整比较决定；`yes/no` 只能缩小或确认用户意图，不能绕过冲突/授权检查。它不是“只发布本次命令增加的单品”。

## 1. 发布前必须掌握的完整事实

发布器必须在发送前顺序读取并锁定以下事实：

1. 目标合集详情（账号、主体、状态、RSS、`latestVersion`）；若 `latestVersion` 非空，再读取该号的 `resourceVersionInfo1`；
2. 已发布单品目录的**全量分页列表**；
3. 服务端目录草稿的**全量分页列表**；
4. 本地合集表单操作草稿；若没有本地草稿，则从已发布表单建立只读基线；尚无已发布快照的新合集以规范化空表单作为只读基线。这样纯目录发布不要求用户先做一次无意义的 `form pull`；
5. 当前类型配置，以及已发布快照/操作稿中的精确授权排除映射；不额外查询直接依赖合同或实时消费授权。

不得依据本地“曾经添加过单品”的标志、首屏列表、标题或时间戳猜测目录是否有变化。目录比较以接口可观察的itemId、`mountResourceInfo.resourceId`、itemTitle、sortId及列表顺序的规范化全量集合为准。GET目录并不返回可验证的单品authExcludedItems，不能补`[]`冒充已核验授权；授权排除映射另以已发布表单的正式字段核验，不以batchAuth布尔重建。无法取到任一页时拒绝发布。

目录读取只认数值ret/errCode均0及`data:{skip,limit,totalItem,dataList}`。固定请求100条，按totalItem读完；偏移/页大小不符、非数值总数、短的非末页、总数中途变化、重复itemId或条目身份/标题/排序类型错误均停止。不能以“本页不足100”独自证明完整，也不读取Console版本表单草稿。

目录操作是独立功能。若本地没有表单操作稿、但服务端目录草稿与已发布目录不同，`collection publish --include-items auto` 必须直接以本次读取的已发布表单和明确返回的授权排除映射作为不变基线，提交一次目录合并；不得要求用户为了目录发布做一次无意义的 `collection form pull`。若已有合集的排除映射未由平台明确返回，仍须拒绝，因为完整更新不能用空数组猜测或覆盖它。没有表单稿且目录也没有变化时应提示无需发布，不发送空更新请求。

表单快照采取“已发布完整基线（首次为规范化空基线）+ 本地已验证操作草稿”的结构化合成，不能把用户未编辑的字段省略为 `undefined`。最终 payload 必含：`inputAttrs`、完整 `customPropertyDescriptors`、`description`、完整 `catalogueProperty`、完整 `dependencies`、**已验证的授权排除快照**，以及 `isMergeCatalogueDraft:0|1`。只有比较确认目录草稿不同且用户允许合并时才写 `1`。

`authExcludedItems` 绝不能被默认写成 `[]`。新合集仅在本次授权流程已证明没有上抛/排除项时写空数组；已存在合集必须从同一份可读的授权操作草稿带入精确 contractId 映射。若 CLI 无法读取或重建该映射，发布以 `COLLECTION_AUTH_STATE_UNREADABLE` 停止，而不是清空线上授权选择。详情见[直接依赖与签约](../表单/02-直接依赖与签约.md)。

可读映射的每项必须是对象，`resourceId`、`excludedValue` 为非空且不含空白/控制/格式字符的原始标识，`excludedType` 只能是 `contractId` 或 `policyId`。不得trim或强转后认定有效；空数组是明确无排除项，坏行/缺字段不是空数组。有效非空映射的条目、次序、类型及标识原样保留；格式未知则发布拒绝，保留当前稿，不创建intent或发送PUT。

Console 会把 `updateCollection` 与 `isMergeCatalogueDraft` 放在同一提交中；CLI 必须保持这一原子边界，不能先发“表单发布”再单独 merge 目录，也不能把表单命令改成即时发布。

## 2. 提交门禁与交互

2026-10-13 dev 无合约实验确认：直接依赖声明可以独立提交。最终表单中的直接依赖不要求有效合约，不查询合约/授权、不签约、不付款；本地操作稿与纯目录发布沿用的线上表单一致。身份、类型、属性/配置、基线、目录并发、精确授权排除映射和 intent/读回门禁仍保留。声明成功不代表可以消费依赖，授权需要在网页另行处理。详见[直接依赖与签约](../表单/02-直接依赖与签约.md)。

提交前重新确认：合集仍属当前账号、`subjectType=4`、非 RSS、未冻结；类型仍允许当前可选配置；最终依赖条目的 ID 与范围非空、ID 不重复；目录读取完整；授权排除快照相对其基线未变且来源可验证。实时目标、已发布版本命中与循环检查由 `collection dep add/range` 执行，publish 不增加逐目标查询或授权门禁。标题、封面、标签、策略、在线状态不属于本接口，发布器不得夹带。

TTY 必须展示不可省略的预览：表单字段差异、依赖增删改、目录增加/移除/重命名/排序/授权差异、是否合并目录草稿、目标环境和合集完整授权标识。`--yes` 可以跳过确认，但不能跳过以上校验或简化 payload。

预览使用本轮预检已验证的同一份完整快照，不再请求或猜测其它数据：

- 系统附加值、自定义属性、可选配置分别按稳定key展示新增、删除和修改；修改展示完整旧值→新值，包括名称、说明、配置种类、全部候选值与默认首项。改key只能显示删除旧项＋新增项；字段顺序变化也明确展示。简介和六项展示设置逐字段展示差异，空串、false和删除不能省略。
- 直接依赖按resourceId展示新增、移除与范围修改，包含完整范围；顺序变化单列，不以数量相同代替无变化。
- 目录按itemId展示增加、移除、来源resourceId变化、重命名及sortId变化，并展示完整的旧、新itemId序列。标题或本地缓存不充当身份。`--include-items no`仍展示已观察到的目录草稿差异，但明确标为“本次不发布”，不能让人误以为已合并。
- 授权部分展示本次将原样保留的完整authExcludedItems映射，并明确“未查询实时消费授权”。本接口不修改映射，基线不一致已在预览前拒绝；目录响应没有可验证的逐单品授权字段，不得补造实时授权差异或额外调用batchAuth/合约接口。
- 用户可控字符串使用JSON转义，防止换行或终端控制字符伪装成预览标题；不截断差异、候选列表或目录序列。未变领域明确写“无变化”。

普通TTY由确认问句展示完整预览；TTY使用`--yes`时仍输出完整预览到stderr、不再提问。非TTY显式`--yes`保留原有无交互行为，不额外输出预览。取消或非TTY缺确认时不创建intent、不发送PUT，完整保留本地稿和目录。确认后的全量并发复核继续保留，不因预览完整而省略。

自动收录开启时，手工目录发布的并发规则见[自动收录与手动目录](../单品/02-自动收录与手动目录.md)：有自动收录时不能用 `--include-items yes` 盲合并。

## 3. 不确定结果绝不重发

2026-10-19用户确认：`collection publish resume`默认只读；新增显式`collection publish resume --apply --yes`收尾。`--yes`本身不申请清理。普通publish发现任何已有intent必须停止，不覆盖记录、不重发PUT；未决期间form pull不负责清理intent，也不能被当作重试许可。

上述只读约束包括完整CLI入口的全局preAction，不能在进入resume领域函数前通过通用写锁前滚本地事务。`--apply`缺`--yes`同样须在任何事务前滚之前拒绝；合法`--apply --yes`由恢复领域入口持项目锁并按既有规则处理本地事务。仅此精确命令路径走恢复入口自己的门禁，不取消普通publish或其它命令的通用未决操作保护。

远端写之前，记录独立v2 intent：immutable ID、完整标识、类型、环境、账号ID、已发布基线及目录摘要、完整预期表单/授权排除快照、是否merge、预期目录指纹、完整payload SHA-256、同次读盘的当前稿SHA-256（无稿为null）、发送时间和状态`prepared`；开始请求时更新为`sending`。记录更新须匹配本次原始字节，不认领或覆盖后来替换的记录。预检/确认期间当前稿有变化时停止，既不创建intent也不发PUT。身份与类型能力同样重新核验。

预期快照仅用于这一次中断核验，不作为版本历史。旧v1缺少环境/账号/完整预期，只能诊断为不可证明，不能推断成功或自动清理。坏JSON/字段/摘要错误同样保留并拒绝；不从当前稿补造旧请求。

回读判定顺序：

1. 重新精确读取本人同环境/同类型合集的最新表单（首次发布时读取新生成的首个快照）、已发布目录和目录草稿。版本接口也须成功信封及resourceId/version精确命中；缺失或错误字段不能默认为空表单；
2. 只有已发布完整表单、明确返回的授权排除映射及（要求merge时）已发布目录均与intent相等才是`confirmed`。当前目录草稿可已有之后的改动，不把它当作本次成功的预期。正常publish成功或显式resume apply时，仅当当前本地稿原始摘要仍等于发送快照才清该稿；改过、坏JSON、原来无稿但后来新建的稿完整保留并明确报告。最后清本次intent；清理中断仍留可恢复记录，不重发请求；
3. 若数值ret/errCode明确失败且完整旧表单、授权映射和发布目录未变，则持久记录rejected及数值错误码、只清本次intent，当前稿始终保留。该清理若失败，用户2026-10-19确认允许后续resume apply再次核验rejected记录与完整旧快照，只清记录、不清稿；诊断用rejected与成功confirmed区分，不宣称发行成功。不输出原始服务端msg或请求诊断；
4. 网络超时、进程中断、读回不完整，或读回既不等于旧基线也不等于intent时，标记`unknown`并停止，保留intent与稿。resume和apply都绝不重发；未确认的apply明确拒绝，不能因当前稿缺失、标题相同或日志有记录而放行。

tools-lib会将非零errCode的业务响应包装为异常。该SDK异常自身携带的完整数值ret/errCode失败信封，与直接返回的失败信封采用同一核验流程：仍须读回完整旧基线且未变，才能归为rejected；不能因SDK抛错一律当网络未知，也不能仅凭异常message、Axios/HTTP状态、单独errCode、cause或不完整result认定明确拒绝。读取只取异常自身的普通数据字段及两个安全整数，不执行getter、不输出原始诊断；没有完整失败信封则保持unknown。

远端成功而本地清理失败时，回读已经确认的发布不得再次PUT；用resume核对后显式apply收尾。CLI项目锁保护自身并发，摘要检查保护已观察的本地前态，不声称能原子隔离外部编辑器写入。

resume输出安全诊断对象：`schemaVersion:1`、resourceId、env、intentState、verification（confirmed/rejected/unconfirmed/legacy-unverifiable）、localDraft（unchanged/changed/absent）、applied；不展开原始intent/payload或异常。默认applied=false，显式apply成功为true（也包括已拒绝记录的收尾，不代表发布成功）；未确认或读取失败不能伪装applied。确认只证明当前线上结果与本次预期或已拒绝旧基线相同，不证明执行者或平台历史因果。

读取版本时，只有详情明确`latestVersion:""`才使用首次空基线，undefined/null/非字符串不是“未发布”。已发布版本必须含匹配resourceId/version、字符串description、数组systemPropertyDescriptors/customPropertyDescriptors/dependencies、对象catalogueProperty；系统附加值按insertMode=2的key/valueDisplay读取，不用写接口inputAttrs冒充读DTO。已知展示枚举出现未知值、下拉默认值不等于候选首项或属性字段类型错误时拒绝无损恢复，不静默补空/强转。平台派生计数等只读字段不发送；授权映射未明确返回仍不可confirmed。

## 4. 与本地状态的关系

`N.json` 的不可变resourceId/name/type/env保留不变；标题缓存只在listing写后同步。发布journal是可回收的事务记录，不是资源版本档案或线上状态替身。目录的唯一可发布事实是服务端草稿/已发布目录；本地为这一次中断核验暂存表单预期及目录摘要，不能把它当可编辑的第二份目录主本。

## 5. 验收

1. 发布仅调用一次 `Resource.updateCollection`，不会调用 `createVersion`，也不隐式上架。
2. 目录 merge 只在全量比较确认后发生；分页、并发或未知单品不会造成漏项发布。
3. 表单没有局部覆盖：未知远端字段、已发布快照基线变化和类型能力变化均安全失败；CLI 不读取或写入 Console 服务端草稿。
4. 请求不确定时绝不自动重发；恢复以回读的规范化完整快照判定。
5. listing、收录规则、策略、上下架和 RSS 均不被发布请求偷偷改变。
6. C07.P01：真实publish入口把完整表单/依赖/目录差异及原样授权映射交给确认；删除和新增不同key不合并为改名，false/空串/候选顺序精确展示。取消零PUT、零intent，稿字节不变。
7. C07.P02：include-items no标记草稿差异本次不发布；C07.P03：纯目录发布无需本地表单稿也预览正确；C07.P04：只改顺序能被展示，目录不按标题或可变资源展示字段误判；C07.P05：TTY yes只展示不问、非TTY yes不输出预览；C07.P06：多页目录全量预览且转义动态字符串。以上是本片回归义务，不替代固定候选真网/TTY验收或完整合集管理矩阵。

### C08：模式与确认期间的变化

以下细化已有§1/2的验收义务，不新增命令或业务行为。模式先按完整目录差异及自动收录状态判断，再判断是否有可发布内容：

| 自动收录 | 目录草稿不同 | auto（含省略参数） | yes | no |
|---|---|---|---|---|
| 关闭 | 否 | 不合并 | 拒绝：无需强制合并 | 不合并 |
| 关闭 | 是 | 合并 | 合并 | 不合并 |
| 开启 | 否 | 不合并 | 拒绝：自动收录开启 | 不合并 |
| 开启 | 是 | 拒绝：自动收录开启 | 拒绝：自动收录开启 | 不合并 |

没有本地表单稿且本次不合并时，提示无需发布、零PUT/intent；有表单稿可以仅发布表单，目录草稿完整保留。`no`不是忽略已发布目录变化的许可；只有未纳入本次请求的服务端目录草稿可以在确认期间继续变化而不被合并。

- C08.M01～M24：表中12个组合分别覆盖有/无本地表单稿；合法成功恰一次PUT、merge值正确，错误精确匹配且零PUT/intent，稿、身份和无关本地文件保持原字节。省略参数另与auto做等价正控。
- C08.C01～C12：确认期间自动规则、类型能力、已发布表单/依赖、授权排除、发布目录、纳入请求的目录草稿、本地稿、归属/完整标识/类型及冻结/RSS发生变化时停止；按具体门禁返回错误，不把后续读回失败当成预检拒绝。验证失败必须发生在intent及PUT之前，保留用户/其它客户端已作的变更。
- C08.W01：成功请求只含本接口的完整表单、精确授权排除与merge，不夹带标题/标签/策略/在线状态，不调用createVersion或上架。

上述域层用例只能证明受控竞态与模式门禁，不证明服务端原子比较交换，也不能替代安装包、真实并发客户端或完整管理矩阵验收。
