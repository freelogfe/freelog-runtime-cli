# 合集维护：更新日志与授权合约（只读）

状态：设计定稿，尚未实现。

这两个功能用于解释“合集已经发生了什么”和“谁正在使用合集授权”，都不能改变合集、目录、表单、依赖、策略或上下架。它们应当作为合集发行后管理的基础只读能力，而不是混进 `collection publish` 的恢复判断。

## 1. 命令边界

```text
freelog-cli collection log list [--resource <collection>]
  [--limit <1..100>] [--order asc|desc] [--all]

freelog-cli collection contract list [--resource <collection>]
  [--status active|terminated|abnormal] [--search <text>]
  [--limit <1..100>] [--order asc|desc] [--all]

freelog-cli collection contract show <contract-id>
```

- `log list` 只调用 `Resource.getCollectionUpdateLogs({ resourceId, skip, limit, sortType })`。
- `contract list` 表示“本合集作为授权方”的授权合约：只调用 `Contract.contracts({ identityType:1, licensorId:collectionId, subjectType:1, ... })`。它不是“合集引用上游单品/直接依赖时作为被授权方签下的合同”，后者由单品授权状态和直接依赖命令分别处理。
- `contract show` 只调用 `Contract.contractDetails`；若以后需要流转记录，另设只读子命令，不能在列表时 N+1 请求。
- `--all` 必须有交互确认或非交互 `--yes`，且有上限/流式输出保护；默认按 100 条一页显示并提供下一页选择。读取错误、分页格式不完整或目标校验失败时不输出“完整列表”。

## 2. 共同门禁与输出

每次操作先重新解析并读取目标：当前账号必须是合集所有者，`subjectType=4`，环境与当前登录态一致。冻结、RSS、未发布不会阻止这两个**只读**命令；但响应必须如实展示状态，不能把“无数据”解释成“可以发布/上架”。

稳定 ID 是唯一可用于详情或分页续读的标识：日志用服务端返回的日志 ID（若接口未返回则仅显示时间和不可复制的序号），合同使用 `contractId`。标题、资源名、策略名、时间都只是显示字段。

`log list` 至少显示：时间、操作类型、操作者（若服务端返回）、影响对象与服务端描述；未知枚举保留原值并标记“未识别”，不丢弃记录。日志不能证明一次发布已完整成功，也不能作为未知写入恢复的依据；恢复仍必须读取已发布快照和目录。

`contract list` 至少显示：合同 ID、被授权方、标的资源/策略、合同状态、授权状态、创建/更新时间。`authStatus:128` 必须显示为“待浏览器支付/未获得授权”，不能显示成已授权；签约成功也不等于支付成功。

## 3. 拓扑位置与验收

```text
collection publish ──> 已发布合集 ──> collection log list
                                     └─> collection contract list/show
```

两条边都是观察边，不是控制边：它们不能作为 `online`、`offline`、`publish`、目录写入或签约写入的前置或后置动作。

验收标准：

1. 所有请求仅使用同仓 `packages/tools-lib`，不复用 Console 页面状态。
2. 空列表、分页、未知状态、合同详情不存在/无权、网络中断均有明确只读结果；没有任何写请求。
3. 合同角色固定为合集作为授权方；与合集作为被授权方的单品/直接依赖合同不会混在一个列表中。
4. 测试对应功能拓扑文档 T-50、T-51，并在 dev 用空、至少一条正常、至少一条待支付或异常样本验证响应形状。
