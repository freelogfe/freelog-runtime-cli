# 合集维护：更新日志与授权合约（只读）

状态：已有命令入口，2026-10-20补强响应、分页、输出与归属门禁；固定候选真实验收未齐，不称全部分支完成。

这两个功能用于解释“合集已经发生了什么”和“谁正在使用合集授权”，都不能改变合集、目录、表单、依赖、策略或上下架。它们应当作为合集发行后管理的基础只读能力，而不是混进 `collection publish` 的恢复判断。

## 1. 命令边界

```text
freelog-cli collection log list [--resource <collection>]
  [--limit <1..100>] [--order asc|desc] [--all]

freelog-cli collection contract list [--resource <collection>]
  [--status active|terminated|abnormal] [--search <text>]
  [--limit <1..100>] [--order asc|desc] [--all]

freelog-cli collection contract show <contract-id>
```

- `log list` 只调用 `Resource.getCollectionUpdateLogs({ resourceId, skip, limit, sortType })`。
- `contract list` 表示“本合集作为授权方”的授权合约：只调用 `Contract.contracts({ identityType:1, licensorId:collectionId, subjectType:1, ... })`。它不是“合集引用上游单品/直接依赖时作为被授权方签下的合同”，后者由单品授权状态和直接依赖命令分别处理。
- `contract show` 先以固定合集ID的授权方合同列表有界核验contractId，再调用一次`Contract.contractDetails`；列表不N+1请求详情。归属查找不等于批量导出，不暗用`--all`或再解析一次可变selector。
- `--all` 必须有交互确认（默认否）或明确`--yes`，最多100页且不超过10000条；超过时拒绝完整导出，不截断冒充全量。默认100条一页，普通TTY提供下一页/结束；`--yes`不自动翻页。JSON和非TTY默认仅一页，不发交互问句；读取全部使用`--all --yes`。没有新增分页参数。

所有分页只认数值ret/errCode均0及`data:{skip,limit,totalItem,dataList}`；skip/limit须命中请求、totalItem须非负安全整数并跨页不变，页长必须等于本页剩余条数与limit的较小值。裸数组、别名列表、数字字符串、失败信封、坏行、短页、错偏移或总数漂移都拒绝，不过滤坏行再声称完整。每次下一页前可结束；出错不自动重试。`--all`先核验目标并确认再读首个数据页；上限按首屏总数预检，不能靠手改limit绕过页数上限。

每个日志必须属于本次resourceId、包含字符串createDate和完整operations/operationItems结构；未知字符串operationType保留并标未识别，不丢记录。实际日志没有稳定logId且resourceVersionId可重复，不能把版本ID当日志ID或按它去重；只用真实logId（若有）或不可复制的页内序号展示。未提供logId可用非ID序号；一旦提供则必须是非空字符串且不含空白、逗号或控制/格式字符，非法值须拒绝整页，不能静默降级成“无ID”或输出成日志标识。合法logId重复仍拒绝，不过滤坏行。

合同列表条目必须有稳定contractId、licensorId与subjectId均为本合集、subjectType为1，policyId及被授权方身份可读，状态为整数；跨页重复contractId拒绝。详情须成功信封且contractId、licensorId、subjectId、subjectType精确匹配；失败/错归属或扫描达到上限时停止，不把未完整查找说成“不存在”。列表与详情只显示已验证原始对象，JSON不添加虚构状态。

## 2. 共同门禁与输出

每次操作先重新解析并读取目标：当前账号必须是合集所有者，`subjectType=4`，环境与当前登录态一致。冻结、RSS、未发布不会阻止这两个**只读**命令；但响应必须如实展示状态，不能把“无数据”解释成“可以发布/上架”。

稳定 ID 是唯一可用于详情或分页续读的标识：日志用服务端返回的日志 ID（若接口未返回则仅显示时间和不可复制的序号），合同使用 `contractId`。标题、资源名、策略名、时间都只是显示字段。

`log list` 至少显示：时间、操作类型、操作者（若服务端返回）、影响对象与服务端描述；未知枚举保留原值并标记“未识别”，不丢弃记录。日志不能证明一次发布已完整成功，也不能作为未知写入恢复的依据；恢复仍必须读取已发布快照和目录。

`contract list` 至少显示：合同 ID、被授权方、标的资源/策略、合同状态、授权状态、创建/更新时间。`authStatus:128` 必须显示“未获得授权（如需支付请在浏览器处理）”，不能显示成已授权，也不能断言每个128都只缺付款；签约成功不等于支付成功。1为正式、2为测试、3按Console实际映射显示正式（含测试）；未知整数原样标未识别。

普通文本分字段展示，动态字符串转义终端控制字符；缺失的可选展示信息标“平台未提供”，不从来源作者猜测操作者，不从状态猜政策内容。`--json`保留完整已验证对象/数组，不混入提示或翻页文本。TTY已展示的前页遇后页失败时明确报错，不宣称完整；JSON及`--all`在全部核验后一次输出，失败不输出残缺成功列表。

## 3. 拓扑位置与验收

```text
collection publish ──> 已发布合集 ──> collection log list
                                     └─> collection contract list/show
```

两条边都是观察边，不是控制边：它们不能作为 `online`、`offline`、`publish`、目录写入或签约写入的前置或后置动作。

验收标准：

1. 所有请求仅使用同仓 `packages/tools-lib`，不复用 Console 页面状态。
2. 空列表、分页、未知状态、合同详情不存在/无权、网络中断均有明确只读结果；没有任何写请求。
3. 合同角色固定为合集作为授权方；与合集作为被授权方的单品/直接依赖合同不会混在一个列表中。
4. 测试对应功能拓扑文档 T-50、T-51，并在 dev 用空、至少一条正常、至少一条待支付或异常样本验证响应形状。
5. C11.R01～R08分别覆盖成功信封/精确分页与坏行、输入枚举边界、all确认与两种上限、TTY下一页/结束、合同归属与详情精确命中、普通文本及128/未知枚举、JSON无交互和无残缺输出、零写入/冻结RSS可读。本地装置不是固定包或真实待支付样本。
