# 01 - F0 单资源发行

Console 四步向导；CLI 多条命令。只有「已 create、还没有版本」接续 `publish`。  
一夹多视频：每条仍是本流程，`--file` 对应 `N.json`。见 [本地状态](../ARCHITECTURE/02-本地状态.md)。

策略 / listing / 上架见 [共用管理](../ARCHITECTURE/05-共用管理.md)，不接续。  
Step2：`publish` 先上传，再**保持会话**改属性 / 配置 / 依赖 / 描述，选提交才发行。见 [06](./06-属性配置与依赖.md)。再发一版见 [M0](./02-M0-发行新版本.md)。

```
freelog-cli login
freelog-cli init <dir> --scaffold runtime|package|none ...   # 可省，见 03-init
freelog-cli create --title "..." [--type] [--name] [--file] --yes
freelog-cli publish                                         # 上传后开会话；反复 1–7，提交才发行（1.0.0）
freelog-cli policy template apply <templateId> --yes        # 可跳过
freelog-cli update --cover --intro --tags --yes
freelog-cli online --yes
```

`publish --yes` 不进会话，只交系统解析结果。没上传、依赖未授权、没提交，都不发行。会话不写 `N.json`。

| Console | CLI |
|---------|-----|
| Step1 创建授权条目 | `create`（body 字段 `name`） |
| Step2 先上传再改属性/配置/依赖/描述，提交才发行 | `publish`（文件 = `N.json.filePath`；会话见 06） |
| Step3 策略 | `policy template apply`（管理） |
| Step4 listing + `status:1` | `update` 与 `online` 拆开（管理） |

已有平台资源：`bind [--file]`，不要再 `create`。同名已存在须改 `name`。自己的壳、无版本则接续 `publish`。  
`create` 打出 `resourceId` 和 `username/name`，加合集用这两样。

| 项 | 规则 |
|----|------|
| 类型 | 平台叶子 code；`init` 已定稿可省 |
| 标题 | 非空，≤100 |
| 短标识 | 1–60，非法字符转下划线 |
| 首版文件 | 仅本地 `--file` |
| `--yes` 缺字段 | 失败，不猜测 |

禁止：`update --status`；把 `init` 当 `create`；付费策略；一条命令走完四步。
