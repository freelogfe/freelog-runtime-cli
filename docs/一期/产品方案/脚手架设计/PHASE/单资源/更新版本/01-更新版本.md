# 更新版本

对照业务：[P0-M0](../../../业务梳理/创建流程%20-%20发行新版本/P0-M0-发行新版本.md)。Console 文案「更新版本」/「新建版本」。  
**必须已有 `latestVersion`。** 工作稿是 `.freelog/N.version.json`。拉 / 盖 / 丢缓存见 [05 §2](../../../ARCHITECTURE/05-版本工作稿与独立命令.md)（`version draft pull` / `discard`），**不要**把「先拉某一号」只藏在本命令里。  
本命令管：**定新号 + 提交**。没有稿时为了一次会话仍会按回显源拉一次（写入规则同 `draft pull`）。有稿则改这份。改完 `POST` 新号。

不是 [发行版本](../创建/02-Step2-发行版本.md)。那边命令是 `create-version`，没有上一版，空表起步，号写死 `1.0.0`。  
不是 [版本信息](../管理/01-版本信息.md)。那边只看已发号、只改描述（`version description`），不发新号。

命令是 **`update-version`**。平台仍是 `POST /v2/resources/{id}/versions`（新号）。和 `create-version` 不是同一条 CLI，不要共用入口、不要自动改口。跑了 `create-version` 且已有版本：失败，让人改跑本文。

```
# 推荐：先管缓存，再交
freelog-cli version draft pull
freelog-cli version draft pull --version 1.0.0
freelog-cli version draft pull --yes                    # 有稿也盖
freelog-cli update-version --yes --bump patch

# 一次会话：无稿则拉 latest，再问新号
freelog-cli update-version

# 这次提交认的底是 1.0.0（稿的 fromVersion 必须也是 1.0.0）
freelog-cli update-version --reuse-version 1.0.0 --version 1.1.0

# 换文件
freelog-cli update-version --file <path> --version 1.1.0

# 丢掉稿再按回显源拉（一次会话）。分步请用 version draft discard + pull
freelog-cli update-version --reset --version 1.1.0
```

`--reuse-version` = **这次提交认的底**（默认 latest）。稿的 `fromVersion` 对不上 → TTY 问；`--yes` **失败**（去 `version draft pull` 或改 `--reuse-version`），不要默默重拉再交。  
`--file` = 先选份；路径不同才换文件。可与 `--reuse-version` 一起用。  
`--reset`：丢掉再拉。`version set --reuse-version` **不存在**。  
`--bump` **必须带方向**。不要默默 patch。

须已 `login`，已有 `resourceId`。本人、未冻结。回显结果、文件 sha1、之后每一项改动都写 `N.version.json`。不做平台草稿。不写 `N.json`。不用 `publish`。只做本地上传。

`--yes`：不进会话。没有稿：按回显源拉再交。有稿且 `fromVersion` 等于回显源：用这份交。对不上：**失败**，稿不动。新号 ≤ 当时 latest：**失败**，「线上已经是 {latest}，不能发 {新号}」，稿留下。缺新号、缺文件仍失败。一夹多条必须 `--file`。`--yes --bump` 必须带方向。`--version` 与 `--bump` 不能一起用。

看缓存：`version show --local`。看线上：`version show`（不写工作稿）。拉/盖缓存：`version draft pull`。

属性 / 可选配置 / 依赖的每一问见 [版本表单](../版本表单/README.md)。本文只写：碰到盘上有没有稿怎么办、定新号、提交。拉 / 盖缓存见 05。

| # | 功能 | 怎么进 |
|---|------|--------|
| 0 | 门禁：必须已有版本 | 没有 `latestVersion` → 失败，去发行版本 |
| 1 | 工作稿 | 已有则用；没有则按回显源拉（同 `version draft pull`）。要盖已有稿：先 `version draft pull --yes` |
| 2 | 新版本号 | `--version` / `--bump` / TTY |
| 3 | 定文件 | `--file` 先选份；路径不同才换；同路径且本地不在则复用 sha1 |
| 4 | SHA1 / 上传 | 换文件才上传；复用回显文件不上传 |
| 5 | 会话：改的是盘上这份缓存 | 菜单 1–6 进版本表单；**有**菜单 7 描述 |
| 6 | 提交新号 | 读工作稿 `POST createVersion`。不接续 Step3 |

```
0 门禁（必须已有 latestVersion）
  → 1 工作稿：没有则拉；有则 TTY 续用或问。`--yes` 对不上失败（不默默重拉）
  → 2 新版本号
  → 3 文件（未传 --file / 只选份且本地不在：复用 sha1；换路径或本地在：按磁盘）
  → 4 SHA1 / 上传 / 解析（续用先 fileIsExist）
  → 5 会话（读盘上的工作稿，改一项写一项）
  → 6 POST createVersion（新号，体来自工作稿）→ 成功清空工作稿
```

成功后**不加策略、不接续 Step3**。成功必须删掉工作稿。

## 0. 进入

`Resource.info`（`GET /v2/resources/{id}`，`isLoadLatestVersionInfo=1`）。

| `subjectType===4` | 失败（合集暂缓） |
| 非本人、冻结 | 失败 |
| 一夹多条未 `--file` | 列出各份 `filePath`，要求指定 |
| `--file` 对不上（多份且路径不在任何 `N.json`） | 失败 |

## 1. 工作稿（没有则拉）

人只想拉、盖、丢掉缓存：**不要走本文**，走 [05 §2](../../../ARCHITECTURE/05-版本工作稿与独立命令.md) `version draft pull` / `discard`。  
本节只写：本命令碰到盘上有没有稿时怎么办。写入字段见 §1.2（与 `draft pull` 同一张表）。

回显源 = `--reuse-version`，未传 = **latest**（这次提交认的底）。

| 进入 | 行为 |
|------|------|
| `--reuse-version <已发号>` | 必须在版本列表里。不在：「没有这个版本」，失败 |
| 未传 | **latest** |

1. `Resource.getVersionListByResourceID`（`GET /v2/resources/{id}/versions`）校验回显源。列表若分页，**拉全**再比，避免旧号误报不存在。
2. `Resource.resourceVersionInfo1`（`GET /v2/resources/{id}/versions/{回显源}`）。失败：平台 `msg`，结束，**不写盘**。
3. 上抛名单**不回显**。工作稿 `baseUpcastResources` 写 `[]`。本期不解决上抛，见 [依赖](../版本表单/03-依赖.md)。
4. 按下面规则写入 `.freelog/N.version.json`。坏文件失败。不准装身份 / listing / 策略 / raw。不对接 `lookDraft`。`fileSha1` / `filename` **要写进**工作稿。

### 1.1 写不写、盖不盖

`fromVersion` 是「这份稿从哪一号拉下来的」，不是即将发行的新号。拿它和**本次回显源**比（未传 `--reuse-version` = latest）。只看本地稿 + 线上已发号，不看平台草稿。总表见 [本地状态 §2.2](../../../ARCHITECTURE/02-本地状态.md)。

| 盘上 | TTY | `--yes` |
|------|-----|---------|
| 没有 `N.version.json` | 按回显源写入 | 同上 |
| 有文件，没有 `fromVersion`（首版残留） | 这不是更新稿。问：用回显覆盖？**默认否**（结束去 `version draft pull --yes`） | **失败**。「请先 version draft pull --yes」。不要在提交里默默盖 |
| `fromVersion` **等于**本次回显源 | 提醒，**默认继续** | 续用，不问 |
| `fromVersion` **不等于**本次回显源 | 说明对不上。问「覆盖重拉 / 仍用这份」，**默认仍用这份**。要盖也可用 `version draft pull` | **失败**。打印来自 {x}、底是 {y}。去 `draft pull` 或改 `--reuse-version` |
| `--reuse-version 1.0.0` 且稿也是 `1.0.0`，即使 latest 已是 1.1.0 | 等于回显源，续用 | 续用 |

TTY **续用**时打：

```
发现本地版本工作稿  .freelog/N.version.json
  来源：从 {fromVersion} 回显
  文件：{filename}  sha1={前8位}…
  自定义 n / 可选配置 n / 依赖 n / 描述：有|无

继续使用这份？ [Y]  放弃，重新拉取 [n]
```

TTY **不等于回显源**时打：

> 本地工作稿来自 {fromVersion}，与本次回显源 {回显源} 不一致。默认仍用这份。要盖请先结束，跑 version draft pull [--version {回显源}] --yes。

选项：**仍用这份稿（默认）** / 覆盖重拉。不要默默盖、也不要默默丢。  
覆盖 = 整份按 §1.2 重写，不要和旧稿混字段。盖之前打将丢掉的摘要，见 [05 §2.1](../../../ARCHITECTURE/05-版本工作稿与独立命令.md)。  
`--reset`：不论是否一致，丢掉工作稿再拉（一次会话）。分步：`version draft discard` 再 `pull`。看内容：`version show --local`。

### 1.2 写入哪些字段

缺一项就写空数组 / 空串，不要整表跳过。写完立刻落盘。

```
fromVersion                 # 本次回显源版本号
fileSha1
filename
description
inputAttrs
customPropertyDescriptors
dependencies
baseUpcastResources
authExcludedItems
```

| 回显源字段 | 写入工作稿 | 条件 |
|------------|------------|------|
| （本次回显源号） | `fromVersion` | 一直写 |
| `fileSha1` / `filename` | 同名 | 一直写。中断后续传靠它 |
| `customPropertyDescriptors` 里 `type===readonlyText` | 自定义属性 | 一直带。和系统 key / 名称撞了：**丢掉这条自定义**，不要盖系统项 |
| 其余 `customPropertyDescriptors`（`editableText` / `select`） | 可选配置 | 仅 `supportOptionalConfig===2`。类型已不允许：写 `[]` |
| `systemPropertyDescriptors` 且 `insertMode===2` | `inputAttrs`：`{ key, value: valueDisplay }` | 仅附加。raw **不要带**（每次现解析） |
| `dependencies` | `dependencies: [{ resourceId, versionRange }]` | 一直带 |
| （不取上抛） | `baseUpcastResources: []` | 一直写空。不要从 `info.baseUpcastResources` 抄 |
| `description` | `description` | 一直带，可 `''` |
| 排除项 | `authExcludedItems` | 仅回显源 / info 里确有才带；没有就 `[]` |

写入或确认续改后打印：

- `已从 {回显源} 写入工作稿` 或 `继续使用本地工作稿（来自 {fromVersion}）`
- 自定义 n、可选配置 n、依赖 n、描述是否空
- 工作稿路径：`.freelog/N.version.json`

人 / AI 此后可以直接改这个文件。自定义 value 上限 CLI **一律 100**。

## 2. 新版本号

本文**必须**有新号。不要写死 `1.0.0`。新号只在当次进程 / `--version`，**不写**进 `N.json`，也不必写进工作稿。

| 进入 | 行为 |
|------|------|
| `--version` 与 `--bump` 一起 | 失败：「不要同时使用 --version 和 --bump」 |
| `--version <semver>` | 校验合法且 **严格大于** `latestVersion` |
| `--bump patch\|minor\|major` | 在 latest 上按该方向生成候选。TTY 再确认。非法或 ≤ latest 失败 |
| 只写了 `--bump`、没方向 | TTY 问一次 `patch` / `minor` / `major`。`--yes`：**失败**，「请使用 --bump patch\|minor\|major 或 --version」。不要默默 patch |
| `--yes --bump patch\|minor\|major` | 直接用候选，**不再确认** |
| TTY 都没传 | 问「新版本号」，提示当前 latest，可给一个 `>` latest 的建议（例如 patch+1） |
| `--yes` 且没有 `--version`、也没有带方向的 `--bump` | 失败，不猜测 |

非法或不大于 latest：文案对齐 `freelog_versioning`（须合法 semver，且大于当前最新版）。空：「请输入版本号」。  
本项无 tools-lib（只做 semver 比较）。

## 3. 定文件

`--file` **先落到哪一份**，不是一律换文件。`--file` 与 `--reuse-version` **可以一起用**：后者只决定回显哪一号的表单。

| `--file` | 哪一份 / 路径 |
|----------|----------------|
| 路径已在某份 `filePath` | 那一份。不改 `filePath`（只选份） |
| 仅一份，路径还不在 index | 写入这份 `filePath` 和 index（换文件，本步仍不上传） |
| 多份，路径不在任何 `N.json` | 失败 |
| 未传，仅一份 | 那一份 |
| 未传，多份 | §0 已失败 |

然后：

| 进入 | 用哪份文件 |
|------|------------|
| 未传 `--file` | **复用**工作稿 / 回显源的 sha1。**不重读**磁盘。本地文件可以不在。打印「复用 {回显源} 的文件 {filename}」 |
| `--file` 就是这份已有 `filePath`，本地文件**不在**，稿或回显有 sha1 | **只选份，复用** sha1。不要失败。打印同上 |
| `--file` 就是这份已有 `filePath`，本地文件**在** | 按磁盘重算（§4.2） |
| `--file` 与当前 `filePath` 不同（或第一次写入路径） | **换文件**。本地必须在 |
| 回显源 / 稿都没有 `fileSha1`，又没有本地文件 | 失败，「回显源没有文件，请 --file」 |

换文件 / 按磁盘算时：文件须在（或 `directory-zip` 的目录）；超大小失败；`directory-zip` 先打 zip。`--yes` 且换文件但路径无效：失败。

## 4. SHA1 / 上传 / 解析

### 4.1 复用稿 / 回显文件

走 §3 的「复用」：优先工作稿 `fileSha1` / `filename`，没有再用回显源的。稿里还没有则写入。**不上传**。  
先 `Storage.fileIsExist`。已有：去 §4.3。没有：「存储上没有这个文件，请 --file 指定本地文件重新上传」。失败，不进会话。

### 4.2 按磁盘

1. 本地算 SHA1（`Tool.getSHA1Hash` / 与平台同一套，小写 hex）。
2. `Storage.fileIsExist`（`GET /v2/storages/files/fileIsExist`）。
3. 已有：跳过上传，记下 `fileSha1`、`filename`。
4. 没有：`Storage.uploadFile`（`POST /v2/storages/files/upload`）。进度；取消 = 失败；中断整文件再传。
5. 失败：平台 `msg`，不进会话。

得到 `fileSha1` / `filename` 后**立刻写入**工作稿。不写 `N.json`。

### 4.3 解析系统属性

打印「属性正在解析...」。

1. `Storage.filesListInfo`（`GET /v2/storages/files/list/info`，`sha1` + `resourceTypeCode`）轮询，直到 `metaAnalyzeStatus` 为 2 或 3。  
   **从第一次请求起最长 120 秒**。超时仍是 0/1：失败，「属性解析超时」，不进会话。不要调用会空转的 `getFilesSha1Info` 还不加超时。  
   `===3` 或平台错误：失败，不进会话。
2. `insertMode===1` → 系统 `raw`（空值不展示）；`insertMode===2` → 系统附加。
3. 附加的 key 逐个 `Resource.getAttrsInfoByKey`。怎么填见 [属性 §2](../版本表单/01-属性.md)。

不要用 `Storage.fileProperty`。raw 不进工作稿。  
工作稿里已有的 additional value：**盘上这份优先于这次解析**。

## 5. 会话：改盘上的工作稿

§1 之后盘上已有 `N.version.json`。本节只读这份、改这份。没有这份：失败，不要空表开会话。

每次先打快照（读盘，不是空表）：

- 新版本号
- 文件：复用哪一号 / 新上传的相对路径；sha1 前 8 位
- raw、附加（标出哪些是回显带来的 value）
- 自定义 `n/30`、可选配置 `n/30`
- 依赖：范围 / 是否已签（不要打是否上抛）
- 描述（空：「无描述」）

再问「下一步？」

| 号 | 选项 | 进哪 | 何时出现 |
|----|------|------|----------|
| 1 | 添加属性 | [属性 §3](../版本表单/01-属性.md) | 自定义 <30 |
| 2 | 删除或修改属性 | [属性 §4](../版本表单/01-属性.md) | 有自定义或可改附加（回显带来的也算） |
| 3 | 添加可选配置 | [可选配置 §2](../版本表单/02-可选配置.md) | 类型允许且 <30 |
| 4 | 删除或修改可选配置 | [可选配置 §3](../版本表单/02-可选配置.md) | 类型允许且已有（含回显） |
| 5 | 添加依赖 | [依赖 §1](../版本表单/03-依赖.md) | 一直有 |
| 6 | 管理依赖 | [依赖 §2](../版本表单/03-依赖.md) | 已有依赖（含回显） |
| 7 | 编辑版本描述 | 可空；默认 = 工作稿里回显来的描述；写进工作稿 `description` | **本文一直有** |
| — | 提交 | §6 | 已有文件 |
| — | 取消 | 不 POST；工作稿已写的保留 | 一直有 |

选 1–7：做完立刻写回 `N.version.json`，回到本菜单。`--yes` 跳过本菜单，提交体必须读盘上这份。  
类型不允许可选配置：菜单 **3、4 不出现**；工作稿若仍带可选配置，§6 失败。

工作稿里的依赖：按 [依赖 §4](../版本表单/03-依赖.md) 核回显结果。先 [依赖 §1.5](../版本表单/03-依赖.md) 看 `isAuth`（`GET /v2/auths/resources/batchAuth/results`）；已授权不必重签。没有再 [§1.6](../版本表单/03-依赖.md) 签。不查合约列表。对方有基础上抛：当不支持，不要去签上抛链。`licenseeVersion` 若平台要 = §2 的新号。回显来的排除项当没有。

## 6. 提交

再拦：无 sha1；有依赖未授权；不该有的可选配置；自定义/可选 >30。  
提交前再 `Resource.info`（`isLoadLatestVersionInfo=1`）：新号非法或 **不大于当时的** `latestVersion` → 失败。工作稿留下。不要改口成 `create-version`。

失败必须**点名字段**，`--yes` 同样。不要只回「校验失败」或只回平台 `msg`：

| 拦 | 文案要点 |
|----|----------|
| 无 sha1 | 文件：工作稿没有 fileSha1，请 --file |
| 依赖未授权 | 依赖 {username/name 或 id}：未获得授权 |
| 对方有基础上抛 | 依赖 {id}：对方存在基础上抛，本期不支持 |
| 类型不允许可选配置 | 可选配置 {key}：当前类型不允许 |
| 条数超 | 自定义属性：已满 30 条 / 可选配置：已满 30 条 |
| 新号 ≤ 当时 latest / 非法 | 版本号：线上已经是 {latest}，不能发 {新号}（非法则对齐 `freelog_versioning`） |

TTY 摘要（新号、文件来自回显还是新上传、属性/配置/依赖条数、描述）。确认。「否」回菜单。

`Resource.createVersion`（`POST /v2/resources/{resourceId}/versions`）：

| 字段 | 值 |
|------|----|
| `version` | §2 的新号 |
