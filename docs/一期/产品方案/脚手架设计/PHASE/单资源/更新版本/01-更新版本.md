# 更新版本

对照业务：[P0-M0](../../../业务梳理/创建流程%20-%20发行新版本/P0-M0-发行新版本.md)。Console 文案「更新版本」/「新建版本」。  
**必须已有 `latestVersion`。** 第一步：把回显源（默认 latest）拉下来，**立刻写入** `.freelog/N.version.json`。之后会话和直接改文件，改的都是这份缓存。没有这份文件，属性 / 可选配置 / 依赖没法续改。改完再 `POST` 一个新号。

不是 [发行版本](../创建/02-Step2-发行版本.md)。那边命令是 `create-version`，没有上一版，空表起步，号写死 `1.0.0`。  
不是 [版本信息](../管理/01-版本信息.md)。那边只看已发号、只改描述（`version description`），不发新号。

命令是 **`update-version`**。平台仍是 `POST /v2/resources/{id}/versions`（新号）。和 `create-version` 不是同一条 CLI，不要共用入口、不要自动改口。跑了 `create-version` 且已有版本：失败，让人改跑本文。

```
# 默认：回显 latest 的文件 + 表单，再问新号
freelog-cli update-version

# 指定从哪一号回显（文件 + 表单）
freelog-cli update-version --reuse-version 1.0.0 --version 1.1.0

# 回显 latest 的表单，但换新文件
freelog-cli update-version --file <path> --version 1.1.0

# 从 1.0.0 回显表单，并换新文件
freelog-cli update-version --reuse-version 1.0.0 --file <path> --version 1.1.0

# 丢掉本地工作稿，按回显源重拉
freelog-cli update-version --reset --version 1.1.0
```

`--reuse-version` = **回显源**（默认 latest）。`--file` = **换文件**。两套可以一起用，不是互斥。  
`--reset`：丢掉工作稿再拉。`version set --reuse-version` **不存在**。`--bump` 可代替手写新号（在 latest 上 bump；具体 patch/minor/major 要问清或 flag 写明，不要默默 patch）。

须已 `login`，已有 `resourceId`。本人、未冻结。回显结果、文件 sha1、之后每一项改动都写 `N.version.json`。不做平台草稿。不写 `N.json`。不用 `publish`。只做本地上传。

`--yes`：不进会话；先保证工作稿在盘上（该拉就拉并写盘），再按这份提交。禁止「只交系统解析、丢掉上一版」。稿落后则放弃重拉。缺新号、缺文件（且回显源也没有文件）仍失败。一夹多条且用 `--file` 时必须指定路径。

看缓存：`version show --local`。看线上：`version show`（不写工作稿）。

属性 / 可选配置 / 依赖的每一问见 [版本表单](../版本表单/README.md)。本文只写：先拉哪一号、怎么落盘、落盘后再怎么改。

| # | 功能 | 怎么进 |
|---|------|--------|
| 0 | 门禁：必须已有版本 | 没有 `latestVersion` → 失败，去发行版本 |
| 1 | 拉回显源，写入 `N.version.json` | `--reuse-version` 或 latest。**本文第一件必须落盘的事** |
| 2 | 新版本号 | `--version` / `--bump` / TTY |
| 3 | 定文件 | 默认用回显源的文件；`--file` 才换 |
| 4 | SHA1 / 上传 | 换文件才上传；复用回显文件不上传 |
| 5 | 会话：改的是盘上这份缓存 | 菜单 1–6 进版本表单；**有**菜单 7 描述 |
| 6 | 提交新号 | 读工作稿 `POST createVersion`。不接续 Step3 |

```
0 门禁（必须已有 latestVersion）
  → 1 工作稿：提醒 / 落后默认放弃 / 没有则 GET 回显源写入（含 sha1）
  → 2 新版本号
  → 3 文件（默认用稿里或回显源的 sha1；--file 换新）
  → 4 换文件才上传 → 写进工作稿
  → 5 会话（读盘上的工作稿，改一项写一项）
  → 6 POST createVersion（新号，体来自工作稿）→ 成功清空工作稿
```

成功后**不加策略、不接续 Step3**。成功必须删掉工作稿。

## 0. 进入

`Resource.info`（`GET /v2/resources/{id}`，`isLoadLatestVersionInfo=1`）。

| 检查 | 失败 |
|------|------|
| 未登录 / 无 `N.json` / 无 `resourceId` | 先 login / create / bind |
| 没有 `latestVersion` | 失败：「还没有发行版本，请先 create-version」。去 [发行版本](../创建/02-Step2-发行版本.md) |
| 误跑 `create-version` | 那条命令自己失败。本文不接它的参数 |
| `subjectType===4` | 失败（合集暂缓） |
| 非本人、冻结 | 失败 |
| 一夹多条未 `--file` | 列出各份 `filePath`，要求指定（`--file` 同时用来落到哪一份；路径已是该份 `filePath` 时仍走 §3 换文件 / 重算 sha1） |
| 一夹多条且传了 `--file` 但对不上 | 失败 |

`Resource.getResourceTypeInfoByCode`（`GET /v2/resources/types/getInfoByCode`）：

| 配置 | 用法 |
|------|------|
| `fileCommitMode` 含 `2^0` | 本地上传；其它提交方式本期不做 |
| `fileMaxSize` + `fileMaxSizeUnit` | `--file` 时的上限 |
| `supportOptionalConfig === 2` | 才回显可选配置；菜单才有 3 / 4 |
| 类型名含「视频」 | 换文件后**可问**版本封面；**不传** `videoCover` |

## 1. 拉回显源，写入工作稿

回显源 = 从哪一号把文件 / 属性 / 可选配置 / 依赖 / 描述拉下来。拉完**必须落盘**，不要只放在进程里。

| 进入 | 行为 |
|------|------|
| `--reuse-version <已发号>` | 必须在版本列表里。不在：「没有这个版本」，失败 |
| 未传 | **latest** |

1. `Resource.getVersionListByResourceID`（`GET /v2/resources/{id}/versions`）校验回显源。
2. `Resource.resourceVersionInfo1`（`GET /v2/resources/{id}/versions/{回显源}`）。失败：平台 `msg`，结束，**不写盘**。
3. 上抛名单用 `info.baseUpcastResources`（和 Console inherit 一样，取资源上的）。
4. 按下面规则写入 `.freelog/N.version.json`。坏文件失败。不准装身份 / listing / 策略 / raw。不对接 `lookDraft`。`fileSha1` / `filename` **要写进**工作稿。

### 1.1 写不写、盖不盖

`fromVersion` 是「这份稿从哪一号拉下来的」，不是即将发行的新号。拿它和**本次回显源**比（未传 `--reuse-version` = latest）。只看本地稿 + 线上已发号，不看平台草稿。总表见 [本地状态 §2.2](../../../ARCHITECTURE/02-本地状态.md)。

| 盘上 | 行为 |
|------|------|
| 没有 `N.version.json` | **必须新建**，写入回显 |
| 有文件，但没有 `fromVersion`（发行版本留下的空稿 / 旧稿） | **用回显覆盖**。TTY 打：「发现首版工作稿，将用回显覆盖」。`--yes` 直接盖 |
| 有 `fromVersion` 且 **等于** 本次回显源 | 可用续改稿。TTY 按下面格式提醒，**默认继续**。`--yes` 续用，不问 |
| 有 `fromVersion` 且 **不等于** 本次回显源（落后 / 换了 `--reuse-version` / 稿比回显源新） | 不是这份回显源的稿。TTY 提醒，**默认放弃**，按回显源整份重拉。`--yes` 同样放弃并重拉 |
| 人明确 `--reuse-version 1.0.0`，稿的 `fromVersion` 也是 `1.0.0`，即使 latest 已是 1.1.0 | **等于回显源**，不算落后，续用 |

TTY **续用**时打：

```
发现本地版本工作稿  .freelog/N.version.json
  来源：从 {fromVersion} 回显
  文件：{filename}  sha1={前8位}…
  自定义 n / 可选配置 n / 依赖 n / 描述：有|无

继续使用这份？ [Y]  放弃，重新拉取 [n]
```

TTY **不等于回显源**时打：

> 本地工作稿来自 {fromVersion}，与本次回显源 {回显源} 不一致。默认放弃这份稿，按回显源重新拉取。

选项：放弃并重拉（默认） / 仍用这份稿。不要默默盖、也不要默默续。  
覆盖 = 整份按 §1.2 重写，不要和旧稿混字段。  
`--reset`：不论是否一致，丢掉工作稿再拉。看内容：`version show --local`。

### 1.2 写入哪些字段

缺一项就写空数组 / 空串，不要整表跳过。写完立刻落盘。

```
fromVersion                 # 本次回显源版本号
fileSha1
filename
description
inputAttrs
customPropertyDescriptors
dependencies
baseUpcastResources
authExcludedItems
```

| 回显源字段 | 写入工作稿 | 条件 |
|------------|------------|------|
| （本次回显源号） | `fromVersion` | 一直写 |
| `fileSha1` / `filename` | 同名 | 一直写。中断后续传靠它 |
| `customPropertyDescriptors` 里 `type===readonlyText` | 自定义属性 | 一直带。和系统 key / 名称撞了：**丢掉这条自定义**，不要盖系统项 |
| 其余 `customPropertyDescriptors`（`editableText` / `select`） | 可选配置 | 仅 `supportOptionalConfig===2`。类型已不允许：写 `[]` |
| `systemPropertyDescriptors` 且 `insertMode===2` | `inputAttrs`：`{ key, value: valueDisplay }` | 仅附加。raw **不要带**（每次现解析） |
| `dependencies` | `dependencies: [{ resourceId, versionRange }]` | 一直带 |
| `info.baseUpcastResources` | `baseUpcastResources: [{ resourceId }]` | 一直带 |
| `description` | `description` | 一直带，可 `''` |
| 排除项 | `authExcludedItems` | 仅回显源 / info 里确有才带；没有就 `[]` |

写入或确认续改后打印：

- `已从 {回显源} 写入工作稿` 或 `继续使用本地工作稿（来自 {fromVersion}）`
- 自定义 n、可选配置 n、依赖 n、描述是否空
- 工作稿路径：`.freelog/N.version.json`

人 / AI 此后可以直接改这个文件。自定义 value 上限 CLI **一律 100**。

## 2. 新版本号

本文**必须**有新号。不要写死 `1.0.0`。新号只在当次进程 / `--version`，**不写**进 `N.json`，也不必写进工作稿。

| 进入 | 行为 |
|------|------|
| `--version <semver>` | 校验合法且 **严格大于** `latestVersion` |
| `--bump` | 在 latest 上生成候选，TTY 确认；非法或 ≤ latest 失败 |
| TTY 都没传 | 问「新版本号」，提示当前 latest，可给一个 `>` latest 的建议（例如 patch+1） |
| `--yes` 且两样都没有 | 失败，不猜测 |

非法或不大于 latest：文案对齐 `freelog_versioning`（须合法 semver，且大于当前最新版）。空：「请输入版本号」。  
本项无 tools-lib（只做 semver 比较）。

## 3. 定文件

| 进入 | 行为 |
|------|------|
| `--file <path>` | 换新文件。覆盖并写回 `N.json.filePath`（与 `version set --file` 相同，本步仍不上传）。打印「将使用文件：{相对路径}」 |
| 未传 `--file` | **复用工作稿 / 回显源的文件**（不重读本地 `filePath` 内容）。不改 `N.json.filePath`。打印「复用 {回显源} 的文件 {filename}」 |

`--file` 与 `--reuse-version` **可以一起用**：后者只决定回显哪一号的表单（以及未传 `--file` 时的文件）。

| `--file` 时 | |
|-------------|--|
| 文件在（或 `directory-zip` 的目录） | 继续 |
| 超大小 | 失败，不上传 |
| `directory-zip` | 先打 zip 再当文件 |
| `--yes` 且路径无效 | 失败 |

回显源没有 `fileSha1`、又没传 `--file`：失败，「回显源没有文件，请 --file」。

## 4. SHA1 / 上传 / 解析

### 4.1 复用回显文件

未传 `--file`：优先用工作稿里的 `fileSha1`、`filename`；没有再用回显源的。**不上传**。仍要按该 sha1 走 §4.3。稿里还没有则写入。

### 4.2 换文件

传了 `--file`：

1. 本地算 SHA1（小写 hex，与平台同一套）。
2. `Storage.fileIsExist`（`GET /v2/storages/files/fileIsExist`）。
3. 已有：跳过上传，记下 `fileSha1`、`filename`。
4. 没有：`Storage.uploadFile`（`POST /v2/storages/files/upload`）。进度；取消 = 失败；中断整文件再传。
5. 失败：平台 `msg`，不进会话。

得到 `fileSha1` / `filename` 后**立刻写入**工作稿。不写 `N.json`。

### 4.3 解析系统属性

打印「属性正在解析...」。

1. `Storage.filesListInfo`（`GET /v2/storages/files/list/info`，`sha1` + `resourceTypeCode`）轮询，直到 `metaAnalyzeStatus` 为 2 或 3。失败或完不成：不进会话。
2. `insertMode===1` → 系统 `raw`（空值不展示）；`insertMode===2` → 系统附加。
3. 附加的 key 逐个 `Resource.getAttrsInfoByKey`。怎么填见 [属性 §2](../版本表单/01-属性.md)。

不要用 `Storage.fileProperty`。raw 不进工作稿。  
工作稿里已有的 additional value：**盘上这份优先于这次解析**。

## 5. 会话：改盘上的工作稿

§1 之后盘上已有 `N.version.json`。本节只读这份、改这份。没有这份：失败，不要空表开会话。

每次先打快照（读盘，不是空表）：

- 新版本号
- 文件：复用哪一号 / 新上传的相对路径；sha1 前 8 位
- raw、附加（标出哪些是回显带来的 value）
- 自定义 `n/30`、可选配置 `n/30`
- 依赖：范围 / 是否已签 / 是否上抛
- 描述（空：「无描述」）

再问「下一步？」

| 号 | 选项 | 进哪 | 何时出现 |
|----|------|------|----------|
| 1 | 添加属性 | [属性 §3](../版本表单/01-属性.md) | 自定义 <30 |
| 2 | 删除或修改属性 | [属性 §4](../版本表单/01-属性.md) | 有自定义或可改附加（回显带来的也算） |
| 3 | 添加可选配置 | [可选配置 §2](../版本表单/02-可选配置.md) | 类型允许且 <30 |
| 4 | 删除或修改可选配置 | [可选配置 §3](../版本表单/02-可选配置.md) | 类型允许且已有（含回显） |
| 5 | 添加依赖 | [依赖 §1](../版本表单/03-依赖.md) | 一直有 |
| 6 | 管理依赖 | [依赖 §2](../版本表单/03-依赖.md) | 已有依赖（含回显） |
| 7 | 编辑版本描述 | 可空；默认 = 工作稿里回显来的描述；写进工作稿 `description` | **本文一直有** |
| — | 提交 | §6 | 已有文件 |
| — | 取消 | 不 POST；工作稿已写的保留 | 一直有 |

选 1–7：做完立刻写回 `N.version.json`，回到本菜单。`--yes` 跳过本菜单，提交体必须读盘上这份。  
类型不允许可选配置：菜单 **3、4 不出现**；工作稿若仍带可选配置，§6 失败。

工作稿里的依赖：按 [依赖 §1.5](../版本表单/03-依赖.md) 检查是否还要为**新号**再签。`licenseeVersion` = §2 的新号。已排除的不要强行签。

## 6. 提交

再拦：无 sha1；有依赖未签完；不该有的可选配置；自定义/可选 >30。  
提交前再 `Resource.info`（`isLoadLatestVersionInfo=1`）：新号非法或 **不大于当时的** `latestVersion` → 失败（文案对齐 `freelog_versioning`）。工作稿留下。不要改口成 `create-version`。

TTY 摘要（新号、文件来自回显还是新上传、属性/配置/依赖条数、描述）。确认。「否」回菜单。

`Resource.createVersion`（`POST /v2/resources/{resourceId}/versions`）：

| 字段 | 值 |
|------|----|
| `version` | §2 的新号 |
| `fileSha1` / `filename` | **读工作稿**（§4 已写入） |
| `description` | **读工作稿**，可 `''` |
| `inputAttrs` | **读工作稿**，解析结果不要盖盘上的 value |
| `customPropertyDescriptors` | 自定义 + 可选配置，见版本表单 |
| `dependencies` / `baseUpcastResources` / `batchSignContracts` / `authExcludedItems` | [依赖 §3](../版本表单/03-依赖.md) |
| `videoCover` | **不传** |

失败：`msg`，工作稿留下。成功：打印新版本号，**删掉** `N.version.json`，**不**串 policy / online / Step3。

`--yes` 未签依赖：按依赖文档自动签的限制来。

## 禁止

没有 `latestVersion` 还走本文。用 `create-version` 当更新版本。把 `update-version` 做成只改已发号描述。把回显只放在进程里、不写 `N.version.json`。文件 sha1 不写工作稿。成功后还留着工作稿。`fromVersion` 不等于本次回显源还默默续用。有同 `fromVersion` 的续改稿还用平台盖掉、也不提醒。`--yes` 只交系统解析、丢掉上一版。用 `version show` 把线上写进工作稿。把本文做成 [发行版本](../创建/02-Step2-发行版本.md) 的空表。`version set --reuse-version`。未传 `--file` 却按磁盘重算 sha1。存储空间 / Markdown / 漫画。`lookDraft` / `saveVersionsDraft`。属性写进 `N.json`。`publish`。付费签约。
