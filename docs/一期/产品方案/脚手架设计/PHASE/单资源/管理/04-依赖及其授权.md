# 依赖及其授权

对照业务：Console「依赖及其授权」（P0-M4）。终端里是 `dep` 一组命令。已发版**不增删**依赖树。授权合约列表**不做**。没有 `dep add`。

本组命令功能：

| # | 功能 | 命令 |
|---|------|------|
| 1 | 看依赖树 | `dep list --tree` |
| 2 | 生成补签模板 | `dep init-auth-map` |
| 3 | 补免费签 | `dep auth` |

增删树、改范围：走 [更新版本](../更新版本/01-更新版本.md) 菜单 5 / 6，问法见 [版本表单/依赖](../版本表单/03-依赖.md)。本期不改上抛。

```
freelog-cli dep list --tree
freelog-cli dep init-auth-map [--out ./auth-map.yaml]
freelog-cli dep auth --policy-map ./auth-map.yaml
```

---

## 0. 门禁

`Resource.info`（`GET /v2/resources/{id}`）。

| 命令 | |
|------|--|
| `list` | 非本人可以只读 |
| `init-auth-map` / `auth` | 须本人、未冻结 |
| 无版本 | `list` 打空树；`auth` 失败 |

---

## 1. 看依赖树

```
freelog-cli dep list --tree [--version 1.0.0]
```

1. 优先 `Resource.dependencyTree`（`GET /v2/resources/{id}/dependencyTree`）。返回不完整再退 `getVersionListByResourceID` + 各版详情。要能打出「版本 → 直接依赖 → 再往下」。
2. 筛哪一版：

| 进入 | 行为 |
|------|------|
| `--version` | 只打这一号 |
| TTY 未传 | 问「全部 / 某一版」，默认全部 |
| `--yes` 未传 | 全部 |

3. 每一条打印：`username/name` 或 id、`versionRange`、是否已有合约。不要在本命令签约。

只读平台，不写本地。

---

## 2. 生成补签模板

```
freelog-cli dep init-auth-map [--out ./auth-map.yaml]
```

1. 收集未签完的依赖 `resourceId`（从 §1 的树来）。没有未签：打印「没有待补签的依赖」，不写文件。
2. 每个依赖再 `Resource.info`（`isLoadPolicyInfo=1`），找 `status===1` 且文本不含 `TransactionEvent` 的策略，填进模板当建议。找不到就 `policyId` 留空。
3. 默认路径 `./auth-map.yaml`。`--out` 覆盖。
4. 目标已存在：TTY 确认覆盖；`--yes` 且无 `--force`：失败（不要默默覆盖）。

写出 YAML：每一项 `resourceId` → `policyId`（可空）。无 tools-lib 写文件。

---

## 3. 补免费签

```
freelog-cli dep auth --policy-map ./auth-map.yaml --yes
```

### 3.1 读 map

每一项：`依赖 resourceId` → `policyId`。缺字段、重复、指向不是本资源依赖的 id：失败。

| 进入 | 行为 |
|------|------|
| `--policy-map` | 读这个文件 |
| TTY 未给 | 提示先 `init-auth-map`，或逐条问未签依赖（`select` 一条免费 `policyId`） |
| `--yes` 未带文件 | 失败 |

### 3.2 每一条怎么签

与 [依赖 §1.5](../版本表单/03-依赖.md) 同一套免费规则：

1. 依赖须已在某已发版的依赖树里（`dep auth` 不新增树）。
2. 策略须存在、启用、免费（不含 `TransactionEvent`）。
3. 对方现有 `baseUpcastResources`：这条失败，「对方存在基础上抛，本期不支持。」不要去签上抛链。
4. 没有免费策略、或签完 `authStatus` 不是 1/2：这条失败，「签约后无法获得授权，本期不支持。」**不要**中断已成功的其它条。不做支付。
5. `Contract.batchCreateContracts`（`POST /v2/contracts/batchSign`）：

| 字段 | 值 |
|------|-----|
| `subjectType` | `1` |
| `licenseeId` | 本资源 `resourceId` |
| `licenseeIdentityType` | `1` |
| `subjects` | `[{ subjectId: 对方 resourceId, policyId }]` |

自己的资源当依赖也要签。

### 3.3 结束

打印成功条数、失败条数及原因。可再 `dep list --tree` 核对。不写 `N.json`。

## tools-lib

| 何时 | 函数 | HTTP |
|------|------|------|
| 壳 | `Resource.info` | `GET /v2/resources/{id}` |
| 树 | `Resource.dependencyTree` 和/或 `getVersionListByResourceID` | `GET .../dependencyTree`、`GET .../versions` |
| 补签 | `Contract.batchCreateContracts` | `POST /v2/contracts/batchSign` |

不用微前端。不用 `Resource.batchSetContracts`（那是按版本挂策略，不是 `dep auth`）。
