# 版本信息

对照业务：Console「资源及其属性」（[P0-M1](../../../业务梳理/维护%20-%20单资源/P0-M1-版本信息.md)）。终端里是两条命令，不是一页。

```
freelog-cli version show [--version 1.0.0]
freelog-cli version show --local
freelog-cli version description --version 1.0.0 [--description "..."]
```

须已 `login`，已有 `resourceId`。本人、未冻结。不做平台草稿。没有 `--sync-properties`。

`version show`（不带 `--local`）和 `version description`：**只看 / 只改线上已发号，不写 `N.version.json`**。有本地工作稿时，`version show` 打完线上后再打一行：「本地有未提交的版本工作稿，查看请 version show --local」。不要为了看线上覆盖缓存。

`version show --local`：只读工作稿，版式与线上相同。不拉平台表单。不与 `--version` 一起用（一起传：失败）。没有工作稿：失败，「没有本地版本工作稿」。

版本数据隔离：某一号发出去之后，文件 / 属性 / 可选配置 / 依赖冻在这一号。要改那些走 [更新版本](../更新版本/01-更新版本.md)。不要去读创建 Step2。

| # | 功能 | 哪条命令 | 写不写平台 / 工作稿 |
|---|------|----------|---------------------|
| L | 看本地工作稿 | `version show --local` | 都不写 |
| 1 | 还没有线上版本 | `version show` / `version description` 先检查 | 不写；失败或非 0 退出 |
| 2 | 选定看哪一号 | `--version` 或 TTY `select` | 不写 |
| 3 | 打印文件 | `version show` 必打；`--local` 打稿里的 sha1 | 不写 |
| 4 | 打印基础属性 | 同上 | 不写 |
| 5 | 打印可选配置 | 同上 | 不写 |
| 6 | 改描述 | 只有 `version description` | **线上唯一的 PUT**。不写工作稿 |
| 7 | 打印依赖 | 同 3 | 不写；补签另跑 `dep auth` |
| 8 | 拒绝改冻住的字段 | 带了 `--file` / `--sync-properties` 等 | 失败，去 `update-version` |

`version show`：0 → 1 或 2 → 3 → 4 → 5 → 7 → 结束。不问描述。有工作稿打提示。  
`version show --local`：读盘 → 按 3–5、7 打工作稿 → 结束。  
`version description`：0 → 1 或 2 → 可打 3–5、7 当快照 → 6。

---

## 0. 门禁

`version show --local`：须已有 `N.json`（知道看哪一份工作稿）。未登录也可以看本地稿。然后走 §1.L。不要 GET 版本列表。

`version show` / `version description`：

1. `Resource.info`（`GET /v2/resources/{id}`，`isLoadLatestVersionInfo=1`）。
2. 未登录 / 无 `resourceId`：失败，先 login / create / bind。
3. 非本人 / `status===2`（冻结）：失败。
4. `subjectType===4`：失败（合集暂缓）。
5. `Resource.getVersionListByResourceID`（`GET /v2/resources/{id}/versions`）。

---

## 1. 还没有版本

`info.latestVersion` 为空，或版本列表空。

打印：

> 还没有发行版本。请先按发行版本 create-version 提交资源文件。

| 命令 | 行为 |
|------|------|
| `version show` | 打完上面一行，退出码非 0 |
| `version description` | 失败。不要空 PUT |
| 任一条加了 `--yes` | 同样失败 |

不要问「要不要现在发行」。不要对接草稿。  
`version show --local` 不走本节（没有线上版本也可以看工作稿）。

tools-lib：§0。

---

## 1.L 看本地工作稿（`--local`）

只读 `.freelog/N.version.json`。坏文件失败。

先打一行：

> 这是本地未提交的版本工作稿（来源：首版 / 从 {fromVersion} 回显）。不是线上已发号。

然后按 §3–5、§7 的版式打：文件（稿里的 `filename` / `fileSha1`）、自定义、系统附加（`inputAttrs`）、可选配置、依赖、描述。  
系统 raw **不在工作稿**：打「系统 raw 不在工作稿，提交时按 sha1 现解析」，不要为了展示去拉平台。

不写盘、不 GET 版本详情。要改：`create-version` 或 `update-version`。要看线上：去掉 `--local`。

---

## 2. 选定哪一号

有版本才继续。默认 **latest**。

1. 把列表按新→旧打印，latest 标出来。每行：版本号、文件名（有则带）、是否 latest。
2. 选定：

| 进入 | 行为 |
|------|------|
| `--version <已发号>` | 必须在列表里。不在：「没有这个版本」，失败 |
| TTY 未传 | `select`，默认 latest。取消 = 结束本命令 |
| `--yes` 未传 | latest |

3. `Resource.resourceVersionInfo1`（`GET /v2/resources/{id}/versions/{version}`）。失败：平台 `msg`，结束本命令。
4. 本进程记下：`version`、`fileSha1`、`filename`、`description`、系统属性、自定义、可选配置、`dependencies`。

再看另一号：重新跑命令并换 `--version`，或 TTY 再 `select` 一次后重拉详情。不要用上一号缓存。

---

## 3. 打印文件

只读。这两条命令都不提供换文件、不提供下载。

打印：

- 文件名：`filename`。没有：「无文件名」
- sha1：完整小写 hex。没有：「无 sha1」

换文件：用户另跑 `version set --file`（只改 `N.json`）再 `update-version`。本命令里出现 `--file`：走 §8。

数据来自 §2。无独立 API。

---

## 4. 打印基础属性

只读。不要学 Console 界面上能点 value。

先打一行：

> 资源属性主要用于存储一些资源相关信息。已发行版本上的属性不能改；要改请 update-version。

### 4.1 系统 raw

`insertMode===1`。**空值不展示**。能展示的每行：`名称 (key) = 值`。

### 4.2 系统附加

`insertMode===2`。每行：`名称 (key) = 值`。没有 value 打「（空）」。

### 4.3 自定义（`readonlyText`）

每行：`名称 (key) = 值`。有说明跟在后面。

一类都没有：打「没有基础属性」。

不要为了展示再 `PUT`。不要问「改哪一条」。用户带了改属性的 flag：走 §8。

---

## 5. 打印可选配置

`getResourceTypeInfoByCode` 得 `supportOptionalConfig!==2`，或该版没有可选配置：打「没有可选配置」，不要再问。

有则先打：

> 可选配置是作品在节点展示/运行时，允许节点管理者更改的设置。已发行版本上不能改；要改请 update-version。

每行：`名称 (key) · 文本/下拉 · 当前默认值`。下拉可附带选项（只读）。

`Resource.getResourceTypeInfoByCode`（`GET /v2/resources/types/getInfoByCode`）只决定打不打本节，不开放编辑。

---

## 6. 改描述

只有 `version description` 写平台。`version show` 只打印当前描述（空：「无描述」），不问、不 PUT。

帮助：

> 版本描述  
> 可空。空则展示为无描述。

### 6.1 怎么问

当前描述空：打印「还没有描述」，再问「版本描述（可空）」。  
当前有内容：问「版本描述」，默认 = 线上当前。直接回车 = **不改**，不 PUT。

| 进入 | 行为 |
|------|------|
| `--description <文本>` | 不问。用这段（可 `''` 表示清空） |
| TTY 未传 | 按上面问 |
| `--yes` 未传 `--description` | 失败，不猜测、不空 PUT |
| 回车且未传 `--description` | 打印「没有变更」，退出，不 PUT |

当纯文本。不要做 HTML 编辑器。空串 = 无描述。

### 6.2 确认并写入

TTY 摘要：版本号、将写入的描述（空：「（无描述）」）。确认「保存描述」。取消不写。

`Resource.updateResourceVersionInfo`（`PUT /v2/resources/{id}/versions/{version}`）**只带**：

```
description    # 可 ''
```

不传 `inputAttrs`、`customPropertyDescriptors`、文件、依赖。

| 结果 | |
|------|--|
| 失败 | 打印平台 `msg`。线上描述不变 |
| 成功 | 再 `resourceVersionInfo1`，打印当前描述 |

---

## 7. 打印依赖

只读。这两条命令不增删、不改范围、不签约。

有：每行 `username/name`（没有就 id）、`versionRange`。  
没有：打「没有依赖」。

补签：另跑 `dep auth`（[04](./04-依赖及其授权.md)）。不要在 `version show` / `version description` 里调签约。  
改树：走 §8。

数据来自 §2。不要在这里调 `dependencyTree`（整树是 `dep list --tree`）。

---

## 8. 拒绝改冻住的字段

`version show` / `version show --local` / `version description` 若带了会改文件或属性结构的参数，直接失败，不要半道改成发新版：

| 不该出现的参数 | |
|----------------|--|
| `--file` / `--reuse-version` | 去 [更新版本](../更新版本/01-更新版本.md) |
| `--sync-properties` | 不存在。要改属性去更新版本 |
| 其它改 `inputAttrs` / 可选配置 / 依赖的 flag | 同上 |

打印：

> 已发行版本的文件、属性、可选配置和依赖不能改。请使用 update-version 回显上一版后发新号。

退出码非 0。不要接着走 §6。

发新号的问法见 [更新版本](../更新版本/01-更新版本.md)，不是 [发行版本](../创建/02-Step2-发行版本.md)。本项无 API。

## tools-lib

| 何时 | 函数 | HTTP |
|------|------|------|
| 门禁 / latest | `Resource.info` | `GET /v2/resources/{id}` |
| 版本列表 | `Resource.getVersionListByResourceID` | `GET /v2/resources/{id}/versions` |
| 看某一版 | `Resource.resourceVersionInfo1` | `GET /v2/resources/{id}/versions/{version}` |
| 是否打可选配置 | `Resource.getResourceTypeInfoByCode` | `GET /v2/resources/types/getInfoByCode` |
| 改描述 | `Resource.updateResourceVersionInfo` | `PUT /v2/resources/{id}/versions/{version}` 只要 `description` |

`--local` 不用上面这些 GET。不用 `createVersion`。不用 `lookDraft` / `deleteResourceDraft`。不要用本命令写 `N.version.json`。

---

## 禁止

用这几条命令改属性 / 可选配置 / 依赖 / 文件。`--sync-properties`。`version set --file` 当成发新号。用 `update-version` 改某一已发号。用 `version show` 把线上写进工作稿。`--local` 和 `--version` 一起用。做平台草稿。
