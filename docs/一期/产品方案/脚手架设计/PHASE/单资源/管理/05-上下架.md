# 上下架

对照业务：Console 上架开关（P0-M6）。终端里是三条命令。上架只用 `online`。禁止 `update --status`。  
Console 可以当场加策略再上架；CLI **先** `policy` **再** `online`，缺了就失败，不打开策略编辑。

这三条命令：

| # | 功能 | 命令 |
|---|------|------|
| 1 | 预检能不能上架 | `validate --for online` |
| 2 | 上架 | `online` |
| 3 | 下架 | `offline` |

```
freelog-cli validate --for online
freelog-cli online
freelog-cli offline
```

---

## 0. 共用门禁

`Resource.info`（`isLoadPolicyInfo=1`，`isLoadLatestVersionInfo=1`）。

| 检查 | |
|------|--|
| 未登录 / 非本人 | 失败 |
| 冻结（`status===2`） | 失败 |
| 没有 `resourceId` | 失败 |

`info.status`：0 未发行，1 上架，2 冻结，4 下架（待上架）。

---

## 1. 预检

```
freelog-cli validate --for online
```

只预检，不写平台。逐条打印通过 / 失败：

| 条件 | 失败说明 |
|------|----------|
| 有 `latestVersion` | 资源上架之前，需要先发行一个版本 |
| 至少一条策略 `status===1` | 没有启用的授权策略。先 `policy template apply` 或 `policy set --on` |

全部通过：打印「可以上架」。有失败：退出码非 0。`--yes` 同样只预检。

本项 tools-lib：`Resource.info`。

---

## 2. 上架

```
freelog-cli online
```

1. 先做与 §1 相同的预检。失败则**不要** PUT。
2. 已上架（`status===1`）：打印「已是上架」，成功退出，不必再 PUT。
3. TTY 摘要：标识、latest、将启用的策略名。确认「上架」。取消不写。`--yes` 跳过确认，预检仍要做。
4. `Resource.update`（`PUT /v2/resources/{id}`）体**只有**：

```
resourceId
status: 1
```

不带 `addPolicies`、`updatePolicies`、listing。

失败：平台 `msg`。成功：打印「上架成功」，再 `info` 确认 `status===1`。

---

## 3. 下架

```
freelog-cli offline
```

| 情况 | 行为 |
|------|------|
| 已是 4 或 0 | 打印当前状态，不必再 PUT（0 本来就没上架） |
| `status===1` | TTY 确认「下架资源」 |

确认后 `Resource.update` 体只有 `status: 4`。不要用 `status:0`。  
成功：「已下架」。

`--yes`：跳过确认。下架不要求策略；冻结仍失败。

---

## tools-lib

| 何时 | 函数 | HTTP | 体 |
|------|------|------|-----|
| 预检 / 门禁 | `Resource.info` | `GET /v2/resources/{id}` | — |
| 上架 | `Resource.update` | `PUT /v2/resources/{id}` | `status: 1` |
| 下架 | `Resource.update` | 同上 | `status: 4` |

---

## 禁止

`update --status`。上架时夹带加策略。无版本或无启用策略仍 PUT。下架写成 `status:0`。
