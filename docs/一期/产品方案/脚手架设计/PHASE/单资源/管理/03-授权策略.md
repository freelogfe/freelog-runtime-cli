# 授权策略

对照业务：Console「授权策略」（P0-M3）。终端里是 `policy` 一组命令。当前后端按资源类型筛选模板的接口存在错误，CLI 暂时请求并展示平台返回的**全部**模板，包含带 `TransactionEvent` 的模板；不在客户端按免费、付费、事件或类型猜测过滤。后端修复筛选契约后再恢复按类型请求。CLI 不提供策略编辑器、支付或执行预览。添加策略本身不会支付，也不会自动上架。

本组命令功能：

| # | 功能 | 命令 |
|---|------|------|
| 1 | 看策略列表 | `policy list` |
| 2 | 加一条策略 | `policy template apply` / `policy apply --from-file` |
| 3 | 启用 | `policy set --on` |
| 4 | 停用 | `policy set --off` |

```
freelog-cli policy list
freelog-cli policy template list
freelog-cli policy template apply <templateId>
freelog-cli policy apply --from-file <path>
freelog-cli policy set --id <policyId> --on
freelog-cli policy set --id <policyId> --off
```

须已 `login`，已有 `resourceId`。本人、未冻结。不要求已有 `latestVersion`。  
资源已上架时，至少保留一条启用（关到 0 条启用要失败）。

---

## 0. 门禁

`Resource.info`（`GET /v2/resources/{id}`，`isLoadPolicyInfo=1`）。非本人 / 冻结失败。

没有策略时打一行：

> 添加并启用授权策略之后，资源才能上架。授权策略也可以稍后添加。

---

## 1. 看策略列表

```
freelog-cli policy list
```

`Resource.info`（`isLoadPolicyInfo=1`，`isTranslate=1`）。

先以资源当前的最终叶子类型为锚，从平台资源类型树取得该叶子及其**全部**上级节点。页头必须按根到叶子的顺序打印完整类型链，例如 `资源类型：祖父节点 / 父节点 / 叶子节点`；不能只打印叶子，也不能按标题或本地猜测祖先。类型树不包含当前叶子或任一级名称缺失时，失败并提示平台类型链无法确认；不要降级成只显示 `typeCode` 或叶子名。

空：先打印完整类型链，再打印「还没有授权策略」，提示去 §2。结束。
有：每行 `policyId`、名称、启用/停用。启用的排前面。页头显示总数，例如 `共 3 条授权策略`；**一次输出全部策略，不分页**，不提供 `--page`、`--page-size` 或翻页交互。资源自身策略是当前资源的小型配置集合，不应被模板目录式分页打断。

本项只读。不要在 list 里开关、缓存类型链或写入本地状态。

---

## 2. 加一条策略

问法和创建 Step3 相同，写在这里，开发不必再跳去 Step3。

`--yes` 必须带 `<templateId>` 或 `--from-file`，缺了失败。

### 2.1 列出平台返回的全部模板（后端修复前的临时契约）

```
freelog-cli policy template list
```

先读取已绑定身份并完成本人、未冻结门禁；当前调用 `Policy.policyTemplates`（`POST /v2/translate/translate-config/list4Client`）使用空请求体 `{}`。已确认：在当前 dev 接口上传入 `resourceTypeCodes4Resource` 会错误过滤结果。该临时行为不代表类型筛选被废弃；等待后端提供正确筛选契约后，才恢复传入当前 `typeCode`。

模板列表必须完整保留平台返回的结果；打表显示模板 id、名称及平台可提供的收费 / 事件摘要，**不得**按免费、付费或 `TransactionEvent` 过滤。平台不提供分页时由 CLI 在完整结果上固定每页 20 条分页：TTY 提供「上一页 / 下一页 / 退出」，切页不重复请求平台；非 TTY 只输出首页和剩余数量提示。没有 `--page`、`--page-size` 参数。当前模板的最终适用性由平台重新编译和资源写入接口判定，CLI 不伪造本地类型判断。

空列表：提示 `policy apply --from-file`，或去 Console。不要伪造模板。

帮助：选中推荐模板可以快速添加策略。

### 2.2 选定模板或文件

| 进入 | 行为 |
|------|------|
| `policy template apply [templateId]` | 给 id 时必须属于本次完整返回列表；模板可为免费或带交易事件，最终适用性由平台判定 |
| TTY 未给 id | 分页选择模板；用户可翻页或取消 |
| 非 TTY / `--yes` 未给 id | 失败；绝不从列表顺序猜一条 |
| `policy apply --from-file <path>` | 读本地策略文本或 `{ policyName, policyText }` JSON；可含交易事件，交由平台做语义校验 |

不要在终端里做策略编辑器预览。

### 2.3 策略名

问：「策略名称」。hint：2–20 个字符。

| 输入 | 行为 |
|------|------|
| 空 | 用模板自带名称；也没有则失败 |
| 空白或 >30 | 「策略名须为 1–30 个字符」，重新问 |
| 与已有策略名或策略文本完全重复 | 失败，换一个名或换模板 |

`--yes`：`--name` 可覆盖模板名；不传就用模板名。模板路径先调用平台 `reCompile`，再使用返回的正文；`--from-file` 直接读取本地文本。当前 CLI 只提交模板报告 UI 提供的默认参数值，不提供时间、金额、事件等参数填写界面。涉及这些参数或事件语法的模板，等待后端给出可被资源写接口接受的编译契约后，再设计参数输入和映射；不得猜测或字符串替换业务语义。本地只做非空、JSON 形状、名称与重复性校验；策略语义、交易事件与适用权限由平台决定。

### 2.4 确认追加

TTY 摘要：策略名、来源。确认「添加授权策略」。取消不写。

`Resource.update`（`PUT /v2/resources/{resourceId}`）：

```
addPolicies: [{
  policyName: 上一步,
  policyText: encodeURIComponent(文本),
  status: 1
}]
```

不传资源 `status`、不传 listing。  
成功：再走 §1 打列表。不要问「是否立即上架」。

---

## 3. 启用

```
freelog-cli policy set --id <policyId> --on
```

### 3.1 选定哪一条

| 进入 | 行为 |
|------|------|
| `--id` | 必须是本资源已有策略 |
| TTY 未传 | 用 §1 的列表 `select` |
| `--yes` 未传 id | 失败 |

### 3.2 写入

TTY 摘要后确认「启用策略 {名称}」。

`Resource.update` **只带** `updatePolicies: [{ policyId, status: 1 }]`，不带资源 `status`。写入前必须确认 id 属于当前资源且当前资源可编辑。

失败：平台 `msg`。成功：再 §1。

---

## 4. 停用

```
freelog-cli policy set --id <policyId> --off
```

选定同 §3.1。必须带 `--off`。

额外门禁：资源已上架（`info.status===1`）且这是最后一条启用策略 → 失败，「上架资源至少保留一条启用策略」。`--on` 和 `--off` 必须且只能提供一个。

TTY 确认「停用策略 {名称}」。`updatePolicies: [{ policyId, status: 0 }]`。成功再 §1。
