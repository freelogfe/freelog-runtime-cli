# 授权策略

单资源策略添加的公共设计见 [参数化策略模板](../../../ARCHITECTURE/09-参数化策略模板.md)。本页只描述单资源目标、列表与启停；不要在此复制模板参数、编译或创建逻辑。

```text
freelog-cli policy list
freelog-cli policy template list
freelog-cli policy template info <templateId>
freelog-cli policy template apply <templateId>
freelog-cli policy set --id <policyId> --on|--off
```

## 1. 目标与列表

每个命令先从绑定单资源身份解析目标，并实时读取 `Resource.info`。目标设计是用远端事实确认本人、单资源主体和最终叶子 `typeCode`；标题缓存不能选择资源。只读列表/模板查询允许冻结资源查看，添加或启停前还须确认未冻结。**当前代码差异**：只读模板入口仍取本地身份的 `typeCode`，本人/冻结严格校验只在写入阶段执行；以 [09 第 8 节](../../../ARCHITECTURE/09-参数化策略模板.md#8-实现边界与验收) 的待补项为准，不能把目标规则误记为已实现。

`policy list` 只读：从类型树取得根到叶的完整类型链，打印全部已有策略（`policyId`、名称、on/off），启用项在前；策略数量有限，**永不分页**。空列表仍先打印类型链，再提示可以添加策略。

## 2. 添加策略

模板列表、`info`、交互编辑、编号参数、`reCompile`、翻译预览、追加策略与读回，目标规则全部遵循公共设计；当前代码与验收差异见公共设计第 8 节。模板策略不读取或生成本地 JSON；`policy apply --from-file` 不属于当前公开命令面。未来手写 DSL 的独立入口见 [10-策略语言接入](../../../ARCHITECTURE/10-策略语言接入.md)，尚未实现。

## 3. 启用与停用

`policy set --id <policyId> --on|--off` 只能操作当前资源读回的策略，策略 ID 必须显式给出。

写入只允许：

```ts
Resource.update({ resourceId, updatePolicies: [{ policyId, status: 0 | 1 }] })
```

资源已上架且该策略是最后一条启用策略时，`--off` 必须失败。写入后重读确认；不传资源 `status`，也不自动上下架。
