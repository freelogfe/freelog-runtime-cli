# 授权策略

对照业务：Console「授权策略」（P0-M3）。终端里是 `policy` 一组命令。无付费、无 `TransactionEvent`、无执行预览。加完**不要**追问上架。

本组命令功能：

| # | 功能 | 命令 |
|---|------|------|
| 1 | 看策略列表 | `policy list` |
| 2 | 加一条免费策略 | `policy template apply` / `policy apply --from-file` |
| 3 | 启用 | `policy set --on` |
| 4 | 停用 | `policy set --off` |

```
freelog-cli policy list
freelog-cli policy template list
freelog-cli policy template apply <templateId>
freelog-cli policy apply --from-file <path>
freelog-cli policy set --id <policyId> --on
freelog-cli policy set --id <policyId> --off
```

须已 `login`，已有 `resourceId`。本人、未冻结。不要求已有 `latestVersion`。  
资源已上架时，至少保留一条启用（关到 0 条启用要失败）。

---

## 0. 门禁

`Resource.info`（`GET /v2/resources/{id}`，`isLoadPolicyInfo=1`）。非本人 / 冻结失败。

没有策略时打一行：

> 添加并启用授权策略之后，资源才能上架。授权策略也可以稍后添加。

---

## 1. 看策略列表

```
freelog-cli policy list
```

`Resource.info`（`isLoadPolicyInfo=1`，`isTranslate=1`）。

空：打印「还没有授权策略」，提示去 §2。结束。  
有：每行 `policyId`、名称、启用/停用。启用的排前面。

本项只读。不要在 list 里开关。

---

## 2. 加一条免费策略

问法和创建 Step3 相同，写在这里，开发不必再跳去 Step3。

`--yes` 必须带 `<templateId>` 或 `--from-file`，缺了失败。

### 2.1 列出模板

```
freelog-cli policy template list
```

`Policy.policyTemplates`（`POST /v2/translate/translate-config/list4Client`），`resourceTypeCodes4Resource: [当前 typeCode]`。

打表：模板 id、名称、是否免费。  
含 `TransactionEvent` / 付费的不要列为可申请（或列了但选中失败：「本期只加免费策略」）。

空列表：提示 `policy apply --from-file`，或去 Console。不要伪造模板。

帮助：选中推荐模板可以快速添加策略。

### 2.2 选定模板或文件

| 进入 | 行为 |
|------|------|
| `policy template apply <templateId>` | 用这条。id 不在列表或付费 → 失败 |
| TTY 未给 id | 用免费列表 `select`，必须选一条或取消 |
| `policy apply --from-file <path>` | 读本地策略文本。仍禁止付费事件 |

不要在终端里做策略编辑器预览。

### 2.3 策略名

问：「策略名称」。hint：2–20 个字符。

| 输入 | 行为 |
|------|------|
| 空 | 用模板自带名称；也没有则失败 |
| 1 或 >20 | 「策略名须为 2–20 个字符」，重新问 |
| 与已有策略名或策略文本完全重复 | 失败，换一个名或换模板 |

`--yes`：`--name` 可覆盖模板名；不传就用模板名。  
策略文本来自模板 `defaultValue` 或 `--from-file`。要改文本用 `--from-file`。

### 2.4 确认追加

TTY 摘要：策略名、来源。确认「添加授权策略」。取消不写。

`Resource.update`（`PUT /v2/resources/{resourceId}`）：

```
addPolicies: [{
  policyName: 上一步,
  policyText: encodeURIComponent(文本),
  status: 1
}]
```

不传资源 `status`、不传 listing。  
成功：再走 §1 打列表。不要问「是否立即上架」。

---

## 3. 启用

```
freelog-cli policy set --id <policyId> --on
```

### 3.1 选定哪一条

| 进入 | 行为 |
|------|------|
| `--id` | 必须是本资源已有策略 |
| TTY 未传 | 用 §1 的列表 `select` |
| `--yes` 未传 id | 失败 |

### 3.2 写入

TTY 摘要后确认「启用策略 {名称}」。

`Resource.update` **只带** `updatePolicies: [{ policyId, status: 1 }]`，不带资源 `status`。

失败：平台 `msg`。成功：再 §1。

---

## 4. 停用

```
freelog-cli policy set --id <policyId> --off
```

选定同 §3.1。必须带 `--off`。

额外门禁：资源已上架（`info.status===1`）且这是最后一条启用策略 → 失败，「上架资源至少保留一条启用策略」。

TTY 确认「停用策略 {名称}」。`updatePolicies: [{ policyId, status: 0 }]`。成功再 §1。

## 禁止

`update --status` 代替开关。加完自动上架。付费策略。合集前缀（暂缓）。
