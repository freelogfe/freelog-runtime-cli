# 依赖

本页适用于所有单资源（图片、视频、主题、插件等）。首版、更新版及 `version dep add|range|rm|list` 共用规则。当前 CLI 暂停签约；依赖声明与消费授权分开处理。

## 0. 声明不等于授权

2026-10-13 dev 实验：新主题、图片、视频与合集对 6 个目标逐个及组合提交，共 28 次均成功；版本/快照读回准确，双方合约始终为 0，平台没有自动签约。详见[无合约试验](../../../../../../../test/DEV-无合约依赖试验-2026-10-13.md)。

因此本期 CLI 可以无合约添加依赖并发行版本，不查合约、不选策略、不签约、不付款，也不在提交前要求合约存在。Console 声明器要求先签约是其当前前端交互规则，不是本实验发现的平台写入前置；CLI 不必把该交互复刻为硬门禁。

`Resource.batchAuth` 不能证明当前资源与目标有合约，也不作为本期声明前置。声明成功不代表已获访问授权。需要授权时，用户到网页当前资源的“依赖及其授权”中处理；乙方应是当前资源 ID（身份 1），不是用户个人。合集是身份 4，按独立合集文档处理。

本期仍不处理基础上抛、授权排除项、合集/存储对象作为单资源依赖。不读取或修改 Console 草稿。本人其它资源与他人资源使用相同的声明校验。

## 1. 添加依赖

```text
核对当前资源身份、环境、owner、可写状态
  → 查询依赖目标的类型、状态、已发布版本及基础上抛
  → 校验版本范围命中
  → 用当前资源 ID 检查完整候选依赖是否成环
  → 原子写入本地依赖声明；不执行签约/支付
```

### 1.1 问目标

输入资源 ID 或完整 `username/name`，不能依赖当前资源自身。不能按可变且可重复的标题定位目标。

### 1.2 定位

经 `Resource.info` 获取真实目标，按当前资源 ID 重读自身核对 owner 与冻结状态。目标必须是可用的已发布单资源，有可信 latest；不存在、错误身份、未发行、冻结、下架、基础上抛或缺少可信字段均保持原稿不变。跨环境、未登录、未绑定和非本人目标维护仍被拒绝。

不为了添加依赖读取策略列表；目标没有启用策略或尚未签约，不因此阻止依赖声明。

### 1.3 版本范围

读取 `Resource.getVersionListByResourceID`。范围须可由 semver 解析，并命中至少一个已发布版本；默认 `^latest`，不将非法输入改成 `*`。依赖已存在时更新同一条范围，不创建重复声明。

### 1.4 循环依赖

使用 `Resource.cycleDependencyCheck({resourceId:当前资源ID, dependencies:完整候选列表})`。成环或接口失败不写稿。检查根不能误用对方 ID。

### 1.5 命令与写盘

```text
version dep add <resourceId|username/name> [--range <range>]
version dep range <resourceId> --range <range>
version dep list
version dep rm <resourceId>
```

删除 `--policy-id`，不保留隐藏签约入口或无效兼容参数。全局 `--yes` 仍可用于其他操作，但添加/改范围不会因它发起签约。

工作稿仅保存 `dependencies:[{resourceId,versionRange}]`，单资源本期 `baseUpcastResources` 和 `authExcludedItems` 保持空数组。不写合同 ID、策略 ID或支付状态到工作稿或永久身份缓存。

添加/修改成功时提示“仅声明依赖，CLI 未签约或支付；需要授权请到网页以当前资源身份处理”，不称已授权、已签或已支付。

## 2. 管理依赖

`list` 仅列本地声明，不能据此判断合约或访问授权。`rm` 只删除当前工作稿的目标，不解约、不退款；没有该依赖时明确失败。

`range` 重走目标、版本与循环校验，再更新原条范围。没有目标或校验失败时保留稿。不换资源 ID，换目标需删后再加。

## 3. 提交（首版与更新版共用）

旧稿、手改 JSON 和线上 pull 稿均按最终完整声明提交，不增加合约查询或签约。仍校验依赖条目的有效 resourceId；文件、分析、属性、可选配置、版本号、身份及恢复事务等原有门禁不取消。

版本 payload 为 `dependencies:[{resourceId,versionRange}]`，`baseUpcastResources:[]`、`authExcludedItems:[]`，不含 `batchSignContracts`。平台拒绝时保留稿并报告错误；未知 POST 结果按原 recover 流程只读核验，不能自动重发。

## 4. 更新版本

`version draft pull` 仅拉依赖声明；add/range 按第 1 节处理，再发行新号。缺合约不删树、不阻止声明或提交，也不自动创建合同。基础上抛仍遵守本期边界，不因暂停签约而开放。

## 5. 已发布版本与网页授权

已发布单资源的依赖树不可原地修改；更改依赖须建立更新稿并发行新号。`version description` 只改说明，删除声明不会撤销已有合同。

网页签约/支付是另一个操作阶段；CLI 不保证无合约依赖可以运行时消费、不保证所有平台类型或策略的访问授权。授权判定以平台及当前资源身份的合约为准，不能把个人签约视为当前资源签约。

## tools-lib

| 目的 | 方法 |
|---|---|
| 自身与依赖详情 | `Resource.info` |
| 可用版本 | `Resource.getVersionListByResourceID` |
| 完整候选循环检查 | `Resource.cycleDependencyCheck` |
| 版本写入 | `Resource.createVersion` |

所有请求仍经本仓 tools-lib。不从 CLI 依赖路径调用 Contract 签约/查询或 batchAuth。对外新增授权策略（`policy template`）是作者配置自己的授权条款，不等于签约，不受本次暂停影响。
