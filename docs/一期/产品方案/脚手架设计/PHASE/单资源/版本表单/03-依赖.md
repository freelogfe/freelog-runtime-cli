# 依赖

对照业务：发行时的依赖授权。终端**不嵌微前端**，把「查资源 → 选版本范围 → 免费签约 → 上抛」拆成一步步问。只在 `create-version` / `update-version` 菜单 5 / 6。

| 场景 | 能做什么 |
|------|----------|
| 发行版本菜单 5 / 6 | 空表上加、改范围、删；加的时候当场免费签 |
| 更新版本菜单 5 / 6 | 先回显上一版依赖，再加、改范围、删 |
| 已发版 | **不能**改树。看树 / 补签见 [管理/04](../管理/04-依赖及其授权.md) |

没有独立的 `dep add`。付费、`TransactionEvent`、须微前端完成的签约：失败并提示去 Console。自己的资源当依赖 **也要签**。

提交时：有依赖但未签完 → 不能 `createVersion`，「依赖中存在未获取授权的资源」。

---

## 1. 发行：添加（菜单 5）

一次只加一条。做完写盘，回菜单。想再加再选 5。

```
1 问目标
  → 2 定位到恰好一条普通资源
  → 3 选 versionRange
  → 4 循环依赖检查
  → 5 选免费策略并签约
  → 6 是否上抛
  → 7 写入工作稿
```

中途失败：这条不加，已问的作废，回菜单。不要留下半条依赖。

### 1.1 问目标

「依赖的资源：resourceId 或 username/name」。

| 输入 | |
|------|--|
| 空 | 重新问 |
| 含 `/` | 当 `username/name`（短标识段仍按平台规范化理解） |
| 否则 | 当 `resourceId` |

不能填自己（本资源 `resourceId` 或自己的 `username/name`）：「不能依赖自己」。

### 1.2 定位

`Resource.info`（`GET /v2/resources/{resourceIdOrName}`），CLI 传未预编码的 id 或 `username/name`。

| 结果 | |
|------|--|
| 没有 / 平台错误 | 「找不到该资源」，回菜单 |
| `subjectType!==1` | 不加（合集、其它标的本期不当依赖） |
| 对方没有 `latestVersion` | 不加，「对方还没有发行版本」 |
| 恰好一条普通资源 | 打印标题、`username/name`、latest，继续 |

### 1.3 版本范围

`Resource.getVersionListByResourceID`（`GET /v2/resources/{对方id}/versions`）。打印对方已发版（新的在前）。

问「版本范围」。hint：须是 semver 可解析范围，例如 `*`、`^1.2.0`、`>=1.0.0`。  
默认建议：`^` + 对方 `latestVersion`（用户能整段改掉）。

非法：重新问。不要默默改成 `*`。

同一依赖（同一 `resourceId`）工作稿里已有：走「改范围」而不是再加一条。本步应提示「已在依赖中，将改范围」或让用户去菜单 6。

### 1.4 循环依赖

`Resource.cycleDependencyCheck`（`POST /v2/resources/{本资源id}/versions/cycleDependencyCheck`）。

体：`dependencies` = 工作稿已有的 + 正要加的这一条 `{ resourceId, versionRange }`。

平台判循环：打印 `msg`，不加。

### 1.5 免费签约

拉对方策略：`Resource.info`（对方 id，`isLoadPolicyInfo=1`）。

只保留：`status===1` 且策略文本 **不含** `TransactionEvent`（大小写不敏感，与现网检测一致）。

| 情况 | |
|------|--|
| 一条免费 | 默认用它，TTY 仍展示名称让用户确认 |
| 多条免费 | `select` 选一条 |
| 零条 / 只有付费 | 不加。提示去 Console 完成付费或微前端授权 |
| 用户取消选策略 | 不加 |

确认后 `Contract.batchCreateContracts`（`POST /v2/contracts/batchSign`）：

| 字段 | 值 |
|------|-----|
| `subjectType` | `1` |
| `licenseeId` | **本资源** `resourceId` |
| `licenseeIdentityType` | `1` |
| `subjects` | `[{ subjectId: 对方 resourceId, policyId }]` |

若平台还要乙方版本：发行版本用 `1.0.0`；更新版本用即将发行的新号（尚未 POST 也可以，与 Console `licenseeVersion=versionInput` 一致）。

签约失败：不加依赖。  
`authExcludedItems` 里已经排除了对方某策略/合约：按 Console，提交时若带了排除项，**不要**再带 `batchSignContracts`。本步若对方被排除：不要强行签，写入排除信息，提交靠排除项通过授权检查（以实现与平台为准，吃不准就当失败并提示 Console）。

### 1.6 上抛

问：「是否上抛此依赖？（上抛后，使用本资源的人要再解决这一层）」是 / 否。默认否。

是：工作稿 `baseUpcastResources` 追加 `{ resourceId: 对方id }`（已有则不重复）。  
否：只进 `dependencies`。

不要发明第二种上抛结构。

### 1.7 写盘

`N.version.json`：

```
dependencies: [{ resourceId, versionRange }]
baseUpcastResources: [{ resourceId }]     // 仅勾了上抛的
authExcludedItems: [{ resourceId, excludedType, excludedValue }]  // 仅确有排除时
```

不写合约 id 进 `N.json`。回菜单。快照上这条标「已签」或「已排除」。

## 2. 发行：管理（菜单 6）

列出工作稿依赖：`username/name`（没有就 id）、`versionRange`、是否上抛、是否已签。

选一条，再选：

### 2.1 删除

确认后从 `dependencies` 去掉；若在 `baseUpcastResources` / `authExcludedItems` 里也去掉。  
**不**调解约 API（平台本步没有必须解约）。写盘，回菜单。

### 2.2 改范围

问新 `versionRange`（规则同 §1.3）。再跑 §1.4。需要则按 §1.5 再签一次（免费策略可默认上次那条）。写盘。

### 2.3 改上抛

是 ↔ 否，只改 `baseUpcastResources`。不重签。

没有「改成另一个 resourceId」：先删再加。

## 3. 提交时带什么（发行）

`createVersion`：

| 字段 | |
|------|--|
| `dependencies` | 工作稿全部 `{ resourceId, versionRange }` |
| `baseUpcastResources` | 工作稿上抛 |
| `batchSignContracts` | 本进程里**还需要**带上的免费签；有对应 `authExcludedItems` 则不带 |
| `authExcludedItems` | 有则原样 |

`--yes`：不进会话。提交前对工作稿里未签的依赖按 §1.5 自动签（策略只有一条免费才敢自动选；多条免费或没有免费：`--yes` 失败，要求进会话或先改工作稿）。

---

## 4. 已发版

已发版不能改依赖树。`version description` 只改描述，不要出现菜单 5 / 6。  
看树、补签：`dep list` / `dep auth`，见 [管理/04](../管理/04-依赖及其授权.md)。要改树走 [更新版本](../更新版本/01-更新版本.md)。

## tools-lib

| 何时 | 函数 | HTTP |
|------|------|------|
| 查目标 | `Resource.info` | `GET /v2/resources/{resourceIdOrName}` |
| 对方版本列表 | `Resource.getVersionListByResourceID` | `GET /v2/resources/{id}/versions` |
| 循环 | `Resource.cycleDependencyCheck` | `POST /v2/resources/{本id}/versions/cycleDependencyCheck` |
| 对方策略 | `Resource.info`（`isLoadPolicyInfo=1`） | 同上 GET |
| 免费签 | `Contract.batchCreateContracts` | `POST /v2/contracts/batchSign` |

不用微前端。不用 `Resource.batchSetContracts`（那是按版本挂策略）。不用 `dep add`。
