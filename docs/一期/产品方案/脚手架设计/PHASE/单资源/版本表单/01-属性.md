# 属性

对照业务：Console 属性编辑器。标题 / 简介 / 封面不是属性，见 [Step4](../创建/04-Step4-完善资源信息.md)。  
问法只写在本文。会话菜单和 `version attr add|set|rm|list` 共用（[05](../../../ARCHITECTURE/05-版本工作稿与独立命令.md)）。  
[发行版本](../创建/02-Step2-发行版本.md) 空表起步；更新路径须先有稿（`version draft pull` 或 `update-version` 无稿时顺带拉）。

帮助（工作稿还没有自定义、或第一次选菜单「添加属性」时打）：

> 资源属性主要用于存储一些资源相关信息，您可以根据需要为您的资源添加更多的信息，方便更好的展示您的作品，同时也让其他用户更快的找到和了解您的作品。

两种用法：

| 场景 | 能做什么 | 写哪 |
|------|----------|------|
| 发行版本会话 / `version attr`（首版稿） | 空表上加、删、改自定义；改系统附加的 value | 立刻写 `N.version.json` |
| 更新路径（已有更新稿） | 在稿上加、删、改 | 立刻写 `N.version.json` |
| 已发版 | **不能改**属性。看用 `version show`；要改先 `version draft pull` 再改稿 | — |

## 1. 三种属性，别混

文件解析之后（见 Step2「解析系统属性」）本进程里有三类：

| 种 | 怎么来 | 发行会话 | 已发版 |
|----|--------|----------|--------|
| 系统 `raw` | `metaInfoArray.insertMode===1` | 快照展示；**空值不展示**；不能改、不能删、不进工作稿 | 只读 |
| 系统附加 | `insertMode===2` | 先解析稿内 `fileSha1`，确认当前格式；成功编辑时保证 `analyzedSha1===fileSha1`，且有 `valueConfig` 才可改 **value**；不能删 key、不能改 key/名称 | 只读 |
| 自定义 | 发行者加 | 可加可删可改名称/值/说明；**key 一经写下不改**（Console 能改 key，CLI 不跟随；换键 = 删整条再加） | 只读 |

自定义最多 **30** 条。满了：「最多可添加30个属性」，不要再进「添加」。  
自定义 **值** 最长 **140**（Console 版本创建页 `value_Editable.text.maxLength=140`；创建向导 Step2 为 100，Console 两入口自身不一致，CLI 取 140。2026-09-07 真网验证平台接受 140。出处见 [业务梳理/字段级校验对照表](../../../../业务梳理/字段级校验对照表.md) §2/§7/§8）。可空。
自定义 **名称** 最长 **50**（`alert_naming_convention_attribute_name`）、**说明** 最长 **50**（`alert_key_remark_length`），出处同上 §2。

key / 名称在「系统 raw + 系统附加 + 自定义 + 可选配置」里必须唯一（和 key 撞、和别人的 **名称** 撞都不行）。创建自定义属性/可选配置前读取当前资源类型的 `attrs`；已有文件时也检查该 SHA 的完整系统字段。raw 空值可以不展示，但不能因此失去重名保护。

解析后若继承数据或人工编辑的工作稿与系统 key / 名称冲突：阻止提交并列出冲突项，保留工作稿，不静默删除用户数据、不以自定义值覆盖系统项。`bundleTool` 和 `noderuntime_target_version` 等系统键必须用系统附加入口填写，不能用 `attr add` 或 `option add` 创建。清理冲突自定义项后，再按平台定义填写对应附加值。

## 2. 解析之后系统附加的 value 怎么问

附加项的填法看 `valueConfig`（由 `Resource.getAttrsInfoByKey` 按 `format` 拼出来）。**不要猜格式。**

上传只提交带真实文件名和 MIME 的 `file`；不带 `resourceType`。随后通过 `Storage.filesListInfoSse`（`GET /v2/storages/files/listSSE/info`）以 `sha1` + `resourceTypeCode` 请求对应资源类型的解析器。0/1 继续等；2 和 3 均按 Console 当前行为读取 `metaInfoArray` 进入会话，3 不是 CLI 可推断的发行失败。**从连接起最长 120 秒**；未收到终态、流无效或连接异常才失败，不进会话。

成功、格式失败、连接结束未完成和超时都必须关闭 SSE 连接，清理不得覆盖原解析结果或错误。Node 端以原流对象调用关闭方法；使用真实 Node Readable 对四条路径做回归，不能只用不依赖对象上下文的模拟流。
`insertMode===2` 的 key 再逐个 `Resource.getAttrsInfoByKey`（`GET /v2/resources/attrs/getInfoByKey`）。

| `format` | `valueConfig` | 终端怎么问 | 校验 |
|----------|---------------|------------|------|
| 4 | `date` | 「日期 YYYY-MM-DD」 | 落在 `startDate`～`limitDate`（缺省 1000-01-01～9999-12-31） |
| 5 | `dataTime` | 「时间 YYYY-MM-DD HH:mm:ss」 | 落在 `startDateTime`～`limitDateTime` |
| 6 | `text` | 单行文本 | 长度 `minLength`～`maxLength`（缺省 0～140） |
| 7 | `textArea` | 可多行 | 同上 |
| 8 | `integer` | 整数 | `min`～`max` |
| 9 | `decimal` | 小数 | `minDecimal`～`maxDecimal`，小数位 ≤ `precision` |
| 10 | `configEnum` | **下拉**，选项 = `allowedElements` | 必须是选项之一 |
| 其它 / 没有 valueConfig | — | **不要问**，当只读展示 | 不能改 |

`nullable===true`（当前拼出来都是 true）时：空值允许，表示清空附加 value。每次展示或编辑系统附加属性前，必须按 [本地状态 §2.2.1](../../../ARCHITECTURE/02-本地状态.md#221-工作稿不变量与文件分析) 重新取得稿内 SHA 对应的格式；没有 SHA 时先准备文件，只有成功编辑才写分析标记。分析 SHA 过期或仍有 `orphanedInputAttrs` 时不能直接提交。
发行时工作稿已有同 key 的 `inputAttrs`：值仍符合当前定义时带出，保留 `""`，不能用 `||` 把清空值替换成默认值。平台数字边界 `0`、精度 `0` 都是有效配置；整数/小数必须完整匹配输入，不能用 `parseInt` / `parseFloat` 接受数字前缀或静默截断精度；日期须校验真实日历日期。

`version draft pull` 以及 `update-version` 自动继承旧版本时，附加值从线上版本的 `systemPropertyDescriptors` 中筛选 `insertMode===2`，读取 `valueDisplay`，归一为 `{key,value:string}`。`inputAttrs` 是提交字段，不假定版本详情也会返回它。资源版本号与 `noderuntime_target_version` 无关；后者是运行时目标版本。CLI 不猜任意工程的构建工具或写死运行时版本，不全局强制这些 nullable 字段非空；应展示未填项供用户明确设置。

改完一条：写工作稿 `inputAttrs`（用户填写或从已发版本恢复的 additional `{key,value}`）。文件分析变更时，保留 / 转入 `orphanedInputAttrs` / 清除的规则只认本地状态 §2.2.1，本文不得另设“本地优先”覆盖规则。`orphanedInputAttrs` 是待复核队列：用 `version attr review` 查看；同 key 在后续分析重新出现且旧值通过当前规则才自动恢复；确认永远不要再用时才执行 `version attr review discard <key>` 并确认。已发版上不要问、不要 PUT 属性。

## 3. 发行：添加自定义

菜单选「添加属性」。标题：「添加属性」。

先问填法（默认逐项问）：

| 选项 | 走哪 |
|------|------|
| 逐项问 | §3.1–3.4，再 §3.5 预览 |
| 一行式 | §3.0，再 §3.5 预览 |

独立命令 `version attr add`：带了一行或带齐参数 → §3.0；TTY 没带齐 → 逐项问；`--yes` 没带齐 → 失败。

### 3.0 一行式

字段（只要这些）：

| 字段 | 必填 | 规则 |
|------|------|------|
| 名称 | 是 | 同 §3.1 |
| 键 | 是 | 同 §3.2 |
| 说明 | 否 | 同 §3.3，可省略 |
| 值 | 否 | 同 §3.4，可省略 = `""` |

```
名称=作者 键=author 说明=作品作者 值=张三
```

语法见 [版本表单 README](./README.md)。字段输入解析失败：指出哪一字段，不写盘，TTY 可重输。
`attr add` 的一行式仅添加自定义属性。系统附加用 `attr set "键=<key> 值=<value>"`，见 §4.3；不能通过写入同名自定义属性绕过平台格式。

### 3.1 名称（逐项）

逐项问时按下面顺序（和 Console 表单一致）。

提示：「名称」。hint：「输入名称」。非空。**最长 50 字**，超过重新问（`alert_naming_convention_attribute_name`）。  
不能和已有系统名称、自定义名称、可选配置名称相同。相同：「名称已存在」，重新问。

### 3.2 键

提示：「键」。hint：「输入键，键是此条目的唯一标识符」。

规则（`alert_naming_convention_key`）：

- 只能英文字母、数字、下划线
- **首字符必须是字母**
- 长度 1–30
- 不能和已有任何 key 相同（系统 / 自定义 / 可选配置）

不过：「请输入英文字母、数字或下划线，首字符必须为字母，长度不能超过30个字符」。

### 3.3 说明（选填）

提示：「说明（选填）」。hint：「输入说明」。可空。写入 `remark`。**最长 50 字**（`alert_key_remark_length`），超过重新问。

### 3.4 值（选填）

提示：「值」。hint：「输入值」。可空。最长 140。超过重新问（2026-09-07 真网验证平台接受 140，读回无截断）。

### 3.5 预览，确认后才写盘

不论逐项还是一行式，校验通过后先打：

```
即将写入自定义属性：
  名称：作者
  键：author
  说明：作品作者          # 空则打「（无）」
  值：张三                # 空则打「（空）」

写入工作稿？ [Y/n]
```

否：不写盘。TTY 可重来或回菜单。`--yes`：仍打印，不确认，直接写。  
是：追加到 `N.version.json` 的自定义列表。提交 `createVersion` 时映射：

```
{
  key, name,
  type: "readonlyText",
  defaultValue: 值（可 ""）,
  remark: 说明
}
```

不要 `editableText` / `select`（那是可选配置）。回会话菜单。

## 4. 发行：删除或修改

列出：

- 每条自定义：`名称 (key) = 值`，动作「改」或「删」
- 每条**有 valueConfig** 的系统附加：`名称 (key) = 值`，动作只有「改 value」
- `raw`：**不要出现在可选列表**（快照里已经展示过）

### 4.1 改自定义

**键不问、不改、不提供「改键」。** Console 能改 key，CLI 不跟随。换键：§4.2 删掉再 §3 加。

填法同添加：逐项问或一行式。逐项按 3.1 / 3.3 / 3.4 再问名称、说明、值（默认填当前）。一行式**不要**改 `键=`；写了且与当前条不同 → 失败。未写的字段保持原值（改不是整份清空）。名称仍要做唯一校验（自己这条除外）。走 §3.5 预览（标题改成「即将修改自定义属性」，多打一行「键：{key}（不可改）」），确认才写盘。

### 4.2 删自定义

确认「删除属性 {名称}？」。是：从工作稿去掉，回菜单。系统附加不能删。

### 4.3 改系统附加 value

独立入口：`version attr set "键=<key> 值=<value>"`。只接受键和值，值必须显式给出；`值=` 表示清空，省略值不能误清空。系统名称、说明与键不可修改。

按稿内 `fileSha1` 重新取得系统字段及平台格式，确认 `insertMode===2` 且 format 在支持范围后，按 §2 校验。拉稿后尚未设置 `analyzedSha1` 时，这次解析可以完成编辑前置；只有成功编辑才一并写入该 SHA 与值。不存在的键、raw、未知格式、错误值都失败且不改稿。提交仍会重新分析实际本地产物，不把来源文件解析当成本次本地文件已验证。

`version attr list` 展示自定义属性和稿内文件的全部附加字段，包括未填值、当前值、可编辑性与平台规则；raw 不提供编辑动作。已有文件时按稿内 SHA 重新读取，只读查询不写 `analyzedSha1`，不将格式缓存成工作稿主本。无文件时列出已有自定义项，并提示先 `create-version --prepare` 后查看系统附加项。

## 5. 已发版：不能改属性

某一版发出去之后，这一版的属性冻住。`version show` 只读。改描述见 [版本信息](../管理/01-版本信息.md)。  
要改 value / 加 key / 删：走 [更新版本](../更新版本/01-更新版本.md)。

## 6. 工作稿里属性怎么存

发行用的 `N.version.json` 片段（不要把 raw 写进去）：

```
inputAttrs: [{ key, value }]          // 仅系统附加、用户填过的
customPropertyDescriptors: [{
  key, name, type: "readonlyText",
  defaultValue, remark?
}]
```

可选配置也在 `customPropertyDescriptors` 里，但 `type` 是 `editableText` / `select`，见 [可选配置](./02-可选配置.md)。两套混在一个数组提交，会话里要分开列。

## tools-lib

| 何时 | 函数 | HTTP |
|------|------|------|
| 等文件元信息 | `Storage.filesListInfoSse` | `GET /v2/storages/files/listSSE/info`（`sha1`,`resourceTypeCode`） |
| 附加格式 | `Resource.getAttrsInfoByKey` | `GET /v2/resources/attrs/getInfoByKey` |
| 无文件、无 sha1 时的类型模板（本期单资源少用） | `Storage.filesInfo` | `GET /v2/storages/files/info` |

不要用 `Storage.fileProperty` 代替上面这条解析链（和 Console `handleData_By_Sha1...` 不一致）。

自定义写入只改本地稿，但为检查系统字段冲突会读取类型定义，必要时读取当前 SHA 的分析结果；纯重名检查不读取无关字段的编辑格式。提交走 `createVersion`，并重新校验附加值及系统重名、自定义/可选配置的类型、长度、数量、重复与下拉默认规则；直接改 JSON 不能绕过。同一次提交复用类型快照，但提交前仍重新取文件分析及所需格式，不跨命令缓存。不要用 `updateResourceVersionInfo` 改属性，不读写 Console 网页草稿。
