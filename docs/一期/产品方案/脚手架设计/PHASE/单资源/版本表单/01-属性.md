# 属性

对照业务：Console 属性编辑器。标题 / 简介 / 封面不是属性，见 [Step4](../创建/04-Step4-完善资源信息.md)。  
只在 `create-version` / `update-version` 会话里问（[发行版本](../创建/02-Step2-发行版本.md) 空表起步；[更新版本](../更新版本/01-更新版本.md) 先回显再改）。

帮助（工作稿还没有自定义、或第一次选菜单「添加属性」时打）：

> 资源属性主要用于存储一些资源相关信息，您可以根据需要为您的资源添加更多的信息，方便更好的展示您的作品，同时也让其他用户更快的找到和了解您的作品。

两种用法：

| 场景 | 能做什么 | 写哪 |
|------|----------|------|
| 发行版本会话 | 空表上加、删、改自定义；改系统附加的 value | 立刻写 `N.version.json` |
| 更新版本会话 | 回显上一版后再加、删、改 | 立刻写 `N.version.json` |
| 已发版 | **不能改**属性。看用 `version show`；要改去更新版本 | — |

---

## 1. 三种属性，别混

文件解析之后（见 Step2「解析系统属性」）本进程里有三类：

| 种 | 怎么来 | 发行会话 | 已发版 |
|----|--------|----------|--------|
| 系统 `raw` | `metaInfoArray.insertMode===1` | 快照展示；**空值不展示**；不能改、不能删、不进工作稿 | 只读 |
| 系统附加 | `insertMode===2` | 有 `valueConfig` 才能改 **value**；不能删 key、不能改 key/名称 | 只读 |
| 自定义 | 发行者加 | 可加可删可改名称/值/说明；key 一经写下不改 | 只读 |

自定义最多 **30** 条。满了：「最多可添加30个属性」，不要再进「添加」。  
自定义 **值** 最长 **100**（F0 Console 100；M0 Console 输入框 140，CLI 一律 100）。可空。

key / 名称在「系统 raw + 系统附加 + 自定义 + 可选配置」里必须唯一（和 key 撞、和别人的 **名称** 撞都不行）。解析后若 inherit / 工作稿里的自定义和系统 key 或名称撞了：**丢掉这条自定义**，不要盖系统项。

---

## 2. 解析之后系统附加的 value 怎么问

附加项的填法看 `valueConfig`（由 `Resource.getAttrsInfoByKey` 按 `format` 拼出来）。**不要猜格式。**

先 `Storage.filesListInfo` 轮询（`GET /v2/storages/files/list/info`，`sha1` + `resourceTypeCode`），直到 `metaAnalyzeStatus` 为 2 或 3。还是 0/1 就继续等。**从第一次请求起最长 120 秒**；超时仍是 0/1：「属性解析超时」。`===3` 或平台错误同样失败。失败则不进会话。不要调用会空转的 `getFilesSha1Info` 还不加超时。  
`insertMode===2` 的 key 再逐个 `Resource.getAttrsInfoByKey`（`GET /v2/resources/attrs/getInfoByKey`）。

| `format` | `valueConfig` | 终端怎么问 | 校验 |
|----------|---------------|------------|------|
| 4 | `date` | 「日期 YYYY-MM-DD」 | 落在 `startDate`～`limitDate`（缺省 1000-01-01～9999-12-31） |
| 5 | `dataTime` | 「时间 YYYY-MM-DD HH:mm:ss」 | 落在 `startDateTime`～`limitDateTime` |
| 6 | `text` | 单行文本 | 长度 `minLength`～`maxLength`（缺省 0～140） |
| 7 | `textArea` | 可多行 | 同上 |
| 8 | `integer` | 整数 | `min`～`max` |
| 9 | `decimal` | 小数 | `minDecimal`～`maxDecimal`，小数位 ≤ `precision` |
| 10 | `configEnum` | **下拉**，选项 = `allowedElements` | 必须是选项之一 |
| 其它 / 没有 valueConfig | — | **不要问**，当只读展示 | 不能改 |

`nullable===true`（当前拼出来都是 true）时：空值允许，表示清空附加 value。  
发行时工作稿已有同 key 的 `inputAttrs`：默认带出该值，解析结果不要盖掉。

改完一条：写工作稿 `inputAttrs`（只存用户填过的 additional `{key,value}`）。已发版上不要问、不要 PUT 属性。

## 3. 发行：添加自定义

菜单选「添加属性」。标题：「添加属性」。

按顺序问（和 Console 表单一致）：

### 3.1 名称

提示：「名称」。hint：「输入名称」。非空。  
不能和已有系统名称、自定义名称、可选配置名称相同。相同：「名称已存在」，重新问。

### 3.2 键

提示：「键」。hint：「输入键，键是此条目的唯一标识符」。

规则（`alert_naming_convention_key`）：

- 只能英文字母、数字、下划线
- **首字符必须是字母**
- 长度 1–30
- 不能和已有任何 key 相同（系统 / 自定义 / 可选配置）

不过：「请输入英文字母、数字或下划线，首字符必须为字母，长度不能超过30个字符」。

### 3.3 说明（选填）

提示：「说明（选填）」。hint：「输入说明」。可空。写入 `remark`。

### 3.4 值（选填）

提示：「值」。hint：「输入值」。可空。最长 100。超过重新问。

### 3.5 写入工作稿

立刻追加到 `N.version.json` 的自定义列表。提交 `createVersion` 时映射：

```
{
  key, name,
  type: "readonlyText",
  defaultValue: 值（可 ""）,
  remark: 说明
}
```

不要 `editableText` / `select`（那是可选配置）。回会话菜单。

---

## 4. 发行：删除或修改

列出：

- 每条自定义：`名称 (key) = 值`，动作「改」或「删」
- 每条**有 valueConfig** 的系统附加：`名称 (key) = 值`，动作只有「改 value」
- `raw`：**不要出现在可选列表**（快照里已经展示过）

### 4.1 改自定义

key **不问、不改**。按 3.1 / 3.3 / 3.4 再问名称、说明、值（默认填当前）。名称仍要做唯一校验（自己这条除外）。写盘，回菜单。

### 4.2 删自定义

确认「删除属性 {名称}？」。是：从工作稿去掉，回菜单。系统附加不能删。

### 4.3 改系统附加 value

按 §2 的格式问。写 `inputAttrs`，回菜单。

---

## 5. 已发版：不能改属性

某一版发出去之后，这一版的属性冻住。`version show` 只读。改描述见 [版本信息](../管理/01-版本信息.md)。  
要改 value / 加 key / 删：走 [更新版本](../更新版本/01-更新版本.md)。

---

## 6. 工作稿里属性怎么存

发行用的 `N.version.json` 片段（不要把 raw 写进去）：

```
inputAttrs: [{ key, value }]          // 仅系统附加、用户填过的
customPropertyDescriptors: [{
  key, name, type: "readonlyText",
  defaultValue, remark?
}]
```

可选配置也在 `customPropertyDescriptors` 里，但 `type` 是 `editableText` / `select`，见 [可选配置](./02-可选配置.md)。两套混在一个数组提交，会话里要分开列。

## tools-lib

| 何时 | 函数 | HTTP |
|------|------|------|
| 等文件元信息 | `Storage.filesListInfo` | `GET /v2/storages/files/list/info`（`sha1`,`resourceTypeCode`） |
| 附加格式 | `Resource.getAttrsInfoByKey` | `GET /v2/resources/attrs/getInfoByKey` |
| 无文件、无 sha1 时的类型模板（本期单资源少用） | `Storage.filesInfo` | `GET /v2/storages/files/info` |

不要用 `Storage.fileProperty` 代替上面这条解析链（和 Console `handleData_By_Sha1...` 不一致）。

添加自定义本身无 API。提交走 `createVersion`。不要用 `updateResourceVersionInfo` 改属性。
