# 版本表单（属性 / 可选配置 / 依赖）

每一问的真源在本目录。两处入口共用，**不要写第二套问法**：

1. `create-version` / `update-version` 会话菜单（一个会话做完）
2. `version attr` / `version option` / `version dep` 等独立命令（多次改缓存）

整体分层见 [05-版本工作稿与独立命令](../../../ARCHITECTURE/05-版本工作稿与独立命令.md)。

两套编排的**起步**不一样：

| 路径 | 工作稿起步 | 编排 |
|------|------------|------|
| [发行版本](../创建/02-Step2-发行版本.md) | 空表（没有上一版）。可 `create-version --prepare` 只建稿 | 创建 Step2 |
| 更新路径先有稿 | `version draft pull [--version]` 拉某一号；或 `update-version` 无稿时顺带拉 | 已有 `latestVersion` |
| [更新版本](../更新版本/01-更新版本.md) | 已有稿则改这份；无稿才按回显源拉。本命令管定新号 + 提交 | POST 新号 |

已发号上的属性 / 配置 / 依赖冻住：看线上用 `version show`；看本地工作稿用 `version show --local`；改已发号描述用 `version description`；要改数据先 `version draft pull`，再用独立命令或 `update-version`。不要用 `update-version --prepare`。

门禁、文件、提交见上面两篇。本文只写每一问；会话菜单和独立命令都走这里。

属性和可选配置有两种填法，**校验规则同一套**，不要写第二套约束：

| 填法 | 谁用 | 落盘前 |
|------|------|--------|
| **逐项问** | 会话默认。独立命令没带齐字段且是 TTY 时也走这里 | 问完打格式化预览，确认才写盘 |
| **一行式** | 一次给出全部字段（见下）。改也用同一格式 | 解析 → 同一套校验 → **同一份预览**，确认才写盘 |

一行式语法（两篇共用，字段名各写在 01 / 02）：

```
名称=作者 键=author 说明=作品作者 值=张三
```

- 若干 `字段=值`，空格分开。值里有空格、`=`、`"` 时用双引号包；引号里的 `"` 写成 `\"`。
- 字段名用各篇表里的中文。不要 JSON，不要靠位置顺序（`作者 author 张三` 禁止）。
- 同一字段写两次、出现表外字段：失败，不写盘。
- 独立命令也可以拆成同义参数（`--name` / `--key` …），和一行式进同一套解析，不要第三套。
- `--yes`：解析校验通过后仍打印预览，跳过确认，直接写盘。解析失败不写盘。

**键一经写下不能改**（自定义、可选配置都是）。Console 属性/配置编辑器可以改 key，CLI **不跟随**。要换键：删整条再加。一行式里的 `键=` 只用来**定位**已有条或**新建**；改的时候写成别的键 → 失败，「键不能改，请删除后重新添加」。

工作稿见 [02-本地状态 §2.2](../../../ARCHITECTURE/02-本地状态.md)。文件 sha1、属性、可选配置、依赖每改一项立刻写 `.freelog/N.version.json`。  
中断后再开：有工作稿必须提醒（见发行版本 / 更新版本）。成功 POST 后删掉这份。不做平台草稿。
