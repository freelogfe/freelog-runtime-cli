# 可选配置

对照 Console `fResourceOptionEditor`。  
不是自定义属性。节点展示/运行时，**节点管理者**可以改这些值。

帮助（空列表或第一次「添加配置」）：

> 可选配置是您的作品在节点展示/运行时，您提供的、允许节点管理者自行更改的设置。您可以根据需要添加。

问法只写在本文。会话菜单和 `version option add|set|rm|list` 共用。

| 场景 | 能做什么 |
|------|----------|
| 发行版本会话 / `version option`（首版稿） | 空表；类型允许才出现菜单 3 / 4 |
| 更新路径（已有更新稿） | 稿上已带回显的可选配置（类型仍允许才带），再加、删、改 |
| 类型不允许 | 菜单不出现 3 / 4。工作稿里若仍有可选配置描述符，**提交失败**，不要默默删 |
| 已发版 | **不能改**。看用 `version show`；要改先 `version draft pull` 再改稿 |

最多 **30** 条。「最多可添加30个可选配置」。  
下拉的选项最多 **30** 个。「选项个数不能超过30项」。

---

## 1. 和属性怎么分

提交时两者都进 `customPropertyDescriptors`，靠 `type` 区分：

| | 自定义属性 | 可选配置 |
|--|------------|----------|
| 会话菜单 | 添加 / 删改属性 | 添加 / 删改可选配置 |
| 提交 `type` | `readonlyText` | `input` → `editableText`；`select` → `select` |
| 谁改 value | 发行者写死 | 发行者给默认；节点上可改 |

key / 名称仍要和属性、系统项全局唯一，规则同 [属性 §1](./01-属性.md)。

更新版本回显：仅类型仍允许可选配置时，才把上一版的可选配置带进工作稿。类型已不允许：不要带。发行版本没有上一版，不回显。

---

## 2. 发行：添加

菜单「添加配置」。标题：「添加可选配置」。

先问填法（默认逐项问），规则同 [属性](./01-属性.md) / [README](./README.md)。  
独立命令 `version option add`：带了一行或带齐参数 → §2.0；TTY 没带齐 → 逐项问；`--yes` 没带齐 → 失败。

### 2.0 一行式

| 字段 | 必填 | 规则 |
|------|------|------|
| 名称 | 是 | 同 §2.1 |
| 键 | 是 | 同 §2.2 |
| 说明 | 否 | 同 §2.3 |
| 方式 | 是 | `文本` 或 `下拉`（也认「文本输入框」「下拉列表」） |
| 默认 | 方式=文本时 | 可空。方式=下拉时**不要写** |
| 选项 | 方式=下拉时 | 用 `\|` 分开，至少 1 个、最多 30、去重、每项非空。第一项即默认 |

```
名称=主题 键=theme 方式=文本 默认=dark
名称=语言 键=lang 方式=下拉 选项=中文|English|日本語
```

下拉还写了 `默认=`：失败，「下拉默认值固定为第一项，请把要默认的选项放在第一位」。  
文本还写了 `选项=`：失败。方式非法：失败。解析失败不写盘。

### 2.1 名称

「名称」。hint：「输入名称」。非空。不与已有名称撞。

### 2.2 键

「键」。hint：「输入键，键是此条目的唯一标识符」。  
同一套 key 规则：`^[A-Za-z][A-Za-z0-9_]{0,29}$`。撞 key 重新问。

### 2.3 说明（选填）

「说明（选填）」。可空 → `remark`。

### 2.4 配置方式

「配置方式」二选一，必须选：

| 选项文案 | 内部 | 提交 `type` |
|----------|------|-------------|
| 文本输入框 | `input` | `editableText` |
| 下拉列表 | `select` | `select` |

不要提供 radio / checkbox（Console 本编辑器没有）。

### 2.5 文本输入框

问「默认值」。hint：「输入默认值」。可空。  
预览用：`type=editableText`，`defaultValue` = 默认值，无 `candidateItems`。写盘在 §2.7。

### 2.6 下拉列表

说明打一行：「（默认选中首个选项）」。

1. 问「选项」第一项。非空。
2. 问要不要「添加选项」。是：再问一项。空字符串不收。
3. 去重：重复项当场拒绝。
4. 满 30 项：不能再加。
5. 至少 1 项才能结束。
6. **默认值固定为第一项**，不要再问「默认选哪一个」。改默认 = 调整选项顺序（见 §3）。

预览用：`type=select`，`candidateItems` = 选项数组，`defaultValue` = `candidateItems[0]`。写盘在 §2.7。

### 2.7 预览，确认后才写盘

校验通过后先打（空说明打「（无）」）：

```
即将写入可选配置：
  名称：语言
  键：lang
  说明：（无）
  方式：下拉列表
  选项：
    1. 中文  ← 默认
    2. English
    3. 日本語
```

文本方式不打「选项」，打「默认值：{值或（空）}」。  
否：不写盘。`--yes`：仍打印，不确认，直接写。  
是：写入 `N.version.json` 的 `customPropertyDescriptors`（和自定义属性同一个数组）。回菜单。

## 3. 发行：删除或修改

列出每条：`名称 (key) · 文本/下拉 · 当前默认值`。选一条：「改」或「删」。

### 3.1 改

**键不问、不改。** Console 能改 key，CLI 不跟随。换键：删整条再加。

填法同添加。逐项：可再问名称、说明、配置方式、默认值 / 选项。一行式未写的字段保持原值；写了 `键=` 且与当前条不同 → 失败。

换配置方式（文本 ↔ 下拉）：按 §2.5 / §2.6 重问（或一行式按新方式带齐 `默认` / `选项`），旧的另一边丢掉。

下拉改选项：

- 可增、可删、可改某一项文案、可「上移」把某项变成第一项（第一项即默认）
- 删到 0 项不让保存
- 当前 `defaultValue` 必须落在候选里；若删掉了原第一项，新的第一项当默认
- 一行式改下拉：`选项=` 是**整份替换**（仍第一项为默认）

走 §2.7 预览（标题改成「即将修改可选配置」，多打「键：{key}（不可改）」），确认才写盘。

### 3.2 删

确认后从工作稿去掉。回菜单。

---

## 4. 已发版：不能改可选配置

某一版发出去之后，这一版的可选配置冻住。不要 PUT `defaultValue`。要改走 [更新版本](../更新版本/01-更新版本.md)。

---

## 5. 提交映射（发行）

```
// 文本
{ key, name, type: "editableText", defaultValue, remark?, candidateItems: [] }

// 下拉
{ key, name, type: "select", defaultValue: candidateItems[0], remark?, candidateItems: [...] }
```

不要把可选配置写成 `readonlyText`。不要把自定义写成 `editableText`。

## tools-lib

添加 / 修改结构无独立 API。  
类型是否允许：`Resource.getResourceTypeInfoByCode`，看 `supportOptionalConfig === 2`。  
提交：`createVersion` 的 `customPropertyDescriptors`。不要用 `updateResourceVersionInfo` 改可选配置。
