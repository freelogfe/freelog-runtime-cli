# 03 · CLI 环境差异与产品原则

> **文档角色：** CLI 环境差异分析与产品原则。本文把 Console UI 场景翻译成 CLI 场景，原则不是口号，而是后续流程和实现的裁决依据。

最后更新：2026-09-02

## 1. Console 与 CLI 的环境差异

| 维度 | Console | CLI | 产品影响 |
|---|---|---|---|
| 身份状态 | 浏览器登录态，UI 显示账号 | 本机登录、临时会话、环境变量、CI secret、多账号共存 | 每次写入前必须显示环境、账号、owner；非交互必须显式选择或唯一确定 |
| 交互方式 | 表单、抽屉、弹窗、按钮禁用 | 一条命令进入连续会话；也可无 TTY 执行 | 表单约束要转成逐步提问、默认值、错误码和确认页 |
| 资源来源 | 上传、存储空间、编辑器 | 本地文件、目录、工程构建产物、stdin、manifest | CLI 必须管理本地资源扫描、构建、压缩、打包和产物确认 |
| 类型选择 | 可视树、搜索、标签 | 终端列表、编号、过滤、搜索 | 逐级浏览是主路径；搜索是加速；不能只支持搜索 |
| 策略配置 | 模板卡片、参数控件、翻译预览 | 模板列表、参数问答、编译/翻译结果文本化 | 必须先选模板再填参数；手写策略不是默认流程 |
| 写入反馈 | 页面状态刷新 | 控制台输出、报告文件、JSON/NDJSON | 每次远端写入必须有结果、状态、恢复点 |
| 失败恢复 | 用户停在页面继续改 | 进程可能退出、网络可能中断 | 写入前 checkpoint，失败后 resume，重试前查远端 |
| 自动化 | 不适合 | AI/CI 是重要使用方 | 输出协议必须稳定，错误必须可解析 |

## 2. 身份与会话原则

CLI 必须支持四种使用方式：

| 模式 | 用途 | 身份来源 | 设计规则 |
|---|---|---|---|
| 持久登录 | 开发者日常使用 | 本机安全存储 | 可记住账号，但写入前仍展示账号和环境 |
| 临时会话 | 借用账号、短期操作、AI 辅助 | 当前进程或指定会话文件 | 进程结束后不污染默认账号 |
| 多账号工作区 | 同一机器维护多个 owner | 显式 profile/account | 资源 owner 与登录账号不一致时必须停下确认权限 |
| CI/AI 非交互 | 自动发布和检查 | 环境变量/secret/显式参数 | 不进入问答；缺字段直接结构化失败 |

会话不只是 token 存储。会话还要记录当前环境、账号、owner、资源选择、草稿路径、上一次写入状态和恢复点。

## 3. 本地资源与准备能力原则

CLI 一期必须把本地资源和发行物准备作为第一等对象。这里的“准备”不是平台业务流程的一部分，而是 CLI 把本地文件、目录或工程转换成明确 artifact 的能力：

```text
本地输入
  → 路径检查
  → 内容来源选择：单文件 / 已有工程 / 新建模板工程 / 已有构建目录 / 已有压缩包
  → 类型推断
  → 可选构建
  → 可选压缩/打包
  → 产物确认
  → 上传得到 sha1/filename
  → 进入 Console 对齐的版本发布流程
```

规则：

- 本地文件必须存在、可读、大小可计算。
- 本地目录不能直接当平台资源上传；必须先构建或打包成明确产物。
- 构建命令、输出目录、压缩规则来自模板、manifest 或用户确认。
- 上传成功但后续发布失败时，必须保留 sha1 和 filename，重试时不重复上传。
- 批量流程必须逐项记录本地路径、推断类型、远端资源、写入结果。

### 3.1 模板原则

模板是 CLI 原生能力，解决“从空目录到可开发工程”的问题。它必须支持两种路径：

| 路径 | 用户目标 | 写平台吗 | 后续 |
|---|---|---|---|
| 独立模板创建 | 用户直接创建 React/Vue/JS/TS 主题或插件工程 | 不写平台 | 输出本地工程、模板版本、开发/构建/发布下一步 |
| 发布流程内模板创建 | 用户在资源发布中选到主题/插件类型后，选择“从模板创建新项目” | 模板阶段不写平台；发行阶段按标准流程写平台 | 模板产物进入构建、压缩、上传、资源发行 |

规则：

- 模板创建不能绕过资源类型、资源壳、版本、策略、listing、上架这些 Console 对齐流程。
- 选中主题/插件资源类型后，CLI 必须询问内容来源：从模板创建、使用现有工程、使用已有构建目录、使用已有压缩包/文件。
- 已有工程不能被强制套模板；模板只作为识别、默认构建命令、默认产物目录和下一步提示的来源。
- 模板 ID、模板来源和具体版本必须进入本地工程记录或执行报告，方便复查。

### 3.2 压缩/打包原则

压缩是独立产品能力，也可以被发布流程调用：

| 模式 | 用户目标 | 副作用 | 输出 |
|---|---|---|---|
| 独立压缩 | 先把目录打成 Freelog 可发布 artifact，供检查、复用或交给 AI/CI | 只写本地压缩包和报告，不上传、不写平台 | artifact 路径、大小、sha1、文件清单 |
| 发布流程内压缩 | 资源类型或模板要求目录型 artifact 时自动准备上传文件 | 写本地临时 artifact，随后进入上传 | artifact 路径、大小、sha1、上传 sha1/filename |

规则：

- 压缩前必须展示将包含、忽略、强制排除的文件摘要。
- `.freelog-auth`、凭据、state、缓存、VCS 和系统临时文件必须强制排除。
- 相同输入、规则和 CLI 版本应生成确定性压缩包。
- 独立压缩完成后流程结束；除非用户明确继续发布，否则不得上传或调用平台接口。

### 3.3 发布流程中的内容来源选择

资源类型选择完成后，CLI 根据类型能力和用户输入决定内容来源。主题/插件不能例外：

| 已选类型/输入 | 内容来源选择 | 下一步 |
|---|---|---|
| 普通单文件类型 | 使用已有文件、已有平台存储对象、已有 artifact | 上传或选择对象 |
| 目录/工程型类型 | 使用现有工程、已有构建目录、已有压缩包；必要时构建/压缩 | 产物确认后上传 |
| 主题资源类型 | 从主题模板创建、使用现有主题工程、使用已有构建目录、使用已有压缩包 | 构建/压缩后回到资源发行 |
| 插件资源类型 | 从插件模板创建、使用现有插件工程、使用已有构建目录、使用已有压缩包 | 构建/压缩后回到资源发行 |
| 批量流程 | 使用目录扫描结果和批量命名模板 | 逐项生成计划 |

这意味着“创建 React 主题”有两条入口：可以直接从模板创建本地工程，也可以在标准资源发布流程中先选择主题资源类型，再选择 React 模板作为内容来源。两条入口最终必须收敛到同一套资源发行流程。

## 4. 类型选择原则

资源类型是业务入口，不能简化成一个搜索框：

1. 默认按平台类型树逐级浏览。
2. 支持搜索，但搜索结果必须显示类型路径、subjectType、是否支持批量、可用入口能力。
3. 普通资源、合集、主题/插件都从平台类型树选择，不能 CLI 自造分类。
4. 批量流程只显示 `supportCreateBatch=2` 的类型。
5. 选择类型后必须展示它影响的后续能力：文件入口、大小限制、编辑能力、可选配置。

## 5. 策略原则

策略流程必须按 Console 业务顺序：

```text
拉取策略模板
  → 浏览模板说明
  → 选择模板
  → 填模板参数
  → 编译策略代码
  → 翻译成人类可读预览
  → 检查重复
  → 保存到资源
```

规则：

- 默认不让用户从空白策略代码开始。
- 没有模板时必须说明是平台模板为空，而不是让用户猜。
- 参数类型、选项、默认值来自模板，不由 CLI 写死。
- 保存前展示策略名、策略代码摘要、翻译预览和影响范围。

## 6. 写入副作用原则

| 副作用等级 | 动作 | 要求 |
|---|---|---|
| L0 本地只读 | scan、plan、preview | 可直接执行 |
| L1 本地写 | manifest、checkpoint、report | 写明路径，可覆盖前备份或原子写 |
| L2 远端草稿 | 保存草稿、上传文件、预览 RSS | 输出远端 ID/sha1，失败可重试 |
| L3 远端发布 | create resource、create version、update listing、set rules | 写入前确认或非交互显式声明 |
| L4 线上影响 | 上架、下架、RSS 绑定、批量发布 | 必须展示环境、账号、资源、数量、后果 |
| L5 Console 接力 | 支付、签约、节点主题激活 | CLI 不伪装闭环，输出链接和携带信息 |

## 7. 输出原则

同一流程必须同时服务人和机器：

- 人类输出：当前步骤、推荐默认值、风险提示、下一步选项。
- JSON 输出：稳定字段、状态、错误 code、resume token、远端 ID。
- NDJSON 输出：批量逐项事件流。
- report 文件：包含 plan、dry-run、writes、unknown、resume。

## 8. 失败恢复原则

- 任何远端写入前必须有本地 checkpoint。
- 远端写入结果未知时，不能简单重试；必须先按资源名、版本号、sha1 或 itemId 查远端。
- 批量失败不能污染成功项。
- 用户取消不是失败，必须保存可恢复状态。
- Console 接力不是失败，但必须说明 CLI 已完成什么、Console 还要做什么。
