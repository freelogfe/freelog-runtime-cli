# Freelog Runtime CLI - 深度场景验证文档

> **目的**: 通过编写高质量、深度覆盖分支的实际场景，反推产品设计（产品方案 00-06）的完整性、合理性和细节漏洞
> 
> **方法**: 不是写 80 个浅层场景，而是精心编写 15-20 个覆盖关键分支的深度场景，每个场景都包含 happy path + 所有异常分支
> 
> **原则**: 
> - 每个场景必须有完整的用户输入 → 系统反馈 → 异常处理
> - 必须基于 Console 源码证据（需求分析报告）和现有产品方案（02-字段接口）
> - 关注边界条件、状态转换、错误恢复
> - 最后汇总为设计修订建议清单

---

## A 组：环境与身份管理（5 个深度场景）

### A01 - 首次登录并发布（完整分支覆盖）

**前置条件**: 
- 未安装 CLI 或已 logout
- Node.js >= 20
- 有本地待发布文件 `./dist/my-app.zip`（大小 2.3MB, sha1=abc123...）

**Happy Path 流程**:
```bash

  即将在 dev 平台创建资源

✅ 登录状态确认完毕，进入发布流程...
```

## 📝 场景验证总结

通过以上 15 个深度场景的演练，我发现产品方案需要补充的细节包括：

### P0 - 严重遗漏

1. **Owner 字段的展示时机不明确**
   - 场景 A01-A05 多次提到需要在启动时就展示 owner
   - 产品方案 04 只提到"登录账号",没明确"资源 owner"
   - **修订建议**: 在 04 节补充"启动时必须展示的信息清单"

2. **Checkpoint 的数据结构与校验规则缺失**
   - 场景 A02 详细验证了 accountId 校验
   - 产品方案 06 只有伪代码，没有定义具体的数据结构
   - **修订建议**: 在 06 节补充 Checkpoint Interface Definition

3. **依赖版本范围命中检测的提前提示**
   - 场景 C01-2 发现应该在上传前就提示授权缺口
   - 产品方案 04 的流程图中依赖检查的位置不够靠前
   - **修订建议**: 在 04 节的单资源发布流程中添加"依赖预检阶段"

4. **RSS 锁定字段的显式禁用逻辑**
   - 场景 E01 中提到 RSS 绑定后标题、作者、类别不可编辑
   - 产品方案 02 的字段表中没有明确这个约束
   - **修订建议**: 在 02 节的 RSS 相关字段补充"锁定条件"列

5. **冻结状态的批量排除**
   - 场景 F01 应该补充"如果资源处于冻结状态，批量时跳过而不是报错"
   - **修订建议**: 在 05 节的批量异常场景中补充冻结状态的处理

### P1 - 重要优化

6. **非交互模式的 checkpoint 恢复策略**
   - 场景 A02 的非交互分支显示 CI 模式下应该 JSON 输出 checkpoint 不匹配的原因
   - 产品方案 04 的非交互章节没有定义这类结构化错误
   - **修订建议**: 在 04 节的 AI-CI 场景补充"checkpoint 相关的 JSON 错误码"

7. **封面图片的维度验证缺失**
   - 场景 C01-3 只测试了格式和大小，实际上 Console 可能还有宽高比要求
   - **修订建议**: 在 02 节的封面字段补充可能的维度约束

8. **标签推荐的呈现方式**
   - 场景 C01 中提到"建议标签"，但产品方案没定义这个功能的实现方式
   - **修订建议**: 在 02 节的标签字段补充"动态推荐来源"的说明

### P2 - 锦上添花

9. **版本描述的 HTML vs 纯文本策略**
   - 场景 D01 提到"继承自上一版",但没说明是纯文本继承还是带 HTML
   - **修订建议**: 在 02 节的版本描述字段补充"富文本 vs 纯文本"的说明

10. **独立压缩的 ignore 规则优先级**
   - 多个场景提到".gitignore",但没定义如果同时存在 `.freelignore` 时的优先级
  - **修订建议**: 在 03 节的本地准备能力补充"ignore 规则的合并与优先级"
