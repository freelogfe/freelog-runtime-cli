## 1. 推荐方案与范围

合集是一个独立的授权主体，里面的单品引用本人已经上架的单资源。推荐让用户在本地逐步整理目录、属性、可选配置、依赖和说明，查看完整变更，再一次发起“发布合集变更”。平台内部需要分批操作时显示实际进度和部分完成结果。

核心设计：

1. 单资源负责文件及其版本；合集负责成员引用、标题、顺序、目录展示和合集自己的表单。添加单品不上传文件，不复制单资源本地缓存。
2. 合集创建、绑定不要求 `--artifact`。合集没有自己的文件或压缩产物。
3. 本人资源库提供分页、搜索、多选；直接输入资源 ID 或完整标识同样可用。选择资格必须在提交前重新检查。
4. 修改先保存本地合集工作稿，`collection diff` 预览，`collection publish` 发布。合集不向用户提供 `--bump` 或新版本号。
5. 策略、listing、上架是独立操作。发布目录不会替用户上架；策略签约、支付沿用已确认的单资源规则。
6. 平台目录草稿是共享对象。必须识别 Console 已有修改、分批失败和未知结果；本地锁只能保护本机工程。

本次设计覆盖手动资源库合集的创建、绑定、单品维护、属性/配置/依赖、策略、listing、展示配置、发布、上下架、更新日志和中断恢复。自动收录单独设计在 §10，建议第二阶段交付；RSS 暂不纳入本轮实现，但识别 RSS 并保护其编辑边界。标准 JSON 驱动的多单资源连续发行属于独立需求，可用于准备合集的候选资源；目录隐式扫描导入、session、studio 继续不纳入。

## 3. 用户需要理解的对象

| 对象 | 例子与身份 | 改动影响 |
|---|---|---|
| 源单资源 | `alice/photo-01`，按资源 ID 定位 | 文件、资源属性、版本由该单资源的命令维护 |
| 合集单品 | 合集内的一个条目；已存在条目按 `itemId` 定位 | 改别名、位置、单品授权设置，仅影响该合集 |
| 合集主体 | `alice/travel-album`，另有资源 ID，`subjectType:4` | 拥有自己的策略、listing、属性、配置、依赖、目录 |

一个单资源可以作为不同合集的候选；是否允许实际加入仍以平台核验为准。同一合集内同一资源只保留一个单品。移除单品不删除源资源，也不影响其它合集或撤销合约。

单品不是依赖的别名：成员列表描述“合集包含什么”，`dependencies` 描述“合集本身依赖什么”。不自动把所有单品复制到依赖数组，不把单品的依赖复制到合集直接依赖中。单品自身的授权链由平台授权接口核验。[E3、E5、E10]

### 3.1 源资源版本与标题

- 单品按 `resourceId` 引用。现有添加契约不接受 `versionRange` 或固定版本；不设计“给单品选版本”或“自动发布源资源”。
- 源资源更新后，列表显示查询时的最新版本。消费者是否立即解析到新版本、是否需要合集重新发布，需 dev 验证后写入使用文档；看到 `latestVersion` 不能证明消费端行为。
- 列表同时显示“源资源当前标题”和“合集自定义单品标题”。标题可重复，不能替代 ID。
- 合集展示标题支持 Console 已有的资源标题、连载编号、自定义、隐藏四种模式。自定义模式保存的 `itemTitle` 不被资源改名自动覆盖；资源标题模式以平台展示契约为准。[E9]
- 显示序号、分页行号、`sortId`、平台连载 `number` 均不作为跨命令稳定标识；菜单选择必须保存该行真实 ID。

### 3.2 本地发布与线上添加的衔接（用户补充确认）

单品的唯一来源是**当前环境、当前账号线上已经上架的单资源**。无论它最初在 Console 创建，还是在本地 CLI 创建，加入合集都走同一条线上查询与验证路径：

```text
本地文件 / 主题或插件工程
  → 现有单资源创建、发行版本、策略、上架流程
  → 平台的本人单资源库
  → 合集从线上查询、选择、精确核验
  → 写合集工作稿
  → 发布合集目录变更

Console 已上架的本人资源 → 同一个平台资源库 → 同一个合集选择入口
```

- 本地单资源身份、文件或工作稿都不能直接成为单品。不扫描 N.json 生成候选；成员新增参数也不接受 `file:N.json` 或本地产物路径。
- 本地已有 resourceId 只说明曾经创建或绑定，不能证明当前已发行、已上架或仍属于当前账号。即使刚刚发行成功，也必须读线上身份和状态；仅创建版本但尚未上架时不可添加。
- 刚发布流程返回的 ID/完整标识可帮助用户定位线上查询目标，不能直接变成已选成员。选择列表尚未刷新时，可以按完整标识精确查询平台；平台暂时读不到则提示刷新/稍后查询，禁止用本地结果兜底成功。
- 没有本地单资源缓存也可以添加；删除本地单资源缓存、换机器、移动源文件不会破坏已发布合集引用。
- 单资源发行成功但合集添加/发布失败时，已经发布的单资源继续保留。接续只需重新查询和添加，不重复发行单资源。

### 3.3 怎样减少来回操作

资源库菜单增加“刷新资源库”和“资源尚未发布，查看单资源发行步骤”。返回刷新时保留按 ID 保存的跨页选择，并提示当前搜索/类型筛选可能隐藏新资源。刚发布资源可用完整标识查询定位，无须从第一页重新找。

核心路径先复用现有单资源命令：暂存合集工作稿 → 完成单资源流程 → 回到合集查询添加。用户不需要为合集复制一份单资源工程，也不需要将单资源绑定到合集身份下。

针对用户后续明确的几十份资源场景，可先使用独立的快速发行能力完成单资源准备；它只报告单资源结果。之后独立执行合集添加，以报告中的ID作为线上查询线索，或直接查询已有资源。合集有自己的工作稿、结果与恢复流程，不把合集阶段加入快速发行任务。

如果后续讨论同一次交互中的“发布一个单资源后返回”，它只能作为合集侧的可选衔接入口，调用已有单资源能力并恢复合集上下文后重新查线上；当前不把这个入口定为必须实现。快速发行输入和执行器本身不包含合集目标、添加或发布目录的步骤。

### 3.4 单资源与合集的复用边界

复用的是领域规则和公共机制，两个主体的工作稿和发布接口分别适配。当前代码有部分服务与单资源存储耦合，必须提取共用部分后使用，不能把复制源码当作复用。[E11]

| 功能 | 可复用内容 | 合集需要适配的部分 |
|---|---|---|
| 账号与环境 | 登录、凭据库、env 检查、错误处理 | 沿用同一账号/环境上下文；返回合集时重新核验 |
| 身份与本地安全 | N 编号、精确选择、锁、原子写入、事务 | subject 区分；合集身份无 filePath；工作稿另用 N.collection.json |
| 类型选择 | 完整祖先路径、叶子校验、搜索、分页交互 | 类型查询 subject=4，核验资源库能力；不能使用当前固定 subject=1 的筛选 |
| 创建与绑定 | 名称/标题校验、查重、owner/冻结/环境验证、创建与读详情 API | 创建 subject=4；不执行文件锚点或上传步骤 |
| 策略 | 全量自身策略、模板分页、DSL处理、显式添加和开关 | 从合集身份取得目标与类型；平台已知 DSL 问题保持同一处理 |
| listing、上下架 | 字段校验、更新API、启用策略检查、即时读回 | 上架前检查合集已发布目录状态；不能套单资源版本/文件门禁 |
| 属性与可选配置 | 一行式解析、名称/键/默认值/数量校验、表单交互 | 从合集类型取定义、读写合集稿；有差异的字段约束显式适配 |
| 依赖与签约 | 目标/范围/循环校验、所有启用策略选择、签约及支付边界 | 当前合集作为使用方；保存到合集稿，单品的上游授权另外检查 |
| 本人线上资源查询 | tools-lib Resource.list/info、请求错误和分页基础设施 | 添加单品的资格过滤、去重、跨页选择和已在合集标记 |
| 发布与恢复 | 校验/预览/确认、pending状态、本地收尾机制 | 单资源提交版本；合集写目录草稿并merge；核验依据不能共用版本号/SHA判定 |

已核实的提取入口：`domain/account/`、`domain/create/typePick.ts`、`domain/version/gates.ts`、`domain/version/form/{parseLine,attr,option,dep}.ts`、`domain/policy/list.ts`、`domain/listing/update.ts`、`local/`。先以实际共享规则提取函数或小型适配器，不先建设覆盖所有主体的通用工作流框架。

单资源的模板安装、构建目录压缩、上传、文件分析、create-version/update-version 全部仍由原流程负责。合集不重新实现这些功能，也不把单资源的版本表单复制成单品的表单。

## 4. 命令与操作边界

建议合集专有流程统一放在 `collection` 下；账号和现有单资源命令保持原有入口。合集内部策略、listing 等复用领域服务，避免复制业务逻辑。

所有合集命令沿用 `--env`、`--cwd`、`--resource`、`--yes`。`--resource` 选择当前合集身份；单品参数选择合集内部对象，两个位置含义明确。创建/绑定新增身份时沿用现有新增规则，不依赖任意“第一份状态”。

| 拟议命令 | 用途 | 本地/平台副作用 |
|---|---|---|
| `collection create --type <code> --name <name> --title <title>` | 创建合集壳；TTY 可引导继续整理 | 创建平台合集及本地身份；不上传、不上架 |
| `collection bind <id或完整name>` | 接入本人线上已有合集 | 验证平台后只写本地身份；不导入/覆盖远端草稿 |
| `collection status` / `collection show` | 前者显示接续状态，后者读已发布内容 | 只读；区分本地工作稿、平台草稿、已发布事实 |
| `collection draft pull [--from published\|platform-draft]` | 默认读已发布内容建立本地工作稿；显式采用 Console 草稿可接续 | 平台只读，本地原子建稿/换稿；有稿先确认 |
| `collection draft show` / `collection diff` | 查看本地完整稿 / 对比来源、目标及平台变化 | 只读；读取失败不能显示“无差异” |
| `collection draft discard` | 丢弃本地尚未发送的修改 | 仅本地；发送后存在未决记录则先 recover |
| `collection item list [--local] [--search <词>] [--all]` | 默认读已发布条目；`--local` 看待发布列表 | 只读，分页规则见 §5 |
| `collection item add [<源资源选择器>...]` | 无参数进入本人资源库多选 | 校验后写本地稿；必要签约必须先显示并确认其远端副作用 |
| `collection item add --input <items.json>` | AI/脚本显式提交大批 ID 与可选单品标题 | 全部检查后原子修改本地稿；不按搜索结果偷偷全选 |
| `collection item remove <单品选择器>...` | 移除选定成员 | 本地稿；源资源不变 |
| `collection item update <单品选择器> --title <标题>` | 改该合集中的单品自定义标题 | 本地稿；展示模式未选 custom 时说明当前不会展示该别名 |
| `collection item move <单品选择器> --before <单品选择器>` | 调整相邻位置 | 本地稿；另支持互斥的 `--after`、`--first`、`--last` |
| `collection item sort --by <字段> --order asc\|desc` | 对整个待发布列表明确重排 | 本地稿；预览影响条数；不只排序当前页 |
| `collection attr / option / dep` | 各自的 `list/add/set或range/rm`；属性附加项 review | 合集工作稿；校验复用，依赖签约有独立远端副作用 |
| `collection authorize` | 检查并补齐当前工作稿缺失的依赖/单品上游签约 | 显式远端签约；逐目标选策略，非 TTY 用 `--input <授权选择.json>` 明确映射；不发布目录 |
| `collection description --description <文本>` | 改合集本次发布说明 | 本地稿 |
| `collection view [set ...]` | 查看/设置目录展示模式 | 查看只读；设置写本地稿 |
| `collection validate [--for publish\|online]` | 验证当前稿或上架准备情况 | 平台只读，不替用户签约或合并目录 |
| `collection publish` | 提交本地目录/表单变更 | 分批写平台目录草稿、合并发布、核验后清稿 |
| `collection publish --resume` | 在已核验的批次检查点继续同一次提交 | 只执行尚未完成部分；未知请求未核实、稿已改或远端变化则拒绝 |
| `collection recover [--apply]` | 查看未知操作结果；可证明时本地收尾 | 核验平台，不重发未知写操作 |
| `collection recover --apply --replan` | 已知部分草稿写入完成、尚未发起合并时重新整理 | 严格核验检查点后转为可编辑本地稿，不撤销平台草稿；未知合并结果不允许此操作 |
| `collection policy list/template list/template apply/apply/set` | 管理合集自己的授权策略 | list 只读，其余按具体命令即时平台写入 |
| `collection update --title/--intro/--tags/--cover ...` | 改 listing | 即时平台写入，含清空语义，复用单资源约束 |
| `collection online` / `collection offline` | 管理上下架 | 即时平台写入；online 不隐式 publish |
| `collection logs [--all]` | 读合集更新日志 | 只读；不把日志号当 semver |

不增加顶层 `publish`。`collection publish` 明确表示“发布合集目录及表单变更”，不表示新建单资源版本或上架。

TTY 创建成功后显示“继续选择单品 / 稍后继续”；后续每个阶段可退出，下一次按真实身份和工作稿接续。非 TTY 只执行明确给定命令，缺少选择时报错。第一次本地修改可在无稿且无平台冲突时自动建立来源快照；交互预览说明来源，不能自动采用 Console 未发布草稿。

## 5. 单品数量多时如何管理

### 5.1 本人资源选择器

工具接口：`Resource.list({ isSelf:1, subjectType:1, status:1, skip, limit:50, keywords, isLoadLatestVersionInfo:1 })`。平台筛选只减少候选，写稿/发布前仍精确核验 owner、主体、版本和上架状态。[E2]

交互屏幕示意：

```text
选择要加入「旅行摄影」的单资源    已选 3 项
搜索：海边    类型：图片 / 照片    第 2 页
[ ] 海边清晨   alice/coast-am   1.2.0   已上架
[x] 海边傍晚   alice/coast-pm   1.0.0   已上架
[-] 海浪       alice/waves      已在本合集
上一页 / 下一页 / 修改搜索或类型 / 查看已选 / 确认加入 / 取消
```

- 固定每页 50，不开放 page/page-size 参数。搜索和类型筛选变化回到第一页，但已选集合保留，并显示总数。
- 选择集合按 `(env, resourceId)` 去重。跨页/跨搜索选中项不能丢失；支持移除已选项和全选当前页，不默认全选全部搜索结果。
- 交互一批最多选 100 项；到上限提示“先加入这批，再继续选择”。100 是一次选择/提交限制，不是合集总容量。[E2]
- 默认只列可添加候选；已包含项标记不可选。若输入未上架资源，解释“请先在单资源流程上架”；不自动修改其状态。
- 取消选择不修改工作稿、不签约。资源库空、搜索无结果、全部已经加入分别提示。
- 同名项展示完整标识、类型全路径和短 ID；选择详情可复制完整 ID。标题只负责搜索和展示。
- 源资源不需要本地 `N.json` 或产物；本人线上已上架资源都可候选。候选仅来自线上查询，不从本地身份集合生成。

### 5.2 直接输入与单品定位

新增源资源：支持 `id:<resourceId>`、`name:<username/name>`，都必须先从当前环境线上查出本人已上架单资源再添加。拒绝本地 JSON、文件或目录路径作为成员输入。非交互推荐显式前缀，不按标题猜测。通用 `--resource file:N.json` 仍可用于选择被操作的**合集身份**，不代表成员来源。

操作已加入单品：支持 `item:<itemId>`；也支持 `resource:<resourceId>`，解析到当前合集唯一成员。尚未发布的新项没有平台 itemId，以资源 ID 或本地生成的 `local:<key>` 定位。所有 itemId 必须属于当前合集，传另一合集条目直接失败。

`--input` 文件保存显式清单，例如 `[{"resource":"name:alice/photo-01","title":"序章"}]`。未知字段、重复资源、非法类型、部分目标不可用都在本地改稿前报告；默认整批本地变更失败，不静默只选合格项。文件是一次导入输入，不成为新的永久状态文件。

重复 add 已在待发布列表中的资源返回“已包含，未改动”，不覆写别名、顺序或授权设置；若存在待移除记录，必须明确撤销该移除后再添加，不悄悄生成第二份条目。批量删除重复 selector 先去重。

### 5.3 列表与排序

- `item list`、`logs` 固定每页 50，TTY 提供上一页/下一页；非 TTY 默认首页，明确总量和剩余数量。`--all` 表示完整输出，供 AI、导出、脚本使用，禁止把首页当全集。
- 本地列表显示“新增 / 修改 / 移除 / 未变”；移除项仍可在 diff 中查询，不算目标成员。
- move 以稳定条目定位相对位置；拒绝把自己放到自己前后，拒绝不存在目标。实现使用平台 sortId 适配，不能把分页序号原样当 sortId。
- sort 支持平台已证明的 `createDate`、`itemTitle`、`resourceUpdateDate`、`sortId`。同值项保持既有相对顺序。自然数字排序、拼音排序不能擅自作为平台默认语义。[E4]
- `collection_sort_list` 是目录展示方向；它与重排成员、连载编号分别记录，避免翻转两次。排序重置是否影响 `number` 需单独验证。
- 拉取整个目录用于 diff/提交时必须遍历所有页；核对重复 ID、返回总数、缺页和中途变化。分页失败则整体快照失败，保留旧稿。大型目录应显示读取进度。

## 6. 本地状态：永久身份与临时工作稿

沿用现有编号体系，通过 subject 区分资源与合集。应把身份类型改成判别联合，不能简单把所有单资源的 `filePath` 都改为可选。[E11]

```text
.freelog/
  1.json                  单资源身份，subject=resource，必须有 filePath
  1.version.json          单资源未提交工作稿
  2.json                  合集身份，subject=collection，不允许 filePath
  2.collection.json       合集本次未提交工作稿
  .pending-operation.json 未知远端操作记录（扩展类型，非业务历史）
```

合集 `N.json` 保存 schemaVersion、subject、typeCode、resourceId、完整 resourceName、环境，以及可过期标题缓存。新合集只在创建/绑定成功后落永久身份；创建结果未知时先保存最小待核验记录。编号继续单调分配；同一 `(env,resourceId)` 不能重复绑定。

N.json 不保存目录、版本号、顺序、策略、依赖、属性、可选配置、是否上架或 RSS/自动收录当前状态。动态能力和状态每次读平台。合集身份可在单资源同一工程长期保留；身份选择先区分命令允许的 subject，多份合集需明确选择。

现有 `resource list/sync` 作为工作区身份诊断/显式标题同步扩展识别合集并显示 subject；标题仍不作为选择器。`artifact:` 仅适用于有产物的单资源，指定合集时报明确类型错误。

### 6.1 合集工作稿结构建议

| 区域 | 内容 | 用途 |
|---|---|---|
| identity | resourceId、typeCode、env、创建工作稿的账号 ID | 防止换绑、换账号、跨环境使用 |
| source | `published` 或显式 `platform-draft`、读取时间、可用的远端修订/指纹 | 说明起点，支持冲突检查 |
| base | 开始编辑时的目录、合集表单与平台草稿差异信息 | 仅本次修改的比较基线，不是历史版本库 |
| target.items | 有序成员：localKey、已有 itemId、resourceId、itemTitle、授权排除等明确字段 | 保存这次期望发布的目录 |
| target.form | description、inputAttrs、customPropertyDescriptors、dependencies、catalogueProperty、已知授权声明 | 完整保留合集自身表单 |
| review | 失效类型配置、未知字段、权限变化、待明确授权等问题 | 显式解决前不发布 |

系统计算属性仅显示；需要编辑的系统附加值写 inputAttrs。源资源标题、当前版本、状态可以作为带时间的预览信息，不能作为比较目录是否被他人修改的字段；源资源改名不等于合集目录被编辑。

不需要同一内容同时保存全量 target 和长期操作日志；操作差异从 base/target 计算。只有开始远端写入后才创建提交记录，包含固定的意图摘要及各批次结果。

成功发布并完成核验后，原子清理 `N.collection.json` 与对应未决记录，永久 `N.json` 保留。下一次编辑重新读取平台。没有稿时 `draft show` 报无稿，不能用旧信息伪造本地稿。

### 6.2 拉稿、采用 Console 草稿、丢稿

- 默认 pull 读取已发布目录和表单。新壳没有已发布内容时按后台类型模板建立空基线，不伪造已存在版本。
- 若平台有未发布目录/版本表单草稿，显示存在差异。默认不得覆盖或合并它；用户可 `draft pull --from platform-draft` 明确接手，或者在 Console 完成/处理后再继续。
- 从平台草稿接手必须同时读目录草稿与相关表单草稿，显示相对已发布内容的全部差异。原有未知字段或授权声明读不全则失败，保留平台数据。
- 有本地稿时，pull 展示被替换摘要并确认；非 TTY 需 `--yes`。网络/解析/确认失败旧稿不动。
- discard 只丢弃尚未发送的本地稿。它不清理 Console 草稿，也不撤销已经签订的合约；如已写平台草稿，指向 recover 和差异说明，不自动执行全量删除重建。

## 7. 属性、配置、依赖和授权

### 7.1 合集表单必须完整支持

| 功能 | 设计 |
|---|---|
| 系统属性 | 用合集类型和空 SHA 获取定义；只读计算项与可编辑附加项分开，无文件上传/分析步骤 |
| 自定义属性 | readonlyText 的新增、修改、删除；名称/键/说明/数量/长度复用校验器，核对合集页面差异 |
| 可选配置 | 文本/下拉新增、修改、删除，默认值和候选项顺序明确；后台能力为 2 才可新增/编辑/提交 |
| 描述 | 空值可清除，作为本次合集发布表单；不假装是某个新版本号说明 |
| 依赖 | add/list/range/rm，版本范围、循环、主体、可用状态及签约校验复用；保存到合集稿 |
| 展示配置 | 列表/卡片、目录方向、标题模式、编号/封面/描述显示；保留未修改字段 |
| 既有授权声明 | 显式读取并保留合集级、单品级排除等字段；不可套用单资源“恒 []”使既有配置消失 |

共用规则以字段对照表为起点，不照搬其“单资源一期恒 []”取舍。授权排除、上抛等完整编辑未交付前，既有信息必须无损保留；如果适配器无法解释或写回，允许只读、阻断受影响发布并明确指出字段。[E5、E8、E12]

单品自定义标题 Console 编辑控件 `FCollectionItems2/CollectionList/index.tsx:639` 为 100 字限制；必填、空白、emoji 长度计数和批量限制需补进合集字段对照表并验证。其它合集专属字段不能靠照抄资源标题常量定案。

### 7.2 授权策略

`collection policy list` 一次列出合集全部自身策略，显示合集类型完整祖先路径。模板 list 固定 20 一页，TTY 上一页/下一页，模板全量请求与现有后端 DSL 阻塞规则一致。增加策略即时生效，不进入合集工作稿；发布目录不会创建默认策略或删除已有策略。

### 7.3 依赖与单品授权是两条流程

合集直接依赖继续支持本人或他人符合现有依赖规则的单资源；“本人已上架”限制只属于单品选择，不能误套到直接依赖。范围只用于 dependencies，不能拿来给单品锁版本。

签约主体是当前合集，授权目标是对应上游单资源；服务提取必须区分主体类别与被授权目标类别。不能仅把原函数 `licenseeId` 换成合集 ID 就断言兼容，需按 Contract API 和真网请求确认字段。

已有授权即可写稿；无授权时显示所有当前可签启用策略供用户选择，明确签约成功即可继续，支付留浏览器。脚本必须显式策略 ID，禁止第一条/仅免费默认选择。签约成功不等于支付完成或消费端一定可用。

签约时机固定为：`item add`、`dep add/range` 在完成该次输入的确定性校验后，展示并确认签约，再写本地稿，沿用单资源“签约成功即可添加”的行为。`publish` 只复查所需授权/已签约事实，不临时选择新策略或自动补签。若编辑后授权条件变化，保留稿并指向 `collection authorize`；该命令明确列出所有缺口及每个目标选择的策略，确认后补签，签约未知结果按下文处理。

本人单品仍可能包含基础上抛资源。添加前读取这些事实和以合集为 licensee 的合约，列出缺少的授权；需要签约时逐一明确目标和策略。不要因为 owner 相同就跳过，也不要只因带上抛便认定资源永远不可加入。[E10]

签约失败不添加对应本地变更；已有成功合约不回滚。平台若在后续合并/上架阶段拒绝待支付状态，原样报告真实拒绝与浏览器处理入口，不能宣称支付链路已通过。

签约请求超时也属于结果未知：记录合集 licensee、目标资源、选择的策略和发送阶段，按合同查询契约核验；未能证明成功或明确拒绝时不自动重签、不宣称本地整批操作已完成。不能只为目录 merge 设计恢复，却让依赖编辑中的签约失去中断记录。

## 8. 发布、冲突和中断

### 8.1 一次 publish 的顺序

1. 解析当前合集，持本地锁；校验 env、owner、subject、冻结、RSS/资源库能力，读取完整工作稿。
2. 读当前已发布目录、相关表单、平台草稿、自动收录状态，与来源基线比较。无变更返回 noop；有外部未认可变化则停下展示冲突。
3. 计算明确的新增、移除、别名、顺序、表单差异；核对全部目标资源以及所需授权/已签约事实。缺少签约则先停止，指向 `collection authorize`。确定性校验一次完成后再允许平台目录写入；publish 不主动签约。
4. 预览：合集、环境、当前上架状态、条目改动数、属性/配置/依赖/授权变化。说明对已上架合集发布后即影响线上内容；确认默认取消，`--yes` 只跳过确认，不绕过校验。
5. 保存 `kind:collection-submit` 提交记录及固定目标摘要。每批新增不超过 100；其它接口按核实的各自限制处理，不凭新增限制推断所有接口相同。只调用草稿 CRUD，不使用 live 删除/排序接口。首次添加明确 `isPublish:0`。
6. 每批解析实际成功/失败/忽略项，读回精确比对。仅 HTTP 成功不足以完成批次；忽略项必须确实已经符合目标。出现失败/未知即停止后续批次并记录已完成部分。[E10]
7. 目录修改时读回完整草稿，核对成员、标题、顺序和授权内容；表单再次验证类型能力与依赖。合并前重查外部变化。
8. 调 `Resource.updateCollection`：单品有变更用 `isMergeCatalogueDraft:1`，仅属性/配置/依赖/展示设置变化用 0；`customPropertyDescriptors` 等数组不能用空默认值覆盖未读取的线上数据。合集不走 `createVersion`。[E4、E5]
9. 查询已发布目录、合集表单、必要授权结果和更新日志，比较固定目标。完成事实核验后本地事务清理稿和记录。部分完成、未知、冲突都返回非零并说明下一步。

### 8.2 多端编辑能力边界

平台接口目前从 tools-lib 可见参数中没有远端草稿隔离 ID、ETag/修订条件或提交幂等键。**读前检查加本地锁不能保证跨机器原子性。**

- 平台草稿已有非本次修改：拒绝默认 publish；通过显式采用草稿或 Console 完成处理继续。
- 在 CLI 读取后 Console 修改：只要重查发现变化就停止；不做 last-writer-wins，不清空重建对方草稿。
- 检查后到 merge 之间的竞争窗口仍存在。推荐后台支持“按草稿 revision 合并”或独立草稿；契约确认前只承诺明确提示用户保持同一合集单端编辑，不能声称可靠支持同时编辑。
- 如产品要求跨端并发时也不误合并任何他人修改，则该场景必须列为后端依赖的发布门槛；不能用提示或 `--yes` 当作实现了并发保护。
- 全目录分页也需要稳定快照保证。没有远端 revision 时，前后复查只降低风险，无法完全排除等量增删；把这个限制与 merge 的并发限制一起验收。

### 8.3 未知结果恢复

沿用本地 `prepared` / `sending` 区分“尚未允许请求”与“可能已发送”，但扩展合集专有核验对象：操作种类、批次、具体目标 ID、字段/顺序摘要、已确认 itemId 映射和提交前后基线。

- 尚未发送：可安全清理准备标记，保留稿。
- 目录草稿写入超时：先查草稿成员与具体字段；可以确认目标已存在且匹配时只记完成。未见结果并不能证明未执行，禁止盲重试。
- 合并超时：查已发布目录和表单。必须完整匹配期望，包括成员、顺序、标题、描述、属性、可选配置、依赖、展示和授权声明，不能用“存在版本 1.0.0”或数量一样认定成功。
- 目标状态一致只证明当前结果符合意图；没有服务端操作 ID 或对应日志时，不声称能证明恰好是本次请求执行。
- CLI 中断后不自动重复新增、签约或合并。不足以证明时保留稿和记录，明确哪些远端草稿可能已变、哪些尚未发送；读状态、diff、logs 仍可用。
- 已确认一部分批次完成但后续明确失败：使用 `collection publish --resume`，仅在未决请求均已核验、工作稿意图未改、平台仍等于已确认检查点时允许。恢复不是重跑整个清单。这里的修复是恢复网络或解决同一意图的外部条件，不能带着修改后的稿套用旧批次进度。
- 部分成功后确实需要更改意图：提供 `recover --apply --replan`。只有所有请求结果已决、没有发起 merge、线上仍等于原基线、平台草稿严格匹配已确认检查点时才允许；将该平台草稿作为已明确接手的新基线，保留原期望 target 和表单供继续编辑，本地事务移除旧批次执行记录。之后 publish 根据新基线计算差异，已完成部分不会重复添加；不重置平台草稿、不撤销合约。任一条件无法证明则保留原记录并报告冲突。
- 创建合集壳超时：按已提交的完整标识查询，核对 owner/主体/类型；只有能够排除创建前已有同名对象等歧义时才绑定，不能直接重发 POST。

目前草稿 reset/丢弃/占有标志未形成完整契约；不能设计默认 `--force` 清空平台草稿作为修复方案。

## 9. 主要用户场景

以下示例均为设计示意。假设已登录 dev、当前工程只绑定一份合集，多份时补 `--resource id:<合集ID>`。

### A. 全新合集，从已有线上资源开始

```sh
freelog-cli collection create --type <合集叶子类型> --name travel --title "旅行摄影" --env dev
freelog-cli collection item add --env dev
freelog-cli collection attr add "名称=作者 键=author 值=张三" --env dev
freelog-cli collection option add "名称=布局 键=layout 方式=下拉 选项=紧凑|宽松" --env dev
freelog-cli collection dep add <上游单资源ID> --env dev
freelog-cli collection diff --env dev
freelog-cli collection publish --env dev
freelog-cli collection policy template apply <模板ID> --name "公开策略" --env dev
freelog-cli collection update --intro "旅途中的照片" --env dev
freelog-cli collection online --env dev
```

表单文本格式沿用现有解析器，具体 help 在实现时验证；可选配置示例仅在后台允许的类型使用。没有单品时应提示先创建并上架单资源，也允许保留空合集壳稍后继续，不自动批量发行文件。

### B. 已有线上合集，本机没有缓存

`collection bind` → `collection status` → `collection draft pull` → `item add/remove/move/update` → `diff` → `publish`。无需源资源文件或本地单资源身份，不改变原合集上架状态；发现 Console 草稿时明确接手或回 Console 处理。

### C. 连载合集持续添加

先在单资源工程完成 `update-version` 或新资源的创建/上架，再在合集工程加入新成员、移到指定位置、改本次说明、发布。源单资源更新本身不产生第二个单品。目录展示方向与编号变化需在 diff 里解释。

### D. 一次整理数百个单品

交互按 100 一批加入本地稿，或导入明确 ID 清单；跨页保留选择。整体预览后发布时分批写草稿；第 2 批失败明确记录第 1 批已完成，修复后核验检查点再 resume。不能把前 100 条成功当作全部成功。

### E. 只改合集表单，单品不变

拉稿 → 修改属性、文本/下拉配置、依赖范围、说明或展示 → diff → publish。`isMergeCatalogueDraft:0`，不顺便合并 Console 未发布目录；若契约显示该调用仍影响目录，必须先修正规划并阻断交付。

### F. 删除、改名、排序

删除成员只影响当前合集；自定义别名不改源标题；move 不以行号定位；sort 处理全集。已有依赖、属性、配置、授权声明必须原样保留，不因编辑单品而被清空。

### G. 源资源改名、更新、下架或冻结

改名只刷新平台展示；新版本只刷新可观察源版本，引用仍是同一个资源 ID。已加入单品后下架/冻结时标识具体失效原因，不自动从目录删除。添加阶段必须已上架；对历史失效成员发布/消费的处理以平台契约核实，不能从“新增须上架”推导出“所有存量成员下架就禁止一切合集管理”。

### H. 多合集、跨账号、离线、中断

不同合集可以引用同一源资源，条目 ID 互不通用。当前账号非 owner、环境不符、合集冻结都阻断写；离线允许读取本地稿/diff 的本地部分，但必须注明平台未核验，不能显示“可发布”。改稿中断可接续；平台写入中断按 §8 恢复。

### I. 只管理策略、listing 或上下架

不用建立合集工作稿，不要求任何本地产物。上架前核验已发布合集内容和启用策略；有本地待发布修改时提示此次上架使用已发布内容，不暗中发布。下架不丢稿，重新上架不重复创建目录。

## 10. 自动收录与 RSS

### 10.1 自动收录建议第二阶段交付

提供 `collection collect-rules show/set`，交互解释“完结/连载”“自动收录开/关”“全部满足/任一满足”，字段与操作符沿用 C2。脚本通过 `--input <rules.json>` 提供完整显式规则，避免大量难记 flags。

规则属于即时平台设置，保存在平台；不放进永久身份，不假装必须 publish 才生效。设置前预览匹配候选及规则变化，但若后台实际匹配逻辑不公开，预览必须标为估算，不能承诺精确收录清单。禁用后仍需核实是否存在在途收录任务。

开启自动收录的合集仍可能允许手动增删，但“删除后是否会再次收录”“规则是否追溯历史资源”“更新状态与收录状态是否联动”“收录直接进入线上还是草稿”都需确认。正式支持前，发现已开启自动收录则允许读取和 listing/策略管理，阻断可能与自动任务竞争的手动目录发布并说明原因，不暗中关规则。切换为完结不能自行假定停止收录。

### 10.2 RSS 边界

按类型能力和实际绑定情况判断：仅 RSS 能力的类型不能走资源库创建；同时支持两种入口时本轮选资源库。已绑定 RSS 的合集只开放确认可编辑的管理项，例如标签/策略/上下架；目录、属性发布及来源受控字段按 Console 禁止编辑。不能只检查类型名称或 typeCode 前缀。[E1、E6]

RSS 发码、绑定、换 feed、同步、失败重试作为独立后续设计，不夹带进手动合集首版。

## 11. 实现前必须补齐的契约验证

这些是明确待验证项，不是已证实的后端缺陷。可先开发纯本地编辑和只读选择，不应在未知语义下实现“保证成功”的远端写流程。

| 编号 | 问题与所需证据 | 影响 |
|---|---|---|
| K1 | 新建壳后目录草稿如何初始化；草稿是否基于当前线上目录；是否能区分干净/不存在/空但有删除意图；版本草稿与目录草稿的关系 | 安全 pull、首次 publish、Console 接手 |
| K2 | 草稿有无 revision/ETag、独占编辑或独立 ID；merge 是否支持条件更新、幂等键；空草稿、整批原子性与 partial 返回 | 并发保证、recover、分批续作 |
| K3 | 单品 itemId 合并前后是否稳定；资源发布新版本后合集消费端的版本解析行为 | 稳定定位、版本说明 |
| K4 | 排序字段、targetSortId 插入方向、同值顺序、连载 number 的生成及重排行为 | move/sort 正确性 |
| K5 | 删除最后一个单品能否发布；无单品能否上架；存量成员下架/冻结后的发布与访问规则 | 空合集和失效单品处理；本地删除仍允许预览，不猜线上允许 |
| K6 | 授权排除真实 DTO、基础上抛授权/付费待执行合约、签约主体字段；集合直接依赖的循环校验 | 授权完整性，不能照搬旧单资源过滤 |
| K7 | 合集各表单字段限制、系统附加属性、可选配置能力；catalogueProperty 缺失类型补齐；未知字段写回能力 | 无损维护 |
| K8 | 自动收录修改的是线上还是草稿、时序与停用语义；RSS 只读字段准确边界 | 第二阶段范围和冲突检测 |

## 12. 验收场景矩阵

每组都应记录单测/契约/dev/真实 TTY 哪层已证明。dev 选本人资源测试；重复执行动态命名并保留资源 ID 到本地忽略报告，不依赖固定公共资源名。

| 组 | 必测情形 | 可观察通过条件 |
|---|---|---|
| C01 创建 | 可用合集叶子；禁用/非叶/单资源类型；RSS-only；标题/标识边界；查重；中断 | 合法创建 subject=4；非法输入无远端写；不产生 filePath |
| C02 绑定 | 无本地缓存；重复 bind；非本人/冻结；错误环境；绑定单资源；多身份 | 不复制文件、不覆写另一身份；多份需明确选择 |
| C03 资源库 | 无本人资源；未上架/未发行/冻结；1/50/51/100/101 个；同名；多层类型；过滤/搜索/翻页 | 选择 ID 准确；跨页已选保留；取消无修改；单批不截断 |
| C04 指定资源 | 线上 ID/完整名；拒绝本地 JSON/文件/目录；错误/重复/跨环境/缺失资源；导入非法字段 | 线上核实本人上架资格后本地整批校验原子；无静默部分成功 |
| C05 添加与发布衔接 | 本人已上架；本地刚发版但未上架；本地完成上架后刷新查询；Console创建且本地无缓存；已有单品；待删除后撤销；大量分批 | 仅线上合格成员可加入；无重复/别名覆盖；刷新保留选择；添加失败不重复发行源资源；总数量不限于100 |
| C06 单品编辑 | 改标题与源标题隔离；重复别名；删首/中/末/全部；另一合集 itemId | 删除仅作用当前合集；错误身份无写入 |
| C07 顺序 | 跨页 move、首尾移动、自己相对自己、同值排序、方向/连载编号 | 线上顺序与目标逐项一致；相同值可重复复验 |
| C08 表单 | 系统附加、自定义属性、文本/下拉配置、依赖与描述共同创建 | publish 读回所有字段，与输入逐项相符 |
| C09 表单维护 | add/set/rm、空值清除、配置失效、待复核、未知字段、存量排除 | 无静默丢值；仅表单 publish 不合并无关目录 |
| C10 授权 | 已授权；显式免费/付费策略；缺策略；签约失败；单品上抛授权；授权变化后 authorize 补签；本人资格与依赖资格分别测 | 策略由用户选；publish 不签约；签后支付留浏览器；不能把跳过支付当支付通过 |
| C11 策略与上架 | 策略全量、模板翻页、添加/开关；无启用策略；listing修改/清空；上/下架 | 发布、listing、策略、上下架副作用准确分离 |
| C12 跨端 | Console 先有草稿、显式采用；CLI编辑后Console改目录/表单；自动收录介入 | 可检测冲突不覆盖；无 CAS 的竞争窗口明确标为未保证 |
| C13 中断 | 本地写失败；第2批部分失败；草稿请求超时；合并超时；成功后本地清理失败；resume 时改稿或远端变化；已决部分提交 replan | 不盲重试；保留可解释检查点；仅同一意图安全续作；replan 无平台重置；恢复后无重复、无误删 |
| C14 源资源变化 | 改名、发布新版本、下架、冻结；多合集引用同一源 | 引用身份稳定；不自动删除；实际版本解析有 dev/消费端证据 |
| C15 本地安全 | N.collection损坏、孤儿稿、schema未来版本、离线、多进程锁、换账号、单资源混存 | 拒绝危险写；可诊断；不改变单资源文件/目录规则 |
| C16 平台分页 | 大目录中途翻页失败、重复ID、总数变化、等量增删；完整 --all | 不形成不完整成功快照；并发无法证明时明确限制 |
| C17 自动/RSS | 已启用自动收录、RSS绑定、只RSS类型、禁止字段及允许标签 | 手动目录操作门禁真实有效；阶段二未完成不宣称支持 |
| C18 交付 | 全命令参数表、帮助、成功/失败JSON、Windows/macOS node-pty、包内文档 | 人与AI有可执行示例；非TTY无交互；当前单资源回归通过 |

首条 dev 主链必须含：使用现有单资源流程从本地创建/发行/上架 → 从线上本人资源库查出该资源 → 创建合集并选择线上单品 → 加属性、文本及下拉配置、依赖 → 首次发布 → 策略/listing/上架 → 拉稿 → 增删改排单品与修改完整表单 → 再次发布 → 逐字段读回 → 下架/重新上架。另跑从 Console 已有合集 bind 起步、添加没有本地缓存的线上本人资源的链路。后端 DSL 问题独立标 BLOCKED，不能漏测表单和单品主路径。

## 13. 推荐落地顺序

当前优先讨论单资源快速发行，但本节任务是合集自身的独立规划。合集创建/绑定、线上添加、目录发布可直接使用已有线上资源，不依赖快速发行执行器。旧草案的批次afterResources耦合方案撤销；两个能力分别定稿、实现和验收。

1. 复核本文对象、命令和工作稿模型；在 §11 做只读 Console/API 契约调查，确定哪些问题需要 dev 写入试验。先补合集字段对照表。
2. 正式设计更新：ARCHITECTURE 本地身份/选择/环境/锁、PHASE/合集、COMMANDS、用户场景、DEV计划；将旧业务分册 CLI 示例标为历史参考，清理 root DESIGN 入口歧义。
3. 身份与只读能力：判别联合、本地诊断/选择、create/bind 门禁、合集类型选择、本人资源库分页和稳定定位。
4. 工作稿与编辑：本地快照、完整表单、单品增删改排、diff、pull/discard、平台草稿接手。
5. 共享业务提取：属性/配置/依赖校验、策略、listing、上下架；按合集上下文调用，跑现有单资源回归。
6. 平台写流程：批次结果核验、草稿 adapter、merge 发布、部分失败、pending/recover/resume；以 K1/K2/K6 已验证契约为前提。
7. dev 与跨端验收：按 C01–C18 对照执行；补齐包内使用文档和可复用测试入口；阶段二单独完成自动收录契约和实现。

详细实施影响清单见 [.omx 规划文件](../../../.omx/plans/2026-09-15-合集CLI设计与实现规划.md)。本设计交付结束于可复核草案，未注册任何新增 CLI 命令。
