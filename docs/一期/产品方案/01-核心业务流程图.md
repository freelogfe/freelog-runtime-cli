## 📋 **二、流程详解索引**

### **A. 创建类流程 (F1-F3)**

#### **F1: 创建单个资源** - 4 步向导模式

```bash
$ freelog publish my-theme

Step 1: 创建资源壳
├─ 选择资源类型 (Theme-Aurora / Plugin-Vue...)
├─ 输入标题 → 自动优化授权标识 {owner}/{authid}
├─ 实时验证唯一性
└─ 创建成功 → 返回 resourceId + resourceName

Step 2: 上传资源文件
├─ 拖拽/选择本地文件
├─ 格式验证 (ZIP/TAR.GZ)
├─ 断点续传支持
└─ 返回 FileID + SHA1 hash

Step 3: 配置授权策略
├─ 选择模板 (Free / Commercial / Custom)
├─ 策略配置向导
└─ 编译为可执行策略 JSON

Step 4: 完善 listing 信息
├─ 上传封面图片 (≤5MB, 16:9 推荐)
├─ 添加标签 (逗号分隔，自动去重转小写)
├─ 填写描述
└─ 确认上架

完整场景脚本：docs/流程设计/01-创建单个资源.md
```

**适用场景**:
- 首次发行单资源 (主题/插件/前端库/软件库)
- 需要完整交互体验的新手用户

---

#### **F2: 批量创建资源** - 目录扫描 + 并发控制

```bash
$ freelog batch-publish ./my-themes/

Phase 1: 扫描阶段
├─ 递归扫描子目录
├─ 识别 manifest.json
├─ 发现 N 个资源条目
└─ 分类有效/无效/重复条目

Phase 2: 批次划分
├─ batchSize = 10 (可配置)
├─ maxConcurrency = 3 (可配置)
└─ 冻结资源跳过而非报错

Phase 3: 并发发布
├─ 并行执行 F1 流程
├─ 进度条实时监控
└─ 失败项自动重试 (maxRetries = 3)

Phase 4: 汇总报告
├─ 成功：X 个
├─ 失败：Y 个
├─ 跳过：Z 个 (冻结)
└─ 生成 CSV/PDF 报告

完整场景脚本：docs/流程设计/02-批量创建资源.md
```

**适用场景**:
- 一批同类型资源 (如系列主题)
- 运营人员的批量操作需求

---

#### **F3: 创建合集** - 从目录扫描手动添加

```bash
$ freelog collection create ./my-series/

Step 1: 目录扫描
├─ 递归扫描子目录
├─ 识别每个子目录的 manifest.json
└─ 提取元数据 (标题/作者/版本)

Step 2: 创建合集壳
├─ 输入合集标题 [回车默认"我的系列剧集"]
├─ 输入描述 (可选)
└─ Collection.create() → 返回 collectionId

Step 3: 关联资源到合集
├─ 循环添加条目
├─ Collection.addResource(collectionId, resourceId)
└─ 自动去重检查

Step 4: 排序与收录规则
├─ 调整条目顺序 (文件名/版本号/手动拖拽)
├─ 配置 collect-rules (AND/OR逻辑)
└─ 启用/禁用自动同步开关

完整场景脚本：docs/流程设计/03-创建合集.md
```

**适用场景**:
- 视频剧集/系列教程等连续内容
- 需要从本地目录快速构建合集

> **注意**: RSS 绑定功能暂时忽略，留待二期实现

### **B. 资源管理流程 (M1-M3)**

#### **M1: 版本更新** - 已有资源的新版本发布

```bash
$ freelog update RES-THEME-8847953

Step 1: 读取远端状态
├─ Resource.getDetail(resourceId)
├─ 获取当前最新版本号 (1.0.0)
└─ 获取远端所有字段值

Step 2: 继承可继承字段
├─ 标题/描述/标签继承自原版本
├─ 用户可选择性覆盖
└─ 版本号自动建议 (1.0.0 → 1.0.1)

Step 3: 创建新版本
├─ 验证 semver 递增 (必须 > 1.0.0)
├─ 拒绝降级 (禁止使用 0.9.0)
└─ 创建 Version ID

Step 4: 上传新文件
├─ 压缩产物为 artifact.zip
├─ 调用 Resource.createVersion()
└─ 返回 FileID + SHA1

Step 5: 策略与 listing 更新
├─ 继承原策略或重新选择
├─ 更新 listing(封面/标签)
└─ 提交生效

完整场景脚本：docs/流程设计/04-版本更新.md
```

**适用场景**:
- 修复 bug 后发布补丁版本
- 功能迭代后的主版本升级

---

#### **M2: listing 属性更新** - 封面/标签/描述维护

```bash
$ freelog listing update RES-THEME-8847953

Step 1: 展示当前值
├─ Listing.getDetail()
├─ 显示当前封面图片 URL
├─ 显示当前标签列表 ["星空", "主题"]
└─ 显示当前描述文本

Step 2: Diff 对比变更
├─ 用户修改的部分高亮显示
├─ 未修改部分灰色显示
└─ 示例:
    ○ 封面：https://... (保持不变)
    ✎ 标签：["星空", "主题", "深色模式"] (新增"深色模式")
    ✎ 描述：以深邃星空为背景... (修改了第一句)

Step 3: 只提交修改的字段
├─ Listing.patchUpdate({
│     tags: ["星空", "主题", "深色模式"],
│     description: "..."
│   })
└─ 不修改的字段不会回写

完整场景脚本：docs/流程设计/05-listing 属性更新.md
```

**适用场景**:
- 优化搜索关键词 (标签)
- 改进商品描述文案
- 更换更吸引人的封面图

---

#### **M3: 授权策略管理** - 策略模板切换

```bash
$ freelog policy manage RES-THEME-8847953

Step 1: 查看当前策略
├─ Policy.getDetail()
├─ 显示当前使用的模板 (Free License v2.0)
└─ 展示策略摘要 (允许/禁止规则)

Step 2: 选择新模板
├─ 浏览所有可用模板
│   ├── Free (免费开放下载)
│   ├── Commercial (商用需授权)
│   └── Custom (自定义策略)
└─ 点击"使用此模板"

Step 3: 策略配置编辑
├─ 可视化编辑器 (GUI 模式)
├─ OR 输入自定义 JSON Schema
└─ 实时语法验证

Step 4: 编译验证
├─ Policy.compile()
├─ 检测逻辑冲突 (如"允许商用"与"禁止分发")
└─ 生成可执行的策略字节码

Step 5: 预览策略摘要
├─ 自然语言描述 ("任何人都可以免费下载，但禁止商业使用")
├─ 决策树可视化
└─ 确认无误后点击"提交"

完整场景脚本：docs/流程设计/06-策略管理.md
```

**适用场景**:
- 免费资源改为付费销售
- 修改授权范围 (如从"个人使用"扩展到"企业使用")

### **C. 合集管理流程 (C1-C3)**

#### **C1: 单品管理** - 合集内条目增删改序

```bash
$ freelog collection items COL-BLOG-12345

Step 1: 列出合集所有条目
├─ Collection.getItems(collectionId)
├─ 显示条目列表 (标题/版本号/发布时间)
└─ 每项右侧有操作按钮 [编辑][删除]

Step 2: 添加新条目
├─ 点击"+ Add Item"
├─ 选择已有资源 (从平台列表)
└─ 或输入新资源的 resourceId

Step 3: 移除旧条目
├─ 点击某条目的"[Delete]"
├─ 二次确认弹窗
└─ 仅解除关联 (不删除原资源)

Step 4: 调整顺序
├─ 拖拽条目上下移动
├─ 或输入序号数字直接设置
└─ 实时反馈新顺序

Step 5: 保存变更
├─ Collection.updateItems()
├─ 异步更新合集结构
└─ 通知订阅者 (Webhook)

完整场景脚本：docs/流程设计/07-单品管理.md
```

**适用场景**:
- 添加新章节到剧集
- 移除过时内容
- 调整观看顺序

---

#### **C2: 合集信息更新** - 标题/描述/封面维护

```bash
$ freelog collection update COL-BLOG-12345

Step 1: 展示当前值
├─ Collection.getDetail()
├─ 显示当前标题、描述、封面
└─ 显示统计信息 (条目数/总播放量)

Step 2: Diff 对比
├─ 用户修改的部分高亮
├─ 示例:
    ○ 标题："技术博客合集" (保持不变)
    ✎ 描述："记录最新技术动态..." (新增"AI 专题")
    ✎ 封面：upload new image.jpg

Step 3: 只提交修改的字段
├─ Collection.patchUpdate({
│     description: "... AI 专题 ...",
│     coverUrl: "https://..."
│   })
└─ 未修改的标题不会回写

完整场景脚本：docs/流程设计/08-合集信息更新.md
```

**适用场景**:
- 优化合集标题以提高曝光
- 更新封面吸引点击
- 修正错误描述

#### **C3: 合集授权策略管理** - 合集级别的策略

```bash
$ freelog collection policy COL-BLOG-12345

说明：合集策略不同于单品策略，它是整个合集的访问控制

Step 1: 查看当前策略
├─ Collection.getPolicy()
├─ 显示当前策略 (如"公开可访问")
└─ 展示策略详情

Step 2: 修改策略
├─ 选择模板或自定义
├─ 例如:"仅会员可见"或"需要购买访问码"
└─ 配置策略参数

Step 3: 验证与预览
├─ Policy.validate()
├─ 检查与单品策略的兼容性
└─ 预览最终效果

Step 4: 提交生效
├─ Collection.setPolicy()
├─ 立即对所有条目生效
└─ 记录操作日志

完整场景脚本：docs/流程设计/09-合集策略管理.md
```

**适用场景**:
- 合集从免费改为付费
- 限制访问权限 (如会员专享)

## 🔄 **三、流程间关系**

### **3.1 依赖关系**

```
创建流程 → 管理流程
F1/F2/F3 是入口，M1/M2/M3/C1/C2/C3是对已创建资源的维护

版本更新 (M1) ← 需要先有原始资源 (通过 F1/F2/F3 创建)
listing 更新 (M2) ← 依赖资源已存在
策略管理 (M3) ← 依赖策略模板系统
```

### **3.2 共享组件**

| 组件 | 被哪些流程共享 | 统一实现位置 |
|------|--------------|------------|
| **资源类型查询** | F1, F2, M1 | `services/resourceTypeService.ts` |
| **文件上传** | F1, F2, M1 | `services/uploadService.ts` |
| **策略编译** | M3, C3 | `services/policyCompiler.ts` |
| **Listing 更新** | M2, C2 | `services/listingService.ts` |
| **Checkpoint 机制** | 所有流程 | `services/checkpointService.ts` |

### **3.3 数据流向**

```
F1/F2/F3 (创建) 
   ↓
平台数据库：Resource 表 / Collection 表
   ↓
M1/M2/M3/C1/C2/C3 (管理)
   ↓
更新数据库记录 → 触发 Console 实时更新 → CDN 刷新
```
