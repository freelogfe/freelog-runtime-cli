## ⚡ **三、Checkpoint 机制总览**

整个 F3 流程涉及多个 Checkpoint 保存点:

| 步骤 | 保存时机 | 数据结构 |
|------|---------|---------|
| Step1 | SCAN_COMPLETE | validEpisodes[], invalidEpisodes[], contentType |
| Step2 | METADATA_SAVED | title, description, coverImage, author |
| Step3 | SELECTION_DONE | selectedGuids[], sortOrder[], episodes[] |
| Step4 | RSS_BINDING | feedUrl, lockedFields[], bindingResult |
| Step5 | PRE_SUBMIT | tags, strategyTemplateId, autoPublish |

详细实现请参考各步骤文档。

## 🚨 **四、核心异常分支**

| 错误码 | 触发条件 | 处理策略 |
|-------|---------|---------|
| MISSING_GUID | episode 缺少 GUID | 加入 invalidEpisodes，提示用户 |
| DUPLICATE_GUID | GUID 重复 | 终止并提示修改 |
| INVALID_FEED_URL | RSS URL 无效 | 重新输入 URL |
| CAPTCHA_REQUIRED | feed 需要验证码 | 显示验证码图像，用户输入 |
| RSS_SYNC_LIMIT_EXCEEDED | 同步数量超限 | 增加天数范围或分批同步 |
| COLLECTION_LIMIT_REACHED | 单合集条目超限 | 拆分多个合集 |

完整错误码体系请参考 [全局错误码映射表](../../通用规范/03-错误码体系.md)。

## 📡 **五、RSS 自动化收录特殊说明**

### **5.1 RSS 绑定完整流程**

1. **Feed URL 验证**: 检查格式有效性
2. **验证码检测**: 判断是否需要验证码
3. **获取 Feed 元数据**: 播客标题/作者/描述
4. **GUID 差异检查**: 检测新旧 GUID 变化
5. **数量限制验证**: 单次同步不超过 50 集
6. **锁定字段定义**: guid/pubDate/enclosure.url 等
7. **保存绑定配置**: 记录到 Checkpoint
8. **后续定时同步**: 后台任务自动拉取新集

### **5.2 验证码处理**

- 获取验证码图像 (Base64 ASCII art 渲染)
- 用户输入 6 位字符
- 后端验证后缓存 session
- 绑定成功后清除

### **5.3 GUID 差异警告**

```
⚠️ 检测到 3 个旧集 GUID 与新 feed 不匹配
   • 新增 GUID: 2
   • 修改 GUID: 1
   → 建议：使用 GUID 作为唯一标识避免重复
```
