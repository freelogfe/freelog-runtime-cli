# 主题与插件：开发、发行和更新

主题、插件仍是单资源：建资源、发行版本、自身策略和上下架分别操作。主要差别是模板和产物——主题固定 `RT001`，插件固定 `RT002`；构建目录发版时由 CLI 临时压缩，不需要用户选择资源类型。

## 从线上模板到主题首次上架

目标：从线上模板新建主题工程，开发构建，发行首版、添加自身策略并上架。

前置条件：已安装 CLI 与 Node.js 20+，有 dev 账号；在工程的父目录操作，目标 `my-theme` 尚不存在或为空。本节始终用 `--cwd my-theme` 指定工程，避免切换目录后路径混乱。

### 1. 选择并下载线上模板

```powershell
freelog-cli template list --env dev
```

这里列的是开发工程模板，不是策略模板。选适用于主题的模板；下面使用清单中的 `vite-react-ts`：

```powershell
freelog-cli init theme my-theme --template vite-react-ts --yes --env dev
```

成功后出现模板工程和默认 `dist` 产物记录。这一步不创建线上资源、不安装依赖、不构建、不渲染占位符。模板来自固定版本的线上 npm 包，不复制 CLI 仓库的本地 templates。

### 2. 登录并创建线上主题资源

若工程或父目录已有正确账号的登录，跳过 login；否则先执行：

```powershell
freelog-cli login --cwd my-theme --env dev
```

完成登录后创建：

```powershell
freelog-cli create --cwd my-theme --title "我的主题" --name my-theme --yes --env dev
```

记下返回的资源 ID。不要另选类型，也不要此时换成一个不同的 `--artifact` 来接续默认身份；更换默认产物的方法见后面的“产物路径与压缩规则”。

### 3. 停下来完成开发和构建

**不要直接跳到发版。**打开生成的工程，按它的 README 和 `package.json` 完成开发、依赖安装和构建。CLI 不代执行这些步骤。

当前模板的 `package.json` 若仍包含 `<%= projectName %>`、`<%= version %>`，构建前自行替换为合法的 npm 工程元数据，例如 `"name": "my-theme"`、`"version": "0.0.0"`。它们只服务本地包管理工具，**不是线上资源标识或发行版本号**；CLI 不从它们读取业务信息，也不会自动渲染或同步。

构建成功后确认 `my-theme/dist/` 内有真实文件，例如入口 HTML 与静态资源，而不只是空目录或软链接。不要上传含源码、依赖与 `.freelog` 的工程根目录。若构建输出叫 build 而不是 dist，先按后面的产物路径规则修改默认记录。

### 4. 发行首版

需要属性、可选配置或依赖时，先准备工作稿：

```powershell
freelog-cli create-version --cwd my-theme --resource id:<资源ID> --prepare --env dev
freelog-cli version show --cwd my-theme --resource id:<资源ID> --local --env dev
```

**可选停顿：发行前填写并核对**[属性、配置与依赖](./06-版本工作稿.md)。该专题示例需加 `--cwd my-theme`，并使用同一资源 ID。配置能力以 `type info RT001 --env dev` 的当前结果为准，不因为是主题就无条件开放。

没有这些扩展需求可以跳过准备；提交首版：

```powershell
freelog-cli create-version --cwd my-theme --resource id:<资源ID> --yes --env dev
freelog-cli version show --cwd my-theme --resource id:<资源ID> --env dev
```

CLI 临时压缩 dist 内容、上传、等待解析再提交；确认线上 `1.0.0`。报错或提交结果未知先看[故障恢复](./09-常见情况与报错.md)，不要盲目再发。

### 5. 添加自身策略

```powershell
freelog-cli policy template list --cwd my-theme --resource id:<资源ID> --env dev
```

**停下来完成选择与确认**：选模板 → 核对全文与参数标记 → 修改名称和所需参数 → 预览译文 → 确认创建。列表每页 20 条可翻页；退出不会创建。非交互执行只查询，AI/脚本请用[策略参数提交路径](./07-单资源授权策略.md#ai-或脚本添加策略)，同样加工程目录与资源 ID。

创建成功后读回：

```powershell
freelog-cli policy list --cwd my-theme --resource id:<资源ID> --env dev
```

至少一条符合预期且启用的自身策略，才能继续。

### 6. 检查并上架

```powershell
freelog-cli validate --for online --cwd my-theme --resource id:<资源ID> --env dev
```

检查成功后才执行上架；缺版本或启用策略时先停下来修正：

```powershell
freelog-cli online --cwd my-theme --resource id:<资源ID> --yes --env dev
freelog-cli status --cwd my-theme --resource id:<资源ID> --env dev
```

先读检查结果；缺版本或启用策略时停下来修正。online 正常完成没有专门成功文案，也不读回上下架状态；status 只显示身份、工作稿与 latest。最后在浏览器资源管理页核对该 ID 已上架。完成标准：线上首版存在、自身策略启用、浏览器确认资源已上架。模板下载或 build 成功都不是发行完成。

## 插件从模板开始

如果目标是插件，**用下面这条替代主题初始化命令**，不要先建主题再建插件：

```powershell
freelog-cli init widget my-widget --template vite-vue-ts --yes --env dev
```

后续仍按本页第 2–6 步操作，将工程目录统一换成 `my-widget`，标题、标识和返回 ID 换成插件的；固定类型为 `RT002`。安装构建依照所选模板实际脚本，不假设所有模板的包管理器相同。

## 已有本地主题或插件首次发行

不要运行模板初始化覆盖已有项目。在自己的项目根登录，先完成构建并确认真实产物。若线上还没有对应资源，可以直接创建：

```powershell
freelog-cli create --title "已有主题" --name existing-theme --type RT001 --artifact dist --yes --env dev
```

插件用 `RT002` 替代 RT001；产物名不是 dist 则换成实际目录或文件。记下 ID，继续本页第 4–6 步完成发行和上架，**删除示例中的 `--cwd my-theme`**，因为现在已在自己的项目根。

已有线上资源则不要 create：按[绑定后更新完整教程](./04-日常路径.md#接入已有资源并发布新版本)操作，将示例 video.mp4 换成实际构建目录。线上只有资源壳时 bind 后发行首版；有已发版本时 bind、拉更新稿、编辑、update-version。每次发版前都先重新构建。

## 产物路径与压缩规则

`--artifact` 是本次产物路径，不是资源选择器。普通资源必须是单个文件；主题、插件可用工程内目录或单文件（包括已生成的 zip），且必须真实存在。目录发行时必须非空，软链接不入包。

模板默认记录 dist。想接续**同一份模板身份**，先将默认路径改成已经存在的 build，再 create：

```powershell
freelog-cli version set --cwd my-theme --artifact build --env dev
```

随后按本页第 2 步 create，不另传不同路径。不同的 `create --artifact` 表示另一份产物的新身份，不会暗中覆盖默认 dist。已经绑定的资源发版要换产物，则先给 `--resource id:<资源ID>` 选目标，再给发行命令 `--artifact <新路径>`。

目录仅打包其内容，不多包一层 dist；临时 zip 成功或失败后都会删除。单文件直接上传，不重复压缩。本地版本稿与普通资源相同，不另建一套目录版本缓存；更多本地文件含义见[文件参考](./10-本地文件参考.md)。
