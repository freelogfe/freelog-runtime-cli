# 资源管理

本页管理已绑定资源的线上事实：展示信息、标题同步、授权策略和可用状态。它们不替代版本发行，也不会修改未提交版本工作稿。发版看[资源生命周期](./02-日常路径.md)，工作稿看[版本工作稿](./04-版本工作稿.md)，所有命令的精确契约看[完整命令参考](./10-命令参考.md)。

多资源工程中，本页除不带选择器即批量的 `resource sync` 外，每条命令都加 `--resource <selector>`。优先用 `id:`、`name:` 或 `artifact:<当前文件>`；`file:N.json` 保留给 AI、脚本和恢复。

## 查看现状

```powershell
freelog-cli status --resource id:<资源ID> --env dev
freelog-cli version show --resource id:<资源ID> --env dev
freelog-cli version show --resource id:<资源ID> --version 1.0.0 --env dev
freelog-cli policy list --resource id:<资源ID> --env dev
```

`status` 汇总本地身份、是否存在工作稿和线上 latest；`version show` 与 `policy list` 读取平台当前结果。若只想看本地未交内容，用 `version show --local`。

## 修改展示信息

```powershell
freelog-cli update --resource id:<资源ID> --title "新标题" --yes --env dev
freelog-cli update --resource id:<资源ID> --intro "一句话简介" --tags "教程,视频" --yes --env dev
freelog-cli update --resource id:<资源ID> --cover cover.png --yes --env dev
```

`update` 只会发送明确给出的字段：标题、简介、封面和标签。它不会提交新版本、修改资源标识或上下架状态。`--intro ""` 会清空简介，`--tags ""` 会清空标签；封面只能传工程内 JPG/PNG/静态 GIF（≤5MB），CLI 先上传图片，再把平台返回 URL 写入资源。暂不支持清空封面。

- 标题最多 100 个字符，简介最多 200 个字符。
- 标签最多 20 个，每个最多 20 个字符，不能重复。输入 `#colour` 时，`#` 只是展示前缀，CLI 会写入 `colour`；只有 `#` 的空标签会被拒绝。
- `--yes` 且没有任一修改字段会失败，不发送空更新。

## 同步本地标题

资源标题可能在网页、另一台机器或其它工具中修改。标题只用于展示，**从不用于选择资源**；需要刷新显示时显式同步：

```powershell
# 当前环境的全部已绑定资源；这是唯一的批量资源命令
freelog-cli resource sync --env dev

# 只同步一份资源
freelog-cli resource sync --resource id:<resourceId> --env dev
```

同步只读取平台资源详情并在响应 `resourceId` 与本地身份完全相同时回写对应 `N.json.title`；不会改版本工作稿、产物路径或线上资源。部分失败时成功项已安全写入，失败项保持原值，命令以非零退出并列出失败的状态文件。`update --title` 成功时会立即回写当前选中身份的标题，无需再同步。

## 提交结果未知时恢复

网络断开、超时或进程在版本提交后中断时，CLI 不会猜测“失败”后再次提交。它会保留工作稿，并在 `.freelog/.pending-operation.json` 记录目标资源、版本和文件 SHA。先查看核验结果：

```powershell
freelog-cli resource recover --env dev
```

CLI 只查询该资源的**目标版本**。只有版本存在且远端 `fileSha1` 与记录完全相同，才会显示“已确认”。此时再明确完成本地收尾：

```powershell
freelog-cli resource recover --apply --yes --env dev
```

这会原子删除该资源已确认提交的工作稿和未决记录；不会重发版本。若版本不存在、SHA 不同、环境不对或本地身份不一致，CLI 会保留两份文件并停止。未决记录存在时，除登录、退出、只读查看和 `resource recover` 外，新的业务写入都会被拦住。

## 管理授权策略

```powershell
freelog-cli policy list --env dev
freelog-cli policy template list --page 1 --page-size 20 --env dev
freelog-cli policy template apply <templateId> --yes --env dev
freelog-cli policy apply --from-file .\free-policy.json --yes --env dev
freelog-cli policy set --id <policyId> --on --env dev
freelog-cli policy set --id <policyId> --off --env dev
```

`policy template list` 按当前资源类型列出**全部**平台模板（默认每页 20 条），包含带交易事件的模板，不按免费/付费过滤。交互执行 `policy template apply` 时可在每页选择、翻页或取消；脚本执行必须提供 `<templateId> --yes`。应用模板或 `policy apply` 都会新增一条**启用**的授权策略，但不会触发支付，也不会自动上架。

`policy apply --from-file` 接受策略文本文件，或包含 `policyName` 与 `policyText` 的 JSON 文件；若文本文件或 JSON 未提供名称，非交互模式还必须传 `--name <策略名>`。策略语义最终由平台校验。

## 上架与下架

```powershell
freelog-cli validate --for online --env dev
freelog-cli online --env dev
freelog-cli offline --env dev
```

上架前必须已有至少一个已发版本和一条启用策略。`validate --for online` 只检查并说明缺失项；`online` 会再次检查后才写线上状态。`offline` 只改变可用状态，不删除资源、版本、策略、身份或工作稿。

如果账号不是资源 owner、资源被冻结或环境不匹配，平台写操作会失败。CLI 不会因此删除本地工程或未提交工作稿；修正登录账号或环境后可继续。
