# 05 - 资源管理

发行之后随时可跑，**不接续**创建流程。门禁：已登录、是本人、未冻结。

---

## 1. 看现状

```bash
freelog-cli status --env dev
# 本地：1.json my-video RT006003 video.mp4
# 工作稿：无
# 线上：resourceId=6a9e… latestVersion=1.0.0

freelog-cli version show --env dev                  # 线上 latest 详情（JSON）
freelog-cli version show --version 1.0.0 --env dev  # 指定已发号
freelog-cli version show --local --env dev          # 本地工作稿（不拉线上）
```

`status` 只打印，不改文件、不接续。

## 2. 改已发号描述（不发新号）

```bash
freelog-cli version description --version 1.0.0 --description "新描述" --env dev
```

只 PUT 描述；文件 / 属性 / 依赖不动。要改这些走发新号（`update-version`）。

## 3. 改 listing（标题 / 简介 / 封面 / 标签）

```bash
freelog-cli update --title 新标题 --intro "一句话简介" --cover ./cover.png --tags 视频,教程 --env dev
freelog-cli update                       # TTY 逐项问，回车跳过
freelog-cli update --title 只改标题 --yes --env dev
```

- 标识（`username/name`）**只读**，创建后不能改。
- 标题 ≤100 字符；超长 `--yes` 直接失败。
- `--yes` 且一个 flag 都没带：失败，不做空 PUT。
- 不带 `status`——上下架是 `online` / `offline` 的事。

## 4. 授权策略（上架前置条件）

```bash
freelog-cli policy list --env dev                    # 看已有策略（启用的排前）
freelog-cli policy template list --env dev           # 平台免费策略模板
freelog-cli policy template apply <templateId> --env dev
freelog-cli policy apply --from-file ./free.json --yes --env dev
freelog-cli policy set --id <policyId> --on --env dev
freelog-cli policy set --id <policyId> --off --env dev
```

- 本期**只做免费策略**：含付费事件（TransactionEvent）的模板不会列为可申请，付费文本也会被拒。
- `--from-file` 传**策略文本**（或 `{"policyName","policyText","status"}` 的 JSON）。
- 资源已上架时不能把启用策略关到 0 条——会失败。
- 加完策略不会自动上架；下一步自己跑 `online`。

## 5. 预检与上下架

```bash
freelog-cli validate --for online --env dev
# 逐条打印：有版本？有启用策略？
# 全过 → 「可以上架」；有失败 → 退出码非 0

freelog-cli online --env dev        # 预检过了才 PUT status:1；已上架则直接提示
freelog-cli offline --env dev       # status:4；下架不要求策略
```

- 缺版本或缺启用策略：`online` 失败且**不打开策略编辑**——先 `policy` 再来。
- 下架后资源留在账号里（status=4 待上架），随时 `online` 再上。

## 6. 已发版依赖（只读）

没有 `version dep` 的「已发号补签」入口。看依赖：`version show`。要改树 / 补依赖：`version draft pull` → `version dep add` → `update-version`。
