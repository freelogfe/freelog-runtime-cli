# 环境、登录与凭据

账号选择与资源选择是两件事：登录决定以谁的身份请求平台；`--resource` 决定操作哪个资源或合集。两者都要与工程、环境一致。

## 环境

| 环境 | 当前状态 |
|---|---|
| `--env dev` | 开发联调可用。 |
| `--env test` | 测试联调可用。 |
| `--env prod` | 当前 CLI 拦截平台调用。 |

优先级：命令行 `--env` → 环境变量 `FREELOG_ENV` → `prod`。教程每条示例显式带 `--env dev`；切换时同时检查身份记录和凭据环境，不复制 dev 身份去当 test 资源。

## 人工登录与切换

```powershell
freelog-cli login --cwd <工程目录> --env dev
```

在交互终端输入账号与密码。当前目标已经有选择器时，必须先退出再登录：

```powershell
freelog-cli logout --cwd <选择器所在目录> --env dev
freelog-cli login --cwd <选择器所在目录> --env test
```

`logout` 不删除资源身份、版本工作稿或线上资源。登录请求默认 15 秒超时；网络、认证或系统凭据保存失败时不会留下有效登录选择器。

## 目录继承与全局默认

命令从 `--cwd`（未传时当前目录）向上查找最近的 `.freelog/auth`。例如已在父目录登录，`--cwd my-theme` 可以继承父目录账号；如果要为该工程单独选择账号，在工程内 login。

找到了最近的选择器，却损坏、凭据缺失或环境不一致时，命令停止，**不会跳过它使用父目录或全局账号**。退出继承的账号时应明确使用实际选择器所在目录。

需要机器默认账号时登录：

```powershell
freelog-cli login --global --env dev
```

之后确实需要清除机器默认账号时再执行，不是登录后的下一步：

```powershell
freelog-cli logout --global --env dev
```

全局默认只有在目录向上没有工作区选择器时才生效。

## AI、脚本与 CI

非交互登录同时提供账号、保密标准输入和确认：

```powershell
freelog-cli login --login-name <账号名> --password-stdin --yes --cwd <工程目录> --env dev
```

这不是可直接复制执行的完整密码输入流程：调用方须通过受保护的标准输入供应密码。不要将真实密码写进命令行、示例、脚本、JSON、日志或 Git；也不要以明文环境变量作为教程中的传递方式。CLI 没有公开 `--password` 参数。

## 凭据存放与安全

| 内容 | 存放位置 | 可提交 Git |
|---|---|---|
| 工作区账号选择器 | `.freelog/auth` | 否。 |
| 机器默认选择器 | 用户目录的 `.freelog/auth-default.json` | 否。 |
| token、Cookie 等登录秘密 | 操作系统凭据库 | 不作为工程文件。 |

选择器只保存环境、用户 ID、账号名、schema 与凭据库 key，不保存密码、token 或 Cookie。复制它到另一台机器不能移植登录态，另一台机器需重新 login。

含旧 token/cookie/iv 的文件不自动解密或迁移，明确 logout 后重新登录。认证失败时停止操作；已有未提交工作内容不因退出登录而清除。其它状态与恢复边界见[本地文件参考](./10-本地文件参考.md)和[故障恢复](./09-常见情况与报错.md)。
