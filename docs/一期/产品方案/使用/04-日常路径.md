# 日常路径：接入与更新单资源

本页主要完成“已有线上单资源，绑定本地产物后发新版”。新资源首次上架看[快速上手](./01-快速上手.md)；主题从模板开始看[主题与插件](./05-主题与插件.md)。

## init、create、bind 各做什么

| 命令 | 作用 | 不会做什么 |
|---|---|---|
| init | 建立首份本地资源记录；theme/widget 还会下载模板 | 不创建线上资源、不发行、不上架 |
| create | 为本地产物创建自己的线上资源 | 不上传、不发行、不上架 |
| bind | 将自己的已有线上资源接入本地 | 不下载源码或文件、不拉版本工作稿、不发行 |

通用 init 是可选前置，直接 create 也可以。已有 init 记录时，create 接续同一产物；已有线上资源时用 bind，不再创建同一个资源。模板初始化的默认产物更改方式见[产物路径规则](./05-主题与插件.md#产物路径与压缩规则)。

## 接入已有资源并发布新版本

前置条件：你已在当前工程登录正确 dev 账号，资源属于这个账号且**已有线上版本**；工程内已经准备好本次要发行的真实产物。普通文件以下用 `video.mp4` 举例；主题/插件替换成已构建好的目录（如 `dist`），不要传源码工程根目录。

### 1. 绑定并确认目标

本地尚未接入该资源时执行：

```powershell
freelog-cli bind <资源ID> --artifact video.mp4 --yes --env dev
freelog-cli status --resource id:<资源ID> --env dev
```

停下来核对账号、资源 ID、产物路径及线上 latest。已经绑定则只查 status，不重复换绑。**默认产物路径必须指向本次要发的内容**；若路径陈旧，给第 4 步提交命令加 `--artifact <新路径>`，或先用 `version set --artifact <新路径> --resource id:<资源ID> --env dev` 更新默认记录。两种方式都要求路径真实存在。bind 不会下载文件，也不会把它变成模板项目。没有线上版本时改走本页“接入只有资源壳”的分支。

### 2. 建立更新工作稿

**已有未提交稿时，先读 `version show --local`。**下面的 pull 会建立一份来自线上 latest 的更新稿；若已有稿，交互确认覆盖会丢弃它，不要不看就加 `--yes`。

若上一步 status 显示已有工作稿，先执行：

```powershell
freelog-cli version show --local --resource id:<资源ID> --env dev
```

需要保留时不要重拉，继续编辑现有稿并核对它的来源版本；只有没有稿或明确放弃旧稿时，才执行下面的 pull：

```powershell
freelog-cli version draft pull --resource id:<资源ID> --env dev
freelog-cli version show --local --resource id:<资源ID> --env dev
```

如果取消覆盖，停止这条教程，不继续提交。AI/脚本只有明确允许覆盖旧稿时才给 pull 加 `--yes`。

### 3. 可选：修改本次版本内容

不改属性、可选配置和依赖时保留拉下来的内容。需要改时**先停下来编辑并检查**，操作见[版本工作稿](./06-版本工作稿.md)。更新说明可以直接填写：

```powershell
freelog-cli version draft description --description "本次更新说明" --resource id:<资源ID> --env dev
freelog-cli version show --local --resource id:<资源ID> --env dev
```

这一步不发行。若更换文件后出现待复核属性，先复核或明确丢弃，不能直接忽略后提交。

### 4. 提交并确认新版本

默认产物路径已经核对正确时提交：

```powershell
freelog-cli update-version --bump patch --resource id:<资源ID> --yes --env dev
```

若本次产物换了路径，**改用**下面一条，不同时执行两种提交：

```powershell
freelog-cli update-version --bump patch --artifact <本次真实文件或构建目录> --resource id:<资源ID> --yes --env dev
```

提交明确成功后再只读确认；结果未知不要重新提交：

```powershell
freelog-cli version show --resource id:<资源ID> --env dev
freelog-cli status --resource id:<资源ID> --env dev
```

确认线上新版本号、说明及内容符合预期；例如 latest 原来为 `1.0.0`，patch 后应为 `1.0.1`。发新版不自动新增策略，也不自动改变上下架状态：原本上架的资源无需再添加一条策略；原本下架的资源仍需按[资源管理](./08-资源管理.md#上架)单独上架。

### 发布新版本的版本号选择

上面的 patch 只是示例。一次提交只选一种：

| 目标 | 替换上述提交命令的版本参数 |
|---|---|
| 修订号增加 | `--bump patch` |
| 次版本号增加 | `--bump minor` |
| 主版本号增加 | `--bump major` |
| 明确指定新号 | `--version <大于当前latest的版本号>` |

不要连续执行三种 bump，也不能把 `--bump` 与 `--version` 同时传入。更新提交当前必须显式带 `--yes`。旧底复用、reset 与覆盖风险见[工作稿专题](./06-版本工作稿.md#换文件复核与放弃工作稿)；结果未知见[故障恢复](./09-常见情况与报错.md)。

## 接入只有资源壳的线上资源

前置条件相同，但线上尚无任何已发行版本。先 bind 关联真实文件或构建目录，确认 status 没有 latest，再按[首次上架教程第 4 步起](./01-快速上手.md#4-发行首版)完成首版、策略和上架。

此时不用 `draft pull` 或 `update-version`。首版固定 `1.0.0`；不要因为资源在网页创建过就当成已有版本。

## 同一目录管理多份资源

每份文件或主题产物分别 create/bind，记下各自 ID，再为每份资源分别发行、添加策略和上架。所有目标操作都传同一 `--resource id:<资源ID>`，不要依赖标题或本地记录顺序。

资源身份和本次产物是两件事：`--resource` 选目标，`--artifact` 指文件或目录。不同资源的产物不能重复或相互嵌套；新建另一份资源用 create，不重复 init。完整选择器与默认产物修改规则见[命令参考](./11-命令参考.md)。

已有身份换绑成另一个线上资源属于替换操作，不是普通 bind 续接；需要明确旧身份及 `--force`，且会丢弃旧工作稿。先备份、核实目标，再查[命令参考](./11-命令参考.md)操作，不把换绑当作账号切换或版本更新。
