# 本地文件参考

CLI 的工程状态都在 `.freelog/`。身份和工作稿使用严格的 `schemaVersion: 1`；不要用旧文件、临时 JSON 或自定义字段替代它们。

```text
my-project/
  .freelog/
    auth                    # 非秘密账号选择器；不提交
    1.json                  # 第 1 份资源身份
    1.version.json          # 第 1 份未提交工作稿（存在时）
    1.template.json         # 主题/插件模板缓存（存在时）
    index.json              # filePath → 身份编号索引
    .lock                   # 瞬时写锁
```

## `N.json`：资源身份

初始化后的普通资源身份只有类型；创建或 bind 成功后才会同时拥有资源 id 和名称。

```json
{
  "schemaVersion": 1,
  "subject": "resource",
  "resourceId": "6a9f...",
  "name": "my-video",
  "typeCode": "RT006003",
  "filePath": "video.mp4",
  "env": "dev"
}
```

| 字段 | 说明 |
|---|---|
| `subject` | 本期恒为 `resource`。 |
| `typeCode` | 普通资源是已验证的最终叶子；主题/插件固定为 `RT001` / `RT002`。 |
| `resourceId` 与 `name` | 绑定后成对出现；未绑定 `init` 身份不应预写。 |
| `filePath` | 相对工程根目录、以 `/` 分隔。普通资源是文件路径；主题/插件是构建目录，例如 `dist`；绝对路径与 `..` 越界路径不合法。 |
| `env` | 非 prod 的已绑定资源会记录 `dev` 或 `test`。 |

这里不保存标题、标签、策略、已发版本、SHA1、`artifactMode` 或秘密凭据；这些信息分别属于平台、工作稿或系统凭据库。

## `N.version.json`：未提交工作稿

工作稿始终包含资源 id、资源类型、稿类型（`initial` / `update`）、文件 SHA、分析 SHA、属性、可选配置、依赖及恒为空的兼容字段。它只在资源已创建或 bind 后出现。

```json
{
  "schemaVersion": 1,
  "draftKind": "update",
  "resourceId": "6a9f...",
  "resourceTypeCode": "RT006003",
  "fromVersion": "1.0.0",
  "fileSha1": "...",
  "filename": "video.mp4",
  "analyzedSha1": "...",
  "description": "下一版说明",
  "inputAttrs": [],
  "orphanedInputAttrs": [],
  "customPropertyDescriptors": [],
  "dependencies": [],
  "baseUpcastResources": [],
  "authExcludedItems": []
}
```

主题/插件在这里记录的是 CLI 临时 zip 的 `filename` / SHA1；身份里的 `filePath` 仍是构建目录。普通资源则记录原文件的 `filename` / SHA1。

## `N.template.json`：模板缓存

只有 `init theme` 和 `init widget` 创建它。它保存 `templateId`、`templateVersion`、`npmName`、`projectName`、`projectVersion`，供未来模板渲染使用。它不替代 `N.json.filePath`，也不参与版本提交。某编号绑定到不同资源或不同类型时，CLI 会同时清理它，避免模板元数据与身份错配。

## `index.json` 与 `.lock`

`index.json` 是 `filePath → N` 的查询索引，不是主数据；它与身份不一致时，CLI 以 `N.json` 为准修复。`.lock` 只在本地写入期间存在，用于阻止两个 CLI 同时修改同一工程。不要在另一个 CLI 仍在运行时删除它。

## Git 建议

- 永远忽略 `.freelog/auth`。
- `N.json` 和 `N.template.json` 不含秘密，适合随工程协作。
- `N.version.json` 是未提交的工作内容；是否提交由团队协作流程决定，不能把它当成已发版本事实。
- 不要提交 `.lock` 或临时 zip。
