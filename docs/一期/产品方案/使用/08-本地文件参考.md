# 本地状态文件参考

本页解释 `.freelog/` 中每个文件的归属与恢复边界，不是手工编辑指南。身份和工作稿使用严格的 `schemaVersion: 1`；不要用旧文件、临时 JSON 或自定义字段替代它们。遇到状态损坏或需要丢弃状态，先看[故障恢复](./06-常见情况与报错.md)。

```text
my-project/
  .freelog/
    auth                    # 非秘密账号选择器；不提交
    1.json                  # 第 1 份资源身份
    1.version.json          # 第 1 份未提交工作稿（存在时）
    .pending-operation.json # 已准备发送或已发送、但尚未完成本地收尾的版本提交（存在时）
    .lock                   # 瞬时写锁
    .txn.json               # 瞬时跨文件事务；异常中断后供 CLI 前滚恢复
```

## `N.json`：资源身份

初始化后的普通资源身份只有类型；创建或 bind 成功后才会同时拥有资源 ID、完整标识和短名称缓存。

```json
{
  "schemaVersion": 1,
  "subject": "resource",
  "resourceId": "6a9f...",
  "resourceName": "alice/my-video",
  "name": "my-video",
  "title": "我的视频",
  "typeCode": "RT006003",
  "filePath": "video.mp4",
  "env": "dev"
}
```

| 字段 | 说明 |
|---|---|
| `subject` | 本期恒为 `resource`。 |
| `typeCode` | 普通资源是已验证的最终叶子；主题/插件固定为 `RT001` / `RT002`。 |
| `resourceId`、`resourceName` 与 `name` | 绑定后写入；`resourceName` 是完整不可变标识，`name` 是其短段展示缓存。旧状态可缺 `resourceName`，此时不得使用 `name:` 选择。 |
| `title` | 创建、bind 或 `resource sync` 写入的本地展示缓存；标题可重复、可变化且可能落后线上，不参与资源选择。旧状态可缺少该字段，选择列表显示“未同步标题”。 |
| `filePath` | 相对工程根目录、以 `/` 分隔。普通资源是文件路径；主题/插件可以是构建目录（例如 `dist`）或单个文件（包括 zip）。绝对路径、`..` 越界路径和 `.freelog/` 内路径不合法；已存在路径即使表面在工程内，解析软链接后也不能逃到工程外。两份资源不能共享同一真实文件，主题/插件构建目录也不能与另一产物路径嵌套。 |
| `env` | 非 prod 的已绑定资源会记录 `dev` 或 `test`。 |

这里不保存标签、策略、已发版本、SHA1、`artifactMode` 或秘密凭据；这些信息分别属于平台、工作稿或系统凭据库。标题是唯一例外：它作为可过期的本地展示缓存保存，可由 `resource sync` 更新。

`N.json` 不要求用户手工记编号。所有单资源命令可用 `--resource id:<资源ID>`、完整 `name:<username/name>` 或 `artifact:<filePath>` 选中它；`file:N.json` 是仍完整支持的精确状态文件形式，适合 AI、脚本和恢复。标题只在列表显示。

## `N.version.json`：未提交工作稿

工作稿始终包含资源 id、资源类型、稿类型（`initial` / `update`）、文件 SHA、分析 SHA、属性、可选配置、依赖及恒为空的兼容字段。它只在资源已创建或 bind 后出现。

```json
{
  "schemaVersion": 1,
  "draftKind": "update",
  "resourceId": "6a9f...",
  "resourceTypeCode": "RT006003",
  "fromVersion": "1.0.0",
  "fileSha1": "...",
  "filename": "video.mp4",
  "analyzedSha1": "...",
  "description": "下一版说明",
  "inputAttrs": [],
  "orphanedInputAttrs": [],
  "customPropertyDescriptors": [],
  "dependencies": [],
  "baseUpcastResources": [],
  "authExcludedItems": []
}
```

主题/插件使用目录时，这里记录 CLI 临时 zip 的 `filename` / SHA1；使用单个文件时记录原文件的 `filename` / SHA1。身份里的 `filePath` 保留用户选择的目录或文件。普通资源始终记录原文件的 `filename` / SHA1。

## `.pending-operation.json`、`.lock` 与 `.txn.json`

`.pending-operation.json` 记录版本提交的本地阶段：`prepared` 表示已完成提交前检查、但 POST 尚未允许发出；`sending` 表示请求可能已经到达平台。旧记录一律按 `sending` 保守处理。它只记录资源 ID、本地编号、环境、目标版本和文件 SHA，不含 token、文件内容、完整版本提交体或版本历史。不要手工删除它：先运行 `resource recover --env <环境>`；`prepared` 由 `resource recover --apply --yes` 只清记录、保留工作稿，`sending` 只有 CLI 证明远端目标版本和 SHA 都相同后，才会清理它与对应工作稿。

身份选择直接读取并校验 `N.json`，CLI 不维护 `index.json` 之类的派生索引。旧工程遗留的 `index.json` 不会被读取、重建或自动删除；可以保留，也可以在确认没有未完成旧版事务后自行移除。`.lock` 只在本地写入期间存在，用于阻止两个 CLI 同时修改同一工程。不要在另一个 CLI 仍在运行时删除它。

需要同时改身份和工作稿的操作会短暂写入 `.txn.json`。进程异常中断后，不要手动删改它；下一次对该工程的持锁写操作会先完成事务的前滚恢复。若文件持续存在且每次都恢复失败，保留 `.freelog/` 现场后再排查。

## Git 建议

- 永远忽略 `.freelog/auth`。
- `N.json` 和版本工作稿不含秘密，适合随工程协作。
- `N.version.json` 是未提交的工作内容；是否提交由团队协作流程决定，不能把它当成已发版本事实。
- 不要提交 `.lock`、`.txn.json`、`.pending-operation.json` 或临时 zip。
