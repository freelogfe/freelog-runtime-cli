# 按场景操作

先判断资源是否已经在线上存在、是否已经发行过版本、当前工程是否已有 `.freelog/` 身份。不要把 `init`、`create`、`bind` 当成同义词：它们分别是立项、建线上资源壳、接入已有线上资源。

所有例子以 `--env dev` 为例；多资源工程中，每一条涉及某资源的命令都补上该资源已记录的 `--file <path>`。

## 先选入口

| 你现在的情况 | 从这里开始 | 不要做 |
|---|---|---|
| 空目录，普通文件资源还未上线 | `init --type <最终叶子>`，再 `create` | 把父类型或类型名称交给 `--type`。 |
| 已有普通文件工程、没有线上资源 | `create --type <最终叶子> --file <文件>` | 为了建壳强行覆盖工程执行 `init`。 |
| 空目录，要从官方主题/插件模板开始 | `init theme|widget <目录> --template <id>` | 选择资源类型，或手工复制本地模板。 |
| 已有主题/插件工程、没有线上资源 | `create --type RT001|RT002 --file <dist|build>` | 对非空工程再执行 `init`，或自己先打 zip。 |
| 线上有自己的壳但没有发行版本 | `bind --file <文件或构建目录>`，再 `create-version` | 再次 `create`。 |
| 线上已有发行版本 | `bind --file <文件或构建目录>`，再 `draft pull` 和 `update-version` | 用 `create-version` 再发 1.0.0。 |
| 已有本地身份和未提交工作稿 | `version show --local` 后继续编辑或丢稿 | 手工编辑工作稿 JSON。 |
| 只改展示信息、策略或上下架 | 进入资源管理命令 | 为此创建新版本或新资源壳。 |

## 场景一：从空目录发行普通文件首版

```powershell
freelog-cli login --env dev
freelog-cli init . --type RT006003 --yes --env dev
freelog-cli create --title "我的视频" --name my-video --file video.mp4 --yes --env dev
freelog-cli create-version --prepare --file video.mp4 --env dev
freelog-cli version show --local --env dev
freelog-cli create-version --yes --file video.mp4 --env dev
```

不知道最终叶子 code 时，先运行 `type search <关键词>`，或省略 `init` 的 `--type` 进入层级、搜索和直接输入 code 的选择器。首版固定为 `1.0.0`。

## 场景二：已有普通文件工程，创建首版资源

不需要也不能为了写状态覆盖已有工程。登录后直接明确类型与文件：

```powershell
freelog-cli login --env dev
freelog-cli create --title "已有视频" --name existing-video --type RT006003 --file video.mp4 --yes --env dev
freelog-cli create-version --file video.mp4 --prepare --env dev
freelog-cli create-version --file video.mp4 --yes --env dev
```

`create` 只登记文件路径并创建资源壳；文件不存在、为空、过大或解析失败时，会在 `create-version` 停止，线上不会出现半个版本。

## 场景三：从官方模板创建主题或插件并发行首版

```powershell
freelog-cli login --env dev
freelog-cli template list
freelog-cli init theme my-theme --template vite-react-ts --yes
freelog-cli create --cwd my-theme --title "我的主题" --name my-theme --yes --env dev
# 在工程自己的流程中运行构建，得到 dist/
freelog-cli create-version --cwd my-theme --file dist --prepare --env dev
freelog-cli create-version --cwd my-theme --file dist --yes --env dev
```

插件把 `theme` 换为 `widget`；它的固定类型是 `RT002`，主题是 `RT001`。模板初始化后的建壳不传 `--type`，固定类型已在身份中。

## 场景四：已有主题或插件工程，创建首版资源

既有非空工程不运行 `init`，也没有必要补造模板元数据。明确其固定类型和构建目录：

```powershell
freelog-cli login --env dev
freelog-cli create --title "已有主题" --name existing-theme --type RT001 --file dist --yes --env dev
# 自己完成构建后
freelog-cli create-version --file dist --prepare --env dev
freelog-cli create-version --file dist --yes --env dev
```

插件使用 `--type RT002`。`dist` / `build` 是目录；CLI 仅在提交前临时压缩其中内容，绝不把 zip 写进 `filePath`。

## 场景五：自己的线上资源未发行，在本地补接后发首版

```powershell
freelog-cli login --env dev
freelog-cli bind <resourceId或username/name> --file video.mp4 --env dev
freelog-cli create-version --file video.mp4 --prepare --env dev
freelog-cli create-version --file video.mp4 --yes --env dev
```

主题/插件把 `video.mp4` 换成 `dist` 或 `build`。`bind` 会从平台读取类型；对主题/插件，没有已记录目录时 `--file` 是必填项。

## 场景六：自己的线上资源已发行，在本地接入并发新版本

```powershell
freelog-cli login --env dev
freelog-cli bind <resourceId或username/name> --file dist --env dev
freelog-cli version draft pull --env dev
# 编辑属性、可选配置、依赖或说明
freelog-cli update-version --file dist --bump patch --yes --env dev
```

普通文件把 `dist` 换成文件。使用 `--version 1.1.0` 也可以代替 `--bump patch`；两者不能同时传。若已有本地工作稿，先 `version show --local`，决定继续、`version draft discard`，或用 `version draft pull --yes` 明确覆盖。

## 场景七：构建路径、工作稿或多资源工程发生变化

- 构建输出从 `dist` 变成 `build`：单份资源用 `version set --artifact build`；多份资源用 `version set --file dist --artifact build`。只更新记录，不上传也不提交。
- 文件或目录不存在：先恢复真实产物；CLI 不会复用旧 SHA1 发新版本。
- 一个工程中有多份身份：`create`、`bind`、`create-version`、`update-version`、`version draft pull` 都传对应的已记录 `--file`；发版要换产物时再传 `--artifact`。不传时 CLI 会停止，不会猜第一份。
- 想从另一线上版本重新开始：`version draft pull --version <版本> --yes`；这会覆盖当前未提交工作稿，先看命令打印的摘要。

## 场景八：版本表单、依赖和上线

首版先 `create-version --prepare`，更新版先 `version draft pull`，之后再用 `version attr`、`version dep` 和 `version draft description` 编辑；仅当当前类型支持时才用 `version option`。依赖签约时从对方显示的**全部启用策略**中选择；签约成功后才写入工作稿。详情见 [版本工作稿](./04-版本工作稿.md)。

展示信息、策略、上架和下架不属于版本工作稿；按 [资源管理](./05-资源管理.md) 单独操作。合集、批量资源、前端库/package 模板和支付不在本期单资源 CLI 范围内。
