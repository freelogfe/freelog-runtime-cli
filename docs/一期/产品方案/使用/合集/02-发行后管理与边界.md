# 合集发行后管理与边界

本页用于已有合集的日常维护。所有示例都显式选择目标：

```text
--cwd . --env dev --resource id:<合集ID>
```

也可用 `--resource name:<用户名/授权标识>` 或 `file:N.json`。省略时，工程里恰一份合集身份会自动使用；零份或多份时，终端会让你从本人线上合集分页选择，包括尚未bind的合集，选择本身不会bind。脚本/AI的非交互调用请明确指定；`--yes`不能代替选择。标题不用于定位，跨环境本地身份会被拒绝。

## 目录单品：服务端目录草稿

`collection item list` 查看的是服务端目录草稿，不是已发布目录：

```powershell
freelog-cli collection item list --search "关键词" --cwd . --env dev --resource id:<合集ID>
```

后续编辑都使用列表里的 `itemId`。每次只执行你需要的那一种，执行后用 `collection item list` 读回。

新增来源可运行`collection item add --cwd . --env dev --resource id:<合集ID>`进入线上资源库：50条分页，支持搜索、类型层级筛选、跨页选择及查看/移除已选，最多100项。省略来源只适用于交互终端；AI/脚本或JSON调用请明确加`id:<来源ID>`或`name:<完整授权标识>`，例如`collection item add id:<单资源ID> --cwd . --env dev --resource id:<合集ID> --yes`。完成选择后会重新校验，列表中的可选状态不是最终写入依据。

添加单品会分别报告“已添加、未变更、失败”；服务端忽略的项只算未变更。部分失败时退出码为1（`COLLECTION_ITEM_ADD_PARTIAL`），错误摘要仍列出已确认的各组和失败原因，不代表整批回滚。`--json`时只输出单行`{code,message}`。若提示`COLLECTION_ITEM_RESULT_UNKNOWN`，先查看目录草稿及网页核实，不能直接当作全部失败重发；CLI不会自动重试，也不会替你签约或支付。

来源必须是本人线上已上架且已有版本的单资源。`COLLECTION_ITEM_SOURCE_INVALID`表示来源资格不满足；`COLLECTION_ITEM_SOURCE_RESPONSE_INVALID`表示平台详情的身份、成功信封或必要字段无法可靠读取，本次不会确认或提交添加。尤其上游信息缺失不能当作“没有依赖”：请核对详情，不能通过手写空授权排除项绕过。来源参数用资源ID或完整授权标识，不用标题。

一次添加最多100个不同来源ID，ID与完整名称指向同一资源时只算一次；超过时会报`COLLECTION_ITEM_LIMIT`，不会自动分批写入。添加前还会核对草稿判重接口和完整目录，`COLLECTION_ITEM_CATALOGUE_CHANGED`表示两次读取不一致，请先重新查看目录再决定是否重试；`COLLECTION_ITEM_EXISTENCE_RESPONSE_INVALID`表示判重响应不完整或无效。两种情况本次都不会确认或提交添加。确认中的标题会转义控制符，提交到平台的原标题不变。

改合集内标题：

```powershell
freelog-cli collection item rename <itemId> --title "合集内标题" --cwd . --env dev --resource id:<合集ID> --yes
```

调整位置：

```powershell
freelog-cli collection item move <itemId> --before <另一个itemId> --cwd . --env dev --resource id:<合集ID> --yes
```

按字段批量排序：

```powershell
freelog-cli collection item sort --by title --asc --cwd . --env dev --resource id:<合集ID> --yes
```

删除目录草稿中的单品：

```powershell
freelog-cli collection item remove <itemId> <itemId> --cwd . --env dev --resource id:<合集ID> --yes
```

这些命令只改目录草稿。要让它们进入已发布合集，之后运行下方发布命令。

move会将单品紧邻放在参照项之前/之后，成功后与sort一样列出完整当前顺序。rename/remove/move/sort在确认后都会重新检查同一合集和完整目录；若报`COLLECTION_ITEM_CATALOGUE_CHANGED`，本次未写，请先重新list核对再决定操作。`--yes`不绕过这些检查。

如果报`COLLECTION_ITEM_RESULT_UNKNOWN`，表示请求或完整读回未能可靠确认，不能直接重发；先查看目录及网页。批量移除部分完成时会列出本次观察“已移除/仍存在”的itemId，不代表其它请求已回滚。普通编辑不会发布目录、删除来源资源或改合同。

**先确认本地是否还有待发布表单稿。**若有，执行 `collection form show` 检查属性、配置、说明、展示和依赖是否也准备好发布：publish 会一并提交该稿，成功后清理它。当前没有“忽略已有本地表单稿、只发目录”的参数；不想发行这些修改时先停止发布，保存并整理表单稿，不能靠 `--include-items` 跳过它。

```powershell
freelog-cli collection publish --include-items auto --cwd . --env dev --resource id:<合集ID> --yes
```

授权状态只有只读查询：

```powershell
freelog-cli collection item auth status <itemId> --cwd . --env dev --resource id:<合集ID>
```

可一次传多个itemId。每行依次显示`itemId`、来源资源`resourceId`和“已授权/未授权”，以制表符分隔；重复输入只显示一次，按输入顺序排列。来源ID从目录草稿读取，不是标题或个人授权结果。目录缺项、响应漏项或重复等异常会让整批查询失败，不输出残缺结果。“未授权”只报告当次状态，不会替你移除单品、改授权、签约或支付；请到网页按当前合集身份核对。

当前没有 `collection item auth resolve`。不要手写授权排除字段。

## 展示资料：立即写线上

展示资料立即写线上资源信息，不需要 publish。下面每次只执行你需要的那一种。

更新标题和简介：

```powershell
freelog-cli collection update --title "新标题" --intro "新简介" --cwd . --env dev --resource id:<合集ID> --yes
```

更新标签：

```powershell
freelog-cli collection update --tag "标签一" --tag "标签二" --cwd . --env dev --resource id:<合集ID> --yes
```

清空标签：

```powershell
freelog-cli collection update --clear-tags --cwd . --env dev --resource id:<合集ID> --yes
```

在交互终端从现有标签开始编辑，可选择推荐/活动标签、添加一个自定义标签或移除已选：

```powershell
freelog-cli collection update --edit-tags --cwd . --env dev --resource id:<合集ID>
```

选择“完成编辑”后预览并确认才提交；取消不会上传封面或修改资料。标签没变且没有其它修改时不写入。这个入口不能与`--tag`、`--clear-tags`或`--json`合用，也不能在非交互脚本中使用；`--yes`只跳过最后确认，仍需实际选择。AI/脚本请使用前面的显式参数。平台推荐中超过现行20字符等约束的标签不会提供为可选项，也不会被截断；可选范围不能代替提交前校验。

工作区若有上一次未完成的可验证本地事务，合法命令会先恢复，再进入编辑。取消本次编辑不会撤销上一次已确认的事务。若提示本地事务损坏或冲突，先备份并处理该状态，不要删除事务文件强行继续；这时尚未打开标签编辑器或修改线上资料。

上传封面：

```powershell
freelog-cli collection update --cover assets/cover.png --cwd . --env dev --resource id:<合集ID> --yes
```

传 `--tag` 时，本次标签就是完整新列表；要保留旧标签就一并写上。标题最多 100 字符，简介最多 200 字符；标签最多 20 个不重复项，每个最多 20 字符。封面须是工程内 JPG、PNG 或静态 GIF，最大 5MB，不支持清空；CLI 不裁剪，上传前在本地处理好。

CLI先校验全部输入，提示原图上传并确认，然后才上传封面和修改资料。取消、输入有误或非交互缺少`--yes`不会上传；上传后修改或读回失败时不会自动重试，请先核对线上资料，不要假定上传已回滚。

## 收录规则与自动收录

查看状态：

```powershell
freelog-cli collection collect-rules get --cwd . --env dev --resource id:<合集ID>
```

更新完结/连载或关闭自动收录时，每次只执行一个命令。

设为已完结：

```powershell
freelog-cli collection collect-rules set --serialize completed --cwd . --env dev --resource id:<合集ID> --yes
```

设为连载中：

```powershell
freelog-cli collection collect-rules set --serialize serial --cwd . --env dev --resource id:<合集ID> --yes
```

关闭自动收录：

```powershell
freelog-cli collection collect-rules set --auto off --cwd . --env dev --resource id:<合集ID> --yes
```

开启自动收录要提供规则文件：

```json
[
  { "field": "title", "operator": "INCLUDES", "value": "教程" },
  { "field": "type", "operator": "EQUAL", "value": "<单资源最终叶子类型编号>" }
]
```

```powershell
freelog-cli collection collect-rules set `
  --auto all `
  --rules collection-rules.json `
  --cwd . --env dev --resource id:<合集ID> --yes
```

`--auto all` 表示全部条件，`--auto any` 表示任一条件。开启自动前，服务端目录草稿必须与已发布目录一致；有手工目录差异时先 publish。自动开启后，手工目录写入和目录 merge 会被拒绝。

`authIdentity` 的 `STARTS_WITH` 规则只填写当前用户名之后的短段，CLI 会补当前用户名和 `/`；其它操作符不会补全，应填写平台实际值。

保存成功须同时收到平台成功确认并完整读回一致。若出现 `COLLECTION_RULES_WRITE_UNCONFIRMED`，不代表平台一定没有修改：先用上面的 `collect-rules get` 查看实际规则，再决定后续操作，不要直接重复提交。CLI 不会自动重发，也不会修改本地表单稿。

## 本地表单操作稿：属性、配置、说明、展示、直接依赖

这部分是进阶能力。它不影响你完成最小首次发行，但可以完善合集表单。

**先确认是否有未发布修改。**已有本地表单稿时，先查看并保存要保留的内容；无稿时跳过查看（show 会报错）：

```powershell
freelog-cli collection form show --cwd . --env dev --resource id:<合集ID>
```

需要继续编辑旧稿时，不要重新 pull：将上面 show 输出的**完整 JSON**复制保存为工程内新的 UTF-8 文件，再编辑。不要沿用旧导出文件，因为之后的 `dep` / `display` 操作可能已改变内部稿，旧文件重新导入会把它们回退。

没有稿或已决定放弃旧稿时，再拉完整表单；已有内部表单稿会提示覆盖，不要随手加 --yes。

**`--out` 指定的导出文件会被同名覆盖，且没有单独确认。**先备份工程内已有的 `collection-form.json`（尤其是尚未导入的编辑），或改用一个未占用的文件名：

```powershell
freelog-cli collection form pull --out collection-form.json --cwd . --env dev --resource id:<合集ID>
```

编辑从当前稿保存的文件或刚 pull 导出的 `collection-form.json` 后，完整替换本地表单操作稿（保存为其它文件名时相应替换 `--from`）：

```powershell
freelog-cli collection form edit --from collection-form.json --cwd . --env dev --resource id:<合集ID>
```

`form edit` 是完整替换，不是局部 patch。已有合集应修改 pull 导出的完整表单，保留不想改变的字段；不要用空示例覆盖已有属性、配置或依赖。`form show` 不是线上状态，只显示本地待发布稿。

### 表单 JSON 形状

```json
{
  "$schema": "freelog-cli.collection-form.v1",
  "inputs": [],
  "properties": [
    { "key": "author", "name": "作者", "value": "Freelog", "description": "" }
  ],
  "options": [
    { "key": "theme", "name": "主题", "kind": "input", "value": "dark", "description": "默认主题" },
    { "key": "palette", "name": "配色", "kind": "select", "values": ["dark", "light"], "description": "选择配色" }
  ],
  "description": "合集说明",
  "display": {
    "sort": "ascending",
    "title": "resource-title",
    "number": true,
    "image": true,
    "description": true,
    "view": "list"
  },
  "dependencies": []
}
```

字段说明：

| 字段 | 内容 |
|---|---|
| `inputs` | 当前类型全部可写的系统附加属性 `{key,value}`；以 pull 的结果为起点，不要编造 key 或漏项。 |
| `properties` | 自定义属性，形如 `{key,name,value,description}`。 |
| `options` | 可选配置；`input` 只用 `value`，`select` 只用 `values` 且第一项为默认值，不能同时提供两种值字段。仅当前合集类型支持时可填写。显式导入将短键 `theme` 保存为与 Console 一致的完整键 `options_theme`；已带前缀不重复添加，总长度含前缀≤30。 |
| `description` | 合集版本说明字符串，可包含富文本 HTML；拉取、编辑和发布时原样保留。它不是 listing 简介，不套用简介的 200 字符限制；平台若拒绝内容仍会报错。传空字符串表示清空。 |
| `display` | 目录排序、标题、编号、图片、描述和列表/卡片视图。 |
| `dependencies` | 直接依赖；建议用 `collection dep` 命令维护。 |

上面的 `inputs: []` 仅适用于当前类型没有可写系统字段的情况。首次 pull 会为当前每个可写字段生成空串；已有版本会保留原值，并在工作稿中为新增字段补空串，历史发布基线不变。完整导入必须包含全部当前可写 key；要清空请明确写 `{ "key": "<原key>", "value": "" }`，不能删除该项。旧字段若已不再可写，不会自动从稿里删除；核对平台配置后，显式整理完整 JSON 再导入。

约束摘要：自定义属性和可选配置各最多 30 项；名称和说明最多 50 字符；它们的值或候选项最多 140 字符；下拉为 1-30 个不重复候选。系统附加值按平台当前字段的格式和范围校验，不统一限制为 140 字符；系统 key 保持平台原样，不能套用自定义 key 规则。自定义属性或配置的 key、名称均不能占用系统字段的保留 key、名称。

导入、发布前及最终确认后都会重新读取系统字段配置。若配置读取失败、字段缺项/多项或值不合法，本次不会提交发布，原稿保留；先核对当前配置并修正 JSON。常见错误为 `COLLECTION_SYSTEM_RESPONSE_INVALID`（无法可靠读取配置）、`COLLECTION_SYSTEM_INPUT_INVALID`（字段集合不符）、`COLLECTION_SYSTEM_VALUE_INVALID`（值不符合格式）及 `COLLECTION_SYSTEM_CONFLICT`（占用系统 key/名称）。这些检查不会修改已有发布快照，也不会读取 Console 的表单草稿。

展示设置有便捷命令：

```powershell
freelog-cli collection display set `
  --sort descending --title resource-title `
  --number true --image true --description false --view card `
  --cwd . --env dev --resource id:<合集ID>
```

直接依赖写入本地表单操作稿。CLI 只声明，不查询合约/授权、不签约或支付；没有合同也能添加并 publish。不再提供 `--policy`。声明不代表可以消费依赖，需要授权时到网页以**当前合集 ID**为乙方处理，不是用户个人购买。

添加直接依赖：

```powershell
freelog-cli collection dep add id:<依赖资源ID> --range "^1.0.0" --cwd . --env dev --resource id:<合集ID>
```

修改版本范围：

```powershell
freelog-cli collection dep range id:<依赖资源ID> --range "^1.2.0" --cwd . --env dev --resource id:<合集ID>
```

发布时不要求直接依赖合同存在；完整表单基线、属性/配置、目录并发与精确授权排除映射等保护仍保留。不能因为不查直接依赖合同而清空已有 `authExcludedItems`。删除依赖不会取消已签合同或退款。

来源必须精确对应请求的单资源ID或完整授权标识，并为已上架且有已发布版本的资源。若报`COLLECTION_DEP_TARGET_RESPONSE_INVALID`或`COLLECTION_DEP_VERSIONS_RESPONSE_INVALID`，表示平台详情/完整版本列表无法可靠确认；本次未改本地稿，也未签约或支付。先核对平台响应，不要手填空依赖列表绕过校验；合法范围但没有命中已发布版本时会报`COLLECTION_DEP_RANGE_INVALID`。

移除直接依赖：

```powershell
freelog-cli collection dep rm <依赖资源ID> --cwd . --env dev --resource id:<合集ID>
```

这些改动要发布才生效：

```powershell
freelog-cli collection publish --include-items no --cwd . --env dev --resource id:<合集ID> --yes
```

## 发布、未知结果和基线变化

常规发布前，检查目录草稿；已有本地表单稿时也先用 `collection form show` 检查。`--include-items` 只控制目录合并，不会阻止已有表单稿一并发行。

确认两者都是本次预期修改后发布：

```powershell
freelog-cli collection publish --include-items auto --cwd . --env dev --resource id:<合集ID> --yes
```

`--include-items`：

| 值 | 行为 |
|---|---|
| `auto` | 目录草稿与已发布目录不同则合并；相同时，只有存在本地表单稿才发表单。没有目录差异且没有表单稿会停止。 |
| `yes` | 要求存在目录差异并合并；没有差异会拒绝。 |
| `no` | 只发表单，需要已有本地表单稿，不合并目录草稿。 |

已有已发布快照时，目录-only 发布也要求平台明确返回授权排除映射；缺失时拒绝，不会用空数组补齐。

`COLLECTION_AUTH_STATE_UNREADABLE`也可能表示平台映射中有空、空白或格式无效的资源/合约/策略标识。CLI不会trim修补或清空这些信息。请保留本地稿并在网页核对，不能手填空数组绕过；有效的非空映射会原样保留。

未知结果只读诊断：

```powershell
freelog-cli collection publish resume --cwd . --env dev --resource id:<合集ID>
```

`resume`默认只读，不重发、不清理。已存在intent时普通publish会停止，不能用重新pull绕过。诊断为confirmed后显式收尾：

```powershell
freelog-cli collection publish resume --apply --yes --cwd . --env dev --resource id:<合集ID>
```

它会重新核验线上完整表单、授权排除映射和本次要求合并的全部目录；相等才清本次记录。发送后没变的旧稿可清理，后来修改或新建的当前稿保留。未确认、坏记录或旧记录不足以证明时两者都保留且拒绝收尾，不重发。线上基线变化时先保存本地修改并核实结果；不要把“重拉”当作未知发布已经解决。

若诊断为`rejected`，表示平台明确拒绝且完整旧快照仍未变，不是发布成功；同一条apply命令只清已拒绝记录，始终保留当前稿供修改。`unconfirmed`不能收尾。

## 上下架、日志和授权方合约

上架要求已有已发布快照和启用的合集自身策略。

上架：

```powershell
freelog-cli collection online --cwd . --env dev --resource id:<合集ID> --yes
```

下架：

```powershell
freelog-cli collection offline --cwd . --env dev --resource id:<合集ID> --yes
```

查日志：

```powershell
freelog-cli collection log list --limit 50 --order desc --cwd . --env dev --resource id:<合集ID>
```

脚本读取全部日志：

```powershell
freelog-cli collection log list --all --yes --json --cwd . --env dev --resource id:<合集ID>
```

查授权方合约：

```powershell
freelog-cli collection contract list --status active --all --yes --cwd . --env dev --resource id:<合集ID>
```

查看单个合约详情：

```powershell
freelog-cli collection contract show <contractId> --json --cwd . --env dev --resource id:<合集ID>
```

`collection contract` 查询的是“合集作为授权方”发出的合约，不是合集作为被授权方签下的单品上游合同或直接依赖合同。

默认一页100条。普通交互终端可选下一页或结束；`--json`及非交互默认只取一页，不弹问句。读全部请用`--all --yes`（人工TTY也可去掉yes后确认），最多100页且10000条，超过会明确拒绝，不输出伪装完整的截断列表。合约128只显示未获得授权，如需付款请到浏览器处理；CLI不会支付。未知枚举会保留原值，`--json`可查看完整已验证记录。

## 问题速查

| 现象 | 处理 |
|---|---|
| 已发布目录看不到刚添加的单品 | 先 `collection item list` 确认目录草稿，再 `collection publish --include-items auto`。 |
| `collection online` 提示无策略 | 添加并启用合集自身策略；单品自身策略和直接依赖签约不能替代它。 |
| 想把本地文件夹整体加入合集 | 先把每个文件作为单资源发行、添加策略并上架，再 `collection item add`。 |
| 自动收录开启后不能手工改目录 | 先 `collect-rules set --auto off`，读回关闭后再改。 |
| 发布网络中断 | 用 `collection publish resume` 看诊断，不要盲目重复发布。 |
| RSS 合集 | 当前 CLI 只做防误写，不提供 RSS 接入、同步、换源或批量维护。 |
| 想让 CLI 帮忙支付 | 当前不做支付；到浏览器完成。 |
