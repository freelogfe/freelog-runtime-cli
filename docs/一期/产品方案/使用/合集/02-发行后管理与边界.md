# 合集发行后管理与边界

本页用于已有合集的日常维护。所有示例都显式选择目标：

```text
--cwd . --env dev --resource id:<合集ID>
```

## 目录单品：服务端目录草稿

`collection item list` 查看的是服务端目录草稿，不是已发布目录：

```powershell
freelog-cli collection item list --search "关键词" --cwd . --env dev --resource id:<合集ID>
```

后续编辑都使用列表里的 `itemId`。每次只执行你需要的那一种，执行后用 `collection item list` 读回。

改合集内标题：

```powershell
freelog-cli collection item rename <itemId> --title "合集内标题" --cwd . --env dev --resource id:<合集ID> --yes
```

调整位置：

```powershell
freelog-cli collection item move <itemId> --before <另一个itemId> --cwd . --env dev --resource id:<合集ID> --yes
```

按字段批量排序：

```powershell
freelog-cli collection item sort --by title --asc --cwd . --env dev --resource id:<合集ID> --yes
```

删除目录草稿中的单品：

```powershell
freelog-cli collection item remove <itemId> <itemId> --cwd . --env dev --resource id:<合集ID> --yes
```

这些命令只改目录草稿。要让它们进入已发布合集，之后运行下方发布命令。

**先确认本地是否还有待发布表单稿。**若有，执行 `collection form show` 检查属性、配置、说明、展示和依赖是否也准备好发布：publish 会一并提交该稿，成功后清理它。当前没有“忽略已有本地表单稿、只发目录”的参数；不想发行这些修改时先停止发布，保存并整理表单稿，不能靠 `--include-items` 跳过它。

```powershell
freelog-cli collection publish --include-items auto --cwd . --env dev --resource id:<合集ID> --yes
```

授权状态只有只读查询：

```powershell
freelog-cli collection item auth status <itemId> --cwd . --env dev --resource id:<合集ID>
```

当前没有 `collection item auth resolve`。不要手写授权排除字段。

## 展示资料：立即写线上

展示资料立即写线上资源信息，不需要 publish。下面每次只执行你需要的那一种。

更新标题和简介：

```powershell
freelog-cli collection update --title "新标题" --intro "新简介" --cwd . --env dev --resource id:<合集ID> --yes
```

更新标签：

```powershell
freelog-cli collection update --tag "标签一" --tag "标签二" --cwd . --env dev --resource id:<合集ID> --yes
```

清空标签：

```powershell
freelog-cli collection update --clear-tags --cwd . --env dev --resource id:<合集ID> --yes
```

上传封面：

```powershell
freelog-cli collection update --cover assets/cover.png --cwd . --env dev --resource id:<合集ID> --yes
```

传 `--tag` 时，本次标签就是完整新列表；要保留旧标签就一并写上。标题最多 100 字符，简介最多 200 字符；标签最多 20 个不重复项，每个最多 20 字符。封面须是工程内 JPG、PNG 或静态 GIF，最大 5MB，不支持清空；CLI 不裁剪，上传前在本地处理好。

## 收录规则与自动收录

查看状态：

```powershell
freelog-cli collection collect-rules get --cwd . --env dev --resource id:<合集ID>
```

更新完结/连载或关闭自动收录时，每次只执行一个命令。

设为已完结：

```powershell
freelog-cli collection collect-rules set --serialize completed --cwd . --env dev --resource id:<合集ID> --yes
```

设为连载中：

```powershell
freelog-cli collection collect-rules set --serialize serial --cwd . --env dev --resource id:<合集ID> --yes
```

关闭自动收录：

```powershell
freelog-cli collection collect-rules set --auto off --cwd . --env dev --resource id:<合集ID> --yes
```

开启自动收录要提供规则文件：

```json
[
  { "field": "title", "operator": "INCLUDES", "value": "教程" },
  { "field": "type", "operator": "EQUAL", "value": "<单资源最终叶子类型编号>" }
]
```

```powershell
freelog-cli collection collect-rules set `
  --auto all `
  --rules collection-rules.json `
  --cwd . --env dev --resource id:<合集ID> --yes
```

`--auto all` 表示全部条件，`--auto any` 表示任一条件。开启自动前，服务端目录草稿必须与已发布目录一致；有手工目录差异时先 publish。自动开启后，手工目录写入和目录 merge 会被拒绝。

`authIdentity` 的 `STARTS_WITH` 规则只填写当前用户名之后的短段，CLI 会补当前用户名和 `/`；其它操作符不会补全，应填写平台实际值。

## 本地表单操作稿：属性、配置、说明、展示、直接依赖

这部分是进阶能力。它不影响你完成最小首次发行，但可以完善合集表单。

**先确认是否有未发布修改。**已有本地表单稿时，先查看并保存要保留的内容；无稿时跳过查看（show 会报错）：

```powershell
freelog-cli collection form show --cwd . --env dev --resource id:<合集ID>
```

需要继续编辑旧稿时，不要重新 pull：将上面 show 输出的**完整 JSON**复制保存为工程内新的 UTF-8 文件，再编辑。不要沿用旧导出文件，因为之后的 `dep` / `display` 操作可能已改变内部稿，旧文件重新导入会把它们回退。

没有稿或已决定放弃旧稿时，再拉完整表单；已有内部表单稿会提示覆盖，不要随手加 --yes。

**`--out` 指定的导出文件会被同名覆盖，且没有单独确认。**先备份工程内已有的 `collection-form.json`（尤其是尚未导入的编辑），或改用一个未占用的文件名：

```powershell
freelog-cli collection form pull --out collection-form.json --cwd . --env dev --resource id:<合集ID>
```

编辑从当前稿保存的文件或刚 pull 导出的 `collection-form.json` 后，完整替换本地表单操作稿（保存为其它文件名时相应替换 `--from`）：

```powershell
freelog-cli collection form edit --from collection-form.json --cwd . --env dev --resource id:<合集ID>
```

`form edit` 是完整替换，不是局部 patch。已有合集应修改 pull 导出的完整表单，保留不想改变的字段；不要用空示例覆盖已有属性、配置或依赖。`form show` 不是线上状态，只显示本地待发布稿。

### 表单 JSON 形状

```json
{
  "$schema": "freelog-cli.collection-form.v1",
  "inputs": [],
  "properties": [
    { "key": "author", "name": "作者", "value": "Freelog", "description": "" }
  ],
  "options": [
    { "key": "theme", "name": "主题", "kind": "input", "value": "dark", "description": "默认主题" },
    { "key": "palette", "name": "配色", "kind": "select", "values": ["dark", "light"], "description": "选择配色" }
  ],
  "description": "合集说明",
  "display": {
    "sort": "ascending",
    "title": "resource-title",
    "number": true,
    "image": true,
    "description": true,
    "view": "list"
  },
  "dependencies": []
}
```

字段说明：

| 字段 | 内容 |
|---|---|
| `inputs` | 平台类型配置里的系统附加属性 `{key,value}`；不要凭空编造 key。 |
| `properties` | 自定义属性，形如 `{key,name,value,description}`。 |
| `options` | 可选配置；`input` 用 `value`，`select` 用 `values` 且第一项为默认值。仅当前合集类型支持时可填写。 |
| `description` | 合集表单说明，最多 200 字符；它和 listing 简介不是同一个字段。 |
| `display` | 目录排序、标题、编号、图片、描述和列表/卡片视图。 |
| `dependencies` | 直接依赖；建议用 `collection dep` 命令维护。 |

约束摘要：属性和配置各最多 30 项；名称和说明最多 50 字符；值或候选项最多 140 字符；下拉为 1-30 个不重复候选；key 在系统属性、属性和配置之间不能重复。

展示设置有便捷命令：

```powershell
freelog-cli collection display set `
  --sort descending --title resource-title `
  --number true --image true --description false --view card `
  --cwd . --env dev --resource id:<合集ID>
```

直接依赖也写入本地表单操作稿。已有授权时不用传 `--policy`；缺授权时交互选择，脚本或 `--yes` 调用才显式传。

添加直接依赖：

```powershell
freelog-cli collection dep add id:<依赖资源ID> --range "^1.0.0" --cwd . --env dev --resource id:<合集ID>
```

修改版本范围：

```powershell
freelog-cli collection dep range id:<依赖资源ID> --range "^1.2.0" --policy <策略ID> --cwd . --env dev --resource id:<合集ID> --yes
```

移除直接依赖：

```powershell
freelog-cli collection dep rm <依赖资源ID> --cwd . --env dev --resource id:<合集ID>
```

这些改动要发布才生效：

```powershell
freelog-cli collection publish --include-items no --cwd . --env dev --resource id:<合集ID> --yes
```

## 发布、未知结果和基线变化

常规发布前，检查目录草稿；已有本地表单稿时也先用 `collection form show` 检查。`--include-items` 只控制目录合并，不会阻止已有表单稿一并发行。

确认两者都是本次预期修改后发布：

```powershell
freelog-cli collection publish --include-items auto --cwd . --env dev --resource id:<合集ID> --yes
```

`--include-items`：

| 值 | 行为 |
|---|---|
| `auto` | 目录草稿与已发布目录不同则合并；相同时，只有存在本地表单稿才发表单。没有目录差异且没有表单稿会停止。 |
| `yes` | 要求存在目录差异并合并；没有差异会拒绝。 |
| `no` | 只发表单，需要已有本地表单稿，不合并目录草稿。 |

已有已发布快照时，目录-only 发布也要求平台明确返回授权排除映射；缺失时拒绝，不会用空数组补齐。

未知结果只读诊断：

```powershell
freelog-cli collection publish resume --cwd . --env dev --resource id:<合集ID>
```

`resume` 不会自动重发，也不清理未知 intent。若线上基线变化，先保存本地修改、核实前次发布结果，再重新 `form pull` 并人工合并；不要把“重拉”当作未知发布已经解决。

## 上下架、日志和授权方合约

上架要求已有已发布快照和启用的合集自身策略。

上架：

```powershell
freelog-cli collection online --cwd . --env dev --resource id:<合集ID> --yes
```

下架：

```powershell
freelog-cli collection offline --cwd . --env dev --resource id:<合集ID> --yes
```

查日志：

```powershell
freelog-cli collection log list --limit 50 --order desc --cwd . --env dev --resource id:<合集ID>
```

脚本读取全部日志：

```powershell
freelog-cli collection log list --all --json --cwd . --env dev --resource id:<合集ID>
```

查授权方合约：

```powershell
freelog-cli collection contract list --status active --all --cwd . --env dev --resource id:<合集ID>
```

查看单个合约详情：

```powershell
freelog-cli collection contract show <contractId> --json --cwd . --env dev --resource id:<合集ID>
```

`collection contract` 查询的是“合集作为授权方”发出的合约，不是合集作为被授权方签下的单品上游合同或直接依赖合同。

## 问题速查

| 现象 | 处理 |
|---|---|
| 已发布目录看不到刚添加的单品 | 先 `collection item list` 确认目录草稿，再 `collection publish --include-items auto`。 |
| `collection online` 提示无策略 | 添加并启用合集自身策略；单品自身策略和直接依赖签约不能替代它。 |
| 想把本地文件夹整体加入合集 | 先把每个文件作为单资源发行、添加策略并上架，再 `collection item add`。 |
| 自动收录开启后不能手工改目录 | 先 `collect-rules set --auto off`，读回关闭后再改。 |
| 发布网络中断 | 用 `collection publish resume` 看诊断，不要盲目重复发布。 |
| RSS 合集 | 当前 CLI 只做防误写，不提供 RSS 接入、同步、换源或批量维护。 |
| 想让 CLI 帮忙支付 | 当前不做支付；到浏览器完成。 |
