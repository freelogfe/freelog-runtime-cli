# 合集发行后管理与边界

合集的发行后管理仍由彼此独立的命令组成。先用稳定身份选中合集，再只执行要改变的那一类事实；不要因为要修改标题、目录或规则而重新发布整个合集。

```powershell
# 多合集工程中先固定目标；下文命令均可沿用此选择器。
--resource id:<合集ID> --cwd <工程目录> --env dev
```

## 目录单品

`collection item list` 读取的是**服务端目录草稿**，不是已发布目录。它适合确认即将通过下一次 publish 合并的内容：

```powershell
freelog-cli collection item list --search "关键词" --resource id:<合集ID> --cwd . --env dev
```

列表每行包含 `itemId`、来源 `resourceId`、合集内标题和来源授权标识。之后所有编辑使用 `itemId`，不能用可变标题或来源文件路径猜测。

```powershell
freelog-cli collection item rename <itemId> --title "合集内显示标题" --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection item move <itemId> --before <另一个itemId> --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection item remove <itemId> <itemId> --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection item sort --by title --asc --resource id:<合集ID> --cwd . --env dev --yes
```

`--by` 可为 `added`、`title` 或 `resource-updated`；排序必须且只能给 `--asc` 或 `--desc`。删除只移除目录草稿项，不删除来源单资源。任何目录修改都要再次执行 `collection publish` 才进入已发布目录。

可读取指定项的授权状态：

```powershell
freelog-cli collection item auth status <itemId> --resource id:<合集ID> --cwd . --env dev
```

当前没有 `auth resolve`。不要自行修改目录授权字段；该能力要等合同映射的完整平台读回契约确认后才会提供。

## 展示信息

以下命令立即修改线上 listing，但不发布目录、不修改表单、不会上架：

```powershell
freelog-cli collection update --title "新标题" --intro "新简介" --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection update --tag "标签一" --tag "标签二" --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection update --clear-tags --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection update --cover assets/cover.png --resource id:<合集ID> --cwd . --env dev --yes
```

标题至多 100 字，简介至多 200 字；标签最多 20 个，每个最多 20 字且不能重复。封面只上传原图，不裁剪；只能使用工程内的 JPG/JPEG、PNG 或静态 GIF，最大 5 MiB。

## 收录规则与自动收录

先查看当前状态：

```powershell
freelog-cli collection collect-rules get --resource id:<合集ID> --cwd . --env dev
```

`serialize` 表示合集更新状态，`auto` 表示自动收录模式；它们可以独立修改：

```powershell
freelog-cli collection collect-rules set --serialize completed --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection collect-rules set --auto off --resource id:<合集ID> --cwd . --env dev --yes
```

开启自动收录时必须提供工程内规则 JSON 文件，并选择“全部条件”或“任一条件”：

```json
[
  { "field": "title", "operator": "INCLUDES", "value": "教程" },
  { "field": "type", "operator": "EQUAL", "value": "<单资源最终叶子类型编号>" }
]
```

```powershell
freelog-cli collection collect-rules set `
  --auto all `
  --rules collection-rules.json `
  --resource id:<合集ID> --cwd . --env dev --yes
```

规则字段仅支持 `title`、`authIdentity`、`type`。`title` 与 `authIdentity` 支持 `INCLUDES`、`NOT_INCLUDES`、`STARTS_WITH`、`ENDS_WITH`；`type` 只支持 `EQUAL`。`authIdentity` 的 `STARTS_WITH` 值填写用户名后的短段，CLI 会按平台规则补上当前用户名。

开启自动收录前，服务端目录草稿必须与已发布目录一致；有手工差异时先 publish。自动收录开启后，所有手工 `item add/rename/remove/move/sort` 和目录 merge 都被保护性拒绝。先 `--auto off` 并读回关闭成功，再恢复手工目录维护。

## 本地表单、展示和直接依赖

表单操作稿始终先拉取，再编辑或读取：

```powershell
freelog-cli collection form pull --out collection-form.json --resource id:<合集ID> --cwd . --env dev
freelog-cli collection form edit --from collection-form.json --resource id:<合集ID> --cwd . --env dev
freelog-cli collection form show --resource id:<合集ID> --cwd . --env dev
```

`form pull` 会覆盖已有本地表单操作稿时提示确认；`form edit` 从工程内完整 JSON 替换操作稿，仍不会发送发布请求。要只调整目录展示设置，可使用便捷入口：

```powershell
freelog-cli collection display set `
  --sort descending --title resource-title `
  --number true --image true --description false --view card `
  --resource id:<合集ID> --cwd . --env dev
```

直接依赖只写本地操作稿；新增或改范围后必须 publish：

```powershell
freelog-cli collection dep list --resource id:<合集ID> --cwd . --env dev
freelog-cli collection dep range id:<资源ID> --range "^1.2.0" --policy <策略ID> --resource id:<合集ID> --cwd . --env dev --yes
freelog-cli collection dep rm <资源ID> --resource id:<合集ID> --cwd . --env dev
```

若当前合集尚无本地表单操作稿，`dep` 和 `display` 会要求先执行 `collection form pull`。删除依赖不会取消已存在的线上合同。

## 再次发布、上架与下架

每次目录草稿或本地表单操作稿改变后，按需要发布：

```powershell
freelog-cli collection publish --include-items auto --resource id:<合集ID> --cwd . --env dev --yes
```

发布后仍可独立下架：

```powershell
freelog-cli collection offline --resource id:<合集ID> --cwd . --env dev --yes
```

上架只在已有发布快照和启用合集策略时可用：

```powershell
freelog-cli collection online --resource id:<合集ID> --cwd . --env dev --yes
```

当前策略管理命令尚未可用；没有启用合集自身策略时，CLI 的上架拒绝是预期行为。单品自身的策略、合集直接依赖的签约、以及合集自身策略不能相互替代。

## 日志与授权合约

发行后可以只读观察，不会修改合集：

```powershell
freelog-cli collection log list --limit 50 --order desc --resource id:<合集ID> --cwd . --env dev
freelog-cli collection contract list --status active --all --resource id:<合集ID> --cwd . --env dev
freelog-cli collection contract show <contractId> --resource id:<合集ID> --cwd . --env dev
```

`collection contract` 固定查询“合集作为授权方”发出的合约，不能用它查看合集作为被授权方时，为单品上游授权或直接依赖签的合同。

## 不能做什么，以及遇到问题怎么办

| 情况 | 正确处理 |
|---|---|
| 已发布目录中看不到刚添加的单品 | 先确认 `collection item list` 中有该项，再运行 `collection publish --include-items auto`。发布成功也不等于上架。 |
| 合集状态为下架 | 已发布目录可以仍有单品；配置并启用合集自身策略后，独立运行 `collection online`。 |
| `collection online` 提示无策略 | 当前 CLI 不创建合集策略；先在 Console 完成该合集的策略配置和启用。 |
| 想把本地文件夹或主题项目整体加入合集 | 先将每个文件分别发行、设置策略并上架为单资源，再用 `collection item add` 加入。 |
| 自动收录开启后无法手工改目录 | 先 `collection collect-rules set --auto off`，读回关闭，再修改目录并 publish。 |
| 发布网络中断或读回不一致 | 运行 `collection publish resume`；它只提供诊断，不自动重发。 |
| RSS 合集 | 当前 CLI 只做防误写保护，不提供 RSS 维护、同步或上架能力。 |
