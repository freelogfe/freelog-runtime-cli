# 合集：添加和管理自身授权策略

本页只操作**合集自身对外提供的授权策略**。合集目录单品的上游授权、合集表单中的直接依赖以及单资源自身策略是另外三件事；不要用这里的策略 ID 代替依赖所需的上游策略或合同 ID。单资源教程单独见[单资源授权策略](../11-单资源授权策略.md)。

以下以 dev 环境为例。先 `freelog-cli login --env dev`，并已通过 `collection create` 或 `collection bind` 拥有可维护的线上合集。策略添加只需要合集线上身份；它不发布目录或表单，也不会自动上架。多合集工程中每条命令都传 `--resource id:<合集ID>`；也可用完整 `name:<username/name>` 或 `file:N.json`。合集选择器**不接受 `artifact:`**；没有本地合集状态时，可直接指定当前账号拥有的线上 `id:` 或 `name:`。工程目录另用 `--cwd <工程目录>`。

## 最短人工路径：从合集模板列表完成添加

```powershell
freelog-cli collection policy template list --resource id:<合集ID> --env dev
```

在交互式终端中，合集模板固定每页 20 个并显示各自参数数量，可以选择“下一页”“上一页”或“退出”。选择模板后，CLI 展示完整策略说明与 `[1]`、`[2]` 等参数编号；可修改策略名称、逐项输入或选择参数、恢复默认值，再“预览并创建”。预览会重新读取模板并校验指纹与参数，调用平台进行合集策略编译和翻译，展示最终策略译文和参数值；确认后才向合集新增并启用策略。取消或预览失败不会写入。

参数可以是数字、选项或时间。数字下限和精度、可选 `value`、默认值均取自当前模板；时间格式为 `YYYY-MM-DD HH:mm`。没有可用默认值的参数必须填写。策略名称为 2–20 个字符，同一合集不能出现同名或相同正文的策略。

## 指定模板 ID 或供 AI 查阅

```powershell
freelog-cli collection policy template info <模板ID> --resource id:<合集ID> --env dev
freelog-cli collection policy template apply <模板ID> --resource id:<合集ID> --env dev
```

`info` 只读，列出全文、参数编号、默认值、选项及非交互命令骨架；复制骨架后还要补上本次的 `--resource`、`--cwd` 和 `--env`。`apply <模板ID>` 在交互终端进入与 `template list` 选择后相同的编辑、预览、确认流程；它不是“看到 ID 就不校验直接创建”。

脚本或 AI 先获取机器可读的完整合集模板快照：

```powershell
freelog-cli collection policy template list --json --resource id:<合集ID> --env dev
freelog-cli collection policy template info <模板ID> --json --resource id:<合集ID> --env dev
```

`list --json` 输出当前合集可见的**全部**模板，不受人工界面每页 20 条的限制；`info --json` 只输出一个模板。机器输出含模板 ID、报告、`fingerprint` 与每个参数的 `slot`、类型、默认值或必填标记、数字规则、选项。脚本须使用**刚查看的指纹**，并给该模板的**每个**编号传 `--param "编号=值"`，包括有默认值的参数；零参数模板不传 `--param`。选项填 `value` 而不是显示名称。

例如当前选中模板恰有两个参数时，命令形状为：

```powershell
freelog-cli collection policy template apply <模板ID> `
  --template-fingerprint <从当前JSON读取的fingerprint> `
  --name "合集授权策略" `
  --param "1=<第一个参数值>" `
  --param "2=<第二个参数值>" `
  --resource id:<合集ID> --env dev --yes
```

**参数个数和值只是占位示例**，必须以该模板实际清单替换。非交互运行或显式传入指纹、参数时，`--template-fingerprint`、`--name`、每个参数的 `--param` 和 `--yes` 缺一不可；单独的 `apply <ID> --yes` 不会替脚本补齐参数。参数缺失、重复、无效或模板指纹变化会停止，重新查询模板后再执行。

## 查询结果、启停与上架

```powershell
freelog-cli collection policy list --resource id:<合集ID> --env dev
freelog-cli collection policy set --id <策略ID> --off --resource id:<合集ID> --env dev
freelog-cli collection policy set --id <策略ID> --on --resource id:<合集ID> --env dev
```

`collection policy list` 一次列出该合集自身的全部策略 ID、名称和 `on/off`，不分页。模板添加成功后默认**启用**，CLI 会读回确认；它不会发布目录、表单或上架合集，也不替使用方付款。`set` 必须且只能指定 `--on` 或 `--off`，交互时会确认，脚本可加 `--yes`；已上架合集不能停用最后一条启用策略，冻结合集也不能修改策略。

合集上架还需要**已发布快照**。完成[首次发行](./01-首次发行与发布.md)的目录／表单发布后，确认至少一条合集自身策略启用，再执行：

```powershell
freelog-cli collection online --resource id:<合集ID> --env dev --yes
```

上架不是策略添加的副作用；下架也不删除策略、已发布目录或已有合同。

## 当前范围及失败后恢复

当前模板接口请求完整列表；CLI 仅保留编译目标为 `collection` 的模板供合集使用，**不按免费／付费或事件标签筛选**，也暂不按合集叶子类型请求缩小范围。因此列表出现某模板不保证它一定能为当前合集编译或创建成功；预览时的平台编译、翻译及最终写入校验仍会把关。CLI 不自行改写支付、金额、时间或事件语义。

若模板指纹变化，重新运行 `template list --json` 或 `template info`，按新编号和值填写；若名称或正文重复，先用 `collection policy list` 核对。出现“创建结果未知”时 CLI 会退出当前编辑流程，先读回列表，不要盲目再添加。没有适用模板时列表正常显示为空；响应损坏才报错。CLI 不处理结算账户或支付，平台若拒绝编译或提交，则如实显示错误。当前合集 CLI 只提供模板添加、列表和启停；没有 `collection policy apply --from-file` 手写策略入口。
