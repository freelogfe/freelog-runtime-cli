# 合集授权策略

本页只操作**合集自身对外提供的授权策略**。它不等于单资源自身策略、单品上游授权，也不等于合集直接依赖。

示例都使用：

```text
--cwd . --env dev --resource id:<合集ID>
```

## 人工添加：推荐路径

```powershell
freelog-cli collection policy template list --cwd . --env dev --resource id:<合集ID>
```

交互终端每页 20 条，可选上一页、下一页或退出。选择模板后，CLI 会展示策略说明和参数编号。此时请停下来确认：

1. 这个模板符合你的授权要求。
2. 参数值、金额、时间、事件等是你真正想给用户的规则。
3. 预览中的平台编译/翻译结果可以接受。

确认后才会创建并默认启用策略。取消、参数错误、编译失败都不会写入。

知道模板 ID 时，可以先只读查看模板详情：

```powershell
freelog-cli collection policy template info <模板ID> --cwd . --env dev --resource id:<合集ID>
```

确认要使用这个模板后，再进入同样的交互流程：

```powershell
freelog-cli collection policy template apply <模板ID> --cwd . --env dev --resource id:<合集ID>
```

`apply <模板ID>` 在交互终端仍会编辑、预览、确认，不是跳过校验直接创建。确认前请停下来核对参数。

创建后读回：

```powershell
freelog-cli collection policy list --cwd . --env dev --resource id:<合集ID>
```

列表只确认策略 ID、名称和启用状态，不展示正文或参数。创建前在译文预览中核对规则；创建后要查看完整线上内容时到浏览器端确认。

## AI 或脚本添加：先由人确定规则

AI 可以代填命令，但不能替人选择商业规则。推荐流程是：

1. 人先决定要用哪个模板，以及每个参数值。
2. AI 读取模板 JSON，确认参数编号和指纹。
3. AI 生成完整 `apply` 命令。
4. 创建后用 `collection policy list` 读回。

先读取模板列表：

```powershell
freelog-cli collection policy template list --json --cwd . --env dev --resource id:<合集ID>
```

确定模板 ID 后，再读取模板详情：

```powershell
freelog-cli collection policy template info <模板ID> --json --cwd . --env dev --resource id:<合集ID>
```

机器输出里主要使用模板 ID、`fingerprint`、参数 `slot`、类型、默认值、必填状态、数字规则和选项 `value`。`fingerprint` 用于确认你提交时看到的模板结构没有变化；它不代表冻结平台编译语义，也不是 dry-run 结果。

非交互创建必须显式提供模板指纹、策略名、全部参数和 `--yes`：

```powershell
freelog-cli collection policy template apply <模板ID> `
  --template-fingerprint <刚查询到的fingerprint> `
  --name "合集授权策略" `
  --param "1=<参数1>" `
  --param "2=<参数2>" `
  --cwd . --env dev --resource id:<合集ID> --yes
```

示例里的参数数量只是占位。必须按当前模板参数清单填写；零参数模板不传 `--param`。即使模板有默认值，脚本模式也要显式传入，让命令记录清楚本次选择。该命令会编译、翻译后直接创建，不等待人确认译文，也没有 dry-run；需要先人工预览时改用上面的交互路径。

创建后读回：

```powershell
freelog-cli collection policy list --cwd . --env dev --resource id:<合集ID>
```

## 参数类型

| 类型 | 填写方式 |
|---|---|
| 数字 | 按模板给出的范围和精度填写。 |
| 选项 | 使用选项 `value`，不是显示文案。 |
| 时间 | 使用 `YYYY-MM-DD HH:mm`。 |

策略名称为 2-20 个字符。同一合集不能出现同名策略或相同策略正文。

## 启停策略

停用：

```powershell
freelog-cli collection policy set --id <策略ID> --off --cwd . --env dev --resource id:<合集ID> --yes
```

启用：

```powershell
freelog-cli collection policy set --id <策略ID> --on --cwd . --env dev --resource id:<合集ID> --yes
```

`set` 必须且只能传 `--on` 或 `--off`。冻结合集不能改策略；已上架合集不能停用最后一条启用策略。

策略命令立即写线上策略列表，但不发布目录、不提交表单、也不上架。上架仍要单独执行：

```powershell
freelog-cli collection online --cwd . --env dev --resource id:<合集ID> --yes
```

上架还要求合集已有已发布快照；只有策略不够。

## 范围和失败处理

当前模板接口由平台返回完整列表，CLI 只保留 `compileType=collection` 的模板。它不按免费/付费筛选，也暂不按合集叶子类型请求缩小范围；最终能不能用，以平台编译、翻译和写入校验为准。

CLI 不处理结算账户或支付，也没有 `collection policy apply --from-file` 手写策略入口。未来如果支持策略语言，也必须先走平台编译验证再提交。

| 提示 | 处理 |
|---|---|
| 模板已变化 | 重新运行 `template list --json` 或 `template info`，按新指纹和参数提交。 |
| 策略名或正文重复 | 先 `collection policy list` 查看已有策略，再换名称或确认是否已创建。 |
| 平台编译、翻译或写入失败 | 修改参数或选择其它模板；CLI 不会自行改写金额、时间、事件或支付语义。 |
| 创建结果未知 | 先 `collection policy list` 读回，不要盲目重复创建。 |
| 没有适用模板 | 空列表是正常结果；响应结构损坏才是错误。 |
