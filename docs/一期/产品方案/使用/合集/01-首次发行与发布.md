# 合集首次发行与发布

本页把首次发行拆成可独立停止、重试的步骤。它不是一个“创建后自动发布”的事务：每一步只改变自己负责的事实。

示例中的 `<...>` 都必须替换；建议先在隔离工程执行，并始终显式传入 `--env dev`。

## 0. 准备条件

1. 已安装 CLI 且 Node.js 为 20 或更高版本；安装与登录见[主手册](../README.md)。
2. 已登录当前工程：

   ```powershell
   freelog-cli login --env dev
   ```

3. 要加入合集的单品已经各自完成“单资源创建版本 → 策略 → 上架”。合集不会替它们上传文件或创建版本。

## 1. 创建合集壳

创建时必须选择**合集最终叶子类型**，填写标题和授权标识短段：

```powershell
freelog-cli collection create `
  --type <合集叶子类型编号> `
  --title "我的合集标题" `
  --name my-collection `
  --cwd . `
  --env dev `
  --yes
```

不知道类型编号时，可省略 `--type`，在交互式终端中用层级选择、搜索或直接输入最终叶子类型编号。直接输入仍会由平台重新校验：父节点、停用节点和非合集类型都不能创建。

标题用于展示和搜索，长度不能超过 100 个字符；授权标识在创建后不可修改。成功后 CLI 输出合集 ID，并在当前工程写入一份 `subject:"collection"` 的 `.freelog/N.json`。该文件没有 `filePath`，也不记录目录或版本历史。

### 已有线上合集时用 bind

不要再次 create。接入已有且属于当前账号的合集：

```powershell
freelog-cli collection bind <合集ID或username/name> --cwd . --env dev
```

后续示例假定本地只有这一份合集身份；多份时在每条命令追加：

```powershell
--resource id:<合集ID>
```

## 2. 添加线上单资源到目录草稿

来源必须是当前账号已经上架的单资源。以下操作只增加服务端目录草稿，尚未改变已发布合集：

```powershell
freelog-cli collection item add `
  id:<单资源ID-A> id:<单资源ID-B> `
  --resource id:<合集ID> `
  --cwd . --env dev --yes

freelog-cli collection item list `
  --resource id:<合集ID> `
  --cwd . --env dev
```

若某个来源资源有上游授权缺口，脚本或 `--yes` 调用必须显式指定每个上游资源对应的启用策略：

```powershell
freelog-cli collection item add id:<单资源ID> `
  --policy <上游资源ID>=<上游策略ID> `
  --resource id:<合集ID> --cwd . --env dev --yes
```

签约成功即可继续添加；付费不会由 CLI 支付，需在浏览器端完成支付。不要把 `policyId` 当作合同 ID，也不要期待添加单品会自动发布合集。

## 3. 补充展示信息与收录规则（可选）

标题、简介、封面和标签立即写线上 listing，但不会发布目录、表单或上架：

```powershell
freelog-cli collection update `
  --title "我的合集标题" `
  --intro "不超过 200 字的合集简介" `
  --tag "设计" --tag "2026" `
  --cover assets/cover.png `
  --resource id:<合集ID> --cwd . --env dev --yes
```

封面必须位于工程内，支持 JPG/JPEG、PNG 或静态 GIF，最大 5 MiB。CLI 不裁剪图片，上传前请自行确认构图。`--clear-tags` 可清空标签，不能与 `--tag` 一起使用。
传入一个或多个 `--tag` 时，会将线上标签设置为这次给出的完整列表；要保留旧标签，请把要保留的标签也一并传入。

如果需要自动收录，先发布当前手工目录，再开启规则；否则 CLI 会拒绝，防止自动模式吞掉未发布的手工目录。规则示例与日常维护见[发行后管理](./02-发行后管理与边界.md#收录规则与自动收录)。

## 4. 建立本地表单操作稿（可选）

属性、可选配置、描述、目录展示和直接依赖都通过完整 JSON 表单维护。先从已发布快照拉取为工程内文件：

```powershell
freelog-cli collection form pull `
  --out collection-form.json `
  --resource id:<合集ID> --cwd . --env dev
```

新合集会得到空基线。修改 `collection-form.json` 后完整写回本地操作稿：

```powershell
freelog-cli collection form edit `
  --from collection-form.json `
  --resource id:<合集ID> --cwd . --env dev

freelog-cli collection form show `
  --resource id:<合集ID> --cwd . --env dev
```

最小表单形状如下；不要添加未声明的顶层字段：

```json
{
  "$schema": "freelog-cli.collection-form.v1",
  "inputs": [],
  "properties": [
    { "key": "author", "name": "作者", "value": "Freelog", "description": "" }
  ],
  "options": [
    { "key": "language", "name": "语言", "kind": "select", "values": ["中文", "English"], "description": "" }
  ],
  "description": "合集说明",
  "display": {
    "sort": "ascending",
    "title": "resource-title",
    "number": true,
    "image": true,
    "description": true,
    "view": "list"
  },
  "dependencies": []
}
```

可选配置仅在当前合集类型支持时可填写；不支持时带 `options` 发布会被拒绝。属性与配置的 `key`、名称、描述、值、数量和候选值均受校验，遇到错误请修改外部 JSON 后重新执行 `form edit`。

### 添加合集自身的直接依赖（可选）

必须先有本地表单操作稿。已有授权时无需 `--policy`；缺授权时在交互式终端选择，脚本中明确指定：

```powershell
freelog-cli collection dep add id:<依赖单资源ID> `
  --range "^1.0.0" `
  --policy <依赖策略ID> `
  --resource id:<合集ID> --cwd . --env dev --yes
```

这和“单品上游授权”不同：前者写入合集表单的 `dependencies`，后者只为某个目录单品准备授权排除映射。

## 5. 发布目录与表单

发布是唯一把目录草稿和本地表单操作稿提交到已发布合集快照的命令：

```powershell
freelog-cli collection publish `
  --include-items auto `
  --resource id:<合集ID> --cwd . --env dev --yes
```

`--include-items` 的选择：

| 参数 | 行为 |
|---|---|
| `auto`（默认） | 目录草稿与已发布目录不同则合并；相同则只发布表单。 |
| `yes` | 强制要求存在目录差异并合并；没有差异会拒绝。 |
| `no` | 只发布表单，不合并目录草稿。 |

自动收录开启时不能合并手工目录草稿；请先关闭自动收录，或使用 `--include-items no` 只发布表单。发布后 CLI 会读取已发布表单和已发布目录；读回不一致时会保留本地 intent，不自动重发。

若网络中断或结果不明确，先检查而不是再次发布：

```powershell
freelog-cli collection publish resume `
  --resource id:<合集ID> --cwd . --env dev
```

## 6. 上架是最后的独立步骤

`collection publish` 完成不代表对外可见。上架前必须同时满足：

1. 合集已有已发布快照；
2. 至少一条**合集自身**策略已启用；
3. 合集未冻结，且不是 RSS 合集。

当前 CLI 尚未提供 `collection policy` 管理命令。策略服务契约稳定前，需要在 Console 为该合集配置并启用策略，然后执行：

```powershell
freelog-cli collection online `
  --resource id:<合集ID> --cwd . --env dev --yes
```

成功后 CLI 会重读 `status:1`。如果没有启用策略，它会明确拒绝；不会替你创建策略、发布目录或绕过支付。下架使用 `collection offline`，不删除目录、表单、依赖、合同或本地身份。
