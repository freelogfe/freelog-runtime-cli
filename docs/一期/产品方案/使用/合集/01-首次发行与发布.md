# 合集首次发行与发布

本页只讲一条最小人工主线：创建一个合集，加入已经上架的单资源，添加合集自身授权策略，发布并上架。属性、可选配置、直接依赖、自动收录等都不是首次上架的必做项，放在[发行后管理](./02-发行后管理与边界.md)里。

所有示例使用当前工程和 dev 环境；未登录时先执行，已有可用登录则跳过：

```powershell
freelog-cli login --cwd . --env dev
```

## 开始前确认

你需要已经有几个本人线上单资源，并且它们已经上架。如果内容还只是本地文件、图片目录或主题工程，先回到单资源教程完成发行、添加单资源自身策略和上架；合集不会替你批量发行本地素材。

准备好以后，记录这些线上单资源 ID，下面会作为 `collection item add` 的来源。

## 1. 创建合集壳

```powershell
freelog-cli collection create `
  --type <合集最终叶子类型> `
  --title "我的合集标题" `
  --name my-collection `
  --cwd . --env dev --yes
```

不知道类型编号时，在交互终端同时去掉 `--type` 和 `--yes`，按提示层级选择或搜索最终叶子类型，并确认创建；带 --yes 时必须明确给出类型。AI/脚本必须事先取得合集最终叶子 code，不能用单资源 type list 的结果冒充；当前没有独立的合集类型查询命令，没有 code 时先走人工创建路径。创建成功后，CLI 输出合集 ID。后文用 `<合集ID>` 表示它。

`--name` 只填写短标识，不带登录名或 `/`。它创建后不可修改：规范化后必须为1～60个字符，超过60会报错，不会替你截断。只有交互时根据标题生成的默认建议会截取前60个字符；确认前请核对最终完整授权标识。

类型选择和创建确认会展示完整祖先路径及code，避免同名叶子混淆。无论层级选择、搜索还是直接给code，都会按当前类型树和详情复验；查询失败不是“没有结果”，不会借失败回复里的数据继续创建。遇到 `COLLECTION_TYPE_RESPONSE_INVALID` 时先核对服务及网络，不要换本地身份绕过。

已有线上合集时，不要再次创建，直接绑定或直接用线上 ID：

```powershell
freelog-cli collection bind id:<合集ID> --cwd . --env dev
```

绑定只是在当前工程保存一份定位信息，不关联本地文件。

`collection create`和`collection bind`都不要带`--resource`：前者新建，后者由位置参数指定接入目标。传入会明确报错，不会被忽略；后续管理已有合集时才使用`--resource`。

创建时如果提示 `COLLECTION_CREATE_RESULT_UNKNOWN`，不要直接重跑创建：先按本次完整授权标识核对线上结果，确认是本人合集后，用 `collection bind name:<登录名>/<短标识> --cwd . --env dev` 接入。若提示 `COLLECTION_CREATE_LOCAL_STATE_FAILED`，表示线上创建已得到成功回复，但本地保存失败；保留当前文件，处理本地故障后，按报错给出的 ID 执行 bind，不要再次创建。两种情况都不会自动重发创建请求。

## 2. 添加线上单品

人工操作可不填来源，让CLI从本人线上资源库中选择：

```powershell
freelog-cli collection item add --cwd . --env dev --resource id:<合集ID>
```

每页50项，可翻页、搜索、按资源类型筛选和跨页多选；选中项可再次点击取消，也能进入“查看/移除已选”。最多100项，完成后还会实时核验并确认添加。未上架、无版本、已在目录等项会显示不可选原因。取消不添加、不发布、不签约或支付。

AI/脚本应明确提供来源；非交互或`--json`不能进入选择器，`--yes`也不能替代选择。例如：

```powershell
freelog-cli collection item add `
  id:<单资源ID-A> id:<单资源ID-B> `
  --cwd . --env dev --resource id:<合集ID>
```

停下来按提示确认添加。这一步只写服务端目录草稿，尚未进入已发布合集。若提示缺少单品上游授权，先到网页按当前合集身份处理，再重试；CLI 不替你签约。用下面命令看目录草稿：

```powershell
freelog-cli collection item list --cwd . --env dev --resource id:<合集ID>
```

单品上游的合同排除映射与合集直接依赖不是一回事。CLI 只读已有有效合集合同生成真实映射；缺少时会提示当前合集 ID 和上游目标，去网页签约/支付后重试。不能用个人合同替代，也不能用空数组猜造映射。`collection item add --policy` 已移除，脚本与人工走同一路径。

## 3. 可选：补充标题、简介、封面和标签

这一步立即写线上展示信息，不需要 `collection publish`：

```powershell
freelog-cli collection update `
  --title "我的合集标题" `
  --intro "合集简介" `
  --cover assets/cover.png `
  --tag "设计" --tag "2026" `
  --cwd . --env dev --resource id:<合集ID> --yes
```

先把示例字段换成自己的，且确认工程内已有 assets/cover.png；不改封面则删除 --cover 参数。封面只上传原图，CLI 不裁剪。`--tag` 会把标签设置为本次给出的完整列表。

## 4. 添加合集自身策略

合集要上架，必须至少有一条启用的合集自身策略。运行模板列表：

```powershell
freelog-cli collection policy template list --cwd . --env dev --resource id:<合集ID>
```

这里会进入交互流程。请停下来完成这些动作：

1. 选择一个符合你授权要求的合集模板。
2. 填写或确认每个参数。
3. 预览平台编译/翻译后的策略说明。
4. 确认创建。

创建后读回确认：

```powershell
freelog-cli collection policy list --cwd . --env dev --resource id:<合集ID>
```

如果你要让 AI 或脚本添加策略，不要让它自己决定商业规则；先由人确定模板和参数，再按[合集授权策略](./03-合集授权策略.md)提供模板指纹和全部参数。

## 5. 发布目录

现在把服务端目录草稿发布为线上合集快照：

```powershell
freelog-cli collection publish `
  --include-items auto `
  --cwd . --env dev --resource id:<合集ID> --yes
```

`auto` 会在目录草稿与已发布目录不同时合并目录；如果没有可发布差异会停止，不发送空更新。发布成功不代表上架。

在交互终端中会展示完整差异：属性、可选配置、简介、展示设置、依赖，以及单品的增删、改名和排序。请核对目标环境和完整授权标识；人工首次操作可去掉`--yes`，确认后才提交。`--yes`在交互终端仍显示预览，但不再询问。选择`--include-items no`时，目录草稿差异会明确标为“本次不发布”。授权排除映射只会原样保留，预览不代表已经核验各单品的实时访问权限。

如果发布过程中断、超时或读回不一致，先诊断：

```powershell
freelog-cli collection publish resume --cwd . --env dev --resource id:<合集ID>
```

`resume`默认只读，不会自动重发。核验结果后可显式`--apply --yes`收尾，未确认不能清理，后来改过的稿保留；细则见[恢复与收尾](./02-发行后管理与边界.md#发布未知结果和基线变化)。不要盲目重复运行publish。

## 6. 上架

确认已经发布，并且 `collection policy list` 里至少有一条 `on` 的合集自身策略后：

```powershell
freelog-cli collection online --cwd . --env dev --resource id:<合集ID> --yes
```

CLI 会读回上下架状态，只有显示“合集已上架”或“合集已处于上架状态”才确认本步骤完成；发布步骤也会核验快照。完成标准：publish 成功、合集自身策略启用、online 已读回上架。下面的只读命令用于查看日志和策略，不能替代已发布目录查询：

```powershell
freelog-cli collection log list --limit 50 --order desc --cwd . --env dev --resource id:<合集ID>
freelog-cli collection policy list --cwd . --env dev --resource id:<合集ID>
```

当前没有专门的 `collection status` 命令，也没有“已发布目录查询”命令；不要用 `collection item list` 误判已发布目录，它查看的是服务端目录草稿。

下架是独立命令，首次上架任务到这里已结束；不要接着下架。需要下架时才执行，它不删除目录、表单、策略或合同：

```powershell
freelog-cli collection offline --cwd . --env dev --resource id:<合集ID> --yes
```
