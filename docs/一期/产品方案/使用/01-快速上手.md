# 快速开始：发行一个普通文件

本页是第一次使用的可执行教程：把 `video.mp4` 作为普通资源发成首版 `1.0.0`。以下示例以 dev 环境为例；不要把真实密码写进命令行参数或脚本文件。已有工程、已有线上资源或主题/插件不要套用本页，先到[按场景操作](./09-按场景操作.md)选入口。

## 1. 安装、确认与登录

CLI 要求 Node.js 20 或更高版本。尚未安装时，先执行：

```powershell
node --version
npm install --global @freelog-cli/cli2
freelog-cli --cli-version
```

如果 `freelog-cli` 找不到，重新打开终端；仍无法使用时，检查 npm 全局可执行目录是否已加入 `PATH`。以下统一写作 `freelog-cli`。

首次使用推荐在交互终端直接登录；CLI 会安全地隐藏密码输入：

```powershell
freelog-cli login --env dev
```

```powershell
# 登录成功后，可查看安装包内自带的完整手册路径
freelog-cli --help
```

自动化或非交互终端需要同时传 `--login-name`、`--password-stdin`、`--yes`；由 CI 的保密输入把密码写入标准输入，绝不把密码写进命令行、脚本或环境变量。登录成功后，工程只保存账号选择器；token、Cookie 等秘密由系统凭据库保存。

## 2. 建立工程身份

普通资源要先登录，因为资源类型来自平台的当前类型树。已知最终叶子 code 时可直接初始化：

```powershell
freelog-cli init . --type RT006003 --artifact video.mp4 --yes --env dev
```

不知道 code 时先查询，或不传 `--type` 进入交互式层级选择：

```powershell
freelog-cli type search 视频 --env dev
freelog-cli type list --env dev
freelog-cli type info RT006003 --env dev
freelog-cli init . --artifact video.mp4 --env dev
```

`type list` 和 `type search` 的每一行都是“类型 code + 根 / … / 叶子”的完整路径，不会只显示容易重名的叶子名称。它们固定每页 50 条：交互终端可选择上一页或下一页；脚本环境只显示首页并提示剩余数量，不需要也不支持分页参数。

`type info` 会同时显示该最终叶子是否支持版本可选配置；只有显示“支持”时才可以在工作稿中使用 `version option add/set`。它不表示任意文件都能用于该类型：做可选配置真网验收时，仍要为该类型选择真实可上传的文件。

通用 `init` 必须用 `--artifact` 指向已经存在的本地文件；交互模式只会帮你选类型，不会扫描或猜测文件。它只写 `.freelog/1.json`，不会创建线上资源、上传文件或创建版本。

上一步已在当前目录写入 `.freelog/auth` 也可以再执行 `init .`：CLI 会保留这一个账号选择器，并拒绝覆盖任何其它已有工程内容或资源身份。

## 3. 创建线上资源壳

```powershell
freelog-cli create `
  --title "我的视频" `
  --name my-video `
  --artifact video.mp4 `
  --yes --env dev
```

因为工程已经通过 `init` 记录了类型，这里不必重复传 `--type`；CLI 会在提交前重新验证该类型。没有先 `init` 时也可以直接创建，但必须额外传入 `--type <最终叶子 code>`。

此步只创建资源壳并回写 `resourceId`、`name`、环境和文件路径，**不会上传视频**。

## 4. 上传、检查并提交首版

最稳妥的做法是先准备工作稿：

```powershell
freelog-cli create-version --prepare --artifact video.mp4 --env dev
freelog-cli version show --local --env dev
freelog-cli create-version --yes --artifact video.mp4 --env dev
```

第一条会校验文件、计算 SHA1、上传并等待平台解析，但不提交版本。确认本地工作稿后，最后一条会再次从当前文件校验、上传和解析，再提交固定首版号 `1.0.0`。提交成功会删除工作稿；失败或中断会保留工作稿以便继续处理。
