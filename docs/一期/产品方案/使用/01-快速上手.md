# 从安装到普通文件首次上架

目标：把工程中已有的 `cover.png` 发成一份普通单资源，发行首版、添加自身授权策略并上架。已有线上资源应走[绑定后更新](./04-日常路径.md#接入已有资源并发布新版本)；主题与插件走[专用教程](./05-主题与插件.md)。

前置条件：Node.js 20+、可用的 dev 账号、工程目录内真实存在的图片文件。本页在该目录的交互式终端执行；将图片名称、标题、资源标识和类型 code 换成自己的。这里只演示人工路径，不是一份无人值守脚本。

## 1. 安装与登录

尚未安装 CLI 时执行：

```powershell
node --version
npm install --global @freelog-cli/cli2
freelog-cli --cli-version
```

命令找不到时先重新打开终端，再检查 npm 全局可执行目录是否在 PATH 中。未登录该工程时执行：

```powershell
freelog-cli login --env dev
```

停下来完成账号、隐藏密码输入，确认登录成功。已有可用登录则跳过，不重复 login。账号切换、父目录继承和 CI 登录见[环境与凭据](./02-环境与凭据.md)。

## 2. 选择资源类型

查询当前平台的图片类型：

```powershell
freelog-cli type search 图片 --env dev
```

从结果的“根 / … / 叶子”完整路径中选定符合文件用途的**最终叶子 code**。交互终端每页 50 条，可以翻页；不要填父节点或类型名称。查询能力、确认选择：

```powershell
freelog-cli type info <选定的最终叶子code> --env dev
```

若当前类型支持可选配置，后面可以填写；不是每种图片类型都支持。没有合适结果时停止，改用 `type list` 查看类型树，不猜 code。

## 3. 创建线上资源

以下一步即可创建，不必先运行通用 init：

```powershell
freelog-cli create --title "我的图片" --name my-image --type <选定的最终叶子code> --artifact cover.png --yes --env dev
```

这一步只创建资源，不上传图片、不发行版本、不上架。**记下返回的资源 ID**，后面所有 `<资源ID>` 都替换成它。标识创建后不能修改，标题以后可以改。

## 4. 发行首版

如果只需要最小首版，直接执行下方“提交首版”。如果要填写属性、可选配置或依赖，先准备工作稿：

```powershell
freelog-cli create-version --prepare --resource id:<资源ID> --env dev
freelog-cli version show --local --resource id:<资源ID> --env dev
```

**可选停顿：现在填写、检查工作稿，再提交。**准备命令会上传并等待解析，但不提交版本；[版本工作稿教程](./06-版本工作稿.md)说明各字段怎么填。不要等首版已经发行后才尝试给首版补属性、配置或依赖。

提交首版：

```powershell
freelog-cli create-version --resource id:<资源ID> --yes --env dev
freelog-cli version show --resource id:<资源ID> --env dev
```

确认线上出现 `1.0.0`。首版号固定，首版说明为空；若要补该已发版本的说明，用工作稿教程中的“已发版本说明”操作。提交失败或结果未知时先查[故障恢复](./09-常见情况与报错.md)，不要直接重复提交。

## 5. 添加自身授权策略

在交互终端执行：

```powershell
freelog-cli policy template list --resource id:<资源ID> --env dev
```

**在这里停下来完成交互**：模板每页 20 条，可以翻页；选择符合自己授权意图的模板 → 核对完整说明和参数标记 → 填写参数、修改策略名称 → 预览译文 → 确认创建。默认值也需要核对。退出或取消并不会创建策略。

确认创建成功后再查询：

```powershell
freelog-cli policy list --resource id:<资源ID> --env dev
```

必须看到至少一条符合预期且启用的**自身策略**，才继续上架。依赖签约不能替代自身策略。非交互运行列表只查询，不会添加；AI/脚本改用[完整参数提交路径](./07-单资源授权策略.md#ai-或脚本添加策略)，创建并读回确认后再回来继续。

## 6. 检查并上架

```powershell
freelog-cli validate --for online --resource id:<资源ID> --env dev
```

检查成功后才执行上架；失败先补缺失项：

```powershell
freelog-cli online --resource id:<资源ID> --yes --env dev
freelog-cli status --resource id:<资源ID> --env dev
```

若检查失败先补缺失项，不继续上架。online 当前正常完成时没有专门的成功文案，也不读回上下架状态；status 只显示本地身份、工作稿与线上 latest，不显示是否上架。最后在浏览器的资源管理页核对该 ID 已上架。成功终点是：线上已有首版、至少一条启用策略、浏览器确认资源已上架；只看到“创建成功”不是整个任务成功。

接下来修改资料看[资源管理](./08-资源管理.md)，发新版看[日常路径](./04-日常路径.md#接入已有资源并发布新版本)。一个目录有多份资源时继续使用明确资源 ID，不通过标题定位。
