# 快速开始：发行一个普通文件

本例把 `video.mp4` 作为普通单资源发成首版 `1.0.0`。以下示例以 dev 环境为例；不要把真实密码写进命令行参数或脚本文件。

## 1. 安装与登录

CLI 要求 Node.js 20 或更高版本。仓库内开发时先构建，再以 `node packages/cli/dist/bin/index.js` 运行；以下统一写作 `freelog-cli`。

```powershell
# PowerShell：密码只通过标准输入传入
$password | freelog-cli login --login-name <账号名> --password-stdin --yes --env dev
```

TTY 中可直接运行 `freelog-cli login --env dev`，再按提示输入登录名和隐藏密码。登录成功后，工程只保存账号选择器；token、Cookie 等秘密由系统凭据库保存。

## 2. 建立工程身份

普通资源要先登录，因为资源类型来自平台的当前类型树。已知最终叶子 code 时可直接初始化：

```powershell
freelog-cli init . --type RT006003 --yes --env dev
```

不知道 code 时先查询，或不传 `--type` 进入交互式层级选择：

```powershell
freelog-cli type search 视频 --env dev
freelog-cli type info RT006003 --env dev
freelog-cli init . --env dev
```

`init` 只写 `.freelog/1.json`，不会创建线上资源、上传文件或创建版本。

## 3. 创建线上资源壳

```powershell
freelog-cli create `
  --title "我的视频" `
  --name my-video `
  --file video.mp4 `
  --yes --env dev
```

因为工程已经通过 `init` 记录了类型，这里不必重复传 `--type`；CLI 会在提交前重新验证该类型。没有先 `init` 时也可以直接创建，但必须额外传入 `--type <最终叶子 code>`。

此步只创建资源壳并回写 `resourceId`、`name`、环境和文件路径，**不会上传视频**。

## 4. 上传、检查并提交首版

最稳妥的做法是先准备工作稿：

```powershell
freelog-cli create-version --prepare --file video.mp4 --env dev
freelog-cli version show --local --env dev
freelog-cli create-version --yes --file video.mp4 --env dev
```

第一条会校验文件、计算 SHA1、上传并等待平台解析，但不提交版本。确认本地工作稿后，最后一条才提交固定首版号 `1.0.0`。提交成功会删除工作稿；失败或中断会保留工作稿以便继续处理。
