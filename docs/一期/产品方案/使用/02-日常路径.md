# 02 - 日常路径

三条主路径的全部命令。参数细节的判断（TTY 问什么、`--yes` 拦什么）真源在 [PHASE](../脚手架设计/PHASE/单资源/创建/00-总览.md)，本文按使用视角给全。

---

## 路径一：创建（全新资源）

```
login → init? → create → create-version → policy? → update? → online
```

| 步骤 | 命令 | 说明 |
|------|------|------|
| 登录 | `login [--global] [--login-name <n> --password-stdin --yes]` | 见 [07-环境与凭据](./07-环境与凭据.md) |
| 查类型 | `type list` / `type search <词>` / `type info <code>` / `type pick` | 先确认叶子 code |
| 立项 | `init [<dir>] --scaffold none --resource-type <code>` | 只建本地工程；主题插件见 [03](./03-主题与插件.md) |
| 看模板 | `template list --scaffold runtime` | 配合 `init --template` |
| 建壳 | `create --title <t> --type <code> --name <短标识> [--file <path>]` | 只建壳，不上传 |
| 备稿 | `create-version --prepare` | 上传 + 解析，不提交。可隔天再交 |
| 提交 | `create-version --yes` | 号写死 `1.0.0`，成功删稿 |
| 策略 | 见 [05-资源管理](./05-资源管理.md) | 上架前至少一条启用 |
| listing | `update --title/--intro/--cover/--tags` | 只改展示信息，不上架 |
| 上下架 | `validate --for online` → `online` / `offline` | |

`create-version` 全量旗标（多余的一律报未知参数失败）：

```
--prepare   只备稿不提交
--reset     丢掉本地首版稿空表重来
--file      定哪一份身份/文件
--yes       跳过会话直接提交
```

**禁止**：`publish`、`release`、`create-version --version/--bump/--reuse-version`（都不存在）。

## 路径二：发新号（已有版本）

```
version draft pull? → 改缓存 → update-version
```

### 推荐：先管缓存，再交

```bash
freelog-cli version draft pull                       # 拉 latest 进稿（不 POST）
freelog-cli version draft pull --version 1.0.0       # 拉指定旧号当底
freelog-cli version draft pull --yes                 # 有稿也明确盖掉
freelog-cli version attr add "名称=作者 键=author 值=张三"
freelog-cli version option add "名称=主题 键=theme 方式=文本 默认=dark"   # 类型允许时
freelog-cli version dep add someone/lib --range ^1.0.0                   # 签完能授权才写进稿
freelog-cli version draft description --description "下一版描述"          # 仅更新稿
freelog-cli version show --local                     # 检查
freelog-cli update-version --yes --bump patch        # 1.2.0 → 1.2.1
```

### 一次会话（无稿时顺带拉）

```bash
freelog-cli update-version --bump patch              # 无稿按 latest 拉 → 交互改 → 交
freelog-cli update-version --reuse-version 1.0.0 --version 1.1.0
freelog-cli update-version --file b.mp4 --bump minor # 交的时候换文件
freelog-cli update-version --reset --version 1.1.0   # 丢稿重拉再交（一次会话内）
```

### 定新号规则

| 旗标 | 行为 |
|------|------|
| `--version 1.3.0` | 合法 semver 且 **> 当时 latest**，否则失败 |
| `--bump patch\|minor\|major` | 必须带方向；不默默 patch |
| `--version` + `--bump` | 失败 |
| `--yes` 且两者都没有 | 失败，不猜号 |

提交前会再查一次线上 latest，并发被人抢先发过会失败且稿留下。

**禁止**：`update-version --prepare`（不存在）；`update-version` 对着「没有版本」的资源跑（先 `create-version`）；用 `version show` 把线上写进稿。

## 路径三：接入已有线上资源（bind）

线上已经有壳（自己创建过 / 网页发过 / 换了台机器），本地没有身份：

```bash
freelog-cli bind <resourceId 或 username/name> --file ./video.mp4 --env dev
freelog-cli bind <id>                  # 主题/插件已有 filePath 时可省 --file
freelog-cli bind <id> --force --yes    # 换绑到另一个 resourceId（会删该份旧工作稿）
```

- 只写身份 + 本地文件对应关系。**不是** `pull`，不拉版本表单。
- 合集（subjectType=4）失败；不是本人的资源失败。
- 同一 id 重复 bind 幂等，工作稿保留；换 id 才删稿。
- 没有 `unbind`：直接删 `.freelog/N.json`，index 会自动修。
- 之后按路径二发新号，或按路径一 §4 发首版。

## 通用约定

| 约定 | 说明 |
|------|------|
| `--file` | 三个含义：选份（一夹多条必须）、换文件、确认路径。路径必须落在工程内 |
| `--cwd <dir>` | 换工作目录，凭据和 `.freelog/` 都按它找 |
| `--json` | 机器可读输出；错误仍是 `{code,message}` |
| `--yes` | 跳过确认，但**不降低校验**；该失败的照失败 |
| 一夹多条 | 多份 `N.json` 时所有版本命令都要 `--file`，只有一份可省 |
