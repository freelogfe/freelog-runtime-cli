# 本地状态文件参考

本地状态用于分步完成工作，不是版本管理系统。平台保存已发版本、策略和合约；本地永久保留身份，工作稿只保留当前未提交内容。不要手工生成这些内部文件来代替命令。

## 文件分工

```text
工程/
  .freelog/
    auth                         # 当前目录账号选择器，不提交
    .sequence                    # 身份编号计数，不是资源列表
    N.json                       # 单资源或合集的本地身份
    N.version.json               # 仅单资源：当前未提交版本稿
    .pending-operation.json      # 仅单资源：版本提交未决记录
    .lock                        # 瞬时工程写锁
    .txn.json                    # 跨文件事务恢复记录
    collection-forms/
      <env>/<合集ID>.json         # 合集：本地表单操作稿
      intents/<合集ID>.json       # 合集：发行 intent
```

`N` 是正整数，如 `1.json`。编号递增，不要求用户记住，也不能按排序猜测目标。合集 ID 在文件路径中由 CLI 编码。

## 身份：`N.json`

身份采用 `schemaVersion: 1`，通过 `subject` 区分单资源 `resource` 与合集 `collection`。

| 信息 | 单资源 | 合集 |
|---|---|---|
| 类型 | 普通资源为已验证的最终叶子；主题 RT001、插件 RT002。 | 合集最终叶子类型。 |
| 线上资源 ID、完整授权标识、短标识 | create/bind 成功后记录；通用 init 阶段尚未绑定。 | collection create/bind 成功后记录。 |
| 标题 | 可过期、可重复的本地展示缓存。 | 同样仅作展示缓存。 |
| 环境 | 绑定的 dev/test 平台身份记录对应环境。 | 同样不能跨环境使用。 |
| 产物路径 `filePath` | 必须记录；普通资源为文件，主题/插件可为构建目录或单个文件。 | 不存在，也不接受 artifact 选择器。 |

因此通用 init 后并非“只有类型”：还记录真实产物锚点。产物路径相对工程根，不能越界、指向 `.freelog/` 或通过软链接逃出工程；不同身份的产物不能重复或相互嵌套。

`N.json` 不缓存资源版本历史、策略、合约、标签、SHA1 或秘密。标题是用于展示的可变缓存；它不是匹配凭据，查询不自动刷新。单资源可显式 `resource sync` 同步标题；合集教程不将此命令当作合集批量同步入口。

选择身份使用 `id:`、完整 `name:`、`file:N.json`；单资源还支持 `artifact:<已记录路径>`。完整授权标识尚未记录的旧身份不能使用 name 选择。详见[主手册](./README.md#多资源工程先选身份再给产物)。

## 单资源工作稿：`N.version.json`

同号身份必须已经绑定。工作稿包含当前资源 ID、类型、首版/更新标记、更新底版本、文件名与 SHA1、分析结果、属性、可选配置、依赖及更新说明。

这些是 CLI 的内部序列化字段，不是公共发行 JSON 协议：属性与配置包含在实际表单结构中，不能自行添加一个名为 `options` 的顶层字段。首版稿的说明为空；更新说明通过 `version draft description` 编辑。

主题/插件目录的稿记录临时 zip 的文件名与 SHA1，身份仍记录目录；单个文件直接记录原文件信息。即使工作稿保留旧 SHA1，下次实际发版也须读取真实产物。

发行确认成功后删稿，身份保留。显式 discard、覆盖拉稿、reset 或换绑也可能丢弃当前稿，详见[版本工作稿](./06-版本工作稿.md)。

## 单资源未决提交：`.pending-operation.json`

当前未决记录使用 schemaVersion 2：

| 阶段 | 含义 | 恢复边界 |
|---|---|---|
| `prepared` | 已完成提交前准备，尚未允许发送版本 POST。 | recover --apply 只清记录，保留稿。 |
| `sending` | 请求可能已经到达平台。 | 精确证明目标版本号与 SHA1 一致后，才能清记录及对应稿。 |

受支持的旧 schemaVersion 1 没有阶段字段，按 sending 保守处理；损坏或其它未知结构不会被猜测或删除。

`resource recover` 只读诊断；确认可收尾后再 `resource recover --apply --yes`。记录不是版本历史，也不保存完整提交体或 token；未解决前阻断新的业务写入。不要删除记录绕过保护。

## 合集表单与发行 intent

合集不使用 `N.version.json`。属性、可选配置、描述、展示和直接依赖写入本地表单操作稿；目录单品操作写服务端目录草稿。两者经 `collection publish` 才进入已发布快照。

CLI 本地表单稿不读取、导入或删除 Console 服务端表单草稿。支持用户编辑的是 `collection form pull --out` 导出的公共表单 JSON，再由 `form edit --from` 导入；不是直接改内部缓存。

合集发行 intent 与单资源的 pending 文件是两套独立记录。`collection publish resume` 只读诊断，不自动清理或重发，不用于其它写操作。具体路径见[合集教程](./合集/README.md)。

## 锁、事务与 Git

CLI 不维护 `index.json`：旧文件不会被读取、重建或自动删除。`resource list` 可报告本地身份和单资源工作稿诊断，但不验证完整合集发行稿，更不是线上资源列表。

`.lock` 防止同一工程并发写入；`.txn.json` 在异常中断后供持锁操作前滚恢复。不要删除正在使用的锁或拆开修改事务。遇到损坏先备份整个 `.freelog/`，按[故障恢复](./09-常见情况与报错.md)处理。

- 永远不提交账号选择器、秘密、锁、事务、未决记录或临时 zip。
- 身份不含登录秘密，可按团队需要随工程保存。
- 版本稿和合集表单稿是未提交工作内容，可能包含业务信息；是否提交由团队决定，不作为线上成功的证据。
- 不把 Git 中旧稿、另一个环境的身份或另一台机器的账号选择器直接覆盖到当前现场。
