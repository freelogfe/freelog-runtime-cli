# 版本工作稿

工作稿是 `.freelog/N.version.json`：一份已绑定资源的、尚未提交的下一版本内容。它保存文件摘要、属性、可选配置、依赖和更新版描述。

工作稿只能属于已 `create` 或 `bind` 的资源。未绑定工程不能先手工攒版本稿；请先创建或接入资源。

| 要做什么 | 命令 | 是否提交线上版本 |
|---|---|---|
| 看线上版本 | `version show [--version <ver>]` | 否 |
| 看本地工作稿 | `version show --local` | 否 |
| 从已发版本建立更新稿 | `version draft pull [--version <ver>]` | 否 |
| 准备首版稿 | `create-version --prepare` | 否 |
| 编辑稿 | `version attr` / `option` / `dep` / `version draft description` | 否；依赖签约是独立平台动作 |
| 丢弃稿 | `version draft discard` | 否 |
| 提交 | `create-version --yes` / `update-version --version <ver> --yes` | 是 |

## 首版工作稿

资源还没有任何已发版本时：

```powershell
freelog-cli create-version --prepare --file video.mp4 --env dev
freelog-cli version show --local --env dev
freelog-cli create-version --yes --file video.mp4 --env dev
```

首版号固定为 `1.0.0`，首版描述为空。`create-version` 成功后删除工作稿；网络、解析或提交失败时保留它。

## 更新工作稿

已有版本时，以线上版本为底建立稿：

```powershell
freelog-cli version draft pull --version 1.0.0 --env dev
freelog-cli version draft description --description "本次更新说明" --env dev
freelog-cli update-version --version 1.1.0 --yes --env dev
```

已有本地稿时，`version draft pull` 默认不会覆盖。明确要重来时使用 `--yes`；命令会打印将被覆盖的来源、文件和条目摘要。不要通过修改 JSON 中的 `fromVersion` 换底，应该重新执行 `draft pull`。

## 编辑属性和可选配置

```powershell
freelog-cli version attr add "名称=作者 键=author 值=张三"
freelog-cli version attr set "键=author 值=李四"
freelog-cli version attr rm author
freelog-cli version attr list

freelog-cli version option add "名称=主题 键=theme 方式=文本 默认=dark"
freelog-cli version option set "键=theme 默认=light"
freelog-cli version option rm theme
freelog-cli version option list
```

可选配置是否可用由资源类型详情的 `supportOptionalConfig` 决定；当前类型不支持时，所有 `version option` 写操作都会停止。属性和配置的键创建后不可改；需要改键时删掉后重新添加。命令会在写入前显示预览，`--yes` 只跳过确认，不跳过字段校验。

## 编辑依赖

```powershell
freelog-cli version dep add <resourceId> --range ^1.0.0
freelog-cli version dep range <resourceId> --range ^1.1.0
freelog-cli version dep rm <resourceId>
freelog-cli version dep list
```

对方资源尚未授权时，交互模式会列出所有可签约且启用的策略供选择。脚本模式必须明确指定策略：

```powershell
freelog-cli version dep add <resourceId> --range ^1.0.0 --policy-id <policyId> --yes
```

CLI 列出的是对方资源的全部启用策略，不按免费/付费筛选。它以平台 `batchAuth` 返回的 `isAuth` 判断是否已授权；签约成功后才把依赖写入工作稿。支付、合约查询和上抛不属于本期 CLI，不能用它们推断授权状态。

## 文件变化与恢复

发版总是以当前存在的本地文件或构建目录为准；不能用旧工作稿 SHA1 代替丢失文件。换文件时在 `create-version` / `update-version` 上给新的 `--artifact`。一个工程有多份资源时，先用 `--file <已记录路径>` 选中身份，再用 `--artifact <新路径>`；普通资源给文件，主题/插件给构建目录。新脚本不要把 `--file` 当作换产物参数。

不要手工改 `N.version.json`。该文件有严格 schema，损坏、旧格式或身份不一致时 CLI 会保留原文件并停止；可明确丢弃工作稿，或从线上版本重新 `draft pull`。
