# 04 - 版本工作稿

工作稿 = `.freelog/N.version.json`：**还没提交的下一版**（文件 sha1、属性、可选配置、依赖、描述）。每改一项立刻写盘，退出后还在；成功 POST 后自动删除，失败则留下。

---

## 1. 四层心智模型

| 想干什么 | 用什么 | 会 POST 吗 |
|----------|--------|-----------|
| 看线上已发号 | `version show [--version 1.0.0]` | 否 |
| 看本地稿 | `version show --local` | 否 |
| 拉某一号当底 / 盖掉本地稿 | `version draft pull [--version <号>] [--yes]` | 否 |
| 丢掉稿 | `version draft discard [--yes]` | 否 |
| 改属性 / 可选配置 / 依赖 / 描述 | `version attr` / `option` / `dep` / `draft description` | 否（依赖签约当场打平台，树只进稿） |
| 真正发版 | `create-version` / `update-version` | **是** |

## 2. 拉底与盖稿（draft pull）

```bash
freelog-cli version draft pull                     # 拉 latest
freelog-cli version draft pull --version 1.0.0     # 拉指定旧号（回退底）
freelog-cli version draft pull --yes               # 已有稿时明确覆盖
freelog-cli version draft pull --version 1.1.0 --yes
```

- 本地已有稿时，**TTY 默认不盖**（打印将丢掉的摘要后问）；`--yes` 才盖。覆盖 = 整份重写，不混字段。
- 稿已来自同一号：提示「稿已来自 X，未覆盖」；`--yes` 强制重拉。
- 号不在版本列表：「没有这个版本」，不写盘。
- 还没有发行版本：失败，先 `create-version`。
- 首版没有「上一号」，**不要**用 `draft pull`，用 `create-version --prepare`。

## 3. 改缓存

前提：有稿（首版稿用 `create-version --prepare` 建；更新稿用 `draft pull` 拉）。无稿且线上已有版本时，改稿命令会失败让你先 `draft pull`。

```bash
# 自定义属性（最多 30 条；key 写下后不能改；值 ≤100）
freelog-cli version attr add "名称=作者 键=author 值=张三 说明=作品作者"
freelog-cli version attr set "键=author 值=李四"        # 只改值/说明/名称，键定位
freelog-cli version attr rm author
freelog-cli version attr list

# 系统附加 value（解析出来的那些，key 不能改）
freelog-cli version attr set "键=时长 值=120"

# 可选配置（类型 supportOptionalConfig===2 才能用）
freelog-cli version option add "名称=主题 键=theme 方式=文本 默认=dark"
freelog-cli version option set "键=theme 默认=light"
freelog-cli version option rm theme
freelog-cli version option list

# 依赖（先查授权；已授权直接写稿，否则当场免费签）
freelog-cli version dep add <resourceId> --range ^1.0.0
freelog-cli version dep range <resourceId> --range ^1.1.0
freelog-cli version dep rm <resourceId>
freelog-cli version dep list

# 描述（只有更新稿能改；首版描述恒空）
freelog-cli version draft description --description "..."
```

一行式语法：`字段=值` 空格分隔；值含空格 / `=` / `"` 用双引号包，内部 `\"` 转义。同字段写两次、出现表外字段：失败不写盘。

**已发号上的属性/配置/依赖是冻住的**：只能看（`version show`），改树走 `draft pull` → 改稿 → `update-version`。

## 4. 脚本 / AI 改稿要点

- 稿是人可读 JSON，可直接编辑；写完跑 `version show --local` 校验。
- `fromVersion` 是「底是哪一号」，不是新号。别手改这个字段来换底——用 `draft pull` 重拉。
- `baseUpcastResources` / `authExcludedItems` 恒 `[]`，不要填。
- raw 系统属性不进稿（每次解析现出），稿里的 `inputAttrs` 只有你填过的附加 value。

## 5. 典型节奏

### 首版分几天

```bash
freelog-cli create-version --prepare    # 今天：传文件 + 解析
freelog-cli version attr add ...        # 明天：加属性
freelog-cli create-version --yes        # 交 1.0.0，稿自动删
```

### 从 1.0.0 起改，发 1.1.0

```bash
freelog-cli version draft pull --version 1.0.0
freelog-cli version dep add ...
freelog-cli update-version --yes --version 1.1.0
```

### 本地稿改了一半，想换成线上 1.2.0 的底

```bash
freelog-cli version draft pull --yes              # 打印将丢掉的摘要并覆盖
```
