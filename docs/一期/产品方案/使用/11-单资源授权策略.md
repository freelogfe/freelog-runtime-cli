# 单资源：添加和管理授权策略

本页只操作**单资源自身的授权策略**。主题、插件、图片等单资源使用同一流程；合集自身策略请看[合集授权策略](./合集/03-合集授权策略.md)。添加策略不创建版本、不会上架资源，也不会替任何人付款或签约。

以下命令以 dev 为例。先在工程中登录，并为目标资源创建线上资源壳或绑定已有资源；只运行 `init`、还没有线上资源 ID 时不能添加策略。工程有多份单资源身份时，每条命令都传 `--resource id:<资源ID>`；只有一份时可以省略。若工程不在当前目录，另加 `--cwd <工程目录>`。

## 最短人工路径：列表中选模板并完成添加

```powershell
freelog-cli policy template list --resource id:<资源ID> --env dev
```

在交互式终端中，列表每页显示 20 个单资源模板及各自参数数量，可选择“下一页”“上一页”或“退出”。**选中模板后不会立即提交**：CLI 展示完整策略说明，并在可修改的位置标出 `[1]`、`[2]` 等参数编号；可以修改策略名称、逐项修改或恢复默认值，然后选择“预览并创建”。预览阶段先重新读取模板、校验参数，调用平台编译与翻译，展示最终策略译文和参数值；确认后才新增策略并启用。选择“取消”或预览校验失败不会写入策略。

参数类型由当前模板决定：

| 类型 | 如何输入 |
|---|---|
| 数字 `number` | 输入有限数字；下限和小数位以 `template info` 或 `--json` 显示的规则为准。 |
| 选项 `select` | 人工操作从模板提供的选项中选择。 |
| 时间 `datetime` | 使用 `YYYY-MM-DD HH:mm` 格式，例如 `2026-10-01 09:00`。 |

模板可能没有可用默认值，此时必须填写相应参数；即使有默认值，也建议逐项核对最终译文。策略名称必须为 2–20 个字符，且不能与该资源现有策略重名。

## 已知道模板 ID：先看完整说明，再进入编辑

```powershell
freelog-cli policy template info <模板ID> --resource id:<资源ID> --env dev
freelog-cli policy template apply <模板ID> --resource id:<资源ID> --env dev
```

`info` 只读，展示模板全文、参数编号、默认值、选项及一条非交互命令骨架；骨架不会自动带上当前工程的 `--resource`、`--cwd` 和 `--env`，复制后请补齐。`apply <模板ID>` 在交互终端进入与列表选择相同的编辑、预览和确认流程。若只想从模板列表开始，不必先执行 `info`。

## AI 或脚本：取得完整模板快照后精确提交

```powershell
freelog-cli policy template list --json --resource id:<资源ID> --env dev
freelog-cli policy template info <模板ID> --json --resource id:<资源ID> --env dev
```

`list --json` 一次输出当前单资源可见的**全部**模板，不按 TTY 的 20 条分页；`info --json` 只输出指定模板。机器输出含模板 ID、整体说明、`fingerprint` 和每个参数的编号 `slot`、类型、默认值或必填标记、数字规则及选项 `value`。同一说明里重复出现的参数仍使用同一个编号。`fingerprint` 用于确认提交时的模板描述与查看时一致，**参数编号只对该模板的当前指纹有效**。

从上述输出选定一个模板后，给它的**每一个参数编号**显式提供一个 `--param "编号=值"`，包括已有默认值的参数；零参数模板不需要 `--param`。例如，假设当前模板有两个参数：

```powershell
freelog-cli policy template apply <模板ID> `
  --template-fingerprint <从当前JSON读取的fingerprint> `
  --name "我的授权策略" `
  --param "1=<第一个参数值>" `
  --param "2=<第二个参数值>" `
  --resource id:<资源ID> --env dev --yes
```

这只是命令形状，**不能照抄两个 `--param` 的数量或值**；以该模板的实际参数清单为准。选项参数传 `value`，不是显示用 `label`；时间使用上述格式。缺编号、重复编号、值不合规则或模板指纹已变化会停止，先重新运行 `list --json` / `info` 再提交。非交互运行或显式传入指纹、参数时，`--template-fingerprint`、`--name`、全部 `--param` 和 `--yes` 是必需的；**单独加 `--yes` 不足以让脚本自动补参数**。

## 确认结果与启停

```powershell
freelog-cli policy list --resource id:<资源ID> --env dev
freelog-cli policy set --id <策略ID> --off --resource id:<资源ID> --env dev
freelog-cli policy set --id <策略ID> --on --resource id:<资源ID> --env dev
```

`policy list` 一次列出这个资源的全部已添加策略和启用状态，不分页；页头还会显示资源类型从根到叶的完整路径。添加成功后策略默认**启用**，CLI 会读回确认。启停只修改策略状态，不删除策略、不创建版本、不会触发付款；已上架资源不能停用最后一条启用策略。`set` 必须且只能给 `--on` 或 `--off`；交互终端会确认，脚本可加 `--yes`。

资源上架仍是独立步骤：先确保已有已发版本和至少一条启用策略，再运行 `freelog-cli validate --for online ...`、`freelog-cli online ...`。策略模板与依赖签约是两件事：此处添加的是**自己资源对外提供的策略**；版本依赖要到[版本工作稿](./04-版本工作稿.md)维护。

## 当前模板范围与失败处理

当前模板接口请求完整列表；CLI 仅保留编译目标为 `normal` 的模板供单资源使用，**不按免费／付费或交易事件标签筛选**，也暂不按资源叶子类型请求缩小范围。列表中出现不适用的模板，并不保证它一定能为当前资源编译成功或被平台接受；最终以预览时的平台编译、翻译以及创建校验为准。平台若拒绝编译，CLI 不猜测修改事件、金额或日期语义。

若提示“模板已变化”，重新查询并按新编号填写；若提示重名或正文重复，先用 `policy list` 核对现有策略。新增与启停均会读回线上状态；出现“创建结果未知”时 CLI 会退出当前编辑流程，先查列表，**不要盲目重复创建**。没有适用模板时列表正常显示为空；响应损坏才报错。CLI 不处理结算账户或支付，平台若拒绝编译或提交，则如实显示错误。目前命令树没有 `policy apply --from-file` 入口；本页的添加路径是策略模板，不要按旧文档中的手写文件示例执行。
