# 故障恢复与常见报错

先确认环境、工程和目标，再判断失败发生在哪一步。网络报错不等于平台没有成功；不要立即重发。需要机器可读错误时加 `--json`，命令参数见[命令参考](./11-命令参考.md)。

示例使用`--env dev`；多资源工程同时传`--resource id:<资源ID>`。正常报错一般保留未提交稿；发行成功清理本次未变稿，后来改变的稿保留并提示。明确覆盖、丢弃、reset或换绑仍可能丢弃内容。不能承诺“任何失败都能恢复旧稿”。

## 登录、路径和选择

| 情况 | 下一步 |
|---|---|
| prod 暂未开放 | 明确传 `--env dev` 或 `test`，不要依赖缺省环境。 |
| 请先 login、凭据损坏或环境不符 | 检查 `--cwd` 和最近的账号选择器；必要时在选择器所在目录 logout 后重新 login。不会静默回退到全局账号。 |
| 当前目标已有凭据 | 在同一登录目标先 logout，再 login；资源身份和工作稿不会因此删除。 |
| `LOGIN_SELECTOR_SAVE_UNCONFIRMED` | 系统凭据已保存、选择器写入未确认。核对所示路径，存在时先在该目标 logout（全局目标加 --global），处理磁盘权限／空间后再 login。不要手动删除可能共享的系统凭据。 |
| 模板初始化拒绝非空目录 | `init theme/widget` 不合并已有源码。选新目录；已有工程改走通用 init 或直接 create。仅已有登录目录时的允许条件见[主题与插件](./05-主题与插件.md)。 |
| 类型不可用、不是最终叶子 | 用 `type search/list/info` 查当前可用最终叶子；脚本传精确 code，不传名称或父节点。 |
| 模板主题/插件类型冲突 | 已有模板身份使用固定类型，移除冲突的 `--type`。 |
| 多份状态，无法确定目标 | 用 `id:`、完整 `name:`、`artifact:` 或 `file:N.json` 明确选择；标题不能定位资源。 |
| 产物不存在、为空或路径越界 | 恢复工程内真实文件或构建内容。普通资源不能传目录；主题/插件登记空目录可以，发行空目录不可以。 |
| 路径与另一资源重复或嵌套 | 为每份单资源使用独立产物；不要让一个构建目录吞入其它资源的文件。 |

登录和账号继承详见[环境与凭据](./02-环境与凭据.md)。

## 工作稿与发行

| 情况 | 下一步 |
|---|---|
| 首版/更新入口用反了 | 无已发版本用 `create-version`；有已发版本用 `version draft pull` 后 `update-version`。 |
| 更新提交提示必须 --yes | 当前更新入口要求显式 `--yes`，同时给 `--version` 或 `--bump`。 |
| 工作稿来源不是当前 latest | 先看 `version show --local`；通常以 `version draft pull --yes` 重建。继续旧底须明确匹配的 `--reuse-version`，新号仍大于当前 latest。 |
| 要覆盖或丢弃，却缺确认 | 先检查摘要；交互终端确认，脚本明确带 `--yes`。 |
| 文件分析变化后有待复核属性 | `version attr review` 查看；恢复对应文件属性或明确 `review discard <key>`，不能忽略后提交。 |
| 当前类型不支持可选配置 | 以类型详情的能力为准；不要新增或修改配置。历史配置可用 `version option rm <key>` 清理。 |
| `TYPE_RESPONSE_INVALID` | 类型服务请求失败、业务码异常或返回结构不完整。本次不会据此新建本地身份或资源壳；确认类型服务恢复后重试，不要把失败当作“没有匹配类型”。 |
| 依赖已声明，但运行时仍提示无授权 | 声明不等于授权。CLI 暂停签约/支付；去网页按当前源资源或合集身份处理，不以个人合同代替。 |
| `--policy-id` 或依赖命令 `--policy` 不识别 | CLI 签约入口已移除；删掉该参数，直接声明依赖，需要授权时到网页处理。作者配置自身策略的 `policy template` 仍可用。 |
| 合集单品提示先到网页处理上游授权 | 单品上游映射与直接依赖不同；按提示的合集 ID 及上游目标在网页签约，再重试，CLI 不自动签或猜填合同 ID。 |
| 上架缺版本或启用策略 | 完成版本发行与自身策略创建后再 online；依赖签约不能代替自身策略。 |
| 改说明没有产生新版本 | `version description` 改已发版本；下一版说明用更新稿的 `version draft description`。 |
| `CLI_UNEXPECTED_ERROR` | CLI 隐藏了可能含凭据的底层异常，不输出原始请求或错误栈。如刚执行写操作，先按下面的恢复流程核对实际结果，不要直接重复提交；不要为排查粘贴 token、cookie 或凭据库内容。 |
| `POLICY_TEMPLATE_COMPILE_FAILED` / `POLICY_TEMPLATE_TRANSLATION_FAILED` | 编译或翻译失败，本次尚未创建策略。平台有安全业务说明时会显示；未知请求仅提示“平台请求失败”，不附原始请求信息。保留模板 ID 便于排查；修正参数或确认平台恢复后再试，CLI 不自动替换其它模板。 |

`--reset` 先做确定性校验，再确认丢弃旧稿。确认后的上传、网络或提交失败不会把旧稿恢复回来。明确换绑另一资源也会丢弃被替换身份的工作稿。

## 中断与结果未知：分开处理

### 单资源版本提交

```powershell
freelog-cli resource recover --env dev
```

该命令根据工程内未决记录固定目标，只读核验，不重发。读清结果后：

```powershell
freelog-cli resource recover --apply --yes --env dev
```

- `prepared`：还未允许发送 POST，只清未决记录，保留工作稿。
- `sending`：只有版本详情的资源ID、版本号与SHA1都和记录精确一致，才清本次未决记录。当前稿还与发送时的字节摘要相同才一起删除；稿已变化或旧v1/v2记录无法证明未变时，保留整份稿并提示。无稿时不会重建。
- 查不到、详情缺字段、返回另一资源/版本、SHA1 不同或仍不确定：不会清理；保留现场，继续核实，不猜成功或失败。

不要手动删除 `.pending-operation.json` 后重发。

`SUBMIT_DRAFT_CHANGED`表示提交前校验期间稿被改过：本次没有POST，也没有新建未决记录；先检查当前稿再重新提交。若已提示“版本已提交，当前稿已保留”，不要重发同一版本；先读线上结果，再决定保留稿如何用于下一版。仅空白变化也按新字节保留。

明确 HTTP 5xx 即使附有可读报错，也不能证明版本没有创建成功；CLI 会保留稿和未决记录，按上面的流程核验，不自动重试。

### 策略创建

```powershell
freelog-cli policy list --resource id:<资源ID> --env dev
```

合集用对应的 `collection policy list`。查名称、启用状态和线上结果，再决定后续动作；不套用 `resource recover`，也不因创建报错立刻重复申请。

### 单资源资料与上下架

`UPDATE_RESULT_UNKNOWN` / `SHELF_RESULT_UNKNOWN`表示写入或其后的核验未能完成；`UPDATE_VERIFY_FAILED` / `SHELF_VERIFY_FAILED`表示实际读回与目标不一致。先在网页核对指定资源的资料/状态，保留工程，不重发、不用resource recover清理。`UPDATE_LOCAL_CACHE_FAILED`则已证明线上资料成功，只是本地标题同步失败，使用`resource sync --resource id:<资源ID> --env dev`修复缓存，不重复改线上。

非TTY写入需要`--yes`；取消或未确认不会上传封面/PUT。幂等结果changed=false不是失败，表示当前已满足请求或无修改项。完整输出和操作说明见[资料与上下架管理](./08-资源管理.md)。

### 合集发行与其它写操作

```powershell
freelog-cli collection publish resume --resource id:<合集ID> --env dev
```

这只是发行 intent 与远端结果的只读诊断，不自动清理、不自动重发，也不是目录添加、资料更新或策略写入的通用恢复器。其它合集写操作通过各自的只读查询核对结果。详见[合集管理](./合集/02-发行后管理与边界.md)。

## 本地状态损坏、锁和事务

先运行不依赖正常业务解析的本地诊断：

```powershell
freelog-cli resource list --env dev
```

它会报告身份、版本稿、重复状态、孤儿稿和未决记录等问题，不会修复或删除文件。

若显示“本地状态读取失败”，这是隐藏了未知底层异常，不代表文件已删除或修复；保留现场，检查对应文件和访问权限，不把凭据内容贴进报告。

- 损坏或错配工作稿可能连 `draft discard/pull` 都无法通过前置校验，不能承诺用同一条命令自动修复。
- 先备份整个 `.freelog/`，保留文件名、内容及错误信息。存在未决提交或事务时先查明远端事实，不能只删身份或稿掩盖问题。
- 确认不要且没有未决操作关联的工作内容，应在保留备份后单独处理；恢复线上身份使用 bind，不把旧 JSON 或自造字段当成受支持导入协议。
- `.lock` 是写锁。先确认没有其它 CLI 在写同一工程；不要删除正在使用的锁。
- `.txn.json` 是跨文件事务。下一次持锁写操作会尝试前滚恢复；持续失败时保留现场，不手动拆开修改事务。
- 凭据选择器不是可移植登录文件，不复制或手改；不要把秘密放进状态 JSON。

本地文件各自的含义见[本地文件参考](./10-本地文件参考.md)。
