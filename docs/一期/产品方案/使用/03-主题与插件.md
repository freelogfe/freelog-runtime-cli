# 主题与插件

主题和插件仍是**单资源**。它们与普通文件资源共用登录、建壳、版本工作稿、属性、可选配置、依赖、策略、管理和上下架流程；区别集中在工程初始化、路径形态和发版前的压缩。

| 项目 | 主题 | 插件 | 普通文件资源 |
|---|---|---|---|
| 初始化 | `init theme` | `init widget` | `init --type <最终叶子>` |
| 固定类型 | `RT001` | `RT002` | 由类型树选择并在线复验 |
| 初始 `filePath` | `dist` 目录 | `dist` 目录 | 可无；建壳或发版时记录一个文件 |
| 模板缓存 | 有 `N.template.json` | 有 `N.template.json` | 没有 |
| 发版输入 | 构建产物目录 | 构建产物目录 | 一个普通文件 |
| 上传前处理 | CLI 临时打 zip | CLI 临时打 zip | 直接上传原文件 |

## 1. 从线上模板创建工程

先查看 CLI 固定的线上模板清单：

```powershell
freelog-cli template list
```

创建主题或插件工程：

```powershell
freelog-cli init theme my-theme --template vite-react-ts --yes
freelog-cli init widget my-widget --template vite-vue-ts --yes
```

这两条命令不需要登录，因为类型固定；它们从固定版本的线上 npm 模板包下载并只复制包内 `template/` 内容。CLI 不从 `packages/templates/` 复制，也不会执行模板脚本、渲染项目名/版本、安装依赖或执行构建。

成功后会生成：

```text
my-theme/
  .freelog/1.json             # typeCode=RT001，filePath=dist
  .freelog/1.template.json    # 模板 id、精确版本、项目名和项目版本缓存
  ...模板文件
```

`N.template.json` 保存的是将来模板渲染所需的元数据；**不是**资源身份、版本表单或构建目录记录。构建目录始终记录在 `N.json.filePath`。

## 2. 创建主题或插件资源壳

初始化只建立本地工程，仍要登录并创建线上资源：

```powershell
freelog-cli login --env dev
freelog-cli create --cwd my-theme --title "我的主题" --name my-theme --yes --env dev
```

不要再传 `--type RT001` / `RT002`：CLI 会使用工程已记录的固定类型并在线复验。若显式传入不同的 `--type`，命令会失败，不能把模板工程改造成普通资源。

## 3. 先自行得到构建产物

CLI 不运行包管理器或构建命令。你需要在工程自己的开发流程中产生 `dist/`（或其他构建目录）。如果产物目录不是 `dist`，只更新记录：

```powershell
freelog-cli version set --cwd my-theme --file build
```

这条命令不上传、不压缩、不创建版本。目录可以暂时还不存在；真正发版时必须存在且非空。

## 4. 发布版本：传目录，不传 zip

```powershell
freelog-cli create-version --cwd my-theme --file dist --prepare --env dev
freelog-cli version show --cwd my-theme --local --env dev
freelog-cli create-version --cwd my-theme --file dist --yes --env dev
```

对于 `RT001` / `RT002`，CLI 会把 `dist` 的**内容**打入临时 zip（不会再包一层 `dist/`），然后计算 SHA1、上传、等待解析并提交。临时 zip 在上传后删除，不写入工程，也不写入 `N.json` 或工作稿。

以下输入会停止：

| 输入 | 结果 |
|---|---|
| `dist` 不存在 | 要求先生成构建产物。 |
| 空目录 | 要求先生成实际文件。 |
| 工程根目录（其中含 `.freelog/`） | 拒绝将工程根作为产物目录。 |
| 一个 `.zip` 或普通文件 | 拒绝；主题和插件只能交构建目录。 |

后续版本与普通资源完全相同：`version draft pull` → 编辑工作稿 → `update-version --version ...` 或 `--bump ...`；只要传入的仍是构建目录，CLI 会重新生成临时 zip。

## 5. 这不是两套版本系统

主题/插件和普通资源都使用同一份 `N.version.json` 工作稿，版本号规则、依赖签约规则、属性/可选配置校验、成功清稿和失败保留规则完全一致。唯一的文件层差异是：

- 普通资源的 `filePath` 指向文件，文件 SHA1 即上传文件的 SHA1；
- 主题/插件的 `filePath` 指向目录，文件 SHA1 与 `filename` 指向 CLI 临时 zip 的结果。

因此不要手工把 zip 记进 `filePath`，也不要因为主题是目录而另建一套版本缓存。
