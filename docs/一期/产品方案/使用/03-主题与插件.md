# 03 - 主题与插件

主题 `RT001`、插件 `RT002`。平台要 zip，**CLI 替你打**：指定构建产物目录，不要自己压 zip。

---

## 1. 模板立项

```bash
freelog-cli template list --scaffold runtime --env dev   # 看有哪些模板
freelog-cli init theme --template <模板id> --env dev     # 主题
freelog-cli init widget --template <模板id> --env dev    # 插件
# 等价写法：
freelog-cli init . --scaffold runtime --template <id> --resource-type RT001
```

- `init` 自动：`typeCode=RT001/RT002`、`filePath=dist`、拉模板代码、`pnpm install`。
- `--yes` 时必须带 `--template`。
- `init` **不**创建线上资源。下一步仍是 `login` → `create`。
- `init package`（前端库）能立项但本期场景不覆盖；`init --scaffold collection` 直接失败。

## 2. 构建（人自己来，CLI 不跑构建）

```bash
pnpm build        # 产物进 dist/
```

产物目录不是 `dist`？改记录即可，不用重新立项：

```bash
freelog-cli version set --file build --env dev
```

`version set` 只改 `N.json.filePath` 和 index，不打 zip、不上传。

## 3. 发首版

```bash
freelog-cli create --title 我的主题 --type RT001 --name my-theme --yes --env dev
freelog-cli create-version --yes --env dev
```

发版时 CLI 自动：

1. 确认本地路径（没传 `--file` 且 `dist` 存在：问「使用已记录的 dist？」，`--yes` 默认采用）。
2. **把目录内容打成临时 zip**（zip 根不套一层 `dist/`），传完即删，工程里不留下 zip。
3. 按平台类型上限校验 zip 大小，然后照常 sha1 → 上传 → 解析 → 提交。

## 4. 发新号

```bash
# 改了代码，重新 pnpm build 后：
freelog-cli version draft pull --env dev
freelog-cli update-version --yes --bump patch --env dev
# dist 已在：采用记录路径重新打 zip；要换目录：
freelog-cli update-version --file build --yes --bump minor --env dev
```

## 5. 主题/插件专用规则

| 情况 | 结果 |
|------|------|
| `dist` 不存在 / 空目录 | 失败：「没有构建产物 / 构建产物是空的，请先构建」 |
| 把工程根当产物目录（目录里有 `.freelog/`） | 失败：「不要把工程根当产物目录」 |
| 给了一个 `.zip` 文件 | 失败：「主题/插件请指定构建产物目录，不要自己打 zip」 |
| 其它类型给目录 | 失败：「不支持文件夹，请指定一个文件」 |
| 类型上溯到 RT001/RT002 + 路径是目录 | 打 zip（写死规则，不看 artifactMode） |

打不打 zip 只看 **类型 + 本次确认的路径是不是目录**。
