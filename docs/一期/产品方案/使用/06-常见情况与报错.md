# 06 - 常见情况与报错

每条提示：**为什么、怎么办**。文案以 CLI 实际输出为准；判断规则的真源在 [脚手架设计](../脚手架设计/PHASE/单资源/创建/00-总览.md)，本文不重复判断细节。

通用姿势：

- 看到 `prod 暂未开放`：联调加 `--env dev`（或 `test`）。prod 当前发布前被硬拦，见 [07](./07-环境与凭据.md)。
- 看到「请先 login」：先 `login --env dev`。
- 报错带 `--json` 时是 `{"code":"XXX","message":"..."}`；下文 code 列在括号里。

---

## 1. 登录与环境

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `prod 暂未开放，请用 --env test 或 --env dev`（PRODUCTION_ENV_DISABLED） | 省略 `--env` = prod，发布前被硬拦 | 加 `--env dev` 联调；发布前撤门禁后 prod 才可用 |
| `环境只能是 prod、test 或 dev`（ENV_INVALID） | `--env` / `FREELOG_ENV` 拼错（如 `staging`） | 用三个字之一；`production`/`development` 也收 |
| `请先 login`（AUTH_REQUIRED） | 当前目录和它的父目录都没有凭据 | `login --login-name <名> --env dev`；或到已 login 的目录跑 |
| `当前凭据是 {A}，本次是 {B}。请 logout 再 login --env {B}`（AUTH_ENV_MISMATCH） | 凭据文件绑着 A 环境，本次要 B | `logout` → `login --env {B}`。一份凭据只绑一个环境 |
| `凭据文件损坏：{路径}`（AUTH_INVALID） | auth 文件不是 JSON、字段缺失或解不开 | `logout` 删掉重登。**不会**悄悄换用另一份凭据 |
| `--password-stdin 必须同时使用 --yes`（LOGIN_PASSWORD_STDIN） | 脚本登录缺 `--yes` | 加 `--yes` |
| `请提供密码` / `登录失败：平台未返回凭据`（LOGIN_PASSWORD_REQUIRED / LOGIN_FAILED） | stdin 没读到密码 / 账号密码错 | 核对账号；`echo 密码 \| freelog-cli login --password-stdin --yes …` |
| `没有可删除的凭据`（LOGOUT_NOTHING） | 工作区和全局都没有凭据 | 无事可做；确认目录对不对 |

## 2. 本地工程（`.freelog/`）

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `一夹多条必须指定 --file`（IDENTITY_FILE_REQUIRED） | 工程里有多份 `N.json`，命令不知道落哪份 | `--file <路径或其对应文件>`；各份路径见 `status` |
| `没有与 --file {路径} 对应的身份`（IDENTITY_FILE_UNMATCHED） | 给的路径不在任何 `N.json` | 先 `version set --file <路径>` 登记，或用已登记的路径 |
| `当前目录没有身份文件`（IDENTITY_NOT_FOUND） | 还没 `init` / `create` | `init` 立项或 `create` 直接建 |
| `找不到身份文件 {n}.json` / `身份文件 {n}.json 无效`（IDENTITY_*） | 手工删改把 `N.json` 弄坏 | 恢复该文件或删掉重来（编号不复用，可留着占位） |
| `N.json 不能写入 {字段}`（IDENTITY_FORBIDDEN_FIELD） | 想把 `title` / `artifactMode` / `latestVersion` 等写进身份 | 身份只认 `subject/resourceId/name/typeCode/filePath/env`，见 [08](./08-本地文件参考.md) |
| `index.json 无法解析` / `index.json 无效`（INDEX_INVALID） | 手工编辑弄坏 index | 删掉 `.freelog/index.json`，下条命令会按 `N.json` 重修 |
| `工程正在被另一进程写入，请稍后再试`（PROJECT_LOCKED） | 上一个 CLI 进程还开着（或残留 `.freelog/lock`） | 等它退出；确认没进程后可删 `.freelog/lock` |

## 3. init / create

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `当前目录已有身份文件。覆盖请加 --yes`（INIT_ALREADY） | 目录已 init 过 | 确认要重置就加 `--yes`；否则直接进 `create` |
| `已有 index.json。覆盖请加 --yes`（INIT_INDEX_EXISTS） | 同上 | 同上 |
| `请选择资源类型`（INIT_TYPE_REQUIRED / CREATE_TYPE_REQUIRED） | 没定叶子类型 | `type list` / `type search` 查 code；`init --resource-type <code>` 或 `create --type <code>` |
| `init theme / widget 使用 --yes 时必须带 --template`（INIT_TEMPLATE_REQUIRED） | `--yes` 立项缺模板 | `template list` 查 id 后带上 |
| `模板种类只能是 runtime 或 package`（TEMPLATE_SCAFFOLD_INVALID） | `--scaffold` 拼错 | 只认 `runtime` / `package` / `none` |
| `合集本期不做`（INIT_COLLECTION_UNSUPPORTED / BIND_COLLECTION） | 合集是二期 | 用普通单资源 |
| `请输入资源标题` / `不超过100个字符`（CREATE_TITLE_*） | 标题空或超长 | 1–100 字符，提交用 trim 后的值 |
| `资源授权标识 {name} 已被使用，请重新输入。`（CREATE_NAME_TAKEN） | 查重命中**别人**的同名资源 | 换一个 `--name` |
| `这个标识已经创建过授权条目，还没有发行版本。`（CREATE_OWN_SHELL） | 查重命中**自己**的壳 | 别再 `create`。本地没身份就 `bind <id>`，然后 `create-version` |
| `这个标识已经有发行版本。`（CREATE_OWN_SHELL） | 自己的壳已发版 | 去 `update-version` 发新号 |
| `这个资源已经创建过授权条目，还没有发行版本。`（CREATE_ALREADY_SHELL） | 本地 `N.json` 已有 `resourceId` | 直接 `create-version`；不要重复 create |
| `--file 必须落在当前工程里`（CREATE_FILE_OUTSIDE） | 给了工程外的绝对路径 | 把文件放进工程目录，用相对路径 |
| `文件 {路径} 已对应 {名}，且还没有发行版本。请对该资源 create-version。`（CREATE_FILE_OCCUPIED） | 文件已被另一份身份占用 | 对那份跑 `create-version`，不要为同一文件再建壳 |
| `文件 {路径} 已对应 {名}。不要再 create。`（CREATE_FILE_OCCUPIED） | 占用方已发版 | 去 `update-version`，或换文件 |
| `授权标识只传短段，不要带 username/`（CREATE_NAME_SLASH） | `--name` 带了 `/` | 只传短标识；`username/name` 全名只用于 `bind` / 查重 |
| `--yes 必须同时提供 --type / --title / --name`（CREATE_YES_FLAGS） | 脚本化建壳缺旗标 | 三个都带上；缺交互提问的任何一项都会失败 |
| `创建失败：平台未返回 resourceId`（CREATE_FAILED） | 平台建壳响应异常 | 看平台 msg；确认网络 / 凭据后重试。若线上已建出壳，**不要**再 create，改用 `bind` |

## 4. bind

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `只能 bind 自己的资源`（BIND_NOT_OWNER） | id 是别人的 | 只能接入本人资源 |
| `路径已被占用`（BIND_PATH_TAKEN） | `--file` 已是另一份身份的 filePath | 换路径，或先清理那份身份 |
| `换绑需要 --force --yes`（BIND_FORCE_REQUIRED） | 这份身份已有别的 resourceId | 确认换绑加 `--force --yes`；**该份工作稿会被删掉** |
| `平台详情缺少身份字段`（BIND_INFO_INVALID） | 平台响应异常 | 重试；核对 id |

## 5. 发版与工作稿

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `这个资源已经有发行版本。线上 latest 是 {X}，请用 update-version。`（GATE_USE_UPDATE） | `create-version` 碰到已发版资源 | 改跑 `update-version`；本地稿不动 |
| `还没有发行版本，请先 create-version`（GATE_USE_CREATE） | `update-version` / `draft pull` 碰到没发过版的资源 | 先 `create-version` 发 1.0.0 |
| `这是更新版本的稿，发行版本不用。`（GATE_CREATE_SEES_UPDATE_DRAFT） | 本地稿带 `fromVersion`，却跑 `create-version` | 发首版用 `create-version --prepare`（重写为首版稿）；发新号走 `update-version` |
| `请先 create 或 bind`（GATE_NO_RESOURCE） | `N.json` 还没有 `resourceId` | 先 `create` 建壳或 `bind` 接入 |
| `提交请加 --yes`（CREATE_VERSION_NEED_YES） | 正式提交必须显式确认 | 预览无误后 `create-version --yes` |
| `缺少文件`（SUBMIT_FILE） | 工作稿里没有 `fileSha1`，本地也没文件 | 先 `create-version --prepare` 或 `--file` 上传 |
| `提交失败：{字段}`（SUBMIT_FAILED） | 平台提交校验没过，点名了字段 | 按字段改稿（`version attr/option/dep`）再交；**稿保留** |
| `没有工作稿，请先 version draft pull`（DRAFT_MISSING） | 改稿命令没有稿可改 | 先 `create-version --prepare`（首版）或 `draft pull`（更新） |
| `工作稿 {n}.version.json 无法解析` / `工作稿不能写入 {字段}`（DRAFT_*） | 手工编辑弄坏稿 | 修 JSON；或 `version draft discard` / `update-version --reset` 重来 |
| `没有这个版本`（DRAFT_VERSION_MISSING） | `draft pull --version` / `--reuse-version` 的号不在版本列表 | `version show` 核对已有号 |
| `稿已来自 {X}，未覆盖` / `未覆盖` | `draft pull` 本地已有稿，没给 `--yes` 不盖 | 确认要盖就 `draft pull --yes` |
| `本地文件不在：{路径}。不准续用 sha1`（FILE_MISSING） | 记录的 filePath 在磁盘上没了 | `--file` 给当前真实路径；文件挪了位置先 `version set --file` |
| `请 --file 指定本地文件或目录`（FILE_NEED_FLAG） | `--yes` 且记录路径本地不在 | 脚本必须显式 `--file` |
| `属性解析超时` / `属性解析失败`（FILE_ANALYZE_*） | 平台解析 120 秒没完成 / 解析报错 | 稍后重跑；稿里的 sha1 还在，不必重传 |

## 6. 定新号（update-version）

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `请指定 --version 或 --bump`（VERSION_NEED_TARGET） | `--yes` 但没说发几号 | `--version 1.1.0` 或 `--bump patch\|minor\|major` |
| `不要同时使用 --version 和 --bump`（VERSION_FLAGS_CONFLICT） | 两个都要 | 二选一 |
| `版本号无效` / `--bump 只能是 patch、minor 或 major`（VERSION_*） | 号不是合法 semver / 方向拼错 | 合法 semver；方向三选一 |
| `线上已经是 {latest}，不能发 {新号}`（UPDATE_VERSION_NOT_GREATER） | 新号没有严格大于当时 latest | 换更大的号；**稿保留** |
| `稿来自 {X}、底是 {Y}。请 version draft pull 或 --reuse-version`（UPDATE_VERSION_MISMATCH） | 本地稿的底和本次认的底对不上，`--yes` 拒绝默默重拉 | `version draft pull --yes` 重拉，或 `--reuse-version {X}` |

## 7. 表单（attr / option / dep）

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `自定义属性需要名称和键` / `可选配置需要名称和键`（ATTR_FIELDS / OPTION_FIELDS） | 一行式缺字段 | `version attr add "名称=作者 键=author 值=张三"` |
| `自定义属性值最长 100`（ATTR_VALUE_LONG） | 值超长 | 缩短 |
| `最多可添加30个属性` / `最多可添加30个可选配置`（ATTR_FULL / OPTION_FULL） | 30 条上限 | 先删再加；30 条是写死的产品规则 |
| `键 {key} 已存在`（ATTR_DUPLICATE / OPTION_DUPLICATE） | 重复加同名键 | 改键，或用 `attr set` 改值 |
| `键不能改`（FORM_KEY_IMMUTABLE） | `attr set` 想换 key | 键写下后不能改；删了重加 |
| `改附加属性须已有 fileSha1`（ATTR_NEED_FILE） | 还没传文件就想改解析出来的附加值 | 先 `create-version --prepare` / `draft pull` |
| `当前类型不支持可选配置`（OPTION_UNSUPPORTED） | 类型 `supportOptionalConfig !== 2` | 该类型没有可选配置；别加 |
| `方式只能是文本或下拉` / `下拉默认值固定为第一项，请把要默认的选项放在第一位` / `文本方式不要写选项` / `选项个数不能超过30项`（OPTION_*） | option 一行式参数不合法 | 按规则改：`方式=文本` 不带选项；`方式=下拉` 带选项，默认取第一项 |
| `不能依赖自己` / `对方不是普通单资源，不加` / `对方还没有发行版本`（DEP_*） | 依赖对象不合法 | 换依赖对象 |
| `这个范围对不上对方已发行的版本`（DEP_RANGE） | `--range` 没覆盖对方现有号（add 与 range 都查） | 改成能命中的范围，如 `^1.0.0` |
| `添加此依赖会导致循环依赖，无法添加。`（DEP_CYCLE） | 平台环检测拒绝 | 换依赖方向 |
| `对方存在基础上抛，本期不支持。`（DEP_UPCAST） | 对方树带基础上抛 | 本期不支持；不加这条依赖 |
| `对方没有可签约的策略`（DEP_NO_POLICY） | 对方一条启用策略都没有 | 换有启用策略的资源做依赖 |
| `无法解析：{token}`（FORM_LINE_INVALID） | 一行式语法错 | `字段=值` 空格分隔；含空格/`=` 用双引号包，内部 `\"` 转义 |
| `请加 --yes 确认预览`（FORM_NEED_YES） | 脚本里改稿没确认 | 预览没问题加 `--yes` |
| `已取消`（FORM_CANCELLED） | 预览时选了否 | 重新跑，稿不变 |

## 8. 管理（update / policy / 上下架）

| 提示（code） | 为什么 | 怎么办 |
|--------------|--------|--------|
| `--yes 且无修改项，拒绝空更新`（UPDATE_NO_FLAGS） | `update --yes` 一个 flag 没带 | 至少带 `--title/--intro/--cover/--tags` 之一 |
| `请提供 --from-file`（POLICY_FROM_FILE） | `policy apply` 缺文件 | 传策略文本或 `{"policyName","policyText","status"}` JSON 路径 |
| `请提供 --id`（POLICY_ID_REQUIRED） | `policy set` 缺策略 id | id 从 `policy list` 拿 |
| `--yes 无模板 id`（POLICY_TEMPLATE_ID） | `policy template apply --yes` 缺 id | 从 `policy template list` 拿 id |
| `上架须已有版本`（ONLINE_NO_VERSION） | 还没发过版 | 先 `create-version` |
| `上架须至少一条启用策略`（ONLINE_NO_POLICY） | 没有启用中的策略 | `policy apply` / `policy set --on` 后再来；**不会**自动帮你加 |
| `目前只支持 --for online`（VALIDATE_FOR） | `validate --for` 拼错 | 只支持 `online` |

## 9. 平台侧错误

| 现象 | 为什么 | 怎么办 |
|------|--------|--------|
| `用户认证失败,请登录` / auth error: unauthorized | 凭据过期或被顶掉 | `logout` → `login --env dev` |
| 平台 `msg` 原文（如「参数xxx校验失败」） | 平台校验，CLI 原样透出 | 按 msg 改；改完稿还在，重跑即可 |
| 命令卡在上传 / 解析 | 大文件或平台慢 | 解析有 120 秒上限会自己失败；上传中断整文件重传，稿里的 sha1 不丢 |

稿的安全网：**除了成功 POST（自动删稿），所有失败都保留工作稿**。下次接着来，不用从头传。
