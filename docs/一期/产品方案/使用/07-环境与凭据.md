# 07 - 环境与凭据

三套环境怎么选、凭据放哪、怎么加密。判断规则的真源在 [ARCHITECTURE/07](../脚手架设计/ARCHITECTURE/07-环境.md)、[ARCHITECTURE/01-账号](../脚手架设计/ARCHITECTURE/01-账号.md)。

---

## 1. 三个环境

| CLI `--env` | 也接受 | API | Console | 用途 |
|-------------|--------|-----|---------|------|
| `prod` | `production` | `https://api.freelog.cn` | `https://console.freelog.cn` | 正式。**当前发布前被硬拦** |
| `test` | — | `https://api.testfreelog.com` | `https://console.testfreelog.com` | 测试 |
| `dev` | `development` | `https://api.devfreelog.com` | `https://console.devfreelog.com` | 联调 |

其它值（`staging`、`local`…）直接失败：`环境只能是 prod、test 或 dev`。

## 2. 这次用哪个环境

优先级从上到下，取第一次命中：

1. `--env <值>`（每个写命令都挂了这面共用旗）
2. 环境变量 `FREELOG_ENV`（CI 用）
3. **默认 `prod`**——因为发布前有 prod 门禁，省略 `--env` 的写命令会失败，不会误打测试环

```bash
freelog-cli status --env dev              # 显式
FREELOG_ENV=dev freelog-cli status        # CI
freelog-cli status                        # = prod：写命令会被 prod 门禁拦下
```

## 3. 登录

```bash
freelog-cli login --login-name <名> --password-stdin --yes --env dev   # 密码走 stdin（唯一入口）
echo '你的密码' | freelog-cli login --login-name <名> --password-stdin --yes --env dev
freelog-cli login --global --login-name <名> --password-stdin --yes --env dev   # 写机器默认号
freelog-cli logout                        # 先工作区，没有才删全局
freelog-cli logout --global               # 只删 ~/.freelog-auth
```

- 密码**必须**走 `--password-stdin`（必须连着 `--yes`）；没有把密码当命令行参数的写法，也没有浏览器授权、二维码。`--login-name` 省略会提示 `请提供 --login-name`。
- dev 的登录态在平台下发的 **Cookie**（`authInfo` + `uid`）里，`login` 会一并捕获，随凭据加密存盘；`tokenSn` 只作展示。
- 登出只删本地凭据，不调平台注销；`.freelog/` 工程不受影响。

## 4. 凭据放哪

从 `--cwd`（否则当前目录）**往上**找：

| 层 | 文件 | 何时用 |
|----|------|--------|
| 工作区 | 最近的一份 `.freelog/auth` | **默认**。子目录的盖过父目录的 |
| 全局 | `~/.freelog-auth` | 整条路径都没有工作区凭据时；或显式 `--global` |

规则：

- 可以先 `login` 再 `init`（登录和立项谁先都行）。
- **坏文件报错，不准回退另一份**——避免静默换成另一个账号。
- 文件里的环境必须等于本次 `--env`，对不上失败：
  `当前凭据是 dev，本次是 test。请 logout 再 login --env test`
- 换账号：`logout` → `login`。换环境：`logout` → `login --env <新环境>`。**一份凭据只绑一个环境**。

## 5. 加密存储

`.freelog/auth` 长这样（都是密文）：

```json
{
  "env": "dev",
  "userId": 50427,
  "loginName": "freelog-test11",
  "iv": "…",
  "tag": "…",
  "token": "…",
  "cookieIv": "…",
  "cookieTag": "…",
  "cookie": "…"
}
```

- AES-256-GCM；`iv` / `tag` 是每次写入随机生成的。
- **不要手改这个文件**；改坏报 `凭据文件损坏`，只能 `logout` 重登。
- 必须在 `.gitignore` 里（工作区 login 会提示确认）；`test/` 下的联调凭据文件同理。

## 6. 和本地状态的关系

- `N.json.env`：只有非 prod 的 `create` / `bind` 才写（`"env": "dev"`）。**没写 = prod**。
- 发版命令会核对 `N.json.env` 与本次环境，dev 壳交到 test/prod 会失败。
- 凭据、身份、工作稿分属三个文件，形状见 [08-本地文件参考](./08-本地文件参考.md)。

## 7. 常见坑

| 坑 | 结果 |
|----|------|
| 忘了 `--env dev` | 写命令报 `prod 暂未开放`（这是门禁在工作，不是 bug） |
| 在旧目录里跑（那目录 login 过别人） | 用的是**那份**凭据；换人先 `logout` |
| 两个终端同时跑写命令 | 第二个报 `工程正在被另一进程写入`，等第一个退出 |
| 复制别人的 `.freelog/auth` | 解密失败或环境对不上，报错不会静默通过 |
