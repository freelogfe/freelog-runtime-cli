# 单资源：资料与上下架管理

前置条件：工程已登录正确账号，目标资源已 create 或 bind。本页在工程根执行，用资源 ID 明确目标与 dev 环境；修改线上资料不会发行新版本，也不改下一版本的工作稿。

## 查看现状

```powershell
freelog-cli status --resource id:<资源ID> --env dev
freelog-cli version show --resource id:<资源ID> --env dev
freelog-cli policy list --resource id:<资源ID> --env dev
```

status 汇总身份、工作稿与线上 latest；version show 读取线上版本，policy list 读取自身策略。指定历史版可给 version show 加 `--version 1.0.0`；只看未提交稿则加 `--local`，两种用途不要混淆。

status当前成功结果为三段文本，不提供成功JSON或完整上下架资料。未绑定时显示“线上：未查询”，不请求平台；绑定后只接受同一资源的有效详情。平台明确没有版本时显示`latestVersion=无`；缺失/错ID、畸形版本或请求失败均非零退出，不用本地缓存补造线上现状。它不会刷新标题、修改稿或清未决记录，冻结/非本人也不额外套用写权限门禁；需要恢复另用resource recover。

## 修改展示信息

只发送明确给出的字段。下面同时修改标题、简介和标签；先把示例内容换成自己的：

```powershell
freelog-cli update --title "新标题" --intro "一句话简介" --tags "教程,图片" --resource id:<资源ID> --yes --env dev
```

只改一个字段时删掉其它字段参数，不必全填。要换封面，先准备工程内图片，再执行独立操作：

```powershell
freelog-cli update --cover cover.png --resource id:<资源ID> --yes --env dev
```

封面支持 JPG、PNG、静态 GIF，最大 5MB，CLI 上传后写入 URL，**没有裁剪功能，也不支持清空封面**。标题最多 100 字符，简介最多 200 字符；最多 20 个不重复标签，每个最多 20 字符。标签可写 # 前缀，存储时去掉前缀。

清空简介用 `--intro ""`，清空全部标签用 `--tags ""`，不是保留原值。没有任何修改字段的 --yes 更新会拒绝，不发送空更新。TTY中也可以只运行`freelog-cli update --resource id:<资源ID> --env dev`，按提示逐项修改，回车保留；全部保留不发请求。有任一修改参数时只改指定字段，不额外询问其它字段。

CLI先显示当前资料、校验全部输入，再确认；确认前不上传封面、不写平台。脚本须显式`--yes`。写后会重新读取整份资料，确认只发生指定修改，才显示成功并同步本地标题。RSS导入资源的资料当前只读。

AI可给update加`--json`，成功只返回`{resourceId,changed,listing:{resourceName,title,intro,tags,coverImages,status}}`，字段来自实际读回；失败为非零和两字段`{code,message}`。`changed:false`表示没有需要写入的变更。出现`UPDATE_RESULT_UNKNOWN`或`UPDATE_VERIFY_FAILED`先核对网页资料，不要立即重发；线上成功但本地缓存失败会明确提示，用resource sync修复本地标题。

`--json`不代表自动同意。在交互终端，资源选择、字段输入和确认仍会执行，提示与答案写stderr，stdout只保留结果JSON；脚本请提供精确`--resource`、修改参数及`--yes`。

## 同步本地标题

标题可以重复，也可能被网页改过，只作展示，**不用标题定位资源，不默认先同步所有标题**。

要刷新当前环境全部已绑定单资源的本地标题：

```powershell
freelog-cli resource sync --env dev
```

若只想刷新一份，使用下面这条替代批量命令：

```powershell
freelog-cli resource sync --resource id:<资源ID> --env dev
```

同步只读线上并回写匹配身份的本地标题，不修改平台、版本稿或产物路径。部分失败时成功项已更新，失败项保持原值，命令非零退出并报告。CLI update --title 成功后已回写本地标题，无需立即再同步。

AI或脚本可获取逐项结果：

```powershell
freelog-cli resource sync --json --env dev
```

stdout只有一个对象，包含`schemaVersion:1`、`env`、`summary:{total,succeeded,failed}`和按状态编号升序的`results`。每项用`stateFile`和`resourceId`定位，`synced`项有`title`，`failed`项有`error:{code,message}`。部分或全请求失败时仍返回完整批次，退出1；不要把非零退出理解成成功项没更新。登录、状态或事务错误则返回普通`{code,message}`，不输出伪成功批次。只重试报告指出的失败目标；不要手工覆盖身份ID。

## 上架

资源必须有已发行版本和至少一条启用的自身策略；依赖签约不算自身策略。

```powershell
freelog-cli validate --for online --resource id:<资源ID> --env dev
```

这条只检查。读清结果，补齐缺失项后才执行：

```powershell
freelog-cli online --resource id:<资源ID> --yes --env dev
freelog-cli status --resource id:<资源ID> --env dev
```

online会再次检查，确认后只写status，再读回同一资源和owner、确认status=1才显示成功。已经上架且前置合法时不重复写。status命令仍不展示上下架状态；可在online加`--json`得到`{resourceId,status,changed}`，或在浏览器核对。完整首次流程见[快速上手](./01-快速上手.md)，策略添加见[单资源授权策略](./07-单资源授权策略.md)。

## 下架

确实需要下架时执行，**不是上架后的下一步**：

```powershell
freelog-cli offline --resource id:<资源ID> --yes --env dev
freelog-cli status --resource id:<资源ID> --env dev
```

只改变可用状态，不删除资源、历史版本、策略、本地身份或工作稿。offline写后强制读回status=4；原本为0或4时不写，保留原状态。它也支持`--json`的`{resourceId,status,changed}`。没有`--yes`的TTY会确认，脚本必须带`--yes`。出现`SHELF_RESULT_UNKNOWN`或`SHELF_VERIFY_FAILED`先核对网页状态，不盲目重试；不要从CLI下架操作自行推导已有合约的退款或解除规则。

## 其它管理与失败

- 自身策略启停见[策略教程](./07-单资源授权策略.md#启停已有策略)。
- 发新版、绑定已有资源见[日常路径](./04-日常路径.md)。
- 修改已发版本说明见[两种版本说明](./06-版本工作稿.md#5-两种版本说明)，不是资源简介。
- 非 owner、被冻结或环境不符时写操作会拒绝，不因此删除本地稿。中断或结果未知先按[故障恢复](./09-常见情况与报错.md)只读核实；资料和策略更新不套用版本提交恢复器。
