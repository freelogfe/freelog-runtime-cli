# 发行前填写版本内容

属性、可选配置、依赖和说明都属于**待发行版本**。不是每个资源都必须填写，但有需求时应在提交前完成；发行成功清理本次未变稿，后来变稿保留并提示。编辑工作稿不会修改已发版本。

前置条件：已经 create 或 bind，工程已登录正确账号。以下在工程根执行，每条命令使用同一资源 ID 和 dev 环境；主题等其它目录操作另加 `--cwd <工程目录>`。不要手工编辑缓存 JSON 当成导入协议。

## 1. 准备工作稿：按情况选一条路径

先用 `status --resource id:<资源ID> --env dev` 确认是否已有工作稿。**有稿时先查看**，保存需要保留的内容；想继续编辑现有稿就跳过下面的准备步骤：

```powershell
freelog-cli version show --local --resource id:<资源ID> --env dev
```

没有稿，或已明确决定放弃旧稿，才按线上是否已有版本选择下列路径。

**还没有任何已发版本：**先准备首版，上传并等待当前文件解析，但不提交：

```powershell
freelog-cli create-version --prepare --resource id:<资源ID> --env dev
```

**线上已有版本：**从 latest 建更新稿。已有未提交稿时，先查看再决定是否覆盖；交互确认覆盖会丢弃旧稿，脚本只有明确允许才加 `--yes`：

```powershell
freelog-cli version draft pull --resource id:<资源ID> --env dev
```

两条路径互斥，不能连着执行。准备成功后查看：

```powershell
freelog-cli version show --local --resource id:<资源ID> --env dev
```

现在停下来按需要编辑下面的项目。不需要某项就跳过；编辑工作稿本身不提交版本，添加依赖只写声明，不签约或支付。

## 2. 自定义属性

新增一条属性并查看：

```powershell
freelog-cli version attr add "名称=作者 键=author 值=张三" --resource id:<资源ID> --env dev
freelog-cli version attr list --resource id:<资源ID> --env dev
```

之后要修改这条属性时执行：

```powershell
freelog-cli version attr set "键=author 值=李四" --resource id:<资源ID> --env dev
```

只有明确不要时才删除，不是新增后的必做步骤：

```powershell
freelog-cli version attr rm author --resource id:<资源ID> --env dev
```

键创建后不可改；换键需要删掉重建。属性与配置的 key 不可互相重复。一行式整体加引号；交互会预览并确认，脚本填全字段后加 `--yes`，不会跳过校验。

### 系统附加属性不是自定义属性

文件分析产生的可填写附加属性用平台提供的 key 设置，不用 add 新造一条：

```powershell
freelog-cli version attr set "键=<当前分析提供的附加属性key> 值=<填写值>" --resource id:<资源ID> --yes --env dev
```

先准备当前文件，再列出自定义属性及平台提供的系统附加字段：

```bash
freelog-cli create-version --prepare --resource id:<资源ID> --env dev
freelog-cli version attr list --resource id:<资源ID> --env dev
```

`create-version --prepare` 仅适用于尚无发行版本的资源；已有版本先 `version draft pull`，再用 `version attr list` 按拉取文件的 SHA 查询字段，正式更新时会重新分析本次本地文件。列表会显示附加字段的当前值、未填状态、可编辑性及平台规则，不能把只读元数据当作可填写字段。

主题/插件的 `bundleTool`（打包工具）、`noderuntime_target_version`（运行时目标版本）是系统附加属性，不是资源版本号，也不是自定义属性。例如列表确认它们可编辑后：

```bash
freelog-cli version attr set "键=bundleTool 值=vite" --resource id:<资源ID> --yes --env dev
freelog-cli version attr set "键=noderuntime_target_version 值=<实际兼容的运行时版本>" --resource id:<资源ID> --yes --env dev
```

不要给未知工程照抄 `vite` 或某个运行时版本。允许清空时显式写 `值=`；省略值不会替你清空。CLI 按平台格式校验，未知键、只读字段及格式错误不会写稿。拉稿会恢复已发行的附加值，但不会操作 Console 网页草稿；旧稿里有同名自定义项时需先检查、清理冲突，再填写系统附加值。

## 3. 可选配置：先确认类型能力

用 `freelog-cli type info <当前类型code> --env dev` 查看，显示“可选配置：支持”才新增或修改配置。是否支持由后台配置决定，不固定为只有主题、插件；普通图片等也须逐类型查询。

文本配置示例：

```powershell
freelog-cli version option add "名称=主题 键=theme 方式=文本 默认=dark" --resource id:<资源ID> --env dev
freelog-cli version option list --resource id:<资源ID> --env dev
```

若需要下拉配置，以下是**另一条配置示例**；候选值用 `|` 分隔，整行须加引号：

```powershell
freelog-cli version option add "名称=配色 键=palette 方式=下拉 选项=dark|light 说明=选择配色" --resource id:<资源ID> --env dev
```

下拉默认值是第一项，不传 `默认=`。需要将默认项改成 light 时调整顺序：

```powershell
freelog-cli version option set "键=options_palette 选项=light|dark" --resource id:<资源ID> --env dev
```

配置按 Console 的规则保存完整键：新增时 `theme` 与 `options_theme` 都保存为 `options_theme`。前缀计入30字符，短键最多22字符；`list` 显示完整键，修改、删除时按列表中的完整键定位。文本配置改默认值用 `option set "键=options_theme 默认=light"`。删除配置是独立操作：

```powershell
freelog-cli version option rm options_theme --resource id:<资源ID> --env dev
```

当前类型不支持时 add/set 会停止；rm 仍可清理历史遗留配置。遗留项未清理时发行也会拒绝，不会偷偷提交。

读取旧配置不自动改键；明确编辑旧配置时，CLI 会按 Console 的保存方式处理前缀，并在确认预览中显示原键和最终键。取消或转换后的键冲突都不会写稿。自定义属性和系统字段不加此前缀。

自定义属性、可选配置各最多 30 项，名称与说明最多 50 字符，值或候选项最多 140 字符；下拉最多 30 个不重复候选。key 为字母开头、最长 30 字符，具体允许字符与其它规则以命令校验为准。

## 4. 声明依赖

人工添加对方单资源的线上 ID 和版本范围：

```powershell
freelog-cli version dep add <依赖资源ID> --range "^1.0.0" --resource id:<当前资源ID> --env dev
```

普通图片、视频与主题、插件使用同一规则：CLI 只声明依赖，不查询合约、不选择策略、不签约或支付。没有合约也能添加并发行版本；人和 AI 都用上面这一条命令，不再提供 `--policy-id`。

声明成功不代表已获得消费授权。需要签约或支付时，到网页中**当前源资源**的“依赖及其授权”处理，乙方是当前资源 ID，不是登录用户个人。发布前也不会补签或以缺合约阻止提交；资源身份、类型、版本范围、循环、文件和表单校验仍保留。

添加后查看（这里只显示本地声明，不证明已付款或已获得访问授权）：

```powershell
freelog-cli version dep list --resource id:<当前资源ID> --env dev
```

以后改范围时执行：

```powershell
freelog-cli version dep range <依赖资源ID> --range "^1.1.0" --resource id:<当前资源ID> --env dev
```

明确要移除时执行：

```powershell
freelog-cli version dep rm <依赖资源ID> --resource id:<当前资源ID> --env dev
```

删除稿中的依赖不撤销已经签过的线上合约。对方未发行、不可用、范围无效或造成循环等情况会拒绝；本页添加的依赖与自己对外提供的授权策略不是一回事。

## 5. 两种版本说明

**更新稿说明：**只编辑尚未提交的下一版，不发行：

```powershell
freelog-cli version draft description --description "本次更新说明" --resource id:<资源ID> --env dev
```

首版说明固定为空，不用该命令给首版稿填说明。

**已发版本说明：**直接写指定线上版本的说明，不产生新版本，也不修改工作稿：

```powershell
freelog-cli version description --version 1.0.0 --description "补充发布说明" --resource id:<资源ID> --env dev
```

两者按目的选择，不是连续步骤。

## 6. 最后检查，然后只提交一次

```powershell
freelog-cli version show --local --resource id:<资源ID> --env dev
```

停下来确认属性、配置、依赖、更新说明及产物无误。无已发版本时提交首版：

```powershell
freelog-cli create-version --resource id:<资源ID> --yes --env dev
```

已有版本时提交新版，**替代上面首版命令**：

```powershell
freelog-cli update-version --bump patch --resource id:<资源ID> --yes --env dev
```

成功后用 `version show`（不带 --local）读回线上结果。上架仍需自身启用策略；完整首次上架见 [01](./01-快速上手.md)，更新完整路径见 [04](./04-日常路径.md)。

## 换文件、复核与放弃工作稿

发版始终需要真实文件或构建目录，旧稿 SHA1 不能代替文件。更换本次产物在发行命令上给 `--artifact <新路径>`，同时保留资源 ID；普通资源只能用文件，主题/插件目录才临时压缩。

文件重新分析导致系统附加属性变化时，CLI 保留旧值并阻止未复核提交。先查看：

```powershell
freelog-cli version attr review --resource id:<资源ID> --env dev
```

同 key 再次出现且旧值符合当前规则时可恢复；仍不合法则继续留待复核，不能仅凭键相同直接提交。确认某项不要时才丢弃：

```powershell
freelog-cli version attr review discard <key> --resource id:<资源ID> --yes --env dev
```

想完全放弃当前稿，先看 show --local，再执行明确丢弃：

```powershell
freelog-cli version draft discard --resource id:<资源ID> --env dev
```

确认成功后再按第 1 节选首版准备或更新拉稿。覆盖、discard、reset 和换绑都会丢弃相应旧内容；后续失败不会把已放弃的稿恢复回来。

进阶参数：`--reset` 明确重置后继续；`--reuse-version <原底版本>` 明确认可当前稿的旧底，必须与稿来源一致，新号仍大于线上 latest。普通更新优先从 latest 拉稿，不手改来源字段。稿损坏或提交结果未知时先保留现场，按[故障恢复](./09-常见情况与报错.md)核实，不能承诺 pull/discard 一定能修复损坏稿。
