# 完整命令参考

本页是发布包内的命令索引：列出当前 CLI 的全部公开命令、何时使用以及它会不会改变线上资源或本地文件。首次完成任务请优先看[按场景操作](./09-按场景操作.md)；执行已知命令、编写脚本或排查影响时以本页为准。

所有示例省略 `freelog-cli` 前缀后的公共参数。推荐每次显式传 `--env dev` 或 `--env test`；多资源工程的**常规单资源命令**要传 `--resource file:N.json`（交互终端可选择）。`create` / `bind` 可新增或接续身份，`resource sync` 不传选择器时批量同步标题，它们不是这条规则的反例而是不同的生命周期语义。`--yes` 只跳过交互确认，不会放宽校验。详细选择规则见[首页](./README.md#多资源工程先选身份再给产物)。

## 发现命令与获得帮助

```powershell
freelog-cli --help
freelog-cli version --help
freelog-cli policy template apply --help
freelog-cli --cli-version
```

顶层 `--help` 会打印安装包内本手册的绝对路径；子命令 `--help` 显示该命令当前支持的选项。脚本不要从帮助文本解析业务结果；需要稳定错误结构时使用 `--json`。

## 账号、工程和类型

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `login [--global]` | 登录当前工作区；脚本可用 `--login-name`、`--password-stdin --yes`。 | 将秘密写入系统凭据库，并写入工作区或全局选择器。 |
| `logout [--global]` | 切换账号或清除本地登录选择。 | 只清选择器及明确孤立的凭据；不删除工程或线上资源。 |
| `init [dir] [--type <叶子类型>]` | 在空目录创建普通资源的本地身份。 | 新建未绑定 `N.json`，不创建线上资源。 |
| `init theme <dir> [--template <id>]` | 从主题模板创建新工程。 | 固定主题类型 `RT001` 与默认构建目录 `dist`。 |
| `init widget <dir> [--template <id>]` | 从插件模板创建新工程。 | 固定插件类型 `RT002` 与默认构建目录 `dist`。 |
| `template list` | 查看可用于主题/插件初始化的模板。 | 只读。 |
| `type list` | 列出全部可用最终叶子类型。 | 只读，需要登录。 |
| `type search [关键词]` | 按名称筛选最终叶子类型。 | 只读，需要登录。 |
| `type info <类型编号>` | 确认某个类型编号及其名称链。 | 只读，需要登录。 |
| `type pick [--type <类型编号>]` | 以命令方式列出或确认一个最终叶子类型。通常 `init` 的交互选择已足够。 | 只读，需要登录。 |

## 建立或接入资源身份

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `create --title <标题> --name <短标识> [--type <叶子类型>] [--artifact <路径>]` | 线上还没有该资源壳时创建它。已有唯一未绑定身份时会接续它；没有未绑定身份时新增一份本地状态。 | 创建线上资源壳并写入 `resourceId`；只记录产物路径，不上传、不发版、不上架。 |
| `bind <资源ID或username/name> [--artifact <路径>] [--force --yes]` | 线上已有且属于当前账号的资源，需要接入本地工程。 | 从平台读取身份，写入或接续一份 `N.json`；不拉版本、不上传。 |
| `status` | 想同时确认选中资源的本地身份、工作稿和线上状态。 | 只读。 |
| `resource sync [--resource <selector>]` | 网页或其它机器改过标题，需要刷新本地标题。 | 不传选择器时批量按资源 ID 同步当前环境全部绑定身份的 `title`；传选择器时只同步一份。 |
| `version set --artifact <路径>` | 文件改名、构建目录从 `dist` 变成 `build`，只想更新默认路径。 | 只改选中 `N.json.filePath`；不上传、不提交。 |

`--name` 是当前账号命名空间中不可重复、创建后不可改的短标识；`--title` 是可修改且可重复的展示名称。创建后的标题用 `update --title` 修改；本地标题用 `resource sync` 对齐。

## 版本：查看、工作稿与提交

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `version show [--version <已发号>]` | 查看线上 latest 或指定已发行版本。 | 只读，不覆盖本地工作稿。 |
| `version show --local` | 查看未提交工作稿。 | 只读；没有工作稿会提示失败。 |
| `version draft pull [--version <已发号>]` | 已有线上版本，基于 latest 或指定版本建立更新稿。 | 写入 `N.version.json`；已有稿默认拒绝覆盖。 |
| `version draft pull --yes` | 明确放弃当前工作稿，重新拉取版本。 | 覆盖工作稿；先打印即将丢失的摘要。 |
| `version draft discard` | 明确放弃当前工作稿。 | 删除选中资源的 `N.version.json`；没有稿时安全退出。 |
| `version draft description --description <文本>` | 修改**更新工作稿**的版本说明。 | 只写工作稿；不发新版本。 |
| `version description --version <已发号> --description <文本>` | 修改一个**已发布版本**的说明，而不创建新版本。 | 唯一直接更新线上版本信息的命令；不写工作稿。 |
| `version attr add|set|rm|list` | 维护工作稿的自定义属性。 | 写操作只改工作稿；`list` 只读。 |
| `version option add|set|rm|list` | 维护工作稿的可选配置。 | 写操作只改工作稿；仅资源类型允许时可用。 |
| `version dep add|range|rm|list` | 维护工作稿中的依赖及版本范围。 | 写操作只改工作稿；首次签约可能产生独立平台授权动作。 |
| `create-version --prepare [--artifact <路径>]` | 尚无已发版本时上传分析并建立首版工作稿。 | 写工作稿，不提交线上版本。 |
| `create-version --yes [--artifact <路径>]` | 尚无已发版本时提交固定的 `1.0.0`。 | 上传并提交首版；成功后删除工作稿并回写有效产物路径。 |
| `create-version --reset ...` | 首版工作稿确认不要了，直接从空表重新走本次命令。 | 会立即丢弃工作稿，再继续准备或提交；后续失败不会恢复旧稿。 |
| `update-version --version <新号> --yes [--artifact <路径>]` | 已有线上版本，指定后续版本号并提交。 | 上传并提交新版本；成功后删除工作稿。 |
| `update-version --bump patch|minor|major --yes` | 已有线上版本，按 latest 自动计算新版本号。 | 与上条相同；不能和 `--version` 同用。 |
| `update-version --reuse-version <已发号> ...` | 工作稿的底不是当前 latest，且明确以该已发号为底提交。 | 只改变本次提交认可的底；工作稿来源必须匹配。 |
| `update-version --reset ...` | 当前更新稿确认不要了，要丢掉并按本次指定底重新拉取后继续。 | 会立即删除现有工作稿，再继续更新流程；后续失败不会恢复旧稿。 |

首版只能使用 `create-version`，已有版本只能使用 `update-version`。`--artifact` 在发行命令中是本次上传的真实文件/构建目录；普通资源必须是文件，主题/插件必须是非空构建目录。不要把 `version draft description` 与 `version description` 混用：前者改未提交更新稿，后者改已发布版本。

属性、配置和依赖的子命令都以工作稿为目标。没有工作稿时，已有线上版本先 `version draft pull`；首版要先 `create-version --prepare`。依赖在非交互模式还须明确 `--policy-id <策略ID> --yes`，CLI 不会代选对方策略。

## 展示信息、策略与上下架

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `update [--title] [--intro] [--cover] [--tags] --yes` | 只修改资源展示信息。 | 更新线上 listing；不发版、不改标识、不上下架。 |
| `policy list` | 查看当前资源的授权策略。 | 只读。 |
| `policy template list [--page <n> --page-size <n>]` | 查看当前资源类型可套用的策略模板。 | 只读。 |
| `policy template apply [templateId] [--name]` | 套用一条平台模板并启用。交互可选择；脚本必须给 `<templateId> --yes`。 | 新增并启用一条策略；不付款、不上架。 |
| `policy apply --from-file <路径> [--name] --yes` | 从策略文本或 JSON 文件新增策略。 | 新增并启用一条策略；策略语义由平台校验。 |
| `policy set --id <策略ID> --on|--off` | 启用或停用某条策略。 | 更新线上策略状态；已上架资源不能停用到零条启用策略。 |
| `validate --for online` | 上架前预检版本和策略条件。 | 只读。 |
| `online` | 资源有已发版本和至少一条启用策略后上架。 | 更新线上可用状态。 |
| `offline` | 暂停线上可用状态。 | 只下架，不删除版本、策略、资源或本地文件。 |

## 脚本最小安全模板

脚本必须显式选择环境；工程有多份状态时也必须显式选择资源。先做只读检查，再执行写操作：

```powershell
freelog-cli status --cwd <工程> --resource file:2.json --env dev
freelog-cli version show --cwd <工程> --resource file:2.json --env dev
freelog-cli update-version --cwd <工程> --resource file:2.json --bump patch --yes --env dev
```

需要机器可读错误时追加 `--json`。不要在脚本中用 `title:<标题>` 作为唯一选择器，也不要依赖交互式选择。
