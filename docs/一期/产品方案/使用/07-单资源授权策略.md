# 单资源：添加和管理授权策略

本页操作自己单资源对外提供的策略，主题、插件、图片等使用同一流程；合集自身策略见[合集授权策略](./合集/03-合集授权策略.md)。这不是依赖签约，不创建版本、不上架、不付款。

前置条件：在工程中登录正确 dev 账号，已 create 或 bind 到自己的线上资源。本页使用明确资源 ID；不在工程根时另加 `--cwd <工程目录>`。人工交互与 AI/脚本是两条替代路径，不要混作一份连续脚本。

## 人工：从模板列表完成添加

```powershell
freelog-cli policy template list --resource id:<资源ID> --env dev
```

交互终端每页 20 个模板，可以选择上一页、下一页或退出。选模板后按顺序完成：

1. 阅读完整策略说明，核对标出的 `[1]`、`[2]` 等参数位置。
2. 设置策略名称，选择需要修改的参数，填写或恢复默认值；默认值也应符合自己的授权意图。
3. 选择“预览并创建”。CLI 重新读取模板、校验参数，调用平台编译和翻译，展示译文与最终参数。
4. 确认译文正确后创建。取消或预览失败不添加策略。

| 参数类型 | 输入方式 |
|---|---|
| number | 有限数字，遵守模板的下限和小数位规则。 |
| select | 从模板提供的选项中选择。 |
| datetime | `YYYY-MM-DD HH:mm`，例如 `2026-12-01 09:00`。 |

缺少可用默认值的参数必须填写；策略名 2–20 字符，不能与现有策略重名。创建成功后读回：

```powershell
freelog-cli policy list --resource id:<资源ID> --env dev
```

确认策略 ID、名称和启用状态符合预期。策略默认启用；列表一次展示该资源全部已添加策略，不分页，不是模板列表。它不展示策略正文或参数：正文在创建前的译文预览中核对，创建后需要查看完整线上内容时到浏览器端确认。

已经知道模板 ID 时，可以先只读查看：

```powershell
freelog-cli policy template info <模板ID> --resource id:<资源ID> --env dev
```

再进入同样的交互编辑：

```powershell
freelog-cli policy template apply <模板ID> --resource id:<资源ID> --env dev
```

不必为了从列表添加而先调用 info。

## AI 或脚本添加策略

这条路径适用于**授权需求已经由人确定**的情况。AI 可以匹配模板和填写数据，但不能自行决定收费、期限、可授权范围等商业规则，也不能只选第一个模板或直接信任默认值。

### 1. 查询完整模板目录

```powershell
freelog-cli policy template list --json --resource id:<资源ID> --env dev
```

JSON 一次包含当前单资源可见的全部模板，不分页、不创建。输出含模板 ID、完整说明、fingerprint、参数 slot、类型、默认值或必填标记、校验规则与选项 value。

根据已确定的需求选择能表达该规则的模板。无法匹配、金额/期限等需求不明确时停止并补充需求，不猜参数。需要核对选定模板的最新信息时再查询：

```powershell
freelog-cli policy template info <模板ID> --json --resource id:<资源ID> --env dev
```

### 2. 确定全部参数，再提交

每个 slot 都要显式提供值，**包括有默认值的参数**。选项传 value，不传展示用 label；时间使用上述格式。同一参数在全文中重复出现仍是一个 slot。

fingerprint 校验的是查看时的模板结构，不承诺冻结所有后端编译语义；参数编号只对当前模板指纹有效。先核对整份模板和参数，再执行写操作。假设当前模板有两个参数，命令形状如下：

```powershell
freelog-cli policy template apply <模板ID> `
  --template-fingerprint <当前JSON中的fingerprint> `
  --name "我的授权策略" `
  --param "1=<第一个参数值>" `
  --param "2=<第二个参数值>" `
  --resource id:<资源ID> --env dev --yes
```

占位符必须替换；参数数量按实际清单调整，零参数模板不传 --param。非交互执行或显式传指纹/参数时，名称、指纹、全部参数和 --yes 都必需；仅模板 ID 加 --yes 不会自动补参数。

**这是直接写入命令，没有等待人工确认译文的停顿，也没有 dry-run。**它会校验、编译、翻译再创建；若希望人查看最终译文后确认，请改用上面的人工路径，不把脚本路径当作只读预览。

### 3. 读回确认

```powershell
freelog-cli policy list --resource id:<资源ID> --env dev
```

看到正确的新策略及启用状态才完成。指纹变化、缺参数或参数不合法时重新查询并修正；重名、正文重复或结果未知时先查询，不盲目重复创建。本流程不需要本地策略 JSON，--json 是查询输出，不是本地提交文件协议。

## 启停已有策略

停用指定策略：

```powershell
freelog-cli policy set --id <策略ID> --off --resource id:<资源ID> --env dev
```

需要重新启用时再执行：

```powershell
freelog-cli policy set --id <策略ID> --on --resource id:<资源ID> --env dev
```

两者不是连续步骤。脚本可加 --yes；只改变启用状态，不删除策略、不签约、不付款。已上架资源不能停用最后一条启用策略。操作后用 policy list 核对结果；资源上下架见[资源管理](./08-资源管理.md)。

## 模板范围与失败边界

当前接口拉全部模板后由 CLI 过滤 `compileType: normal`，不是请求参数；不按免费/付费筛选，暂不按资源叶子类型缩小请求。模板出现不保证最终编译或创建可被平台接受，平台拒绝时如实报错，不猜改业务语义。

info 展示的脚本骨架不会自动补工程、环境和资源选择，复制后需补齐。创建或启停结果未知时先 policy list 核实；不要套用版本的 resource recover。没有合适模板时不提交。当前不处理支付、结算账户，也没有手写策略 JSON 或策略语言提交入口。
