## 方案裁决规则

1. 业务规则以 **[03-Console 业务流程字段接口](../核心设计层/03-Console 业务流程字段接口.md#4-f2-单资源创建流程)** 为准。
2. CLI 交互和本地体验以 **[05-CLI 流程与命令设计](../核心设计层/05-CLI 流程与命令设计.md)** 为准。
3. 异常、恢复和验收以 **[06-场景异常与验收方案](../核心设计层/06-场景异常与验收方案.md)** 为准。
4. 实现分层以 **[07-实现解决方案](../核心设计层/07-实现解决方案.md)** 为准。
5. 接续上下文以 **[Y-项目上下文与接续记录](../补充说明/Y-项目上下文与接续记录.md)** 为准，但它不裁决产品规则。
6. 归档目录只保留历史材料，不参与新实现裁决。
7. **首次查阅必读**：[00-产品方案总纲与导航](../核心设计层/00-产品方案总纲与导航.md) → **包含角色化学习路径和 F→文档速查表**

## 禁止状态

- 禁止代码里存在产品方案没有定义的业务流程。
- 禁止用“按 Console 处理”“以接口为准”替代具体字段规则。
- 禁止只写接口名，不写调用时机、输入来源、成功状态和失败恢复。
- 禁止把旧实现中的交互当成新设计依据。
- 禁止因为 CLI 是终端就牺牲用户体验；CLI 必须提供可探索、可恢复、可脚本化、适合 AI 使用的流程。
