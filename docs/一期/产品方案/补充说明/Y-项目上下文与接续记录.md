| 文件 | 状态 | 用途 |

1. 新会话需要真实 dev 测试时，从本机私有文件读取，或让用户在当前会话重新提供。
2. 不把账号、密码、会话凭据、Cookie、Authorization 值写入 `docs/`、`README`、测试快照或报告正文。
3. 真实测试报告只能记录脱敏后的环境、场景、资源 ID、结果和错误码。
4. 如果必须临时展示凭据存在性，只写“已配置/未配置”，不写明文值。

## 5. 已明确的核心设计结论

1. 设计是源头，代码只能实现设计；代码里不能出现产品方案没有定义的业务流程、字段或错误语义。
2. Console 对齐重点是业务流程、字段约束、接口调用、创建/更新流程和禁用条件，不是复制 UI。
3. CLI 自身体验必须独立设计：一次命令进入连续会话、可探索、可恢复、可脚本化、适合 AI/CI。
4. 资源类型选择必须支持逐级浏览，搜索只是加速。
5. 策略默认必须先看模板、选模板、填参数、编译、翻译、保存；手写策略只属于高级/迁移场景。
6. 模板/脚手架是 CLI 原生产品能力，可以独立创建本地工程，也可以在发布流程中作为内容来源。
7. 独立压缩/打包是 CLI 原生产品能力，可以单独生成 artifact，不上传、不写平台，也可以被发布流程调用。
8. 选中主题/插件资源类型后，必须允许选择“从模板创建、使用现有工程、使用已有构建目录、使用已有压缩包/artifact”。
9. 主题/插件资源发行仍按资源发行流程走；节点主题激活、支付、签约属于 Console 接力。
10. RSS 和 collect-rules 是两个独立能力，不能混成一个功能。
11. 批量不是黑盒调用，必须分批、逐项结果、报告和恢复。

## 6. 已确认的 Console 业务事实

| 领域 | 已确认事实 |
|---|---|
| 资源类型 | 类型来自平台类型树；普通资源、合集、主题/插件、批量都不能写死类型全集 |
| 标题 | 资源标题必填，Console 输入限制为 100 字符 |
| 授权标识 | 输入部分限制为 60 字符，非法字符规范化，创建后不可改 |
| 版本号 | 首版为 `1.0.0`；新版本使用 semver，必须大于当前最新版本 |
| 版本描述 | Console 保存富文本 HTML；空编辑器保存为空字符串；RSS 相关资源/合集禁用描述编辑 |
| 依赖版本范围 | 使用 semver range，并要求至少命中依赖的一个已有版本 |
| 封面 | 默认支持 JPEG/PNG/GIF，最大 5MB，通过上传接口得到 URL |
| 简介 | listing 简介限制为 200 字符 |
| 标签 | 最多 20 个，单个最多 20 字符，去 `#`，去重 |
| RSS | `matchedItemCount > 1000` 时必须日期筛选；验证码错误保留 feed 和预览；RSS 绑定后标题、封面、简介锁定，tags 仍可维护 |
| collect-rules | 规则包含启用状态、序列化状态、条件关系、条件字段、操作符和值；保存前必须有人类可读摘要 |
| 合集条目标题 | 一期只确认条目标题草稿维护；它不是资源全局标题 |
| 主题激活 | Console 节点主题页涉及展品创建和上线；CLI 一期作为接力，不伪装闭环 |

## 9. 下一步接续建议

如果继续做产品方案：

1. 先从 [04-CLI流程与命令设计.md](./04-CLI流程与命令设计.md) 逐条模拟真实用户操作。
2. 再用 [05-场景异常与验收方案.md](./05-场景异常与验收方案.md) 反查是否漏掉异常。
3. 发现流程或字段缺口时，先改 00-06，再改代码。

如果开始代码实现：

1. 先比对现有 CLI 代码是否具备 06 所需分层和状态机。
2. 先实现 field registry、workflow event、artifact 准备状态机，而不是先写零散命令。
3. 先让模板创建和独立压缩能单独验收，再接入发布流程。
4. 每个写平台能力都必须有 checkpoint、脱敏报告和恢复策略。
5. dev 真实测试必须使用本机私有凭据，报告脱敏。
