# 单工程多份独立单资源重构清单

最后更新：2026-09-10。
说明：名称中的“单资源”表示每份状态只对应一个平台资源，并不表示一个工程只能有一份状态。产品规则以 [脚手架设计](./脚手架设计/README.md) 为准；本清单只追踪实现和验收。

状态含义：`[x]` 已有设计、代码和针对性自动化证据；`[~]` 已部分完成或待最终全量/dev 验收；`[ ]` 未完成。

## A. 不变量和公开接口

- [x] 一个工程能管理多份独立资源；普通单资源操作按 `--resource` 或零/一/多规则确定一份。
- [x] `N.json` 是永久身份与产物锚点，`N.version.json` 是唯一未提交工作稿；平台保存版本历史。
- [x] 身份只用 `id:`、完整 `name:`、`artifact:`、`file:N.json`；标题仅展示/显式同步，不能选择身份。
- [x] `--resource` 只选身份，`--artifact` 只给产物；公开命令没有 `--file`。
- [x] `N.json` 是身份集合唯一主本；不读取、重建或自动删除遗留 `index.json`。
- [x] 普通资源只接受文件；主题/插件只在目录发版时由 CLI 临时压缩，显式文件（含 zip）直传。

## B. 本地状态、选择和路径

- [x] 已绑定身份缓存完整 `resourceName`；不再将短名或标题模糊匹配为身份。
- [x] `.sequence` 保证编号在工程内单调不复用。
- [x] 产物路径只相对最终工程根解析，拒绝工程外、`.freelog`、软链接逃逸、重复真实路径和目录嵌套。
- [x] 事务恢复先于正常业务校验；新事务仅允许 `.freelog` 白名单相对文件。旧事务的 `index.json` 条目仅为恢复兼容。
- [x] `resource list` 在坏状态下只读诊断；正常业务命令采用保守的全量冲突阻断。

## C. 生命周期：init、create、bind

- [x] 新/已有普通资源均需明确关联现存工程内文件；主题/插件关联文件或构建目录。
- [x] 模板 init 创建 `dist/` 锚点但不渲染、不安装依赖、不写模板元数据；主题/插件类型固定。
- [x] create/bind 仅在显式选择或 artifact 与未绑定状态精确一致时接续；其它新产物新建状态。
- [x] create/bind 写盘前验证锚点；bind 写入前核验单资源主体、ID 和当前 owner。
- [x] create 查重、bind 和已有资源写门禁兼容 `userId` / `ownerId` / `creatorId`。
- [~] 首个普通文件、同目录第二文件、主题/插件已有工程、bind 后更新等组合尚待本轮全量 CLI/dev 复验。

## D. 版本、工作稿和产物

- [x] `create-version` 只提交首版 `1.0.0`；`update-version` 只提交已有资源的新版本，两者不互相改口。
- [x] reset、discard、pull 的有损路径在确定性预检和确认后才影响选中工作稿。
- [x] 文件 SHA 流式计算，上传使用 Blob；上传/分析前后发现源文件变化即停止，不用旧 SHA。
- [x] 主题/插件目录 zip 稳定排序、拒绝软链接/非正常条目并清理临时包。
- [x] 文件重分析后的系统附加值保留在待复核项；`version attr review` 支持逐项查看与 discard。
- [~] 显式文件大小上限、取消协议和大规模目录性能边界尚未形成已批准设计。

## E. 管理、策略、依赖和上下架

- [x] listing 的 title/intro/tags 有未传、清空、设置三值；封面路径先本地校验上传，平台只收 URL。
- [x] 策略模板按当前资源类型显示全部适用项，支持稳定分页；不按免费/付费过滤。
- [x] 依赖未授权时显示对方全部启用策略；脚本必须传当前列表中的 `--policy-id`，不会自动签“第一条”。
- [x] 所有现有资源写入口在写前重查精确 resourceId、环境、owner 与冻结；`validate --for online` 使用与 `online` 相同门禁。
- [~] 多资源的新增、精确/批量标题同步与连续 bind 已有 dev 证据；实际 TTY 选择因本机缺 `expect` 暂未端到端验证（包内单测已覆盖选择路由）。

## F. 中断和结果未知

- [x] 版本 POST 前写 `.pending-operation.json`；未知结果保留未决记录和工作稿，阻断新业务写。
- [x] `resource recover [--apply --yes]` 只核验版本号和文件 SHA；ID/owner 不符或无法证明时不清理、不重发。冻结不阻断只读 SHA 核验。
- [~] create、listing、策略、上下架和依赖签约尚无同等 pending/recover 闭环。扩展前必须先证明平台有可靠的操作关联或用户确认模型；不得凭目标最终状态假装可以无歧义恢复。

## G. 文档、打包与最终验收

- [x] 正式 ARCHITECTURE、相关 PHASE、COMMANDS、使用手册、真实场景、开发说明、问题记录和交接文档已同步本轮主要取舍。
- [x] 已扫描非归档文档；`index.json`、`--file`、`artifactMode`、标题选择器和“仅免费模板”只作为废弃/禁止/历史说明出现，不再写成现行规则。
- [x] 最新修改后已运行完整 `test`（30 files / 162 tests）、`typecheck`、`build`、`verify:package`、`git diff --check`，并检查发布包 docs 与真实 CLI help。
- [~] 用户授权的 dev 已验证普通文件、主题目录和预制 zip、插件预制 zip、已有本地工程、bind/换绑、多资源同目录、字段与工作稿边界、资源池依赖；实际 TTY 缺 `expect` 跳过，版本 POST 未知结果仅有可控单测证据。测试资源按脚本下架或保留未发布审计壳。

## 完成门槛

只有 G 的最后两项完成，并且 F 的未覆盖范围被明确接受或实现为可证明闭环，才能将本轮治理标记为完成。历史绿测、历史 dev 报告或单个领域测试都不能替代这一门槛。
