### **B. API 错误码速查表**

```typescript
// 字段验证错误
FIELD_REQUIRED        → 必填字段缺失
TITLE_EXCEEDS_LIMIT   → 标题长度超限 (max=100)
AUTH_ID_EXISTS        → 授权标识已存在  
SEMVER_INVALID        → 版本号格式非法
VERSION_NOT_INCREMENTAL → 版本号未递增

// API 调用错误
NETWORK_ERROR         → 网络连接失败
API_TIMEOUT           → API 响应超时
RESOURCE_FROZEN       → 资源处于冻结状态

// Checkpoint 错误
ACCOUNT_MISMATCH      → 账号不一致
CHECKPOINT_EXPIRED    → checkpoint 过期 (>7 天)

// RSS 专属错误
FEED_INVALID          → Feed 源无效
GUID_CONFLICT         → GUID 重复
CAPTCHA_EXHAUSTED     → 验证码次数耗尽 (max=3)

// 策略模板错误
POLICY_COMPILE_FAILED → 策略编译失败
MISSING_REQUIRED_PARAM → 缺少必填参数
```

## 📊 **四、角色化学习路径**

### **PM (产品经理)**
```
00 方案总纲 (5min) 
→ 01 需求分析 (10min)
→ 02 业务流程浏览 (30min,F1-F11流程图)
→ 04 命令体系 (15min)
```

### **后端开发**
```
接收任务 → 确定 F 编号
→ 02 文档对应章节 (核心业务契约)
→ 对应实现规格文档 (如有独立成文则优先)
→ CLI 实现规格说明书 (全局规范)
→ 按步骤逐行实现代码
→ 参考 05 文档编写测试用例
```

### **QA 测试工程师**
```
05 场景异常与验收方案 (全部 S01-S21)
→ 02 文档字段约束验证规则
→ 各实现规格的验收测试章节
→ 编写端到端测试脚本
```

## 🔧 **五、开发实施检查清单**

### **新功能开发 Checklist**

- [ ] 确定功能的 F 流程编号 (查看第二章对照表)
- [ ] 在 02 文档中找到对应的字段账本
- [ ] 确认每个字段的约束强度 (HARD/DYNAMIC/SERVER_FALLBACK/SOFT)
- [ ] 查阅对应实现规格文档 (策略模板→封面→RSS→批量)
- [ ] 检查字段验证规则是否与 02 文档一致
- [ ] 检查错误码是否使用标准定义 (参考第三章 B 节)
- [ ] 检查 Checkpoint 保存点是否覆盖 BEFORE_REMOTE_WRITE(参考第三章 C 节)
- [ ] TTY 提示文案符合色彩规范 (✅绿色/✗红色/⚠️黄色/ℹ️蓝色)
- [ ] 编写至少 5 个测试用例 (来自 05 文档或自创)
- [ ] 提交代码前运行完整测试套件

### **文档维护 Checklist**

- [ ] 新增字段必须在 02 文档中定义 FORM-XXX 编号
- [ ] 新增业务规则必须标注 P0/P1/P2 优先级
- [ ] 新增实现细节必须引用相关文档链接
- [ ] 修改字段约束必须同步更新所有引用文档
- [ ] 新增测试用例必须加入 05 文档的测试矩阵
