# 研发与发布质量契约

状态：规范与门禁已建立，产品全量验收仍有阻断项。2026-10-15 建立，2026-10-16 复核；适用于人和 AI 的设计、开发、测试、验收、npm 发布与 Git 收尾。本文约束交付过程，不替代产品设计。任何“完成”必须有相应证据，不能从测试数量推导功能覆盖率。

## 1. 真源与边界

- 当前产品：`docs/一期/产品方案/脚手架设计/`；字段约束以业务梳理的字段级校验对照表为准。Console 实际代码与真实接口样本用于核对平台行为，注释不是接口契约。冲突先记录和裁决、修改正式设计，再实现。
- `DESIGN.md` 仅指向现行契约，不保留历史 session、studio、批量等设想为当前承诺。运行时协同、下一代策略语言仍为独立讨论，不自动扩大已实现能力。
- 交接文档记录事实；使用文档教用户操作；测试计划定义覆盖；报告只证明一次运行，不能成为第二份产品规格。
- 活动交接只保留一套当前目标/非目标、实际状态、未决操作、覆盖缺口和下一步；规范细则用链接引用。日期流水与已废止操作放独立历史页，明确非操作依据，不在活动页留下多个“当前任务”。测试保护入口、唯一结构、相对链接及缺口集合，不假称自动理解全部语义。
- 无旧代码兼容负担不等于允许静默改变业务语义。可以删旧层或重构，但必须先锁定应保留的行为和数据边界。
- 本机真实 dev 测试只用获授权的 primary 账号，新建隔离资源；资源池默认只读。禁止测试支付、自动签约、prod 写入和删除用户资源。

### Console 与 tools-lib 的核对及同步

请求流程同时核对 Console 实际调用代码、其同仓 `packages/@freelog/tools-lib/src` 与 CLI 的 `packages/tools-lib/src`，浏览器用于验证实际表现，不能替代代码链；注释、包版本号或文件时间不能证明接口一致。记录本次上游提交及具体差异，区分上游新方法/参数、CLI 已验证扩展与 Node/browser 适配，不能整目录覆盖。

上游新增的公共请求方法和参数须在本库同步并有精确方法/路径/参数/请求体与类型回归；Node 适配（鉴权、流、二进制、惰性国际化、无浏览器全局）保留。共享国际化变化还须验证有缓存刷新、失败保留、通知/取消订阅及 browser 富文本/Node纯文本边界；从真正公开入口核验，browser必须先安装平台适配再构造实例，不以未接入的内部模块通过代替公开能力。SDK能力同步不等于开放相应CLI业务，尤其不自动启用RSS、支付或签约；实际业务语义冲突先回到正式规则与真实响应裁决，不因上游注释更新改变CLI行为。

### 用户与 AI 的责任边界

用户参与验证产品设计是否符合业务意图，与 AI 讨论正常/异常场景和规则；不承担通读代码、发现技术遗漏或检查测试脚本是否可靠的职责。AI 必须主动补充场景、揭示歧义，不能把需求不完整的责任全部推给用户。

设计经用户确认后，影响分析、用例设计、代码实现、回归测试、独立复核、真实环境与安装包验证、授权后的发布及收尾由 AI 负责完成。常规技术步骤不逐项交用户审批，也不以“用户没有指出”为实现或漏测免责。用户确认设计不等于确认实现正确、测试充分或批准发布，更不表示当前全部历史设计已经获得确认。

每次落实都要标明本次确认的设计条目及讨论依据，将业务规则对应到可观察预期、用例与执行证据；涉及共享模块时主动核对其它消费者，不等用户逐个提问。独立验收从设计和平台事实推导预期，不从实现反推正确答案。发现实现偏离已确认设计时，先按交付缺陷修复并补回归，不能倒改设计、快照或断言迁就错误实现。

仅在业务歧义、需要改变已确认设计或缺少必要授权/外部条件时回到用户，提供具体证据、影响及建议；停止受影响链路，不猜测规则继续写入。认证、支付、prod、破坏性操作和发布仍受原有授权边界约束，“后续交给 AI”不扩大这些权限。

用户收到的交付摘要应能直接回答：符合哪些设计、实际验证了哪些结果、还有哪些缺口及是否阻断交付/发布。详细代码、日志和逐项证据由 AI 维护，不能要求用户阅读它们才能判断当前状态。AI 对工程验证与如实报告负责，但不以“独立审查”或测试数量承诺零缺陷。

以上是执行责任，不是完整机器能力声明。候选级门禁已开始约束9项已登记目录义务的设计映射和本次审查记录；完整的字段/场景逐项追溯仍未形成，7 项产品验收缺口也未消失。补齐这些工程能力由 AI 承担，不转交用户维护或用一条笼统的“设计已确认”代替。

## 2. 每项变更的交付顺序

| 阶段 | 必须产出 | 通过条件 |
|---|---|---|
| 设计 | 问题证据、目标/非目标、正常/异常流程、字段与状态约束 | 歧义已解决；接口依据明确；先更新受影响正式设计 |
| 影响分析 | 命令、资源类型、共享模块、本地/线上状态、使用文档、安装包 | 不能只看被修改函数；共用入口和跨端消费者都列出 |
| 测试设计 | 用例 ID、前置、动作、精确预期、副作用与清理 | 每个功能和有差异的参数等价类有用例；未知项明确 NOT_TESTED/BLOCKED |
| 开发 | 小而完整的切片、必要注释、故障回归 | 修缺陷先证明旧实现失败；注释解释规则/边界，不复述代码 |
| 本地验证 | 自动化测试、类型/构建、架构/命令/文档/安全检查 | 空测试、错误 workspace filter、未知脚本、缺失用例不算通过 |
| 独立复核 | 业务/代码和架构两条复核意见 | 作者不能自称独立通过；不可用时明确记录，不能冒充 APPROVE |
| 候选包验收 | 固定 tarball、源码摘要、包摘要、隔离安装、dev 报告 | 执行安装包而非 workspace dist；全程绑定同一候选；覆盖缺口不消失 |
| 发布与收尾 | 浏览器认证、同一 tarball、registry 核验、提交/tag/推送 | 用户给版本才发布；不自动改版本/重复 publish；Git 与包版本实现可追溯 |

使用[变更记录模板](./变更记录模板.md)记录任务；普通小改可直接在任务报告使用同一字段，不为每次修改制造多份长文档。

风险分层：纯文档/注释做链接与打包检查；独立本地命令做定向回归及错误/取消分支；涉及身份、认证、共享表单、协议、发行/恢复或两类主体的改动做完整影响分析及跨链回归。准备发布始终验证固定候选，不能因上次通过省略。独立双路复核用于高风险变更和发布，不要求每个错别字启动两名审阅者。

## 3. 测试必须证明什么

1. 清单来自批准的命令和场景，而不是从当前实现生成正确答案。命令树可用于发现差异，但修改快照不等于批准新行为。
2. 覆盖对象分开：普通文件、主题、插件、合集；生命周期分开：全新、本地已有、bind、首版、更新、管理；输入分开：缺失、空串、零、边界、未知值、重复/冲突。组合以业务差异和独立性为依据，不盲目做全部笛卡尔积。
3. 版本表单必须在同一条真实链同时包含系统附加值、自定义属性、文本/下拉可选配置、依赖及说明；精确读回字段、类型、值及继承，不能用关键词出现代替。
4. 断言包含退出码、错误码、完整 JSON、本地应变/不应变和线上应变/不应变。命令执行完成不是业务通过；失败不登记、丢弃结果、无条件记成功都是测试缺陷。
5. 取消、重复执行、缺权限、冻结、环境错误、错误响应结构、超时和未知结果分别覆盖。故障注入在可控装置实施，不为造错破坏真实用户请求。
6. CLI 与 Console 共享数据时必须安排双向往返验收。未做浏览器验证就写 NOT_TESTED；API 结构正确不能替代 UI 回显证明。
7. 同一错误假设不能同时作为实现与模拟数据的真源。保留脱敏真实响应结构；写接口 DTO 不冒充读接口 DTO；后端变化需重新核对样本。
8. Windows/macOS/Linux、Node 最低支持版本和主要开发版本分开记录。本机通过不代表 CI 已运行；无样本的分页不代表真网已验。

测试替身先记录调用、参数和观察，再在被测调用之外断言；不要把断言异常放进被测catch会包装为“结果未知/预期失败”的回调中，否则错误断言也可能被当成成功反例。若必须在回调中断言，须证明该异常不会被被测代码吞并。红回归必须对应目标缺陷，而不是类型装置错误或级联失败。

禁止让断言差异展开宿主`process.env`、真实凭据或完整HTTP配置；只比较布尔/安全投影并给固定消息，反例预先使用合成值。真实PTY子进程必须能显式传入筛过的隔离env，超时/输出上限先锁定失败再终止，不能被终止时的同步exit0回调救成PASS。完整原始终端保留但有固定上限，截断只能FAIL；物理TTY能力和实际按键行为分别验证。

PTY收到正常onExit后只释放订阅，不再调用kill/destroy终止已退出的会话；node-pty的destroy并非纯订阅清理。超时、输出越限或启动回调故障时先锁定失败，再至多一次kill；同一会话不能destroy后再kill。原生宿主崩溃保留独立装置失败，不记作业务PASS或靠重复运行掩盖。

离线装置必须在全新、尚未构建的检出上成立，不依赖操作者遗留的dist、全局Git配置或其它测试的产物。针对“文件存在但不是安装包入口”的用例，自建存在的非安装入口；入口缺失另测，不合并错误类别。源码提取/内存变异测试要覆盖LF与CRLF并确认命中目标，不把换行差异当成业务反例。此类测试允许在解析副本中统一换行，不改变源码指纹、原始证据或发行内容的字节核验。隔离Git装置须明确所需配置并覆盖平台环境差异，不为凑绿放宽生产的固定源码门禁。

浏览器证据不能由操作人手工重建`visible/readings/observedAt/axSnapshot`。当前Console切片使用源码固定的只读采集器：在实际浏览器调用中自动记录每帧起止时间、完整AX原返回和必要控件的实际value/text及元素种类；不接受调用方覆盖这些值。只将工具完整输出原样归档，截断或不完整时停止，不补写旧快照。验收器按固定页面/弹窗profile从原始帧推导字段及其来源；字段值碰巧相同但页面、控件label/key、读取方式或来源不符仍拒绝。分类或默认首项等推导明确标为有限变换并保留输入，不伪装直接读取。该结构不认证工具操作者、也不能识别恶意伪造整份数据；仍需实际工具正控及独立复核。旧手组capture不迁移成新证据，任一前缀无效均不得发出后继网页写请求。

原始帧的解析先确认唯一、有序的区块边界，再消费区块内的完整内容；不能先丢弃节点再声明来源。固定profile必须拒绝未覆盖的属性、配置卡片、重复区块和非文本描述节点；值出现在其它区块不算该字段的回显。空描述按实际编辑器种类同时核对text/value为空，不忽略非空value。原始数据可使用标准无损压缩传递，解压后核对完整字节长度和摘要；这只验证复制完整性，不认证采集者。

### 本地测试的凭据边界

CLI Vitest 用例每项使用新建的内存凭据库；测试可显式注入缺失/故障替身，但不得访问宿主的系统凭据库。临时 cwd/home 只隔离文件，不能隔离 Windows Credential Manager、macOS Keychain 或 Linux Secret Service。统一 setup 必须在加载生产适配器前替换原生 keyring 入口并拒绝访问；漏注入、重置模块或恢复默认 store 时也只能受控失败，不能落回真实凭据库。

回归须证明：假登录可在内存读回、同一 key 不跨用例保留、原生 get/set/delete 全部拒绝、恢复默认 store 或重新加载模块不触及原生库。既有注入故障与错误码测试继续保留。此隔离仅限 Vitest 进程，不宣称保护另起的 CLI 子进程；安装包/TTY/dev 测试仍遵守各自的环境、账号与网络边界。禁止读取或清除未知宿主条目来“清理”历史测试。

## 4. 结果协议与证据有效期

- 状态只有 PASS、FAIL、BLOCKED、NOT_TESTED。没有输出、进程 signal/error/超时、未知 case、重复 case、缺失 case、错误报告、空清单均不得成为完整 PASS。
- 脚本级结果与业务 case 分开。旧脚本 exit 0 只证明该脚本正常完成，不能替代尚未实现的命令参数、版本更新、资源管理与跨端专项。
- 未调度的旧脚本可以记录为NOT_TESTED、空断言、明确原因且无process，不能为满足结构校验伪造一次进程。若提供process仍须完整合法；PASS/FAIL/BLOCKED不能借此省略进程证据。此分支只让验证器继续核对其它真实PASS的原始证据，不消除任何必需未测项或允许发布。
- 后端模板失败须保留为具体失败/阻塞项，不能通过换两个成功样本覆盖。BLOCKED 必须给出实际原因与补测条件，不能靠匹配一段 DSL 文本猜测责任。
- 每份候选记录源码内容摘要、锁文件/测试/设计摘要、版本、tarball SHA-512、安装后 bin、平台/Node、开始/结束时间。源码、测试、规格或 tarball 改变则证据失效；发布前再次校验，默认最长有效期 24 小时。
- 必需用例 FAIL、BLOCKED、NOT_TESTED 都阻止标准发布。不得设置“忽略全部失败”开关；若决定缩小产品范围，先明确修改范围与设计，不以修改测试预期掩盖缺陷。
- 当前完整覆盖尚未建立，必须让发布门禁如实拒绝，而不是创建空脚本补齐名字。已接入 14 条回归的历史 PASS 不是新门禁的授权。

### 业务验收的统一最低要求

验收目录仅区分 `legacy-suite`（过程完成）与 `product-case`（业务事实）。`gap` 只表示业务项尚未实现，不产生弱于其它业务项的验证分类。目录先校验唯一ID、非空唯一断言、required布尔、合法kind及生产者；没有gap的业务项必须有注册且真实存在的普通生产者文件，路径越界/软链接/未知kind均拒绝。

每个业务PASS都需要完整成功断言及精确expected/actual、候选本轮run绑定的原始证据文件与字节摘要，不能只填布尔。消除gap的迁移回归必须证明缺生产者、缺精确结果和缺原始证据仍分别拒绝；合法正例只在装置测试里验证校验器，不构成真实验收。生产者由目录稳定去重调度；一个生产者多case时逐项核对完整集合，不能少报、重复、报别人的case或用过程exit 0补业务PASS。

登记生产者及匹配原始文件摘要只证明来源绑定，不等于已经核验业务语义。新增业务ID还必须接入源码固定的语义核验分支；未登记的ID即使自填expected/actual并保存匹配raw，也不能PASS。消除gap不得绕过此要求，验证装置须同时保留已登记叶子的合法正例及未登记ID的精确拒绝反例。

共享Console生产者的独立类型可能一条成功、一条失败：仅当该已登记生产者正常完成、完整结果通过结构校验，并在末尾写出同run/producer的完成信封，且派生退出码（有FAIL为1，其它非PASS为3，全部PASS为0）与实际进程一致时，允许分别保留case事实。生产者过程另记，不把整个进程的业务exit1挂成已成功case的命令失败。缺失/错信封、崩溃、signal、error、超时或退出码矛盾仍全部拒绝；不泛化放宽旧生产者。每个保留PASS仍须原始命令、文件和业务语义重核，信封不是独立业务证明。

七类专项后续必须拆成源码固定的逐规则/逐case清单，含设计依据、前置/动作/输入等价类、独立预期、禁止副作用、执行层次与生产者；rule到case是明确的多对多映射，不默认ID相同。完整字段/场景清单和真实生产者尚未完成，不能因本节定下规范而移除现有七项gap。

新增叶子不能仅自行填写expected/actual：最终协议按源码固定的叶子预期重新核算其run-bound原始observations，再与报告断言逐项比较。真实命令输出、网络守卫及状态快照不符时，不能把报告布尔改成true来放行；这仍不宣称能识别作者恶意伪造全部原始数据。

生命周期的必需成功步骤由源码固定命令、参数、顺序和成功退出语义，不能只认步骤标签，或由报告把成功改成“预期拒绝”。线上读回的派生DTO必须与对应真实命令stdout解析值完全一致；只把旧DTO放进 `versions`、同时忽略本轮失败/不同版本输出，不能成为PASS。动态隔离资源名允许每轮变化，但类型、产物、目标版本、环境和必需旗标不能任意替换。

## 5. 固定候选包与发布

本节新增的源码/远端契约处于本轮落实中，是否已实现须看当前目标记录，不因规范文字存在即称门禁完成。未来授权发布的标准链：固定源码经受保护路径进入可信远端 → 精确最终提交的必需CI → 本地质量检查/一次生成候选tarball/隔离安装 → 同包dev与跨平台验收、实际双路复核 → 重核来源/覆盖/时效/CI → 发布同一tarball → registry下载与安装核验 → tag指向固定源码提交并推送 → 后续审计/交接记录。

候选区分自动判定的 `purpose:development|release`，包含真实 `sourceRevision:{commit,tree,clean}`。无固定Git提交、有效输入未提交或非排除的源码未跟踪时，只能准备development候选供本地/dev取证，报告不得获得releaseEvidence或releaseApproved。release候选必须在最终源码提交上重新准备，模式/提交/树与内容摘要、包、bin共同贯穿验收、delivery及原始复核、check/publish。不是仅多填三个JSON字段；实际Git和有效输入须重核，换提交但内容相同也不能复用旧身份。

仓库根身份按文件系统原生规范路径比较：调用方根与Git报告的顶层目录须规范化到同一物理根，Windows盘符大小写别名不应丢失真实提交；不得用全量大小写折叠合并目录，也不得把仓库的子目录冒充独立根。此规范化只解决路径别名，不改变文件名、文件内容/模式、索引、提交/树或有效输入摘要的严格核验。无法确认同根仍只作development，不扩大Git信任或忽略失败。

PR合并/rebase以最终SHA为准，它改变即重新prepare。正式设计、测试和随包手册仍是输入，不整体排除docs。发布前先固定源码并经实际保护流程推送/批准，不能先npm后补源码提交；当前任务没有Git/npm写入授权。发布中/未知/Git未收尾事实先记候选排除目录的绑定回执，新会话检查真实未决记录。完成registry核验后tag只能指已验源码提交；后续审计和交接另提交，不能移动tag。Git失败只补Git，不重发npm；事实记录也不能冒充发布源码。

`pnpm verify` 是本地质量门禁，不执行账号测试或 npm 发布写入（隔离安装依赖可能访问 npm）。`pnpm release:prepare` 创建候选；`pnpm test:dev --candidate <candidate.json>` 验候选；`pnpm release:check --candidate <candidate.json>` 只读核验；`pnpm release --candidate <candidate.json>` 才是 npm 写入入口。实际参数以根 README 与脚本 help 为准，未验证的入口不得称已通过。

定向诊断可使用源码固定的`--scope collection-lifecycle`：只调度现有单资源生命周期原子生产者（主题/PNG/JPEG）及合集完整字段生产者，保持同候选/同run及全部原始前置核验。不接受任意脚本、用例列表或环境覆盖；实际执行必须绑定development候选，不能从workspace退回。`--plan`只读时可不带候选。此范围不依赖TTY，不能借本次诊断声明TTY通过；未调度义务仍为NOT_TESTED，目录和manifest保持完整。报告另存`acceptance.collection-lifecycle.<runId>.json`及对应summary，不覆盖完整acceptance.json。定向报告即使被复制到标准路径也不能成为完整发布批准；必须独立核验其中PASS的原始业务证据后，再明确拒绝其非完整scope。默认完整验收流程不变。

固定`--scope collection-recovery`只运行安装包合集恢复矩阵，沿用上述development候选/同run/完整目录和非完整scope拒绝规则，报告另存`acceptance.collection-recovery.<runId>.json`。它不需真实账号或TTY，SDK目标虽为dev，传输只到受控本机服务且原生凭据库已替换；因此只能证明安装包的受控故障恢复，不能登记为平台真实中断、Console或跨平台验收。普通full仍自动调度已注册生产者，不能以本范围替代其它必需项。

固定`--scope collection-items`只运行C03显式单品添加/授权查询的33场景安装包矩阵，同样无需真实私有输入或TTY，原始请求/响应、完整本地字节与精确远端副作用须经源码语义重算；报告另存`acceptance.collection-items.<runId>.json`。不以缺合同/未知结果反例向真实平台写入，也不把本机通过称真实dev、交互选择或完整合集管理通过。两个本机scope均不得探测真实凭据/资源池/可选配置文件，full/lifecycle前置不变。

固定`--scope collection-selection`调度`verify-collection-identity.mjs`的C01身份33场景和`verify-collection-selection.mjs`的C03选择12场景，不接受任意脚本选择。两生产者各自用隔离env探测原生PTY，不读取真实私有输入；分别重核能力探针、实际pid/退出/按键、SDK完整请求响应、本地字节和本机模型状态。C01包含非TTY精确错误、真实菜单和创建/bind副作用，C03保留原12场景。任一失败不借另一个PASS放行；缺PTY为BLOCKED，信号/超时/截断不能当取消。传输仅本机，不是实际dev、浏览器或跨平台验收，WindowsNode22不覆盖其它平台；scope报告始终不是完整发布依据，执行事实只在活动交接维护。

固定`--scope collection-edit`为必要的本机集成批次：运行C02目录编辑30场景及上述C03选择12场景，用同包同run验证共享items与生产者退出修复；不是任意脚本过滤器。无需/不得探测真实私有输入，传输与凭据隔离，生产者分别提供完整原始结果。报告按scope/run另存，不覆盖标准acceptance，不升级完整合集或跨平台批准；缺失或非正常退出仍FAIL/BLOCKED。源码及场景就绪后只prepare一次（含根），不因事实回填再重包。

区分诊断前置与发布批准：development候选准备及上述固定诊断不以候选级`delivery.json`为前置；候选级审查本就需要先有候选路径/包摘要，不能倒置为生成候选的条件。已有代码/安全发现仍须处理，准备时完整本地门禁不变；缺失正式审查继续阻止release:check/publish，不得借诊断输出补造批准。纯本机collection-recovery不得检查或读取真实dev凭据、资源池、可选配置私有文件作为前置；full与collection-lifecycle仍保留原有真实输入门禁。

直接从包目录执行 `npm publish` 必须拒绝；标准工具发布的是已验 tarball，不能在发布瞬间悄悄重建。人为 `--ignore-scripts` 等方式可以绕过本机 npm hook，因此本地门禁不宣称能对抗有发布权限者的故意绕过；当前不改变 npm 账号权限。

同一仓库的 registry/包名/版本共用一个持久发布占用记录，不按候选隔离。多个候选并发只能由一次原子创建取得写资格；超时或结果未知后，新建候选不能绕开旧记录再次发布。只有 registry 的精确完整性与候选一致时才允许只读下载、安装及核验恢复。共享记录保存在忽略目录 `.artifacts/publications/`，候选目录另存审计副本，不删除占用记录来重试。这个本地边界不声称能协调不同机器或独立 clone；团队发布还必须指定单一发布执行者。

固定`--scope collection-rules`只运行C05规则34场景，绑定development安装包，传输/凭据隔离且不探测真实私有输入，不需要TTY。读取、POST和手工目录拒绝均按正式测试§8.16核完整JSON、请求响应、全本地/home字节、模型前后和原始文件；不允许由相同读回值补造失败写成功。scope报告另存、不覆盖完整acceptance，未调度项保持NOT_TESTED；它不证明平台自动匹配、TTY取消、publish模式或完整C05。输入冻结后一次prepare（含根），事实回填不重包。

固定`--scope collection-publish-preflight`只运行C08的48个非TTY安装包场景，沿用development候选、禁止私有输入探测、同run原始证据及非完整scope拒绝规则。复核时变化由独立本机模型注入，不代表真实并发客户端或TTY；实际intent持久化事件与完整请求/状态分别核验，不能凭最终文件已删证明零写。成功也不能覆盖C07预览/问句取消、实际平台或其它义务。细则见正式测试§8.17；一次prepare已含根，事实回填不重包。

固定`--scope collection-publish-preview`只运行C07的9个发布预览场景及原生探针，生产者自己用隔离env调用node-pty，不使用宿主env的通用探针，也不探测真实私有输入。实际TTY、完整有序预览、实际stdout/stderr写入、按键/退出、SDK与模型、本地/home及intent事件都独立保存并源码重核；通道不能由合并的PTY输出推断。原始UTF8字节跨写入须无损合并，不能逐块解码丢字符。缺PTY/截断/信号不通过；C08模式、真实平台和其它平台仍各有义务，不能合并成总PASS。一次prepare含根，事实回填不重包。

### 候选级设计追溯与独立审查证据

标准检查还须有候选自己的 `delivery.json`。源码内交付契约固定已登记规则的正式设计路径和业务 case ID；报告只能逐项对应，不能把无关用例、LEGACY 进程退出或另一个成功样本当覆盖。每个设计文件校验当前 SHA-256。当前粒度为9项目录义务，不是完整的字段级追溯，7项未完成专项继续由业务验收拒绝。

作者在候选生成后收集两条真实独立审查的原始记录（代码 APPROVE、架构 CLEAR）。原始文件自身须标明同一候选路径、源码/包/交付契约摘要、全部登记规则、作者、审查者、起止时间、结论和未关闭问题；摘要和原始记录一致，作者与两lane的记录身份各不相同。自审、旧候选结论、缺lane、未关闭问题、非通过、未来/倒序/超过24h的记录均不得放行。文件只放在候选忽略目录，不回填源码；发布前网络等待后再次读取核验。

这些检查证明已登记追溯关系、记录一致性与字节绑定，不证明设计语义完全正确，也不通过身份字符串认证独立审查者。原始结论必须来自实际独立审查，禁止把旧结论改时间/改哈希或自动填 APPROVE。正式设计文件摘要不是用户批准记录；本次用户要求严格流程不等于批准所有历史设计。报告由 AI 整理，用户不承担编写证据JSON的职责。新增门禁没有绕过参数；不能用 delivery 代替真实业务报告。

归档格式（仅供 AI 整理真实结果，不是自动批准模板）：

- `scripts/release/delivery-contract.mjs` 固定规则、正式设计路径与 case ID；`delivery.json.rules` 必须完整对应，每条包含 `ruleId`、`designs:[{path,sha256}]` 和 `caseIds`，不自定义覆盖清单，不填业务 PASS。
- `delivery.json` 顶层固定 `schemaVersion:2`、`candidateFile`、`purpose`、`sourceRevision`、`sourceFingerprint`、`tarballSha512`、`contractSha256`、`createdAt`、`authorId`、`rules`、`reviews`。文件位于候选目录，契约摘要按当前源码计算。
- 两个 `reviews` 条目包含 `lane`（code / architecture）、真实任务身份 `reviewerId`、实际 `verdict`、`evidenceRef:{path,sha256}`。原始 JSON 必须是候选目录内普通文件，最大2MB，不经过软链接或路径别名。没有真实原始结果时不建一个空 APPROVE 文件。
- 原始 JSON 固定 `schemaVersion:2`、`candidateFile/purpose/sourceRevision/sourceFingerprint/tarballSha512/contractSha256`六个绑定字段、`authorId`、`reviewerId`、`lane`、`verdict`、`startedAt`、`finishedAt`、全部 `ruleIds`、`findings` 和完整原始 `report`。审查者须核对被提供的绑定再输出，主代理原样归档，不改写结论。每项 finding 有 id/description/status/resolution；未解决项不能标 RESOLVED，实际无发现才为空数组。开始不早于候选创建，结束不晚于归档，不晚于当前时间，最长24h。

fixture 仅用于测试上述拒绝路径，不是独立复核证据；归档程序不可能凭本机 JSON 检测所有恶意伪造。最终结论必须同时说明审查实际范围及未覆盖边界。远端CI必需状态和分支保护须由实际只读结果证明满足，不能把本地门禁说成远端治理已完成。

npm 支持直接发布 tarball，并对 tarball 提供完整性标识，见 [npm publish](https://docs.npmjs.com/cli/v11/commands/npm-publish/)；生命周期执行范围见 [npm scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts/)。认证仍按仓库 README：AI 主动打开 npm 当次登录/验证链接，用户本人完成浏览器身份验证。禁止把链接、OTP、token 或 `.npmrc` 放入证据。

## 6. CI 与安全

- CI 在 dev 分支和 PR 执行明确存在的命令；workspace filter 必须 fail-if-no-match，空测试失败。CI 不保存真实账号，不在不可信 PR 上执行 dev 写入或发布。
- 候选、安装副本、认证与真网日志位于忽略目录或临时目录；Git 和 npm 包采用明确禁入规则。报告默认只含标识/证据路径，不包含请求 cookie、密码、认证链接或池内标识正文。
- 未受控的请求/程序异常在CLI统一出口转换为固定安全错误，不让Node打印原始异常对象；已受控业务错误及未知结果恢复语义保留。真网报告另做已知秘密值、认证字段及多行HTTP诊断的脱敏，使用假凭据故障回归同时验证CLI输出和报告落盘；不得用真实秘密复现泄漏，脱敏不抹掉失败状态。
- 同时审查领域catch、结果未知包装和只读诊断的正常返回；禁止把未知异常message先包装成受控错误再输出。回归须从实际失败调用走到实际出口，另有结构化业务错误正控，核对请求次数及稿/未决记录；只测formatter或把业务失败隐藏为成功，不满足验收。
- 私有凭据文件的读取/解析失败只能给固定受控说明，不转发原始异常或cause：JSON解析器可能摘出没有字段名的密码片段，此时尚未登记秘密值，正则脱敏不能兜底。诊断必须先完整脱敏再截断，覆盖带错误前缀的Authorization/Basic/Bearer及多段Cookie；业务DTO、PTY内部返回和断言值不靠批量改写来凑绿。
- 版本、锁文件、手册和打包清单自动核对；文档链接、批准命令清单与实际注册树要一致。没有配置 lint/coverage 时不能在报告虚报执行过。
- 质量工具本身必须有负例测试：假 PASS/非零、空测试、缺报告、报告重复/伪结构、源码变化、包被替换、缺候选、过期证据、不同 bin、错误环境均不能放行。
- 发布前核验可信远端仓库/受保护来源分支及候选精确SHA、工作流/应用、Windows/macOS/Linux×Node20/22六格与最终汇总的真实完成结果；仅明确success通过，skipped/neutral/缺失/旧SHA/不同工作流同名job均不能替代。最终汇总始终执行并拒绝任一格非success。源码构建CI不代替同tarball的跨平台安装/TTY；各runner记录自己的实际安装bin和同包摘要，不复制本机candidate或放松本机路径绑定。
- 工作流、门禁、测试与验收/交付契约的变更纳入真实独立保护审查；本地CODEOWNERS或身份字符串不证明审批身份。核验范围为固定源码在GitHub当前策略下的状态，不重建历史权限。初始可验证的CODEOWNERS覆盖契约是一条全仓通用 `* owner...` 活动规则；GitHub核验语法/owner有效性，平台计算PR审批。仅README等局部规则、带覆盖的多规则或未知复杂配置不能证明门禁受覆盖，明确COVERAGE_UNVERIFIED并BLOCKED，不私造通配/RBAC引擎。需要复杂分组时先扩展并复核契约，不默默略过覆盖问题。
- 401/403、保护不可核实/未启用、必需检查未运行或缺权限时，发布治理保持BLOCKED；先解决实际外部条件，不造本地CI批准记录，不擅改组织设置。只读核验已接入本地发布入口，远端配置仍未满足，最终实现独立复核与全量验证另记当前交接，不能用本地verify通过宣称远端完成。
- 当前保护核验支持明确的classic分支保护且生效ruleset为空。若发现任何生效/继承rules，保留type/来源和可见绕过配置，但其parameters效果尚未实现完整核验，统一 `RULESET_POLICY_UNVERIFIED` 阻断，不能因active且无bypass就判通过。支持复杂ruleset应另扩受审契约，不自行推断审批数/额外必需检查已经满足。
