# 从核心到复杂的授权流程图解

状态：**下一代授权产品模型讨论稿；不是现行语言、接口或 CLI 行为说明。** 图中的「待决」必须在允许相应策略发布前定稿；「推荐」不是已批准的默认规则。各图描述产品可见的判断与结果，不规定内部事件实现。

## 0. 阅读路线：逐层增加一个问题

```mermaid
flowchart LR
    A["一份承诺怎样变成一次可使用的授权？"] --> B["什么承诺允许发布？"]
    B --> C["怎样形成并履行一份合同？"]
    C --> D["已取得的权利对本次使用是否适用？"]
    D --> E["时间、地域、版本、合集如何改变结果？"]
    E --> F["多合同、续费、下架、失败怎样保持承诺？"]
    F --> G["用组合场景与反例回检整套规则"]
```

## 1. 最小闭环：先不加入任何特殊条件

```mermaid
flowchart LR
    S["授权方提出可兑现的策略承诺"] --> U["使用方接受确定的条款"]
    U --> C["形成合同：主体、标的、条件、范围、补救依据固定"]
    C --> F["履行取得条件：免费时可立即完成"]
    F --> R["形成一项完整权利：谁可对什么做什么、边界是什么"]
    R --> Q["使用方提出一次具体使用请求"]
    Q --> A{本次请求落在该权利范围内？}
    A -->|是| G["再检查平台治理限制和内容可交付性"]
    G -->|交付成功| M["按这份合同的权利计量；形成可解释结果"]
    G -->|无法交付| X["解释原因，进入已承诺的补救或争议路径"]
    A -->|否| N["仅本次不适用；不等于合同失效或权利被撤销"]
    A -->|暂不可核验| W["说明未知原因并提供重试、更正或申诉出口"]
```

## 2. 策略发布：不能只检查状态图能否运行

```mermaid
flowchart TD
    A["拟发布一个可签约选项"] --> B{授权方有权承诺此标的与行为？}
    B -->|否| Z["不能发布该选项"]
    B -->|是| C{所用身份、支付、任务等能力已获平台开放且适用于此标的？}
    C -->|否或不可核验| Z
    C -->|是| D{签前能展示确定的条件、总代价与步骤上限、目标权利范围、期限和补救？}
    D -->|否| Z
    D -->|是| E{对合格用户，目标权利非空、可达、有界？}
    E -->|否| Z
    E -->|是| F{每条正常完成路径都会兑现其承诺的权利？}
    F -->|否| Z
    F -->|是| H{已经付出代价却不能兑现时，有可执行的补救且不低于平台底线？}
    H -->|否| Z
    H -->|是| I{版本、合集成员、持续资格等被使用的范围规则已定稿？}
    I -->|否：待决产品规则| P["先定规则、补充反例；不可由语言或实现猜默认值"]
    I -->|是或不涉及| Y["可以作为候选策略发布；每次签约仍需重新核验报价和资格"]
```

## 3. 签约：接受的是确定承诺，不是可随时改写的页面

```mermaid
flowchart TD
    A["使用方选择一个策略选项"] --> B["核验当前可新签、主体资格、报价和已有交易或合同"]
    B --> C{当前信息是否可确认？}
    C -->|未知| X["解释未知并允许安全重试；不默认为无资格"]
    C -->|否| N["展示不能签约的原因与可行下一步"]
    C -->|是| D{是否同一交易的重试？}
    D -->|是| E["恢复原交易结果；不能重复形成合同或扣款"]
    D -->|否| F["展示标的、最终价格、取得路径、权利边界、期限与补救"]
    F --> G{展示后报价或条件发生变化？}
    G -->|是| H["重新展示并要求再次接受"]
    H --> F
    G -->|否| I{使用方接受？}
    I -->|否| J["不形成合同"]
    I -->|是| K["形成新合同并固定被接受的条款及范围规则"]
    K --> L["开始按该合同履约；已签约不等于已获得目标权利"]
```

## 4. 合同履约：状态机推进承诺，不能用状态名冒充权利

```mermaid
flowchart TD
    A["合同成立：固定每条取得路径与补救约定"] --> B["立即判断签约时即可确认的条件"]
    B --> C{某条路径的条件已经全部满足？}
    C -->|是| G["形成该路径承诺的完整权利"]
    C -->|尚未| D["保留已完成进度与待完成条件"]
    D --> E["等待约定的时间到达、身份变化、支付或任务结果等"]
    E --> F{平台确认其来源、主体、合同关联、时间和唯一性？}
    F -->|否或未知| V["不凭动作或回调直接授权；解释、重试、更正或争议"]
    F -->|是| H{该事实按已接受条款产生什么效果？}
    H -->|部分满足| D
    H -->|全部满足| G
    H -->|没有约定效果| I["合同保持原进度；不擅自改变权利"]
    H -->|期限到达或无法继续| R["按约处理未完成、退出或补救"]
    G --> Q["权利独立记录受益人、行为、标的、范围、额度与合同依据"]
    Q --> U["以后每次使用另行判断适用性"]
```

## 5. 逐次使用：把“有权”与“这一次能用”拆开

```mermaid
flowchart TD
    A["一次使用请求：人、行为、标的、版本或单品、时间、地域等"] --> B["寻找同一份合同产生的一项完整权利"]
    B --> C{是否存在覆盖本次请求的完整权利？}
    C -->|否| N["本次不适用；展示缺少的范围，不拼接多份合同的局部字段"]
    C -->|暂不可核验| U["本次结果未知；说明缺失事实并保留重试或申诉路径"]
    C -->|是| D{是否受到平台强制治理限制？}
    D -->|是| E["停止本次交付，说明限制；合同与补救责任仍须处理"]
    D -->|否| F{内容此刻可交付？}
    F -->|否| G["不把不可交付说成无权；进入交付失败和补救路径"]
    F -->|是| H{达到约定的使用成功点？}
    H -->|否| I["不扣使用额度；失败和重试可追踪"]
    H -->|是| J["只按所选完整权利及其合同计量一次"]
```

## 6. 同一个时间输入：可以推进合同，也可以只限制一次使用

```mermaid
flowchart TD
    A["示例承诺：付款后取得 24 小时浏览权；仅白天且在中国境内适用"] --> B["12:00 签约并确认付款"]
    B --> C["合同履约推进：形成 12:00 起 24 小时的浏览权"]
    C --> D["20:00 在中国请求浏览"]
    D --> E["权利尚在期间内；但本次不在白天 → 本次不适用"]
    C --> F["次日 10:00 在美国请求浏览"]
    F --> G["权利尚在期间内；但本次地域不符 → 本次不适用"]
    C --> H["次日 10:00 在中国请求浏览"]
    H --> I["期间、白天、地域均满足 → 再检查治理与交付"]
    C --> J["次日 12:00 后请求浏览"]
    J --> K["权利期间已过 → 本次不适用；合同历史仍可查"]
    E --> L["不必把合同按昼夜或移动位置来回切成有权／无权状态"]
    G --> L
```

## 7. 多条件取得：每条承诺路径都要有出口

```mermaid
flowchart TD
    A["示例选项：七天内完成两次指定任务并满足身份条件，取得浏览权"] --> B{签前是否定义任务可累计方式、身份判断时点、期限和失败补救？}
    B -->|否：待决| X["不能发布；用户不能先付出代价再发现隐藏门槛"]
    B -->|是| C["使用方接受确定规则，形成合同"]
    C --> D["已确认第一次任务完成"]
    D --> E["已确认第二次任务完成"]
    E --> F{按签前约定时点检查身份是否满足？}
    F -->|满足| G["在约定期限内形成指定浏览权"]
    F -->|不满足但仍可完成| H["保留约定进度，等待允许的后续变化"]
    F -->|未知| U["不能算满足或失败；核验、更正、重试"]
    H --> I{七天期限到达或任务能力无法继续？}
    I -->|否| F
    I -->|是| R["依已接受条款与平台最低保护处理退出或补救"]
    G --> J["之后是否持续要求该身份？若要，须在签前明确；不能事后追加"]
```

## 8. 版本和合集：内容变化不能偷偷改旧合同

```mermaid
flowchart TD
    A["签约时固定资源或合集的稳定身份及范围规则"] --> B["日后发布新版本，或合集新增、移出单品"]
    B --> C{已接受条款约定的范围模式是什么？}
    C -->|固定范围| D["按签约时确定的版本或成员集合判断"]
    C -->|动态范围| E["按已接受的动态规则判断变化如何纳入旧约"]
    C -->|模式未定：待决| X["产品先决定未来版本、加入和移出分别如何影响旧约；不能默认全纳入或全排除"]
    D --> F{本次请求在该合同的完整权利范围内？}
    E --> F
    F -->|否| N["本次不适用；不能追溯改写签约时的承诺"]
    F -->|是| G{对应内容仍可交付？}
    G -->|是| H["继续做治理、交付和成功计量判断"]
    G -->|否| R["权利范围与交付能力分开解释；处理已约定补救"]
```

## 9. 已有权利后再签：合同并存，不拼接权利

```mermaid
flowchart TD
    A["使用方已有一份或多份合同"] --> B["提出新的签约请求"]
    B --> C{同一交易重试？}
    C -->|是| D["恢复原交易；不重复签约"]
    C -->|否| E{是续期？}
    E -->|是| F["重新报价与接受，形成关联旧周期的新合同；旧周期不被改写"]
    E -->|否| G{新选项与旧权益的关系可证明吗？}
    G -->|无新增收益| H["明确提示重复购买风险；销售限制与例外细则待决；当前不自动成交"]
    G -->|有新增范围、时间、额度或行为| I["展示增量与重叠，允许按规则独立形成新合同"]
    G -->|无法证明或存在冲突| J["显示不确定或冲突；增量、替换、结算细则待决；当前不自动成交"]
    F --> K["每份合同仍有各自完整权利、义务、额度和补救"]
    I --> K
    H --> O["旧合同继续独立履行；不能拼接其局部权利来凑出新权利"]
    J --> O
    K --> L["一次使用请求逐份寻找可独立覆盖请求的合同"]
    L --> M{有一份完整适用的合同？}
    M -->|是| N["选择该合同；成功后仅扣该合同的额度"]
    M -->|否| O
```

## 10. 停售、下架与无法交付：区分未来交易与既有责任

```mermaid
flowchart TD
    A["策略停售、资源下架或平台施加强制限制"] --> B{用户是否已有合同？}
    B -->|否| C["按当前可发现、可新签状态处理未来用户"]
    B -->|是| D["旧合同和接受的承诺仍可追溯；停售本身不自动消灭已取得权利"]
    D --> E{本次使用受强制限制或内容无法交付？}
    E -->|否| F["继续按旧约的范围和逐次条件判断"]
    E -->|是| G["停止当前交付并说明原因，不谎称历史合同不存在"]
    G --> H{已接受条款和平台最低保护可否确定补救？}
    H -->|可确定| I["执行并审计约定补救、退款或替代安排"]
    H -->|待决产品规则| J["先定撤回、保护下限与争议规则；不能让已付费用户无出口"]
    C --> K["可发现、可新签、旧约可用、当前可交付是不同问题"]
    F --> K
    I --> K
```

## 11. 组合演练：一份付费合集权利遇到新单品、跨境和交付失败

```mermaid
flowchart TD
    A["售卖方发布付费合集策略：签约前写明成员范围模式、版本范围、地域、期限、补救"] --> B{这些模式与补救是否已由产品定稿并可兑现？}
    B -->|否：待决| X["暂停该选项发布；先补产品规则"]
    B -->|是| C["用户接受报价并付款；形成固定条款的合同"]
    C --> D["付款事实经确认；合约形成一项有界的合集使用权"]
    D --> E["售卖方后来增加单品并给原单品发新版本"]
    E --> F["按旧约固定的成员与版本范围规则，判断这次请求是否覆盖"]
    F -->|不覆盖| N["本次不适用；可另行展示新交易，不改旧约"]
    F -->|覆盖| G["用户从另一地域发起请求"]
    G --> H{本次地域、时间、额度等条件满足？}
    H -->|否| I["本次不适用；合约与已取得权利仍在"]
    H -->|是| J{治理允许且内容可交付？}
    J -->|是且成功| K["只扣这份合同对应权利的额度一次"]
    J -->|受限或无法交付| R["说明原因；依据旧约和平台保护进入补救或争议"]
    D --> L["若用户后来续期：重新接受并形成关联的新周期合同"]
    L --> M["新旧合同分别判断；不因续期重写旧周期"]
```

## 12. 用反例回检：流程图不是一次画完就算定稿

```mermaid
flowchart LR
    A["为每个策略选项与范围模式画出正常完成路径"] --> B["再画未完成、事实未知、重复、迟到、更正与撤销"]
    B --> C["加入时间、地域、身份、版本、单品、额度的边界变化"]
    C --> D["加入多合同、续期、停售、下架和交付失败的组合"]
    D --> E{能否对每个分支说明合同、权利、本次结果与补救？}
    E -->|能| F["作为候选产品规则；再做治理、法务与能力审查"]
    E -->|不能：规则待决| G["显式列为待决；相应策略不能靠实现猜测上线"]
    E -->|不能：模型缺对象或判断| H["修正核心模型，再回测之前全部流程"]
    G --> A
    H --> A
```
