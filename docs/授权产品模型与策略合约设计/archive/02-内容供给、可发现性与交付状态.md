# 内容供给、可发现性与交付状态

状态：**历史专题草案，不作为当前产品规则**。下文的市场状态同时承载「可发现」和「可新签」两种独立判断，状态划分尚未定稿；以[当前主模型](../12-策略合约核心抽象与场景覆盖.md)为准。

## 目标

内容是否能在市场中被看到、能否签新合同、已签约用户能否继续取得内容，是三件不同的事情。产品必须分别管理，避免“下架”同时导致搜索消失、不能购买和老用户突然失去权益。

## 1. 三条独立状态轴

| 状态轴 | 面向谁 | 推荐状态 | 解决的问题 |
|---|---|---|---|
| 市场状态 | 未签约用户 | 未发布 / 可发现 / 停止新签约 / 已归档 | 是否可搜索、查看商品页、发起新签约 |
| 交付状态 | 已签约使用方 | 可交付 / 暂时受限 / 补救中 / 不可交付 | 是否还能取得合同承诺的内容 |
| 合规状态 | 平台与所有用户 | 正常 / 审核中 / 冻结 / 强制限制 | 法律、安全、侵权等平台级限制如何影响前两者 |

状态之间可以联动，但不能混为一个值。例如“停止新签约”通常让市场状态变化，却不改变交付状态；“强制限制”可能同时阻断交付，但必须触发合同补救。

## 2. 四种用户视图

同一个内容不应只存在“可见/不可见”两种结果。

| 视图 | 可看到什么 | 主要用途 |
|---|---|---|
| 公共市场 | 可发现且可新签约的内容 | 搜索、推荐、分享、购买前了解 |
| 已签约内容库 | 用户拥有有效或补救中合同的内容 | 找回已购内容、继续履约、处理异常 |
| 创作者管理台 | 自己的全部内容、草稿、停止签约、归档和合同负担 | 管理供给、版本、规则和撤回申请 |
| 平台运营台 | 受权限控制的全量状态与审计资料 | 审核、风控、投诉、补救和人工裁决 |

“公共市场不可见”不等于“对当事人不可查询”。相反，合同履约期间，已签约内容库应是老用户稳定的交付入口。

## 3. 内容生命周期

```text
创建中 → 已发布但未开放 → 可发现且可新签约
                                  ↓
                          停止新签约、继续履约
                                  ↓
                无有效合同 → 归档
                                  ↑
        暂时受限 / 补救中 ────────┘
```

### 创建中

仅创作者和被授权协作者可见。可准备版本、元数据、授权发布与交付材料；不进入公共市场，也不能产生面向外部使用方的合同。

### 已发布但未开放

内容已有稳定身份和至少一个可交付版本，但创作者尚未开放市场。可用于内部核验、预览或准备授权规则；默认不能被陌生用户签约。

### 可发现且可新签约

满足内容交付、必要元数据、至少一个可用授权发布与平台合规门槛后，进入市场。公共页应明确显示可签约的授权选项、条件、适用范围与风险提示。

### 停止新签约、继续履约

创作者不再接受新用户，但已有合同继续得到原承诺。公共搜索、推荐和新签约入口关闭；合同当事人仍可在已签约内容库访问必要信息和交付入口。

### 暂时受限 / 补救中

内容暂时不能按原方式交付，或正处理撤回、退款、替代内容、侵权争议。页面不得简单显示“内容不存在”；当事人应看到原因、预计处理、当前权利影响和下一步。

### 已归档

只有在不再存在需要继续交付或补救的有效合同后，内容才能完全归档。归档保留必要的审计记录，但不再作为市场商品或可交付内容提供。

## 4. 上架门槛与开放市场

当前业务中，上架要求至少有版本和一条启用策略。目标产品应把它表达为“开放市场门槛”，而非技术开关：

1. 存在符合内容类型要求的可交付内容版本或合集已发布目录；
2. 已完成必要的标题、封面、简介、类型属性与合规声明；
3. 至少一个对使用方可理解、可签约、可履约的授权发布；
4. 若依赖影响交付，依赖授权状态能支持该内容的承诺；
5. 不存在未处理的高风险合规限制。

门槛失败时，产品应告诉创作者缺少的是“可交付版本”“可签约授权”“必要展示信息”还是“依赖/合规条件”，不要只报一个笼统的上架失败。

## 5. 内容下架与删除的用户体验

创作者发起停止新签约时，应先看到：当前有效合同数、仍需履约的最晚日期、是否存在自动续费、是否存在需要处理的退款或争议。默认动作应是“停止新签约”，而不是破坏性“删除”。

如果创作者申请完全撤回，产品必须改为撤回向导：说明理由、展示受影响合同、选择允许的补救方案、生成通知预览，并提示完成条件。详细规则见 [07-合同存续、撤回、违约与补救](./07-合同存续、撤回、违约与补救.md)。

## 6. 需要统一到各端的产品行为

| 产品端 | 必须遵守的行为 |
|---|---|
| 市场与搜索 | 默认只展示可发现且可新签约内容；不能因公共下架泄露或丢失合同权益 |
| 内容详情 | 对未签约用户展示市场状态；对当事人展示合同状态和交付状态 |
| 我的内容 | 分开显示“市场中”“停止新签约”“履约中”“补救中”“归档”，并显示合同负担 |
| 我的已授权内容 | 独立于公共列表，稳定展示用户的有效、暂停、补救和已结束合同 |
| CLI / API | 返回状态轴与可执行操作，而不是只返回 `online/offline` 后让客户端猜测 |
| 通知 | 市场停止、交付受限、补救启动、恢复与结束都应通知受影响合同当事人 |
