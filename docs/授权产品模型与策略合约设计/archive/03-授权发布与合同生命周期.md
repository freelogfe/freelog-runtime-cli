# 授权发布与合同生命周期

状态：**历史专题草案，不作为当前产品规则**。合同阶段、取得权利与本次请求判断的边界以[当前主模型](../12-策略合约核心抽象与场景覆盖.md)和[顶层规则](../13-策略产品规则与能力边界.md)为准；下文推荐状态尚未定稿。

## 目标

把“规则”“可购买的授权商品”和“用户已经签下的合同”分开。这样作者可以推出新方案、停止旧方案或调整未来价格，同时不破坏已有使用方的权益。

## 1. 授权发布是用户实际选择的商品

授权规则描述一类交易条件；授权发布把它绑定到一个具体内容后，才成为用户能签约的商品。

每个授权发布至少应向使用方清楚展示：

- 授权方和具体内容；
- 取得哪些权利，例如浏览、下载、使用、分享；
- 权利范围：整个内容、固定部分，还是签约时可选择的单品；
- 生效条件：免费接受、付款、认证、资格、时间或其他要求；
- 价格、币种、期限、次数、地域、用途等限制；
- 版本范围：全部版本、明确的版本范围，或指定版本；
- 续费和升级是否可用；
- 后续发布的新版本是否落入该版本范围；
- 提前终止、无法交付时的处理方式；
- 版本号与生效时间。

作者对内容新建一条更优惠或更严格的授权发布，是面向未来的商品调整；旧授权发布应继续服务于已签约合同，直至最后一份合同结束或被依法处理。

## 2. 发布的状态

| 状态 | 新用户能否签约 | 已有合同 | 作者可做什么 |
|---|---|---|---|
| 准备中 | 否 | 无 | 编辑并完成平台校验 |
| 开放签约 | 是 | 正常履约 | 可停止新签约，不可改写已签条款 |
| 停止签约 | 否 | 正常履约 | 查看合同负担、等待合同结束或申请撤回补救 |
| 已结束 | 否 | 无有效合同 | 仅保留审计与历史展示 |
| 被平台限制 | 否 | 视限制进入履约或补救 | 不能自行绕过平台限制 |

授权发布的停止签约与资源停止新签约可以单独发生：资源仍可销售其他授权发布，或者资源整体停止销售但旧授权发布继续履约。

## 3. 合同的推荐生命周期

```text
待接受
  → 待满足生效条件 ──付款/认证/确认──→ 生效
  → 生效中 ──条件暂失──→ 暂停
  → 暂停 ──条件恢复────→ 生效
  → 生效中 ──到期/取消──→ 正常结束
  → 任一履约阶段 ──无法交付/争议──→ 补救中
  → 补救中 ──恢复/补偿/解除──────→ 生效或已结束
```

| 合同状态 | 使用方感受 | 平台必须提供 |
|---|---|---|
| 待满足生效条件 | 已表达接受意愿，但暂未获得完整权利 | 待完成事项、超时规则、取消入口 |
| 生效 | 可以行使合同约定权利 | 内容交付、权利说明、使用记录与续费入口 |
| 暂停 | 原合同仍存在，但部分或全部权利暂不可用 | 暂停原因、恢复条件、宽限期和通知 |
| 补救中 | 无法按普通流程履约 | 受影响范围、补救计划、进度、申诉与历史 |
| 正常结束 | 权利按约到期或完成 | 历史合同、续费/重新签约入口（若允许） |
| 已解除 | 合同因取消、违约或平台决定提前结束 | 解除依据、补偿结果、可申诉期限 |

“合同存在”不等于“当前一定有权利”；“付款订单存在”也不等于“合同已经生效”。产品页面必须同时显示合同状态、条件状态和当前有效权利。

### 3.1 合同状态、授权范围与本次请求适用性必须分开

| 层次 | 它回答的问题 | 国家/IP、版本、用途在这里的含义 |
|---|---|---|
| 合同状态 | 这份合同是否正在履约、已结束或进入补救？ | 不因用户换国家、请求另一个版本或用途变化而改变 |
| 授权范围 | 这份有效合同承诺覆盖哪些内容、版本、地域、用途和限制？ | 地域和版本范围是合同条款的一部分，签约后固定 |
| 本次请求适用性 | 当前这次浏览、下载、安装或使用，是否落在该合同范围内？ | 当前 IP 国家不在地域范围、请求版本不在版本范围时，只拒绝这次请求 |

因此，“仅限中国大陆使用”的合同在使用方位于其他国家时仍是有效合同，只是该次请求不适用；回到支持地区后自动可用。它不进入暂停、违约、补救或结束，也不需要产生合同状态变更记录。

只有会改变合同整体履约能力的事实，才可进入暂停或补救，例如付款条件长期未满足、合同明确约定的持续资格失效、内容无法交付或平台强制处理。日服务时段、地域、设备、用途和请求版本等通常属于本次请求适用性，不应滥用“暂停”描述。

## 4. 签约流程

```text
选择授权发布
  → 平台检查资格、内容可签约性、待完成交易和已有权利
  → 按权益增量、重叠和真实冲突解释是否可再签
  → 使用方查看完整承诺与需填写选项
  → 使用方确认接受
  → 生成合同与待履行事项
  → 条件满足后生效；不满足则保持待条件或按规则取消
```

签约前的检查只能决定“是否可以发起这次交易”，不能偷改最终合同。已有授权不是一律禁止新签：同一交易重试应恢复原交易，确有增量的可并存或续费，可证明无增量的默认不再出售，真正互斥的须先处理；不能可靠比较时须披露风险而非猜测。具体判断见[已有授权后的再次签约](../14-已有授权后的再次签约与多合同.md)。所有需要用户选择的内容范围、用途、档位、付款周期或资格声明，必须在确认页明确显示并写入合同；接受时重新确认报价和相关合同状态，避免并发重复收费。

## 5. 不得静默发生的变更

以下变化必须显式通知并在合同历史中留痕：

- 作者停止该授权发布的后续签约；
- 合同因资格、付款、时间或交付问题进入暂停；
- 内容交付承诺改变、内容暂时受限或撤回；
- 自动续费即将发生、失败或改用新版条款；
- 发生退款、替代交付、解除或人工裁决；
- 多份合同被合并展示、升级或替换。

产品设计的目标不是让用户“少看到状态”，而是让用户只在权益发生变化时看到足够明确、可行动的信息。
