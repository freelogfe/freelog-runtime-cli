# 核心对象与信任边界

状态：**历史专题草案，不作为当前产品规则**。对象与流程以[当前主模型](../12-策略合约核心抽象与场景覆盖.md)为准；本文的分层、合同快照与现状判断尚未逐条复核。

## 目标

让用户能始终回答四个问题：

1. 我现在面对的是什么内容？
2. 我为什么能、或不能使用它？
3. 双方当时到底同意了什么？
4. 内容和规则后来变化后，我的原有权益是否受影响？

平台必须用稳定对象回答这些问题，不能依赖标题、页面当前显示、作者口头说明或客户端本地记录。

## 1. 平台的五层对象

```text
内容类型 ──定义可提供的内容与能力──→ 内容
                                          ↓
授权规则 ──定义交易条件────────────→ 授权发布
                                          ↓
使用方接受────────────────────────→ 授权合同
                                          ↓
合同在某时刻的有效权利、待履行事项与历史记录
```

| 层级 | 对象 | 用户视角 | 核心规则 |
|---|---|---|---|
| 1 | 内容类型 | 图片、主题插件、视频合集等类别 | 定义允许的内容形态、可提供能力、可选配置与合规要求；不代表某项内容 |
| 2 | 内容 | 某张图片、某个主题插件、某个合集 | 有不可变身份；标题、封面、简介、标签可变且可重复 |
| 3 | 授权规则 | “支付后可下载 30 天”“认证用户可浏览”这类公开规则 | 说明可授予的权利、范围、条件、期限、续费与提前终止安排 |
| 4 | 授权发布 | 这条规则被某个作者用于某项具体内容后形成的可签约商品 | 固定内容、规则版本、对外条款与签约选项；停止新签约不影响既有合同 |
| 5 | 授权合同 | 某个使用方在某时接受的一次具体承诺 | 固定双方、接受时间、选择项、适用条款和后续履约历史 |

“策略模板”只是授权方创建授权规则的工具；“策略”在产品上应呈现为用户可理解的授权规则或授权发布，不能让用户面对模板、代码和合同三种含义混杂的同一个词。

## 2. 每份合同必须固定的内容

授权合同成立时，平台至少要固化以下快照：

| 快照 | 必须包含 | 原因 |
|---|---|---|
| 当事人 | 授权方、使用方及其当时有效身份 | 避免账户展示名变化影响归属 |
| 内容 | 内容不可变身份、内容类型、合同授权范围、版本范围声明 | 避免标题、合集目录、排序或后续版本变化影响标的 |
| 授权发布 | 规则版本、对外条款、价格、期限、可用权利、版本范围 | 避免作者以后改规则倒改旧合同 |
| 使用方选择 | 选择的单品、档位、地域、用途或其他签约选项 | 解释为什么该用户取得的是这一范围而非另一范围 |
| 履约约定 | 条件、付款安排、续费安排、暂停和提前终止补救 | 让双方知道发生异常时怎么办 |

快照不是“复制一张页面”。它是双方确认的交易事实。展示页后来修改时，旧合同仍应能打开自己的历史版本并看到当时承诺。

## 3. 可变信息与不可变承诺

| 信息 | 是否允许变化 | 变化后对既有合同的影响 |
|---|---|---|
| 标题、封面、简介、标签、搜索排序 | 可以变化 | 仅更新展示；不得改变权利、范围、价格或期限 |
| 内容的新版本 | 可以发布 | 是否适用于旧合同，取决于合同中固定的版本范围；作者不能事后扩大或缩小该范围 |
| 授权规则的新版 | 可以发布 | 只供新授权发布/新合同使用；旧合同继续按原版本履行 |
| 授权发布是否接受新签约 | 可以关闭 | 不影响已签约合同 |
| 合同的履约状态 | 可以按事实变化 | 每次变化必须留下原因、时间与影响范围 |
| 已接受的条款、签约选择、历史付款和历史状态 | 不可原地修改 | 只能追加纠正、补偿、终止或新周期记录 |

## 4. 不能由任何一方单独决定的事实

以下事实影响使用方权益，平台必须有可验证来源，而不能只相信某一方提交的字段：

- 支付是否成功、退款是否成功；
- 用户是否拥有某项平台资格；
- 内容是否实际可以交付；
- 内容因侵权、法律或安全原因被限制；
- 合同是否到期、被取消、进入争议或补救；
- 合集中合同范围内的具体单品是什么。

授权方可以发起变更，使用方可以申请取消或申诉，外部服务可以报告结果；但只有平台确认并记录后，才可改变合同当前状态或有效权利。

## 5. 平台必须提供的解释能力

任何“不能访问”“不能签约”“不能下架”“需要付款”“合同已结束”的结果，都需要有面向用户的解释卡片，最少展示：

- 当前对象和合同；
- 当前状态；
- 触发该状态的时间和原因；
- 对使用权、付款、续费、下载或交付的影响；
- 用户下一步能做什么；
- 可查看的历史记录、通知或申诉入口。

这不是客服附加功能，而是授权产品的基本可信度。若平台不能解释一项决定，就不应让该决定静默影响权益。

## 6. 当前产品的兼容边界

现状中，资源与合集有不可变线上 ID；版本的文件、属性、可选配置和依赖已经是版本快照；策略可独立上下线；授权方可查看签出的合约。这些是目标模型可复用的基础。

现状中仅有资源 `online/offline` 等状态、策略状态和合同只读列表，尚不足以表达“停止新签约但继续履约”“补救中”“合同范围冻结”“多合同聚合”等目标规则。后续不能把这些新含义塞回现有单一状态字段。
