# 合约关心对象、事实与流程抽象

状态：**已归档的历史讨论材料，不作为当前规则。**对象变化事件、合同流程与场景覆盖的当前主模型见[策略合约核心抽象与场景覆盖](../12-策略合约核心抽象与场景覆盖.md)。

## 目标

平台不能把一切都称作“事件”，也不能把所有变化都变成合同状态变化。授权产品需要先回答：合同关心的是什么、这些信息从哪里来、何时有效，以及它究竟影响签约、履约、当前访问，还是后续事项。

本章定义产品层的共同抽象，不规定策略语言、接口字段或实现方式。

另一份历史抽象讨论见 [11-授权与合约核心抽象设计](./11-授权与合约核心抽象设计.md)。本章保留为业务对象分类与典型场景材料。

## 1. 核心抽象：合约关心对象

平台提供给授权产品的每一种能力，都先抽象为一个**合约关心对象**：合同可以在签约、履约或一次使用时引用、读取或等待它。用户、资源、资源版本、支付单、广告活动、广告完成记录、平台资格、时间服务和请求环境，都可以属于这个统一对象空间。

但“固定对象”和“可监听事件”不是两类互斥对象，而是合同与同一对象的不同关系：

```text
合约关心对象
  ├─ 稳定身份：它到底是谁/是什么
  ├─ 可绑定内容：签约时固定进合同的值
  ├─ 可观察事实：某时刻由可信来源确认的当前值
  ├─ 可通知变化：平台愿意对外发布、可被可靠处理的变化
  └─ 可允许用途：它可以影响签约、合同状态、本次请求适用性、计算或待办中的哪些部分
```

例如“平台用户”是一个对象：用户 ID 在合同中固定；会员等级是可观察、会变化的事实；会员升降级可以是平台通知的变化；授权发布再决定该变化只影响续费、暂停合同，还是仅影响价格。

同理，“资源”也是一个对象：资源 ID 和合同版本范围固定；某个版本是否已发布是事实；发布新版本是变化通知；用户请求某一版本时，平台用该事实加合同版本范围判断当前是否可以交付。

### 1.1 为什么不能只分“固定”与“可监听”

一个对象的身份可以固定，但它的状态可以变化；同一个变化也可以被不同合同以不同方式使用。

| 对象 | 签约时固定什么 | 合同期间可能变化什么 | 可作为变化通知什么 |
|---|---|---|---|
| 平台用户 | 用户 ID、签约主体 | 会员、认证、风险状态 | 会员到期、认证通过、资格撤销 |
| 单资源 | 资源 ID、授权版本范围 | 新版本、交付状态、合规状态 | 新版本发布、内容受限、恢复交付 |
| 支付单 | 对应合同、应付金额 | 待支付/已支付/退款中/已退款 | 支付确认、退款确认 |
| 广告活动 | 广告 ID、奖励规则 | 活动是否可参与 | 指定用户完成观看 |
| 请求环境 | 本次请求 ID | 当前 IP 推断地区、当前时间、设备 | 通常不订阅，只在本次请求读取 |

因此，事件不是孤立的“东西”。它是平台针对某个对象或某件完成事项发出的、带来源和唯一性的可信通知；通知被处理后，可以成为合同历史中的一条事实。

### 1.2 合约关心对象的最小登记项

每种对象在开放给授权产品前，平台都必须定义：

1. **对象类型与实例身份**：例如“平台用户 / 用户 U”“资源版本 / 资源 R 的 1.4.2 版”。
2. **可信提供方**：由哪个平台模块、外部服务或人工流程确认。
3. **可绑定内容**：签约时哪些字段允许写进合同快照。
4. **可观察事实**：哪些当前属性允许在签约、履约或访问时读取。
5. **可通知变化**：哪些状态改变可被可靠、去重地通知合同处理。
6. **允许影响范围**：该对象可影响签约门槛、合同状态、本次请求适用性、权益计算或待办中的哪些部分。
7. **可见性与隐私**：谁能使用、用户如何知情、何时留存和如何申诉。
8. **故障语义**：提供方不可用、数据延迟或通知重复时，合同应保持什么状态。

这张“对象能力卡”是平台的扩展点。以后接入广告、地理围栏、企业认证、设备信任、外部许可或新的支付方式，不需要临时给策略塞一个特殊事件；只需先把它作为合约关心对象登记并限定能力。

## 2. 总模型：对象、事实、事件、上下文与结果

```text
合同固定的承诺与选择 ─────┐
平台/外部提供的可靠事实 ───┼─→ 合同判断 ─→ 当前权利 / 合同阶段 / 待履行事项
一次发生且可验证的事件 ───┤
本次访问的即时环境 ───────┘
```

| 类别 | 是什么 | 是否进入合同历史 | 典型例子 |
|---|---|---|---|
| **绑定对象** | 签约时选定、之后不能被悄悄替换的人、内容和承诺 | 必须固定 | 双方账户、资源 ID、合集单品、版本范围、价格档位 |
| **事实** | 某个对象在某时已被可信来源确认的属性或状态 | 影响合同的事实必须留痕 | 会员有效、已付款、资源版本已发布、内容交付受限 |
| **事件** | 在明确时间发生、只应被处理一次的事情 | 必须记录事件身份和处理结果 | 广告观看完成、付款回调、资格被撤销、版本发布 |
| **即时上下文** | 仅对当前一次访问/操作有效的环境 | 通常不写入合同历史 | 当前时间、IP 推断国家/地区、设备能力、请求用途 |
| **合同结果** | 平台据此前四类信息得出的结论 | 必须可解释、关键变化留痕 | 可下载、合同暂停、待付款、应退款、需通知 |

最重要的边界是：**事件告诉平台“发生了什么”；事实说明“现在确认为什么样”；即时上下文说明“这一次处于什么环境”；合同结果才是“平台允许或要求什么”。**

## 3. 合同关心对象的业务分类

### 3.1 当事人与身份

| 对象 | 可关心的信息 | 典型用途 |
|---|---|---|
| 授权方 | 不可变账户身份、授权资格、收款资格、风险状态 | 是否能发布、收款、继续履约或被限制 |
| 使用方 | 不可变账户身份、年龄/认证/会员/渠道资格、风险状态 | 是否能签约、是否享有折扣、合同能否持续生效 |
| 受益人/使用主体 | 合同权利最终由谁使用 | 企业账户、团队成员、指定节点等场景 |

账户身份本身应稳定；会员、认证、渠道身份等是会变化的**资格事实**。产品必须说明资格是只在签约时检查，还是在合同期间持续影响权利。

### 3.2 内容、版本与合集成员

| 对象 | 可关心的信息 | 典型用途 |
|---|---|---|
| 单资源 | 内容类型、市场状态、交付状态、当前与历史版本 | 是否可签约、能否交付、哪些版本可用 |
| 资源版本 | 版本号、发布时间、属性、依赖、可交付状态 | 判断请求版本是否落入授权范围、是否能交付 |
| 合集 | 已发布目录、目录状态、收录规则、合集自身交付状态 | 判断新合同可以选择哪些单品 |
| 合集单品 | 不可变单品身份、在合同中的范围、该单品版本 | 决定合集合同实际授权到什么内容 |

资源发布新版本是一个**内容事件**；“当前请求的是 1.4.2，合同允许 `1.x`”是一次**事实与范围判断**。一般情况下，发布新版本不应主动改变已有合同状态；它只是使符合该合同版本范围的新交付物变得可取得。

### 3.3 交易与履约对象

| 对象 | 可关心的信息 | 典型用途 |
|---|---|---|
| 授权发布 | 价格、权利、范围、期限、版本范围、续费和补救承诺 | 形成合同的条款来源 |
| 合同 | 当前阶段、已满足条件、剩余额度、周期、前序合同 | 判断当前权益、升级和续费 |
| 支付/退款 | 金额、币种、对象、确认结果、结算状态 | 付款生效、退款完成、补救结案 |
| 依赖合同 | 上游内容授权是否满足下游交付要求 | 判断创作者能否合法发行或持续交付 |

### 3.4 用户行为与外部完成事项

| 对象 | 可关心的信息 | 典型用途 |
|---|---|---|
| 平台行为 | 已完成广告、已阅读说明、已提交材料、已安装/激活 | 作为一次性资格或获得权利的条件 |
| 外部服务结果 | 支付成功、身份核验通过、第三方许可已获得 | 满足合同条件或触发后续事项 |
| 人工处理 | 审核通过、投诉成立、争议裁决 | 暂停、恢复、补救或解除合同 |

广告观看完成正是典型的**已验证事件**：它必须绑定具体广告、使用方、合同（或可签约对象）、完成时间和唯一记录，重复上报不能重复获得权益。事件被接受后，平台可把“已完成该广告”写成合同事实，再据此让合同生效或授予一次性权益。

### 3.5 时空与设备环境

| 对象 | 可关心的信息 | 典型用途 |
|---|---|---|
| 时间 | 当前时间、合同生效/到期、服务时段、宽限窗口 | 是否处于有效期、是否可续费、是否在开放时段 |
| 地域 | 当前请求 IP 可靠推断的国家/地区、授权地域范围 | 判断本次访问是否允许 |
| 设备与客户端 | 支持能力、设备数、受信任状态、节点环境 | 下载/使用限制、额度与安全要求 |
| 请求目的 | 本次是浏览、下载、安装、分享还是商用使用 | 将正确的能力与限制应用到本次操作 |

这些信息通常是即时上下文，而不是用户永久属性。IP 所在国家变化时，最准确的产品表述是：**本次请求不落在合同的地域范围内，因而本次请求不适用；回到支持地域后，该合同立即重新适用于请求。**合同始终有效，不进入暂停、违约、补救或结束，也不需要把每次 IP 变化保存为合同事件。

## 4. 五种合同反应方式

同一对象或事实可以被合同关心，但影响方式必须明确选择，不能只写“监听”。

| 反应方式 | 何时判断 | 是否改变合同状态 | 例子 |
|---|---|---|---|
| **签约门槛** | 创建合同前 | 否 | 仅认证用户可签、资源必须可新签约 |
| **生效/状态迁移** | 收到可信事件或确认事实时 | 是 | 付款成功后生效、广告完成后获得授权、资格撤销后进入暂停 |
| **本次请求适用性** | 每次请求内容或操作时 | 否 | 当前 IP 在允许国家、当前时间在服务时段、请求版本在范围内 |
| **权益计算** | 签约、续费、使用或结算时 | 视情况 | 会员折扣、剩余下载次数、选中的单品和版本范围 |
| **后续事项触发** | 合同状态或事实变化后 | 可产生待办 | 创建付款单、发送到期提醒、启动退款、通知创作者 |

同一个“会员失效”可有不同产品规则：只禁止下一次续费；立即暂停合同；给予 7 天宽限期后暂停；或者仅影响折扣而不影响已取得权利。必须由授权发布明确选择，不应由各端自行猜测。

## 5. 典型场景的正确抽象

| 场景 | 关心对象 | 应采用的反应方式 | 不应误用为 |
|---|---|---|---|
| 看完指定广告获得 24 小时浏览权 | 已验证广告完成事件、合同、时间 | 事件使合同生效或产生限时权利 | 普通页面点击、可重复的客户端回调 |
| 仅限中国大陆可下载 | 当前请求地域、合同地域范围 | 本次请求适用性；合同持续有效，换回支持地域自动恢复 | 暂停、违约、终止或修改合同状态 |
| 会员可享 8 折 | 用户会员资格、价格规则 | 签约/续费时计算价格 | 把会员标签直接当作内容访问权 |
| 会员失效即暂停 | 用户会员资格变化事实 | 状态迁移，附宽限与恢复规则 | 每次访问都永久改合同状态 |
| 主题插件仅授权 `1.x` | 请求版本、合同版本范围 | 本次请求适用性 | 作者发布 `2.0` 时自动解除旧合同 |
| 发布 `1.4.2` | 资源版本发布事件 | 让符合 `1.x` / 全部版本范围的合同可取得该版本 | 逐份修改所有旧合同 |
| 内容被强制移除 | 平台合规决定、内容交付状态 | 状态迁移与补救事项 | 简单把资源隐藏、让合同消失 |
| 付款成功 | 支付确认事件、合同待付款状态 | 状态迁移为生效 | 前端返回成功页即视为付款成功 |

## 6. 每一项可被合同使用的信息都要有“产品登记卡”

未来平台增加一个新的身份、事件、环境变量或内容状态前，应先填写以下产品登记项：

1. **它是什么对象或事实**：不使用模糊名称，例如“地区”要明确是当前 IP 推断地区还是账户注册地址。
2. **谁是可信来源**：平台账户、支付渠道、广告服务、边缘网络、人工运营还是内容服务。
3. **它如何变化**：一次事件、持续事实、定期更新还是每次请求重新观察。
4. **允许影响什么**：签约、生效/暂停、本次请求适用性、价格/范围、通知/补救中的哪些项。
5. **影响的默认方式**：默认是本次请求不适用、暂停、宽限、后续不续费，还是只记录。
6. **用户如何被告知**：签约前是否展示，变化后是否通知，详情页如何解释。
7. **保存与隐私边界**：是否需要保存历史、保存多久、谁可见、能否申诉和更正。
8. **失败时怎么办**：来源不可用、结果延迟、重复事件、数据冲突时，默认允许、默认拒绝还是进入待处理。

没有这张登记卡，就不应把新的信息开放给授权规则使用。它能防止“策略可以随便监听一切”造成不可解释、侵犯隐私或跨端不一致的产品。

## 7. 平台应提供的统一能力

为让上述抽象真正成为产品能力，平台需要统一提供：

- 可查询的合同当前权利及其依据；
- 针对一次内容请求的适用性判断，包含版本、地域、时间、设备和用途；
- 可确认、可去重、可追溯的事件接入；
- 资格、内容状态、版本、支付和人工裁决等事实的统一来源与变化通知；
- 合同状态迁移、宽限、恢复、补救和待办事项的统一处理；
- 面向使用方、授权方、运营方的不同解释与可见范围；
- 对事实源、事件源和授权发布适用范围的运营治理。

### 7.1 平台能力怎样一层层扩展

平台的扩展顺序应是：先有稳定对象和可信来源，再开放事实读取，再开放变化通知，最后才允许它影响更敏感的合同结果。

```text
平台模块
  → 注册合约关心对象
  → 定义可绑定内容与可观察事实
  → 定义可通知变化及去重、延迟和失败语义
  → 限定可影响的合同反应方式
  → 运营审核后开放给内容类型和授权发布使用
```

以“广告获得授权”为例：平台先提供广告活动对象，再提供“某用户完成指定广告”的可信完成记录与变化通知；随后仅允许它作为指定内容类型的生效条件或一次性权益来源。广告服务不能直接给用户写入内容访问权，也不能未经平台确认地通知合同成功。

以“地域限制”为例：平台先提供请求环境中的可信地区观察；它只能作为本次请求是否落入合同地域范围的判断。即使存在合规要求，平台也应拒绝该地区的交付请求或限制内容在该地区的交付，而不是把“用户换了国家”变成合同暂停或合同惩罚。

CLI、Console、市场页、节点与外部合作方都只应使用这套平台结论，不各自复刻“广告是否完成、IP 是否允许、版本是否在范围内”的私有判断。

## 8. 与流程设计的关系

流程只描述“收到什么后怎样走下一步”；对象分类决定“这个输入究竟是什么、能否相信、何时有效、会影响什么”。两者缺一不可：

```text
对象/事实分类正确
  → 选择反应方式（签约门槛 / 状态迁移 / 本次请求适用性 / 计算 / 待办）
  → 才能设计广告完成、付款、资格变化、版本发布等具体流程
```

因此，下一步讨论策略与合同，不应先问“怎样监听事件”，而应先问：这个信息属于哪一类、由谁提供、它应改变合同，还是只决定本次请求是否落入合同范围、用户是否能理解和申诉。
