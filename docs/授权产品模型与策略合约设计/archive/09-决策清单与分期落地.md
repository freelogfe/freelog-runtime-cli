# 决策清单与分期落地

状态：**已归档的阶段规划，不是当前实施计划**。其中默认值、分期与验收场景基于旧专题草案；产品决策请以[当前主模型](../12-策略合约核心抽象与场景覆盖.md)和[顶层规则](../13-策略产品规则与能力边界.md)为准。

## 目标

先把会影响用户权益的产品规则定清，再逐步扩展现有资源、合同、支付与管理能力。分期不是降低规则标准，而是避免在缺少基础对象时承诺复杂场景已经可用。

## 1. 必须先定稿的业务决策

| 决策 | 为什么不能由实现自行决定 | 推荐方向 |
|---|---|---|
| 单资源的版本范围 | 决定旧合同可取得哪些版本及是否包含后续版本 | 按内容类型提供默认，授权发布明确展示全部版本（含后续）、有界范围或指定版本 |
| 合集的范围模式 | 决定新增和移除单品是否影响旧合同 | 默认签约选择集或发布时固定目录；持续更新必须显式选择 |
| 完全撤回的最低保护 | 决定已付款用户是否会无补救失去内容 | 有有效合同时默认只允许停止新签约；彻底撤回需可执行补救 |
| 已有授权后再签 | 决定重复收费、增权、续期和真正冲突如何区分 | 以受益人和具体签约选项比较当前及未来增量、容量、义务与保障；同一交易重试恢复原交易，未知重叠不得假装确知 |
| 多合同使用与扣额 | 决定访问、额度和义务如何共存 | 每次使用须有一份完整适用的合同；明确依据与扣额顺序，不拼接限制或义务；详见[当前多合同专题](../14-已有授权后的再次签约与多合同.md) |
| 续费条款版本 | 决定自动续费是否可能变相改条款 | 新周期合同；采用新版条款必须显式确认 |
| 资格持续检查 | 决定会员/认证变化是否暂停旧合同 | 每项资格明确一次性或持续检查、宽限和申诉 |
| 平台强制处理 | 决定侵权/违法时如何兼顾合规与合同权益 | 强制限制进入补救与审计流程，不伪装成普通下架 |

这些决策应由产品、法务、支付/结算、内容治理和技术共同确认。它们形成平台规则，不应散落在某条策略模板、某个页面提示或某个客户端判断中。

## 2. 建议的落地顺序

### 第一阶段：先建立正确的事实与展示

- 在合同中保存完整授权发布和签约选择快照；
- 为内容、授权发布、合同补充可解释的状态与历史；
- 分离公共市场视图、创作者管理视图和已授权内容库；
- 将“停止新签约”从普通下架中拆出；
- 在详情、合同页和 API 中返回当前权利、原因和下一步。

这一阶段的目标是即使复杂补偿尚未开放，也不会让用户误以为内容或合同无故消失。

### 第二阶段：规范未来交易

- 新授权发布必须选择版本范围、合集范围模式、资格检查方式和提前终止安排；
- 签约前核对待履行交易、已有权利与真实增量；恢复同一交易重试，防止可证明无增量的重复售卖；
- 支付、待付款、生效、失败、取消和退款使用统一状态；
- 新续费一律建立关联的新周期合同；
- 合集新合同固定范围或按明确的持续更新规则处理。

这一阶段只约束新发布和新合同，不追溯修改历史合同；历史合同可先按“保守展示、不可倒改”的兼容模式运行。

### 第三阶段：处理复杂履约

- 引入暂停、宽限、资格持续检查、升级/替换和多合同可解释聚合；
- 建立撤回申请、补救计划、退款/替代交付、通知和案件处理；
- 支持单品强制下架时批量识别受影响合集与合同；
- 完成跨市场、节点、API、Console、CLI 的一致权益判断。

### 第四阶段：开放高级授权商品

- 面向内容类型开放持续更新目录、自动续费、复杂资格和更多补偿方案；
- 用真实争议和履约数据评估模板、默认值和风控门槛；
- 仅在基础合同模型稳定后，才讨论如何让创作者更自由地表达授权规则。

## 3. 现有能力的过渡原则

当前存在资源 `online/offline`、策略开关、版本快照、合集目录草稿、依赖签约和合约只读列表。过渡时应遵守：

1. 不改变既有合同的实际含义，不以新字段回写旧承诺；
2. 先新增可解释状态和视图，再替换旧开关的产品含义；
3. 旧资源下架先映射到“停止新签约”或平台现状允许的最保守行为，不能自动视为彻底撤回；
4. 新的复杂能力必须有端到端闭环：创建、用户确认、状态展示、失败恢复、通知、审计与人工处理；
5. CLI 只消费平台已定稿的产品能力，不在本地缓存合同、付款、资格或权益判断。

## 4. 验收方式：用场景而不是页面验收

每项能力上线前至少要走通以下场景，并由市场、合同页、内容库、创作者管理、API/节点和必要的 CLI 路径给出一致结果：

1. 免费单资源首次签约、使用、到期；
2. 付费 30 天单资源，付款成功、失败、退款和到期；
3. 作者停止新签约后，老用户继续使用、新用户无法签约；
4. 有有效合同时申请完全撤回，进入补救并完成退款或替代交付；
5. 合集签约时选择部分单品，之后作者新增和移除单品；
6. 持续更新合集新增单品、同步失败和移除单品；
7. 同一用户已有 30 天授权，再购买更长周期、商业升级或重复授权；
8. 同一用户待付款、额度耗尽、资格暂停、合集单品重叠或新授权仅价格降低时再签约；
9. 资格在签约前不满足、签约后失效、宽限、恢复和续费；
10. 内容受平台强制限制、当事人收到通知、合同进入补救与申诉；
11. 支付回调、通知发送、撤回申请和退款结果重复到达或暂时失败。

一个场景若只能在某个页面“看起来正确”，但合同历史、交付判断、支付记录或另一产品端不一致，就不能算完成。

## 5. 本设计的边界

本文定义的是平台应该提供什么产品结果和约束；它不指定接口字段、数据库模型、页面组件、策略语法或 CLI 参数。实现设计必须回到本目录逐项证明：用户权益、状态解释、失败恢复、通知和审计均未被破坏。
