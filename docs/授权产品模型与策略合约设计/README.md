# 授权产品模型与策略合约设计

状态：**产品设计讨论中；不实现；不改变当前线上策略、策略模板或 CLI 命令。**

设计中的术语约定：

## 1. 平台要完成的交易

Freelog 的核心产品不是“上传一个文件并设置访问限制”，而是让内容供给方与使用方围绕一项内容达成并履行一份授权交易：

> 授权方把明确内容的明确使用权，以公开、可理解的条件提供给使用方；使用方接受条件后，平台持续保障双方都能知道合同是否有效、内容能否交付、发生问题时如何处理。

这要求平台同时管理内容供给与合同履约。内容可以改名、更新、停止销售或撤回；已经成立的合同不能因此无声消失。

## 2. 参与者与责任

| 角色 | 对用户的承诺 | 平台应保障的边界 |
|---|---|---|
| 授权方 | 提供内容，并按已接受的条件履约 | 不能通过改标题、改展示页、下线策略或编辑合集，倒改已成立合同 |
| 使用方 | 接受条款、提供必要信息、完成付款或其他条件 | 能看到自己拥有什么权利、为什么暂不可用、怎样恢复或申诉 |
| 平台 | 记录承诺、保存合同、验证条件、提供交付与争议处理入口 | 不能把不可追溯的后台当前状态当作改变历史合同的理由 |
| 外部服务 | 提供支付、身份验证、通知等结果 | 结果需要可确认、可追踪；外部服务不能悄悄替平台修改合同 |
| 运营方 | 配置内容类型、支持的授权方式与风控规则 | 运营标签或后台设置不能绕过已成立合同的基本保护 |

## 3. 必须分开的产品对象

| 对象 | 用户能理解的含义 | 不可混淆为 |
|---|---|---|
| **内容类型** | 一类内容可提供什么能力、可按什么范围授权 | 某一个实际资源 |
| **内容** | 一个实际在线上的单资源或合集 | 标题、文件名或本地文件夹 |
| **授权规则** | 授权方愿意按何种条件提供哪些权利的公开规则 | 一次具体签约 |
| **授权发布** | 某条规则被用于某个具体内容后，供用户选择的授权商品 | 通用模板或本地草稿 |
| **授权合同** | 某个使用方接受某个授权发布后形成的独立履约记录 | 授权规则的当前版本 |
| **权利** | 使用方当前真正可做的事，例如浏览、下载、使用 | 会员标签、运营标签或内容标题 |
| **范围** | 权利覆盖整个内容还是其中的明确部分 | 当前合集的可变列表 |
| **条件** | 获得或维持权利需要满足的事实，例如付款、时效、认证 | 平台的猜测或未确认的外部动作 |
| **义务** | 某方需要完成并可被追踪的动作，例如付款、补偿、通知 | 权利本身 |

内容、授权发布、合同和合同中选定的合集单品，都必须使用不可变线上身份关联。标题、简介、标签、排序只是展示信息，可变化、可重复、可同步，但不能作为合同判断依据。

## 4. 用户可感知的完整生命周期

```text
内容发布
  → 授权方为该内容发布授权规则
  → 使用方阅读规则、选择范围并接受
  → 合同成立，平台记录双方选择与当时承诺
  → 使用方履行付款/认证等条件
  → 平台提供当前有效权利对应的内容交付
  → 到期、续费、暂停、恢复、撤回补救或结束
```

### 发布前后

授权规则可以下线，内容可以停止新签约，但这些动作只改变未来交易机会。它们不能撤销已经成立的合同。

### 签约时

使用方必须看到完整的内容、范围、价格/期限、条件、权利和提前终止处理方式。若签约时可选择合集单品、档位或其他选项，平台必须把选择固定到该合同中。

### 履约期间

平台基于可确认的事实判断合同当前是否有效。例如付款确认、资格有效、到期、用户取消、发生违约。每次变化都应能解释发生时间、触发原因、受影响权利及后续处理。

### 结束或异常

合同正常到期后历史仍可查询。无法继续交付、资格失效、支付失败等异常，必须进入预先说明的暂停、宽限、恢复、补偿或解除流程；不能直接从用户视野中消失。

## 5. 单资源与合集的一致性

单资源与合集应共享同一套授权产品模型：内容、授权发布、合同、权利、条件、义务都相同。

- 单资源通常授权整个内容。
- 合集可授权整个合集，也可授权合同成立时明确选定的一组线上单资源。
- 合集成员必须是线上已发布的单资源；本地文件夹只是创作者的工作组织方式，不是合同对象。
- 合集后续新增、移除、排序或改名单品，只影响未来授权。已有合同中的被授权单品范围必须冻结。

因此，“合集部分单品授权”是权利范围问题，不需要创造第二套合同或第二套授权产品。

## 6. 产品必须保证的底线

1. **默认无权利**：任何访问都应能对应一份当前有效合同。
2. **承诺不可倒改**：授权方不能通过编辑内容或下线策略改写已接受条款。
3. **范围不可猜测**：合同明确记录授权的内容和单品，不从当前标题或合集列表推断。
4. **条件可解释**：付款、认证、时间、资格等影响结果时，用户可看到原因和处理状态。
5. **交付不中断或可补救**：停止新签约不影响履约；确实无法交付时必须走补救流程。
6. **历史可追溯**：合同、关键选择、状态变化、补偿与通知结果都保留历史。
7. **展示不改变权益**：标题、翻译、标签、运营文案和搜索展示变化不得改变合同权利。
