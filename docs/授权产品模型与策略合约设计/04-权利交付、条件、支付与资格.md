# 权利交付、条件、支付与资格

## 目标

平台应把“当前能否做某事”变成一项可解释的产品判断，而不是由内容页、支付页、节点或客户端各自猜测。使用方需要知道自己可做什么、限制在哪里、差哪一步；授权方需要知道承诺何时真正生效、何时未履约。

## 1. 权利是合同产生的结果

使用方对一项内容的有效权利由以下共同决定：

```text
存在有效合同
  + 合同包含该能力与范围
  + 本次请求落在合同的版本、地域、用途、设备和额度范围内
  + 生效条件已经满足
  + 合同未到期、未暂停、未解除
  + 内容当前可按该合同交付
  = 当前可行使的权利
```

任何一项不满足时，平台都应返回“不可用原因”，而不是只返回拒绝。

| 结果 | 面向用户的解释示例 | 推荐下一步 |
|---|---|---|
| 尚未签约 | 你尚未取得该内容的下载权 | 查看可用授权发布 |
| 本次请求不在授权范围 | 该合同仅允许在中国大陆取得 `1.x` 版本；你当前请求不符合其中一项 | 更换符合范围的版本/用途/地区；合同仍然有效 |
| 待付款 | 合同已创建，付款确认后生效 | 继续支付、取消或查看超时规则 |
| 资格不满足 | 本授权要求有效的创作者认证 | 查看资格要求、完成认证或申诉 |
| 暂停 | 会员资格已失效，合同处于宽限期 | 恢复资格、查看恢复日期 |
| 内容补救中 | 内容暂时无法交付，正在处理退款或替代方案 | 查看补救进度和申诉入口 |
| 已到期 | 本周期授权已于某日结束 | 续费、重新签约或查看历史 |

## 2. 权利的组成

每一项权利至少包含四部分：

| 部分 | 说明 | 示例 |
|---|---|---|
| 能力 | 使用方可以执行的动作 | 浏览、下载、安装使用、分享、商用使用 |
| 范围 | 动作作用的内容、单品和版本 | 整个图片的全部版本、主题插件 `1.x`、合集的指定 10 个单品 |
| 限制 | 动作的边界 | 30 天、100 次、仅中国大陆、仅个人用途 |
| 依据 | 产生该权利的合同 | 合同号、授权发布、当前状态与生效时间 |

在“我的已授权内容”和内容详情中，平台应该先展示用户真正可用的能力、内容范围和版本范围，再提供合同详情；而不是让用户从规则名或复杂条款自行推断。

## 3. 条件的产品分类

| 条件类别 | 例子 | 谁提供事实 | 影响方式 |
|---|---|---|---|
| 接受条件 | 勾选授权条款、选择单品 | 使用方 | 未完成则合同尚未成立或待确认 |
| 付款条件 | 首期付款、续费付款、补款 | 支付服务与平台账务 | 未确认付款前不生效或进入待支付 |
| 资格条件 | 实名、会员、渠道、年龄 | 平台身份与资格服务 | 可只在签约时检查，也可持续影响合同 |
| 时间条件 | 生效日、到期日、宽限期 | 平台时间服务 | 自动生效、暂停、到期或进入续费窗口 |
| 使用范围 | 次数额度、设备、地域、用途、版本 | 平台交付/使用记录与本次请求环境 | 不在范围内时拒绝该次操作；不改变合同状态 |
| 外部条件 | 关联合同完成、人工审核结果 | 经平台认可的外部服务或人工流程 | 必须记录来源、时间与可申诉性 |

每个授权发布在用户签约前都必须说明：条件何时检查、失败会怎样、是否可恢复、是否有宽限期。产品不能把“持续监听资格变化”当作后台细节而不告知用户。

## 4. 支付与合同应各自有状态

支付是履行合同的一种方式，不是合同本身。推荐状态关系：

```text
合同：待付款 ──支付成功──→ 生效
  │               │
  ├──支付失败─────┘（仍待付款、允许重试或取消）
  └──超时/取消────────→ 已取消或失效

退款：合同补救中 ──退款成功──→ 已解除/已结算
```

平台至少需要做到：

- 创建支付前明确金额、币种、支付用途、对应合同和应得权利；
- 同一笔付款不得因重复回调重复生效；
- 付款成功、失败、撤销、退款、部分退款都有独立可查记录；
- 支付服务故障时，合同不会被错误标为已付款；
- 已付款但交付未开始、交付中断或提前撤回时，可进入合同补救而非丢失订单关联；
- CLI、Console 和节点看到的是同一份平台确认的付款结果，不各自维护“已支付”判断。

## 5. 平台资格的正确位置

平台资格是平台对用户作出的事实认定，例如实名认证、会员等级、创作者身份、渠道身份或风险状态。它不是某个内容的授权，也不能被内容标题或运营标签替代。

对于每种资格，运营产品必须配置：

1. 签发者和撤销者；
2. 生效期、失效期和更新时间；
3. 能用于哪些内容类型和授权发布；
4. 在签约时检查一次，还是在合同期间持续检查；
5. 变化后的合同动作：不影响、暂停、宽限、恢复、禁止续费或解除；
6. 用户可见的说明、纠正与申诉路径。

推荐默认是：资格变化不能静默删除历史合同。它应按已展示的合同规则导致暂停、恢复或后续周期不可续费；涉及风控或法律强制限制时，进入受权限控制的特殊流程。

## 6. 交付与使用记录

内容交付不只是在合同生效时给一个“允许”结果。对下载、安装、播放、调用、分享等动作，平台应根据合同能力、范围和限制作一次可解释判断，并保留与限制有关的最小记录。

记录的目的应限定为：防止重复消耗额度、解释争议、支持退款/补偿计算和保护内容安全；不应借授权检查无边界收集使用方隐私。对于使用记录的保留期限、展示范围和删除/匿名规则，需要纳入平台隐私治理。
