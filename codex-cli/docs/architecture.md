# 架构说明

## 目标
- 落地《脚手架设计.md》中描述的流程，确保离线环境也能完成主要操作。
- 将命令调度与业务逻辑解耦，便于编写测试和扩展功能。
- 优先使用稳定的社区库（axios、archiver、ora、inquirer 等），减少重复造轮子。

## 模块职责
- **CLI 层（`src/cli`）**：参数解析、终端输出、交互式输入、加载动画等。
- **命令层（`src/commands`）**：对外暴露各子命令，完成参数校验并调用对应服务。
- **服务层（`src/services`）**：封装登录、发布、依赖管理、同步、初始化等领域逻辑，负责网络请求与本地存储。
- **配置层（`src/config`）**：提供 `freelog.json` 默认骨架，集中管理环境变量加载。
- **工具层（`src/utils`）**：文件操作、语义化版本、终端表格、选项解析等通用能力。
- **常量层（`src/constants`）**：统一维护路径、数据目录等固定值。

## 数据流
1. `bin/freelog-cli.js` 调用 `src/index.js` 的 `runCli`。
2. `runCli` 使用 `cli/argv` 解析参数，并在命令注册表中匹配目标命令。
3. 命令处理函数调用服务层，服务层通过 axios 访问 Freelog 接口或读取本地配置。
4. `cli/output` 根据输出模式（文本/JSON）渲染结果。

## 测试策略
- 以服务层单元测试为主，结合临时目录模拟文件系统操作。
- CLI 层保留冒烟测试（如 `--help`、参数解析）。
- 后续可在 `codex-cli/__tests__` 中补充更细粒度的用例。

## 后续扩展
- 接入真实接口后，补充更多资源/模板管理能力。
- 增加插件机制，让 CLI 可以按需加载自定义指令。
- 完善日志与遥测，目前仅预留目录结构。
