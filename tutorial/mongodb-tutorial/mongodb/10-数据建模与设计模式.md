# 第十章：MongoDB 数据建模与设计模式

## 10.1 数据建模原则

### MongoDB 与关系型数据库的区别

| 关系型数据库 | MongoDB |
|------------|---------|
| 规范化设计 | 反规范化设计 |
| 表结构固定 | 文档结构灵活 |
| JOIN 操作 | 嵌入或应用层 JOIN |
| ACID 事务 | 单文档 ACID，多文档需要副本集 |
| 垂直扩展 | 水平扩展 |

### 核心设计原则

1. **根据查询模式设计**：数据结构应该匹配应用如何访问数据
2. **嵌入 vs 引用**：根据数据关系和使用模式选择
3. **避免过度嵌套**：嵌套层级不超过 3-4 层
4. **考虑文档大小**：单个文档不超过 16MB
5. **预聚合数据**：提前计算常用统计信息

## 10.2 嵌入 vs 引用决策树

### 何时使用嵌入（Embedding）

✅ **使用嵌入的场景：**

1. **一对一关系**
   ```javascript
   // 用户和用户配置：一对一
   {
     _id: ObjectId("..."),
     name: "张三",
     profile: {
       avatar: "avatar.jpg",
       bio: "个人简介",
       preferences: { theme: "dark" }
     }
   }
   ```

2. **一对少关系（子文档数量少且固定）**
   ```javascript
   // 订单和订单项：一对少
   {
     _id: ObjectId("..."),
     orderNumber: "ORD001",
     items: [
       { productId: "prod1", quantity: 2, price: 100 },
       { productId: "prod2", quantity: 1, price: 50 }
     ],
     total: 250
   }
   ```

3. **数据访问模式是读取整个文档**
   ```javascript
   // 博客文章和评论：总是同时读取
   {
     _id: ObjectId("..."),
     title: "MongoDB 教程",
     content: "...",
     comments: [
       { author: "用户1", text: "好文章", date: ISODate("...") },
       { author: "用户2", text: "学习了", date: ISODate("...") }
     ]
   }
   ```

4. **子文档不会单独查询**
   ```javascript
   // 用户和地址：地址不会单独查询
   {
     _id: ObjectId("..."),
     name: "张三",
     addresses: [
       { type: "home", city: "北京", street: "..." },
       { type: "work", city: "上海", street: "..." }
     ]
   }
   ```

### 何时使用引用（Referencing）

✅ **使用引用的场景：**

1. **一对多关系（子文档数量多）**
   ```javascript
   // 用户和订单：一个用户可能有成千上万个订单
   // users 集合
   {
     _id: ObjectId("user123"),
     name: "张三"
   }
   
   // orders 集合
   {
     _id: ObjectId("order1"),
     userId: ObjectId("user123"),
     total: 100
   }
   {
     _id: ObjectId("order2"),
     userId: ObjectId("user123"),
     total: 200
   }
   ```

2. **多对多关系**
   ```javascript
   // 学生和课程：多对多关系
   // students 集合
   {
     _id: ObjectId("student1"),
     name: "学生1",
     courseIds: [ObjectId("course1"), ObjectId("course2")]
   }
   
   // courses 集合
   {
     _id: ObjectId("course1"),
     name: "数学",
     studentIds: [ObjectId("student1"), ObjectId("student2")]
   }
   ```

3. **子文档需要单独查询**
   ```javascript
   // 文章和评论：评论需要单独查询和分页
   // articles 集合
   {
     _id: ObjectId("article1"),
     title: "文章标题"
   }
   
   // comments 集合
   {
     _id: ObjectId("comment1"),
     articleId: ObjectId("article1"),
     author: "用户1",
     text: "评论内容"
   }
   ```

4. **子文档会被多个父文档引用**
   ```javascript
   // 多个订单引用同一个产品
   // products 集合
   {
     _id: ObjectId("product1"),
     name: "商品A",
     price: 100
   }
   
   // orders 集合
   {
     _id: ObjectId("order1"),
     items: [{ productId: ObjectId("product1"), quantity: 2 }]
   }
   {
     _id: ObjectId("order2"),
     items: [{ productId: ObjectId("product1"), quantity: 1 }]
   }
   ```

5. **子文档频繁更新**
   ```javascript
   // 用户和活动日志：日志频繁更新
   // users 集合
   {
     _id: ObjectId("user1"),
     name: "张三"
   }
   
   // activity_logs 集合
   {
     _id: ObjectId("log1"),
     userId: ObjectId("user1"),
     action: "login",
     timestamp: ISODate("...")
   }
   ```

## 10.3 常见设计模式

### 模式 1：子集模式（Subset Pattern）

**场景**：集合很大，但经常只访问部分数据

```javascript
// 主文档：存储完整信息
{
  _id: ObjectId("movie1"),
  title: "电影标题",
  fullCast: [
    { name: "演员1", role: "主角", ... },
    { name: "演员2", role: "配角", ... },
    // ... 100+ 演员
  ],
  reviews: [
    // ... 1000+ 评论
  ]
}

// 子集文档：只存储常用数据
{
  _id: ObjectId("movie1"),
  title: "电影标题",
  topCast: [
    { name: "演员1", role: "主角" },
    { name: "演员2", role: "配角" }
  ],
  recentReviews: [
    // ... 最近 10 条评论
  ]
}
```

**优点**：减少内存占用，提高查询性能

### 模式 2：扩展引用模式（Extended Reference Pattern）

**场景**：需要引用其他集合，但也要存储一些常用字段

```javascript
// 订单文档：引用用户，但也存储用户常用信息
{
  _id: ObjectId("order1"),
  userId: ObjectId("user123"),  // 引用
  userSnapshot: {  // 快照
    name: "张三",
    email: "zhangsan@example.com"
  },
  items: [...],
  total: 250
}
```

**优点**：避免频繁 JOIN，提高查询性能

### 模式 3：预聚合模式（Pre-Aggregation Pattern）

**场景**：需要频繁计算统计数据

```javascript
// 产品文档：预聚合销售数据
{
  _id: ObjectId("product1"),
  name: "商品A",
  price: 100,
  // 预聚合数据
  salesStats: {
    totalSales: 1000,
    totalRevenue: 100000,
    averageRating: 4.5,
    reviewCount: 200,
    lastUpdated: ISODate("...")
  }
}

// 更新时同时更新预聚合数据
db.products.updateOne(
  { _id: ObjectId("product1") },
  {
    $inc: {
      "salesStats.totalSales": 1,
      "salesStats.totalRevenue": 100,
      "salesStats.reviewCount": 1
    },
    $set: {
      "salesStats.lastUpdated": new Date()
    }
  }
)
```

**优点**：避免实时计算，提高查询性能

### 模式 4：桶模式（Bucket Pattern）

**场景**：时间序列数据，如传感器数据、日志等

```javascript
// 每小时一个桶
{
  _id: ObjectId("..."),
  sensorId: "sensor001",
  startTime: ISODate("2024-01-01T00:00:00Z"),
  endTime: ISODate("2024-01-01T01:00:00Z"),
  measurements: [
    { timestamp: ISODate("..."), value: 25.5 },
    { timestamp: ISODate("..."), value: 26.0 },
    // ... 最多 1000 个测量值
  ],
  // 预聚合统计
  stats: {
    min: 25.5,
    max: 26.0,
    avg: 25.75,
    count: 1000
  }
}
```

**优点**：减少文档数量，提高查询效率

### 模式 5：计算字段模式（Computed Field Pattern）

**场景**：需要根据其他字段计算的值

```javascript
// 用户文档：存储计算字段
{
  _id: ObjectId("user1"),
  firstName: "张",
  lastName: "三",
  fullName: "张三",  // 计算字段
  email: "zhangsan@example.com",
  domain: "example.com",  // 从 email 提取
  age: 25,
  birthYear: 1999,  // 从 age 计算
  isAdult: true  // 从 age 计算
}
```

**优点**：避免重复计算，提高查询性能

### 模式 6：版本控制模式（Versioning Pattern）

**场景**：需要保留历史版本

```javascript
// 当前版本
{
  _id: ObjectId("product1"),
  version: 3,
  name: "商品A v3",
  price: 100,
  current: true
}

// 历史版本
{
  _id: ObjectId("product1_v1"),
  version: 1,
  name: "商品A v1",
  price: 80,
  current: false,
  replacedBy: ObjectId("product1_v2")
}
```

### 模式 7：树形结构模式（Tree Pattern）

**场景**：层级数据，如分类、组织架构

#### 方法 1：父引用模式

```javascript
{
  _id: ObjectId("category1"),
  name: "电子产品",
  parentId: null,
  path: "/category1"
}

{
  _id: ObjectId("category2"),
  name: "手机",
  parentId: ObjectId("category1"),
  path: "/category1/category2"
}
```

#### 方法 2：子引用模式

```javascript
{
  _id: ObjectId("category1"),
  name: "电子产品",
  children: [
    ObjectId("category2"),
    ObjectId("category3")
  ]
}
```

#### 方法 3：数组祖先模式

```javascript
{
  _id: ObjectId("category2"),
  name: "手机",
  ancestors: [
    ObjectId("category1"),  // 根分类
    ObjectId("category2")   // 自己
  ],
  parentId: ObjectId("category1")
}
```

## 10.4 实际项目建模案例

### 案例 1：电商系统

```typescript
// 用户模型
@EntityModel()
export class User {
  @Prop({ required: true, unique: true })
  public userId: string;

  @Prop({ required: true })
  public name: string;

  @Prop({ required: true, unique: true })
  public email: string;

  // 嵌入：用户配置（一对一）
  @Prop({ type: () => Object })
  public profile: {
    avatar: string;
    bio: string;
    preferences: {
      theme: string;
      language: string;
    };
  };

  // 嵌入：常用地址（一对少）
  @Prop({ type: () => Array })
  public addresses: Array<{
    type: string;
    city: string;
    street: string;
    isDefault: boolean;
  }>;
}

// 订单模型（引用用户）
@EntityModel()
export class Order {
  @Prop({ required: true, ref: () => User })
  public userId: Ref<User>;

  // 扩展引用：用户快照
  @Prop({ type: () => Object })
  public userSnapshot: {
    name: string;
    email: string;
  };

  // 嵌入：订单项（一对少）
  @Prop({ type: () => Array })
  public items: Array<{
    productId: string;
    productSnapshot: {
      name: string;
      price: number;
    };
    quantity: number;
    price: number;
  }>;

  // 预聚合：订单统计
  @Prop({ type: () => Object })
  public totals: {
    subtotal: number;
    tax: number;
    shipping: number;
    total: number;
  };

  @Prop({ type: () => Date, default: Date.now })
  public createdAt: Date;
}
```

### 案例 2：内容管理系统

```typescript
// 文章模型
@EntityModel()
export class Article {
  @Prop({ required: true })
  public title: string;

  @Prop({ required: true })
  public content: string;

  // 嵌入：最近评论（子集模式）
  @Prop({ type: () => Array })
  public recentComments: Array<{
    author: string;
    text: string;
    createdAt: Date;
  }>;

  // 预聚合：评论统计
  @Prop({ type: () => Object })
  public commentStats: {
    totalCount: number;
    lastUpdated: Date;
  };

  @Prop({ type: () => Date, default: Date.now })
  public createdAt: Date;
}

// 评论模型（引用文章）
@EntityModel()
export class Comment {
  @Prop({ required: true, ref: () => Article })
  public articleId: Ref<Article>;

  @Prop({ required: true })
  public author: string;

  @Prop({ required: true })
  public text: string;

  @Prop({ type: () => Date, default: Date.now })
  public createdAt: Date;
}
```

## 10.5 建模最佳实践

### 1. 文档大小限制

```javascript
// ❌ 差：文档可能超过 16MB
{
  _id: ObjectId("..."),
  items: [
    // ... 10000+ 项
  ]
}

// ✅ 好：使用引用或分页
{
  _id: ObjectId("..."),
  itemIds: [ObjectId("..."), ...],
  totalItems: 10000
}
```

### 2. 避免深度嵌套

```javascript
// ❌ 差：嵌套层级太深
{
  level1: {
    level2: {
      level3: {
        level4: {
          level5: { value: "..." }
        }
      }
    }
  }
}

// ✅ 好：扁平化或使用引用
{
  "level1.level2.level3.level4.level5.value": "..."
}
```

### 3. 考虑查询模式

```javascript
// 根据查询模式设计索引
// 查询：按用户和日期查询订单
db.orders.createIndex({ userId: 1, createdAt: -1 });

// 查询：按产品查询订单
db.orders.createIndex({ "items.productId": 1 });
```

### 4. 使用合适的数据类型

```javascript
// ✅ 好：使用 ObjectId 引用
{
  userId: ObjectId("...")
}

// ❌ 差：使用字符串引用（占用更多空间）
{
  userId: "507f1f77bcf86cd799439011"
}
```

## 10.6 数据迁移策略

### 从嵌入迁移到引用

```javascript
// 1. 创建新集合
db.comments.insertMany([
  { articleId: ObjectId("..."), text: "...", author: "..." }
]);

// 2. 从原文档提取数据
db.articles.find({}).forEach(function(article) {
  article.comments.forEach(function(comment) {
    db.comments.insert({
      articleId: article._id,
      text: comment.text,
      author: comment.author,
      createdAt: comment.createdAt
    });
  });
});

// 3. 更新原文档（可选）
db.articles.updateMany(
  {},
  { $unset: { comments: "" } }
);
```

### 从引用迁移到嵌入

```javascript
// 1. 聚合关联数据
const articlesWithComments = db.articles.aggregate([
  {
    $lookup: {
      from: "comments",
      localField: "_id",
      foreignField: "articleId",
      as: "comments"
    }
  }
]);

// 2. 更新文档
articlesWithComments.forEach(function(article) {
  db.articles.updateOne(
    { _id: article._id },
    { $set: { comments: article.comments } }
  );
});
```
