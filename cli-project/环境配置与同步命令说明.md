## 🌍 一、环境配置

### 1. 支持的环境

Freelog CLI 支持两种环境：

| 环境 | 说明 | API 地址 |
|------|------|----------|
| **测试环境** (development) | 用于开发和测试 | `http://api.testfreelog.com` |
| **生产环境** (production) | 正式环境，默认 | `https://api.freelog.com` |

### 2. 如何切换环境

#### 方法一：设置环境变量

**Windows (CMD)**
```cmd
set FREELOG_ENV=development
freelog-cli login
```

**Windows (PowerShell)**
```powershell
$env:FREELOG_ENV="development"
freelog-cli login
```

**Linux/Mac**
```bash
export FREELOG_ENV=development
freelog-cli login
```

#### 方法二：使用 NODE_ENV

```bash
# Linux/Mac
export NODE_ENV=development

# Windows PowerShell
$env:NODE_ENV="development"
```

#### 方法三：创建 .env 文件

在项目根目录创建 `.env` 文件：

```env
# 开发环境
FREELOG_ENV=development

# 或使用自定义 API 地址
FREELOG_API_URL=http://api.testfreelog.com
```

### 3. 环境优先级

1. **FREELOG_API_URL** - 最高优先级，自定义 API 地址
2. **FREELOG_ENV** - 选择预设环境
3. **NODE_ENV** - 作为备选
4. **默认** - 生产环境

### 4. 查看当前环境

```bash
# Linux/Mac
echo $FREELOG_ENV

# Windows PowerShell
echo $env:FREELOG_ENV

# 或使用 Node.js
node -e "console.log(process.env.FREELOG_ENV || 'production')"
```

## 🔄 二、Sync 命令详解

### 1. 命令功能

`sync` 命令用于同步线上资源信息到本地 `freelog.json` 配置文件。

### 2. freelog.json 文件格式

```json
{
  "version": "1.3.2",
  "workId": "6768d232d83d52002f6b0f59",
  "name": "vue3-theme",
  "publishPath": "dist",
  "baseUpcastResources": [],
  "dependencies": [],
  "resolveResources": [],
  "inputAttrs": [],
  "customPropertyDescriptors": [
    {
      "type": "readonlyText",
      "key": "aab",
      "name": "补充属性",
      "remark": "补充属性说明",
      "defaultValue": "默认值"
    }
  ],
  "description": "资源描述"
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | string | 当前版本号 |
| `workId` | string | 资源ID（必需） |
| `name` | string | 资源名称 |
| `publishPath` | string | 发布路径，默认 "dist" |
| `description` | string | 资源描述 |
| `dependencies` | array | 依赖列表 |
| `baseUpcastResources` | array | 基础上抛资源 |
| `resolveResources` | array | 解决资源 |
| `customPropertyDescriptors` | array | 自定义属性 |
| `inputAttrs` | array | 输入属性 |

## 📖 三、使用方法

### 1. 初始化配置文件

从线上资源创建本地配置文件。

```bash
# 基本用法
freelog-cli sync <resourceIdOrName>

# 示例：使用资源名称
freelog-cli sync vue3-theme

# 示例：使用资源ID
freelog-cli sync 6768d232d83d52002f6b0f59

# 指定版本
freelog-cli sync vue3-theme@1.3.2
```

**执行流程**：
1. 🔍 调用 API 获取资源信息
2. 📦 获取指定版本的详细信息
3. 📝 创建 `freelog.json` 配置文件
4. ✅ 如果文件已存在，询问是否覆盖

**输出示例**：
```
初始化项目配置
资源: vue3-theme
版本: 1.3.2
✓ 资源信息获取成功
✓ 配置文件创建成功!
✓ 资源: vue3-theme
✓ workId: 6768d232d83d52002f6b0f59
✓ 版本: 1.3.2
ℹ 配置文件已保存到: freelog.json
```

### 2. 同步作品信息

更新本地配置文件中的作品基本信息。

```bash
freelog-cli sync --work
# 或
freelog-cli sync -w
```

**同步内容**：
- 资源名称 (`name`)
- 资源描述 (`description`)

### 3. 同步所有信息

同步资源的所有信息，包括版本、依赖、属性等。

```bash
# 同步最新版本
freelog-cli sync --all

# 同步指定版本
freelog-cli sync --all --version 1.3.2

# 强制覆盖（不合并，完全替换）
freelog-cli sync --all --force
```

**同步内容**：
- 版本号
- 资源名称
- 资源描述
- 依赖列表
- 基础上抛资源
- 解决资源
- 自定义属性

**输出示例**：
```
同步所有信息 (版本: latest)
✓ 所有信息同步成功
✓ 版本: 1.3.2
✓ 依赖: 2 个
✓ 自定义属性: 4 个
```

### 4. 同步部分信息

只同步特定的信息类别。

```bash
# 同步自定义属性
freelog-cli sync --props

# 同步依赖配置
freelog-cli sync --config

# 同步描述信息
freelog-cli sync --changelog

# 组合使用
freelog-cli sync --props --config --version 1.3.2
```

**选项说明**：

| 选项 | 简写 | 说明 |
|------|------|------|
| `--props` | | 同步自定义属性 |
| `--config` | | 同步依赖配置 |
| `--changelog` | | 同步描述信息 |
| `--version <version>` | `-v` | 指定版本号 |

### 5. 交互式同步

不带参数运行，进入交互式模式。

```bash
freelog-cli sync
```

**交互流程**：

```
同步配置
当前资源: vue3-theme

? 请选择要同步的内容: (按空格选择，回车确认)
  ✓ 作品基本信息
  ✓ 自定义属性
  ✓ 依赖配置
    描述信息

? 请输入版本号（留空使用最新版本）: latest

正在同步...
✓ 同步成功
✓ 已同步 3 项内容
✓ 版本: 1.3.2
```

## 🔧 四、完整使用示例

### 示例 1：在测试环境开发

```bash
# 第一步：设置测试环境
export FREELOG_ENV=development

# 第二步：登录测试环境
freelog-cli login -g

# 第三步：从测试环境初始化项目
freelog-cli sync my-test-resource

# 第四步：查看配置
cat freelog.json

# 第五步：发布草稿到测试环境
npm run build
freelog-cli publish --draft
```

### 示例 2：同步生产环境资源

```bash
# 第一步：确保使用生产环境（默认）
export FREELOG_ENV=production

# 第二步：登录
freelog-cli login -g

# 第三步：初始化配置
freelog-cli sync vue3-theme

# 第四步：开发...

# 第五步：同步最新信息
freelog-cli sync --all

# 第六步：发布
npm run build
freelog-cli publish --patch -m "更新功能"
```

### 示例 3：更新项目依赖

```bash
# 同步最新的依赖配置
freelog-cli sync --config --version latest

# 查看更新的依赖
cat freelog.json | grep -A 10 "dependencies"

# 测试发布
freelog-cli publish --draft
```

### 示例 4：多环境切换工作流

```bash
# === 测试环境开发 ===
export FREELOG_ENV=development
freelog-cli login -g
freelog-cli sync test-resource
npm run build
freelog-cli publish --draft

# === 切换到生产环境 ===
export FREELOG_ENV=production
freelog-cli login -g
freelog-cli sync prod-resource
npm run build
freelog-cli publish --patch -m "正式发布"
```

## ⚠️ 五、注意事项

### 1. workId 必需

`freelog.json` 中的 `workId` 是必需的：

```json
{
  "workId": "6768d232d83d52002f6b0f59",  // 必需！
  "name": "my-theme",
  // ...
}
```

**如何获取 workId**：
- 方法1：使用 `sync` 命令自动获取
- 方法2：从 Freelog 平台复制资源ID
- 方法3：查看资源 URL（包含 workId）

### 2. 环境隔离

测试环境和生产环境的资源是分开的：

- ✅ 测试环境的资源只在测试环境可见
- ✅ 生产环境的资源只在生产环境可见
- ⚠️ 确保切换环境时也切换对应的资源

### 3. 版本管理

```bash
# ✅ 好的做法
freelog-cli sync --all --version 1.3.2  # 明确版本

# ⚠️ 注意
freelog-cli sync --all  # 使用 latest，可能会覆盖本地修改
```

### 4. 配置合并 vs 覆盖

```bash
# 默认：合并模式（保留本地未同步的字段）
freelog-cli sync --all

# 强制覆盖模式（完全替换为线上配置）
freelog-cli sync --all --force
```

## ❓ 六、常见问题

### Q1: 如何知道当前使用的是哪个环境？

```bash
# 查看环境变量
echo $FREELOG_ENV  # Linux/Mac
echo $env:FREELOG_ENV  # Windows PowerShell

# 或查看 API 地址
node -e "const {getApiBaseURL} = require('./src/constants/config'); console.log(getApiBaseURL())"
```

### Q2: sync 命令提示"资源不存在"？

**可能原因**：
1. 资源ID/名称错误
2. 环境不匹配（测试环境的资源在生产环境不存在）
3. 未登录或 Token 过期

**解决方案**：
```bash
# 1. 检查环境
echo $FREELOG_ENV

# 2. 重新登录
freelog-cli login -g

# 3. 确认资源名称/ID
freelog-cli sync <正确的resourceIdOrName>
```

### Q3: 同步后本地修改被覆盖了？

使用 `--force` 会完全覆盖本地配置。

**避免方法**：
```bash
# ✅ 只同步需要的部分
freelog-cli sync --props

# ✅ 或不使用 --force（默认合并模式）
freelog-cli sync --all
```

### Q4: 如何在不同环境使用不同的配置文件？

可以创建多个配置文件：

```bash
# 测试环境配置
cp freelog.json freelog.test.json

# 生产环境配置
cp freelog.json freelog.prod.json

# 发布时指定配置
freelog-cli publish --config freelog.test.json
```

### Q5: CI/CD 中如何使用？

**GitHub Actions 示例**：

```yaml
name: Deploy

on:
  push:
    branches: [main, develop]

jobs:
  deploy-test:
    if: github.ref == 'refs/heads/develop'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      
      - name: Install Dependencies
        run: npm install
      
      - name: Login to Freelog Test
        env:
          FREELOG_ENV: development
        run: |
          freelog-cli login -u ${{ secrets.TEST_USER }} -p ${{ secrets.TEST_PASS }}
      
      - name: Build and Publish Draft
        env:
          FREELOG_ENV: development
        run: |
          npm run build
          freelog-cli publish --draft

  deploy-prod:
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      
      - name: Install Dependencies
        run: npm install
      
      - name: Login to Freelog Prod
        env:
          FREELOG_ENV: production
        run: |
          freelog-cli login -u ${{ secrets.PROD_USER }} -p ${{ secrets.PROD_PASS }}
      
      - name: Build and Publish
        env:
          FREELOG_ENV: production
        run: |
          npm run build
          freelog-cli publish --patch -m "Release ${{ github.sha }}"
```
