## ✨ 核心功能更新

### 1️⃣ Token 加密存储功能

#### 功能描述
实现了完整的 Token 加密存储和自动解密机制，保护用户登录凭证安全。

#### 技术细节
- **加密算法**: AES-256-CBC
- **密钥长度**: 256位
- **IV长度**: 128位（每次随机生成）
- **存储格式**: `iv:encryptedData`

#### 实现内容
✅ 新增加密工具模块 `src/utils/crypto.js`
- `encrypt(text)` - 加密文本
- `decrypt(encryptedText)` - 解密文本
- `encryptObject(obj)` - 加密对象
- `decryptObject(str)` - 解密对象

✅ 更新认证模块 `src/core/auth.js`
- `saveAuth()` - 保存时自动加密 Token
- `getAuth()` - 读取时自动解密 Token
- `getCurrentToken()` - 获取当前有效的解密 Token

#### 安全特性
🔒 Token 加密存储，防止明文泄露
🔒 随机 IV，相同 Token 每次加密结果不同
🔒 仅在内存中解密，不写入磁盘
🔒 自动过期检查，默认 30 天有效期

### 2️⃣ 双重登录机制

#### 功能描述
支持全局登录和工作空间登录两种模式，灵活适应不同使用场景。

#### 登录模式

**🌍 全局登录**
```bash
freelog-cli login -g
freelog-cli login --global
```
- 存储位置: `~/.freelog-cli/auth.json`
- 适用场景: 个人开发，单一账号
- 作用范围: 所有项目

**📁 工作空间登录**
```bash
freelog-cli login
```
- 存储位置: `<项目目录>/.freelog/auth.json`
- 适用场景: 团队协作，多账号切换
- 作用范围: 当前项目

#### 优先级规则
1. 优先使用工作空间 Token
2. 工作空间无 Token 时使用全局 Token
3. 都没有则提示登录

#### 使用示例

**交互式登录**
```bash
freelog-cli login
# 提示输入用户名
# 提示输入密码
```

**命令行登录**
```bash
freelog-cli login -u your-email@example.com -p your-password
freelog-cli login -g -u your-email@example.com -p your-password
```

**查看登录状态**
```bash
freelog-cli status
```

**退出登录**
```bash
freelog-cli logout          # 退出工作空间登录
freelog-cli logout -g       # 退出全局登录
freelog-cli logout --all    # 退出所有登录
```

### 3️⃣ 发布功能整合

#### 功能描述
整合旧版 CLI 的发布逻辑，使用正确的 Freelog API 端点和数据格式，实现完整的发布流程。

#### 发布流程

**第一步：文件打包**
- 使用 AdmZip 压缩构建目录
- 支持文件夹和文件混合
- 保存到临时目录 `~/.freelog-cli/temp/`

**第二步：文件上传**
- API: `http://api.testfreelog.com/v2/storages/files/upload`
- 使用 FormData 上传
- 显示上传进度
- 获取文件 SHA1

**第三步：发布版本**
- 草稿: `https://api.testfreelog.com/v2/resources/{workId}/versions/drafts`
- 正式: `http://api.testfreelog.com/v2/resources/{workId}/versions`
- 自动处理自定义属性
- 支持版本管理

**第四步：清理临时文件**
- 自动删除临时压缩包
- 错误不影响发布结果

#### 版本管理

**自动递增**
```bash
freelog-cli publish --patch    # 1.0.0 -> 1.0.1
freelog-cli publish --minor    # 1.0.0 -> 1.1.0
freelog-cli publish --major    # 1.0.0 -> 2.0.0
```

**交互式选择**
```bash
freelog-cli publish
# 1. 保持当前版本
# 2. 补丁版本递增 (patch)
# 3. 次版本递增 (minor)
# 4. 主版本递增 (major)
# 5. 手动输入版本号
```

#### 发布模式

**🔖 草稿发布**
```bash
freelog-cli publish --draft
freelog-cli publish -d
```
- 保存为草稿，不对外发布
- 可以反复修改
- 适合开发测试阶段

**🚀 正式发布**
```bash
freelog-cli publish
freelog-cli publish -m "版本更新说明"
```
- 正式对外发布
- 不可修改，只能发新版本
- 适合生产环境

#### 使用示例

**基本发布**
```bash
# 进入项目目录
cd my-project

# 执行构建
npm run build

# 发布草稿
freelog-cli publish --draft

# 发布正式版本（补丁递增）
freelog-cli publish --patch -m "修复了一些bug"
```

**使用现有文件**
```bash
freelog-cli publish --file ./dist/my-resource.zip
freelog-cli publish --packagePath ./dist/my-resource.zip
```

**自定义配置**
```bash
freelog-cli publish --config ./custom-freelog.json
```

## ⚠️ 注意事项

### 必需配置
❗ 发布前必须在 `freelog.json` 中配置 `workId`
❗ 确保构建目录（`dist`）存在
❗ 登录后 Token 有效期为 30 天

### 安全建议
🔐 不要将 `auth.json` 提交到版本控制
🔐 定期更换密码
🔐 Token 过期后重新登录
🔐 工作空间 `auth.json` 已自动加入 `.gitignore`

### 常见问题

**Q: 登录后提示未登录？**
A: Token 可能已过期，请重新登录

**Q: 发布失败提示 workId 不存在？**
A: 请在 `freelog.json` 中添加 `workId` 字段

**Q: 构建目录不存在？**
A: 请先执行 `npm run build` 生成构建文件

**Q: 文件上传失败？**
A: 检查网络连接，或文件大小是否超过限制（100MB）

**Q: 如何查看当前登录状态？**
A: 执行 `freelog-cli status`
