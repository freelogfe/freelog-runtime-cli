# CLI 代码边界

产品规则见[正式设计](../../../docs/一期/产品方案/脚手架设计/README.md)，交付流程见[研发规范](../../../docs/研发交付规范/README.md)。此文件解释目录，不另定产品。

| 目录 | 职责 | 需要避免 |
|---|---|---|
| `bin/` | 装配 Commander、环境/资源路由、顶层错误出口 | 在注册树中实现发行规则；导入 index 触发真正 CLI 来做只读检查 |
| `commands/` | 解析输入、交互、调用领域入口、展示结果 | 自行发平台请求或复制业务校验 |
| `domain/` | 账号/初始化/单资源/合集等场景编排和规则 | 用 API 成功替代完整业务成功；越过恢复、身份和环境门禁 |
| `local/` | 身份、工作稿、锁、事务与未决记录 | 把标题当 ID；把工作稿变版本库；异常时丢数据 |
| `platform/` | tools-lib 适配、环境和凭据装配 | 再造一套 HTTP API；把读写 DTO 视为同一结构 |
| `core/` | 参数、交互、错误等小型公共能力 | 为单一例子增加通用框架；让公共工具反向依赖具体场景 |

领域层可以按流程拆模块，共享模块需有真实复用点。单资源和合集共享能力发生变化时，两边分别验证，不用“一边调用成功”代替另一边。

只读注册树检查调用 `program.ts` 的 `createProgram()`，不执行 parse；`bin/index.ts` 会装配环境并执行命令，不是检查 API。

注释说明业务依据、不可见副作用、失败保留和为何采用该方案；不写“这里处理数据”一类复述。产品约束的变化先改设计；技术重构先列保留行为和回归，不因处于开发期降低验证标准。

## 仓库级质量工具

- `scripts/quality/`：离线文档/脚本/明显秘密检查；其负例在 `test/quality/`。
- `scripts/release/`：固定候选、内容指纹、安装验证与发布边界，不承担业务规则。
- `test/acceptance/`：预期清单、结果协议、候选 bin 解析；旧脚本结果不冒充完整业务覆盖。
- `test/*.mjs`：实际 dev 场景和观测器。观测器可经 tools-lib 只读核对，被测 CLI 必须是报告绑定的安装包。

工具结果、未实现覆盖、平台阻塞和产品失败分别记录；规范工具本身通过不代表 CLI 所有功能通过。
