## 1. 单品首次发布

**目标**：从零到上架（严格 online）。

| Console | CLI |
|---------|-----|
| Step1 创建 | `create` |
| Step2 文件+首版 | `updateVersion` → `publish` |
| Step3 策略 | `policy add --from-file` |
| Step4 meta + **软上架** | `update` + **`online`（严格，非 soft status:1）** |

```bash
freelog-cli login
freelog-cli init my-theme && cd my-theme
pnpm install && pnpm build

freelog-cli create --type <code> --title "我的主题" --name my-theme --yes
freelog-cli updateVersion --version 1.0.0 --description "初始版本" --filePath ./dist
freelog-cli publish --yes
freelog-cli policy add --from-file ./policy.json --yes
freelog-cli update --intro "介绍" --tags "Vue,主题" --cover ./cover.png --yes
freelog-cli online --yes
```

| 规则 | 说明 |
|------|------|
| Owner | `create` 写入；后续写命令 `ensureOwner` |
| 不可变 | `resourceName` / `resourceTypeCode` 创建后不可改 |
| 首版 | `version` 固定 `1.0.0`；`updateVersion` 只写本地，`publish` 才 createVersion |
| 授权 | 未完成 → publish exit 5 + Console hint |
| online | **严格** resourceOnline：须有 latestVersion + ≥1 启用策略；**禁止**用 `update(status:1)` 冒充 |
| 策略文件 | `policy.json` 最小 schema 见 [开发命令规格 §6](../开发设计/02-命令规格.md)；可视化在 Console Builder 导出后落盘 |

API：`create` → upload+`createVersion` → `update`(policies) → `update`(listing) → **resourceOnline**。

## 2. 单品发新版

**目标**：在线上最新之上发更高版本。

```bash
pnpm build
freelog-cli status
freelog-cli pull                                          # 落后时默认也可 auto-pull
freelog-cli updateVersion --version 1.3.0 --description "新功能" --filePath ./dist
freelog-cli publish --yes
# 或：freelog-cli publish --bump patch --yes
```

| 规则 | 说明 |
|------|------|
| 版本 | `semver.valid` 且 `> latest` |
| 冻结 / 合集 | `(status&2)===2` 或 `subjectType===4` → 拒绝单品 publish |
| 只改说明 | `version edit`（不升版本、不换文件） |

### 跨端草稿（可选，不正式发行时）

```bash
freelog-cli updateVersion --version 1.3.0 --filePath ./dist --description "WIP"
freelog-cli draft push --yes
# Console versionCreator 续编…
freelog-cli draft pull
freelog-cli publish --yes
```

#### 仅打开过 Console 发版页（防抖已写远端草稿）

从未 `draft push`，但 Console Step2/versionCreator 的 300ms 防抖可能已 `saveVersionsDraft`：

```bash
freelog-cli status
# 平台发版草稿: 有；localDraftSync 空或不匹配
freelog-cli draft pull                 # 以 Console 草稿为准
# 或：freelog-cli draft push --force   # 以本地意图覆盖远端
# 或：freelog-cli draft discard
freelog-cli publish --yes
```

规格与决策树：[开发设计/04-草稿转换层.md](../开发设计/04-草稿转换层.md) · [05 对照 §8](./05-Console与CLI对照.md)。

### 策略作者路径（Builder → 文件）

1. Console 策略页用 fPolicyBuilder3 编好策略  
2. 导出 / 复制最终 `policyText`（及 policyName）  
3. 落盘 `policy.json`（schema 见开发命令规格）  
4. `freelog-cli policy add --from-file ./policy.json --yes`  

CLI **不做** Builder。

## 3. 改 listing / 策略 / 依赖 / 上下架

```bash
freelog-cli pull
freelog-cli update --title "新标题" --intro "…" --tags "a,b" --cover ./cover.png --yes
freelog-cli policy add --from-file ./policy.json --yes
freelog-cli policy list --json
freelog-cli dep add <id> -v "^1.0.0"
freelog-cli updateVersion --version 1.4.0 --filePath ./dist
freelog-cli publish --yes          # 依赖变更随新版；未授权 exit 5
freelog-cli online --yes           # 严格；无 soft online
freelog-cli offline --yes
```

| 规则 | 说明 |
|------|------|
| 标签 | ≤20 个，单标 ≤20 |
| 已上架 | 不能关掉最后一条启用策略 |
| 冻结 | 写命令拒绝；不解冻 |
| online | 仅严格 resourceOnline；Console 软上架资源若缺门禁，CLI `online` 仍拒 |
| contract | `contract list` 为 P2，不是依赖签约入口 |

## 4. 多文件一次发行

**目标**：文件夹内多文件全部作成单品并首版发行（无 batch 命令面）。

```bash
cd photos
freelog-cli create --from-dir . --type <code> --title-prefix "照片" --yes
freelog-cli update --cwd ./a --tags "风景" --yes
```

| 规则 | 说明 |
|------|------|
| 对外 | 仅 `create --from-dir` |
| 对内 | `createBatch` 或循环 create+publish（对用户透明） |
| 落盘 | 每文件一子目录 + owner config；无 batch-resources.config |
| 约束 | 同类型；最多 20；首版 1.0.0 |

## 5. 合集首次发布

**目标**：合集壳 + 章节单品 + 目录合并发布。

```bash
freelog-cli init my-novel && cd my-novel
freelog-cli collection create --title "我的小说" --type <collectionType> --yes

freelog-cli create --cwd ./chapters/01-intro --title "序章" --type <chapterType> --yes
freelog-cli updateVersion --cwd ./chapters/01-intro --version 1.0.0 --filePath ./dist
freelog-cli publish --cwd ./chapters/01-intro --yes
# … 其它章节同理 …

freelog-cli collection item add ./chapters/01-intro
freelog-cli collection item add ./chapters/02-chapter
# 或：collection item add <他人已发布 resourceId>

freelog-cli collection policy add --from-file ./policy.json --yes
freelog-cli collection update --intro "系列简介" --tags "小说" --yes
freelog-cli collection publish --yes
freelog-cli online --yes             # 合集目录下同样严格；勿模仿 Console Step4 软上架
```

| 规则 | 说明 |
|------|------|
| 合集 owner | 只校验合集所属用户 |
| item add 路径 | 路径资源须为本账号；否则用 resourceId |
| item add resourceId | **允许他人已发布资源** |
| publish | `isMergeCatalogueDraft` 合并目录草稿 |
| online | **严格**；无 soft online |

## 6. 合集维护

```bash
freelog-cli pull --collection
freelog-cli collection update --title "新名" --display-sort asc --yes

# 新增一章
freelog-cli create --cwd ./chapters/03-new … && publish …
freelog-cli collection item add ./chapters/03-new
freelog-cli collection publish --yes

# 某章发新版后刷新合集
freelog-cli publish --cwd ./chapters/01-intro --yes
freelog-cli collection publish --yes

# 自动收录 / RSS（人机混合：码来自邮箱）
freelog-cli collection collect-rules set --from-file ./rules.json --yes
freelog-cli collection rss send-code <feedUrl>
# 查邮箱拿到 code 后：
freelog-cli collection rss bind <feedUrl> --code <code> --yes
freelog-cli collection rss sync --yes
```

RSS 合集：除标签外 listing/目录多只读；无 `--code` 拒绝 bind。CI **不能**纯自动收码，只能人工注入 `--code`。

## 7. Console 与 CLI 交替

```bash
freelog-cli status                 # owner + 同步 + 平台发版草稿（含「仅 Console 防抖」）
freelog-cli pull                   # 以平台覆盖本地 listing/缓存
# 再 update / updateVersion / publish

# 账号不符 → 写命令 exit 2 → login 切回 owner
```

跨端 WIP：`draft push` → Console 改 → `draft pull` → `publish`。  
仅打开过 Console 发版页：见 §2「仅打开过 Console」。决策树 → [05 §8](./05-Console与CLI对照.md)。

## 8. CI / `--cwd` 脚本示例

无 TTY 主路径（RSS / 微应用签约除外）：

```bash
#!/usr/bin/env bash
set -euo pipefail
ROOT="$(cd "$(dirname "$0")/.." && pwd)"

freelog-cli create --cwd "$ROOT" --type "$TYPE" --title "$TITLE" --name "$NAME" --yes
freelog-cli updateVersion --cwd "$ROOT" --version 1.0.0 --filePath "$ROOT/dist" --yes
freelog-cli publish --cwd "$ROOT" --yes
freelog-cli policy add --cwd "$ROOT" --from-file "$ROOT/policy.json" --yes
freelog-cli online --cwd "$ROOT" --yes
```

合集多章节循环：

```bash
for d in chapters/*/; do
  freelog-cli publish --cwd "$d" --bump patch --yes || true
done
freelog-cli collection publish --cwd . --yes
freelog-cli online --cwd . --yes
```

| 永远做不到纯自动 | 做法 |
|------------------|------|
| RSS 邮箱验证码 | 人工 `bind --code` |
| 依赖策略可视化签约（Phase1） | exit 5 → Console；Phase5 才 policy-map |
| 策略 Builder | Console 导出 → `--from-file` |
